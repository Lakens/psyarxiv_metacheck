How Power Analysis Check works

This module uses regular expressions to identify sentences that contain a statistical power analysis. If specified by the user, it also uses a large language model (LLM) to extract information reported in power analyses, including the statistical test, sample size, alpha level, desired level of power, and magnitude and type of effect size.

The Power Analysis Check module uses regular expressions to identify sentences that contain a statistical power analysis. Without the use of an LLM, the module uses regular expressions to classify the power analysis as a-priori, sensitivity or post-hoc. With the use of an LLM, it checks if the power analysis is reported with all required information.

The regular expressions can miss power analyses, or fail to classify them correctly. The type of power analysis is often difficult to classify, which can easily be solved by explicitly specifying the type of power analysis as ‘a-priori’, ‘sensitivity’, or ‘post-hoc’. Note that ‘post-hoc’ or ‘observed’ power is rarely useful. The LLM can fail to identify information in the paper, and will not have access to information in paragraphs in the paper other than those that contain the word ‘power’. This package was validated by the Metacheck team on articles in Psychological Science.

How StatCheck works

Check consistency of p-values and test statistics

The Statcheck module runs Statcheck. Statcheck searches for regular expressions that match a predefined pattern, and identifies APA reported statistical tests. More information on the package can be found at https://github.com/cran/statcheck. The module only returns Statcheck results for t-tests and F-tests, as these are the only tests which have been validated, see https://osf.io/preprints/psyarxiv/tcxaj_v1/.

Statcheck was developed by Michèle Nuijten and Sascha Epskamp.

Statcheck considers p = 0.000 an error, as you should report p < 0.001. Furthermore, p < 0.03 is an error if the p-value was 0.031, and one should simply report exact p-values (p = 0.031). When the sentence of a test says it is one-sided (“one-tailed”, “one-sided” or “directional”), a p-value that fits a one-sided test counts as consistent (statcheck’s OneTailedTxt setting; #695). When the paper says anywhere that its tests are one-sided, a p-value that fits a one-sided test in either direction counts as consistent too: half the two-sided p, or 1 minus that half for an effect against the predicted direction. Equivalence tests (TOST) are left out, as their p-values do not test the difference. A statistic written with “<” or “>” is read as a bound, and in a sentence about equal variances an F-test’s two-sided p (twice the one-tailed p) counts as consistent. For more information, see StatCheck.

This module only checks statistical results reported in the running text of the manuscript. It cannot (yet) process statistics reported only in tables.

How Exact P-Values works

List any p-values reported with insufficient precision (e.g., p < .05 or p = n.s.), reported as exactly zero (e.g., p = .000), or impossible (below 0 or above 1, e.g., p = -.22).

This module uses regular expressions to identify p-values. It will flag any values reported as p > ? or p < numbers greater than .001. It will also flag p-values reported as exactly zero (e.g., p = .000, p = 0.00), which are mathematically impossible — p-values are never exactly zero and should instead be reported as p < .001.

A p-value that is not the result of a test is not flagged: a table note (“* p < .05, ** p < .01”), a figure legend (“Asterisks indicate significant differences (p < .05)”, “Values in bold are significant at p < .05”) or a stated threshold (“p < .05 was considered significant”, “thresholded at p < .001”). GROBID often puts such notes into the running text, so each p-value is judged by the words in its own clause (the text up to a “;” or a full stop), and never left out when a test statistic belongs to it (“F(1, 7) = 8.03, # p < .05”). The column not_a_test of the table says why a p-value was left out (“marker”, “threshold”, “legend” or “named”).

A p-value with the name of a correction or a test after the p (“pFWE < .05”, “padj < 0.05”, “p Wilcoxon = .02”) is flagged only when a test statistic comes before it in its clause (“t(37) = 7.17, p FWE < .05”). Without one it is mostly the rule that decided what was significant (“genes with padj < 0.05 were selected”); such a p-value is “named” in not_a_test. Notes in other forms, such as a marker after the p-value (“p < .05 (*)“), are still flagged.

A p-value below 0 or above 1 is impossible; it is listed apart and not also as imprecise. Often the statistic before it, or its minus sign, was copied into it (“t(134) = -2.32, p = -.13”, “Z = 3.091, P = 3.091”). A value above 1 is listed only after a test statistic in its clause: without one, a “P” above 1 was nearly always another quantity (a proportion, pH, a group’s mean, a model parameter). A number in scientific notation whose power of ten was lost when the PDF was read (“p = 2.4 x 10 -9” read as 2.4) is not listed. A “p” that is the subscript of another symbol (“r p = .64”, “²p = .02” for partial eta squared, “Δp = .33”), or a quantity with a unit, a logarithm or a ratio (“P = 2.9 µm”, “-log10 P = 7.5”, “Ca/P = 1.67”), is not read as a p-value at all (see extract_p_values()). Each p-value has its own row, also when the same one is written twice in a sentence.

This module sometimes flags false positives when sentences discuss how p-value thresholds were set. It can also miss an imprecise p-value that is reported against a threshold (“decreased at the p < .05 significance threshold”).

This module only checks p-values reported in the running text of the manuscript. It cannot (yet) process p-values reported only in tables (as opposed to a table’s footnote text, which the module does see and tries to exclude — see above).

This module was developed by Lisa DeBruine and Daniel Lakens

Read more in the metacheck manual.

Validation: Validated on 226 Psychological Science papers with 5,019 hand-coded p-values, 438 of them imprecise (scienceverse/validation, branch stat_p_exact). Version 0.4.4.3 reported 419 p-values as imprecise, 388 of them correctly (93%), and missed 50 (89% found). How Non-Significant P Value Check works

This module checks for imprecisely reported p values. If p > .05 is detected, it warns for misinterpretations.

The nonsignificant p-value check searches for regular expressions that match a predefined pattern. The module identifies all p-values in a manuscript and selects those that are not reported to be smaller than or equal to 0.05. It returns all sentences containing non-significant p-values.

In the future, the Metacheck team aims to incorporate a machine learning classifier to only return sentences likely to contain misinterpretations. If you want to help to improve the module, reach out to the Metacheck development team.

How Repository Check works

This module retrieves information from repositories.

The Repository Check module lists files on the OSF, GitHub, ResearchBox, DSpace (PsychArchives and other legacy- and DSpace 7-based installations), Zenodo, Dataverse, Figshare, Dryad, ReShare, 4TU.ResearchData, Mendeley Data, DataONE (Arctic Data Center, KNB, and other member nodes), and LDbase based on links in the manuscript.

A link to a file-sharing service (Google Drive, Dropbox, OneDrive, Box, WeTransfer, MEGA, iCloud Drive, Baidu Netdisk, SURFdrive; see [file_share_links()]) gets a warning and makes the light yellow: such services are not repositories, as files can be changed or deleted at any time, get no DOI, and the link stops working when the account is closed. The report advises a stable repository such as Zenodo instead. Their files are not read, and summary_table$file_share_n counts the links.

Deposits in archives for sequence and expression data (GEO, the INSDC archives BioProject, SRA, ENA and DDBJ, and ArrayExpress; see [seq_archive_links()]), mostly named by accession number, are read for whose deposit they are. The authors’ own are listed with what they hold ([seq_archive_size()]) and are not downloaded or checked as data and code; summary_table$archive_own_n counts them.

R packages on CRAN ([cran_links()], [cran_info()]) are the paper’s own when a paper author is a package author and the paper presents the package; the paper’s own are listed with their version and not checked (summary_table$cran_own_n). A Handle link (hdl.handle.net/...) that leads to a repository read here is checked as a link to that repository ([handle_links()]).

Listing a repository’s files never requires an API key, but some hosts answer faster or more completely with one: OSF allows 100 requests/hour unauthenticated versus 10,000/day with a token (see [osf_pat()]), and Dryad enforces a strict per-IP daily quota on repeated listing (see cache below). Dryad is a special case beyond rate limits: listing a Dryad dataset’s files works without a key, but actually downloading file CONTENTS from Dryad fails with HTTP 401 unless a key is set, even for a fully public dataset (see [dryad_pat()] or [dryad_auth()]). Since this module only lists files and never downloads their contents itself, that limitation applies to data_check and code_check (which do download content), not here – see their own documentation.

When a linked OSF page is a registration, its registered_from project (the one it was registered from, which the manuscript itself may never link directly) is also checked: if that project is public its files are listed under its own URL, and if it is closed or otherwise inaccessible the report flags it explicitly, since some registrations only describe their content rather than mirroring it.

Whose deposit is each link? The ownership table gives, for every repository linked in the text and (with references = TRUE) every deposit cited in the reference list, one of six labels: own_this (made by the authors for this paper), own_earlier_data or own_earlier_code (the authors’ own, from earlier work), others_data or others_code (made by other people, reused here), or not_data (a publication such as a preprint, not a deposit), with ownership_group (“own”, “others”, “not_data”) and the reason. It is decided without a language model, from the sentence or reference that cites the link, the paper’s authors (names, ORCID iDs, affiliations), and what the deposit’s own record and files say (who made it, what it names, when, whether it is a software package; for an OSF project cited only in the reference list, its record alone). On a round of labelled links the rules had not been written from, the three groups were right for 98% of links in the main text (93 of 95) and 90% in reference lists (74 of 82); the labels were made by Claude agents from each link’s evidence, and disputed ones checked against the deposits. Telling this paper’s own deposit from the authors’ earlier one is less certain.

Only the deposits that are this paper’s own are checked. A deposit linked in the text that holds other people’s work (others_data, others_code) or the authors’ earlier work (own_earlier_data, own_earlier_code) is listed in the report, with the reason, but its files are left out of table and kept in table_not_checked: they count toward nothing here (files that do not belong in a repository, naming, READMEs, studies, the traffic light), and code_check, data_check and reproducibility_check, which read table, do not check them either. reproducibility_check still puts the files of theirs that the paper’s code names in the folder the code runs in, as a re-analysis needs the data it re-analyses. When every linked deposit is set aside, the traffic light is “na”. A deposit that is the paper’s own is counted as such when its README, title or description names the paper (its title or DOI).

How Code Check works

This module retrieves information from repositories checked by repo_check about code files (R, Python, SAS, SPSS, Stata, Mplus, MATLAB).

The Code Check module checks R (also R Markdown and Quarto), Python (also Jupyter notebooks), SAS, SPSS, Stata, Mplus, and MATLAB files, using regular expressions to check the code; JASP files are listed but not read. The language of a Quarto document or a notebook is read from the file itself (its engine or kernel), not from its extension. The regular expression search will detect the number of comments, the lines at which libraries/imports are loaded, attempts to detect absolute paths to files, setwd() and install.packages() calls, and lists files that are loaded, and checks if these files are in the repository; R code is also parsed. The module will return suggestions to improve the code if there are no comments, if libraries/imports are loaded in lines further than 4 lines apart, if files that are loaded are not in the repository, if absolute file paths, setwd() or install.packages() are found, and if R code cannot be parsed.

The regular expressions can miss information in code files, or falsely detect parts of the code as a fixed file path. Libraries/imports might be loaded in one block, even if there are more than 3 intermittent lines. The module was tried out internally on papers published in Psychological Science, but has not been formally validated. There might be valid reasons why some loaded files can’t be shared, but the module can’t evaluate these reasons, and always gives a warning.

The module also checks whether the repository pins the R/package versions the analysis actually depended on: an renv.lock file (parsed for the R version and every locked package + its version/source), a sessionInfo()/sessioninfo::session_info() text dump (matched by filename — sessionInfo.txt/session_info.txt and similar, or embedded in a README), or a groundhog::groundhog.library()/checkpoint::checkpoint() date-pin call in the code (a bare library(groundhog)/library(checkpoint) does not count — the pinning call itself must be present). When none of these is found, the report flags it as a reproducibility gap: package versions may drift between when the analysis was run and any later reproduction attempt.

If you want to extend the package to perform additional checks on code files, or make the checks work on other types of code files, reach out to the Metacheck development team.

Checking code requires downloading its file contents. For a paper whose repository is on Dryad, this never succeeds unless a Dryad API key is set: Dryad requires one to download file bytes, even from a fully public dataset (listing the repository’s files does not need one). Without a key, every Dryad-hosted code file is listed but unchecked, and a warning naming Dryad and ?dryad_pat/?dryad_auth is included among the download failures recorded in the manifest.

How Data Check works

This module classifies the files in a repository into semantic types (data, codebook, code, software, output, supplemental, readme, asset, other) and, for tabular data files, extracts each column’s type and summary statistics.

The Data Check module consumes the file list produced by repo_check (or any files added via local_path). Each file is classified with rule-based heuristics layered over metacheck’s file_category() and file_types: file names matching README / codebook patterns win first, then an extension crosswalk, then format-locked extension overrides. For every file classified as tabular data that is available locally, the module reads the file head, describes each column with data_col_facets() and computes summary statistics for numeric columns. Every sheet of a spreadsheet that holds a table is read: a file with several such sheets has its columns under source_file = "file.xlsx [sheet]", and the sheet column names the sheet of any spreadsheet with several sheets; a sheet of notes or a codebook is treated as documentation when the file has another table. Following DDI, a column is described by orthogonal facets rather than a single type: representation (numeric/text/datetime/code — how it is stored), measurement_level (Stevens: nominal/ordinal/interval/ratio), concept (what it measures: reaction_time/age/gender/likert/id/…), role (identifier/measure/condition/timestamp), unit, and a quality state (ok/empty/constant). Concepts are detected by name+value rules (the demographic concepts via data_check_demographic()); when llm_use(TRUE) the model fills concepts and measurement levels the rules left blank. Qualtrics survey exports are recognised (data_check_is_qualtrics()): their extra header rows are stripped so columns type correctly, and the reserved response-metadata columns (StartDate, Duration, Finished, …) are tagged.

The module defaults to rules-only when llm_use(FALSE): columns the rules cannot resolve (ambiguous 3–20-unique integers, ambiguous character columns) fall back to continuous / text respectively. When llm_use(TRUE), ambiguous columns and unresolved file types (other) are sent to llm() for optional refinement, and every file is assigned a study group (ex1, pilot2, shared, …) so that multi-study repositories can be recognised (used by psychds_check). Without an LLM the study group is left NA (unknown).

Column extraction requires files to be readable from disk. Files fetched by repo_check from OSF/GitHub/etc. without a local copy (file_location is NA) are classified but not column-extracted; pass local_path to point at a downloaded copy of the repository.

For a paper whose repository is on Dryad, this means column extraction never happens unless a Dryad API key is set: Dryad requires one to download file bytes, even from a fully public dataset (dataset listing and metadata do not need one). Without a key, every Dryad file stays classified but un-downloaded, column_n is 0, and a warning naming Dryad and ?dryad_pat/?dryad_auth is included among the download failures. A one-time session message is also shown (see repo_check) the first time a Dryad dataset is encountered with no key set.

Every downloaded text file the authors wrote (code, settings, survey definitions such as Qualtrics .qsf files, documentation, outputs) is searched for keys: API keys, access tokens and private keys, which let anyone who downloads the file use a paid service at the authors’ cost. Of a tabular data file only the column names and first 3 rows of the table as read are searched: its values come from participants, but a key the authors set for a whole survey (as embedded data in a Qualtrics survey flow) is exported in every response. The search uses the rules of the secret scanner betterleaks (https://github.com/betterleaks/betterleaks, MIT licence) of high and medium confidence. A key found turns the traffic light red; the report and the keys table give its file, line and type, and only its beginning. Other files over 25 MB and binary files are not searched. A key is never tested with its provider. Every module’s result has any whole key replaced by “keyremoved” (see module_run()).

How Reproducibility Check works

This module assesses whether a paper’s R and Python code can be run on its data. It works in two phases. The static phase (always run) collects the package dependencies the code declares, rewrites the data-file paths that do not work in the repository as the authors organised it, works out the order the scripts must run in, and diagnoses why any referenced input file is unavailable — reporting what a reproduction attempt would involve and where it is likely to break. The execution phase (opt-in, execute = TRUE) then actually runs the code: it copies the repository into a throwaway directory, optionally installs the declared dependencies into a throwaway library, runs each script in order in an isolated subprocess with a per-script timeout, and captures the outcome and full output of each run.

By default (execute = FALSE) the module does not run any code — it performs only static analysis: reading dependencies with the same extractors as code_check, finding the files the code references in the repository, and building a run-order dependency graph. It reports what would be installed and run rather than doing it.

When execute = TRUE, the module additionally runs the downloaded code on your machine — a deliberate, opt-in action gated behind that argument (callr is required for R code). Each script runs in an isolated subprocess so a crash cannot take down the R session; note this isolates crashes, not the filesystem or network. Installs (when install_missing = TRUE) and the throwaway run library never touch your main R library. Each script’s outcome is one of ran_ok, errored, timed_out, dependency_unavailable, not_parsed, run_by_source (an R script another script runs with source(), which is run only inside that script, since on its own it lacks the packages and objects the sourcing script sets up first), run_by_import (a Python file other files import, a module rather than a script, unless it has an if __name__ == "__main__": block), jags_model (a JAGS or BUGS model saved with an R extension, which another script reads) or not_r_content (a file that is not R at all, such as a JSON or HTML dump); these last two are not run and are not failures. python2 marks Python 2 code that was not run. With sandbox = "docker" such code runs with Python 2.7 (option metacheck.docker_image_py2; FALSE turns this off), which modifications records; it is never converted, since that can change results. defines_functions is a file that only defines functions, which is used, not run (table$used_by names the scripts that use it), and not_analysis is a file of software rather than of the analysis: a package’s code, tests, documentation or setup.py, a copy of a tool, a web application, a script a program wrote (table$not_analysis_why says which); neither is run or counted as a script. docker_failed means the container never started, which says nothing about the script, so it keeps the light from being green but does not make it red. needs_a_person is a script that stopped because it asks a person to choose a file or answer a question, or that starts an app, and needs_internet one that stopped because the network is off in a Docker run, or, with internet = TRUE, could not reach what it asked for; download_too_large is a script stopped for downloading more than the limits allow (see internet), and out_of_memory one that, or a program it started (such as a compiler), ran out of the memory each script may use. All four are treated the same way. not_downloaded is a script that stopped on a file the repository lists but that was not downloaded, such as one over max_file_size: it could not be tried, so it is not counted as a script that did not reproduce (summary_table$repro_not_downloaded_n counts them apart). not_read is a file metacheck could not read, so it was not run; the light is then not green, as the file may read and run on another computer, and table$error_message says why, naming a package that is installed but cannot be loaded on the computer that ran the check. empty is a file with nothing in it, which is not run or counted as a script. For a script that did not run through, table$error_message is its error, short (at most 300 characters): the error line of its output, which names a package that is not there, with the address it asked for when it needed the internet, or the time limit it reached; table$reason sorts it into a kind. A timeout means “still running at the cutoff”, not a failure, so raise timeout for legitimately long-running (e.g. Bayesian) scripts. dependency_unavailable means the script’s own package could not be installed from live CRAN, the CRAN Archive, or a named GitHub/URL source — an infrastructure limitation, not a defect in the paper’s code. The full stdout/stderr of every run is kept in the result’s run_results (the report shows it in per-script dropdowns, capped for readability).

Provenance, kept so that a TRACE Research Object (TRO) declaration of the run can be written later from a stored result (metacheck #404; the helpers are in R/provenance.R). Only when code was run (execute = TRUE): * run_results$started_at, run_results$ended_at: when each run of a script started and ended (ISO 8601, UTC, milliseconds); NA for a script that was not started. A script run again in a later pass has the times of its last run. A TRO uses them for each trov:TransparentResearchPerformance. * run_results$exit_status: the exit status of the process that ran the script (0 = ended normally); NA when the process did not report one (a time limit, or Docker failing to start the container). * artifacts: one row per file, with stage (deposit: as downloaded from the repository, hashed from the downloaded file; before_run: the run folder just before the first script ran, after metacheck’s own changes, such as rewritten paths and unpacked archives; after_run: only the files the scripts made (status new), changed (changed) or removed (removed), as an unchanged file is the one listed before the run), path (relative to the run folder, as valid UTF-8, a byte of another encoding written as <xx>), size (bytes), sha256, mime_type (by extension, NA when unknown), source (the file’s address in the repository, for deposit). The package libraries metacheck installs in the run folder are left out, as are metacheck’s own files there (a script’s runner, and the statistical output it writes in statistical_output/). Files metacheck itself copied or made between passes (see modifications, output_copied, file_placed) show in after_run too. A TRO uses the rows as trov:ResearchArtifacts and each stage as a trov:ArtifactArrangement. * modifications$sha256_before, modifications$sha256_after: the hash of the changed script as downloaded and as it ran; NA when the script is not at the same path in both (a script made from an R Markdown file). * environment: the system that ran the code (trov:TransparentResearchSystem in a TRO): metacheck_version, started_at, ended_at, host (R version, platform, operating system), sandbox, network_isolated (TRUE only when every Docker run had --network none; the process sandbox does not stop the network), internet, timeout_per_script, total_timeout, python_local (the Python run outside Docker and its version), and docker: runs (for each kind of run, r_run, r_install, python_run, python_install, the image and the docker run arguments, such as --network none, --read-only, --cap-drop ALL, no-new-privileges, the process limit and the memory and processor limits) and images (for each image, its ID and digests from docker image inspect, its creation time and the R and Python versions its environment declares).

run_results$checked says what the run of each script shows about the code, in five groups, so that a script that does not reproduce is kept apart from one the check could not test: ran (it ran to the end); code_error (it did not reproduce: it stopped with an error of the code or the deposit, could not be read, or needs a file the deposit does not hold); dependency (a package or program was not available: a package that could not be installed or was not loaded, a program outside R and Python, a system library, or R crashing in a package’s compiled code); time (it did not finish within the time limit for one script, or was not started because the time for all scripts had run out); and not_checkable (it could not be checked automatically: it needs a person, the internet, a key or another setting of the authors’ computer, one platform such as Google Colab, Windows or OpenSAFELY, more memory than the run allows, a file that was not downloaded, a screen, or a program that runs it, or it is a file of a package of the code that Python runs only as a module of that package). It is NA for files run inside another script, files that are not an analysis, files not read, and a Docker failure. summary_table counts each group (repro_ran_n, repro_code_error_n, repro_dependency_n, repro_time_n, repro_not_checkable_n), and the report’s first sentence gives them. The traffic light reflects the static readiness signals by default; a script in code_error that stopped with an error makes it red, as a script that crashes on its own analysis is a genuine reproduction failure, and a script in one of the other three groups keeps it from being green. Calls that need a screen, which the run does not have (dev.print(), dev.copy2pdf(), dev.copy2eps(), savePlot(), windows(), win.graph(), x11(), quartz(), View()), are replaced before the run by calls that need none, which modifications records as screen_call_replaced. A script that fails with could not find function is run once more with the library() calls the project’s other scripts make added at its top (or the one package that exports the function, or magrittr for %>%), and a script that then runs is reported as reproducible only after that repair.

Dependencies are reported name-only, with the source (CRAN, GitHub, or a base package already shipped with R) — static analysis of the code cannot know which version was used, and running against current package versions is itself informative: a break argues the authors should have pinned versions. When the repository does record versions, a run with recorded_versions = TRUE installs the packages the scripts load at those versions, but it does not change the R version, which remains a limitation of the check.

Run order is derived from read-after-write data dependencies (a script writing a file another reads must run first), source() edges, and numeric filename prefixes as a weak tie-breaker. Ambiguous orderings, dependency cycles, and inputs a script reads but that no earlier script produces (and that are not in the repository) are surfaced as warnings, since these are the situations most likely to make an otherwise-correct reproduction fail.

Python code (.py files, and notebooks and Quarto documents whose code is Python, from which the code is extracted first) goes through the same two phases, reported in its own “Python code” section. Each file is checked for syntax errors with Python’s own parser when a Python interpreter (python, or else python3) is available; dependencies are read from the import statements, with versions from a requirements.txt or pyproject.toml when there is one, and installed with pip; each script runs as its own python process (processx is required), so unlike R scripts, a name one script defines is not available to another. When no Python interpreter is available, the Python files are reported as not run and the R results are still returned. Statistics the Python scripts print are compared with the paper together with the R output and any self-reproducible output (JASP/jamovi, SPSS-Viewer, notebook outputs).

Abstract

Individuals with neurodivergent and other high processing cost phenotypes (HPCPh)-marked by pronounced cross-domain functional disparity-frequently experience severe functional collapse, burnout, and migrating somatic symptoms despite routine blood panels deemed "normal." Whether an adaptive, reversible multisystem regime-Third Allostasis-operates hidden inside ordinary clinical testing remained unmapped. Here we chart 921 chronological panels across 41 anonymized HPCPh individuals (21 longitudinal series; 20 independent multi-laboratory referrals), analyzing inflamed draws separately and measuring within-person mobility against healthypopulation normal biological variation benchmarks (European EFLM/EuBIVAS 95% and 99% Reference Change Values). Beneath an intact structural crust (preserved albumin and normal median HbA1c), 37 of 41 individuals engaged core containment axes (watersolutes, iron, adrenal, or thyroid), rising to 19 of 22 engaging three or all four axes where cryoscopic osmometry was measured. Excursions rose and fell symmetrically (212 versus 195 steps), reverted rapidly across clinical thresholds, and took turns across consecutive panels-revealing an isostatic physiology legible only longitudinally within the person.

1. Introduction

High processing cost phenotypes (HPCPh) encompass neurodivergent and other constitutional profiles defined not by discrete categorical boundaries, but by a shared cross-domain functional disparity [1, 2]: high-gain sensory and associative central nervous system domains (islands) coexisting with executive implementation bottlenecks (deserts), imposing the dual metabolic cost of hyper-engaged networks and ongoing compensation (bridges) [3, 4]. HPCPh and their multisystem comorbidities [5] [6] [7] indicate a constitutional biophysical condition shaping neuronal migration-the Islands, Deserts, and Bridges (IDB) topography-and lifelong physiological constraint points. Under a Bayesian rationale [8] seeking one parsimonious upstream factor for this convergence, these features point to extracellular matrix (ECM) biophysics [9]. This model emerged from over two decades of clinical practice, teaching, and research spanning trauma, stress physiology, burnout, and the psychotherapy-biology interface. Patients later framed within HPCPh typically presented with treatment-resistant, depression-like collapse, burnout, uneven functioning, or migrating "psychosomatic" complaints-years of fluctuating fatigue and dysautonomia shifting across systems. Repeated routine work-ups were deemed "normal," while atypical values were dismissed for fitting no label. Lacking a biological explanation, clinical impasse often yielded to moral attribution-"personal failure," "laziness," being "spoiled," or a "character flaw"-eroding identity and exacting a toll especially cruel to children [10] [11] [12].

Over time, disparate presentations began revealing one stage governed by shared constraints. Seeking to name lived realities and alleviate suffering-why we treat people-we traced the clearest laboratory entry point, where alternatives were quickly excluded: Functional Iron Blockade (FIB). Defined by elevated ferritin without inflammation (hs-CRP < 5 mg/L, often < 1 mg/L) alongside iron and transferrin saturation unexplained by hemochromatosis, FIB frequently co-occurred with altered circadian HPA curves, DHEA-S declining before cortisol, low vitamin D, and an apparent familial pattern responsive to context [13]. Retrospective review across dozens of cases-and parallel clinical and laboratory improvement after shifting therapeutic focus-uncovered additional contextual responders. Whereas acute shifts were rapid and reversible, sustained incompatibility between environment and individual architecture (masking) drove slower set-point shifts, exposing a far steeper biological cost than recognized [14].

Case after case reframed depression, fatigue, burnout, and migrating somatic symptoms as active adaptation rather than primary disease-a coordinated multisystem maneuver defending temporal coherence and structural integrity at the temporary expense of output speed. Read longitudinally within the person, routine panels rendered this state legible as a reproducible multisystem regime termed Third Allostasis [15].

Unlike Type 1 (energetic deficit) or Type 2 allostasis (chronically aversive social environments despite intact energy stores) [16, 17], Third Allostasis is governed by informational load as a rate-limiting physical constraint: throughput outpacing local recovery. Sustained high-rate firing strains excitable membranes preserving ionic gradients via neuronal Na⁺/K⁺-ATPase and astrocytic K⁺ clearance [18, 19], even with intact oxygen and glucose supply. This approaches the spreading depolarization boundary-first described by Aristides Leão in 1944 as cortical spreading depression [20]-where excessive excitation precipitates electrocortical silencing [21, 22]. Because this threatens cellular viability, defense begins with cell-autonomous, feedforward programs conserved from marine origins protecting ionic and osmotic integrity [23, 24]; when load-topology mismatch persists, newer integrative systems-including the hypothalamic-pituitary-adrenal (HPA) and hypothalamicpituitary-thyroid (HPT) axes-reinforce that shield [25, 26].

Third Allostasis therefore operates through involuntary adaptive buffers-not a rigid domino cascade, but coupled, semi-autonomous oscillators visible longitudinally. Rather than isolated endocrine failure or noise, these trajectories reflect physiological isostasy. Borrowed from geophysics-where tectonic plates of fixed composition preserve surface stability by adjusting buoyancy over a shared, pressurized mantle [27]-physiological isostasy describes how functionally invariant axes absorb processing load through coordinated, bounded shifts. No axis loses identity or crosses into structural disease; each modulates its set-point while redistributing tension across coupled systems. What snapshots read as "normality" emerges longitudinally as active mutual compensation preserving surface stability.

Within this architecture, intercompartmental water and solute handling (IWSH) and FIB [13] form first-line cell-autonomous buffers [28, 29]. Under sustained load, HPA and HPT complete four continuous 24/7 core axes modulating processing rate, metabolic allocation, and biosynthesis [30] [31] [32] [33], flanked by punctual brakes such as prolactin [34], anabolic-catabolic permissiveness via somatotropic (GH/IGF-1) and adrenal androgen (DHEA/DHEA-S) pathways [35] [36] [37], and a consistent immunometabolic and hematologic signature. Longitudinal inspection uncovered a biophysical footprint pointing under the same Bayesian rationale to compatible solutes: non-toxic osmolal gaps (up to 22 mOsm/kg) during contextual transitions, paired with red-cell hydration shifts chronicling intercompartmental traffic in routine blood counts.

Clinic-first Bayesian updating rather than a priori hypothesis testing. Epistemically, this framework was never constructed by formulating a theoretical hypothesis beforehand and searching retrospective records to confirm it. Instead, following MacKay's Bayesian model-comparison rationale [8], clinical reality set the initial conditions: unexplained functional collapse coexisting with preserved organ structure forced sequential updating of provisional mechanistic priors as longitudinal panels accumulated in routine care. Candidate explanations incompatible with incoming data fell away, whereas convergent biophysical constraints expanded-an abductive, data-updated process fundamentally distinct from frequentist null-hypothesis testing. Chronologically, non-inflammatory Functional Iron Blockade emerged first [13]; recurrent water-andsolute handling shifts were noted clinically the following year; an initial 12-case longitudinal synthesis was locked [14] while dozens of unreviewed charts and external referrals remained unexamined; and only subsequently did cryoscopic osmometry unmask non-toxic osmolal gaps [15], prompting the systematic evaluation across all 41 longitudinal and independent consultation series reported here.

Building on prior clinical and mechanistic work [14, 15], we map these dynamics across 41 anonymized HPCPh individuals-children, adults, and older adults-under an institutional ethics waiver (Hospital de Clínicas de Porto Alegre; CAAE 99556626.7.0000.5327) limited strictly to anonymized laboratory data. Using a stratified Cold-Column Clinical Barcode across two streams (21 longitudinal; 20 independent consultation referrals), we chart mark prevalence, quantify within-person excursions against healthy-population European EFLM/EuBIVAS normal biological variation benchmarks [38, 39], and track load hand-overs-bringing hidden dynamics into view for those seeking answers amid signs legible only longitudinally within the person.

2.1. An intact structural crust across two clinical streams

In this naturalistic retrospective series, every test order followed routine care; reporting arose afterwards, strictly limited to anonymized laboratory data. We mapped 921 chronological panels from 41 HPCPh individuals-21 followed longitudinally and 20 referred for independent multi-laboratory consultation (median 14 panels/person; median follow-up 10.4 years). Using each draw's inflammatory markers (Section 4, Methods), panels were sorted into 579 non-inflammatory, 264 unflagged ambulatory, and 78 inflamed draws (41 with C-reactive protein [CRP] ≥ 5 mg/L) analyzed apart. Only markers inflammation can mimic were state-gated, confining iron kinetics and inflammation-sensitive signatures to non-inflammatory draws while reading structural anchors throughout.

Structural crust. Across the Cold-Column Clinical Barcode (Fig. 1; osmometry layout, Supplementary Fig. S1; Table 1), the crust stays unbroken. Serum albumin remained ≥ 4.0 g/dL in every non-inflammatory draw (27/27 tested; median 4.50 g/dL; the only two readings < 4.0 g/dL cooccurred with severe acute-illness indicators and were excluded). 2.2. First-line cellular shields: water, uncharged solutes, and iron

IWSH and RCH-ST. Consistent with membrane-conserved feedforward defense, the earliest footprint appeared in water-solute partitioning and iron storage (Fig. 1a, Table 1). Among 22 individuals with cryoscopic osmometry, 21 (95%) exhibited direct IWSH marks across both streams. Its hallmark was sodium-decoupled hyperosmolality: across all 17 draws reaching serum osmolality ≥ 300 mOsm/kg (9 individuals), electrode sodium remained strictly normonatremic (137-142 mEq/L), pointing to uncharged compatible osmolytes rather than dehydration or salt excess. Osmolal gaps ≥ 10 mOsm/kg and sodium normalized to 290 mOsm/kg unmasked hidden solutes in over half of tested individuals despite normal sodium (Table 1). Paired urine panels caught the kidney alternating between water conservation and episodic free-water release while exposing dipstick blindness: inside an unremarkable specific gravity of 1.015-1.020, measured urine osmolality spanned nearly threefold (302-817 mOsm/kg).

Chronicling this traffic in a routine complete blood count (CBC), RCH-ST offers bedside arithmetic readable in any clinic against a hemoglobinstratified EFLM/EuBIVAS lookup table [38, 39] (Supplementary Table S1). As an indirect IWSH proxy, RCH-ST crossed its 95% biological variation limit in 28/37 evaluable individuals (45 rises, 43 drops), tracking nearly everyone with direct IWSH marks (19/21) and flagging likely water-axis activity in 8/15 evaluable individuals without an osmometer (Fig. 1a, Supplementary Fig. S1). Beyond step-to-step shifts, serial RCH-ST also serves as a background set-point marker: sustained baseline shifts across consecutive CBCs register when physiology settles into a new hydration regime after persistent contextual change.

FIB.

Strictly in non-inflammatory draws, FIB engaged in 29/38 evaluable individuals across both cohorts (Table 1). Acting as a dynamic storage valve rather than static overload, ferritin exceeded the sex-and age-blind WHO ceiling (≥ 200 ng/mL in 17/38), oscillated bidirectionally across EFLM limits (19/30; 16/30 both ways), uncoupled from transferrin saturation, or sequestered iron despite low circulating saturation-capturing cases missed by ferritin ceilings alone.

2.4. Tectonic choreography: isostatic symmetry, reversible returns, and load hand-overs

Against one external normative ruler-uniform European EFLM/EuBIVAS healthy-population within-person biological variation across ten analytes (where normal healthy fluctuation crosses 95% and 99% Reference Change Values in ~5% and ~1% of steps, respectively)excursions showed striking symmetry at rates far exceeding healthy variation (Fig. 2a, Table 2). Ascents and descents balanced nearly evenly at 95% (212 upward versus 195 downward; 1.09:1) and 99% limits (110 versus 102; 1.08:1). Nearly every evaluable individual crossed an EFLM limit (35/39; 90%), and nearly two-thirds moved bidirectionally within the same analyte (25/39; 64%)-a bounded, elastic equilibrium rather than progressive organ failure. Although ethics rules preclude clinical or medication records, within-person threshold returns were strikingunfolding within days to weeks when closely re-tested (cold creatinine > 1.20 mg/dL returning in 1-29 days, prolactin ≥ 20 ng/mL in 10-35 days, and morning cortisol < 8 µg/dL reaching ≥ 10 µg/dL in 41-86 days, with drops < 1 µg/dL rebounding into range in 11 days): cortisol (6/6), HbA1c (4/4), flat salivary curves (3/3), cold creatinine (5/6), and prolactin (5/7; Fig. 2b).

This equilibrium resolves why single snapshots appear reassuring while longitudinal series expose a multisystem architecture (Fig. 2d, Table 2). Across 98 non-inflamed draws assessing all four core axes together (32 individuals), 81% carried active containment, yet only 2% (2/98) engaged all four at once-and 0/81 also reading the second line engaged all five. Over time, however, 86% (19/22) with osmometry recruited three or all four core axes. Consecutive draws explain why: as in geological isostasy, tectonic plates take turns. When an active core axis released its mark, another held the load at the next draw in 32/60 releases (53%; 56% including second line).

Stepped reopening and set-point rescaling after lifelong overload have been detailed in a consented series [14, 15]. Here, an independent anonymized sequence (HPC_019, Fig. 2c) shows six out-of-range markers across distinct systems-neutrophils, free T3, IGF-1, parathyroid hormone, ferritin, and prolactin-re-entering reference intervals simultaneously within 35 days: a coordinated shift nearly impossible to reconcile with concurrent structural pathologies resolving together, even assuming intervention.

2.5. Background signatures, acute inflammation apart, and sensitivity control

Cross-cutting all tiers, a coherent hematologic and immunometabolic background chronicled regulatory cost rather than phase switches (Fig. 1b, Table 3). Metabolically, an "anti-metabolic-syndrome" pattern paired normal HbA1c and clean lipids (36% of draws; 22/37 people) with wide within-person insulin swings (HOMA-HS ≥ 2-fold in 8/19), while cold creatinine and urea frequently crossed EFLM limits. Across all draws, substrate depletion was pervasive-vitamin D < 30 ng/mL (45%; 34/40) and zinc-to-copper ratio < 1.0 (89%; 27/28)-remaining virtually unchanged outside inflamed draws (Table 3).

3. Discussion

Across 41 anonymized individuals from two clinical streams, routine laboratory records revealed a coherent multisystem regime beneath an unbroken structural crust. The central finding is not isolated organ failure, but physiological isostasy: within-person excursions crossed EFLM variation limits symmetrically (212 versus 195 steps), reverted across clinical thresholds-within days to weeks when closely re-tested, including cortisol rebounding from < 1 µg/dL into range in 11 days and six out-of-range markers normalizing in 35 days-and took turns across consecutive panels. Because all four core axes rarely engaged together in one draw (2%) yet accumulated longitudinally in 86% with osmometry, cross-sectional snapshots systematically mask the phenomenon, leaving it legible only longitudinally within the person.

At the cellular first line, these data ground Third Allostasis in conserved membrane biophysics. Sodium-decoupled hyperosmolality (normonatremic across all draws ≥ 300 mOsm/kg), osmolal gaps, and dipstick-invisible urine osmolality swings point to uncharged compatible osmolytes defending intracellular volume and ionic stability [23, 24, 28]. Crucially, RCH-ST translates this intercompartmental traffic into bedside arithmetic on a routine CBC-flagging water-axis engagement without osmometry and tracking sustained baseline set-point shifts across consecutive draws. In parallel, FIB's speed, bidirectionality, and non-inflammatory setting refine our earlier perspective [13]: rather than the hepatic IL-6-hepcidin inflammatory cascade, non-inflammatory ferritin mobility and storage sequestration point to rapid, cell-autonomous iron regulation (cytosolic IRP/IRE and macrophage redox control) [29] operating in the same ancestral feedforward tier as osmotic defense.

Equally essential is recognizing what these mechanisms are-and are not. Containment buffers are not villains or primary failures; they are adaptive safeguards without which living with an HPCPh architecture would not be biologically sustainable. Across wide individual variations in islands and deserts, high-gain sensory and associative networks support parallel processing and pattern detection at steep metabolic cost whenever external demands clash with neural topology [1, 3, 4]. Under intense, inescapable mismatch, sustained braking lowers throughput and investment readiness toward a "hibernationlike" state-including flattened HPA profiles biologically mirroring learned helplessness [40]-producing trajectories resembling treatment-resistant depression where conventional protocols often fail. Conversely, when context matches individual architecture, release is not an instantaneous switch: set-points rescale along a stepped staircase marked by physiological hysteresis, rarely symptom-free and often turbulent as velocity and investment progressively reopen [14, 15]. The clinical goal is therefore never to abolish containment buffers-still less override them iatrogenically with iron or hormone replacement aimed at reversible brakes-but to achieve a compatible organism-environment arrangement.

Put simply, it is futile to try to "fix" an alkaline-water fish when the aquarium water is acidic-even when every other fish in the tank thrives. An alkaline-water fish cannot flourish in acidic water, and never will. That incompatibility is not a defect of the fish; it is its innate biology. Recognizing Third Allostasis shifts clinical care away from moral attribution toward restoring environmental fit-where clinicians and families can genuinely help these individuals live well.

Three methodological considerations warrant note. First, anchoring mobility to an external normative ruler-healthypopulation within-person EFLM/EuBIVAS Reference Change Values [38, 39]-removes author-selected cut-offs and directly separates organized physiological excursions from normal healthy biological variability. Second, avoiding linear exclusions that discard the very adaptive deviations studied (such as transient hyperprolactinemia), only analytes mechanistically mimicked by acute inflammation were state-gated. Reading the 78 inflamed panels separately underscored why: at CRP > 20 mg/L, canonical neutrophilia, lymphopenia, and hyperferritinemia fired on cue (Fig. 2e), showing that habitual cold-column physiology reflects an organized response to another load-preserved under the ±7-day control (Supplementary Table S2).

Third, this naturalistic retrospective design has clear boundaries: unscheduled testing underestimates prevalence, lacking a parallel clinical control cohort precludes cross-diagnostic specificity estimates across other medical or psychiatric conditions, and strict anonymization precludes pairing laboratory waves with individual symptoms or medications. Prospective standardized cohorts pairing clinical phenotyping with targeted metabolomics for compatible osmolytes (taurine, betaine, myoinositol) are now needed to test these mechanisms directly.

By mapping physiological isostasy within ordinary blood panels-including bedside red-cell hydration accessible in any clinic-this cartography renders an invisible multisystem economy legible, opening a precision-psychiatry agenda and offering biological recognition to children, adults, and older individuals whose suffering was long dismissed behind "normal" snapshots.

4. Methods

The mechanisms examined here are adaptive and allostatic; population reference intervals, designed to detect structural disease, were not built to capture them. Within-person longitudinal comparison is therefore the reference standard, capturing coordinated shifts that frequently remain inside population ranges while representing substantial within-person excursions [14, 15]. Because isostatic hand-overs are non-ergodic-unfolding sequentially within individuals rather than simultaneously across a group snapshot (Fig. 2d)-longitudinal within-person series provide the primary empirical resolution required before prospective controlled trials can be meaningfully designed. Selected clinical cut-offs (such as serum osmolal gap ≥ 10 mOsm/kg or morning cortisol < 8 µg/dL) were retained alongside biological variation limits because containment intensity frequently approaches or crosses conventional pathology thresholds. Because all panels arose from unscheduled clinical care rather than a prospective research protocol, specialized assays such as cryoscopic osmometry or reverse T3 were available only in subsets of cases; observed frequencies therefore represent conservative lower bounds.

4.1. Cohort architecture and ethics

This naturalistic retrospective longitudinal study followed an institutional ethics protocol approved by the Research Ethics Committee of Hospital de Clínicas de Porto Alegre (CEP/HCPA; CAAE 99556626.7.0000.5327), which granted a waiver of informed consent strictly restricted to anonymized routine laboratory records from individuals meeting the HPCPh profile [1, 2]. The consent waiver permitted inclusion across the lifespan-spanning children, adolescents, adults, and older adultswithout selection bias from contact burden, isolating laboratory dynamics from clinical narratives. Records from 41 individuals (921 chronological collection columns, including home salivary cortisol profiles; median 14 panels per person; median followup 10.4 years) were analyzed across two independent streams: 21 individuals followed longitudinally in regular clinical practice (codes 001-021) and 20 individuals referred for independent multi-laboratory consultation (codes 022-041). To safeguard strict anonymity across pediatric and adult participants, age, biological sex, clinical narratives, medication histories, and calendar dates were excluded from the reported dataset; dates were used solely to order draws chronologically and calculate between-draw intervals, and no age-or sex-stratified cut-offs were applied anywhere in the analysis.

4.2. Data extraction and three-state inflammatory gating

Original laboratory reports were transcribed into standardized per-person master tables (one chronological column per collection; one row per analyte). Consultation records underwent independent double-reading; apparent outliers prompted verification against original laboratory headers and unit conversions without altering any value. Following local clinical standards, metabolic and endocrine blood draws were collected in the morning after overnight fasting.

Each collection was assigned one of three inflammatory states by its own markers in cascade: (1) non-inflammatory-C- reactive protein (CRP, any assay) < 5 mg/L; absent CRP, erythrocyte sedimentation rate (ESR) ≤ 30 mm/h; absent both, complete blood count (CBC) within leukocytes ≤ 11,100/mm³, neutrophils ≤ 7,500/mm³, and lymphocytes ≤ 3,200/mm³; absent all three, borrowing non-inflammatory status from a draw of the same individual within ±7 days; (2) unflagged-no inflammatory marker on the draw or within ±7 days; and (3) inflamed-CRP ≥ 5 mg/L, ESR > 30 mm/h, or leukocytosis/neutrophilia/lymphocytosis exceeding the cut-offs above. The ±7-day rule lent only non-inflammatory status and never excluded a draw; only a draw's own marker classified it as inflamed. Across 921 collections, 579 were non-inflammatory (226 by CRP, 21 by ESR, 224 by CBC, and 108 by ±7-day neighbor), 264 were unflagged, and 78 were inflamed (41 by CRP, 1 by ESR, and 36 by CBC).

Only analytes mechanistically mimicked by acute inflammation were restricted by state (Supplementary Table S3 summarizes the acute-phase direction of each analyte [41] [42] [43] [44] [45] [46]): Category A (read in all collections, as acute inflammation does not mimic or opposes the mark)-HbA1c, clean lipid profile, morning serum cortisol < 8 µg/dL (return to ≥ 10 µg/dL restricted outside inflamed draws because acute inflammation elevates cortisol), and home salivary cortisol curves, with vitamin D and zinc-tocopper ratio counted across all draws and reported alongside counts excluding inflamed draws; Category B (read in noninflammatory and unflagged draws; inflamed draws excluded)-water and solutes (IWSH), red-cell hydration (RCH-ST), withinperson cortisol movement, HPT markers (TSH, free T4, free T3/reverse T3, Jostel index), prolactin, IGF-1, and DHEA-S; and Category C (read strictly in non-inflammatory draws)-serum albumin, functional iron blockade (FIB), insulin/glucose/HOMA-HS, renal markers (creatinine, urea), and hematologic background signatures (monocytes, mean platelet volume, white-cell synthesis economy, analyzer-zero eosinophils/basophils, D-dimer).

To assess robustness against unflagged subclinical inflammation, an ultraconservative sensitivity analysis restricted every blood analyte globally to the 579 non-inflammatory draws-applying the ±7-day non-inflammatory window uniformly across all axes (Supplementary Table S2). Separately, inflamed draws defined strictly by CRP (≥ 5 mg/L and > 20 mg/L, avoiding circularity with white-cell counts) were compared within-person against each individual's non-inflammatory median (requiring ≥ 2 non-inflammatory measures; Fig. 2e, Table 3).

Governance exclusions applied over general rules removed only documented primary structural endocrine causes or technicalquality artifacts without disclosing individual clinical histories: axes governed by a known primary structural cause were masked and left unread; isolated technical-quality outliers (one urine osmolality and one isolated blood-gas panel) and overt biochemical hyperthyroidism (TSH < 0.1 mIU/L with free T4 > 1.8 ng/dL) were unread; and the only two serum albumin readings below 4.0 g/dL, which co-occurred with laboratory indicators of severe acute illness, were excluded.

4.3. Within-person biological variation limits (EFLM ruler)

Within the four-axis core count, an individual marked the water axis via direct IWSH or RCH-ST (with RCH-ST-only capture distinguished visually by hatched bars in Fig. 1a).

Functional iron blockade (FIB; Level 1).

To maintain strict sex-and age-blindness, we applied the conservative World Health Organization (WHO) non-inflammatory ferritin ceiling for adult men and non-menstruating women (≥ 200 ng/mL; showing the 150-199 ng/mL female/pediatric zone as intermediate in Fig. 1a) [47]. FIB was marked in non-inflammatory draws by at least one of four expressions: HPT axis (Level 2). Marked centrally by TSH (≥ 1.67 or ≤ 0.60) or free T4 (≥ 1.21 or ≤ 0.83) steps exceeding EFLM limits. Two complementary indices are reported alongside: Jostel's central TSH index, sTSHI = (ln TSH + 0.1345 × FT4 [pmol/L] -2.7) / 0.676 (≤ -1.0 and ≤ -2.0) [48], and peripheral tissue gating via within-person free T3-to-reverse T3 amplitude (≥ 1.5 and ≥ 2.0; Fig. 1a displays four-axis totals including peripheral gating alongside central-only totals in Table 1).

Second-line buffers (Levels 3 and 4).

Tracked outside the four-axis core count: prolactin (Level 3: ≥ 20 ng/mL, amplitude ≥ 2.0, or EFLM step ≥ 3.31/≤ 0.30); IGF-1 (Level 4: within-person amplitude ≥ 1.34); and DHEA-S (Level 4: EFLM step ≥ 1.76/≤ 0.57, evaluated strictly by relative movement without raw values or cut-offs to preserve age/sex anonymity). Strongly sex-and age-dependent markers (such as testosterone and SHBG) were excluded.

Background phenotype signatures. Cross-cutting marks reported per measurement (outside core-axis counts): cold monocytes (> 600, > 500, and > 400/mm³); low mean platelet volume (below printed lower limit and < 9.0 fL with normal platelet count); white-cell synthesis economy (neutrophils < 1,700, lymphocytes < 1,100, or leukocytes < 3,700/mm³); analyzerzero eosinophils or basophils; cold D-dimer above printed cut-off; clean lipid profile (LDL > 100, HDL > 40, triglycerides < 100 mg/dL); renal mobility (creatinine > 1.20 mg/dL with return, plus creatinine and urea EFLM steps); substrate depletion (vitamin D < 30 and < 20 ng/mL; zinc-to-copper ratio < 1.0 and ≤ 0.7); and the "anti-metabolic-syndrome" block (fasting glucose, insulin ≥ 14 µIU/mL, insulin EFLM step, and HOMA-HS amplitude ≥ 2.0, excluding glucose/insulin within ±60 days of any HbA1c ≥ 5.8%). Because classical Matthews HOMA-β = 360 × insulin / (glucose -63) [49] inflates hyperbolically or becomes undefined whenever fasting glucose dips near or below 63 mg/dL-a recurring feature in HPCPh-we defined HOMA-HS (Hundred-Scaled) via a within-draw rule of three normalizing insulin to a reference glucose of 100 mg/dL (Ins@G100 = insulin × 100 / glucose) multiplied by 3.6: HOMA-HS = 3.6 × Ins@G100 = 360 × insulin / glucose, preserving HOMA-β scaling without the unstable -63 denominator singularity.

4.5. Longitudinal film, single snapshot, load hand-overs, and barcode synthesis

All frequencies are reported descriptively as n/N without inferential P values, stratified by clinical stream (longitudinal 001-021 versus consultation 022-041; Fig. 1) and osmometry availability (Supplementary Fig. S1). Over each individual's longitudinal film, a core axis counted as engaged if any of its marks appeared at least once. In single-snapshot analysis across non-inflamed draws, an axis was counted as read when ≥ 1 of its analytes was measured and active when a mark (or arriving EFLM step) occurred on that draw; co-occurrence was quantified across the 98 draws with all four core axes simultaneously read (and 81 also reading the second line). Between consecutive draws of the same individual, a release occurred when an active core axis was read and inactive on the next draw, and a load hand-over was scored when ≥ 1 other core axis was active on that next draw. Threshold returns were counted only when ≥ 1 subsequent eligible measurement existed. All 41 profiles were synthesized into a 22-row Cold-Column Clinical Barcode (Fig. 1) hiding dates and raw personal values.
