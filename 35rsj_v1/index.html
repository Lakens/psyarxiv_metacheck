Meta-scientific research has shown nonsignificant p values are commonly misinterpreted. It is incorrect to infer that there is ‘no effect’, ‘no difference’, or that groups are ‘the same’ after p > 0.05.

It is possible that there is a true non-zero effect, but that the study did not detect it. Make sure your inference acknowledges that it is possible that there is a non-zero effect. It is correct to include the effect is ‘not significantly’ different, although this just restates that p > 0.05.

Power analyses need to contain the following information to be interpretable: the type of power analysis, the statistical test, the software used, sample size, critical alpha criterion, power level, effect size, and an effect size metric. How Power Analysis Check works

This module uses regular expressions to identify sentences that contain a statistical power analysis. If specified by the user, it also uses a large language model (LLM) to extract information reported in power analyses, including the statistical test, sample size, alpha level, desired level of power, and magnitude and type of effect size.

The Power Analysis Check module uses regular expressions to identify sentences that contain a statistical power analysis. Without the use of an LLM, the module uses regular expressions to classify the power analysis as a-priori, sensitivity or post-hoc. With the use of an LLM, it checks if the power analysis is reported with all required information.

The regular expressions can miss power analyses, or fail to classify them correctly. The type of power analysis is often difficult to classify, which can easily be solved by explicitly specifying the type of power analysis as ‘a-priori’, ‘sensitivity’, or ‘post-hoc’. Note that ‘post-hoc’ or ‘observed’ power is rarely useful. The LLM can fail to identify information in the paper, and will not have access to information in paragraphs in the paper other than those that contain the word ‘power’. This package was validated by the Metacheck team on articles in Psychological Science.

How Preregistration Check works

Retrieve information from preregistrations in a standardised way, and make them easier to check.

The Preregistration Check module identifies preregistrations on the OSF and AsPredicted based on links in the manuscript, retrieves the preregistration text, and organizes the information into a template. The module retrieves text from the OSF with its API, and from AsPredicted with ResearchBox’s API when a ResearchBox key is set (see rbox_token()), or else from the preregistration’s web page. How StatCheck works

Check consistency of p-values and test statistics

The Statcheck module runs Statcheck. Statcheck searches for regular expressions that match a predefined pattern, and identifies APA reported statistical tests. More information on the package can be found at https://github.com/cran/statcheck. The module only returns Statcheck results for t-tests and F-tests, as these are the only tests which have been validated, see https://osf.io/preprints/psyarxiv/tcxaj_v1/.

Statcheck was developed by Michèle Nuijten and Sascha Epskamp.

Statcheck considers p = 0.000 an error, as you should report p < 0.001. Furthermore, p < 0.03 is an error if the p-value was 0.031, and one should simply report exact p-values (p = 0.031). When the sentence of a test says it is one-sided (“one-tailed”, “one-sided” or “directional”), a p-value that fits a one-sided test counts as consistent (statcheck’s OneTailedTxt setting; #695). When the paper says anywhere that its tests are one-sided, a p-value that fits a one-sided test in either direction counts as consistent too: half the two-sided p, or 1 minus that half for an effect against the predicted direction. Equivalence tests (TOST) are left out, as their p-values do not test the difference. A statistic written with “<” or “>” is read as a bound, and in a sentence about equal variances an F-test’s two-sided p (twice the one-tailed p) counts as consistent. For more information, see StatCheck.

This module only checks statistical results reported in the running text of the manuscript. It cannot (yet) process statistics reported only in tables.

How Exact P-Values works

List any p-values reported with insufficient precision (e.g., p < .05 or p = n.s.), reported as exactly zero (e.g., p = .000), or impossible (below 0 or above 1, e.g., p = -.22).

This module uses regular expressions to identify p-values. It will flag any values reported as p > ? or p < numbers greater than .001. It will also flag p-values reported as exactly zero (e.g., p = .000, p = 0.00), which are mathematically impossible — p-values are never exactly zero and should instead be reported as p < .001.

A p-value that is not the result of a test is not flagged: a table note (“* p < .05, ** p < .01”), a figure legend (“Asterisks indicate significant differences (p < .05)”, “Values in bold are significant at p < .05”) or a stated threshold (“p < .05 was considered significant”, “thresholded at p < .001”). GROBID often puts such notes into the running text, so each p-value is judged by the words in its own clause (the text up to a “;” or a full stop), and never left out when a test statistic belongs to it (“F(1, 7) = 8.03, # p < .05”). The column not_a_test of the table says why a p-value was left out (“marker”, “threshold”, “legend” or “named”).

A p-value with the name of a correction or a test after the p (“pFWE < .05”, “padj < 0.05”, “p Wilcoxon = .02”) is flagged only when a test statistic comes before it in its clause (“t(37) = 7.17, p FWE < .05”). Without one it is mostly the rule that decided what was significant (“genes with padj < 0.05 were selected”); such a p-value is “named” in not_a_test. Notes in other forms, such as a marker after the p-value (“p < .05 (*)“), are still flagged.

A p-value below 0 or above 1 is impossible; it is listed apart and not also as imprecise. Often the statistic before it, or its minus sign, was copied into it (“t(134) = -2.32, p = -.13”, “Z = 3.091, P = 3.091”). A value above 1 is listed only after a test statistic in its clause: without one, a “P” above 1 was nearly always another quantity (a proportion, pH, a group’s mean, a model parameter). A number in scientific notation whose power of ten was lost when the PDF was read (“p = 2.4 x 10 -9” read as 2.4) is not listed. A “p” that is the subscript of another symbol (“r p = .64”, “²p = .02” for partial eta squared, “Δp = .33”), or a quantity with a unit, a logarithm or a ratio (“P = 2.9 µm”, “-log10 P = 7.5”, “Ca/P = 1.67”), is not read as a p-value at all (see extract_p_values()). Each p-value has its own row, also when the same one is written twice in a sentence.

This module sometimes flags false positives when sentences discuss how p-value thresholds were set. It can also miss an imprecise p-value that is reported against a threshold (“decreased at the p < .05 significance threshold”).

This module only checks p-values reported in the running text of the manuscript. It cannot (yet) process p-values reported only in tables (as opposed to a table’s footnote text, which the module does see and tries to exclude — see above).

How Non-Significant P Value Check works

This module checks for imprecisely reported p values. If p > .05 is detected, it warns for misinterpretations.

The nonsignificant p-value check searches for regular expressions that match a predefined pattern. The module identifies all p-values in a manuscript and selects those that are not reported to be smaller than or equal to 0.05. It returns all sentences containing non-significant p-values.

In the future, the Metacheck team aims to incorporate a machine learning classifier to only return sentences likely to contain misinterpretations. If you want to help to improve the module, reach out to the Metacheck development team.

A p-value in a table note (“† p < .10, * p < .05”) or a figure legend (“dashed lines indicate non-significant paths (p > .05)”) is left out, as in stat_p_exact; the column not_a_test says why. A p-value next to words that state a threshold is kept, because such sentences often report a result against that level (“not significant at the conventional threshold (p = .054)”).

This module retrieves information from repositories.

The Repository Check module lists files on the OSF, GitHub, ResearchBox, DSpace (PsychArchives and other legacy- and DSpace 7-based installations), Zenodo, Dataverse, Figshare, Dryad, ReShare, 4TU.ResearchData, Mendeley Data, DataONE (Arctic Data Center, KNB, and other member nodes), and LDbase based on links in the manuscript.

A Handle link (hdl.handle.net/...) that leads to a repository read here is checked as a link to that repository ([handle_links()]).

Dryad is a special case beyond rate limits: listing a Dryad dataset’s files works without a key, but actually downloading file CONTENTS from Dryad fails with HTTP 401 unless a key is set, even for a fully public dataset (see [dryad_pat()] or [dryad_auth()]). When a linked OSF page is a registration, its registered_from project (the one it was registered from, which the manuscript itself may never link directly) is also checked: if that project is public its files are listed under its own URL, and if it is closed or otherwise inaccessible the report flags it explicitly, since some registrations only describe their content rather than mirroring it.

It is decided without a language model, from the sentence or reference that cites the link, the paper’s authors (names, ORCID iDs, affiliations), and what the deposit’s own record and files say (who made it, what it names, when, whether it is a software package; for an OSF project cited only in the reference list, its record alone). Telling this paper’s own deposit from the authors’ earlier one is less certain.

Only the deposits that are this paper’s own are checked. How Code Check works

This module retrieves information from repositories checked by repo_check about code files (R, Python, SAS, SPSS, Stata, Mplus, MATLAB).

The Code Check module checks R (also R Markdown and Quarto), Python (also Jupyter notebooks), SAS, SPSS, Stata, Mplus, and MATLAB files, using regular expressions to check the code; JASP files are listed but not read. The language of a Quarto document or a notebook is read from the file itself (its engine or kernel), not from its extension. The regular expression search will detect the number of comments, the lines at which libraries/imports are loaded, attempts to detect absolute paths to files, setwd() and install.packages() calls, and lists files that are loaded, and checks if these files are in the repository; R code is also parsed. The module will return suggestions to improve the code if there are no comments, if libraries/imports are loaded in lines further than 4 lines apart, if files that are loaded are not in the repository, if absolute file paths, setwd() or install.packages() are found, and if R code cannot be parsed.

The regular expressions can miss information in code files, or falsely detect parts of the code as a fixed file path. Libraries/imports might be loaded in one block, even if there are more than 3 intermittent lines. The module was tried out internally on papers published in Psychological Science, but has not been formally validated. There might be valid reasons why some loaded files can’t be shared, but the module can’t evaluate these reasons, and always gives a warning.

The module also checks whether the repository pins the R/package versions the analysis actually depended on: an renv.lock file (parsed for the R version and every locked package + its version/source), a sessionInfo()/sessioninfo::session_info() text dump (matched by filename — sessionInfo.txt/session_info.txt and similar, or embedded in a README), or a groundhog::groundhog.library()/checkpoint::checkpoint() date-pin call in the code (a bare library(groundhog)/library(checkpoint) does not count — the pinning call itself must be present). When none of these is found, the report flags it as a reproducibility gap: package versions may drift between when the analysis was run and any later reproduction attempt.

If you want to extend the package to perform additional checks on code files, or make the checks work on other types of code files, reach out to the Metacheck development team.

Checking code requires downloading its file contents. For a paper whose repository is on Dryad, this never succeeds unless a Dryad API key is set: Dryad requires one to download file bytes, even from a fully public dataset (listing the repository’s files does not need one). Without a key, every Dryad-hosted code file is listed but unchecked, and a warning naming Dryad and ?dryad_pat/?dryad_auth is included among the download failures recorded in the manifest.

How Data Check works

This module classifies the files in a repository into semantic types (data, codebook, code, software, output, supplemental, readme, asset, other) and, for tabular data files, extracts each column’s type and summary statistics.

The Data Check module consumes the file list produced by repo_check (or any files added via local_path). Each file is classified with rule-based heuristics layered over metacheck’s file_category() and file_types: file names matching README / codebook patterns win first, then an extension crosswalk, then format-locked extension overrides. For every file classified as tabular data that is available locally, the module reads the file head, describes each column with data_col_facets() and computes summary statistics for numeric columns. Every sheet of a spreadsheet that holds a table is read: a file with several such sheets has its columns under source_file = "file.xlsx [sheet]", and the sheet column names the sheet of any spreadsheet with several sheets; a sheet of notes or a codebook is treated as documentation when the file has another table. Following DDI, a column is described by orthogonal facets rather than a single type: representation (numeric/text/datetime/code — how it is stored), measurement_level (Stevens: nominal/ordinal/interval/ratio), concept (what it measures: reaction_time/age/gender/likert/id/…), role (identifier/measure/condition/timestamp), unit, and a quality state (ok/empty/constant). Concepts are detected by name+value rules (the demographic concepts via data_check_demographic()); when llm_use(TRUE) the model fills concepts and measurement levels the rules left blank. Qualtrics survey exports are recognised (data_check_is_qualtrics()): their extra header rows are stripped so columns type correctly, and the reserved response-metadata columns (StartDate, Duration, Finished, …) are tagged.

The module defaults to rules-only when llm_use(FALSE): columns the rules cannot resolve (ambiguous 3–20-unique integers, ambiguous character columns) fall back to continuous / text respectively. When llm_use(TRUE), ambiguous columns and unresolved file types (other) are sent to llm() for optional refinement, and every file is assigned a study group (ex1, pilot2, shared, …) so that multi-study repositories can be recognised (used by psychds_check). Without an LLM the study group is left NA (unknown).

Column extraction requires files to be readable from disk. Files fetched by repo_check from OSF/GitHub/etc. without a local copy (file_location is NA) are classified but not column-extracted; pass local_path to point at a downloaded copy of the repository.

For a paper whose repository is on Dryad, this means column extraction never happens unless a Dryad API key is set: Dryad requires one to download file bytes, even from a fully public dataset (dataset listing and metadata do not need one). Without a key, every Dryad file stays classified but un-downloaded, column_n is 0, and a warning naming Dryad and ?dryad_pat/?dryad_auth is included among the download failures. A one-time session message is also shown (see repo_check) the first time a Dryad dataset is encountered with no key set.

Every downloaded text file the authors wrote (code, settings, survey definitions such as Qualtrics .qsf files, documentation, outputs) is searched for keys: API keys, access tokens and private keys, which let anyone who downloads the file use a paid service at the authors’ cost. Of a tabular data file only the column names and first 3 rows of the table as read are searched: its values come from participants, but a key the authors set for a whole survey (as embedded data in a Qualtrics survey flow) is exported in every response. The search uses the rules of the secret scanner betterleaks (https://github.com/betterleaks/betterleaks, MIT licence) of high and medium confidence. A key found turns the traffic light red; the report and the keys table give its file, line and type, and only its beginning. Other files over 25 MB and binary files are not searched. A key is never tested with its provider. Every module’s result has any whole key replaced by “keyremoved” (see module_run()).

How Reproducibility Check works

This module assesses whether a paper’s R and Python code can be run on its data. It works in two phases. The static phase (always run) collects the package dependencies the code declares, rewrites the data-file paths that do not work in the repository as the authors organised it, works out the order the scripts must run in, and diagnoses why any referenced input file is unavailable — reporting what a reproduction attempt would involve and where it is likely to break. The execution phase (opt-in, execute = TRUE) then actually runs the code: it copies the repository into a throwaway directory, optionally installs the declared dependencies into a throwaway library, runs each script in order in an isolated subprocess with a per-script timeout, and captures the outcome and full output of each run.

By default (execute = FALSE) the module does not run any code — it performs only static analysis: reading dependencies with the same extractors as code_check, finding the files the code references in the repository, and building a run-order dependency graph. It reports what would be installed and run rather than doing it.

When execute = TRUE, the module additionally runs the downloaded code on your machine — a deliberate, opt-in action gated behind that argument (callr is required for R code). Each script runs in an isolated subprocess so a crash cannot take down the R session; note this isolates crashes, not the filesystem or network. Installs (when install_missing = TRUE) and the throwaway run library never touch your main R library. Each script’s outcome is one of ran_ok, errored, timed_out, dependency_unavailable, not_parsed, run_by_source (an R script another script runs with source(), which is run only inside that script, since on its own it lacks the packages and objects the sourcing script sets up first), run_by_import (a Python file other files import, a module rather than a script, unless it has an if __name__ == "__main__": block), jags_model (a JAGS or BUGS model saved with an R extension, which another script reads) or not_r_content (a file that is not R at all, such as a JSON or HTML dump); these last two are not run and are not failures. python2 marks Python 2 code that was not run. With sandbox = "docker" such code runs with Python 2.7 (option metacheck.docker_image_py2; FALSE turns this off), which modifications records; it is never converted, since that can change results. defines_functions is a file that only defines functions, which is used, not run (table$used_by names the scripts that use it), and not_analysis is a file of software rather than of the analysis: a package’s code, tests, documentation or setup.py, a copy of a tool, a web application, a script a program wrote (table$not_analysis_why says which); neither is run or counted as a script. docker_failed means the container never started, which says nothing about the script, so it keeps the light from being green but does not make it red. needs_a_person is a script that stopped because it asks a person to choose a file or answer a question, or that starts an app, and needs_internet one that stopped because the network is off in a Docker run, or, with internet = TRUE, could not reach what it asked for; download_too_large is a script stopped for downloading more than the limits allow (see internet), and out_of_memory one that, or a program it started (such as a compiler), ran out of the memory each script may use. All four are treated the same way. not_downloaded is a script that stopped on a file the repository lists but that was not downloaded, such as one over max_file_size: it could not be tried, so it is not counted as a script that did not reproduce (summary_table$repro_not_downloaded_n counts them apart). not_read is a file metacheck could not read, so it was not run; the light is then not green, as the file may read and run on another computer, and table$error_message says why, naming a package that is installed but cannot be loaded on the computer that ran the check. empty is a file with nothing in it, which is not run or counted as a script. For a script that did not run through, table$error_message is its error, short (at most 300 characters): the error line of its output, which names a package that is not there, with the address it asked for when it needed the internet, or the time limit it reached; table$reason sorts it into a kind. A timeout means “still running at the cutoff”, not a failure, so raise timeout for legitimately long-running (e.g. Bayesian) scripts. dependency_unavailable means the script’s own package could not be installed from live CRAN, the CRAN Archive, or a named GitHub/URL source — an infrastructure limitation, not a defect in the paper’s code. The full stdout/stderr of every run is kept in the result’s run_results (the report shows it in per-script dropdowns, capped for readability).

Provenance, kept so that a TRACE Research Object (TRO) declaration of the run can be written later from a stored result (metacheck #404; the helpers are in R/provenance.R). Only when code was run (execute = TRUE): * run_results$started_at, run_results$ended_at: when each run of a script started and ended (ISO 8601, UTC, milliseconds); NA for a script that was not started. A script run again in a later pass has the times of its last run. A TRO uses them for each trov:TransparentResearchPerformance. * run_results$exit_status: the exit status of the process that ran the script (0 = ended normally); NA when the process did not report one (a time limit, or Docker failing to start the container). * artifacts: one row per file, with stage (deposit: as downloaded from the repository, hashed from the downloaded file; before_run: the run folder just before the first script ran, after metacheck’s own changes, such as rewritten paths and unpacked archives; after_run: only the files the scripts made (status new), changed (changed) or removed (removed), as an unchanged file is the one listed before the run), path (relative to the run folder, as valid UTF-8, a byte of another encoding written as <xx>), size (bytes), sha256, mime_type (by extension, NA when unknown), source (the file’s address in the repository, for deposit). The package libraries metacheck installs in the run folder are left out, as are metacheck’s own files there (a script’s runner, and the statistical output it writes in statistical_output/). Files metacheck itself copied or made between passes (see modifications, output_copied, file_placed) show in after_run too. A TRO uses the rows as trov:ResearchArtifacts and each stage as a trov:ArtifactArrangement. * modifications$sha256_before, modifications$sha256_after: the hash of the changed script as downloaded and as it ran; NA when the script is not at the same path in both (a script made from an R Markdown file). * environment: the system that ran the code (trov:TransparentResearchSystem in a TRO): metacheck_version, started_at, ended_at, host (R version, platform, operating system), sandbox, network_isolated (TRUE only when every Docker run had --network none; the process sandbox does not stop the network), internet, timeout_per_script, total_timeout, python_local (the Python run outside Docker and its version), and docker: runs (for each kind of run, r_run, r_install, python_run, python_install, the image and the docker run arguments, such as --network none, --read-only, --cap-drop ALL, no-new-privileges, the process limit and the memory and processor limits) and images (for each image, its ID and digests from docker image inspect, its creation time and the R and Python versions its environment declares).

run_results$checked says what the run of each script shows about the code, in five groups, so that a script that does not reproduce is kept apart from one the check could not test: ran (it ran to the end); code_error (it did not reproduce: it stopped with an error of the code or the deposit, could not be read, or needs a file the deposit does not hold); dependency (a package or program was not available: a package that could not be installed or was not loaded, a program outside R and Python, a system library, or R crashing in a package’s compiled code); time (it did not finish within the time limit for one script, or was not started because the time for all scripts had run out); and not_checkable (it could not be checked automatically: it needs a person, the internet, a key or another setting of the authors’ computer, one platform such as Google Colab, Windows or OpenSAFELY, more memory than the run allows, a file that was not downloaded, a screen, or a program that runs it, or it is a file of a package of the code that Python runs only as a module of that package). It is NA for files run inside another script, files that are not an analysis, files not read, and a Docker failure. summary_table counts each group (repro_ran_n, repro_code_error_n, repro_dependency_n, repro_time_n, repro_not_checkable_n), and the report’s first sentence gives them. The traffic light reflects the static readiness signals by default; a script in code_error that stopped with an error makes it red, as a script that crashes on its own analysis is a genuine reproduction failure, and a script in one of the other three groups keeps it from being green. Calls that need a screen, which the run does not have (dev.print(), dev.copy2pdf(), dev.copy2eps(), savePlot(), windows(), win.graph(), x11(), quartz(), View()), are replaced before the run by calls that need none, which modifications records as screen_call_replaced. A script that fails with could not find function is run once more with the library() calls the project’s other scripts make added at its top (or the one package that exports the function, or magrittr for %>%), and a script that then runs is reported as reproducible only after that repair.

Dependencies are reported name-only, with the source (CRAN, GitHub, or a base package already shipped with R) — static analysis of the code cannot know which version was used, and running against current package versions is itself informative: a break argues the authors should have pinned versions. When the repository does record versions, a run with recorded_versions = TRUE installs the packages the scripts load at those versions, but it does not change the R version, which remains a limitation of the check.

Run order is derived from read-after-write data dependencies (a script writing a file another reads must run first), source() edges, and numeric filename prefixes as a weak tie-breaker. Ambiguous orderings, dependency cycles, and inputs a script reads but that no earlier script produces (and that are not in the repository) are surfaced as warnings, since these are the situations most likely to make an otherwise-correct reproduction fail.

Python code (.py files, and notebooks and Quarto documents whose code is Python, from which the code is extracted first) goes through the same two phases, reported in its own “Python code” section. Each file is checked for syntax errors with Python’s own parser when a Python interpreter (python, or else python3) is available; dependencies are read from the import statements, with versions from a requirements.txt or pyproject.toml when there is one, and installed with pip; each script runs as its own python process (processx is required), so unlike R scripts, a name one script defines is not available to another. When no Python interpreter is available, the Python files are reported as not run and the R results are still returned. Statistics the Python scripts print are compared with the paper together with the R output and any self-reproducible output (JASP/jamovi, SPSS-Viewer, notebook outputs).

Abstract

Wellbeing is central to public health and policy. Yet, it remains unclear whether sources of wellbeing differences are similar across populations worldwide. We investigated genetic and environmental influences on wellbeing using standardized classical twin models across 20 cohorts from 18 countries (N = 122,418 twins; 19,848 complete monozygotic and 29,037 complete dizygotic pairs). Estimates across cohorts were combined in meta-analyses. The pooled heritability estimate was 36% (95% CI: 35-37%), indicating moderate and broadly consistent genetic influences across diverse populations. However, estimates varied substantially between cohorts (18-77%). Exploratory analyses suggested that heterogeneity was partly related to mean cohort age (b = -0.004, p = .047). The estimate was higher (41%; 95% CI: 40-43%) and less heterogeneous among cohorts using the Satisfaction with Life Scale.

Heritability did not differ between W.E.I.R.D. and non-W.E.I.R.D. countries (36% and 33% respectively). These findings highlight both cross-population similarity and contextdependence among sources of individual differences in wellbeing.

Introduction

The interest in studying wellbeing dates back to ancient Greece, where philosophers were already concerned with what a "good life" entails [1, 2]. Although different words and expressions are used interchangeably to describe feeling and functioning well, the conventional term among social and psychological scientists is wellbeing. Despite philosopher's early interest in the topic, the study of wellbeing by behavioral scientists is relatively recent and most of the advances in the field occurred in the last five decades [1] [2] [3]. Evidence from diverse lines of research demonstrates that wellbeing is associated with many positive outcomes [4], including social relationships [5], income and wealth [6, 7], age [8], health [9] and later age survival [10]. Moreover, the recognition that building wellbeing is as fundamental as responding to illness has spurred initiatives to integrate wellbeing into mental health policies worldwide. Nowadays, wellbeing is used as a metric to evaluate new policies in many countries.

While the EU Council of Ministers and the OECD vouch for the inclusion of wellbeing at the center of policy design, Australia [11], New Zealand [12], and Norway [13] have already implemented a wellbeing budget. To include wellbeing in the center of policy, it is important to understand the sources of individual differences in wellbeing, including whether these vary across populations worldwide.

Wellbeing is a broad construct that can be defined as feeling good and functioning well [14], and is often divided into hedonic and eudaimonic wellbeing [15]. Hedonic wellbeing, also referred to as subjective wellbeing, concerns how individuals perceive their lives based on emotional and cognitive aspects and includes measures of life satisfaction and positive affect [16, 17]. Eudaimonic wellbeing or psychological wellbeing refers to how an individual functions in life, including measures of self-realization and personal development [18].

Research shows strong phenotypic-and genetic correlation between subjective and psychological wellbeing [19] [20] [21]. Moreover, different aspects of subjective wellbeing share a common genetic factor [22, 23] and different measurement instruments are used to assess those [24, 25]. Therefore, in this manuscript, we refer to wellbeing as an umbrella construct that includes both subjective-and psychological wellbeing measures.

People differ in their levels of wellbeing, and these differences reflect both genetic and environmental influences. Meta-analyses of classical twin studies point to a heritable component of wellbeing of around 40%, indicating that a large part of the differences in wellbeing between people can be explained by genetic factors [26, 27]. The remaining variance is accounted for by environmental differences between people. However, these estimates are mostly based on European samples and particularly from W.E.I.R.D. (Western, Educated, Industrialized, Rich, and Democratic) countries [28]. Because heritability is a populationspecific estimate that depends on both genetic and environmental variation, populations in different countries may show a different balance of genetic and environmental influences on wellbeing. Research on other phenotypes demonstrates that different environments may enhance or reduce genetic influences. For example, twin studies in populations of different socioeconomic status (SES) show that, in contexts with higher equality, genetic factors explain a larger proportion of the variance in educational outcomes, while in more unequal contexts, the variance is explained to a greater extent by differences in SES and the heritability is lower [29]. Thus, heritability estimates can vary as a function of the environment. As to wellbeing, studies have shown that heritability estimates differ by SES [30], marital status [31], and parental divorce [32].

Due to the predominance of European samples, the generalizability of findings from classical twin studies to other populations may be limited [33]. A recent study [34] estimated the heritability of wellbeing globally. Relying on simulated data, worldwide heritability of 31% to 32% for SWB was reported. Unique environmental factors accounted for 46% to 52% of the variance (including measurement error), while shared environments explain 16% to 23% of the global variance in SWB. In this particular study, wellbeing is somewhat less heritable than it is within individual countries. And unlike earlier within-country studies, they observed a notable contribution of shared environments. As a next step real data of different countries should be analyzed jointly. If environmental contexts can influence the genetic architecture of wellbeing, expanding twin research across the globe [35] is valuable both to test whether heritability estimates vary across populations and to assess whether estimates derived from W.E.I.R.D. samples generalize more broadly. Understanding these differences can clarify how genetic factors and population-specific environments shape wellbeing, helping to build a more nuanced understanding of wellbeing worldwide.

In the current study, we investigated the relative influence of genetic and environmental factors on wellbeing across the world. Using a standardized classical twin design across 20 cohorts spanning all continents except Africa, each cohort fitted models to estimate genetic and environmental influences on wellbeing, after which results were combined in a meta-analysis to derive a worldwide heritability estimate of wellbeing. Given the strong phenotypical and genetic correlation among different aspects and measures of wellbeing and to maximize sample size, the primary phenotype definition for the present study included a broad array of wellbeing measures, treating them as measures of the same underlying construct.

Methods

Participants

Twin cohorts across the world were invited to participate. A total of 39 study cohorts were contacted. Participating and invited cohorts were grouped according to the geographical region of the registry/country of origin. Most of the invited cohorts were based in Europe (17 twin cohorts), followed by Asia (7 twin cohorts), North America (6 twin cohorts), Oceania (3 cohort studies), Africa (2 twin cohorts), and South America (1 twin cohort). A list with the invited twin cohorts is available in Supplementary Materials (see Table S1). The criteria for inclusion were to have available wellbeing data for both monozygotic (MZ) and dizygotic (DZ) twins, as well as information on age and country.

Twenty cohorts (51% of invited cohorts) from 18 countries provided data and were included in the current study. The included cohorts were mainly of European Ancestry (North America and Europe;) 15 twin cohorts), followed by Asian (3 twin cohorts), and Latin American (2 twin cohorts). The final total sample was composed of 122,418 twins (19, 848 complete MZ twin pairs and 29,037 complete DZ twin pairs) ranging from 7 to 97 years of age and with 57% females (see Table 1). A description of each study cohort is included in the Supplementary Materials (See Description of the Cohort Studies). Data collection protocols in all countries were approved by their respective ethics committees.

Wellbeing Measures

As wellbeing was assessed using different instruments across cohorts, we selected the most commonly available measures to maximize sample size while reducing heterogeneity in phenotype definition. Ten of the study cohorts (50%) collected data using the Satisfaction with Life Scale [36], two study cohorts (10%) used the reduced version of the World Health Organization Quality of Life Scale [37, 38], and the remaining study cohorts had access to other wellbeing measures (see Table 2 for the details).

Analyses

The study and analysis plans were preregistered at https://osf.io/rwfy2/. The study cohorts received a Standard Operation Procedure (SOP) that contained a detailed explanation of the objective, background, phenotype of interest and instructions on how to conduct the data analysis (see Supplementary Materials). To facilitate and unify the format of analyses across all participants, OpenMx scripts [39], and example data were included in the SOP. After all cohorts shared the results of their data-analysis, a meta-analysis was performed to estimate the worldwide heritability of wellbeing.

Univariate Twin Modeling

An estimation of the genetic and environmental variance of a trait is possible by comparing the phenotypic covariance of a trait within MZ twin pairs to the covariance within DZ twin pairs [40]. The genetic variance component includes additive genetic variance (A), the variance explained by independent effects of alleles on the phenotype, and non-additive genetic variance (D), such as allelic dominance or epistasis (i.e., gene-by-gene interactions). The environmental variance components are the shared environment (C), the variance explained by the effects of the environment that an individual shares with family members (both MZ and DZ twins) and the non-shared environment (E), which corresponds to the variance explained by unique environmental effects experienced by an individual. Since C and D effects cannot be estimated together in the classical twin model, the observed twin correlations inform to include C or D in the estimated model. If the DZ correlation (rDZ) is more than half the MZ correlation (rMZ), there is evidence for an ACE model. If the rDZ is lower than half the rMZ, an ADE model is more likely [41]. The statistical analyses were performed using OpenMx in R, version 3.6.3 or higher [42].

Means, variances, and covariances were estimated in a saturated model for each sample separately. If data were available for both males and females, the sample was segregated into five (or four) different zygosity groups: MZm (monozygotic male), DZm (dizygotic male), MZf (monozygotic female), DZf (dizygotic female), and DOs (opposite sex twins) when Dos was available. Age was included in the model as a covariate on wellbeing means. Next, quantitative sex differences were tested by constraining the correlations between same-sex male and female twins to be equal. If the sample size did not allow the division into five groups, the analysis was carried considering only MZ and DZ twins and sex was included in the model as a covariate on wellbeing means.

Next, sources of individual differences were estimated using the classical twin model where individual differences in wellbeing estimates were decomposed in genetic and environmental variance using structural equation modeling (SEM) as implemented in the software package OpenMx, version 2.17.2. (or higher). Models were fitted to the raw data using full information maximum likelihood [39]. To test sub-models, likelihood-ratio tests (LRT) were performed in which a more restricted model was compared to a more general model. The negative log-likelihood (-2LL) of the more restricted model is subtracted from the -2LL of the more general model. The test provides a χ2 statistic distributed with degrees of freedom (df) equal to the difference in number of parameters between the compared models. Given the large sample sizes and the number of tests, we used a more stringent significance threshold of p < .01 to reduce the likelihood of false-positive findings. If there was no significant difference, the more restricted model was selected as the most parsimonious model and used for comparisons with next model(s) [41]. Ninety-five percent confidence intervals were calculated for the parameter estimates of the best fitting model. To verify the goodness of fit and the parsimony of the models, Akaike's Information Criterion (χ2-2df) was calculated and compared [43]. A lower AIC value indicated a better fit of the model relative to the data observed in the study.

Meta-analysis

The preregistered meta-analysis was performed in R (version 4.0.4 [42]) using the R package Metaphor [44]. For two cohort studies for which an ACE or ADE model was identified as the best fitting model, we included their AE model results for consistency.

Similarly, for two cohort studies that fitted models with four groups (male-female / monozygotic -dizygotic same sex) or five groups (+ dizygotic opposite sex), and for which the best fitting model was not an AE model, we included the best fitting AE model (i.e., the AE model with or without sex differences, depending on fit).

To estimate the overall heritability estimate of wellbeing, we performed a preregistered fixed-effects meta-analysis using the results from all 20 cohorts. In a fixed-effects metaanalysis, the observed effect sizes of each study are assumed to share a common effect size, and between-study differences are attributed to within-study sampling error. Under this model, studies are weighted by the inverse of their sampling variance, such that more precise estimates (typically from larger samples) contribute more strongly to the pooled estimate. The pooled estimate is calculated as the weighted mean of the study-specific effect sizes [44, 45].

To evaluate potential heterogeneity, the Q -statistic and the I² -index were calculated.

The Q -statistic is computed based on the sum of the squared deviations of each study's estimate from the overall estimate of the meta-analysis. Each study is weighted by the inverse of the variance, in the same fashion as in the meta-analysis. A heterogeneity test is then performed by calculating a p-value based on a comparison of the obtained statistic with a χ2 distribution with k-1 degrees of freedom, where k is the number of studies [46]. A p-value higher than .05 indicates no evidence of heterogeneity being present.

The I² -index measures the degree of inconsistency in the results of the meta-analysis by describing the percentage of total variation across studies that is accounted for by heterogeneity.

The I² -index is obtained based on the Q-statistic and the degrees of freedom where I² equals Q minus the degrees of freedom divided by Q. The result is multiplied by 100 to be displayed as a percentage. The I² -index varies from 0% to 100% (negative values are considered null). While values above 75% indicate high heterogeneity, values around 50% suggest moderate heterogeneity and values below 25% point to no observed heterogeneity [47].

Non-Registered Analyses

To investigate potential sources of heterogeneity, we performed additional non-preregistered exploratory country-level estimates, sub-group analyses (W.E.I.R.D. vs non-W.E.I.R.D.), stratified analyses, and meta-regressions. For the country-level estimates, subgroup analyses and meta-regressions, random effects models were included as well. The random effects model accounts for the possibility that there are other variables having an influence on the main studied variable. In the random effects model, the estimates of each study are weighed by the inverse of its total variance which is based on within-study variance (sampling variance) and between-study variance. The random pooled estimate is weighted based on the inverse of the sum of within-study variance and the between-study heterogeneity [44, 45].

Country-level estimates. First, we repeated the main meta-analysis using estimates based on two group models (MZ vs. DZ twins) only. When multiple cohort-specific estimates were available within a country, these were first pooled to obtain a single country-level estimate.

Subgroup analyses.

Because cohorts from W.E.I.R.D. [28] populations were overrepresented, we conducted a sub-group analysis comparing fourteen W.E.I.R.D. and six non-W.E.I.R.D. cohorts. As a sensitivity analysis, we evaluated effects of outliers and influential cases within each sub-group.

Stratified analyses.

We included sex-stratified analyses (male and female specific) with estimates from the study cohorts that fitted sex-specific twin models. Similarly, we conducted an analysis restricted to cohorts that assessed wellbeing using the Satisfaction with Life Scale, to examine whether the use of a common instrument affected the pooled heritability estimate.

Meta-regressions.

Given the difference in mean age of the cohorts present in the study, we conducted a meta-regression including cohort mean age as a covariate. Finally, to examine whether broader country-level context was associated with variation in heritability estimates, we conducted meta-regressions including the Human Development Index (HDI) [48], and its sub-dimensions life expectancy at birth (LEB), mean years of education (MYE), and gross national income per capita (GNI).

Results

Descriptives

Twenty study cohorts from 18 different countries returned results. Thirteen cohorts provided results based on both two groups (MZ and DZ twins) and sex-specific models (MZ female, MZ male, DZ female, DZ male, and, if available, DZ opposite sex). Seven smaller study cohorts shared results of twin models based on two groups, i.e., MZ and DZ twins. The estimates for the mean and variance of the wellbeing measures for males and females (13 study cohorts), and for total group (males plus females; 7 study cohorts) can be found in the Supplementary Materials (See Table S2). In addition, the correlations between the MZ male and DZ male twins and the MZ female and DZ female twins (for the 13 cohorts that used the twin model based on the four or five groups), and the correlations between the MZ and DZ twins (for the 7 cohorts that used the twin model based on two groups) with the respective indicated ADCE selected model are available in Table S3.

The model comparison results are shown in Table 3. For 16 study cohorts the best fitting model was an AE model, including only additive genetic effects (A) and unique environmental effects (E). Two study cohorts (Germany and United Kingdom) reported an ACE model (additive genetic effects, shared-and unique environmental effects) to be the best fitting model and only one study cohort (Norway-1) reported an ADE model (additive-and dominance genetic effects and unique environmental effects) to be the best fitting model (See Table 3).

One study cohort had issues with fitting the best fitting model in OpenMx (Sri Lanka) and for this reason the AE results, which are plausible, were considered. Out of the 13 study cohorts that provided estimates from males and females, nine observed sex differences in the estimates of men and women while four observed no sex differences.

The estimates for the genetic and environmental effects based on the best fitting model for each cohort are shown in Table 4. Estimates of the heritability of wellbeing ranged from 18% (95% CI: 6-29% for Germany) to 77% (95%CI: 65-85% for Michigan, USA). Estimates outside of Europe included lower heritability estimates (i.e., below 30% for Brazil, Japan, Mexico, and Sri Lanka). The highest heritability was found in the USA (i.e., above 60% in Michigan and Wisconsin).

Among cohorts for which sex-specific estimates were available, heritability estimates for women were often higher than those for men based on a parsimonious AE model for all cohorts. However, differences should be interpreted with caution, as male estimates were often less precise (wider confidence intervals), and confidence interval overlap was sometimes asymmetric (e.g., the female estimate fell within the male CI, whereas the male estimate fell outside the female CI). Similarly, heritability estimates from cohorts of adolescents and young adults were generally higher than those from cohorts of middle-aged and older adults.

Meta-analysis

The results of the meta-analysis, which considers the heritability estimates based on the best AE fitting model, can be found in Figure 1. Cohorts without sex differences or that only performed the model with two groups are shown as "MALES + FEMALES," whereas cohorts with sex differences contributed separate estimates for females ("FEMALES") and males ("MALES"). The weighted average estimate for the (broad) heritability of wellbeing was 36% (95% CI: 35-37%). Heterogeneity across estimates was substantial (Q = 289.51, df = 29, p < .001, I² = 90.0% variability).

Exploratory analyses

Given the high heterogeneity observed, we performed additional analyses to explore why the heritability estimates of wellbeing varied across countries.

Country-level estimates. At the country level (pooling multiple cohorts within

Norway and the USA), the fixed-effects pooled heritability estimate across 18 countries was 36% (95% CI: 35-37%), with substantial heterogeneity (Q = 261.66, df = 17, p < .001; I² = 93.5%); the random-effects estimate was 37% (95% CI: 32-42%). See figures 2 and 3 for an overview.

Subgroup analyses. The W.E.I.R.D. vs. non-W.E.I.R.D. subgroup analysis showed no statistically significant between-group difference (Q-Between = 3.16, df = 1, p = .076), although pooled estimates were somewhat higher in W.E.I.R.D. cohorts (fixed: 36%, 95% CI: 35-37%; random: 39%, 95% CI: 33%-46%) than in non-W.E.I.R.D. cohorts (fixed: 33%, 95% CI: 29-36%; random: 32%, 95% CI: 25%-40%) (see Figure 4). Given the high within group heterogeneity, we performed sensitivity analyses excluding outliers and influential cases and observed that the between-group difference became significant (see Sensitivity Analyses Tables A and B).

Stratified analyses.

In the 13 cohorts with sex-specific estimates, pooled heritability estimates were 38% (95% CI: 36-39%) for females and 34% (95% CI: 32-36%) for males (see Figures S1 and S2). Restricting analyses to 11 cohorts using the Satisfaction with Life Scale resulted in a pooled heritability estimate of 41% (95% CI: 40-43%), with lower heterogeneity than in the main analysis (Q = 100.77, df = 16, p < .001; I² = 84.1%; see Figure S3) Meta-regressions. Mean cohort age was negatively associated with heritability estimates (b = -0.004, p = .047) and explained 22% of heterogeneity (See Figure S4). HDI and its sub-dimensions (life expectancy, mean years of education, and gross national income) were not significant moderators (all p > .050, see Table S4).

Discussion

In this global twin study including 20 cohorts from 18 countries, and ~50,000 complete twin pairs, we found that wellbeing is moderately heritable, with a pooled heritability estimate of 36% (95% CI: 35-37%). This estimate is consistent with previous meta-analyses [26, 27], and, importantly, shows substantial similarity across a wider set of populations than has typically been studied. Most cohorts identified an AE model as the best fitting model, indicating that additive genetic and unique environmental influences explain most of the variation in wellbeing, and that the shared environment seems less important. Heritability estimates did range across cohorts from 18% (95% CI: 6-29%) in Germany to 77% (95%CI: 65-85%) in Michigan, USA. Furthermore, the heterogeneity was high. Exploratory analyses suggested that part of this heterogeneity was related to cohort characteristics, including age and wellbeing measurement instrument, whereas macrolevel national indicators, including life expectancy, mean years of education, and gross national income, did not significantly explain betweencohort differences. Overall, these findings suggest that a moderate genetic contribution to wellbeing is a robust and broadly shared pattern across the world, while the relative balance of genetic and environmental influences varies across populations and contexts.

Beyond the pooled estimate, an important contribution of this study is that it provides the first coordinated global comparison of twin-based heritability estimates for wellbeing using standardized analyses across 20 cohorts in 18 countries. While most of the cohorts were still from European-ancestry populations (15 study cohorts), the inclusion of Asian (3 study cohorts), and Latin American twin cohorts (2 study cohorts) adds diversity and supports the broadly similar heritability of wellbeing across more diverse populations. At the same time, this design also allows evaluation of meaningful variation in estimates across cohorts.

Heterogeneity in heritability of wellbeing across the world

Across most European ancestry cohorts, heritability estimates were in the range of 30-40%, closely matching earlier estimates derived primarily from Western samples [26, 27] and the heritability of wellbeing globally based on simulated data [34]. Despite the substantial variation across cohorts, the central pattern was one of convergence with previous findings.

We did observe variation, with some of the highest estimates in North American cohorts (60-77%) and lower estimates in several cohorts from Asia and Latin America (<30%). These descriptive patterns should be interpreted cautiously because of sample sizes, but they show the importance of testing the generalizability of behavioral genetic findings beyond the populations in which they have most often been studied. The substantial heterogeneity observed across cohorts is consistent with the idea that heritability is context-dependent [49] [50] [51]. In subgroup analyses, pooled heritability estimates were somewhat lower in non-W.E.I.R.D. cohorts (h2 = 33%, 95%CI: 29-36%) than in W.E.I.R.D. cohorts (h2 = 36%, 95%CI: 35-37%). However, confidence intervals overlapped, and this difference was not statistically significant. In sensitivity analyses excluding outliers and influential cases, the difference became significant. These findings should be interpreted cautiously given the smaller number and lower precision of non-W.E.I.R.D. cohorts.

Nevertheless, the pattern is consistent with potential environmental moderation, in which contextual conditions may influence the extent to which genetic predisposition affects wellbeing [49, [51] [52] [53].

To examine whether broader societal conditions could account for differences in heritability estimates across countries, we conducted meta-regressions using the Human Development Index (HDI) and its subdimensions (life expectancy, mean years of education, and gross national income per capita). None of these indicators significantly explained heterogeneity in heritability estimates. This suggests that the relevant contextual moderators may not be well captured by broad macro-level development indicators. Instead, other features of the environment, such as cultural norms, social relationships, stress exposure, inequality, or opportunities for autonomy and participation, may play a more important role in shaping genetic influences on wellbeing.

Differences in wellbeing measurement did appear to contribute to heterogeneity. We used a standardized analytical approach, but cohorts differed in the instruments used to assess wellbeing. When analyses were restricted to the 11 cohorts using the Satisfaction with Life Scale (SWLS), the pooled heritability estimate increased slightly to 41% (95% CI: 40-43%) and although heterogeneity was reduced, it was still substantial. These findings highlight the importance of phenotype definition in cross-cohort behavioral genetic research, but also support the assumption that different wellbeing instruments capture overlapping aspects of a broader underlying wellbeing construct [21, [54] [55] [56] [57] Age did also explain part of the heterogeneity of heritability estimates. Mean cohort age was negatively associated with heritability estimates in meta-regression analyses. Cohorts including adolescents and young adults showed higher heritability estimates than cohorts including middle-aged or older adults. These developmental patterns in the heritability mirror those found in personality traits [58, 59], indicating a degree of shared etiology of wellbeing and personality [60] [61] [62]. One possible interpretation is that non-shared environmental influences (e.g., health events, life transitions, or cumulative stress exposure) become increasingly important for wellbeing later in life, thereby reducing the relative contribution of genetic factors (see also de Vries et al. [63] and Skaug et al. [64] ). However, we cannot rule out that the observed age effect may be influenced by the decision to perform an AE model meta-analysis.

Particularly in young cohorts where C is present, the use of an AE model may inflate the estimates of A. Assortative mating may further complicate this interpretation. For wellbeing, studies have reported spousal similarity in life satisfaction, but such resemblance may reflect phenotypic assortment, shared social background, partner influence, or shared environments [65, 66] Finally, we observed a small difference in the heritability estimates in females (38%, 95% CI: 36-39%) compared to males (34%, 95% CI: 33-36%). Variation in the heritability of wellbeing by sex has been reported previously [67, 68]. However, sex differences in the present study should be interpreted with caution. Male estimates were often less precise due to smaller male sample sizes, resulting in wider confidence intervals and asymmetric confidence interval overlap in some cohorts. Larger and more balanced samples will be important to clarify whether sex differences in the genetic and environmental architecture of wellbeing are robust across populations.

Strengths, limitations, and future directions

This study has several strengths. First, it represents a large coordinated global metaanalysis of twin-based heritability of wellbeing, including more than 120,000 individuals across diverse countries. Second, the use of standardized analytic procedures provided via a SOP across cohorts improved comparability and reduced methodological variation due to analytic decisions. Third, although still limited (25%), the inclusion of Asian and Latin America cohorts increased the diversity. Together, this provides a strong foundation for examining both shared and context-specific patterns in the genetic and environmental influences on wellbeing worldwide. However, despite including cohorts from multiple continents, our sample did not include representation from Africa, and no wellbeing data were available from twin cohorts with African participants. This limits the global generalizability of our conclusions and shows the need for greater investment in behavioral genetic research infrastructures outside overrepresented regions. In addition, sample sizes for non-W.E.I.R.D. cohorts were generally smaller than those for W.E.I.R.D. cohorts, reducing precision and limiting power to detect subgroup differences and moderators. More globally balanced datasets are needed to test whether observed differences are robust and to better characterize cross-population variability.

Furthermore, although we standardized the analytic procedure, wellbeing was assessed using multiple instruments across cohorts. As in previous meta-analyses, differences in constructs, item content, time frames, and psychometric properties may have introduced conceptual and measurement heterogeneity. Our restricted analyses of Satisfaction with Life scores only support this interpretation, as this resulted in a higher heritability estimate and lower heterogeneity. Finally, cross-cohort differences may partly reflect differences in sampling strategy, assessment, and cohort composition rather than only true population-level differences in the genetic and environmental determinants of wellbeing. Classical twin models also rely on assumptions that vary across cohorts, including equality of means across zygosity groups and random mating. Future extended twin-family studies including parental and spousal data would help test these assumptions more directly.

Conclusion

This coordinated global twin study indicates that wellbeing is moderately heritable across populations, while also showing heterogeneity in heritability estimates across cohorts and countries. These findings reinforce that heritability is not a fixed property, but a populationand context-dependent parameter. Future research should expand representation in global behavioral genetics, particularly in underrepresented regions such as Africa, and incorporate more precise contextual measures to identify which environmental factors shape the influence of genes on wellbeing. Continued international collaboration, standardized analyses, and open data-sharing efforts will be needed to build a more inclusive and globally representative science of wellbeing genetics.
