How Power Analysis Check works

This module uses regular expressions to identify sentences that contain a statistical power analysis. If specified by the user, it also uses a large language model (LLM) to extract information reported in power analyses, including the statistical test, sample size, alpha level, desired level of power, and magnitude and type of effect size.

The Power Analysis Check module uses regular expressions to identify sentences that contain a statistical power analysis. Without the use of an LLM, the module uses regular expressions to classify the power analysis as a-priori, sensitivity or post-hoc. With the use of an LLM, it checks if the power analysis is reported with all required information.

The regular expressions can miss power analyses, or fail to classify them correctly. The type of power analysis is often difficult to classify, which can easily be solved by explicitly specifying the type of power analysis as ‘a-priori’, ‘sensitivity’, or ‘post-hoc’. Note that ‘post-hoc’ or ‘observed’ power is rarely useful. The LLM can fail to identify information in the paper, and will not have access to information in paragraphs in the paper other than those that contain the word ‘power’. This package was validated by the Metacheck team on articles in Psychological Science.

How StatCheck works

Check consistency of p-values and test statistics

The Statcheck module runs Statcheck. Statcheck searches for regular expressions that match a predefined pattern, and identifies APA reported statistical tests. More information on the package can be found at https://github.com/cran/statcheck. The module only returns Statcheck results for t-tests and F-tests, as these are the only tests which have been validated, see https://osf.io/preprints/psyarxiv/tcxaj_v1/.

Statcheck was developed by Michèle Nuijten and Sascha Epskamp.

Statcheck considers p = 0.000 an error, as you should report p < 0.001. Furthermore, p < 0.03 is an error if the p-value was 0.031, and one should simply report exact p-values (p = 0.031). When the sentence of a test says it is one-sided (“one-tailed”, “one-sided” or “directional”), a p-value that fits a one-sided test counts as consistent (statcheck’s OneTailedTxt setting; #695). Statcheck might still miss one-sided tests that are described in another sentence, and falsely assume the p-value is incorrect. For more information, see StatCheck.

How Exact P-Values works

List any p-values reported with insufficient precision (e.g., p < .05 or p = n.s.), reported as exactly zero (e.g., p = .000), or impossible (below 0 or above 1, e.g., p = -.22).

This module uses regular expressions to identify p-values. It will flag any values reported as p > ? or p < numbers greater than .001. It will also flag p-values reported as exactly zero (e.g., p = .000, p = 0.00), which are mathematically impossible — p-values are never exactly zero and should instead be reported as p < .001.

A p-value that is not the result of a test is not flagged: a table note (“* p < .05, ** p < .01”), a figure legend (“Asterisks indicate significant differences (p < .05)”, “Values in bold are significant at p < .05”) or a stated threshold (“p < .05 was considered significant”, “thresholded at p < .001”). GROBID often puts such notes into the running text, so each p-value is judged by the words in its own clause (the text up to a “;” or a full stop), and never left out when a test statistic belongs to it (“F(1, 7) = 8.03, # p < .05”). The column not_a_test of the table says why a p-value was left out (“marker”, “threshold”, “legend” or “named”).

A p-value with the name of a correction or a test after the p (“pFWE < .05”, “padj < 0.05”, “p Wilcoxon = .02”) is flagged only when a test statistic comes before it in its clause (“t(37) = 7.17, p FWE < .05”). Without one it is mostly the rule that decided what was significant (“genes with padj < 0.05 were selected”); such a p-value is “named” in not_a_test. Notes in other forms, such as a marker after the p-value (“p < .05 (*)“), are still flagged.

A p-value below 0 or above 1 is impossible; it is listed apart and not also as imprecise. Often the statistic before it, or its minus sign, was copied into it (“t(134) = -2.32, p = -.13”, “Z = 3.091, P = 3.091”). A value above 1 is listed only after a test statistic in its clause: without one, a “P” above 1 was nearly always another quantity (a proportion, pH, a group’s mean, a model parameter). A number in scientific notation whose power of ten was lost when the PDF was read (“p = 2.4 x 10 -9” read as 2.4) is not listed. A “p” that is the subscript of another symbol (“r p = .64”, “²p = .02” for partial eta squared, “Δp = .33”), or a quantity with a unit, a logarithm or a ratio (“P = 2.9 µm”, “-log10 P = 7.5”, “Ca/P = 1.67”), is not read as a p-value at all (see extract_p_values()). Each p-value has its own row, also when the same one is written twice in a sentence.

This module sometimes flags false positives when sentences discuss how p-value thresholds were set. It can also miss an imprecise p-value that is reported against a threshold (“decreased at the p < .05 significance threshold”).

This module only checks p-values reported in the running text of the manuscript. It cannot (yet) process p-values reported only in tables (as opposed to a table’s footnote text, which the module does see and tries to exclude — see above).

How Non-Significant P Value Check works

This module checks for imprecisely reported p values. If p > .05 is detected, it warns for misinterpretations.

The nonsignificant p-value check searches for regular expressions that match a predefined pattern. The module identifies all p-values in a manuscript and selects those that are not reported to be smaller than or equal to 0.05. It returns all sentences containing non-significant p-values.

In the future, the Metacheck team aims to incorporate a machine learning classifier to only return sentences likely to contain misinterpretations. If you want to help to improve the module, reach out to the Metacheck development team.

A p-value in a table note (“† p < .10, * p < .05”) or a figure legend (“dashed lines indicate non-significant paths (p > .05)”) is left out, as in stat_p_exact; the column not_a_test says why. A p-value next to words that state a threshold is kept, because such sentences often report a result against that level (“not significant at the conventional threshold (p = .054)”).

This module only checks p-values reported in the running text of the manuscript. It cannot (yet) process p-values reported only in tables.

How Repository Check works

This module retrieves information from repositories.

The Repository Check module lists files on the OSF, GitHub, ResearchBox, DSpace (PsychArchives and other legacy- and DSpace 7-based installations), Zenodo, Dataverse, Figshare, Dryad, ReShare, 4TU.ResearchData, Mendeley Data, DataONE (Arctic Data Center, KNB, and other member nodes), and LDbase based on links in the manuscript.

A link to a file-sharing service (Google Drive, Dropbox, OneDrive, Box, WeTransfer, MEGA, iCloud Drive, Baidu Netdisk, SURFdrive; see [file_share_links()]) gets a warning and makes the light yellow: such services are not repositories, as files can be changed or deleted at any time, get no DOI, and the link stops working when the account is closed. The report advises a stable repository such as Zenodo instead. Their files are not read, and summary_table$file_share_n counts the links.

The authors’ own are listed with what they hold ([seq_archive_size()]) and are not downloaded or checked as data and code; summary_table$archive_own_n counts them.

A Handle link (hdl.handle.net/...) that leads to a repository read here is checked as a link to that repository ([handle_links()]).

Listing a repository’s files never requires an API key, but some hosts answer faster or more completely with one: OSF allows 100 requests/hour unauthenticated versus 10,000/day with a token (see [osf_pat()]), and Dryad enforces a strict per-IP daily quota on repeated listing (see cache below). Dryad is a special case beyond rate limits: listing a Dryad dataset’s files works without a key, but actually downloading file CONTENTS from Dryad fails with HTTP 401 unless a key is set, even for a fully public dataset (see [dryad_pat()] or [dryad_auth()]). Since this module only lists files and never downloads their contents itself, that limitation applies to data_check and code_check (which do download content), not here – see their own documentation.

When a linked OSF page is a registration, its registered_from project (the one it was registered from, which the manuscript itself may never link directly) is also checked: if that project is public its files are listed under its own URL, and if it is closed or otherwise inaccessible the report flags it explicitly, since some registrations only describe their content rather than mirroring it.

Whose deposit is each link? The ownership table gives, for every repository linked in the text and (with references = TRUE) every deposit cited in the reference list, one of six labels: own_this (made by the authors for this paper), own_earlier_data or own_earlier_code (the authors’ own, from earlier work), others_data or others_code (made by other people, reused here), or not_data (a publication such as a preprint, not a deposit), with ownership_group (“own”, “others”, “not_data”) and the reason. It is decided without a language model, from the sentence or reference that cites the link, the paper’s authors (names, ORCID iDs, affiliations), and what the deposit’s own record and files say (who made it, what it names, when, whether it is a software package; for an OSF project cited only in the reference list, its record alone). On a round of labelled links the rules had not been written from, the three groups were right for 98% of links in the main text (93 of 95) and 90% in reference lists (74 of 82); the labels were made by Claude agents from each link’s evidence, and disputed ones checked against the deposits. Telling this paper’s own deposit from the authors’ earlier one is less certain.

Only the deposits that are this paper’s own are checked. A deposit linked in the text that holds other people’s work (others_data, others_code) or the authors’ earlier work (own_earlier_data, own_earlier_code) is listed in the report, with the reason, but its files are left out of table and kept in table_not_checked: they count toward nothing here (files that do not belong in a repository, naming, READMEs, studies, the traffic light), and code_check, data_check and reproducibility_check, which read table, do not check them either. reproducibility_check still puts the files of theirs that the paper’s code names in the folder the code runs in, as a re-analysis needs the data it re-analyses. When every linked deposit is set aside, the traffic light is “na”. A deposit that is the paper’s own is counted as such when its README, title or description names the paper (its title or DOI).

How Code Check works

This module retrieves information from repositories checked by repo_check about code files (R, Python, SAS, SPSS, Stata, Mplus, MATLAB).

The Code Check module checks R (also R Markdown and Quarto), Python (also Jupyter notebooks), SAS, SPSS, Stata, Mplus, and MATLAB files, using regular expressions to check the code; JASP files are listed but not read. The language of a Quarto document or a notebook is read from the file itself (its engine or kernel), not from its extension. The regular expression search will detect the number of comments, the lines at which libraries/imports are loaded, attempts to detect absolute paths to files, setwd() and install.packages() calls, and lists files that are loaded, and checks if these files are in the repository; R code is also parsed. The module will return suggestions to improve the code if there are no comments, if libraries/imports are loaded in lines further than 4 lines apart, if files that are loaded are not in the repository, if absolute file paths, setwd() or install.packages() are found, and if R code cannot be parsed.

The regular expressions can miss information in code files, or falsely detect parts of the code as a fixed file path. Libraries/imports might be loaded in one block, even if there are more than 3 intermittent lines. The module was tried out internally on papers published in Psychological Science, but has not been formally validated. There might be valid reasons why some loaded files can’t be shared, but the module can’t evaluate these reasons, and always gives a warning.

The module also checks whether the repository pins the R/package versions the analysis actually depended on: an renv.lock file (parsed for the R version and every locked package + its version/source), a sessionInfo()/sessioninfo::session_info() text dump (matched by filename — sessionInfo.txt/session_info.txt and similar, or embedded in a README), or a groundhog::groundhog.library()/checkpoint::checkpoint() date-pin call in the code (a bare library(groundhog)/library(checkpoint) does not count — the pinning call itself must be present). When none of these is found, the report flags it as a reproducibility gap: package versions may drift between when the analysis was run and any later reproduction attempt.

If you want to extend the package to perform additional checks on code files, or make the checks work on other types of code files, reach out to the Metacheck development team.

Checking code requires downloading its file contents. For a paper whose repository is on Dryad, this never succeeds unless a Dryad API key is set: Dryad requires one to download file bytes, even from a fully public dataset (listing the repository’s files does not need one). Without a key, every Dryad-hosted code file is listed but unchecked, and a warning naming Dryad and ?dryad_pat/?dryad_auth is included among the download failures recorded in the manifest.

How Data Check works

This module classifies the files in a repository into semantic types (data, codebook, code, software, output, supplemental, readme, asset, other) and, for tabular data files, extracts each column’s type and summary statistics.

The Data Check module consumes the file list produced by repo_check (or any files added via local_path). Each file is classified with rule-based heuristics layered over metacheck’s file_category() and file_types: file names matching README / codebook patterns win first, then an extension crosswalk, then format-locked extension overrides. For every file classified as tabular data that is available locally, the module reads the file head, describes each column with data_col_facets() and computes summary statistics for numeric columns. Every sheet of a spreadsheet that holds a table is read: a file with several such sheets has its columns under source_file = "file.xlsx [sheet]", and the sheet column names the sheet of any spreadsheet with several sheets; a sheet of notes or a codebook is treated as documentation when the file has another table. Following DDI, a column is described by orthogonal facets rather than a single type: representation (numeric/text/datetime/code — how it is stored), measurement_level (Stevens: nominal/ordinal/interval/ratio), concept (what it measures: reaction_time/age/gender/likert/id/…), role (identifier/measure/condition/timestamp), unit, and a quality state (ok/empty/constant). Concepts are detected by name+value rules (the demographic concepts via data_check_demographic()); when llm_use(TRUE) the model fills concepts and measurement levels the rules left blank. Qualtrics survey exports are recognised (data_check_is_qualtrics()): their extra header rows are stripped so columns type correctly, and the reserved response-metadata columns (StartDate, Duration, Finished, …) are tagged.

The module defaults to rules-only when llm_use(FALSE): columns the rules cannot resolve (ambiguous 3–20-unique integers, ambiguous character columns) fall back to continuous / text respectively. When llm_use(TRUE), ambiguous columns and unresolved file types (other) are sent to llm() for optional refinement, and every file is assigned a study group (ex1, pilot2, shared, …) so that multi-study repositories can be recognised (used by psychds_check). Without an LLM the study group is left NA (unknown).

Column extraction requires files to be readable from disk. Files fetched by repo_check from OSF/GitHub/etc. without a local copy (file_location is NA) are classified but not column-extracted; pass local_path to point at a downloaded copy of the repository.

For a paper whose repository is on Dryad, this means column extraction never happens unless a Dryad API key is set: Dryad requires one to download file bytes, even from a fully public dataset (dataset listing and metadata do not need one). Without a key, every Dryad file stays classified but un-downloaded, column_n is 0, and a warning naming Dryad and ?dryad_pat/?dryad_auth is included among the download failures. A one-time session message is also shown (see repo_check) the first time a Dryad dataset is encountered with no key set.

Every downloaded text file the authors wrote (code, settings, survey definitions such as Qualtrics .qsf files, documentation, outputs) is searched for keys: API keys, access tokens and private keys, which let anyone who downloads the file use a paid service at the authors’ cost. Of a tabular data file only the column names and first 3 rows of the table as read are searched: its values come from participants, but a key the authors set for a whole survey (as embedded data in a Qualtrics survey flow) is exported in every response. The search uses the rules of the secret scanner betterleaks (https://github.com/betterleaks/betterleaks, MIT licence) of high and medium confidence. A key found turns the traffic light red; the report and the keys table give its file, line and type, and only its beginning. Other files over 25 MB and binary files are not searched. A key is never tested with its provider. Every module’s result has any whole key replaced by “keyremoved” (see module_run()).

How Reproducibility Check works

This module assesses whether a paper’s R and Python code can be run on its data. It works in two phases. The static phase (always run) collects the package dependencies the code declares, rewrites the data-file paths that do not work in the repository as the authors organised it, works out the order the scripts must run in, and diagnoses why any referenced input file is unavailable — reporting what a reproduction attempt would involve and where it is likely to break. The execution phase (opt-in, execute = TRUE) then actually runs the code: it copies the repository into a throwaway directory, optionally installs the declared dependencies into a throwaway library, runs each script in order in an isolated subprocess with a per-script timeout, and captures the outcome and full output of each run.

By default (execute = FALSE) the module does not run any code — it performs only static analysis: reading dependencies with the same extractors as code_check, finding the files the code references in the repository, and building a run-order dependency graph. It reports what would be installed and run rather than doing it.

When execute = TRUE, the module additionally runs the downloaded code on your machine — a deliberate, opt-in action gated behind that argument (callr is required for R code). Each script runs in an isolated subprocess so a crash cannot take down the R session; note this isolates crashes, not the filesystem or network. Installs (when install_missing = TRUE) and the throwaway run library never touch your main R library. Each script’s outcome is one of ran_ok, errored, timed_out, dependency_unavailable, not_parsed, run_by_source (an R script another script runs with source(), which is run only inside that script, since on its own it lacks the packages and objects the sourcing script sets up first), run_by_import (a Python file other files import, a module rather than a script, unless it has an if __name__ == "__main__": block), jags_model (a JAGS or BUGS model saved with an R extension, which another script reads) or not_r_content (a file that is not R at all, such as a JSON or HTML dump); these last two are not run and are not failures. python2 marks Python 2 code that was not run. With sandbox = "docker" such code runs with Python 2.7 (option metacheck.docker_image_py2; FALSE turns this off), which modifications records; it is never converted, since that can change results. defines_functions is a file that only defines functions, which is used, not run (table$used_by names the scripts that use it), and not_analysis is a file of software rather than of the analysis: a package’s code, tests, documentation or setup.py, a copy of a tool, a web application, a script a program wrote (table$not_analysis_why says which); neither is run or counted as a script. docker_failed means the container never started, which says nothing about the script, so it keeps the light from being green but does not make it red. needs_a_person is a script that stopped because it asks a person to choose a file or answer a question, or that starts an app, and needs_internet one that stopped because the network is off in a Docker run, or, with internet = TRUE, could not reach what it asked for; download_too_large is a script stopped for downloading more than the limits allow (see internet), and out_of_memory one that, or a program it started (such as a compiler), ran out of the memory each script may use. All four are treated the same way. not_downloaded is a script that stopped on a file the repository lists but that was not downloaded, such as one over max_file_size: it could not be tried, so it is not counted as a script that did not reproduce (summary_table$repro_not_downloaded_n counts them apart). not_read is a file metacheck could not read, so it was not run; the light is then not green, as the file may read and run on another computer, and table$error_message says why, naming a package that is installed but cannot be loaded on the computer that ran the check. empty is a file with nothing in it, which is not run or counted as a script. For a script that did not run through, table$error_message is its error, short (at most 300 characters): the error line of its output, which names a package that is not there, with the address it asked for when it needed the internet, or the time limit it reached; table$reason sorts it into a kind. A timeout means “still running at the cutoff”, not a failure, so raise timeout for legitimately long-running (e.g. Bayesian) scripts. dependency_unavailable means the script’s own package could not be installed from live CRAN, the CRAN Archive, or a named GitHub/URL source — an infrastructure limitation, not a defect in the paper’s code. The full stdout/stderr of every run is kept in the result’s run_results (the report shows it in per-script dropdowns, capped for readability).

Provenance, kept so that a TRACE Research Object (TRO) declaration of the run can be written later from a stored result (metacheck #404; the helpers are in R/provenance.R). Only when code was run (execute = TRUE): * run_results$started_at, run_results$ended_at: when each run of a script started and ended (ISO 8601, UTC, milliseconds); NA for a script that was not started. A script run again in a later pass has the times of its last run. A TRO uses them for each trov:TransparentResearchPerformance. * run_results$exit_status: the exit status of the process that ran the script (0 = ended normally); NA when the process did not report one (a time limit, or Docker failing to start the container). * artifacts: one row per file, with stage (deposit: as downloaded from the repository, hashed from the downloaded file; before_run: the run folder just before the first script ran, after metacheck’s own changes, such as rewritten paths and unpacked archives; after_run: only the files the scripts made (status new), changed (changed) or removed (removed), as an unchanged file is the one listed before the run), path (relative to the run folder, as valid UTF-8, a byte of another encoding written as <xx>), size (bytes), sha256, mime_type (by extension, NA when unknown), source (the file’s address in the repository, for deposit). The package libraries metacheck installs in the run folder are left out, as are metacheck’s own files there (a script’s runner, and the statistical output it writes in statistical_output/). Files metacheck itself copied or made between passes (see modifications, output_copied, file_placed) show in after_run too. A TRO uses the rows as trov:ResearchArtifacts and each stage as a trov:ArtifactArrangement. * modifications$sha256_before, modifications$sha256_after: the hash of the changed script as downloaded and as it ran; NA when the script is not at the same path in both (a script made from an R Markdown file). * environment: the system that ran the code (trov:TransparentResearchSystem in a TRO): metacheck_version, started_at, ended_at, host (R version, platform, operating system), sandbox, network_isolated (TRUE only when every Docker run had --network none; the process sandbox does not stop the network), internet, timeout_per_script, total_timeout, python_local (the Python run outside Docker and its version), and docker: runs (for each kind of run, r_run, r_install, python_run, python_install, the image and the docker run arguments, such as --network none, --read-only, --cap-drop ALL, no-new-privileges, the process limit and the memory and processor limits) and images (for each image, its ID and digests from docker image inspect, its creation time and the R and Python versions its environment declares).

run_results$checked says what the run of each script shows about the code, in five groups, so that a script that does not reproduce is kept apart from one the check could not test: ran (it ran to the end); code_error (it did not reproduce: it stopped with an error of the code or the deposit, could not be read, or needs a file the deposit does not hold); dependency (a package or program was not available: a package that could not be installed or was not loaded, a program outside R and Python, a system library, or R crashing in a package’s compiled code); time (it did not finish within the time limit for one script, or was not started because the time for all scripts had run out); and not_checkable (it could not be checked automatically: it needs a person, the internet, a key or another setting of the authors’ computer, one platform such as Google Colab, Windows or OpenSAFELY, more memory than the run allows, a file that was not downloaded, a screen, or a program that runs it, or it is a file of a package of the code that Python runs only as a module of that package). It is NA for files run inside another script, files that are not an analysis, files not read, and a Docker failure. summary_table counts each group (repro_ran_n, repro_code_error_n, repro_dependency_n, repro_time_n, repro_not_checkable_n), and the report’s first sentence gives them. The traffic light reflects the static readiness signals by default; a script in code_error that stopped with an error makes it red, as a script that crashes on its own analysis is a genuine reproduction failure, and a script in one of the other three groups keeps it from being green. Calls that need a screen, which the run does not have (dev.print(), dev.copy2pdf(), dev.copy2eps(), savePlot(), windows(), win.graph(), x11(), quartz(), View()), are replaced before the run by calls that need none, which modifications records as screen_call_replaced. A script that fails with could not find function is run once more with the library() calls the project’s other scripts make added at its top (or the one package that exports the function, or magrittr for %>%), and a script that then runs is reported as reproducible only after that repair.

Dependencies are reported name-only, with the source (CRAN, GitHub, or a base package already shipped with R) — static analysis of the code cannot know which version was used, and running against current package versions is itself informative: a break argues the authors should have pinned versions. When the repository does record versions, a run with recorded_versions = TRUE installs the packages the scripts load at those versions, but it does not change the R version, which remains a limitation of the check.

Run order is derived from read-after-write data dependencies (a script writing a file another reads must run first), source() edges, and numeric filename prefixes as a weak tie-breaker. Ambiguous orderings, dependency cycles, and inputs a script reads but that no earlier script produces (and that are not in the repository) are surfaced as warnings, since these are the situations most likely to make an otherwise-correct reproduction fail.

Python code (.py files, and notebooks and Quarto documents whose code is Python, from which the code is extracted first) goes through the same two phases, reported in its own “Python code” section. Each file is checked for syntax errors with Python’s own parser when a Python interpreter (python, or else python3) is available; dependencies are read from the import statements, with versions from a requirements.txt or pyproject.toml when there is one, and installed with pip; each script runs as its own python process (processx is required), so unlike R scripts, a name one script defines is not available to another. When no Python interpreter is available, the Python files are reported as not run and the R results are still returned. Statistics the Python scripts print are compared with the paper together with the R output and any self-reproducible output (JASP/jamovi, SPSS-Viewer, notebook outputs).

Abstract

Short-form video use is associated with poor emotional well-being, yet its short-term associations with affect in daily life remain unclear. In a 14-day ecological momentary assessment study, 134 Chinese university students completed 17,514 surveys, yielding 14,899 complete same-day lag-1 transitions. Bayesian multilevel dynamic models separated within-person fluctuations from between-person differences and estimated associations of prior affect with subsequent interval use, interval use with end-of-interval affect, and daily use rate with affective dynamics. We identified several associations at the momentary timescale: 1) At the 90-minute reference interval, reported short-form video use was associated with 1.36 points lower positive affect (95% credible interval -2.36 to -0.39) and 1.47 points higher overall negative affect (0.59 to 2.40) on 0-100 scales; 2) Among occasions with prior non-zero negative affect, the 75th versus 25th percentile of its intensity corresponded to an increase of 1.74 percentage points in subsequent short-form video use probability (0.89 to 2.60).

At the daily timescale: 1) Daily short-form video use rate was not associated with mean levels of either positive or negative affect; 2) Higher daily use rates were associated with slightly weaker positive-affect carryover and lower residual variability. In conclusion, our findings highlight the dynamic associations between short-form video use and affect across multiple timescales. These findings motivate further research using objective use logs and designs capable of supporting causal inference.

1. Introduction

Over the past decade, short-form video has emerged as a prominent and rapidly growing mode of digital entertainment (Nguyen et al., 2025). It is characterized by brief videos, typically lasting from a few seconds to several minutes, delivered through a scrolling interface (Q. Zhang et al., 2024). Unlike traditional long-form video platforms, where users typically engage in active content search and selection, short-form video platforms primarily expose users to content through a continuous, algorithmically curated feed that requires little interaction beyond swiping (Yang et al., 2023). This design can foster flow (Zheng, 2023), time distortion (Yang et al., 2024), and continued engagement, while affective factors such as satisfaction and dependence may further sustain use (Jiang et al., 2025; Yang et al., 2023).

These features may connect short-form video use with users' momentary affective experiences. Understanding these associations therefore requires attention to how SV use and affect covary over time in daily life (Faelens et al., 2021; Marciano et al., 2022).

Current evidence generally suggests that short-form video use is associated with poor emotional well-being and psychological distress. A recent systematic review and metaanalysis found that higher levels of short-form video use were associated with poorer mental health compared to lower levels of use, with comparatively stronger associations for stress and anxiety (Nguyen et al., 2025). In adolescents, addictive TikTok use has been linked to higher levels of depression, anxiety, stress, loneliness, social anxiety, and attention problems, as well as lower life satisfaction and sleep quality, relative to moderate use or nonuse (Chao et al., 2023). Longitudinal evidence among college students further suggests that short-form video overuse may be associated with later depression, whereas prior depression may not be associated with later short-form video overuse (D. Zhang et al., 2024).

Although these studies provide important evidence on the adverse emotional outcomes of short-form video use, most have focused on associations between overall use and longer-term psychological outcomes and have not sufficiently addressed its short-term association with affective states in daily life. To characterize temporal ordering, studies must examine whether prior affect predicts subsequent SV use and whether SV use reported during an interval predicts affect at the interval-ending assessment.

The core features of short-form video platforms suggest two potentially related temporal associations with affect. Readily accessible distraction may make higher-than-usual negative affect a precursor of subsequent SV use (Xia et al., 2023). Work on social media also links use with affect measured subsequently (Wirtz et al., 2021). Examining these associations requires repeated measurements that capture short-term fluctuations in daily life (Elmer et al., 2025). In a recent twice-daily study, intervals for average within-person cross-lagged estimates linking anxiety with active use, passive use and time spent on short-form video platforms included zero (Yang et al., 2026). Associations may vary with the affective construct, use behavior and observation interval. We therefore used ten EMA prompts per day, scheduled approximately one to two hours apart, to examine momentary affect before a use interval and affect assessed at its end.

The association between short-form video use and affect may operate at two levels: betweenperson differences in stable affective tendencies, and within-person fluctuations in momentary emotion relative to one's own average (Elmer et al., 2025). Based on existing cross-sectional and daily diary evidence, individuals may be more likely to report short-form video use when their affect differs from their own typical level, while those with generally higher emotional baseline intensities may also differ in their overall use of short-form video (große Deters & Schoedel, 2024). Conversely, individuals with higher levels of person-mean shortform video use may also differ in overall affective functioning (Chao et al., 2023) compared to those with lower person-mean usage. Since stable affective dispositions and momentary affective fluctuations do not necessarily align within individuals, existing conclusions may reflect a mixture of associations operating at different levels (Chao et al., 2023; Nguyen et al., 2025). To address this gap, we therefore decomposed occasion-level observations into deviations from participant-specific means. This approach reduced the risk that stable between-person differences would be misinterpreted as short-term within-person processes.

An additional methodological consideration would be the pronounced floor effect that often characterizes intensive longitudinal measures of negative affect (NA). A floor effect occurs when a substantial proportion of observations cluster at the lowest possible score. Because NA exhibited a point mass at zero together with continuously distributed positive values, a single Gaussian model would not distinguish processes associated with the occurrence of any NA from those associated with its conditional intensity (Muthén et al., 2025). A pronounced all-zero state was evident for NA, but not PA, in our data. A two-part model estimates these processes separately (Olsen & Schafer, 2001). We therefore represented NA using a binary component which modeled the probability that all three NA items (i.e., anxious, depressed, and irritated) were zero versus at least one item being non-zero, and a conditional intensity component that modeled the magnitude of NA only on occasions when NA was nonzero.

We estimated whether the all-zero NA state and above-zero NA intensity at the preceding prompt were associated with short-form video use during the subsequent interval, and whether short-form video use reported during an interval was associated with the all-zero NA state and above-zero NA intensity at the interval-ending prompt. This specification allowed the all-zero NA state and above-zero NA intensity to be examined separately. As a secondary summary, we combined the two components to estimate overall expected NA.

Beyond their average levels, affective experiences are also characterized by their persistence and variability. Affective inertia is the extent to which an affective state or deviation carries over from one assessment to the next, with greater inertia indicating stronger temporal persistence (Jongerling et al., 2015; Kuppens et al., 2010). Innovation variability is the conditional standard deviation of new occasion-level deviations after prior affect and other modeled predictors are considered (Jongerling et al., 2015). As affect evolves between assessments, we expected its self-lag association to weaken over longer intervals. We compared the estimated time pattern with this expectation. We suggest that positive and negative affect on days with higher or lower SV exposure may exhibit different degrees of inertia or variability without a shift in their average levels. As an exploratory hypothesis developed during revision, we also examined whether higher-than-usual daily SV use rates were associated with PA carryover, above-zero NA carryover, all-zero-state persistence and residual variability.

1.1 The Present Study

The present study used EMA to examine within-person temporal associations between reported SV use and affect, while including participant-level means to distinguish withinperson fluctuations from between-person differences. In response to the gaps in the existing literature, the study aims were to address four research questions: The fourth research question was developed following the initial analyses in response to reviewer feedback. We first examined momentary affect in relation to subsequent interval use and reported interval use in relation to affect at the ending assessment. We then explored associations of the daily SV reported-use rate with affective carryover and residual variability. These analyses characterize within-person associations between reported shortform video use and affect across momentary and daily timescales.

2. Methods

>Methods

2.1 Study Design and Participants

This study adopted a longitudinal design including a pre-EMA survey and a 14-day EMA study.

The pre-EMA survey was conducted on November 22, 2024, via the online survey platform "Wenjuanxing" (https://www.wjx.cn/). Those who passed the screening subsequently participated in a 14-day Ecological Momentary Assessment (EMA) of momentary emotion and smartphone use via their mobile phones. The 14-day EMA study was conducted from November 25, 2024, to December 8, 2024, via smartphone push surveys. This study was not preregistered. This study was approved by the Ethics Committee of Capital Medical University (2024SY055), and all participants provided written informed consent. Participants were informed that they could withdraw from the study at any time without penalty.

Participants were recruited through university bulletin boards and social media platforms between November 14 th and November 20 th , 2024. Undergraduate and graduate students were eligible if they: (a) reported no history of a severe psychiatric disorder, (b) had no major examinations during the study or the following week, (c) used smartphone applications daily, and (d) provided written informed consent. A total of 147 university students joined the study. Three participants withdrew before EMA began. Ten further participants did not meet the inclusion rule of at least 40 valid smartphone-duration records. Duration reports exceeding the corresponding survey interval were set to missing before valid records were counted. Eight of these participants withdrew on the first day. The other two had 13 and 34 valid smartphone-duration records. The participant with 34 valid records completed 138 EMA surveys and reported no short-form video use. This participant was excluded because of the duration-record criterion, despite the high survey completion rate. Refitting the models with this participant included produced only negligible changes in the model estimates. An audit identified a gap between 34 and 51 valid records: the largest count below the threshold was 34, and the smallest retained count was 51. Every integer threshold from 35 to 51 selected the same 134 participants. The final analytic sample comprised 134 participants who completed the pre-EMA survey and met the data requirement of the 14-day EMA period. There were 49 males (36.6%) and 85 females (63.4%), aged 18 to 26 years (M = 19.8, SD = 1.5). Participants provided 17,514 of 18,760 planned EMA surveys (93.4%). Participants could receive up to CNY 150 (about USD 21) in compensation based on their level of completion.

2.2 Study Procedures

Web-based pre-EMA survey

In the pre-EMA survey, participants' trait anxiety (Spielberger et al., 1971; Wang et al., 2016), adverse life events (Liu et al., 1997), depression, anxiety, and stress (Wang et al., 2016) were assessed at baseline. We collected participants' demographic information and information on their regular daily routines. The latter was used to schedule the start and end times of the EMA to minimize the influence of individual sleep habits.

Measures

State-Trait Anxiety Inventory

The State-Trait Anxiety Inventory (Spielberger et al., 1971) is a 40-item self-report measure of anxiety. We utilized the 20-item trait anxiety subscale, which assesses how anxious a person generally feels, in this study. A sample item is "I worry too much over something". It uses a 4point Likert-type scale for each item (1 = Almost never,4 = Almost always), while a higher summed score represents higher general anxiety. Cronbach's α for this study is .90.

Adolescent Self-Rating Life Events Checklist

The Adolescent Self-Rating Life Events Checklist (Liu et al., 1997) is a 27-item self-report measure of negative life events. It consisted of 27 items across 6 dimensions, including interpersonal relationships, learning difficulties, punishment, bereavement and property loss, health and adaptation, and general life events. A sample item is "Being separated from family for a long time and unable to reunite". It uses a 6-point Likert-type scale for each item (0 = Never,5 = Extremely), while a higher summed score represents greater perceived impact of negative life events. Cronbach's α for this study is .88.

DASS-21

The Depression, Anxiety, and Stress Scale-21 (Wang et al., 2016) is a 21-item self-report measure of depression, anxiety, and stress symptoms experienced in the past week. A sample item is "I found it hard to wind down". It uses a 4-point Likert-type scale for each item (0 = Did not apply to me at all,3 = Applied to me very much, or most of the time), while a higher summed score on each subscale represents higher levels of depression, anxiety, and stress.

Cronbach's α values for the depression, anxiety, and stress subscales were .75, .72, and .82, respectively.

Smartphone-based 14-day EMA (Figure 1)

We used an interval-based EMA design. During the 14-day EMA period, ten surveys per day were scheduled between 8:00 AM and 10:00 PM on weekdays and between 9:00 AM and 11 PM during weekends, for a maximum of 140 surveys in total. Each survey lasted approximately 3 minutes. Scheduled intervals varied randomly between 1 and 2 hours, and participants received automatic push notifications from instant messenger WeChat to access the link to each survey prompt (via the survey platform "Wenjuanxing", https://www.wjx.cn). All surveys assessed current emotion. App-use questions were administered from the second daily survey onward and covered short-form video platforms, social media, games and long-form video platforms (Figure 1).

Measures

Momentary Emotion

At each survey, participants rated their current emotional state (i.e., positive and negative affect) on a continuous scale from 0 to 100 (0 = Not at all,100 = Extremely). Positive affect items include joyful ("I feel joyful"), relaxed ("I feel relaxed"), and active ("I feel active").

Within-person and between-person ω values for positive affect were .78 and .96, respectively.

Negative affect items include anxious ("I feel anxious"), depressed ("I feel depressed"), and irritated ("I feel irritated"). These selected three-item composites were designed to cover positive and negative valence across different activation levels while keeping ten daily assessments brief. Item selection was informed by PANAS and PANAS-X affect descriptors and by dimensional models that conceptualize affect in terms of valence and arousal (Watson et al., 1988). Within-person omega was 0.781 (95% interval 0.760-0.799) for PA and 0.710 (0.679-0.740) for NA. Corresponding between-person values were 0.956 and 0.900. Reliability estimates and associations of participant-average affect with baseline symptoms are reported separately in Supplementary Section 12.

Momentary Smartphone Use

From the second daily prompt, participants reported whether they had used short-form video platforms, social media, games, and/or long-form video platforms since the last available survey (e.g., short-form video item: "Since the last available survey, have you used short-form video platforms? (e.g., Douyin / TikTok, Kuaishou, etc.)";0 = no,1 = yes).

Submission times provided the actual interval between responses. The first daily survey assessed morning affect only. App use during the overnight interval was outside the questionnaire schedule. Morning affect contributed to participant summaries and, when paired with the next scheduled survey on the same day, served as prior affect for the subsequent interval-use analysis.

2.3 Statistical Analysis

Data Preparation

In total, 17,514 valid responses were acquired from the EMA, contributing 14,899 consecutive same-day lag-1 transitions and 1,863 eligible participant-days that were included in the analysis at the momentary level. Missingness patterns are shown in the supplementary material. To account for systematic temporal structure in daily life, measurement occasions were indexed by study day (1 to 14) and by measurement wave (prompt 1 to 10) within each day. The elapsed interval was recorded in minutes and represented as l idt =log ( Δ t idt / 90 ), making 90 min the coefficient reference.

At each assessment, positive affect (PA) was calculated as the mean of active, relaxed, and joyful ratings, and negative affect (NA) as the mean of depressed, anxious, and irritated ratings. PA was analyzed on a standardized model scale and converted back to raw PA points.

Responses with NA = 0 accounted for 21.4% of assessments, so we used a hurdle model to represent the NA distribution. Z idt = 1 indicated all three NA items were zero for participant summarized the whole day, including reports after a given affect assessment.

Analytic Strategy

We fitted three Bayesian dynamic structural equation models (DSEM) to the EMA data (Asparouhov et al., 2018). These comprised Bernoulli models for subsequent interval SV use and the all-zero NA state, and a joint Gaussian location-scale model for PA and above-zero NA intensity. The hurdle structure separated the probability of an all-zero NA report from variation in above-zero intensity. Joint modeling allowed PA and above-zero NA residuals to covary.

Participant random intercepts accounted for repeated observations and stable differences between individuals. Time-varying affect and app-use variables were decomposed into participant-mean between-person components and person-centered within-person deviations.

The models were fitted in Stan using observed participant means to separate within-person and between-person components rather than the latent centering used in Mplus-style DSEM. Models further adjusted for other app use, age, sex, study day, weekend, prompt, and occasion-, day-, and person-level interval components. Participant-specific random intercepts accounted for stable individual differences.

Analyses were conducted in R 4.5.3. Models were fitted in Stan using CmdStan 2.39.0 (Carpenter et al., 2017) through cmdstanr 0.9.0 (Gabry J, 2025). Posterior summaries and convergence diagnostics were computed using posterior 1.7.0 (Bürkner P, 2026). In the main analysis, the all-zero NA state and joint continuous components were each estimated with four chains. Each We summarized posterior distributions using medians and equal-tail, pointwise 95% credible intervals (CrIs). Odds ratios were calculated as exp(β) for Bernoulli-logit coefficients. We also reported the probability of direction (PD), the posterior probability that a parameter or contrast had the same sign as its posterior median. Each interval described one parameter or contrast. Interpretation considered effect magnitude, interval width, and consistency across sensitivity analyses. Convergence was assessed using rank-normalized R-hat and bulk and tail effective sample sizes. The study criteria were a maximum R-hat of 1.01 or lower and bulk and tail effective sample sizes of at least 400 across the four chains (Vehtari et al., 2021). We also required no divergent transitions, no iterations reaching the maximum tree depth, and an energy Bayesian fraction of missing information (E-BFMI) of at least 0.30 in each chain (Carpenter et al., 2017). Conditional one-step posterior predictive checks compared simulated current outcomes with selected observed statistics, using observed prior states and covariates. We additionally examined parameter precision and the Monte Carlo stability of daily NA-carryover estimates.

Primary contrasts were evaluated at 90 minutes and averaged equally over the same 14,898 main-sample observations. Current-use contrasts compared predicted outcomes under reported SV use with those under no reported use. Overall expected NA combined the probability of above-zero NA with its conditional mean intensity. Contrast calculations and back-transformation procedures are detailed in Supplementary Section 6. Sensitivity analyses examined wider priors, removal of daily-use terms, and restriction to same-day adjacent surveys 75-105 minutes apart. We also used inverse-probability-of-response weighting to examine sensitivity to differences in the probability of observing eligible survey pairs, conditional on the measured predictors of response (Robins et al., 1995). Implementation details and prior predictive checks are provided in Supplementary Sections 9-11. These additional analytic specifications were developed after the initial analyses in response to reviewer feedback and are therefore exploratory.

Model diagnostics and sensitivity analyses

All three model components met the prespecified HMC criteria, with no divergent transitions or maximum-treedepth hits. For the short-form video use, all-zero NA-state, and joint PA/above-zero-NA continuous components, maximum R-hat values were 1.004, 1.003, and 1.009; minimum bulk ESSs were 976, 868, and 840; minimum tail ESSs were 1,692, 1,341, and 1,414; and minimum E-BFMI values were 0.762, 0.704, and 0.638, respectively.

Divergences and maximum-treedepth hits were zero. In the targeted one-step predictive check, 38 of 48 observed summary statistics for the main model fell within their 95% predictive intervals. The predicted proportion of PA scores outside the 0-100 range had a 95% interval of 3.34%-4.06%, compared with zero in the observed data. The observed SD of above-zero NA was 19.847 points, compared with a predictive interval of 20.251-20.847. The model reproduced most of the assessed features, although slight discrepancies remained in the proportion of predicted PA scores outside the observed scale and in the variability of above-zero NA (Supplementary Section 8).

Results were similar under wider priors and after removing the daily-use terms. At 90 minutes, wider priors gave estimated differences of -1.33 [-2.40, -0.29] PA points and 1.80 [0.87, 2.81] above-zero NA points for reported SV use versus no use. The corresponding differences in the simpler model were -1.04 [-2.00, -0.05] and 2.10 [1.23, 2.95] points. Both analyses retained the main pattern, with a weaker PA association in the simpler model. In each model, 38 of 48 observed summary statistics fell within their 95% predictive intervals, although the statistics covered differed (Supplementary Sections 9 and 10).

Response-probability weighting also produced estimates similar to the main analysis: -1.41 [-2.49, -0.31] PA points and 1.83 [0.81, 2.85] above-zero NA points. Higher prior above-zero NA was associated with a 1.70 [0.86, 2.70] percentage-point increase in subsequent use probability. These weighted intervals are 95% conditional pseudo-posterior intervals.

Restricting intervals to 75-105 minutes gave differences of -2.16 [-3.97, -0.53] PA points and 1.38 [-0.26, 2.90] above-zero NA points. The prior-NA contrast for subsequent use was 1.42 [-0.05, 2.91] percentage points. Thus, the interval restriction supported the PA association, while the NA estimates became less precise and their intervals included zero (Supplementary Sections 9 and 11).

Higher daily use rates remained associated with slightly weaker PA carryover and lower PA residual SD across the four analyses that estimated these effects. Daily NA carryover associations were small and less precisely estimated. Under wider priors, the upper credible limit shifted from just above zero with 800 posterior draws to just below zero with all 4,000 draws; the median remained similar. Estimates were also less precise for the daily-use interaction with the prior all-zero NA state, the daily-use effect on above-zero NA residual variability, and demographic coefficients (Supplementary Section 13).

4. Discussion

The aim of this study was to use a 14-day ecological momentary assessment approach to examine the temporal relationship and within-person fluctuations in short-form video use and affective states. Among occasions preceded by above-zero NA, greater prior intensity was associated with a slightly higher probability of use during the following interval. Reported interval use was associated with slightly lower PA and higher above-zero and overall NA at the interval-ending assessment. Analyses with wider priors, a simpler model and responseprobability weights retained this concurrent pattern. Restricting intervals supported the PA association and produced less precise NA estimates. At the daily level, the small associations with weaker PA carryover and lower residual variability were consistent across analyses estimating daily terms.

Prior affect and subsequent reported short-form video use

Our findings regarding the association between prior affect and subsequent SV use were specific to the intensity of negative affect. Greater intensity of negative affect was associated with a small increase in subsequent SV use probability. The prior PA and allzero-state estimates were less precise. People may turn to accessible digital content when they feel worse than usual, a hypothesis consistent with research on distraction, avoidance and emotion regulation during unpleasant affect (Shi et al., 2023). A large experience-sampling study likewise found that higher negative affect preceded greater smartphone-based emotional expression and avoidance, with small average subsequent changes in negative affect (de Segovia Vicente et al., 2026). Our finding adds an interval-level association to this literature and suggests measuring motives immediately before use in future studies. Yang et al. (2026) reported imprecise average within-person cross-lagged associations of anxiety with active use, passive use and duration, while upward social-comparison tendency moderated the association between passive use and subsequent anxiety. Since we did not assess motives, duration of use, specific contexts of use, or emotional consequences other than self-reported affect, we could not distinguish whether the reported short-form video use was habitual use, random usage behavior, or problematic use. Differences in affective constructs, use behaviors, prompt schedules and analytic approaches offer plausible reasons for differences between studies. Episode-level records of motives, duration and context would allow future work to distinguish habitual use, intentional emotion regulation and use that conflicts with personal goals.

Reported short-form video use during an interval and affect at the interval-ending assessment

After adjustment for prior affect, person-level differences, and prespecified covariates, intervals with reported SV use ended with slightly lower PA and higher above-zero NA intensity than intervals without reported use. The hurdle components indicate that the higher overall NA primarily reflected stronger negative feelings on occasions when negative affect was reported. This pattern is consistent with the possibility that SV use amplifies negative feelings that are already present. For people seeking distraction, the practical question is whether viewing helps these feelings subside or is followed by greater intensity. Assessments immediately before and after viewing could test this interpretation by tracking changes in intensity during episodes that begin with negative affect.

One hypothesis for future study is emotion-regulation rebound: viewing may offer temporary distraction, followed by a return to the stressor or task. Such a sequence could explain how an activity chosen for immediate relief is followed by stronger negative feelings. This account draws on research on negative emotions associated with short-form video use (Cheng et al., 2023), smartphone-based avoidance (de Segovia Vicente et al., 2026), transient relief (Shi et al., 2023), post-browsing affect (Colasante et al., 2024), and experiential avoidance (Wang et al., 2024).

A second hypothesis concerns cognitive fatigue after viewing. Rapid audiovisual transitions and sustained attentional demands may be relevant to post-use affect, as suggested by work on attention (Yan et al., 2024; Zhai et al., 2025) and fatigue (Alruwaili, 2025). Evidence from TikTok studies suggests that post-use negative affect may be especially pronounced in situations where use is harder to stop or feels goal-incongruent (Miedzobrodzka et al., 2024).

Specifically, self-control-failure use (i.e., defined as TikTok use that conflicts with other important goals or tasks people want or need to pursue, like studying for exams) is more strongly linked to bedtime procrastination and poorer well-being compared with use by selfcontrolled users (Miedzobrodzka et al., 2024). Future studies could compare fatigue and rebound accounts by assessing attention, fatigue, use motives and goal conflict around individual episodes, alongside immediate affect.

Daily short-form video use rate and affective dynamics

Daily-use associations with affect levels were small, with intervals spanning both positive and negative values. Affective carryover describes how strongly a deviation persists, whereas residual variability describes the variation remaining after accounting for the predictors (Jongerling et al., 2015; Kuppens et al., 2010). Accordingly, a null association with the daily mean does not imply that the daily SV reported-use rate is unrelated to within-day affect dynamics. Evaluating these features separately characterizes daily differences in affect levels, persistence and variability.

On days with higher short-form video use rates, positive affect and above-zero negative affect showed lower levels of affective inertia. Affective inertia refers to the degree to which deviations from a person's typical affective level persist from one assessment to the next (Kuppens et al., 2010). Lower inertia therefore indicates that departures from the expected affective level were less persistent and that affect updated more rapidly across successive contexts. Short-form video feeds cause users to repeatedly disengage from one stimulus and redirect attention to another by presenting a rapid succession of brief visual, auditory, and narrative contexts. Because short-form video feeds present rapidly changing audiovisual content, repeated viewing may entail frequent attentional reorientation. Consistent with this possibility, a recent meta-analysis found that greater short-form video use was associated with poorer attention and inhibitory control, and an EEG study linked stronger short-video addiction tendencies to weaker executive-control indices (Nguyen et al., 2025).

Repeated exposure to rapidly changing short-form content could plausibly promote attentional reorientation. Content transitions, attention and affect could be measured together at finer timescales to evaluate that hypothesis. A higher daily SV reported-use rate was also associated with lower PA innovation variability. Innovation variability summarizes variation remaining after accounting for prior affect and other predictors, including contributions from daily context and affective events. It summarizes otherwise unexplained affective dispersion and may reflect unmeasured contextual variation, exposure to affectively relevant events, and/or differential reactivity, but it cannot distinguish among these sources (Jongerling et al., 2015; Simons et al., 2021). The practical significance of these small dynamic differences remains uncertain and should be evaluated against daily functioning and participants' subjective experience.

The daily use rate summarizes the whole day, and the standardized scenarios can extend beyond an individual's observed rates. The estimates therefore describe associations across common standardized daily-use scenarios.

Limitations

SV use was assessed through retrospective self-reports at randomly scheduled prompts approximately one to two hours apart. The binary item did not capture viewing duration, episode count, content, interactions or motives, and no objective app logs were collected.

Recall error and the grouping of different viewing experiences may attenuate associations with affect. Assessments covered smartphone use, potentially underestimating exposure through tablets or computers. App-category misclassification is also possible because Chinese social-media and long-form video platforms incorporate short-form feeds. Logs identifying the content viewed and capturing use across devices would improve exposure measurement.

The first daily prompt assessed morning affect without an accompanying app-use report.

Morning affect contributed to the analysis of use during the following interval, while overnight and early-morning use before the first prompt remained unrecorded. Missing affect and app-use responses were not imputed, and nonresponse varied across study days and prompts. Response-probability weighting reduced measured covariate imbalance and yielded estimates similar to the main results (Supplementary Section 11). Unobserved affect may also influence whether participants respond, potentially leading to data that are missing not at random. Wider-prior analyses likewise produced estimates similar to the main concurrent associations (Supplementary Section 9). However, several parameters were estimated imprecisely with 134 participants. Broad credible intervals suggest limited power for daily-use effects on all-zero NA persistence and above-zero NA residual variability, and for demographic associations with SV use (Supplementary Section 13). We reported 95% posterior credible intervals for individual parameters and contrasts without a study-wide multiplicity adjustment. Examining many associations increases the risk of emphasizing unstable findings, so interpretation considered effect magnitude, precision and consistency across sensitivity analyses together.

The construct validity of the three-item affect composites needs further evaluation. Across participants, average NA correlated positively with stress and trait anxiety, while average PA correlated negatively with depression, providing evidence relevant to construct validity (Supplementary Section 12). Measurement error associated with the within-person reliability of NA (ω = 0.710) may attenuate associations involving NA. Convergence with full PANAS or PANAS-X measures and measurement invariance across participants and time were not assessed. Comparisons with longer validated scales and alternative item sets would strengthen the interpretation of these momentary scores.

The sample comprised Chinese university students who reported no history of severe psychiatric disorders. SV use patterns and affective processes may differ in adolescents, older adults and people with diagnosed mood disorders. Academic workload, daily routines and seasonal conditions during the November 25-December 8, 2024 study period may also have influenced both affect and digital-media use. These sampling characteristics should be considered when applying the findings to other populations and settings. Repeated observation across academic periods and seasons would help establish how consistently the associations occur. The revised research questions and analytic specifications were developed after the initial analyses in response to reviewer feedback. The findings are therefore exploratory and require independent replication before they can inform theory or intervention.

Implications and Future Directions

This study illustrates the value of intensive longitudinal methods for separating within-person associations from between-person differences in SV use and affect. Ten daily surveys enabled the joint assessment of affect occurrence, intensity, carryover and residual variability in everyday settings. The small estimates provide quantitative benchmarks for planning subsequent studies, including research on daily differences in PA persistence and residual variability.

Theoretically, the findings highlight the distinction between whether negative affect is present and how strongly it is experienced. The clearest NA association concerned greater intensity at the interval-ending assessment, while the association with the all-zero NA state was less precise. This pattern motivates the hypothesis that SV use may intensify negative feelings that are already present. The association between prior NA and subsequent use also motivates research on viewing as a response to negative feelings. Together, these findings generate specific questions about the role of SV use in everyday emotion regulation.

Practically, this distinction draws attention to the emotional context in which viewing occurs.

For people who turn to SV when upset, a relevant question is whether viewing helps their feelings subside or is followed by greater distress. If replicated at the episode level, these findings could guide support that considers users' initial emotional states, reasons for viewing and emotional experiences afterwards. The practical value of such support would depend on whether it produces meaningful improvements in everyday functioning and well-being.

Future studies should prespecify their questions and combine validated affect measures with objective app logs and episode-level records of content, motives and context. Assessing affect immediately before and after episodes that begin with and without negative affect would help distinguish intensification from onset. Measures of attention, fatigue and goal conflict would allow direct comparison of the proposed rebound and cognitive-fatigue accounts. Data collection across devices, academic periods and seasons would improve coverage of viewing experiences and their contexts. Simulations reflecting the sample structure and survey schedule could assess parameter recovery and precision for small associations. Independent replication is needed before these findings inform theory or intervention.
