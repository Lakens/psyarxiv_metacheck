Meta-scientific research has shown nonsignificant p values are commonly misinterpreted. It is incorrect to infer that there is ‘no effect’, ‘no difference’, or that groups are ‘the same’ after p > 0.05.

It is possible that there is a true non-zero effect, but that the study did not detect it. Make sure your inference acknowledges that it is possible that there is a non-zero effect. It is correct to include the effect is ‘not significantly’ different, although this just restates that p > 0.05.

How Ethics Approval Check works

This module searches for statements of ethics approval, IRB approval, institutional review board approval, and related terms.

Patterns are designed to capture:

How Power Analysis Check works

This module uses regular expressions to identify sentences that contain a statistical power analysis. If specified by the user, it also uses a large language model (LLM) to extract information reported in power analyses, including the statistical test, sample size, alpha level, desired level of power, and magnitude and type of effect size.

The Power Analysis Check module uses regular expressions to identify sentences that contain a statistical power analysis. Without the use of an LLM, the module uses regular expressions to classify the power analysis as a-priori, sensitivity or post-hoc. With the use of an LLM, it checks if the power analysis is reported with all required information.

The regular expressions can miss power analyses, or fail to classify them correctly. The type of power analysis is often difficult to classify, which can easily be solved by explicitly specifying the type of power analysis as ‘a-priori’, ‘sensitivity’, or ‘post-hoc’. Note that ‘post-hoc’ or ‘observed’ power is rarely useful. The LLM can fail to identify information in the paper, and will not have access to information in paragraphs in the paper other than those that contain the word ‘power’. This package was validated by the Metacheck team on articles in Psychological Science.

How Preregistration Check works

Retrieve information from preregistrations in a standardised way, and make them easier to check.

The Preregistration Check module identifies preregistrations on the OSF and AsPredicted based on links in the manuscript, retrieves the preregistration text, and organizes the information into a template. The module retrieves text from the OSF with its API, and from AsPredicted with ResearchBox’s API when a ResearchBox key is set (see rbox_token()), or else from the preregistration’s web page. The information in the preregistration is returned. An AsPredicted link that could not be read is named in the report, with the reason.

The module can’t extract information from non-structured preregistration templates (i.e., where the preregistration is uploaded in a single text field) and it can’t retrieve information in preregistrations that are stored as text documents on the OSF.

If you want to extend the package to be able to download information from other preregistration sites, reach out to the Metacheck development team.

How Marginal Significance works

List all sentences that describe an effect as ‘marginally significant’.

The marginal module searches for regular expressions that match a predefined pattern. The list of terms is a subset of those listed in a blog post by Matthew Hankins. The module returns all sentences that match terms describing ‘marginally significant’ results.

Some of the terms identified might not be problematic in some contexts, and there are ways to describe ‘marginal significance’ that are not detected by the module.

How Exact P-Values works

List any p-values reported with insufficient precision (e.g., p < .05 or p = n.s.) or reported as exactly zero (e.g., p = .000).

This module uses regular expressions to identify p-values. It will flag any values reported as p > ? or p < numbers greater than .001. It will also flag p-values reported as exactly zero (e.g., p = .000, p = 0.00), which are mathematically impossible — p-values are never exactly zero and should instead be reported as p < .001.

A p-value that is not the result of a test is not flagged: a table note (“* p < .05, ** p < .01”), a figure legend (“Asterisks indicate significant differences (p < .05)”, “Values in bold are significant at p < .05”) or a stated threshold (“p < .05 was considered significant”, “thresholded at p < .001”). GROBID often puts such notes into the running text, so each p-value is judged by the words in its own clause (the text up to a “;” or a full stop), and never left out when a test statistic belongs to it (“F(1, 7) = 8.03, # p < .05”). The column not_a_test of the table says why a p-value was left out (“marker”, “threshold”, “legend” or “named”).

A p-value with the name of a correction or a test after the p (“pFWE < .05”, “padj < 0.05”, “p Wilcoxon = .02”) is flagged only when a test statistic comes before it in its clause (“t(37) = 7.17, p FWE < .05”). Without one it is mostly the rule that decided what was significant (“genes with padj < 0.05 were selected”); such a p-value is “named” in not_a_test. Notes in other forms, such as a marker after the p-value (“p < .05 (*)“), are still flagged.

This module sometimes flags false positives when sentences discuss how p-value thresholds were set. It can also miss an imprecise p-value that is reported against a threshold (“decreased at the p < .05 significance threshold”).

This module only checks p-values reported in the running text of the manuscript. It cannot (yet) process p-values reported only in tables (as opposed to a table’s footnote text, which the module does see and tries to exclude — see above).

How Repository Check works

This module retrieves information from repositories.

The Repository Check module lists files on the OSF, GitHub, ResearchBox, DSpace (PsychArchives and other legacy- and DSpace 7-based installations), Zenodo, Dataverse, Figshare, Dryad, ReShare, 4TU.ResearchData, Mendeley Data, DataONE (Arctic Data Center, KNB, and other member nodes), and LDbase based on links in the manuscript.

Listing a repository’s files never requires an API key, but some hosts answer faster or more completely with one: OSF allows 100 requests/hour unauthenticated versus 10,000/day with a token (see [osf_pat()]), and Dryad enforces a strict per-IP daily quota on repeated listing (see cache below). Dryad is a special case beyond rate limits: listing a Dryad dataset’s files works without a key, but actually downloading file CONTENTS from Dryad fails with HTTP 401 unless a key is set, even for a fully public dataset (see [dryad_pat()] or [dryad_auth()]). When a linked OSF page is a registration, its registered_from project (the one it was registered from, which the manuscript itself may never link directly) is also checked: if that project is public its files are listed under its own URL, and if it is closed or otherwise inaccessible the report flags it explicitly, since some registrations only describe their content rather than mirroring it.

How Code Check works

This module retrieves information from repositories checked by repo_check about code files (R, Python, SAS, SPSS, Stata, Mplus, MATLAB).

The Code Check module checks R (also R Markdown and Quarto), Python (also Jupyter notebooks), SAS, SPSS, Stata, Mplus, and MATLAB files, using regular expressions to check the code; JASP files are listed but not read. The language of a Quarto document or a notebook is read from the file itself (its engine or kernel), not from its extension. The regular expression search will detect the number of comments, the lines at which libraries/imports are loaded, attempts to detect absolute paths to files, setwd() and install.packages() calls, and lists files that are loaded, and checks if these files are in the repository; R code is also parsed. The module will return suggestions to improve the code if there are no comments, if libraries/imports are loaded in lines further than 4 lines apart, if files that are loaded are not in the repository, if absolute file paths, setwd() or install.packages() are found, and if R code cannot be parsed.

The regular expressions can miss information in code files, or falsely detect parts of the code as a fixed file path. Libraries/imports might be loaded in one block, even if there are more than 3 intermittent lines. The module was tried out internally on papers published in Psychological Science, but has not been formally validated. There might be valid reasons why some loaded files can’t be shared, but the module can’t evaluate these reasons, and always gives a warning.

The module also checks whether the repository pins the R/package versions the analysis actually depended on: an renv.lock file (parsed for the R version and every locked package + its version/source), a sessionInfo()/sessioninfo::session_info() text dump (matched by filename — sessionInfo.txt/session_info.txt and similar, or embedded in a README), or a groundhog::groundhog.library()/checkpoint::checkpoint() date-pin call in the code (a bare library(groundhog)/library(checkpoint) does not count — the pinning call itself must be present). When none of these is found, the report flags it as a reproducibility gap: package versions may drift between when the analysis was run and any later reproduction attempt.

How Data Check works

This module classifies the files in a repository into semantic types (data, codebook, code, software, output, supplemental, readme, asset, other) and, for tabular data files, extracts each column’s type and summary statistics.

The Data Check module consumes the file list produced by repo_check (or any files added via local_path). Each file is classified with rule-based heuristics layered over metacheck’s file_category() and file_types: file names matching README / codebook patterns win first, then an extension crosswalk, then format-locked extension overrides. For every file classified as tabular data that is available locally, the module reads the file head, describes each column with data_col_facets() and computes summary statistics for numeric columns. Every sheet of a spreadsheet that holds a table is read: a file with several such sheets has its columns under source_file = "file.xlsx [sheet]", and the sheet column names the sheet of any spreadsheet with several sheets; a sheet of notes or a codebook is treated as documentation when the file has another table. Following DDI, a column is described by orthogonal facets rather than a single type: representation (numeric/text/datetime/code — how it is stored), measurement_level (Stevens: nominal/ordinal/interval/ratio), concept (what it measures: reaction_time/age/gender/likert/id/…), role (identifier/measure/condition/timestamp), unit, and a quality state (ok/empty/constant). Concepts are detected by name+value rules (the demographic concepts via data_check_demographic()); when llm_use(TRUE) the model fills concepts and measurement levels the rules left blank. Qualtrics survey exports are recognised (data_check_is_qualtrics()): their extra header rows are stripped so columns type correctly, and the reserved response-metadata columns (StartDate, Duration, Finished, …) are tagged.

The module defaults to rules-only when llm_use(FALSE): columns the rules cannot resolve (ambiguous 3–20-unique integers, ambiguous character columns) fall back to continuous / text respectively. When llm_use(TRUE), ambiguous columns and unresolved file types (other) are sent to llm() for optional refinement, and every file is assigned a study group (ex1, pilot2, shared, …) so that multi-study repositories can be recognised (used by psychds_check). Without an LLM the study group is left NA (unknown).

Column extraction requires files to be readable from disk. Files fetched by repo_check from OSF/GitHub/etc. without a local copy (file_location is NA) are classified but not column-extracted; pass local_path to point at a downloaded copy of the repository.

For a paper whose repository is on Dryad, this means column extraction never happens unless a Dryad API key is set: Dryad requires one to download file bytes, even from a fully public dataset (dataset listing and metadata do not need one). Without a key, every Dryad file stays classified but un-downloaded, column_n is 0, and a warning naming Dryad and ?dryad_pat/?dryad_auth is included among the download failures. A one-time session message is also shown (see repo_check) the first time a Dryad dataset is encountered with no key set.

Every downloaded text file the authors wrote (code, settings, survey definitions such as Qualtrics .qsf files, documentation, outputs) is searched for keys: API keys, access tokens and private keys, which let anyone who downloads the file use a paid service at the authors’ cost. Of a tabular data file only the column names and first 3 rows of the table as read are searched: its values come from participants, but a key the authors set for a whole survey (as embedded data in a Qualtrics survey flow) is exported in every response. The search uses the rules of the secret scanner betterleaks (https://github.com/betterleaks/betterleaks, MIT licence) of high and medium confidence. A key found turns the traffic light red; the report and the keys table give its file, line and type, and only its beginning. Other files over 25 MB and binary files are not searched. A key is never tested with its provider. Every module’s result has any whole key replaced by “keyremoved” (see module_run()).

How Reproducibility Check works

This module assesses whether a paper’s R and Python code can be run on its data. It works in two phases. The static phase (always run) collects the package dependencies the code declares, rewrites the data-file paths that do not work in the repository as the authors organised it, works out the order the scripts must run in, and diagnoses why any referenced input file is unavailable — reporting what a reproduction attempt would involve and where it is likely to break. The execution phase (opt-in, execute = TRUE) then actually runs the code: it copies the repository into a throwaway directory, optionally installs the declared dependencies into a throwaway library, runs each script in order in an isolated subprocess with a per-script timeout, and captures the outcome and full output of each run.

By default (execute = FALSE) the module does not run any code — it performs only static analysis: reading dependencies with the same extractors as code_check, finding the files the code references in the repository, and building a run-order dependency graph. It reports what would be installed and run rather than doing it.

When execute = TRUE, the module additionally runs the downloaded code on your machine — a deliberate, opt-in action gated behind that argument (callr is required for R code). Each script runs in an isolated subprocess so a crash cannot take down the R session; note this isolates crashes, not the filesystem or network. Installs (when install_missing = TRUE) and the throwaway run library never touch your main R library. Each script’s outcome is one of ran_ok, errored, timed_out, dependency_unavailable, not_parsed, run_by_source (an R script another script runs with source(), which is run only inside that script, since on its own it lacks the packages and objects the sourcing script sets up first), run_by_import (a Python file other files import, a module rather than a script, unless it has an if __name__ == "__main__": block), jags_model (a JAGS or BUGS model saved with an R extension, which another script reads) or not_r_content (a file that is not R at all, such as a JSON or HTML dump); these last two are not run and are not failures. python2 marks Python 2 code that was not run. With sandbox = "docker" such code runs with Python 2.7 (option metacheck.docker_image_py2; FALSE turns this off), which modifications records; it is never converted, since that can change results. defines_functions is a file that only defines functions, which is used, not run (table$used_by names the scripts that use it), and not_analysis is a file of software rather than of the analysis: a package’s code, tests, documentation or setup.py, a copy of a tool, a web application, a script a program wrote (table$not_analysis_why says which); neither is run or counted as a script. docker_failed means the container never started, which says nothing about the script, so it keeps the light from being green but does not make it red. needs_a_person is a script that stopped because it asks a person to choose a file or answer a question, or that starts an app, and needs_internet one that stopped because the network is off in a Docker run, or, with internet = TRUE, could not reach what it asked for; download_too_large is a script stopped for downloading more than the limits allow (see internet), and out_of_memory one that, or a program it started (such as a compiler), ran out of the memory each script may use. All four are treated the same way. not_downloaded is a script that stopped on a file the repository lists but that was not downloaded, such as one over max_file_size: it could not be tried, so it is not counted as a script that did not reproduce (summary_table$repro_not_downloaded_n counts them apart). not_read is a file metacheck could not read, so it was not run; the light is then not green, as the file may read and run on another computer, and table$error_message says why, naming a package that is installed but cannot be loaded on the computer that ran the check. empty is a file with nothing in it, which is not run or counted as a script. For a script that did not run through, table$error_message is its error, short (at most 300 characters): the error line of its output, which names a package that is not there, with the address it asked for when it needed the internet, or the time limit it reached; table$reason sorts it into a kind. A timeout means “still running at the cutoff”, not a failure, so raise timeout for legitimately long-running (e.g. Bayesian) scripts. dependency_unavailable means the script’s own package could not be installed from live CRAN, the CRAN Archive, or a named GitHub/URL source — an infrastructure limitation, not a defect in the paper’s code, so unlike errored/timed_out it does not force the traffic light red. The full stdout/stderr of every run is kept in the result’s run_results (the report shows it in per-script dropdowns, capped for readability). The traffic light reflects the STATIC readiness signals by default, but an execution error (errored/timed_out) does recolour it to red — a script that crashes on its own analysis is a genuine reproduction failure. A script that fails with could not find function is run once more with the library() calls the project’s other scripts make added at its top (or the one package that exports the function, or magrittr for %>%), and a script that then runs is reported as reproducible only after that repair.

Dependencies are reported name-only, with the source (CRAN, GitHub, or a base package already shipped with R) — static analysis of the code cannot know which version was used, and running against current package versions is itself informative: a break argues the authors should have pinned versions. When the repository does record versions, a run with recorded_versions = TRUE installs the packages the scripts load at those versions, but it does not change the R version, which remains a limitation of the check.

Run order is derived from read-after-write data dependencies (a script writing a file another reads must run first), source() edges, and numeric filename prefixes as a weak tie-breaker. Ambiguous orderings, dependency cycles, and inputs a script reads but that no earlier script produces (and that are not in the repository) are surfaced as warnings, since these are the situations most likely to make an otherwise-correct reproduction fail.

Python code (.py files, and notebooks and Quarto documents whose code is Python, from which the code is extracted first) goes through the same two phases, reported in its own “Python code” section. Each file is checked for syntax errors with Python’s own parser when a Python interpreter (python, or else python3) is available; dependencies are read from the import statements, with versions from a requirements.txt or pyproject.toml when there is one, and installed with pip; each script runs as its own python process (processx is required), so unlike R scripts, a name one script defines is not available to another. When no Python interpreter is available, the Python files are reported as not run and the R results are still returned. Statistics the Python scripts print are compared with the paper together with the R output and any self-reproducible output (JASP/jamovi, SPSS-Viewer, notebook outputs).

Abstract

Visual processing varies systematically with eccentricity: Stimuli in the periphery are perceived as slower, lower in contrast, and shorter in duration compared with foveal stimuli.

Whether these asymmetries reflect a single underlying mechanism, such that removing one asymmetry eliminates others, or partly distinct mechanisms remains unknown. We tested this question for perceived motion speed and duration, both underestimated in the periphery, by asking whether perceptually equalizing motion speed across the visual field eliminates or reduces the foveal duration bias. In a two-phase design, each participant's peripheral speed bias was first measured at two eccentricities (approximately 11° and 22°). Participants then compared the durations of foveal and peripheral random dot kinematograms (100-1,600 ms) under physical or perceptual speed equality. The calibration showed robust peripheral speed underestimation at both eccentricities, increasing with distance from fixation. Under physical speed equality, the foveal stimulus was judged to last longer than the peripheral one. Critically, perceptual speed equalization reduced this foveal duration bias by approximately 60%, and this reduction was larger for participants whose calibrated speed correction was larger, consistent with a doseresponse relationship. However, a significant residual bias persisted even after perceptual speed equalization. These findings suggest that asymmetries between foveal and peripheral vision do not reflect a single underlying mechanism, but rather reflect a number of partly distinct yet related mechanisms that operate on different features, in this case motion speed and duration.

Testing the Speed-Duration Link: Perceptual Equalization of Motion Speed Reduces the

Foveal Duration Bias

Visual processing varies systematically across the visual field: As stimuli move from the fovea toward the periphery, spatial resolution declines (Anstis, 1974) and contrast sensitivity decreases (Rovamo et al., 1978). These eccentricity-dependent changes affect the perceived magnitude of many stimulus features, including size, numerosity, and speed (for a review, see Stewart et al., 2020), and such features in turn interact directionally with the perception of time (Brown, 1995; Cai & Connell, 2015; Eagleman, 2008; Eagleman & Pariyadath, 2009; Karsilar et al., 2025 Karsilar et al., , 2026;; Walsh, 2003; Xuan et al., 2007). A key question is whether these various eccentricity-dependent asymmetries are manifestations of a single underlying mechanism, in which case removing the asymmetry in one dimension should eliminate it in another, or whether they arise from partly distinct processes. The present study addresses this question for two particularly well-established asymmetries: those in perceived motion speed and perceived duration.

One of the most robust perceptual asymmetries across the visual field is the underestimation of motion speed in peripheral vision. Peripheral stimuli moving at the same physical speed as foveal stimuli are perceived as slower (Brooks & Mather, 2000; Tynan & Sekuler, 1982), and the magnitude of this underestimation scales with eccentricity (Johnston & Wright, 1986). The effect is substantial: Under typical viewing conditions, peripheral gratings appear approximately 10% slower at 6° and 20% slower at 32° eccentricity even when their perceived contrast is matched to that of foveal gratings, and slow gratings appear slower still when it is not (Hassan et al., 2016). This underestimation is generally attributed to reduced spatial-frequency sensitivity, lower effective contrast, and noisier motion encoding at greater eccentricities (Blakemore & Snowden, 1999; Hassan et al., 2016; Mareschal et al., 2008; Orban et al., 1986; Thompson, 1982; Thompson et al., 2006).

A parallel asymmetry exists for perceived duration. Peripheral stimuli are perceived as shorter in duration than foveal stimuli of the same physical duration, and the magnitude of this underestimation increases with eccentricity (Aedo-Jury & Pins, 2010; Bao et al., 2024; Kliegl & Huckauf, 2014). The effect persists after cortical magnification scaling (Kliegl & Huckauf, 2014) and is not reduced by transient attentional cueing (Krug et al., 2024) or endogenous attentional cueing (Krug & Huckauf, 2025). The direction of the effect may depend on the duration range: Krug et al. (2025) reported that while peripheral stimuli appear shorter at brief durations (20-220 ms), the effect reverses at longer durations (400-1,600 ms), possibly due to endogenous attentional shifts, and Upadhyayula et al. (2023) found longer perceived durations at 12° than at 3° eccentricity for durations of 750-1,525 ms. However, these reversal findings, like the demonstrations of the underestimation itself (Aedo-Jury & Pins, 2010; Bao et al., 2024; Kliegl & Huckauf, 2014), were obtained with static or briefly flashed stimuli; whether continuously moving stimuli, which provide a sustained perceptual cue to duration encoding, produce the same pattern is unknown.

The relationship between motion speed and perceived duration is also well documented and is perhaps the most robust finding in the time perception literature. Faster-moving stimuli are generally perceived as lasting longer than slower or stationary stimuli of the same physical duration (Brown, 1995; Kaneko & Murakami, 2009; Karsilar et al., 2018; Tomassini et al., 2011). Whether the critical variable is speed per se (Kaneko & Murakami, 2009) or temporal frequency (Kanai et al., 2006; Linares & Gorea, 2015) remains debated, but the empirical pattern is robust: Increased motion speed lengthens perceived duration.

These three findings raise a natural question: Are the eccentricity-dependent duration underestimation and the eccentricity-dependent motion speed underestimation different manifestations of the same underlying mechanism? If so, removing the speed asymmetry should also remove the duration asymmetry. If, instead, eccentricity affects duration through additional, speed-independent mechanisms, such as differences in temporal integration, attention, or neural processing efficiency (Poggel et al., 2012; Tse et al., 2004; Zakay & Block, 1997), then a residual duration bias should persist even after perceived motion speed is equated. We refer to this eccentricity-dependent distortion of perceived duration as the foveal duration bias, adopting this term rather than the broader "eccentricity effect on perceived duration" used in prior work (e.g., Kliegl & Huckauf, 2014; Krug et al., 2024) to emphasize the directional pattern under investigation: a systematic bias toward judging the foveal stimulus as lasting longer in a direct comparison. Crucially, none of the existing studies have isolated perceived motion speed as the mediating variable. The present study was designed to fill this gap. We tested these predictions using a two-phase within-subjects design. In the calibration phase, each participant's peripheral motion speed underestimation (relative to a foveally presented stimulus) was individually measured at two eccentricities (near: 11.4°, far: 22.0°) using QUEST adaptive staircases (Watson & Pelli, 1983), yielding a point of subjective equality (PSE) for perceived motion speed. In the main phase, participants compared the durations of a foveal and a peripheral random dot kinematogram (RDK) in a two-interval forced-choice (2IFC) task under two speed conditions: physically equal (identical on-screen speeds) and perceptually equal (foveal speed unchanged, peripheral speed set to the participant's PSE; see Design below). This design tests three predictions. First, peripheral stimuli should be perceived as slower than foveal stimuli, with greater underestimation at the farther eccentricity (H1). Second, under physical speed equality, a foveal duration bias should emerge: Peripheral stimuli should be perceived as lasting shorter than foveal stimuli (H2). Third, equalizing perceived motion speed should reduce the foveal duration bias (H3). If the eccentricity-dependent asymmetries for motion speed and duration reflect a common mechanism, equalization should eliminate the bias entirely; if a residual foveal duration bias persists, this would indicate that multiple, partly distinct eccentricity-dependent mechanisms are at play.

In sum, the present study provides a direct test of whether the eccentricity-dependent asymmetries in perceived motion speed and perceived duration reflect a shared mechanism (such that removing the speed asymmetry eliminates the duration asymmetry) or partly distinct processes that leave a residual bias even after speed is equalized. two eccentricities × two presentation orders × 16 durations, with random intercepts for participants; see below), assuming a random-intercept standard deviation of 0.25 on the logit scale, 256 equal-duration trials per participant, and a loss of 10% of trials to exclusions. Method

This expected effect size was derived by reasoning from two independent literatures: Peripheral stimuli appear substantially slower than foveal stimuli moving at the same physical speed (Hassan et al., 2016; Johnston & Wright, 1986), and perceived duration increases approximately in proportion to log speed (Brown, 1995; Kaneko & Murakami, 2009). Because these literatures use different paradigms and dependent measures (speed matching and duration reproduction/production, respectively), the expected OR for a 2IFC duration comparison could not be read directly from prior work; OR = 0.90 represents a deliberately conservative estimate of the predicted shift, chosen so that the design would not be underpowered if the true effect were small. Our final sample of 66 participants meets the 65 needed for 85% power. The foveal duration bias itself (H2) was well-powered (> 99%) at all sample sizes considered.

Stimuli and Apparatus

Stimuli were presented on an ASUS ROG Swift OLED PG27AQDM monitor (2,560 × 1,440 pixels, 0.229 mm per pixel; 120 Hz) using OpenSesame 4.1.8 (Mathôt et al., 2012) with the PsychoPy backend (Peirce, 2007) for stimulus presentation and PyGaze (Dalmaijer et al., 2014) for eye tracking. An EyeLink 1000 eye tracker (SR Research) recorded eye position at 1000 Hz throughout the experiment. Participants sat in a dimly lit room, with their head stabilized by a chin rest, at a viewing distance of 57 cm from the screen. At this distance, one pixel subtended approximately 1.4 arcmin at the center of the screen (43.4 pixels per degree); the visual angles reported below were computed from the pixel dimensions of the stimuli and the viewing distance.

The stimuli were RDKs displayed within circular apertures against a dark gray background (RGB: #3d3846; 12.6 cd/m²). Each aperture had a diameter of 269 pixels, corresponding to 6.2° of visual angle at the screen center. Dots were generated in a circular field six times the diameter of the aperture and were visible only inside the aperture, so that dots continuously entered and left the aperture. A new set of dot positions was generated for every stimulus presentation.

The display contained five circular placeholders arranged horizontally: one at the center of the screen (fixation location) and one on each side at two eccentricities, 11.4° (near) and 22.0° (far) from fixation (see Figure 1). These placeholders were drawn as thin (1-pixel) white outlines against the dark gray background and remained visible throughout each trial. On each trial, the two active locations (center and one peripheral location) were indicated by thicker (4-pixel) outlines. A small white fixation dot was drawn at each of the five locations. Design

The experiment used a within-subjects design with two sequential phases.

Calibration Phase Design

A QUEST adaptive staircase (Watson & Pelli, 1983) was used to estimate each participant's PSE for perceived speed between a foveal and a peripheral RDK. Two interleaved staircases were run, one for each eccentricity level (near, far), with 40 trials per staircase (80 calibration trials total). The staircase operated on a log₁₀ scale of the peripheral speed, starting at 10% above the center speed (12.7°/s), with a starting standard deviation of 0.15 log₁₀ units. The target threshold was set to .50 (the 50% response point, corresponding to the PSE), the slope parameter (β) was 4.0, the lower asymptote (γ) was .01, and the lapse rate (δ) was .01. The tested peripheral speed was bounded between 0.033 and 2 times the center speed (0.4 and 23.1°/s). At the end of the calibration phase, each participant's PSE was extracted as the posterior mean of the QUEST distribution and converted to linear speed. This participant-specific PSE was used to set the peripheral stimulus speed in the perceptually equal condition of the main phase.

Main Phase Design

Duration judgments were collected in a 2IFC paradigm. On each trial, one stimulus appeared at the center of the screen and one at a peripheral location; participants judged which stimulus lasted longer. On equal-duration trials, the design crossed four factors: speed condition (physically vs. perceptually equal), eccentricity of the peripheral stimulus (near: 11.4°, far: 22.0°), presentation order (center first vs. peripheral first), and stimulus duration (16 levels from 100 to 1,600 ms in 100-ms steps). In the physically equal condition, the peripheral stimulus moved at the same on-screen speed as the central stimulus. In the perceptually equal condition, the peripheral stimulus moved at the participant's individually calibrated PSE speed, such that the two stimuli were expected to be perceived as moving at the same speed.

On equal-duration trials (80% of all trials), both stimuli had the same duration. On catch trials (20%), the center stimulus was 20% longer or 20% shorter than the peripheral stimulus, serving as a check on task compliance as well as making the task more engaging. Each block contained eight catch trials with peripheral durations of 150 to 1,550 ms in 200-ms steps, alternating between a longer and a shorter center stimulus, each with a fixed presentation order and motion direction (upward on all longer-center and downward on all shorter-center catch trials).

The main phase was divided into eight blocks of 40 trials each (320 trials per participant), with each block fixing one combination of peripheral side (left or right of fixation), eccentricity, and speed condition. Each block contained the 32 equal-duration trials (16 durations × 2 presentation orders) and the eight catch trials in random order. Motion direction was fixed for each combination of duration and presentation order (upward for one order and downward for the other, alternating across durations), so that each direction occurred on half of the trials in each presentation order. Block order was randomized.

Procedure

Each session began with the participant reading and signing the informed consent form, followed by a brief verbal explanation of the task (~3-4 min). Participants then completed a practice session (~5 min), which was a shortened version of the full experiment: It included a brief speed-judgment calibration block (10 trials at near eccentricity) and two abbreviated duration-judgment blocks (eight trials each, one per speed condition, with the peripheral stimulus on the right and durations of 200-800 ms), using the same response mappings and trial structure as the main experiment.

Following the practice session, the main experiment began with a standard 9-point eyetracking calibration. Each trial within the session was initiated with a fixation-triggered drift correction (single-point recalibration) procedure. Including consent, practice, and data collection, the full session lasted approximately 55-60 min.

Calibration Phase Procedure

Each calibration trial began with a drift correction, followed by the fixation display (placeholders and fixation dots; see Figure 1), which lasted approximately 461 ms. The first stimulus (Stimulus 1) then appeared for 850 ms, followed by a blank interstimulus interval (ISI) of approximately 262 ms (SD = 13 ms), during which only placeholders and fixation dots were visible, and then the second stimulus (Stimulus 2) for 850 ms. A jittered stimulus-response interval (SRI; 300-500 ms, uniform distribution) preceded the response prompt. The fixed 850ms stimulus duration was chosen to ensure a long enough viewing period for stable speed percepts, and is also at the center of the array of durations tested in the main phase (see Main Phase Procedure below).

On each calibration trial, one stimulus appeared at the center and the other at the peripheral location; the order of center and peripheral stimulus was counterbalanced. Participants indicated which stimulus appeared to move faster by pressing the "Up Arrow" key for center or either the "Left Arrow" or the "Right Arrow" key for the peripheral stimulus. The response was scored as 1 (peripheral judged faster) or 0 (center judged faster), and the QUEST staircase was updated accordingly.

Main Phase Procedure

The trial structure was identical to the calibration phase (with the same ISI), except that Stimulus 1 and Stimulus 2 durations varied from trial to trial (100-1,600 ms, with catch-trial adjustments where applicable). Participants now judged which stimulus lasted longer, responding with the same key mapping. Responses could only be registered after the response prompt had appeared; key presses made earlier were discarded. Brief breaks were offered between blocks.

Trials on which the participant's gaze deviated from the fixation location during stimulus presentation were flagged offline and excluded from analysis (see Data Processing and Exclusion Criteria).

Data Processing and Exclusion Criteria

Eye-tracking data were preprocessed using the Python eyelinkparser package (Mathôt & Vilotijević, 2023). A trial was flagged as a fixation loss if the average position of any fixation that ended during Stimulus 1 or Stimulus 2 (as detected by the EyeLink parser) was more than 135 pixels (3.1°, the radius of the central aperture) horizontally or vertically from the screen center. Across all participants, 1,403 of 21,120 main-phase trials (6.6%) were excluded on this basis (per participant: M = 6.6%, SD = 11.6%, Mdn = 2.3%). Fixation losses were concentrated in four participants, who lost 42.8%-55.9% of their trials; they retained 108-140 of their 256 equal-duration trials, whereas all other participants retained at least 206. Trials with response times longer than the participant's mean + 3 SD (computed over all 320 main-phase trials of that participant) were also removed (357 of the 19,717 remaining trials, 1.8%; 1-10 trials per participant).

After all exclusions, 19,360 main-phase trials remained for analysis, of which 15,473 were equal-duration trials.

Analytical Approach

The dependent variable in the main phase (i.e., whether the center stimulus was judged as lasting longer) is a binary outcome on each trial. We modeled these trial-level responses using GLMMs with a binomial family and logit link, which naturally accommodate unbalanced trial counts, binary outcomes, and between-participant variability via random effects (see Karsilar et al., 2025 Karsilar et al., , 2026)). All GLMMs were estimated with the glmer function in the lme4 package (version 2.0-1; Bates et al., 2015) in R (version 4.5.2), using the bobyqa optimizer (maxfun = 100,000); convergence was checked with gradient and singularity diagnostics, and all models whose results we report converged without singular fits. Stimulus duration (in seconds) was centered at 850 ms, the midpoint of the tested range. Categorical predictors were effect coded (+1/-1), so that main effects and lower-order interactions are averaged over the levels of the other factors. Fixed-effect significance was assessed with Type III Wald χ² tests (car package; Fox & Weisberg, 2019); estimated marginal means (EMMs) and contrasts were obtained with the emmeans package (Lenth & Piaskowski, 2026), with Šidák adjustment for the three pairwise catch-trial contrasts. Model diagnostics were evaluated using simulated residuals (DHARMa; Hartig, 2024) and showed no deviations from the model assumptions. Unless stated otherwise, all models included by-participant random intercepts and random slopes for speed condition, presentation order, duration, and the presentation order × duration interaction, with correlations among them (in the random part, speed condition and presentation order were coded numerically as ±0.5). Following Barr et al. (2013), this is the maximal random-effects structure that could be estimated without singular fits: It fitted better than random intercepts only (ΔAIC = 957), whereas adding random slopes for eccentricity and its interaction with speed condition produced singular fits. With random intercepts only, or without the correlations among the random effects, all conclusions were the same.

We complement the GLMMs with descriptive analyses of per-participant response proportions. For each participant and condition, P(center longer) was computed by averaging the binary responses. These proportions were tested against .50 (chance) using one-sample t tests, with paired t tests for within-subject comparisons. Effect sizes are reported as Cohen's d (onesample) or Cohen's dz (paired). To quantify evidence for and against the null, we computed Jeffreys-Zellner-Siow (JZS) Bayes factors (BF₁₀; Rouder et al., 2009) with a default Cauchy prior (r = √2/2), interpreted following Lee and Wagenmakers (2014): BF₁₀ > 10 strong evidence for the alternative hypothesis; 3-10 moderate; 1/3-3 anecdotal; < 1/3 moderate-to-strong evidence for the null hypothesis. All frequentist tests were two-tailed. Where within-subject error bars are shown, the Cousineau-Morey correction was applied (Cousineau, 2005; Morey, 2008).

The three core hypotheses (H1-H3), the two-phase experimental design, and the primary analytical strategy were specified before data collection began. Models for the time-order effect, the duration interactions, and individual differences are reported as exploratory analyses and are labeled as such where they are reported.

Discussion

In the present study, we tested whether the eccentricity-dependent asymmetries in perceived motion speed and perceived duration reflect a shared mechanism, by asking whether perceptually equalizing motion speed eliminates the foveal duration bias. Using individually calibrated speed corrections derived from QUEST adaptive staircases, we found that equalizing the perceived speed of foveal and peripheral stimuli reduced the foveal duration bias by approximately 60%, but did not eliminate it. In other words, the speed asymmetry, although substantial, accounted for only part of the duration asymmetry. This suggests that eccentricitydependent asymmetries in perceived speed and duration reflect at least in part distinct mechanisms, because eliminating one does not fully eliminate the other.

The equalization effect also showed a dose-response relationship with the calibrated speed correction: Participants who exhibited greater peripheral motion speed underestimation showed a correspondingly larger reduction in foveal duration bias when that speed difference was removed. Because a larger correction also meant a faster peripheral stimulus, one might ask whether the equalization effect is instead a generic consequence of increasing peripheral speed (e.g., through an arousal or salience mechanism). Two further observations favor a link to perceived speed: Under physical speed equality, when all participants saw identical speeds, the foveal duration bias was larger in participants with greater speed underestimation, and after equalization the bias did not vary significantly with the size of the correction.

Our calibration measured each participant's PSE at 850 ms, the middle of the duration range, and applied it at all durations, which assumes that peripheral speed underestimation does not depend on stimulus duration. The data are consistent with this assumption: The equalization effect did not vary with duration, either linearly or across the 16 durations, and it was in the same direction at every duration (see Supplementary Materials S4). Because each PSE was estimated from 40 staircase trials, equalization cannot have been exact for every participant (Supplementary Materials S1). Random error of this kind would not by itself produce a residual bias, and the absence of a relationship between the residual bias and the size of the correction (see above) argues against a systematic undercorrection proportional to the speed bias. Finally, because the stimuli were shown on a flat screen, the peripheral stimuli were slightly slower and smaller in angular terms than their on-screen values imply; crucially, expressed in angular units, the calibration results and the dose-response relationship were the same (Supplementary Materials S6).

How do our findings relate to cortical magnification? In a landmark study, Daniel and Whitteridge (1961; see also Talbot & Marshall, 1941) showed that, in primary visual cortex (V1), foveal vision is strongly overrepresented relative to peripheral vision. (More accurately, there is a steep drop-off as a function of eccentricity in the amount of cortical surface dedicated to processing a constant area of visual space; Horton & Hoyt, 1991). This likely explains, at least in part, why many visual features, including motion speed and perceived duration, are underestimated in peripheral as compared to foveal vision. However, the extent of foveal overrepresentation is relatively constant across different areas in the visual cortex, including area MT involved in motion perception, likely because all visual areas inherit this property from V1 (Harvey & Dumoulin, 2011; Tootell et al., 1995). This means that differences in eccentricitydependent asymmetries between different visual features (such as motion speed and perceived duration) do not necessarily reflect differences in cortical magnification between the visual areas involved in processing these features. Why, then, does removing the speed asymmetry leave part of the duration asymmetry in place?

A key observation is that the ability to distinguish between different motion speeds is relatively constant across the visual field (McKee & Nakayama, 1984). Motion discrimination is a temporal task that requires integration of information across a large area, rather than a spatial task that requires high spatial resolution. This likely explains why the eccentricity-dependent asymmetry for perceived motion is weaker than for most other features-though still clearly present. But shouldn't the same apply to perceived duration? Isn't time perception by definition a temporal task? The counterintuitive answer may be that time perception is in fact not a temporal task in the same way that motion discrimination is. Rather, as intrinsic (or distributed) models of time perception propose, perceived duration reflects aggregated activity across a wide range of brain areas, involved in processing a wide range of stimulus features (Ivry & Schlerf, 2008; Roseboom et al., 2019; Salet et al., 2022). Many of the stimulus features that contribute to perceived duration are spatial and have a strong eccentricity-dependent asymmetry (Burr et al., 2007). As a result, perceived duration itself also has a strong eccentricity-dependent asymmetry, and equalizing only one of these features-perceived speed-would reduce, but not eliminate, the duration asymmetry, as we observed. Taken together, our results are consistent with intrinsic models of time perception, at least when it comes to perceived duration of brief visual stimuli.

However, it should be noted that, because it is not known where in the brain perceived duration is computed, this argument is necessarily speculative.

In conclusion, the eccentricity-dependent asymmetries in perceived motion speed and perceived duration are partly but not entirely shared: Removing the speed asymmetry substantially reduced the foveal duration bias but did not eliminate it. The residual bias after equalization suggests that eccentricity also influences temporal processing through mechanisms other than perceived speed.

S2. Participants Without Peripheral Speed Underestimation

Although the group-level results clearly confirm peripheral motion speed underestimation (H1; see main text), a subset of participants showed PSE ratios at or below 1.0 at one or both eccentricities, indicating no measurable speed underestimation in the calibration phase.

Specifically, 12 of 66 participants (18%) showed a PSE ratio ≤ 1.0 (a PSE at or below the center speed of 11.6°/s) at near eccentricity, five participants (8%) at far eccentricity, and four participants (6%) at both eccentricities. These PSE ratios ranged from 0.62 to 0.98 (7.2-11.4°/s).

Several factors may explain individual PSE ratios at or below 1.0. First, genuine individual differences in peripheral speed perception exist: Some individuals may show little or no speed underestimation at moderate eccentricities, particularly at near (11.4°) where the group-level effect is smaller. Second, measurement noise in the QUEST staircase could produce PSE estimates at or below 1.0 even for participants who do underestimate peripheral speed on average; the staircase had 40 trials per eccentricity, which provides reasonable but not unlimited precision. Third, the lower incidence at far eccentricity (8% vs. 18% at near) is consistent with the stronger group-level underestimation at greater eccentricities. These participants were retained in all analyses. Excluding them would bias the sample toward participants with the strongest calibration effects, potentially inflating both the H1 effect and the speed equalization effect (H3). Their inclusion provides a more conservative test of our hypotheses.

S5. Logit-Scale Verification of Decomposition

In the main text, we report that perceptual speed equalization reduced the foveal duration bias from approximately 7.4 percentage points above chance to approximately 3.1 percentage points, accounting for 59% of the raw bias magnitude (95% BCa bootstrap CI: [41%, 78%]). Because the GLMM uses a logit link, we verified this proportion on the logit scale to confirm it is not an artifact of the probability scale (logits computed from the unrounded means): logit(.574) = 0.300, logit(.531) = 0.123, logit(.50) = 0, yielding a reduction of (0.300 -0.123) /0.300 ≈ 59%. This near-identity between the probability-scale and logit-scale estimates is expected when probabilities are close to .50, where the logit function is approximately linear.

S6. Display Geometry

The experiment script specified stimulus sizes, positions, and speeds in degrees of visual angle and converted them to pixels at a viewing distance of 57 cm. Because the screen was flat, the angular size and speed of a stimulus also decreased with its distance from the screen center: At equal on-screen speed, the near and far peripheral stimuli moved 2.0% and 7.3% slower in angular terms than the central stimulus. The PSE ratios in the main text are ratios of on-screen speeds, the quantity that was manipulated.
