How Power Analysis Check works

This module uses regular expressions to identify sentences that contain a statistical power analysis. If specified by the user, it also uses a large language model (LLM) to extract information reported in power analyses, including the statistical test, sample size, alpha level, desired level of power, and magnitude and type of effect size.

The Power Analysis Check module uses regular expressions to identify sentences that contain a statistical power analysis. Without the use of an LLM, the module uses regular expressions to classify the power analysis as a-priori, sensitivity or post-hoc. With the use of an LLM, it checks if the power analysis is reported with all required information.

The regular expressions can miss power analyses, or fail to classify them correctly. The type of power analysis is often difficult to classify, which can easily be solved by explicitly specifying the type of power analysis as ‘a-priori’, ‘sensitivity’, or ‘post-hoc’. Note that ‘post-hoc’ or ‘observed’ power is rarely useful. The LLM can fail to identify information in the paper, and will not have access to information in paragraphs in the paper other than those that contain the word ‘power’. This package was validated by the Metacheck team on articles in Psychological Science.

How Exact P-Values works

List any p-values reported with insufficient precision (e.g., p < .05 or p = n.s.), reported as exactly zero (e.g., p = .000), or impossible (below 0 or above 1, e.g., p = -.22).

This module uses regular expressions to identify p-values. It will flag any values reported as p > ? or p < numbers greater than .001. It will also flag p-values reported as exactly zero (e.g., p = .000, p = 0.00), which are mathematically impossible — p-values are never exactly zero and should instead be reported as p < .001.

A p-value that is not the result of a test is not flagged: a table note (“* p < .05, ** p < .01”), a figure legend (“Asterisks indicate significant differences (p < .05)”, “Values in bold are significant at p < .05”) or a stated threshold (“p < .05 was considered significant”, “thresholded at p < .001”). GROBID often puts such notes into the running text, so each p-value is judged by the words in its own clause (the text up to a “;” or a full stop), and never left out when a test statistic belongs to it (“F(1, 7) = 8.03, # p < .05”). The column not_a_test of the table says why a p-value was left out (“marker”, “threshold”, “legend” or “named”).

A p-value with the name of a correction or a test after the p (“pFWE < .05”, “padj < 0.05”, “p Wilcoxon = .02”) is flagged only when a test statistic comes before it in its clause (“t(37) = 7.17, p FWE < .05”). Without one it is mostly the rule that decided what was significant (“genes with padj < 0.05 were selected”); such a p-value is “named” in not_a_test. Notes in other forms, such as a marker after the p-value (“p < .05 (*)“), are still flagged.

A p-value below 0 or above 1 is impossible; it is listed apart and not also as imprecise. Often the statistic before it, or its minus sign, was copied into it (“t(134) = -2.32, p = -.13”, “Z = 3.091, P = 3.091”). A value above 1 is listed only after a test statistic in its clause: without one, a “P” above 1 was nearly always another quantity (a proportion, pH, a group’s mean, a model parameter). A number in scientific notation whose power of ten was lost when the PDF was read (“p = 2.4 x 10 -9” read as 2.4) is not listed. A “p” that is the subscript of another symbol (“r p = .64”, “²p = .02” for partial eta squared, “Δp = .33”), or a quantity with a unit, a logarithm or a ratio (“P = 2.9 µm”, “-log10 P = 7.5”, “Ca/P = 1.67”), is not read as a p-value at all (see extract_p_values()). Each p-value has its own row, also when the same one is written twice in a sentence.

This module sometimes flags false positives when sentences discuss how p-value thresholds were set. It can also miss an imprecise p-value that is reported against a threshold (“decreased at the p < .05 significance threshold”).

This module only checks p-values reported in the running text of the manuscript. It cannot (yet) process p-values reported only in tables (as opposed to a table’s footnote text, which the module does see and tries to exclude — see above).

This module was developed by Lisa DeBruine and Daniel Lakens

How Non-Significant P Value Check works

The nonsignificant p-value check searches for regular expressions that match a predefined pattern. The module identifies all p-values in a manuscript and selects those that are not reported to be smaller than or equal to 0.05. It returns all sentences containing non-significant p-values.

In the future, the Metacheck team aims to incorporate a machine learning classifier to only return sentences likely to contain misinterpretations. If you want to help to improve the module, reach out to the Metacheck development team.

How Reproducibility Check works

This module assesses whether a paper’s R and Python code can be run on its data. It works in two phases. The static phase (always run) collects the package dependencies the code declares, rewrites the data-file paths that do not work in the repository as the authors organised it, works out the order the scripts must run in, and diagnoses why any referenced input file is unavailable — reporting what a reproduction attempt would involve and where it is likely to break. The execution phase (opt-in, execute = TRUE) then actually runs the code: it copies the repository into a throwaway directory, optionally installs the declared dependencies into a throwaway library, runs each script in order in an isolated subprocess with a per-script timeout, and captures the outcome and full output of each run.

By default (execute = FALSE) the module does not run any code — it performs only static analysis: reading dependencies with the same extractors as code_check, finding the files the code references in the repository, and building a run-order dependency graph. It reports what would be installed and run rather than doing it.

When execute = TRUE, the module additionally runs the downloaded code on your machine — a deliberate, opt-in action gated behind that argument (callr is required for R code). Each script runs in an isolated subprocess so a crash cannot take down the R session; note this isolates crashes, not the filesystem or network. Installs (when install_missing = TRUE) and the throwaway run library never touch your main R library. Each script’s outcome is one of ran_ok, errored, timed_out, dependency_unavailable, not_parsed, run_by_source (an R script another script runs with source(), which is run only inside that script, since on its own it lacks the packages and objects the sourcing script sets up first), run_by_import (a Python file other files import, a module rather than a script, unless it has an if __name__ == "__main__": block), jags_model (a JAGS or BUGS model saved with an R extension, which another script reads) or not_r_content (a file that is not R at all, such as a JSON or HTML dump); these last two are not run and are not failures. python2 marks Python 2 code that was not run. With sandbox = "docker" such code runs with Python 2.7 (option metacheck.docker_image_py2; FALSE turns this off), which modifications records; it is never converted, since that can change results. defines_functions is a file that only defines functions, which is used, not run (table$used_by names the scripts that use it), and not_analysis is a file of software rather than of the analysis: a package’s code, tests, documentation or setup.py, a copy of a tool, a web application, a script a program wrote (table$not_analysis_why says which); neither is run or counted as a script. docker_failed means the container never started, which says nothing about the script, so it keeps the light from being green but does not make it red. needs_a_person is a script that stopped because it asks a person to choose a file or answer a question, or that starts an app, and needs_internet one that stopped because the network is off in a Docker run, or, with internet = TRUE, could not reach what it asked for; download_too_large is a script stopped for downloading more than the limits allow (see internet), and out_of_memory one that, or a program it started (such as a compiler), ran out of the memory each script may use. All four are treated the same way. not_downloaded is a script that stopped on a file the repository lists but that was not downloaded, such as one over max_file_size: it could not be tried, so it is not counted as a script that did not reproduce (summary_table$repro_not_downloaded_n counts them apart). not_read is a file metacheck could not read, so it was not run; the light is then not green, as the file may read and run on another computer, and table$error_message says why, naming a package that is installed but cannot be loaded on the computer that ran the check. empty is a file with nothing in it, which is not run or counted as a script. For a script that did not run through, table$error_message is its error, short (at most 300 characters): the error line of its output, which names a package that is not there, with the address it asked for when it needed the internet, or the time limit it reached; table$reason sorts it into a kind. A timeout means “still running at the cutoff”, not a failure, so raise timeout for legitimately long-running (e.g. Bayesian) scripts. dependency_unavailable means the script’s own package could not be installed from live CRAN, the CRAN Archive, or a named GitHub/URL source — an infrastructure limitation, not a defect in the paper’s code, so unlike errored/timed_out it does not force the traffic light red. The full stdout/stderr of every run is kept in the result’s run_results (the report shows it in per-script dropdowns, capped for readability). The traffic light reflects the STATIC readiness signals by default, but an execution error (errored/timed_out) does recolour it to red — a script that crashes on its own analysis is a genuine reproduction failure. A script that fails with could not find function is run once more with the library() calls the project’s other scripts make added at its top (or the one package that exports the function, or magrittr for %>%), and a script that then runs is reported as reproducible only after that repair.

Dependencies are reported name-only, with the source (CRAN, GitHub, or a base package already shipped with R) — static analysis of the code cannot know which version was used, and running against current package versions is itself informative: a break argues the authors should have pinned versions. When the repository does record versions, a run with recorded_versions = TRUE installs the packages the scripts load at those versions, but it does not change the R version, which remains a limitation of the check.

Run order is derived from read-after-write data dependencies (a script writing a file another reads must run first), source() edges, and numeric filename prefixes as a weak tie-breaker. Ambiguous orderings, dependency cycles, and inputs a script reads but that no earlier script produces (and that are not in the repository) are surfaced as warnings, since these are the situations most likely to make an otherwise-correct reproduction fail.

Python code (.py files, and notebooks and Quarto documents whose code is Python, from which the code is extracted first) goes through the same two phases, reported in its own “Python code” section. Each file is checked for syntax errors with Python’s own parser when a Python interpreter (python, or else python3) is available; dependencies are read from the import statements, with versions from a requirements.txt or pyproject.toml when there is one, and installed with pip; each script runs as its own python process (processx is required), so unlike R scripts, a name one script defines is not available to another. When no Python interpreter is available, the Python files are reported as not run and the R results are still returned. Statistics the Python scripts print are compared with the paper together with the R output and any self-reproducible output (JASP/jamovi, SPSS-Viewer, notebook outputs).

Abstract

The "AI placebo effect" occurs when user outcomes change because of the belief that an AI is assisting them. In a within-subjects anagram study (Kosch et al., 2022, Experiment II), participants who expected webcam-based AI difficulty adaptation anticipated higher performance than in the control condition, but actual performance showed no group-level difference (N = 75; Bayes factor favouring the null = 7.7). The difference in stated expectancy correlated only modestly with the difference in performance (r = .28), and no formal model linking belief to performance has been tested on these data. Adapting established Bayesian models of placebo responding, which integrate prior expectation and evidence via precision weighting, we asked whether an AI placebo is best described as shifting the mean of expected performance, altering its precision, or both, and whether such changes appear at the group or the individual level. In an exploratory secondary analysis of the public data, hierarchical Bayesian models treated each participant's score in each condition as a Gaussian posterior combining a prior (centred on stated expectancy plus a participant-level shift) with a likelihood (centred on mean performance across conditions). We compared Shift, Precision, and Combined models using leave-one-out cross-validation and correlated participant-level parameter changes with observed performance changes. The Combined model had the best expected predictive accuracy (elpd_loo = -473.0 vs. -480.2 for Precision and -500.6 for Shift). Group-level differences were inconclusive (∆ shift = 4.2, 95% HDI [-14.5, 19.3]; ∆ log variance scale = 0.47, [-1.7, 3.5]): compatible with no average change, but too imprecise to exclude moderate ones. Across participants, performance change correlated strongly with the estimated change in shift (r = .96) and positively with the estimated change in variance scale (r = .57). Because these parameters are estimated from the same single score per condition that they are correlated with, these associations are partly determined by model structure and are not independent confirmation of a mechanism. Other limitations, which constrain the inferences that can be drawn, are discussed in detail in the paper. This study makes three contributions. First, it formalises the expectancy account of the AI placebo using established frameworks by separating the level from the certainty of expectation so that each can be tested in HCI. Second, it applies this framework to an established dissociation (an expectancy effect without a group-level performance effect) and shows what such a model can and cannot reveal. Third, it provides open code and specifies the design which can open the avenue for further research in this direction.

1 Introduction

Artificial intelligence systems are increasingly embedded in everyday human-computer interaction (HCI), from productivity tools and recommendation engines to healthcare decision support and adaptive interfaces. Evaluating whether such systems genuinely improve user performance requires rigorous experimental methodology. A critical, and often overlooked, confound in this evaluation is the possibility that observed benefits arise not from the system itself, but from users' beliefs about what it can do. This phenomenon, the AI placebo effect, mirrors the well-documented medical placebo effect: just as inert treatments can produce real physiological and psychological benefits when patients believe in their efficacy, the mere belief that an AI is providing support can elevate user expectations and may alter task outcomes. Kosch et al. (2022) provided the foundational empirical demonstration of an AI placebo effect on performance expectancy in HCI. In their Experiment II, participants told that a sham AI was adapting puzzle difficulty to their physiological signals held significantly higher performance expectations than when they were told that no AI was present, and elevated expectation ratings persisted after interaction, even though no actual AI assistance was provided. Objective performance, however, did not differ between conditions.

While Kosch et al. (2022) showed that an AI description raises expectations, the process linking belief to objective performance was described only verbally, as an expectancy account, and has not been formalised. In particular, it is unclear whether a placebo primarily shifts the mean of users' performance expectations, alters their precision (certainty), or involves both. In the original data, a null group-level performance effect co-occurred with a modest positive correlation between the placebo-related difference in expectancy and the difference in performance (r = .28). This pattern is compatible with heterogeneity across individuals that group-mean analyses cannot capture, although with a single measurement per condition, heterogeneity cannot be distinguished from measurement noise (Section 7.6).

A productive route to formalising this link lies in the Bayesian computational frameworks developed in the pain placebo literature. Anchisi and Zanon (2015), building on predictivecoding accounts of placebo analgesia (Büchel et al., 2014), formalised the idea that perceived or observed outcomes arise from the precision-weighted integration of prior expectations and incoming sensory (or performance) evidence. Under this account, a placebo can alter the posterior estimate of outcome either by shifting the mean of the prior distribution, by changing its precision, or by doing both. These models have been used to describe individual differences in placebo magnitude in clinical and experimental pain settings, because they treat expectation level and expectation certainty as separable, quantifiable parameters. The present study therefore asks whether the same computational architecture can be adapted to describe expectancy-related variation in task performance within an HCI context, and what it can and cannot reveal when applied to existing data.

We re-analyse the Kosch et al. (2022, Experiment II) dataset in an exploratory secondary analysis. Within a hierarchical Bayesian framework, we treat objective task performance as if it were the product of Bayesian inference: a prior expectation distribution is combined with a like-lihood representing baseline ability. This is a modelling assumption rather than an established fact. In placebo analgesia the posterior corresponds to a percept, whereas task performance also depends on effort, strategy and persistence (Section 2.3). Under this formalisation, the AI placebo manipulation can affect performance by shifting the mean of the prior, by altering its precision (the certainty of the expectation), or through a combination of both. We compare three competing model specifications (Shift-only, Precision-only, and Combined) using leave-one-out cross-validation, and then examine whether the latent parameters of the best-predicting model are associated with individual differences in observed performance change.

2 Background and Related Work

2.1 The Placebo Effect in Medical and Psychological Contexts

The placebo effect refers to real, measurable changes in health, perception, or behaviour that arise from a patient's belief in an inert treatment rather than any pharmacologically active substance (Büchel et al., 2014). Mechanistically, placebo responses involve expectancy-driven modulation of neurobiological systems: positive expectations can activate endogenous opioid pathways, reduce pain-related neural activation, and improve outcomes across a wide range of conditions. Critically, the magnitude of the placebo response is shaped both by the strength of the prior expectation and by how certain the individual is about the expected outcome, a distinction that maps directly onto the Bayesian framework employed in the present study. Anchisi and Zanon (2015) formalised this within a Bayesian framework, proposing that perceived outcomes arise from the precision-weighted integration of prior expectations and incoming sensory evidence. Under this account, a strong, high-certainty prior expectation of improvement, the kind induced by a convincing placebo, shifts the posterior estimate of outcome in the direction of the prior, yielding real changes in subjectively and objectively measured performance.

This Bayesian framing provides a principled theoretical basis for applying a similar model to AI-mediated HCI contexts.

2.2 Expectancy Effects and the AI Placebo in HCI

User expectations are central to established technology acceptance frameworks. The Technology Acceptance Model (TAM; Davis, 1989) and the Unified Theory of Acceptance and Use of Technology (UTAUT; Venkatesh et al., 2003) both identify perceived usefulness (PU) and perceived ease of use (PEOU) as primary drivers of technology adoption and satisfaction. If AI placebo effects artificially inflate these perceptions by making a system seem more capable than it is, evaluations grounded in these frameworks will yield misleading conclusions about a technology's genuine utility.

The susceptibility of technology users to expectancy effects has been demonstrated across multiple paradigms. How an AI is described, whether as helpful, neutral, or even as a threat, substantially alters users' trust, perceived effectiveness, and subjective satisfaction, even when the underlying system behaviour is held constant. Users often develop strong mental models of AI capabilities that are shaped more by framing and prior beliefs than by actual system performance. Kosch et al. (2022) provided the most direct demonstration of an AI placebo effect on expectations in HCI. In their Experiment II, 100 participants were recruited and 75 were analysed after exclusions for failed comprehension checks and incomplete task completion. Each participant completed 40 word puzzles (anagrams) under each of two counterbalanced within-subjects conditions, after a short calibration phase of five puzzles. In the Control condition, participants were explicitly told they would receive no AI assistance and that puzzle difficulty was random.

In the AI Placebo condition, participants were led to believe that an AI was analysing their webcam feed, monitoring physiological signals such as heart rate and facial expressions, to adapt puzzle difficulty in real time and optimise their performance. No such analysis or adaptation occurred; the system behaved identically in both conditions. Before each block, participants stated how many of the 40 puzzles they expected to solve. Participants also rated their expected performance on a seven-point scale before and after interaction. Objective performance was recorded as the number of correctly solved anagrams. A comprehension check verified that participants understood the system descriptions; belief in the AI was not otherwise measured.

Three findings of Kosch et al. (2022, Experiment II) are relevant here. First, the AI description raised stated performance expectancy (mean 24.4 vs. 21.1 puzzles, d = 0.32), and higher expectation ratings persisted after interaction. Second, despite this subjective effect, there was no difference in task performance (61.2% vs. 60.8% correct, d = -0.02; a Bayes factor of 7.7 in favour of the null). Third, the difference in stated expectancy between conditions was modestly correlated with the difference in performance, r(73) = .28, p = .014. The original authors interpreted these results as a placebo effect on subjective expectations, not on objective performance, and favoured an expectancy-based over a conditioning-based account. A stronger expectancyperformance correlation under the AI description (Spearman r = .40, compared with .12 in the control condition) was reported in their between-subjects Experiment I (N = 255), not in Experiment II.

Three design features of the original study matter for the present analysis. First, the control condition told participants explicitly that no AI would be used, so it is a "known no-assistance" condition rather than a neutral baseline, and demand effects cannot be excluded. Second, expectancy was elicited after a calibration phase and, for the second block, after the first block, so stated expectancy partly reflects experience with the task and not only the framing. Third, belief in the AI was not measured, so the manipulation check establishes comprehension of the description, not credibility. This pattern, a clear subjective effect without a reliable group-level objective effect and a modest individual-level association between changes in expectancy and changes in performance, is compatible with the idea that the AI placebo operates heterogeneously across individuals.

Whether the pattern reflects genuine heterogeneity or measurement noise cannot be decided from group means alone. A model of how expectation relates to performance allows the question to be posed formally, although, as discussed in Section 7.6, a single crossover limits what such a model can resolve.

2.3 Bayesian Models of Performance and Expectancy

Bayesian frameworks have been applied productively in cognitive science to model how prior beliefs combine with incoming evidence to produce perception, decision-making, and action. In the context of performance and pain, Anchisi and Zanon (2015) demonstrated that a Bayesian integration model, in which prior expectations combine with a performance likelihood in a precision-weighted fashion, could account for the relationship between expectancy and observed outcomes in placebo-controlled studies.

Applied to HCI performance, this framework formalises the intuition that a participant's final performance on a task reflects not just their underlying ability (captured by the likelihood), but also the influence of their expectations (the prior). The strength of this prior's influence depends on its precision: a high-certainty expectation (narrow prior distribution) will pull the posterior strongly toward the expected value, while a low-certainty expectation (wide prior) will allow the likelihood to dominate. This distinction between mean-level effects (where the prior is centred) and precision-level effects (how tightly the prior constrains the posterior) is the central theoretical question of the present study.

A modelling assumption. Applying this framework to task performance requires an assumption that is stronger than in the pain literature. In placebo analgesia, the posterior is a perceived quantity (pain intensity) that plausibly results from integrating expectation with sensory evidence. The number of anagrams solved is not a percept; it depends on effort, strategy, persistence and anxiety. We therefore assume, as a modelling simplification, that the observed score behaves like a precision-weighted combination of expectation and ability. We treat the resulting model as a formal description that can be fitted and compared, not as a validated account of the underlying mechanism. A more plausible causal route, in which expectancy changes effort allocation and effort changes output, is a rival account that the present data cannot distinguish (Section 7.7).

3 Research Gap and Research Questions Kosch et al. (2022) established that an AI description raises performance expectancy and identified a key puzzle: despite a clear effect on subjective expectancy, the group-level effect on objective performance was null, while the placebo-related difference in expectancy was modestly correlated with the difference in performance. This dissociation is compatible with interindividual variability in how the placebo belief translates into behaviour, although it could also reflect measurement noise. The authors offered a verbal expectancy account but did not model the cognitive process that might link expectation to performance, nor did they investigate whether the placebo affected expectation certainty as well as expectation level.

The present study addresses this gap by applying a hierarchical Bayesian model to the Kosch et al. (2022, Experiment II) dataset. We ask three specific research questions: RQ1: Which specification, within a Bayesian framework (altering the mean (shift) of the prior performance expectation, altering its precision (variance), or a combination of both), best predicts the relationship between stated expectations and observed task performance across the control and AI placebo conditions? RQ2: Does the AI placebo manipulation (the 'camera' vs. 'nothing' condition) produce credible differences in the group-level average of the latent parameters (prior mean shift, p shift , and prior variance scale, log_var_scale), according to the best-predicting model identified in RQ1?

RQ3: Are individual differences in the estimated change in these parameters between the placebo and control conditions associated with individual differences in the observed change in task performance?

4 Hypotheses

Based on the Bayesian theoretical framework and the findings of Kosch et al. (2022), we derived the following theory-based hypotheses. They were formulated with knowledge of the original study's results, and the study is therefore best regarded as exploratory.

4.1 H1 -Model Selection

If the AI placebo acts through both the expected performance level and the certainty of that expectation, the Combined Shift-Precision model will predict the performance data better than the Shift-only or Precision-only models, as indicated by leave-one-out cross-validation scores.

4.2 H2 -Group-Level Parameter Differences (conditional on H1 being supported)

Assuming the Combined model is best: • H2a (Shift -Directional): The estimated prior mean shift parameter (p shift , the difference between the effective prior mean and the stated expectancy) will be greater (more positive) in the Placebo condition than in the Control condition.

• H2b (Precision -Non-directional): The estimated prior variance scale (log_var_scale, directly related to prior variance and therefore inversely related to prior precision) will differ credibly between the Placebo and Control conditions.

4.3 H3 -Individual-Level Correlations (conditional on H1 being supported)

• H3a (Shift -Directional): The individual difference in the estimated prior shift parameter (Placebo -Control) will be positively correlated with the individual difference in task performance (Placebo -Control).

• H3b (Precision -Directional): The individual difference in the estimated prior variance scale (Placebo -Control) will be negatively correlated with the individual difference in task performance (Placebo -Control); that is, a larger increase in prior precision (a smaller variance scale) was expected to accompany a larger performance gain.

Note on H3b. This directional prediction was derived from the intuition that tighter priors strengthen the influence of expectation. In the Gaussian model, however, the effect of precision on the posterior mean depends on whether the prior mean lies above or below baseline ability (Section 7.4). The direction of H3b was therefore under-specified, and we retain it as originally stated for transparency.

5.1 Data Source and Participants

This study re-analyses data from Experiment II of Kosch et al. The experiment employed a within-subjects design with N = 100 participants recruited, of whom N = 75 were analysed in the original study after exclusion of participants who failed comprehension checks or completed too few puzzles. Participants performed a word puzzle (anagram) task under two counterbalanced conditions: a Control condition ('nothing') and an AI Placebo condition ('camera'), described in detail below. In the present preprocessing (Section 5.3), the analytic sample was N = 75. The original data collection, ethical approval, and participant recruitment procedures are described in Kosch et al.

(2022) and are not reproduced here.

5.2 Experimental Conditions and Key Variables

In the Control condition, participants were explicitly informed that no AI assistance would be provided and that puzzle difficulty was randomly assigned. In the AI Placebo condition, participants were told that an AI system was analysing their webcam feed, monitoring physiological signals (heart rate, facial expressions) in real time to adapt puzzle difficulty and optimise their performance. In reality, no such analysis or adaptation occurred; the system behaved identically to the Control condition.

Four variables were extracted from the dataset for the present analysis. The participant identifier (id) distinguished individual participants, and the group variable coded the condition ('nothing' or 'camera'). The expectancy variable (expectancy) captured the participant's numeric self-report of the number of puzzles they expected to solve (ranging from 0 to 40), recorded immediately before each task block, after the calibration puzzles and, for the second block, after the first block had been completed. The outcome variable (numcorrectanswers) was the objective count of correctly solved anagrams in each block (also ranging from 0 to 40).

5.3 Preprocessing

The dataset was restricted to observations from the Control ('nothing') and AI Placebo ('camera') conditions. Data were restructured from long to wide format so that each participant contributed a single row containing their expectancy and performance scores for both conditions (yielding columns expect_Control, expect_Placebo, perf_Control, and perf_Placebo).

Participants with missing values on any of these four variables were excluded listwise. This yielded a final analytic sample of N = 75 participants. Two derived variables were then computed: a performance difference score (perf_diff = perf_Placebo -perf_Control) reflecting each participant's placebo-related performance change, and a baseline performance estimate (baseline_perf_data) computed as the mean of perf_Control and perf_Placebo across conditions. Note that this baseline is computed from the same observed scores that the models are fitted to (Section 5.4).

Interpretation of the parameters. Because the prior mean is built from the participant's stated expectancy, s ic does not measure how much the placebo raised expectation (that increase is already contained in the stated expectancy, as reported by Kosch et al., 2022). The variance scale λ ic is the log of a multiplicative scale on the base prior variance; larger values correspond to wider priors and hence lower prior precision.

Three features of this specification should be kept in mind. First, the observed scores appear on both sides of the model: the likelihood mean µ lik,i is computed from the same scores y ic that the posterior is fitted to, and it includes the placebo-block score. Second, the posterior standard deviation σ post,ic is used as the observation noise, so the variance scale λ ic governs both the pull of the prior and the model's tolerance for misfit. Third, with one observation per participant and condition, participant-level parameters are constrained only by the hierarchical priors. These points are developed in Section 7.6.

5.5 Model Specifications

Three hierarchical Bayesian models were specified, differing in which aspects of the prior expectation distribution were allowed to vary between the Control and Placebo conditions.

In all models, observed performance was treated as a draw from a Gaussian posterior formed by the precision-weighted combination of a prior expectation distribution and a fixed likelihood (baseline ability). The models differed solely in how the prior was parameterised across conditions: • Shift model.

Only the mean of the prior (µ prior ) was allowed to differ between the Control and Placebo conditions via a participant-level shift parameter p shift (λ ic = 0). Prior variance (σ 2 prior ) was held constant across conditions. This model tests the hypothesis that the AI placebo effect operates purely by raising (or lowering) the effective expected performance level.

• Precision model. Only the precision (inverse variance) of the prior was allowed to differ between conditions, implemented via a participant-level log-variance scale parameter log _var_scale (s ic = 0). The prior mean was held at the stated expectancy. This model tests the hypothesis that the placebo effect operates purely by changing how certain participants are about their performance expectations.

• Combined model. Both the prior mean (via p shift ) and the prior precision (via log _var_scale) were allowed to vary freely between the Control and Placebo conditions at the participant level. This model tests the hypothesis that the AI placebo effect involves simultaneous modulation of both expectation level and expectation certainty.

Participant-level parameters were drawn from condition-specific group distributions, s ic = m s c + τ s c z s ic and λ ic = m λ c + τ λ c z λ ic with z ∼ N (0, 1) (non-centred parameterisation). Control and placebo parameters were modelled independently across conditions, so within-person correlation between a participant's control and placebo parameters was not modelled. The condition differences of interest are ∆s i = s i,plac -s i,ctrl and ∆λ i = λ i,plac -λ i,ctrl at the participant level, and ∆m s = m s plac -m s ctrl and ∆m λ = m λ plac -m λ ctrl at the group level (∆_group_mu_p_shift and ∆_group_mu_log_var_scale in the code). 5.6 Parameter Estimation

All three models were estimated using Markov Chain Monte Carlo (MCMC) sampling implemented via PyMC's No-U-Turn Sampler (NUTS). For each model, four independent chains were run with 2,500 posterior samples each, following 2,500 tuning (warm-up) steps. The tar-get_accept parameter was set to 0.98 to encourage careful exploration of the posterior. A fixed random seed (8927) was used for reproducibility. Log-likelihood values for the observed performance variables were computed and stored for model comparison.

5.7 Convergence Diagnostics

Convergence was assessed using standard diagnostics from the ArviZ library. A model was considered to have converged if the Gelman-Rubin R statistic did not exceed 1.05, bulk and tail effective sample sizes (ESS) were at least 400 (100 times the number of chains), and divergent transitions made up fewer than 1% of draws. Convergence was assessed prior to interpreting any posterior distributions or conducting any comparisons.

5.8 Model Comparison

To address RQ1 and test H1, the three models were compared using Pareto-smoothed importancesampling leave-one-out cross-validation (LOO; Vehtari et al., 2017), calculated via ArviZ's az.compare function. LOO estimates the expected log-predictive density (elpd_loo), which approximates out-of-sample predictive accuracy while penalising model complexity. Pointwise loglikelihood values across both observed performance variables (perf_ctrl_obs and perf_plac_obs) were summed per participant and passed to the comparison function, so that each left-out unit is one participant. Models were ranked by elpd_loo; the model with the highest (least negative) value was identified as the best-predicting model. Model weights (stacking) were also examined.

Two caveats apply: the likelihood mean is computed from the observed scores (Section 5.4), so the comparison is not strictly out-of-sample, and no reference models (for example, a no-effect model or a regression of performance on expectancy) were included.

5.9 Hypothesis Testing

All subsequent hypothesis testing was conducted using posterior samples from the best-predicting model identified through model comparison. For H2, group-level posterior distributions of the condition difference parameters (∆_group_mu_p_shift and ∆_group_mu_log_var_scale) were examined using posterior means, 95% Highest Density Intervals (HDIs), and the posterior probability that the difference exceeded zero. For H3, participant-level posterior means of the condition difference parameters were extracted and correlated with the observed perf_diff score using Pearson's r. This two-stage procedure does not propagate posterior uncertainty in the participant-level estimates into the correlation.

7 Discussion

This study adapted a hierarchical Bayesian model of expectancy, originally developed in the pain placebo literature, to AI-placebo data. Of the three models compared, the Combined model, in which both the mean and the precision of the prior may differ between conditions, had the best expected predictive accuracy. Group-level differences in both parameters were inconclusive, and participant-level changes in both parameters were associated with performance change. These associations are partly constrained by the model's structure, and the association for prior variance ran opposite to our prediction. We therefore read the results as showing that the framework can be applied to these data and as clarifying what it can and cannot resolve, not as establishing a mechanism.

7.1 Model Comparison (H1)

The Combined model's advantage over both single-parameter models is compatible with a role for both expectation level and expectation certainty, and with the proposal by Anchisi and Zanon (2015) that both the location and the precision of prior beliefs shape the integration of expectation with incoming evidence. Two features of the models limit this interpretation. First, the precision parameter also sets the observation noise (Section 5.4). The Shift-only model has a fixed, comparatively small noise level, whereas the Precision and Combined models can widen it for participants whose scores depart from their expectancy-based prediction. Part of their advantage may therefore reflect flexibility in absorbing residual variance, whether or not expectation certainty differs. Second, the likelihood mean includes the observed scores and no reference models were fitted, so the elpd values cannot be interpreted in absolute terms and the comparison is not strictly out-of-sample. The ranking among the three candidates is thus a statement about relative predictive accuracy within this model family, not a demonstration that both mechanisms operate.

If direct measures of expectation certainty were to confirm a role for precision, the implication for technology-acceptance frameworks (TAM, Davis, 1989; UTAUT, Venkatesh et al., 2003) would be that AI placebo effects may alter not only how useful a system is expected to be but also how confidently that belief is held. The present data cannot establish this.

7.2 Group-Level Null Effects and the Question of Heterogeneity (H2)

The group-level differences in the shift and variance-scale parameters were inconclusive. The interval for the shift difference was wider than the interval implied by the hyperpriors alone, indicating that the data are uninformative about the group-level shift. These results are in line with the null group-level performance effect in the original study (Bayes factor 7.7 in favour of the null) but do not explain it.

One possibility is heterogeneity: some individuals may show positive shifts and others negative ones, which would cancel at the group level. However, with a single score per condition, between-person variability in performance change is the sum of any true individual differences in placebo response and measurement noise from order effects, practice, item difficulty and chance, and the design cannot separate these. Heterogeneity is therefore a hypothesis consistent with the data, not a finding. Testing it requires repeated blocks per condition so that the reliability of the placebo response can be estimated.

For HCI evaluation practice, the analysis is consistent with the recommendation of Kosch et al. (2022) to measure expectancy before and after interaction and to examine within-person relationships between expectancy and outcomes, in addition to comparing group means. The present analysis does not show that group-mean comparisons are inadequate; it shows that group means alone leave open how expectancy and performance relate within persons.

7.3 The Shift-Performance Association (H3a)

The association between the estimated change in shift and the change in performance was very strong (r = 0.962). This should not be read as evidence that the extent to which a person internalises the belief that the AI helps is the primary determinant of whether a placebo belief translates into performance. The shift parameter is estimated from the same scores with which it is then correlated. With one observation per participant and condition, the shift that best reproduces a participant's score is approximately that score minus the stated expectancy (rescaled by the weight on the prior), so the change in shift is largely a re-expression of the change in performance adjusted for the change in stated expectancy. Hierarchical shrinkage compresses the scale of the estimates but preserves their ordering, which produces a near-linear relationship. A strong correlation is therefore expected largely by construction. How much of it is structural can be quantified with a null simulation in which performance is independent of expectancy (Section ??). For comparison, the raw correlation between the difference in stated expectancy and the difference in performance in the original data was r = .28.

If the shift parameter proves identifiable in richer data, it could be related to individualdifference variables such as dispositional trust in technology, prior experience with AI, suggestibility and optimism, which may modulate how strongly the framing affects behaviour. Such variables were not measured here.

7.4 The Unexpected Precision Finding (H3b)

The relationship between the variance scale and performance change was positive: participants whose prior variance was estimated to increase more under the placebo tended to show larger performance gains. Three considerations should come before any substantive interpretation.

First, the sign of the hypothesised relationship is not determined by the model. In Gaussian integration, increasing prior precision increases the weight on the prior mean. This raises the posterior mean only if the prior mean lies above the likelihood mean (baseline ability) and lowers it if the prior mean lies below. The relationship between precision change and performance change therefore depends on the gap between prior and baseline, so the prediction of a negative association (H3b) was under-specified, and the observed positive association does not by itself contradict the Bayesian account.

Second, the variance scale also sets the observation noise, and it is estimated alongside the shift. In a model that estimates both, parameter trade-offs may couple the two parameters and produce correlations that are partly artefactual. We did not run parameter-recovery analyses, so the extent of such coupling is unknown. A replication using direct measures of expectation certainty, for example by asking participants for confidence intervals around their expectancy estimates, would address this.

Third, if the association is substantive, several speculative interpretations are possible. In a task where performance is highly variable and strategy-dependent, a looser expectation might allow more flexible problem solving. Alternatively, the AI framing may induce uncertainty about the appropriate performance level, and participants most responsive to this might also engage most actively with the task, so that better outcomes arise through increased effort and not through the precision mechanism as such. The present data cannot distinguish among these possibilities, and the finding is best treated as an open question that requires experiments with direct measures of both expectation level and certainty, ideally at several time points within the task.

7.5 Contributions and Implications

The study makes three contributions. First, it formalises the expectancy account of the AI placebo, which was stated only verbally in the original work, by adapting a Bayesian model that separates the level from the certainty of expectation, so that each can be examined in HCI. Second, it applies this framework to a known dissociation (an expectancy effect without a group-level performance effect) and shows what such a model can and cannot reveal in a singlecrossover dataset: the models can be fitted and compared, but participant-level parameters are only weakly constrained and individual-level associations are partly determined by model structure. Third, it provides open code and specifies design requirements (repeated measures per condition, elicited expectation distributions, parameter-recovery checks, and modelling of post-interaction ratings) for deciding whether a placebo acts through the prior mean, the prior precision, or neither. A methodological implication is that expectancy-performance correlations in single-crossover data, whether raw or model-derived, cannot on their own establish a placebo mechanism, because ability, order effects and measurement noise can produce them.

7.6 Limitations

Several limitations should be considered when interpreting these findings. They are listed roughly in order of how much they constrain the conclusions. 3. The models are close to saturated. Participants contribute two observations, while the models have two to four participant-level parameters regularised only by the hierarchical priors. Control and placebo parameters are modelled as independent, ignoring within-person correlation.

The group-level shift is weakly identified (Section 7.2).

4. Individual differences and measurement noise cannot be separated. With one score per condition, observed differences in performance change combine true individual differences with noise, so heterogeneity in placebo response is not established. 7. Stated expectancy is not a clean prior. It was elicited after calibration and, for the second block, after the first block, so it partly reflects experience. The control condition explicitly told participants that no AI was used, so demand effects and a negative expectation in the control cannot be excluded, and belief in the AI was not measured.

8. Mapping assumption. Treating task performance as a precision-weighted posterior is a stronger assumption than in the pain literature (Section 2.3), and rival accounts (e.g. effort allocation) are not tested. 9. Scope. The analysis is a secondary, exploratory, correlational analysis of one dataset (N = 75 after exclusions that removed about a quarter of recruited participants) with one task, and inherits the design constraints of the original experiment. In the original between-subjects Experiment I, the physiology description did not significantly raise expectancy, so the generality of the manipulation across designs is unclear. The model also does not incorporate subjective outcome measures (perceived workload, satisfaction) or individual-difference variables (personality traits, AI attitudes, cognitive ability); the hierarchical structure captures individual differences implicitly but does not explain them.

7.7 Future Directions

Deciding whether an AI placebo acts through the prior mean, the prior precision, or neither requires designs and analyses that the present data cannot provide. We suggest: (i) several blocks per condition, so that true heterogeneity can be separated from noise; (ii) a neutral baseline and a pre-experiment ability measure; (iii) expectation elicited as a distribution (for example, confidence intervals) together with post-task performance estimates, so that certainty is measured instead of inferred; (iv) parametric variation of the credibility of the AI claim; (v) behavioural measures of effort (time on task, attempts); and (vi) trial-level (binomial or item-response) models that account for measurement error, which would also allow the fixed variances to be estimated.

Two directions would address the mapping assumption. First, rival accounts should be compared with the Bayesian account, in particular an effort-allocation account in which expectancy changes effort and effort changes output. Second, the cognition-and-placebo literature cited by Kosch et al. (2022) reports that expectation manipulations often change subjective perception but not actual performance (Schwarz & Büchel, 2015; Looby & Earleywine, 2011). This suggests that a better target for precision-weighted integration may be the post-interaction subjective rating, which is closer to a percept, and that expectation and rating (or performance) could be modelled jointly. Finally, adding a nocebo condition would test whether the same architecture accounts for expectation of impairment.

8 Conclusion

This study adapted a hierarchical Bayesian model of placebo responding to the AI placebo effect on task performance, using data from Kosch et al. (2022, Experiment II). Among the three models compared, the one allowing the placebo to change both the mean and the precision of the prior had the best expected predictive accuracy. At the group level, the data were inconclusive about changes in either parameter. At the individual level, changes in the prior shift and the prior variance scale were associated with performance change, the first very strongly and the second opposite to our prediction. Because the latent parameters are estimated from the same single score per condition with which they are correlated, these associations are partly determined by model structure and do not by themselves establish a mechanism.

The main contribution is therefore a formalisation of the expectancy account of the AI placebo, together with a clear statement of what such a model can and cannot reveal in a singlecrossover dataset and of the design needed to go further: repeated measures per condition, directly elicited expectation distributions, parameter-recovery and null-simulation checks, and comparison with rival accounts. As AI systems become more pervasive, understanding the psychology of AI-induced expectations will be essential for ensuring that evaluations of these systems reflect genuine capability rather than the beliefs they happen to inspire.

Latent parameters are estimated from the outcome they are correlated with. The individual-level correlations (H3) are therefore partly determined by model structure and do not provide independent confirmation of a mechanism.

2.

The likelihood mean contains the outcome. The baseline ability is the mean of each participant's two observed scores, and therefore includes the placebo-block score. This makes the baseline partly dependent on the treatment, and it means that LOO is not strictly an outof-sample comparison.
