Meta-scientific research has shown nonsignificant p values are commonly misinterpreted. It is incorrect to infer that there is ‘no effect’, ‘no difference’, or that groups are ‘the same’ after p > 0.05.

It is possible that there is a true non-zero effect, but that the study did not detect it. Make sure your inference acknowledges that it is possible that there is a non-zero effect. It is correct to include the effect is ‘not significantly’ different, although this just restates that p > 0.05.

How Power Analysis Check works

This module uses regular expressions to identify sentences that contain a statistical power analysis. If specified by the user, it also uses a large language model (LLM) to extract information reported in power analyses, including the statistical test, sample size, alpha level, desired level of power, and magnitude and type of effect size.

The Power Analysis Check module uses regular expressions to identify sentences that contain a statistical power analysis. Without the use of an LLM, the module uses regular expressions to classify the power analysis as a-priori, sensitivity or post-hoc. How Exact P-Values works

List any p-values reported with insufficient precision (e.g., p < .05 or p = n.s.) or reported as exactly zero (e.g., p = .000).

This module uses regular expressions to identify p-values. It will flag any values reported as p > ? or p < numbers greater than .001. It will also flag p-values reported as exactly zero (e.g., p = .000, p = 0.00), which are mathematically impossible — p-values are never exactly zero and should instead be reported as p < .001.

A p-value that is not the result of a test is not flagged: a table note (“* p < .05, ** p < .01”), a figure legend (“Asterisks indicate significant differences (p < .05)”, “Values in bold are significant at p < .05”) or a stated threshold (“p < .05 was considered significant”, “thresholded at p < .001”). GROBID often puts such notes into the running text, so each p-value is judged by the words in its own clause (the text up to a “;” or a full stop), and never left out when a test statistic belongs to it (“F(1, 7) = 8.03, # p < .05”). The column not_a_test of the table says why a p-value was left out (“marker”, “threshold”, “legend” or “named”).

A p-value with the name of a correction or a test after the p (“pFWE < .05”, “padj < 0.05”, “p Wilcoxon = .02”) is flagged only when a test statistic comes before it in its clause (“t(37) = 7.17, p FWE < .05”). Without one it is mostly the rule that decided what was significant (“genes with padj < 0.05 were selected”); such a p-value is “named” in not_a_test. Notes in other forms, such as a marker after the p-value (“p < .05 (*)“), are still flagged.

This module sometimes flags false positives when sentences discuss how p-value thresholds were set. It can also miss an imprecise p-value that is reported against a threshold (“decreased at the p < .05 significance threshold”).

This module only checks p-values reported in the running text of the manuscript. It cannot (yet) process p-values reported only in tables (as opposed to a table’s footnote text, which the module does see and tries to exclude — see above).

How Codebook Check works

This module checks whether the data columns in a repository are documented in a codebook or README. It locates codebook/readme files, extracts the variable definitions they contain, matches those definitions against the data columns extracted by data_check, and reports documentation coverage: how many data columns are documented, and which documented variables are never used.

The Codebook Check module consumes the columns and file classification produced by data_check (and, transitively, repo_check). Files classified as codebook or readme are parsed with parse_codebook(), which reads structured tables (CSV/TSV/Excel with a variable-name column and a label column), embedded labels in haven files (SPSS/Stata/SAS), and plain text from rich-text formats (docx/pdf/rtf/odt). These are carried onto the matched data columns and exported into the Psych-DS variableMeasured (as a schema.org code list plus namespaced metacheck: fields).

The module defaults to rules-only when llm_use(FALSE). When llm_use(TRUE), three optional LLM tiers run: parsing unstructured codebook text that the rules could not handle, fuzzy-matching still-unlabelled columns to still-unmatched codebook variables, and merging conflicting label definitions into a single canonical label.

How Repository Check works

This module retrieves information from repositories.

The Repository Check module lists files on the OSF, GitHub, ResearchBox, DSpace (PsychArchives and other legacy- and DSpace 7-based installations), Zenodo, Dataverse, Figshare, Dryad, ReShare, 4TU.ResearchData, Mendeley Data, DataONE (Arctic Data Center, KNB, and other member nodes), and LDbase based on links in the manuscript.

Listing a repository’s files never requires an API key, but some hosts answer faster or more completely with one: OSF allows 100 requests/hour unauthenticated versus 10,000/day with a token (see [osf_pat()]), and Dryad enforces a strict per-IP daily quota on repeated listing (see cache below). Dryad is a special case beyond rate limits: listing a Dryad dataset’s files works without a key, but actually downloading file CONTENTS from Dryad fails with HTTP 401 unless a key is set, even for a fully public dataset (see [dryad_pat()] or [dryad_auth()]). Since this module only lists files and never downloads their contents itself, that limitation applies to data_check and code_check (which do download content), not here – see their own documentation.

When a linked OSF page is a registration, its registered_from project (the one it was registered from, which the manuscript itself may never link directly) is also checked: if that project is public its files are listed under its own URL, and if it is closed or otherwise inaccessible the report flags it explicitly, since some registrations only describe their content rather than mirroring it.

Whose deposit is each link? The ownership table gives, for every repository linked in the text and (with references = TRUE) every deposit cited in the reference list, one of six labels: own_this (made by the authors for this paper), own_earlier_data or own_earlier_code (the authors’ own, from earlier work), others_data or others_code (made by other people, reused here), or not_data (a publication such as a preprint, not a deposit), with ownership_group (“own”, “others”, “not_data”) and the reason. It is decided without a language model, from the sentence or reference that cites the link, the paper’s authors (names, ORCID iDs, affiliations), and what the deposit’s own record and files say (who made it, what it names, when, whether it is a software package; for an OSF project cited only in the reference list, its record alone). Telling this paper’s own deposit from the authors’ earlier one is less certain.

How Code Check works

This module retrieves information from repositories checked by repo_check about code files (R, Python, SAS, SPSS, Stata, Mplus, MATLAB).

The Code Check module checks R (also R Markdown and Quarto), Python (also Jupyter notebooks), SAS, SPSS, Stata, Mplus, and MATLAB files, using regular expressions to check the code; JASP files are listed but not read. The language of a Quarto document or a notebook is read from the file itself (its engine or kernel), not from its extension. The regular expression search will detect the number of comments, the lines at which libraries/imports are loaded, attempts to detect absolute paths to files, setwd() and install.packages() calls, and lists files that are loaded, and checks if these files are in the repository; R code is also parsed. The module will return suggestions to improve the code if there are no comments, if libraries/imports are loaded in lines further than 4 lines apart, if files that are loaded are not in the repository, if absolute file paths, setwd() or install.packages() are found, and if R code cannot be parsed.

The regular expressions can miss information in code files, or falsely detect parts of the code as a fixed file path. Libraries/imports might be loaded in one block, even if there are more than 3 intermittent lines. The module was tried out internally on papers published in Psychological Science, but has not been formally validated. There might be valid reasons why some loaded files can’t be shared, but the module can’t evaluate these reasons, and always gives a warning.

The module also checks whether the repository pins the R/package versions the analysis actually depended on: an renv.lock file (parsed for the R version and every locked package + its version/source), a sessionInfo()/sessioninfo::session_info() text dump (matched by filename — sessionInfo.txt/session_info.txt and similar, or embedded in a README), or a groundhog::groundhog.library()/checkpoint::checkpoint() date-pin call in the code (a bare library(groundhog)/library(checkpoint) does not count — the pinning call itself must be present). When none of these is found, the report flags it as a reproducibility gap: package versions may drift between when the analysis was run and any later reproduction attempt.

If you want to extend the package to perform additional checks on code files, or make the checks work on other types of code files, reach out to the Metacheck development team.

Without a key, every Dryad-hosted code file is listed but unchecked, and a warning naming Dryad and ?dryad_pat/?dryad_auth is included among the download failures recorded in the manifest.

How Data Check works

This module classifies the files in a repository into semantic types (data, codebook, code, software, output, supplemental, readme, asset, other) and, for tabular data files, extracts each column’s type and summary statistics.

The Data Check module consumes the file list produced by repo_check (or any files added via local_path). Each file is classified with rule-based heuristics layered over metacheck’s file_category() and file_types: file names matching README / codebook patterns win first, then an extension crosswalk, then format-locked extension overrides. For every file classified as tabular data that is available locally, the module reads the file head, describes each column with data_col_facets() and computes summary statistics for numeric columns. Every sheet of a spreadsheet that holds a table is read: a file with several such sheets has its columns under source_file = "file.xlsx [sheet]", and the sheet column names the sheet of any spreadsheet with several sheets; a sheet of notes or a codebook is treated as documentation when the file has another table. Following DDI, a column is described by orthogonal facets rather than a single type: representation (numeric/text/datetime/code — how it is stored), measurement_level (Stevens: nominal/ordinal/interval/ratio), concept (what it measures: reaction_time/age/gender/likert/id/…), role (identifier/measure/condition/timestamp), unit, and a quality state (ok/empty/constant). Concepts are detected by name+value rules (the demographic concepts via data_check_demographic()); when llm_use(TRUE) the model fills concepts and measurement levels the rules left blank. Qualtrics survey exports are recognised (data_check_is_qualtrics()): their extra header rows are stripped so columns type correctly, and the reserved response-metadata columns (StartDate, Duration, Finished, …) are tagged.

The module defaults to rules-only when llm_use(FALSE): columns the rules cannot resolve (ambiguous 3–20-unique integers, ambiguous character columns) fall back to continuous / text respectively. When llm_use(TRUE), ambiguous columns and unresolved file types (other) are sent to llm() for optional refinement, and every file is assigned a study group (ex1, pilot2, shared, …) so that multi-study repositories can be recognised (used by psychds_check). Without an LLM the study group is left NA (unknown).

Column extraction requires files to be readable from disk. Files fetched by repo_check from OSF/GitHub/etc. without a local copy (file_location is NA) are classified but not column-extracted; pass local_path to point at a downloaded copy of the repository.

For a paper whose repository is on Dryad, this means column extraction never happens unless a Dryad API key is set: Dryad requires one to download file bytes, even from a fully public dataset (dataset listing and metadata do not need one). Without a key, every Dryad file stays classified but un-downloaded, column_n is 0, and a warning naming Dryad and ?dryad_pat/?dryad_auth is included among the download failures. A one-time session message is also shown (see repo_check) the first time a Dryad dataset is encountered with no key set.

Every downloaded text file the authors wrote (code, settings, survey definitions such as Qualtrics .qsf files, documentation, outputs) is searched for keys: API keys, access tokens and private keys, which let anyone who downloads the file use a paid service at the authors’ cost. Of a tabular data file only the column names and first 3 rows of the table as read are searched: its values come from participants, but a key the authors set for a whole survey (as embedded data in a Qualtrics survey flow) is exported in every response. The search uses the rules of the secret scanner betterleaks (https://github.com/betterleaks/betterleaks, MIT licence) of high and medium confidence. A key found turns the traffic light red; the report and the keys table give its file, line and type, and only its beginning. Other files over 25 MB and binary files are not searched. A key is never tested with its provider. Every module’s result has any whole key replaced by “keyremoved” (see module_run()).

How Reproducibility Check works

This module assesses whether a paper’s R and Python code can be run on its data. It works in two phases. The static phase (always run) collects the package dependencies the code declares, rewrites the data-file paths that do not work in the repository as the authors organised it, works out the order the scripts must run in, and diagnoses why any referenced input file is unavailable — reporting what a reproduction attempt would involve and where it is likely to break. The execution phase (opt-in, execute = TRUE) then actually runs the code: it copies the repository into a throwaway directory, optionally installs the declared dependencies into a throwaway library, runs each script in order in an isolated subprocess with a per-script timeout, and captures the outcome and full output of each run.

By default (execute = FALSE) the module does not run any code — it performs only static analysis: reading dependencies with the same extractors as code_check, finding the files the code references in the repository, and building a run-order dependency graph. It reports what would be installed and run rather than doing it.

When execute = TRUE, the module additionally runs the downloaded code on your machine — a deliberate, opt-in action gated behind that argument (callr is required for R code). Each script runs in an isolated subprocess so a crash cannot take down the R session; note this isolates crashes, not the filesystem or network. Installs (when install_missing = TRUE) and the throwaway run library never touch your main R library. Each script’s outcome is one of ran_ok, errored, timed_out, dependency_unavailable, not_parsed, run_by_source (an R script another script runs with source(), which is run only inside that script, since on its own it lacks the packages and objects the sourcing script sets up first), run_by_import (a Python file other files import, a module rather than a script, unless it has an if __name__ == "__main__": block), jags_model (a JAGS or BUGS model saved with an R extension, which another script reads) or not_r_content (a file that is not R at all, such as a JSON or HTML dump); these last two are not run and are not failures. python2 marks Python 2 code that was not run. With sandbox = "docker" such code runs with Python 2.7 (option metacheck.docker_image_py2; FALSE turns this off), which modifications records; it is never converted, since that can change results. defines_functions is a file that only defines functions, which is used, not run (table$used_by names the scripts that use it), and not_analysis is a file of software rather than of the analysis: a package’s code, tests, documentation or setup.py, a copy of a tool, a web application, a script a program wrote (table$not_analysis_why says which); neither is run or counted as a script. docker_failed means the container never started, which says nothing about the script, so it keeps the light from being green but does not make it red. needs_a_person is a script that stopped because it asks a person to choose a file or answer a question, or that starts an app, and needs_internet one that stopped because the network is off in a Docker run, or, with internet = TRUE, could not reach what it asked for; download_too_large is a script stopped for downloading more than the limits allow (see internet), and out_of_memory one that, or a program it started (such as a compiler), ran out of the memory each script may use. All four are treated the same way. not_downloaded is a script that stopped on a file the repository lists but that was not downloaded, such as one over max_file_size: it could not be tried, so it is not counted as a script that did not reproduce (summary_table$repro_not_downloaded_n counts them apart). not_read is a file metacheck could not read, so it was not run; the light is then not green, as the file may read and run on another computer, and table$error_message says why, naming a package that is installed but cannot be loaded on the computer that ran the check. empty is a file with nothing in it, which is not run or counted as a script. For a script that did not run through, table$error_message is its error, short (at most 300 characters): the error line of its output, which names a package that is not there, with the address it asked for when it needed the internet, or the time limit it reached; table$reason sorts it into a kind. A timeout means “still running at the cutoff”, not a failure, so raise timeout for legitimately long-running (e.g. Bayesian) scripts. dependency_unavailable means the script’s own package could not be installed from live CRAN, the CRAN Archive, or a named GitHub/URL source — an infrastructure limitation, not a defect in the paper’s code, so unlike errored/timed_out it does not force the traffic light red. The full stdout/stderr of every run is kept in the result’s run_results (the report shows it in per-script dropdowns, capped for readability). The traffic light reflects the STATIC readiness signals by default, but an execution error (errored/timed_out) does recolour it to red — a script that crashes on its own analysis is a genuine reproduction failure. A script that fails with could not find function is run once more with the library() calls the project’s other scripts make added at its top (or the one package that exports the function, or magrittr for %>%), and a script that then runs is reported as reproducible only after that repair.

Dependencies are reported name-only, with the source (CRAN, GitHub, or a base package already shipped with R) — static analysis of the code cannot know which version was used, and running against current package versions is itself informative: a break argues the authors should have pinned versions. When the repository does record versions, a run with recorded_versions = TRUE installs the packages the scripts load at those versions, but it does not change the R version, which remains a limitation of the check.

Run order is derived from read-after-write data dependencies (a script writing a file another reads must run first), source() edges, and numeric filename prefixes as a weak tie-breaker. Ambiguous orderings, dependency cycles, and inputs a script reads but that no earlier script produces (and that are not in the repository) are surfaced as warnings, since these are the situations most likely to make an otherwise-correct reproduction fail.

Python code (.py files, and notebooks and Quarto documents whose code is Python, from which the code is extracted first) goes through the same two phases, reported in its own “Python code” section. Each file is checked for syntax errors with Python’s own parser when a Python interpreter (python, or else python3) is available; dependencies are read from the import statements, with versions from a requirements.txt or pyproject.toml when there is one, and installed with pip; each script runs as its own python process (processx is required), so unlike R scripts, a name one script defines is not available to another. When no Python interpreter is available, the Python files are reported as not run and the R results are still returned. Statistics the Python scripts print are compared with the paper together with the R output and any self-reproducible output (JASP/jamovi, SPSS-Viewer, notebook outputs).

Abstract

Children are often thought to engage in imagination freely, but research has found they show boundaries in their play. However, when and how children show limits to moral permissiveness specifically within their pretense is unknown. We conducted two studies to investigate how and when children display moral boundaries and Imaginative Resistance during imaginative activities. Study 1 tested 60 children (aged 4-6) with scenarios differing on moral valence (moral or immoral) and agent (self or other) and asked for evaluations of immoral actions in different contexts. Study 2, a large online replication of study 1 (N = 152; aged 4-7) suggested a developmental trajectory of more Imaginative Resistance with age. Across both studies, children resisted engagement in immoral play, however, they were more morally permissible in pretend over real contexts. Thus, Imaginative Resistance follows a developmental trajectory, showing possibilities for malleable moral engagement and intervention opportunities on moral judgements.

Young Children's Resistance to Immoral Actions 3 "Maybe I don't wanna be the bad guy"; Resistance to Immoral Actions in Young Children's Pretense

Despite the commonly-held belief that imagination is boundless, there are limits to what people can or will imagine, particularly in the moral domain. Encountering violence, sex, logical fallacies, and feelings of disgust can all trigger a refusal to engage, termed Imaginative Resistance. Imaginative Resistance occurs when a narrative crosses a held value, boundary, or belief, either moral or non-moral in nature, thus causing an individual to refuse or resist engaging in that situation (Gendler, 2000; Hume, 1757). Developmentally, how children engage, or refuse to engage (i.e., resist), with different moral views and frameworks has implications for their general moral development and judgments about ideas, beliefs, or people that may have differing morals. However, how Imaginative Resistance develops and changes, and if young children display Moral Imaginative Resistance at all remain open questions. Here, we explore young children's engagement or resistance when introduced to and asked to enact novel, morallydeviant scenarios in the naturalistic, embodied context of pretend play.

Children's Moral Development in the Real World

How morality develops for children in real world evaluative contexts is a well-studied topic. Preschool aged children explicitly evaluate moral actions as "good" or "bad" (Wainryb et al., 2004), prefer positive moral behavior, and distinguish between moral and conventional violations (Killen & Smetana, 2015). Further, young children begin to develop differentiations in moral judgements depending on who is being harmed, what the intent is behind the violation, and who is doing the violation beginning at age 4 (Killen & Smetana, 2015). While not at adult levels of moral reasoning, young children are able to make moral judgments and evaluations and begin to consider morality differently depending on context.

Young Children's Resistance to Immoral Actions 4 Pretense as a Moral Context

Fiction and pretense may serve as a way for children to understand and be exposed to a wide variety of ideas and concepts, including novel moral actions and conventions, similar to how fiction has been viewed as important to moral understanding in adults (i.e., as a "moral laboratory" (Hakemulder, 2000)). Fictional play may allow for children to develop Moral Imagination -the ability to imaginatively engage in the perspective taking, deliberation, judgment of, or action planning in response to a moral situation, whether deviant or morally positive (Black & Barnes, 2021; Coles, 1989). Pretense generally may be a way for children to engage in related skills such as emotional control and regulation, executive function, and social competence (Goldstein & Lerner, 2018; Lillard, 2017; Smits-van der Nat et al., 2024).

Pretend play is a prime context to study moral judgements in young children because it is a developmentally appropriate, naturally occurring activity (Weisberg, 2015) containing characters and stories where moral themes can occur or be explored. There are two possibilities for how and why children may display Moral Imaginative Resistance in thematically negative play. One possibility is that Imaginative Resistance may occur as a result of the play itself crossing a value or belief. For example, a young child may not want to play a game where their doll gets thrown into a volcano as a human sacrifice because they think hurting people is wrong.

However, a second possibility is the role the child takes on within the theme causes Moral Imaginative Resistance. Children may not want to play the villain in a superhero story, instead wanting to role play a prosocial "good guy" instead.

Imaginative Resistance would not occur if children left their morality behind in the real world but might if children's reality bias in play extends to morals. Generally, children prefer realism in their pretend play, and for their pretend play to be realistic (Harris, 2021) and three to four-year-olds not only bring real-world knowledge into pretense, but also protest when the pretense goes against their pre-held knowledge (Van de Vondervoort & Friedman, 2017), a form of non-moral Imaginative Resistance.

Moral Imaginative Boundaries

Thus, moral violations may present an imaginative boundary to children, driven by the realism of the scenario. In previous work, four-year-old children judge both immoral and socially impermissible events as impossible, and that their occurrence requires magical involvement (Shtulman & Phillips, 2018). Three to five-year-olds bring real world moral judgements into realistic narratives through judging antisocial actions as wrong in real narratives and realistic pretend narratives. But, they judge these actions as more permissible in a fantastical context (Fast & Van Reet, 2018), suggesting children may bring moral judgments into pretense.

Children may also display Imaginative Resistance differently when they engage in pretend play, as opposed to just being presented with scenarios. Children do show immoral actions and themes in their pretense, and have been observed pretending to kill toys or other children (i.e., Dunn & Hughes, 2001; Galman, 2021; Howe et al., 1998), and cook (i.e., Sturdivant & Alanis, 2021) or steal babies (i.e., Logue & Detour, 2011). However, even during these scenarios, children still showed Imaginative Resistance to specific components within the pretense, such as actually portraying or playing the role of the immoral or antagonistic agent (e.g., Logue & Detour, 2011). The question of which situations, and which types of actions cause Moral Imaginative Resistance for children in their pretend play is still open.

Current Study and Questions

The current two studies were developed to examine Moral Imaginative Resistance in 4 to 7-year-old children's thematically negative pretend play though their willingness to engage with moral and immoral actions conducted by either the themselves or a moral 'other'. We hypothesized children would engage in more Moral Imaginative Resistance to playing immoral over moral scenarios within pretense (i.e., they will prefer to play moral scenarios), given that children use an objective moral framework (Heiphetz & Young, 2017; Nichols & Folds-Bennett, 2003) and have a preference for other's moral behavior in pretense (Fast & Van Reet, 2018).

Further, we hypothesized children will resist pretense scenarios where they have to embody the antisocial or immoral agent more than when others portray the immoral agent. Finally, we hypothesized a developmental trajectory for Moral Imaginative Resistance, where younger children will display more resistance across both moral valence (moral or immoral) and agent (self or other).

Study 1 Method Participants

Study 1 consisted of 60 children and their primary caregiver, recruited in the summer of 2023 from parks in a suburban area outside a large east-coast city. An additional 20 children failed the warm-up task answering questions about pretense and reality and were excluded as we could not be confident in their understanding of pretend actions.

Children were between the ages of 51 and 82 months (Mean = 66.42, SD = 9.01). There was an uneven distribution of age, with 14 (23.3%) four-year-olds, 30 children (50%) five-yearolds, and 16 (26.7%) six-year-olds. The child sample was 71.7% female and 28.3% male. Measures

Children's Imaginative Resistance Children's Imaginative Resistance was measured through a card-sorting task developed for this study. Each card had an image corresponding to one of 24 pretense scenarios, evenly distributed among morality (moral or immoral) and moral agent (self or other), with six items in each. Children were asked "would you want to play…" followed by the pretend play scenario and sorted into yes/maybe/no. As this measure included situations of pretend violence, harm, and death, parents were able to red-line scenarios. A total play Imaginative Resistance score was calculated as the mean score (yes = -1, maybe = 0, no = 1) across all 24 scenarios. All items from all measures are available in supplementary materials.

Child Moral Imagination To measure child Moral Imagination, we developed a measure asking the child if it is ever okay to do something traditionally impermissible, such as hitting someone. Items spanned across five moral domains; fairness/, loyalty/betrayal, authority/subversion, care/harm, and purity/sanctity (Graham et al., 2013), and children were asked whether the action would be ok to do in real life, when pretending, and when joking. This measure allowed us to test what domain of moral behaviors children were more likely to resist against, if any.

Child Moral Evaluations

Children's moral evaluations were measured via a moral transgression task developed by Killen et al. (2011) for use with 4-6-year olds. Children were asked for the intent of a transgressor (Alex), a justification for that intent, an evaluation of the act, a justification for the evaluation, and, as an open-ended response, the emotions of victim and the transgressor. The moral evaluation score was the average of intent judgement and evaluation of the act.

Parental Report of Negative Child Play.

We developed a 12-item questionnaire to measure parental reports of child negatively themed play. Items were chosen from negative themes described in the play therapy literature (i.e., Benedict, 2004; Bruin, 2018; Snow et al., 2007) and reports of themes in studies focused on other topics within play (i.e., Bauman, 2015; Hellendoorn & Harinck, 1997; Sturdivant & Alanis, 2021).

Procedure

Recruitment and participation occurred in several local parks in the Mid-Atlantic region of the USA from July to September of 2023. Parents and children were approached by a researcher, completed consent and assent forms, and then parents complete their questionnaire via QR code while children worked with the researcher individually. IRB approval was given by Geroge Mason University (Study # 2046296-1). The researcher defined real and pretend, and presented 4-6 warm up vignettes of real and pretend characters (e.g. Tinkerbell, Spiderman, President Obama). Participants were excluded if they got more than one reality judgement incorrect.

Once children passed, they were given the Moral Imaginative Resistance card sort task for all 24 scenarios (unless red-lined by the parent). Then, children asked if they would actually play one of the "maybe-play" scenarios for a 10-minute free play time. If there were no cards in the "maybe-play" square, participants were offered one from the "no-play" square. Children were offered up to three scenarios, and, if no scenario was selected, told to play whatever they liked.

Study 1 Discussion

For preschoolers' displays of Moral Imaginative Resistance in their thematically negative pretense, there was a main effect of moral valence, where children preferred positive moral valence over negative moral valence. However, there was no effect for how they engaged in that moral or immoral behavior (i.e. as themselves or another agent), and resistance did not differ across age. Thus, our first hypothesis that Moral Imaginative Resistance would be engaged more often for immoral over moral scenarios was supported. Young children seemed to incorporate their real world moral values into their pretense, consistent with past literature (Fast & Van Reet, 2018; Kushnir, 2022).

There was no main effect found for moral agent, though this may be influenced by our small sample size. However, when enacting the pretense scenarios, the majority of children across pretense scenarios reported playing as the good guy in their pretense and less than a third as the bad guy. Perhaps who plays the moral agent does not matter when abstractly discussing the pretense scenarios but does when it comes to active, embodied imaginative engagement.

Additionally, we found no age effects for Moral Imaginative Resistance which was surprising, considering morality and moral understanding follow a developmental trajectory. However, that effect may be due to the relatively small sample size at each age bracket. Thus, we conducted study two to replicate our findings with a more diverse sample of participants.

Study 2 Discussion

Study 2 replicated and extended the findings from Study 1. Similar pretense scenarios invoked the most and least amount of Imaginative Resistance across both studies, and we found age effects with our larger sample size, suggesting Imaginative Resistance may have a developmental trajectory. For the interaction between agent and morality, it seems that no individual difference is driving the interaction effect, but that the interaction is being driven by main effects.

Further, young children again find moral violations more permissible in a pretend context than in real life or when the offender is joking. Thus, the introduction of make-believe into a setting may be enough psychological distance for a child to view moral violations as more okay, though moral permissibility differed depending on the child and the violation, suggesting individual differences. Similar to Study 1, the majority of the moral evaluations for a story containing an act of harm judged the act as immoral, suggesting that, when presented with a realistic scenario, 4-7-year-olds are able to provide moral evaluations.

General Discussion

Children display Imaginative Resistance in response to morally-deviant pretend play scenarios. Across two studies, we found children were less likely to want to engage in pretense containing immoral versus moral actions, supporting our first hypothesis. Our second hypothesis, that children will resist pretense scenarios where they are playing the immoral over moral agent was partially supported. While neither of the current studies showed a main effect of agent on Imaginative Resistance Study 2 showed an interaction between agent and moral valence, where children showed more resistance to the self acting as the immoral agent than others acting as the immoral agent, and less resistance to the self being good than others being good (in an immoral scenario). This experimentally supports past observational work where, despite immoral themes being present, children did not want to physically be the one enacting those immoral themes (Logue & Detour, 2011).

Our third question was where there is a developmental trajectory to moral imaginative resistance. We initially hypothesized that younger children would display more Moral

Imaginative Resistance, but our Study 2 showed an effect of age in the opposite direction. Older children displayed more Imaginative Resistance, primarily driven by 4-year-olds displaying less Imaginative Resistance than 6-and 7-year-olds, pointing to a developmental shift around age 5. Perhaps Imaginative Resistance draws upon similar cognitive underpinnings as possibility judgements (which shift between 4-and 8-years old, Shtulman & Carey, 2007) or relies on developing a firmer idea of the moral self (which begins to emerge around age 5 (Söldner et al., 2024).

Another possible explanation is the introduction of more formal schooling at this age, containing more explicit instruction of what is considered "proper" or "improper" play and behavior, but more research is required to investigate this shift in moral engagement.

Distance also seemed to affect Moral Imagination and Imaginative Resistance. In the Moral Imagination task, moral judgements on pretend actions were judged more permissible than joking actions, which were judged more permissible than real ones. There were no difference across age, perhaps because either the range of ages was too narrow to detect a developmental trajectory, or because the scenarios were all within the age-appropriate range and were not too complicated for the younger participants, resulting in a celling effect. However, our results suggest moral evaluations and Imaginative Resistance may be context-dependent in children, dependent on how close to reality the immoral scenario is. A gradient of reality status on moral evaluations on immoral actions may exist, where immoral actions are deemed most permissible in pretend, somewhat permissible when joking, and least permissible in real-life. These findings are consistent with the past work of fictionality influencing moral evaluations (Sabo & Giner-Sorolla, 2017) and other work in preschoolers where fantastical contexts allow immoral actions to be permissible more than in realistic or real narratives (Fast & Van Reet, 2018) or require fantastical elements to even occur (Shtulman & Phillips, 2018).

There was no significant effect of moral domain type on the moral judgements across reality context in either study. This may be because any differences found in the reality context were washed out by the increased Moral Imagination engaged with in the pretend and joking contexts compared to the reality context. Perhaps domain differences in moral judgments found in realistic or real contexts (e.g., Ball et al., 2017) do not extend to pretend contexts even though general moral judgments can and do (Fast & Van Reet, 2018), though further research is needed.

While this Moral Imagination measure spanned moral domains in order to ensure a range of moral contexts for participants to engage with, the primary purpose was to examine Moral Imagination across contexts varying in closeness to reality. Further studies could be more Young Children's Resistance to Immoral Actions 22 specifically tailored to focus on situations spanning moral domains to see whether or not differences domain-based judgements in this age groups extend to varying contexts.

Conclusions

This study is the first to explore Moral Imaginative Resistance in a developmental context and through embodied engagement.

Taken together, these two studies suggest Moral Imaginative Resistance follows a developmental trajectory, with resistance of morally-deviant behavior increasing with age, but even young children still view immoral actions as more morally permissible in non-realistic contexts. The flexibility of moral engagement and disengagement supports morality as malleable in early childhood and that moral views may be more expansive with increased psychological distance of reality.
