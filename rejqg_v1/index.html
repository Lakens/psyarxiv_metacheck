To check Non-Significant P Value Check

What we found

We found 29 non-significant p values that should be checked for appropriate interpretation.

Show details

Meta-scientific research has shown nonsignificant p values are commonly misinterpreted. It is incorrect to infer that there is ‘no effect’, ‘no difference’, or that groups are ‘the same’ after p > 0.05.

It is possible that there is a true non-zero effect, but that the study did not detect it. Make sure your inference acknowledges that it is possible that there is a non-zero effect. It is correct to include the effect is ‘not significantly’ different, although this just restates that p > 0.05.

Metacheck does not yet analyze automatically whether sentences which include non-significant p-values are correct, but we recommend manually checking the sentences below for possible misinterpreted non-significant p values.

Patterns are designed to capture:

The Power Analysis Check module uses regular expressions to identify sentences that contain a statistical power analysis. How StatCheck works

Check consistency of p-values and test statistics

The Statcheck module runs Statcheck. Statcheck searches for regular expressions that match a predefined pattern, and identifies APA reported statistical tests. More information on the package can be found at https://github.com/cran/statcheck. The module only returns Statcheck results for t-tests and F-tests, as these are the only tests which have been validated, see https://osf.io/preprints/psyarxiv/tcxaj_v1/.

Statcheck was developed by Michèle Nuijten and Sascha Epskamp.

Statcheck considers p = 0.000 an error, as you should report p < 0.001. Furthermore, p < 0.03 is an error if the p-value was 0.031, and one should simply report exact p-values (p = 0.031). When the sentence of a test says it is one-sided (“one-tailed”, “one-sided” or “directional”), a p-value that fits a one-sided test counts as consistent (statcheck’s OneTailedTxt setting; #695). When the paper says anywhere that its tests are one-sided, a p-value that fits a one-sided test in either direction counts as consistent too: half the two-sided p, or 1 minus that half for an effect against the predicted direction. Equivalence tests (TOST) are left out, as their p-values do not test the difference. A statistic written with “<” or “>” is read as a bound, and in a sentence about equal variances an F-test’s two-sided p (twice the one-tailed p) counts as consistent. For more information, see StatCheck.

This module only checks statistical results reported in the running text of the manuscript. It cannot (yet) process statistics reported only in tables.

How Exact P-Values works

List any p-values reported with insufficient precision (e.g., p < .05 or p = n.s.), reported as exactly zero (e.g., p = .000), or impossible (below 0 or above 1, e.g., p = -.22).

This module uses regular expressions to identify p-values. It will flag any values reported as p > ? or p < numbers greater than .001. It will also flag p-values reported as exactly zero (e.g., p = .000, p = 0.00), which are mathematically impossible — p-values are never exactly zero and should instead be reported as p < .001.

A p-value that is not the result of a test is not flagged: a table note (“* p < .05, ** p < .01”), a figure legend (“Asterisks indicate significant differences (p < .05)”, “Values in bold are significant at p < .05”) or a stated threshold (“p < .05 was considered significant”, “thresholded at p < .001”). GROBID often puts such notes into the running text, so each p-value is judged by the words in its own clause (the text up to a “;” or a full stop), and never left out when a test statistic belongs to it (“F(1, 7) = 8.03, # p < .05”). The column not_a_test of the table says why a p-value was left out (“marker”, “threshold”, “legend” or “named”).

A p-value with the name of a correction or a test after the p (“pFWE < .05”, “padj < 0.05”, “p Wilcoxon = .02”) is flagged only when a test statistic comes before it in its clause (“t(37) = 7.17, p FWE < .05”). Without one it is mostly the rule that decided what was significant (“genes with padj < 0.05 were selected”); such a p-value is “named” in not_a_test. Notes in other forms, such as a marker after the p-value (“p < .05 (*)“), are still flagged.

A p-value below 0 or above 1 is impossible; it is listed apart and not also as imprecise. Often the statistic before it, or its minus sign, was copied into it (“t(134) = -2.32, p = -.13”, “Z = 3.091, P = 3.091”). A value above 1 is listed only after a test statistic in its clause: without one, a “P” above 1 was nearly always another quantity (a proportion, pH, a group’s mean, a model parameter). A number in scientific notation whose power of ten was lost when the PDF was read (“p = 2.4 x 10 -9” read as 2.4) is not listed. A “p” that is the subscript of another symbol (“r p = .64”, “²p = .02” for partial eta squared, “Δp = .33”), or a quantity with a unit, a logarithm or a ratio (“P = 2.9 µm”, “-log10 P = 7.5”, “Ca/P = 1.67”), is not read as a p-value at all (see extract_p_values()). Each p-value has its own row, also when the same one is written twice in a sentence.

This module sometimes flags false positives when sentences discuss how p-value thresholds were set. It can also miss an imprecise p-value that is reported against a threshold (“decreased at the p < .05 significance threshold”).

This module only checks p-values reported in the running text of the manuscript. It cannot (yet) process p-values reported only in tables (as opposed to a table’s footnote text, which the module does see and tries to exclude — see above).

Listing a repository’s files never requires an API key, but some hosts answer faster or more completely with one: OSF allows 100 requests/hour unauthenticated versus 10,000/day with a token (see [osf_pat()]), and Dryad enforces a strict per-IP daily quota on repeated listing (see cache below). Dryad is a special case beyond rate limits: listing a Dryad dataset’s files works without a key, but actually downloading file CONTENTS from Dryad fails with HTTP 401 unless a key is set, even for a fully public dataset (see [dryad_pat()] or [dryad_auth()]). Since this module only lists files and never downloads their contents itself, that limitation applies to data_check and code_check (which do download content), not here – see their own documentation.

When a linked OSF page is a registration, its registered_from project (the one it was registered from, which the manuscript itself may never link directly) is also checked: if that project is public its files are listed under its own URL, and if it is closed or otherwise inaccessible the report flags it explicitly, since some registrations only describe their content rather than mirroring it.

Whose deposit is each link? The ownership table gives, for every repository linked in the text and (with references = TRUE) every deposit cited in the reference list, one of six labels: own_this (made by the authors for this paper), own_earlier_data or own_earlier_code (the authors’ own, from earlier work), others_data or others_code (made by other people, reused here), or not_data (a publication such as a preprint, not a deposit), with ownership_group (“own”, “others”, “not_data”) and the reason. It is decided without a language model, from the sentence or reference that cites the link, the paper’s authors (names, ORCID iDs, affiliations), and what the deposit’s own record and files say (who made it, what it names, when, whether it is a software package; for an OSF project cited only in the reference list, its record alone). On a round of labelled links the rules had not been written from, the three groups were right for 98% of links in the main text (93 of 95) and 90% in reference lists (74 of 82); the labels were made by Claude agents from each link’s evidence, and disputed ones checked against the deposits. Telling this paper’s own deposit from the authors’ earlier one is less certain.

Only the deposits that are this paper’s own are checked. A deposit linked in the text that holds other people’s work (others_data, others_code) or the authors’ earlier work (own_earlier_data, own_earlier_code) is listed in the report, with the reason, but its files are left out of table and kept in table_not_checked: they count toward nothing here (files that do not belong in a repository, naming, READMEs, studies, the traffic light), and code_check, data_check and reproducibility_check, which read table, do not check them either. reproducibility_check still puts the files of theirs that the paper’s code names in the folder the code runs in, as a re-analysis needs the data it re-analyses. When every linked deposit is set aside, the traffic light is “na”. A deposit that is the paper’s own is counted as such when its README, title or description names the paper (its title or DOI).

How Code Check works

This module retrieves information from repositories checked by repo_check about code files (R, Python, SAS, SPSS, Stata, Mplus, MATLAB).

The Code Check module checks R (also R Markdown and Quarto), Python (also Jupyter notebooks), SAS, SPSS, Stata, Mplus, and MATLAB files, using regular expressions to check the code; JASP files are listed but not read. The language of a Quarto document or a notebook is read from the file itself (its engine or kernel), not from its extension. The regular expression search will detect the number of comments, the lines at which libraries/imports are loaded, attempts to detect absolute paths to files, setwd() and install.packages() calls, and lists files that are loaded, and checks if these files are in the repository; R code is also parsed. The module will return suggestions to improve the code if there are no comments, if libraries/imports are loaded in lines further than 4 lines apart, if files that are loaded are not in the repository, if absolute file paths, setwd() or install.packages() are found, and if R code cannot be parsed.

The regular expressions can miss information in code files, or falsely detect parts of the code as a fixed file path. Libraries/imports might be loaded in one block, even if there are more than 3 intermittent lines. The module was tried out internally on papers published in Psychological Science, but has not been formally validated. There might be valid reasons why some loaded files can’t be shared, but the module can’t evaluate these reasons, and always gives a warning.

The module also checks whether the repository pins the R/package versions the analysis actually depended on: an renv.lock file (parsed for the R version and every locked package + its version/source), a sessionInfo()/sessioninfo::session_info() text dump (matched by filename — sessionInfo.txt/session_info.txt and similar, or embedded in a README), or a groundhog::groundhog.library()/checkpoint::checkpoint() date-pin call in the code (a bare library(groundhog)/library(checkpoint) does not count — the pinning call itself must be present). When none of these is found, the report flags it as a reproducibility gap: package versions may drift between when the analysis was run and any later reproduction attempt.

If you want to extend the package to perform additional checks on code files, or make the checks work on other types of code files, reach out to the Metacheck development team.

Without a key, every Dryad-hosted code file is listed but unchecked, and a warning naming Dryad and ?dryad_pat/?dryad_auth is included among the download failures recorded in the manifest.

How Data Check works

This module classifies the files in a repository into semantic types (data, codebook, code, software, output, supplemental, readme, asset, other) and, for tabular data files, extracts each column’s type and summary statistics.

The Data Check module consumes the file list produced by repo_check (or any files added via local_path). Each file is classified with rule-based heuristics layered over metacheck’s file_category() and file_types: file names matching README / codebook patterns win first, then an extension crosswalk, then format-locked extension overrides. For every file classified as tabular data that is available locally, the module reads the file head, describes each column with data_col_facets() and computes summary statistics for numeric columns. Every sheet of a spreadsheet that holds a table is read: a file with several such sheets has its columns under source_file = "file.xlsx [sheet]", and the sheet column names the sheet of any spreadsheet with several sheets; a sheet of notes or a codebook is treated as documentation when the file has another table. Following DDI, a column is described by orthogonal facets rather than a single type: representation (numeric/text/datetime/code — how it is stored), measurement_level (Stevens: nominal/ordinal/interval/ratio), concept (what it measures: reaction_time/age/gender/likert/id/…), role (identifier/measure/condition/timestamp), unit, and a quality state (ok/empty/constant). Concepts are detected by name+value rules (the demographic concepts via data_check_demographic()); when llm_use(TRUE) the model fills concepts and measurement levels the rules left blank. Qualtrics survey exports are recognised (data_check_is_qualtrics()): their extra header rows are stripped so columns type correctly, and the reserved response-metadata columns (StartDate, Duration, Finished, …) are tagged.

The module defaults to rules-only when llm_use(FALSE): columns the rules cannot resolve (ambiguous 3–20-unique integers, ambiguous character columns) fall back to continuous / text respectively. When llm_use(TRUE), ambiguous columns and unresolved file types (other) are sent to llm() for optional refinement, and every file is assigned a study group (ex1, pilot2, shared, …) so that multi-study repositories can be recognised (used by psychds_check). Without an LLM the study group is left NA (unknown).

Column extraction requires files to be readable from disk. Files fetched by repo_check from OSF/GitHub/etc. without a local copy (file_location is NA) are classified but not column-extracted; pass local_path to point at a downloaded copy of the repository.

For a paper whose repository is on Dryad, this means column extraction never happens unless a Dryad API key is set: Dryad requires one to download file bytes, even from a fully public dataset (dataset listing and metadata do not need one). Without a key, every Dryad file stays classified but un-downloaded, column_n is 0, and a warning naming Dryad and ?dryad_pat/?dryad_auth is included among the download failures. A one-time session message is also shown (see repo_check) the first time a Dryad dataset is encountered with no key set.

Every downloaded text file the authors wrote (code, settings, survey definitions such as Qualtrics .qsf files, documentation, outputs) is searched for keys: API keys, access tokens and private keys, which let anyone who downloads the file use a paid service at the authors’ cost. Of a tabular data file only the column names and first 3 rows of the table as read are searched: its values come from participants, but a key the authors set for a whole survey (as embedded data in a Qualtrics survey flow) is exported in every response. The search uses the rules of the secret scanner betterleaks (https://github.com/betterleaks/betterleaks, MIT licence) of high and medium confidence. A key found turns the traffic light red; the report and the keys table give its file, line and type, and only its beginning. Other files over 25 MB and binary files are not searched. A key is never tested with its provider. Every module’s result has any whole key replaced by “keyremoved” (see module_run()).

How Reproducibility Check works

This module assesses whether a paper’s R and Python code can be run on its data. It works in two phases. The static phase (always run) collects the package dependencies the code declares, rewrites the data-file paths that do not work in the repository as the authors organised it, works out the order the scripts must run in, and diagnoses why any referenced input file is unavailable — reporting what a reproduction attempt would involve and where it is likely to break. The execution phase (opt-in, execute = TRUE) then actually runs the code: it copies the repository into a throwaway directory, optionally installs the declared dependencies into a throwaway library, runs each script in order in an isolated subprocess with a per-script timeout, and captures the outcome and full output of each run.

By default (execute = FALSE) the module does not run any code — it performs only static analysis: reading dependencies with the same extractors as code_check, finding the files the code references in the repository, and building a run-order dependency graph. It reports what would be installed and run rather than doing it.

When execute = TRUE, the module additionally runs the downloaded code on your machine — a deliberate, opt-in action gated behind that argument (callr is required for R code). Each script runs in an isolated subprocess so a crash cannot take down the R session; note this isolates crashes, not the filesystem or network. Installs (when install_missing = TRUE) and the throwaway run library never touch your main R library. Each script’s outcome is one of ran_ok, errored, timed_out, dependency_unavailable, not_parsed, run_by_source (an R script another script runs with source(), which is run only inside that script, since on its own it lacks the packages and objects the sourcing script sets up first), run_by_import (a Python file other files import, a module rather than a script, unless it has an if __name__ == "__main__": block), jags_model (a JAGS or BUGS model saved with an R extension, which another script reads) or not_r_content (a file that is not R at all, such as a JSON or HTML dump); these last two are not run and are not failures. python2 marks Python 2 code that was not run. With sandbox = "docker" such code runs with Python 2.7 (option metacheck.docker_image_py2; FALSE turns this off), which modifications records; it is never converted, since that can change results. defines_functions is a file that only defines functions, which is used, not run (table$used_by names the scripts that use it), and not_analysis is a file of software rather than of the analysis: a package’s code, tests, documentation or setup.py, a copy of a tool, a web application, a script a program wrote (table$not_analysis_why says which); neither is run or counted as a script. docker_failed means the container never started, which says nothing about the script, so it keeps the light from being green but does not make it red. needs_a_person is a script that stopped because it asks a person to choose a file or answer a question, or that starts an app, and needs_internet one that stopped because the network is off in a Docker run, or, with internet = TRUE, could not reach what it asked for; download_too_large is a script stopped for downloading more than the limits allow (see internet), and out_of_memory one that, or a program it started (such as a compiler), ran out of the memory each script may use. All four are treated the same way. not_downloaded is a script that stopped on a file the repository lists but that was not downloaded, such as one over max_file_size: it could not be tried, so it is not counted as a script that did not reproduce (summary_table$repro_not_downloaded_n counts them apart). not_read is a file metacheck could not read, so it was not run; the light is then not green, as the file may read and run on another computer, and table$error_message says why, naming a package that is installed but cannot be loaded on the computer that ran the check. empty is a file with nothing in it, which is not run or counted as a script. For a script that did not run through, table$error_message is its error, short (at most 300 characters): the error line of its output, which names a package that is not there, with the address it asked for when it needed the internet, or the time limit it reached; table$reason sorts it into a kind. A timeout means “still running at the cutoff”, not a failure, so raise timeout for legitimately long-running (e.g. Bayesian) scripts. dependency_unavailable means the script’s own package could not be installed from live CRAN, the CRAN Archive, or a named GitHub/URL source — an infrastructure limitation, not a defect in the paper’s code. The full stdout/stderr of every run is kept in the result’s run_results (the report shows it in per-script dropdowns, capped for readability).

Provenance, kept so that a TRACE Research Object (TRO) declaration of the run can be written later from a stored result (metacheck #404; the helpers are in R/provenance.R). Only when code was run (execute = TRUE): * run_results$started_at, run_results$ended_at: when each run of a script started and ended (ISO 8601, UTC, milliseconds); NA for a script that was not started. A script run again in a later pass has the times of its last run. A TRO uses them for each trov:TransparentResearchPerformance. * run_results$exit_status: the exit status of the process that ran the script (0 = ended normally); NA when the process did not report one (a time limit, or Docker failing to start the container). * artifacts: one row per file, with stage (deposit: as downloaded from the repository, hashed from the downloaded file; before_run: the run folder just before the first script ran, after metacheck’s own changes, such as rewritten paths and unpacked archives; after_run: only the files the scripts made (status new), changed (changed) or removed (removed), as an unchanged file is the one listed before the run), path (relative to the run folder, as valid UTF-8, a byte of another encoding written as <xx>), size (bytes), sha256, mime_type (by extension, NA when unknown), source (the file’s address in the repository, for deposit). The package libraries metacheck installs in the run folder are left out, as are metacheck’s own files there (a script’s runner, and the statistical output it writes in statistical_output/). Files metacheck itself copied or made between passes (see modifications, output_copied, file_placed) show in after_run too. A TRO uses the rows as trov:ResearchArtifacts and each stage as a trov:ArtifactArrangement. * modifications$sha256_before, modifications$sha256_after: the hash of the changed script as downloaded and as it ran; NA when the script is not at the same path in both (a script made from an R Markdown file). * environment: the system that ran the code (trov:TransparentResearchSystem in a TRO): metacheck_version, started_at, ended_at, host (R version, platform, operating system), sandbox, network_isolated (TRUE only when every Docker run had --network none; the process sandbox does not stop the network), internet, timeout_per_script, total_timeout, python_local (the Python run outside Docker and its version), and docker: runs (for each kind of run, r_run, r_install, python_run, python_install, the image and the docker run arguments, such as --network none, --read-only, --cap-drop ALL, no-new-privileges, the process limit and the memory and processor limits) and images (for each image, its ID and digests from docker image inspect, its creation time and the R and Python versions its environment declares).

run_results$checked says what the run of each script shows about the code, in five groups, so that a script that does not reproduce is kept apart from one the check could not test: ran (it ran to the end); code_error (it did not reproduce: it stopped with an error of the code or the deposit, could not be read, or needs a file the deposit does not hold); dependency (a package or program was not available: a package that could not be installed or was not loaded, a program outside R and Python, a system library, or R crashing in a package’s compiled code); time (it did not finish within the time limit for one script, or was not started because the time for all scripts had run out); and not_checkable (it could not be checked automatically: it needs a person, the internet, a key or another setting of the authors’ computer, one platform such as Google Colab, Windows or OpenSAFELY, more memory than the run allows, a file that was not downloaded, a screen, or a program that runs it, or it is a file of a package of the code that Python runs only as a module of that package). It is NA for files run inside another script, files that are not an analysis, files not read, and a Docker failure. summary_table counts each group (repro_ran_n, repro_code_error_n, repro_dependency_n, repro_time_n, repro_not_checkable_n), and the report’s first sentence gives them. The traffic light reflects the static readiness signals by default; a script in code_error that stopped with an error makes it red, as a script that crashes on its own analysis is a genuine reproduction failure, and a script in one of the other three groups keeps it from being green. Calls that need a screen, which the run does not have (dev.print(), dev.copy2pdf(), dev.copy2eps(), savePlot(), windows(), win.graph(), x11(), quartz(), View()), are replaced before the run by calls that need none, which modifications records as screen_call_replaced. A script that fails with could not find function is run once more with the library() calls the project’s other scripts make added at its top (or the one package that exports the function, or magrittr for %>%), and a script that then runs is reported as reproducible only after that repair.

Dependencies are reported name-only, with the source (CRAN, GitHub, or a base package already shipped with R) — static analysis of the code cannot know which version was used, and running against current package versions is itself informative: a break argues the authors should have pinned versions. When the repository does record versions, a run with recorded_versions = TRUE installs the packages the scripts load at those versions, but it does not change the R version, which remains a limitation of the check.

Run order is derived from read-after-write data dependencies (a script writing a file another reads must run first), source() edges, and numeric filename prefixes as a weak tie-breaker. Ambiguous orderings, dependency cycles, and inputs a script reads but that no earlier script produces (and that are not in the repository) are surfaced as warnings, since these are the situations most likely to make an otherwise-correct reproduction fail.

Python code (.py files, and notebooks and Quarto documents whose code is Python, from which the code is extracted first) goes through the same two phases, reported in its own “Python code” section. Each file is checked for syntax errors with Python’s own parser when a Python interpreter (python, or else python3) is available; dependencies are read from the import statements, with versions from a requirements.txt or pyproject.toml when there is one, and installed with pip; each script runs as its own python process (processx is required), so unlike R scripts, a name one script defines is not available to another. When no Python interpreter is available, the Python files are reported as not run and the R results are still returned. Statistics the Python scripts print are compared with the paper together with the R output and any self-reproducible output (JASP/jamovi, SPSS-Viewer, notebook outputs).

Abstract

Optimizing human cognitive functioning requires a delicate balance between top-down self-regulation and bottom-up motivational reinforcement. However, the precise temporal trade-offs between these opposing trajectories (specifically, immediate reward-driven gains versus gradual mindfulness-based structural adaptation) remain poorly understood. Using a mixed longitudinal design, we assessed cognitive and psychological outcomes using the Mindful Attention Awareness Scale, Perceived Stress Scale, Stroop task (executive control), N-back task (working memory), and Rapid Visual Presentation task (sustained attention). Results showed that mindfulness meditation significantly improved working memory (in an N-back task). Interestingly, the Stroop task showed declined accuracy, but with faster reaction times, suggesting a speed-accuracy trade-off rather than genuine improvement for executive control. Moreover, while mindfulness did lead to an increase in the Mindful Attention Awareness Scale, it did not decrease perceived stress. The result patterns for the reward condition differed from mindfulness meditation. Explicit reward resulted in faster reaction times on the Stroop task, but these were accompanied by reduced accuracy, suggesting a speed-accuracy trade-off rather than genuine cognitive improvement for executive control (in line with mindfulness meditation). Reward did not lead to any significant changes over time in other cognitive tasks. Thus, the improvements in working memory over time were specific to mindfulness meditation and not shown for reward-based manipulations. Overall, these findings highlight the importance of distinguishing genuine cognitive improvements from changes in response strategies.

1 Introduction

A central challenge in cognitive science is identifying methods that have the potential to optimize human cognitive functioning. This pursuit increasingly highlights the tension between top-down self-regulation and bottom-up motivational reinforcement. Specifically, investigating the temporal dynamics of cognitive enhancement requires reconciling the mechanisms of mindfulness-based interventions with reward-based interventions that are more incentive-driven. While both aim to enhance cognitive performance, they operate on opposing trajectories over time. Reward-based systems are known to focus mostly on the dopaminergic pathway to alter task salience which often leads to immediate improvements (Tafet & Ortiz Alonso, 2024). However, these gains are highly susceptible to habituation (Dubey et al., 2022; Lloyd et al., 2014). Conversely, mindfulness modulates frontoparietal and executive control networks (Bremer et al., 2022; Liu et al., 2026; Melis et al., 2022), which requires effortful training that initially yields minimal behavioral change but gradually over time leads to gains in cognitive function that are more structural. While both approaches have been studied extensively in isolation within cognitive enhancement literature, they are rarely evaluated in direct opposition. Here we aim to fill this critical empirical gap. Consequently, a longitudinal comparison of these two approaches provides a critical framework for evaluating the trade-offs between immediate motivational cognitive enhancement that is prone to habituation and gradual, long-term and more sustained increase in cognitive performance.

Mindfulness meditation (i.e., intentional and non-judgmental focus on the present moment to increase awareness of thoughts and feelings (Basso et al., 2019; Verhaeghen, 2020)) consistently shows benefits for attention; for prioritization of cognitive resources (Mancas, 2016) as well as maintaining focus on tasks over long periods (Bajestani et al., 2024; Cohen, 2011; Petranker & Eastwood, 2021; Roy & Subramanya, 2025). It also benefits the coordination of goal-directed behavior also known as executive control (Cásedas et al., 2020; Gallant, 2016; Miller & Wallis, 2009). It is still a matter of debate which aspects of attention improve and how working memory (i.e., temporary information storage and manipulation; Baddeley, 2010) is affected. Some studies show that short-term meditation enhances sustained attention, working memory, and executive functioning, suggesting rapid cognitive gains similar to those seen in long-term practitioners (Zainal & Newman, 2024; Zeidan et al., 2010). However, other studies highlighted improvements specifically in the orienting aspect of attention, supporting flexible shifting, rather than in executive control or sustained attention (Tsai et al., 2018; van den Hurk et al., 2010). Positive effects of meditation on focused attention and executive control are shown in adults (Ainsworth et al., 2013) as well as children (Flook et al., 2010), indicating that mindfulness-based interventions can be effective across ages. There are also clear discrepancies in the meditation literature. For example, Yakobi et al., 2021 reported slight gains in attention and executive control but no clear benefits for working memory, contrasting with Zeidan et al., 2010 and Basso et al., 2019 observations of short-term working memory improvements, which appear to depend on meditation length and intensity, as suggested by a meta-analysis (Verhaeghen, 2020). Another meta-analysis (Sumantry & Stewart, 2021) found that combining meditation styles did not outperform individual styles, implying that focused and open monitoring practices may engage similar cognitive mechanisms and that training specificity matters. This aligns with van den Hurk et al., 2010's finding of selective effects on orienting attention but challenges expectations of broad attentional enhancement from combined practices. Altogether, these discrepancies across studies suggests meditation may affect cognition differently depending on the focus and duration of practice. In more detail, summarizing across these studies, attention and executive control seem to be most consistently improved by meditation (Basso et al., 2019; van den Hurk et al., 2010; Yakobi et al., 2021; Zeidan et al., 2010). Results on working memory are a bit more diverse, with some evidence pointing to improvements in working memory (Basso et al., 2019; Verhaeghen, 2020; Zeidan et al., 2010) while a meta-analysis (Yakobi et al., 2021) found no significant working memory effects. Yet another metaanalysis (Moradi et al., 2025) did find effects of mindfulness on working memory on average, but indicated that it is moderated by age and number of weeks of practice.

Here, we compare the results of mindfulness meditation across all these cognitive domains and also relative to another cognitive enhancement strategy, namely receiving either explicit or implicit rewards. This leads to direct comparison between top-down self-regulation methods for cognitive enhancement and bottom-up motivational reinforcement methods. Explicit rewards (or conscious rewards) are explicit incentives which are tangible rewards consciously known to participants (van Triest, 2018; Zedelius et al., 2012). Implicit rewards (unconscious rewards) are unconscious incentives that are subliminal and non-physical incentives (van Triest, 2018; Zedelius et al., 2012).

Explicit rewards may promote proactive strategic control by encouraging to use cognitive effort when tasks place substantial demands on working memory. When rewards are consciously represented and perceived as attainable, they can motivate individuals to engage more deeply with a task (Pessoa, 2014; Zedelius et al., 2012). The importance of conscious reward processing is particularly evident in the distinction between explicit and implicit incentives. In a 2-back working memory task, high-value explicit rewards enhanced performance, whereas implicit rewards did not produce the same benefit (Xu et al., 2022). This difference suggests that the effectiveness of incentives may depend on whether individuals consciously process reward information and can use it to guide their behavior (Pessoa, 2014). More broadly, motivation may improve working memory by influencing how information is prioritized and retrieved, rather than simply increasing memory capacity (Grogan et al., 2022). Reward-related improvements may therefore reflect not only increased willingness to exert effort but also the strategic allocation of cognitive resources toward valued goals. Such strategic investment may depend on whether cognitive effort is perceived as instrumental to achieving a desired outcome (Grahek et al., 2023). A meta-analysis by (Wang et al., 2024) found that both monetary and non-monetary explicit rewards significantly improved working memory performance. Together, these findings suggest that explicit rewards can support working memory by making reward value available for deliberate, goal-directed regulation of cognitive effort.

Implicit rewards may facilitate attention through relatively automatic, stimulusdriven processes (Pearson et al., 2022), making them useful when rapid responses are required. For instance, subliminal monetary rewards improved performance in the attentional blink task, whereas explicit rewards impaired it, possibly by directing excessive attention toward the first target (Bijleveld et al., 2011). Similarly, implicit high-value cues enhanced executive control accuracy, suggesting that learned reward associations can guide attentional processing without deliberate control (Capa et al., 2011; Pessoa, 2014). However, these benefits may depend on task demands (Milner et al., 2023): in a 2-back working memory task, implicit rewards failed to improve performance, whereas explicit rewards did (Xu et al., 2022). Thus, implicit rewards may benefit relatively automatic processing, while explicit rewards may be more effective when tasks require sustained cognitive effort and strategic resource allocation.

Beyond cognitive tasks, similar patterns emerge in motivational contexts where it was found that implicit incentives (e.g., long-term career advancement) sustained motivation over time, whereas explicit incentives (e.g., performance bonuses) boosted only short-term output, strengthening the cognitive finding that implicit rewards may promote stable engagement, while explicit ones invoke temporary effects (van Triest, 2018). Overall, these findings highlight the differential roles of top-down self-regulation and bottom-up motivational strategies in cognitive enhancement, with their relative effectiveness depending on task demands, the level of conscious reward processing, and the timescale over which benefits are expected.

Therefore, in the current study, we focused on the following research questions: What are the effects bottom-up motivational reinforcement strategies (i.e., explicit and implicit reward) and top-down self-regulation strategies (i.e., mindfulness meditation) on attention, executive control and working memory? To what extent are the effects of these distinct strategies similar or dissimilar across these cognitive domains? While mindfulness meditation and (explicit/implicit) rewards have been studied separately, they have not been studied together in the same study design. We hypothesized that explicit and implicit rewards may induce short-term cognitive improvements, while meditation may foster longer-term improvements, which would offer insights into their differential applications (Bijleveld et al., 2011; Zeidan et al., 2010). Understanding these different mechanisms can help identify which approach is suitable for specific goals or populations. We measured cognitive performance across a wide range of domains, including working memory (N-Back task), sustained attention (Rapid Serial Visual Response task) and executive control (Stroop task) in three subsequent test sessions (day 1, day 15, day 30) and in four separate groups (meditation, explicit reward, implicit reward, control). We hypothesized that explicit rewards, implicit rewards, and mindfulness meditation will each lead to improvements in all three tested cognitive domains. However, we expect rewards to produce more immediate improvements, especially in early sessions (days 1 and 15). Once a perceived reward threshold is reached or if the reward is deemed less attractive, attentional control may decline towards the end of the tested period. In contrast, the effects of mindfulness meditation are anticipated to be more gradual but sustained, showing relatively greater improvements by day 30.

2 Methods

This longitudinal study (i.e., day 1, day 15 and day 30) measured cognitive performance across three sessions and across a wide range of domains, including working memory (N-Back task), sustained attention (Rapid Serial Visual Response task) and executive control (Stroop task).

2.1 Participants

105 participants (70 females, 35 males, 0 non-binary; mean age of 21.9) participated in this study, spread across four groups: The meditation group included 40 participants (25 females, 15 males, mean age 22.3); the explicit reward group included 26 participants (14 females, 12 males, mean age 21.3); the implicit reward group included 24 participants (17 females, 7 males, mean age 22.4); the control group consisted of 15 participants (14 females, 1 male, mean age 21.6). The study was approved by the Research Ethics and Data Management Committee of the Tilburg School of Humanities and Digital Sciences (code REDC2024.80). All participants gave written informed consent before participation. Participants were recruited using the University's SONA system and received study credits as compensation.

2.2 Tasks

Participants were randomly assigned to one of four groups: control group, explicit reward group, implicit reward group, or meditation group. The meditation group was instructed to meditate for 15 minutes daily from day 1 to day 30 in a quiet space, focusing on breathing. This 15 minute meditation period was guided by a Youtube video and they did this at home. We recorded whether they clicked on these reminder links, but we did not record whether they actually watched the entire 15 minute meditation video to completion. The explicit reward group was told they would receive a reward at the end for their participation. We used pieces of candy as reward. The implicit reward group were told they had to try and perform well since they would be ranked for performance. They received the following instruction: "If you have been assigned to this group, you will be ranked based on performance, so you should try your best to perform well. The ranking will be sent after the study is over." They indeed received this ranking at the end of the study day. To determine the effectiveness of our mindfulness meditation manipulation, we also collected the following standardized surveys: the Mindful Attention Awareness Scale (MAAS) Score (Brown & Ryan, 2003) and the Perceived Stress Scale (PSS) (S. Cohen et al., 1983).

Thus, we used a 4 (Group: meditation, explicit reward, implicit reward, control) X 3 (Time: day 1, day 15, day 30) mixed longitudinal design.

2.2.1 N-back task

Participants performed a standard 2-back task (Kirchner, 1958) on day 1, day 15 and day 30 of the study. During this task, they were presented with a sequence of letters, displayed one at a time. For each letter, they were asked to determine whether this letter is the same as the letter presented two trials earlier. For example, in the sequence "H I H," a response (i.e., pressing the space-bar) should be made upon presentation of the second "H," as it matches the letter from two trials prior. They are instructed that they only need to respond for target trials, not for non-target trials. The task consisted of 40 trials (8 target and 32 non-targets), presented in random order, with each letter presented for 760 ms. Both accuracy scores and reaction times were recorded. There was no inter-trial interval.

2.2.2 Rapid Serial Visual Response task

Participants performed a standard Rapid Serial Visual Response (RVP) task (Flook et al., 2010; Gil-Gómez de Liaño et al., 2013; Moore et al., 2018) on day 1, day 15 and day 30 of the study. During this task, participants were presented with a rapid stream of letters and were asked to respond by pressing the space-bar when the target letter (i.e., "A") appeared. Both target detection accuracy and false alarms were recorded. The task consisted of 40 letters presented sequentially at 400 ms intervals, with 8 target letters randomly embedded among non-target letters. Each letter appeared on the screen for 400 ms. There was no inter-trial interval.

2.2.3 Stroop Task

Participants performed a standard Stroop task (Kiyonaga & Egner, 2014; Taylor & Barch, 2022) on day 1, day 15 and day 30 of the study. During this task, participants are required to identify the ink color of words, with congruent (e.g., "green" in green ink) and incongruent (e.g., "green" in blue ink) trials. They see one word at the time and were instructed to press the space-bar for congruent trials and do nothing for incongruent trials. Both reaction times and accuracy were recorded. Each participant completed 40 trials (30 incongruent, 10 congruent) presented in random order, with each stimulus displayed for 700 ms. There was no inter-trial interval.

2.2.4 MAAS

Participants completed the MAAS questionnaire on day 1, day 15 and day 30 of the study. The MAAS is a self-report survey questionnaire that assesses the ability to maintain attention and awareness in the present moment (Brown & Ryan, 2003; Carlson & Brown, 2005). Items are rated on a 6-point Likert scale (1 = almost always,6 = almost never), with higher scores indicating greater mindfulness.

2.2.5 PSS

Participants completed the PSS survey on day 1, day 15 and day 30 of the study. The PSS survey is a 10-item self-report questionnaire that measures the degree to which situations in one's life are appraised as stressful in the past month (S. Cohen et al., 1983). Each item is rated on a 5-point Likert scale (0 = never,4 = very often), with higher scores indicating greater perceived stress.

2.3 Procedure

First, participants provided informed consent before starting the study. Then they completed all three cognitive tasks and both surveys on each of the experimental days (i.e., 1, 15, 30). At day 1, they additionally answered the following questions: "Are you a student?", "Do you have any diagnosed attention deficit disorder?" and "Do you have any experience with mindfulness or meditation?" along with some demographic questions (i.e., age, sex). At the end of the final day of the experiment (i.e., day 30), participants were asked "Do you believe whether mindfulness meditation has a positive impact on cognition". The meditation group were sent daily reminders to meditate. All tasks and surveys were completed via Qualtrics.

2.4 Data analysis

We used repeated measures ANOVAs with Time (1, 15, 30) as within-subject factor, using statsmodels.stats.anova.AnovaRM, to evaluate changes in N-back, Stroop and RVP task performance across the three experimental days (separately for each of the four groups and separately for accuracy and for reaction times). When a repeated measures ANOVA showed a significant effect, we used post-hoc pairwise ttests with Bonferroni correction to further investigate the nature of the effect, using scipy.stats.ttest rel. We used an alpha level of 0.05 to determine significance.

The MAAS survey was analyzed by averaging across participant's responses on the 15 items of the survey. The PSS survey had 10 items. First, items 4, 5, 7 and 8 were reverse-scored as per standard in analyzing PSS survey scores. Subsequently, the scores were summed to determine one PSS score per participant per session.

Data pre-processing and analysis were implemented in Python (version 3.12.3; Python Software Foundation, 2024) in a Jupyter Notebook environment (Kluyver et al., 2016). We used several Python libraries, including pandas (McKinney, 2010) and NumPy (Harris et al., 2020) for data manipulation, statsmodels (Seabold & Perktold, 2010) for repeated measures ANOVA, and SciPy (Virtanen et al., 2020) for statistical testing. Multiple comparisons were corrected using the Bonferroni method with SciPy.

2.4.1 Participant inclusion

Reaction times could only be analyzed when participants indeed responded to the target trials (since they only needed to actively respond to target and not to non-target trials in either of the three tasks. To be conservative in our analysis, we only included participants in the final set of data analysis that indeed responded to all target trials of that task of each of the three days. This led to the following participant numbers being included for each of the four groups for each of the three tasks: • For the RVP task: In the control group, 9 participants were included.

In the explicit reward group, 15 participants were included. In the implicit reward group, 19 participants were included. In the meditation group, 31 participants were included.

• For the N-Back task: In the control group, 6 participants were included. In the explicit reward group, 14 participants were included. In the implicit reward group, 14 participants were included. In the meditation group, 26 participants were included.

• For the Stroop task: In the control group, 9 participants were included. In the explicit reward group, 24 participants were included In the implicit reward group, 19 participants were included. In the meditation group, 33 participants were included.

3 Results

3.1 Meditation group

Confirming our meditation manipulation, the meditation group showed a significant increase in MAAS score over time (significant effect of Time in a repeated-measures ANOVA; F(2, 78) = 3.579, p = 0.033, η² = 0.017). Mean MAAS scores increased from 3.40 (SD = 0.77) at Day 1 to 3.59 (SD = 0.74) at Day 15 and 3.64 (SD = 0.81) at Day 30. In contrast to our prediction, there was no significant decrease in perceived stress over the 30-day period as measured by the PSS (F(2, 78) = 1.366, p = 0.262).

3.1.1 Improved working memory following meditation

In the N-back task, the meditation group showed significant improvements in accuracy and hit rate over the 30-day period (Table 1). Our results revealed a significant increase in accuracy over time (main Time effect: F(2, 50) = 7.228, p = 0.002, η² = 0.132). Post-hoc pairwise comparisons with Bonferroni correction showed significant improvements from Day 1 to Day 15 (t = -3.070, p corrected = 0.015, d = 0.602) and from Day 1 to Day 30 (t = -3.815, p corrected = 0.002, d = 0.748), but no significant change from Day 15 to Day 30 (t = -0.517, p corrected = 1.000). Reaction times (RT) did not show a significant change over time (F(2, 50) = 0.333, p = 0.718, η² = 0.007) so the improvement in working memory performance in the mindfulness meditation group was solely focused on accuracy improvement. At the end of day 30, participants were asked whether they expected daily mindfulness meditation to have a positive impact on cognition. Mixed ANOVAs revealed a significant main effects of time for accuracy (F(2, 46) = 5.311, p = 0.008, η² p = 0.188), but no significant main effects of expectation and no significant time x expectation interactions for any metric (accuracy, RT). This indicates that while N-back performance improved significantly over time overall, expectation level did not moderate these changes.

3.1.2 Meditation improved speed at the cost of accuracy in the stroop Task

The meditation group showed significant changes in Stroop performance (Table 1). Participants in fact became less accurate in the Stroop task (F(2, 64) = 4.286, p = 0.018, η² = 0.058). Post-hoc pairwise comparisons with Bonferroni correction revealed a significant decline from Day 1 to Day 30 (t = 2.720, p corrected = 0.031, d = -0.474). Hit rate also showed a significant decline in performance over time (F(2, 64) = 3.634, p = 0.032, η² = 0.058, with a significant decline from Day 1 to Day 30 (t = 2.722, p corrected = 0.031, d = -0.474). Interestingly, participants did become significantly faster over time in responding in the Stroop task (significant Time effect: F(2, 64) = 21.311, p < 0.001, η² = 0.238). Post-hoc comparisons revealed significant RT improvements from Day 1 to Day 15 (t = 4.954, p corrected < 0.001, d = -0.862) and from Day 1 to Day 30 (t = 5.202, p corrected < 0.001, d = -0.906). This overall pattern of significantly faster RTs accompanied by significantly worse accuracy and hit rate suggests that the meditation intervention might have led to a speed-accuracy trade-off, suggesting that the meditation manipulation encouraged participants to prioritize speed over accuracy rather than improving overall executive control.

Similar to the N-back task results, Mixed ANOVAs revealed no significant time x expectation interactions for any metric, indicating that expectation level (i.e., "do you think that mindfulness has a position effect on cognition?") did not statistically moderate the changes in Stroop performance over time.

3.1.3 Meditation did not lead to improved RVP task performance

The meditation group showed no significant changes in performance in the RVP task over the 30-day period (Table 1). A repeated-measures ANOVA revealed no significant change in accuracy (F(2, 60) = 1.368, p = 0.262, η² = 0.026) or RT (F(2, 60) = 0.527, p = 0.593, η² = 0.013). Hit rate was at ceiling for all participants indicating the RVP task might have been too easy for participants to measure subtle changes in performance over time.

3.2 Control group did not show any changes

As expected, the control group did not show a significant effect of Time on MAAS scores (F(2, 28) = 0.191, p = 0.827, η² = 0.005), which revealed that, in contrast to the meditation group, their MAAS scores indeed remained relatively stable (from 4.02 to 3.95). There was also no significant decrease in perceived stress over the 30-day period as measured by the PSS (F(2, 28) = 0.947, p = 0.400, η² = 0.033).

As expected, neither of the three cognitive tasks revealed significant changes in the control group (Table 2). More specifically, no significant improvement in Stroop performance over the 30-day period, as evidenced by no significant main effect of time for accuracy (F(2, 16) = 0.553, p = 0.586, η² = 0.035) or RT (F(2, 16) = 0.371, p = 0.696, η² = 0.033). The control group showed no significant changes in RVP performance over the 30 day period, as evidenced by no significant main effect of time for accuracy (F(2, 16) = 3.171, p = 0.069, η² = 0.160) or for RT (F(2, 16) = 2.148, p = 0.149, η² = 0.159). The control group showed no significant improvements in Nback performance over the 30-day period, as evidenced by no significant main effect of time for accuracy (F(2, 10) = 0.221, p = 0.806, η² = 0.038) or RT (F(2, 10) = 0.015, p = 0.985, η² = 0.003). As expected, the explicit reward group did not show a significant effect of Time on MAAS scores (F(2, 50) = 0.008, p = 0.992, η² = 0.000), which revealed that, in contrast to the meditation group, their MAAS scores remained relatively stable (3.53-3.51).

There was also no significant decrease in perceived stress over the 30-day period as measured by the PSS (F(2, 46) = 0.526, p = 0.595, η² = 0.004).

For the N-back task (Table 3), the explicit reward group showed no significant changes in accuracy (F(2, 26) = 1.591, p = 0.223, η² = 0.068) or RT (F(2, 26) = 0.432, p = 0.654, η² = 0.022). Also the RVP task (Table 3) revealed no significant differences over time for accuracy (F(2, 28) = 0.893, p = 0.421, η² = 0.035) or RT (F(2, 28) = 1.005, p = 0.379, η² = 0.038) for the explicit reward group.

For the Stroop task (Table 3), accuracy decreased significantly over time (F(2, 46) = 5.643, p = 0.006, η² = 0.127). Post-hoc pairwise comparisons with Bonferroni correction revealed significant declines from Day 1 to Day 15 (t = 3.308, p corrected = 0.009, d = -0.675) and from Day 1 to Day 30 (t = 3.147, p corrected = 0.014, d = -0.642), but no significant change from Day 15 to Day 30 (t = -0.205, p corrected = 1.000). Additionally, participants became faster (F(2, 46) = 13.517, p ¡ 0.001, η² = 0.208). Post-hoc comparisons revealed significant RT improvements from Day 1 to Day 15 (t = 3.940, p corrected = 0.002, d = -0.804) and from Day 1 to Day 30 (t = 4.272, p corrected = 0.001, d = -0.872). The pattern of significantly faster RTs accompanied by significantly worse accuracy is consistent with a speed-accuracy trade-off, suggesting that the explicit reward manipulation, similar to the meditation manipulation, encouraged participants to prioritize speed over accuracy rather than improving overall executive control.

3.4 Implicit reward did not lead to changes in cognitive performance

As expected, the implicit reward group did not show a significant effect of Time on MAAS scores (F(2, 46) = 0.041, p = 0.960, η² = 0.001), which revealed that, in contrast to the meditation group, their MAAS scores remained relatively stable (3.

62-3.65).

There was also no significant decrease in perceived stress over the 30-day period as measured by the PSS (F(2, 46) = 0.149, p = 0.862). The implicit reward group showed no significant changes in N-back performance over time (Table 4). There was no significant main effect of time for accuracy (F(2, 26) = 0.717, p = 0.498, η² = 0.031) or RT (F(2, 26) = 1.074, p = 0.356, η² = 0.043). Moreover, the implicit reward group showed no significant changes in Stroop performance over time (Table 4). Repeated-measures ANOVAs revealed no significant effect of time for accuracy (F(2, 36) = 1.815, p = 0.178, η² = 0.066) or RT (F(2, 36) = 1.263, p = 0.295, η² = 0.033).

The implicit reward group showed a significant improvement in RT over time in the RVP task (F(2, 36) = 3.750, p = 0.033, η² = 0.135; Table 4), but no significant change in accuracy (F(2, 36) = 0.902, p = 0.415, η² = 0.028). Post-hoc pairwise comparisons with Bonferroni correction showed a significant RT improvement from Day 1 to Day 15 (t = 3.155, p corrected = 0.016, d = -0.724), but not from Day 15 to Day 30 (t = 1.003, p corrected = 0.987) or from Day 1 to Day 30 (t = 1.898, p corrected = 0.221).

4 Discussion

This study investigated how mindfulness meditation, explicit rewards, and implicit rewards influence attention, executive control, and working memory. Consistent with the hypothesis that mindfulness meditation enhances cognitive performance, the meditation group demonstrated significant improvements in working memory. However, contrary to predictions, meditation did not improve executive control or sustained attention. Rather, it showed declined accuracy along with faster reaction times for executive control, aligning with interpretations of speed-accuracy trade-offs rather than genuine task improvement. With regards to reward strategies, neither explicit nor implicit rewards produced the predicted short-term attention and motivation benefits. Explicit reward showed faster reaction times at the cost of significantly reduced accuracy in executive control, similar to meditation, representing a speed-accuracy trade-off rather than genuine cognitive improvement.

The meditation group showed a significant improvement in working memory demonstrated using an N-Back task, which is consistent with earlier studies (Basso et al., 2019; Zeidan et al., 2010). Interestingly, it is consistent with some meta-analysis (Moradi et al., 2025; Verhaeghen, 2020), but contrasts with other meta-analysis that reported no clear working memory benefits from meditation (Yakobi et al., 2021). The discrepancy across these meta-analysis may stem from differences in intervention duration (15 minutes daily for 30 days in the current study versus shorter or less frequent protocols in studies included in the meta-analysis of Yakobi et al., 2021) or task parameters (2-back versus higher cognitive loads). Our findings suggest that consistent daily practice over an extended period may be sufficient to yield working memory improvements even when total daily meditation practice is brief. Whether or not participants expected meditation to benefit their cognitive performance did not statistically moderate any outcomes. This indicates that the observed cognitive improvements cannot be easily attributed to expectancy or placebo effects, strengthening the interpretation that meditation produced genuine working memory improvement.

Unlike meditation, neither explicit nor implicit rewards produced the predicted immediate working memory improvements. This contradicts other empirical studies (Wang et al., 2024; Xu et al., 2022; Zedelius et al., 2012) that did find improved working memory performance due to explicit rewards, in particular under high cognitive load. One explanation for this discrepancy concerns the nature of the reward manipulation. Prior studies (Xu et al., 2022; Zedelius et al., 2012) used monetary incentives with substantial perceived value, whereas the current study used candy (explicit) and performance rankings (implicit). It is possible that these rewards lacked sufficient motivational salience to drive the strategic cognitive engagement observed in previous research. Additionally, explicit rewards facilitate proactive control when individuals consciously anticipate and prepare for reward-driven goals (Pessoa, 2014). The absence of such effects here may reflect that participants did not perceive the rewards as sufficiently valuable to justify the cognitive effort required to improve.

Contrary to predictions, meditation did not enhance executive control as measured by the Stroop task, nor did it improve sustained attention on the RVP task. This diverges from earlier work suggesting that meditation (both focused attention and open monitoring) boost executive control (Ainsworth et al., 2013; Zeidan et al., 2010). However, some later meta-analysis did not find significant effects of meditation on attention (Sumantry & Stewart, 2021). Our findings align with van den Hurk et al., 2010, who discovered that meditation selectively improved the orienting network of attention (i.e., shifting focus) rather than executive control. The Stroop task primarily measures executive control and conflict monitoring and inhibition which are processes that may be less sensitive to focused attention meditation than orienting-based measures. It is also possible that 30 days of daily 15-minute practice was insufficient to produce detectable changes in executive control, particularly given that participants were students (a population that may already possess relatively high baseline executive control, limiting room for improvement).

Moreover, a striking finding across both the meditation and explicit reward groups on the Stroop task was the presence of a speed-accuracy trade-off: reaction times improved significantly, but at the same time accuracy declined significantly. This pattern indicates that participants prioritized speed over accuracy rather than achieving genuine cognitive improvement. Interestingly, this trade-off was absent in the N-back task for the meditation group, where accuracy improved while reaction times remained stable. This dissociation suggests that meditation's benefits may be task-specific, meaning, working memory tasks requiring maintained representation and manipulation may benefit from meditation practice, whereas executive control tasks requiring rapid conflict resolution may induce strategic shifts toward speed at the expense of accuracy.

The differences we found between explicit and implicit rewards can perhaps be explained with earlier work (Bijleveld et al., 2011) that found that implicit (subliminal) rewards enhanced performance on the attentional blink task, while explicit rewards impaired performance due to over-focused attention. Our findings partially align with this pattern: explicit rewards produced a significant accuracy decline on the Stroop and RVP tasks, while implicit rewards produced only isolated reaction time improvements and no accuracy benefits. However, unlike Bijleveld et al., 2011, implicit rewards did not outperform explicit rewards in any condition, and neither reward type produced the automatic attentional benefits reported in their study. The absence of subliminal reward presentation in the current design (implicit rewards were rankings revealed post-task, not subliminal stimuli) may explain this discrepancy, as the automatic mechanisms may require truly unconscious reward cues (Pessoa, 2014).

Contrary to some earlier work who showed that meditation reduced perceived stress (Venkatesan et al., 2020), our meditation group showed no significant reduction in PSS scores. However, this null finding aligns with other studies reporting that mindfulness meditation increases MAAS scores without directly reducing PSS (Goldstein et al., 2018). Stress reduction may be mediated by increased self-efficacy in mindfulness skills. The current study did not measure mindfulness self-efficacy, which may explain why MAAS scores improved but perceived stress remained unchanged. Additionally, the 30-day time-frame may be insufficient for stress reduction to manifest. The meditation group showed a modest but significant increase in MAAS scores over time, consistent with the intended effect of the intervention. This confirms that daily 15-minute focused attention meditation is sufficient to increase trait mindfulness, even if stress reduction and executive control benefits lag behind or require additional mediators.

4.1 Conclusion

Our prediction that cognitive improvement due to reward are immediate motivationaldriven benefits that would be present in early sessions and cognitive improvement due to meditation would be gradual and henceforth in later sessions is not supported. Rather, meditation gradually improved working memory but did not affect sustained attention or executive control. Explicit and implicit reward did not affect working memory at all. Both explicit reward and meditation led to improvements in speed in executive control but did so at the cost of reduced accuracy. These findings highlight that different strategies engage distinct mechanisms. Meditation may enhance working memory, perhaps through improved attentional stability and reduced mindwandering, though this interpretation would need future work to empirically test directly. Rewards, at least when possibly relatively low in motivational salience, may primarily influence response strategies rather than core cognitive processes. The current study directly compared these interventions within a single design. This revealed important similarities; both meditation and rewards can alter response patterns. It also revealed critical differences; only meditation produced accuracy improvements without a speed-accuracy trade-off, and this benefit was specific to working memory. Contrary to prior claims that brief meditation broadly enhances executive control and sustained attention (Zeidan et al., 2010), the current results align with more metaanalytic findings (Verhaeghen, 2020; Yakobi et al., 2021) suggesting that working memory may be particularly sensitive to meditation training, while executive functions require longer or more intensive practice. Similarly, reward-based cognitive improvements may depend critically on motivational salience, as the null and trade-off findings here diverge from studies using monetary incentives. Nevertheless, these findings suggest that daily mindfulness meditation is a promising, scalable intervention for working memory enhancement, even when practiced briefly (15 minutes daily) over 30 days.
