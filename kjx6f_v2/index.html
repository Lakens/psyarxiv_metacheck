Meta-scientific research has shown nonsignificant p values are commonly misinterpreted. It is incorrect to infer that there is ‘no effect’, ‘no difference’, or that groups are ‘the same’ after p > 0.05.

It is possible that there is a true non-zero effect, but that the study did not detect it. Make sure your inference acknowledges that it is possible that there is a non-zero effect. It is correct to include the effect is ‘not significantly’ different, although this just restates that p > 0.05.

How Power Analysis Check works

This module uses regular expressions to identify sentences that contain a statistical power analysis. If specified by the user, it also uses a large language model (LLM) to extract information reported in power analyses, including the statistical test, sample size, alpha level, desired level of power, and magnitude and type of effect size.

The Power Analysis Check module uses regular expressions to identify sentences that contain a statistical power analysis. Without the use of an LLM, the module uses regular expressions to classify the power analysis as a-priori, sensitivity or post-hoc. With the use of an LLM, it checks if the power analysis is reported with all required information.

The regular expressions can miss power analyses, or fail to classify them correctly. The type of power analysis is often difficult to classify, which can easily be solved by explicitly specifying the type of power analysis as ‘a-priori’, ‘sensitivity’, or ‘post-hoc’. Note that ‘post-hoc’ or ‘observed’ power is rarely useful. The LLM can fail to identify information in the paper, and will not have access to information in paragraphs in the paper other than those that contain the word ‘power’. This package was validated by the Metacheck team on articles in Psychological Science.

This module was developed by Lisa DeBruine, Daniel Lakens and Cristian Mesquida

How Preregistration Check works

Retrieve information from preregistrations in a standardised way, and make them easier to check.

The Preregistration Check module identifies preregistrations on the OSF and AsPredicted based on links in the manuscript, retrieves the preregistration text, and organizes the information into a template. The module retrieves text from the OSF with its API, and from AsPredicted with ResearchBox’s API when a ResearchBox key is set (see rbox_token()), or else from the preregistration’s web page. How StatCheck works

Check consistency of p-values and test statistics

The Statcheck module runs Statcheck. Statcheck searches for regular expressions that match a predefined pattern, and identifies APA reported statistical tests. More information on the package can be found at https://github.com/cran/statcheck. The module only returns Statcheck results for t-tests and F-tests, as these are the only tests which have been validated, see https://osf.io/preprints/psyarxiv/tcxaj_v1/.

Statcheck was developed by Michèle Nuijten and Sascha Epskamp.

Statcheck considers p = 0.000 an error, as you should report p < 0.001. Furthermore, p < 0.03 is an error if the p-value was 0.031, and one should simply report exact p-values (p = 0.031). When the sentence of a test says it is one-sided (“one-tailed”, “one-sided” or “directional”), a p-value that fits a one-sided test counts as consistent (statcheck’s OneTailedTxt setting; #695). When the paper says anywhere that its tests are one-sided, a p-value that fits a one-sided test in either direction counts as consistent too: half the two-sided p, or 1 minus that half for an effect against the predicted direction. Equivalence tests (TOST) are left out, as their p-values do not test the difference. A statistic written with “<” or “>” is read as a bound, and in a sentence about equal variances an F-test’s two-sided p (twice the one-tailed p) counts as consistent. For more information, see StatCheck.

This module only checks statistical results reported in the running text of the manuscript. It cannot (yet) process statistics reported only in tables.

This module was developed by Daniel Lakens and Lisa DeBruine

Read more in the metacheck manual.

Therefore 0% of true instances were missed, and 43% of detections were false positives. See https://osf.io/preprints/psyarxiv/tcxaj_v1/ for more details of the validation.

How Exact P-Values works

List any p-values reported with insufficient precision (e.g., p < .05 or p = n.s.), reported as exactly zero (e.g., p = .000), or impossible (below 0 or above 1, e.g., p = -.22).

This module uses regular expressions to identify p-values. It will flag any values reported as p > ? or p < numbers greater than .001. It will also flag p-values reported as exactly zero (e.g., p = .000, p = 0.00), which are mathematically impossible — p-values are never exactly zero and should instead be reported as p < .001.

A p-value that is not the result of a test is not flagged: a table note (“* p < .05, ** p < .01”), a figure legend (“Asterisks indicate significant differences (p < .05)”, “Values in bold are significant at p < .05”) or a stated threshold (“p < .05 was considered significant”, “thresholded at p < .001”). GROBID often puts such notes into the running text, so each p-value is judged by the words in its own clause (the text up to a “;” or a full stop), and never left out when a test statistic belongs to it (“F(1, 7) = 8.03, # p < .05”). The column not_a_test of the table says why a p-value was left out (“marker”, “threshold”, “legend” or “named”).

A p-value with the name of a correction or a test after the p (“pFWE < .05”, “padj < 0.05”, “p Wilcoxon = .02”) is flagged only when a test statistic comes before it in its clause (“t(37) = 7.17, p FWE < .05”). Without one it is mostly the rule that decided what was significant (“genes with padj < 0.05 were selected”); such a p-value is “named” in not_a_test. Notes in other forms, such as a marker after the p-value (“p < .05 (*)“), are still flagged.

A p-value below 0 or above 1 is impossible; it is listed apart and not also as imprecise. Often the statistic before it, or its minus sign, was copied into it (“t(134) = -2.32, p = -.13”, “Z = 3.091, P = 3.091”). A value above 1 is listed only after a test statistic in its clause: without one, a “P” above 1 was nearly always another quantity (a proportion, pH, a group’s mean, a model parameter). A number in scientific notation whose power of ten was lost when the PDF was read (“p = 2.4 x 10 -9” read as 2.4) is not listed. A “p” that is the subscript of another symbol (“r p = .64”, “²p = .02” for partial eta squared, “Δp = .33”), or a quantity with a unit, a logarithm or a ratio (“P = 2.9 µm”, “-log10 P = 7.5”, “Ca/P = 1.67”), is not read as a p-value at all (see extract_p_values()). Each p-value has its own row, also when the same one is written twice in a sentence.

This module sometimes flags false positives when sentences discuss how p-value thresholds were set. It can also miss an imprecise p-value that is reported against a threshold (“decreased at the p < .05 significance threshold”).

This module only checks p-values reported in the running text of the manuscript. It cannot (yet) process p-values reported only in tables (as opposed to a table’s footnote text, which the module does see and tries to exclude — see above).

How Repository Check works

This module retrieves information from repositories.

The Repository Check module lists files on the OSF, GitHub, ResearchBox, DSpace (PsychArchives and other legacy- and DSpace 7-based installations), Zenodo, Dataverse, Figshare, Dryad, ReShare, 4TU.ResearchData, Mendeley Data, DataONE (Arctic Data Center, KNB, and other member nodes), and LDbase based on links in the manuscript.

A link to a file-sharing service (Google Drive, Dropbox, OneDrive, Box, WeTransfer, MEGA, iCloud Drive, Baidu Netdisk, SURFdrive; see [file_share_links()]) gets a warning and makes the light yellow: such services are not repositories, as files can be changed or deleted at any time, get no DOI, and the link stops working when the account is closed. The report advises a stable repository such as Zenodo instead. Their files are not read, and summary_table$file_share_n counts the links.

Deposits in archives for sequence and expression data (GEO, the INSDC archives BioProject, SRA, ENA and DDBJ, and ArrayExpress; see [seq_archive_links()]), mostly named by accession number, are read for whose deposit they are. The authors’ own are listed with what they hold ([seq_archive_size()]) and are not downloaded or checked as data and code; summary_table$archive_own_n counts them.

R packages on CRAN ([cran_links()], [cran_info()]) are the paper’s own when a paper author is a package author and the paper presents the package; the paper’s own are listed with their version and not checked (summary_table$cran_own_n). A Handle link (hdl.handle.net/...) that leads to a repository read here is checked as a link to that repository ([handle_links()]).

Listing a repository’s files never requires an API key, but some hosts answer faster or more completely with one: OSF allows 100 requests/hour unauthenticated versus 10,000/day with a token (see [osf_pat()]), and Dryad enforces a strict per-IP daily quota on repeated listing (see cache below). Dryad is a special case beyond rate limits: listing a Dryad dataset’s files works without a key, but actually downloading file CONTENTS from Dryad fails with HTTP 401 unless a key is set, even for a fully public dataset (see [dryad_pat()] or [dryad_auth()]). Since this module only lists files and never downloads their contents itself, that limitation applies to data_check and code_check (which do download content), not here – see their own documentation.

When a linked OSF page is a registration, its registered_from project (the one it was registered from, which the manuscript itself may never link directly) is also checked: if that project is public its files are listed under its own URL, and if it is closed or otherwise inaccessible the report flags it explicitly, since some registrations only describe their content rather than mirroring it.

Whose deposit is each link? The ownership table gives, for every repository linked in the text and (with references = TRUE) every deposit cited in the reference list, one of six labels: own_this (made by the authors for this paper), own_earlier_data or own_earlier_code (the authors’ own, from earlier work), others_data or others_code (made by other people, reused here), or not_data (a publication such as a preprint, not a deposit), with ownership_group (“own”, “others”, “not_data”) and the reason. It is decided without a language model, from the sentence or reference that cites the link, the paper’s authors (names, ORCID iDs, affiliations), and what the deposit’s own record and files say (who made it, what it names, when, whether it is a software package; for an OSF project cited only in the reference list, its record alone). On a round of labelled links the rules had not been written from, the three groups were right for 98% of links in the main text (93 of 95) and 90% in reference lists (74 of 82); the labels were made by Claude agents from each link’s evidence, and disputed ones checked against the deposits. Telling this paper’s own deposit from the authors’ earlier one is less certain.

Only the deposits that are this paper’s own are checked. A deposit linked in the text that holds other people’s work (others_data, others_code) or the authors’ earlier work (own_earlier_data, own_earlier_code) is listed in the report, with the reason, but its files are left out of table and kept in table_not_checked: they count toward nothing here (files that do not belong in a repository, naming, READMEs, studies, the traffic light), and code_check, data_check and reproducibility_check, which read table, do not check them either. reproducibility_check still puts the files of theirs that the paper’s code names in the folder the code runs in, as a re-analysis needs the data it re-analyses. When every linked deposit is set aside, the traffic light is “na”. A deposit that is the paper’s own is counted as such when its README, title or description names the paper (its title or DOI).

How Code Check works

This module retrieves information from repositories checked by repo_check about code files (R, Python, SAS, SPSS, Stata, Mplus, MATLAB).

The Code Check module checks R (also R Markdown and Quarto), Python (also Jupyter notebooks), SAS, SPSS, Stata, Mplus, and MATLAB files, using regular expressions to check the code; JASP files are listed but not read. The language of a Quarto document or a notebook is read from the file itself (its engine or kernel), not from its extension. The regular expression search will detect the number of comments, the lines at which libraries/imports are loaded, attempts to detect absolute paths to files, setwd() and install.packages() calls, and lists files that are loaded, and checks if these files are in the repository; R code is also parsed. The module will return suggestions to improve the code if there are no comments, if libraries/imports are loaded in lines further than 4 lines apart, if files that are loaded are not in the repository, if absolute file paths, setwd() or install.packages() are found, and if R code cannot be parsed.

The regular expressions can miss information in code files, or falsely detect parts of the code as a fixed file path. Libraries/imports might be loaded in one block, even if there are more than 3 intermittent lines. The module was tried out internally on papers published in Psychological Science, but has not been formally validated. There might be valid reasons why some loaded files can’t be shared, but the module can’t evaluate these reasons, and always gives a warning.

The module also checks whether the repository pins the R/package versions the analysis actually depended on: an renv.lock file (parsed for the R version and every locked package + its version/source), a sessionInfo()/sessioninfo::session_info() text dump (matched by filename — sessionInfo.txt/session_info.txt and similar, or embedded in a README), or a groundhog::groundhog.library()/checkpoint::checkpoint() date-pin call in the code (a bare library(groundhog)/library(checkpoint) does not count — the pinning call itself must be present). When none of these is found, the report flags it as a reproducibility gap: package versions may drift between when the analysis was run and any later reproduction attempt.

If you want to extend the package to perform additional checks on code files, or make the checks work on other types of code files, reach out to the Metacheck development team.

Checking code requires downloading its file contents. For a paper whose repository is on Dryad, this never succeeds unless a Dryad API key is set: Dryad requires one to download file bytes, even from a fully public dataset (listing the repository’s files does not need one). Without a key, every Dryad-hosted code file is listed but unchecked, and a warning naming Dryad and ?dryad_pat/?dryad_auth is included among the download failures recorded in the manifest.

How Data Check works

This module classifies the files in a repository into semantic types (data, codebook, code, software, output, supplemental, readme, asset, other) and, for tabular data files, extracts each column’s type and summary statistics.

The Data Check module consumes the file list produced by repo_check (or any files added via local_path). Each file is classified with rule-based heuristics layered over metacheck’s file_category() and file_types: file names matching README / codebook patterns win first, then an extension crosswalk, then format-locked extension overrides. For every file classified as tabular data that is available locally, the module reads the file head, describes each column with data_col_facets() and computes summary statistics for numeric columns. Every sheet of a spreadsheet that holds a table is read: a file with several such sheets has its columns under source_file = "file.xlsx [sheet]", and the sheet column names the sheet of any spreadsheet with several sheets; a sheet of notes or a codebook is treated as documentation when the file has another table. Following DDI, a column is described by orthogonal facets rather than a single type: representation (numeric/text/datetime/code — how it is stored), measurement_level (Stevens: nominal/ordinal/interval/ratio), concept (what it measures: reaction_time/age/gender/likert/id/…), role (identifier/measure/condition/timestamp), unit, and a quality state (ok/empty/constant). Concepts are detected by name+value rules (the demographic concepts via data_check_demographic()); when llm_use(TRUE) the model fills concepts and measurement levels the rules left blank. Qualtrics survey exports are recognised (data_check_is_qualtrics()): their extra header rows are stripped so columns type correctly, and the reserved response-metadata columns (StartDate, Duration, Finished, …) are tagged.

The module defaults to rules-only when llm_use(FALSE): columns the rules cannot resolve (ambiguous 3–20-unique integers, ambiguous character columns) fall back to continuous / text respectively. When llm_use(TRUE), ambiguous columns and unresolved file types (other) are sent to llm() for optional refinement, and every file is assigned a study group (ex1, pilot2, shared, …) so that multi-study repositories can be recognised (used by psychds_check). Without an LLM the study group is left NA (unknown).

Column extraction requires files to be readable from disk. Files fetched by repo_check from OSF/GitHub/etc. without a local copy (file_location is NA) are classified but not column-extracted; pass local_path to point at a downloaded copy of the repository.

For a paper whose repository is on Dryad, this means column extraction never happens unless a Dryad API key is set: Dryad requires one to download file bytes, even from a fully public dataset (dataset listing and metadata do not need one). Without a key, every Dryad file stays classified but un-downloaded, column_n is 0, and a warning naming Dryad and ?dryad_pat/?dryad_auth is included among the download failures. A one-time session message is also shown (see repo_check) the first time a Dryad dataset is encountered with no key set.

Every downloaded text file the authors wrote (code, settings, survey definitions such as Qualtrics .qsf files, documentation, outputs) is searched for keys: API keys, access tokens and private keys, which let anyone who downloads the file use a paid service at the authors’ cost. Of a tabular data file only the column names and first 3 rows of the table as read are searched: its values come from participants, but a key the authors set for a whole survey (as embedded data in a Qualtrics survey flow) is exported in every response. The search uses the rules of the secret scanner betterleaks (https://github.com/betterleaks/betterleaks, MIT licence) of high and medium confidence. A key found turns the traffic light red; the report and the keys table give its file, line and type, and only its beginning. Other files over 25 MB and binary files are not searched. A key is never tested with its provider. Every module’s result has any whole key replaced by “keyremoved” (see module_run()).

How Reproducibility Check works

This module assesses whether a paper’s R and Python code can be run on its data. It works in two phases. The static phase (always run) collects the package dependencies the code declares, rewrites the data-file paths that do not work in the repository as the authors organised it, works out the order the scripts must run in, and diagnoses why any referenced input file is unavailable — reporting what a reproduction attempt would involve and where it is likely to break. The execution phase (opt-in, execute = TRUE) then actually runs the code: it copies the repository into a throwaway directory, optionally installs the declared dependencies into a throwaway library, runs each script in order in an isolated subprocess with a per-script timeout, and captures the outcome and full output of each run.

By default (execute = FALSE) the module does not run any code — it performs only static analysis: reading dependencies with the same extractors as code_check, finding the files the code references in the repository, and building a run-order dependency graph. It reports what would be installed and run rather than doing it.

When execute = TRUE, the module additionally runs the downloaded code on your machine — a deliberate, opt-in action gated behind that argument (callr is required for R code). Each script runs in an isolated subprocess so a crash cannot take down the R session; note this isolates crashes, not the filesystem or network. Installs (when install_missing = TRUE) and the throwaway run library never touch your main R library. Each script’s outcome is one of ran_ok, errored, timed_out, dependency_unavailable, not_parsed, run_by_source (an R script another script runs with source(), which is run only inside that script, since on its own it lacks the packages and objects the sourcing script sets up first), run_by_import (a Python file other files import, a module rather than a script, unless it has an if __name__ == "__main__": block), jags_model (a JAGS or BUGS model saved with an R extension, which another script reads) or not_r_content (a file that is not R at all, such as a JSON or HTML dump); these last two are not run and are not failures. python2 marks Python 2 code that was not run. With sandbox = "docker" such code runs with Python 2.7 (option metacheck.docker_image_py2; FALSE turns this off), which modifications records; it is never converted, since that can change results. defines_functions is a file that only defines functions, which is used, not run (table$used_by names the scripts that use it), and not_analysis is a file of software rather than of the analysis: a package’s code, tests, documentation or setup.py, a copy of a tool, a web application, a script a program wrote (table$not_analysis_why says which); neither is run or counted as a script. docker_failed means the container never started, which says nothing about the script, so it keeps the light from being green but does not make it red. needs_a_person is a script that stopped because it asks a person to choose a file or answer a question, or that starts an app, and needs_internet one that stopped because the network is off in a Docker run, or, with internet = TRUE, could not reach what it asked for; download_too_large is a script stopped for downloading more than the limits allow (see internet), and out_of_memory one that, or a program it started (such as a compiler), ran out of the memory each script may use. All four are treated the same way. not_downloaded is a script that stopped on a file the repository lists but that was not downloaded, such as one over max_file_size: it could not be tried, so it is not counted as a script that did not reproduce (summary_table$repro_not_downloaded_n counts them apart). not_read is a file metacheck could not read, so it was not run; the light is then not green, as the file may read and run on another computer, and table$error_message says why, naming a package that is installed but cannot be loaded on the computer that ran the check. empty is a file with nothing in it, which is not run or counted as a script. For a script that did not run through, table$error_message is its error, short (at most 300 characters): the error line of its output, which names a package that is not there, with the address it asked for when it needed the internet, or the time limit it reached; table$reason sorts it into a kind. A timeout means “still running at the cutoff”, not a failure, so raise timeout for legitimately long-running (e.g. Bayesian) scripts. dependency_unavailable means the script’s own package could not be installed from live CRAN, the CRAN Archive, or a named GitHub/URL source — an infrastructure limitation, not a defect in the paper’s code. The full stdout/stderr of every run is kept in the result’s run_results (the report shows it in per-script dropdowns, capped for readability).

Provenance, kept so that a TRACE Research Object (TRO) declaration of the run can be written later from a stored result (metacheck #404; the helpers are in R/provenance.R). Only when code was run (execute = TRUE): * run_results$started_at, run_results$ended_at: when each run of a script started and ended (ISO 8601, UTC, milliseconds); NA for a script that was not started. A script run again in a later pass has the times of its last run. A TRO uses them for each trov:TransparentResearchPerformance. * run_results$exit_status: the exit status of the process that ran the script (0 = ended normally); NA when the process did not report one (a time limit, or Docker failing to start the container). * artifacts: one row per file, with stage (deposit: as downloaded from the repository, hashed from the downloaded file; before_run: the run folder just before the first script ran, after metacheck’s own changes, such as rewritten paths and unpacked archives; after_run: only the files the scripts made (status new), changed (changed) or removed (removed), as an unchanged file is the one listed before the run), path (relative to the run folder, as valid UTF-8, a byte of another encoding written as <xx>), size (bytes), sha256, mime_type (by extension, NA when unknown), source (the file’s address in the repository, for deposit). The package libraries metacheck installs in the run folder are left out, as are metacheck’s own files there (a script’s runner, and the statistical output it writes in statistical_output/). Files metacheck itself copied or made between passes (see modifications, output_copied, file_placed) show in after_run too. A TRO uses the rows as trov:ResearchArtifacts and each stage as a trov:ArtifactArrangement. * modifications$sha256_before, modifications$sha256_after: the hash of the changed script as downloaded and as it ran; NA when the script is not at the same path in both (a script made from an R Markdown file). * environment: the system that ran the code (trov:TransparentResearchSystem in a TRO): metacheck_version, started_at, ended_at, host (R version, platform, operating system), sandbox, network_isolated (TRUE only when every Docker run had --network none; the process sandbox does not stop the network), internet, timeout_per_script, total_timeout, python_local (the Python run outside Docker and its version), and docker: runs (for each kind of run, r_run, r_install, python_run, python_install, the image and the docker run arguments, such as --network none, --read-only, --cap-drop ALL, no-new-privileges, the process limit and the memory and processor limits) and images (for each image, its ID and digests from docker image inspect, its creation time and the R and Python versions its environment declares).

run_results$checked says what the run of each script shows about the code, in five groups, so that a script that does not reproduce is kept apart from one the check could not test: ran (it ran to the end); code_error (it did not reproduce: it stopped with an error of the code or the deposit, could not be read, or needs a file the deposit does not hold); dependency (a package or program was not available: a package that could not be installed or was not loaded, a program outside R and Python, a system library, or R crashing in a package’s compiled code); time (it did not finish within the time limit for one script, or was not started because the time for all scripts had run out); and not_checkable (it could not be checked automatically: it needs a person, the internet, a key or another setting of the authors’ computer, one platform such as Google Colab, Windows or OpenSAFELY, more memory than the run allows, a file that was not downloaded, a screen, or a program that runs it, or it is a file of a package of the code that Python runs only as a module of that package). It is NA for files run inside another script, files that are not an analysis, files not read, and a Docker failure. summary_table counts each group (repro_ran_n, repro_code_error_n, repro_dependency_n, repro_time_n, repro_not_checkable_n), and the report’s first sentence gives them. The traffic light reflects the static readiness signals by default; a script in code_error that stopped with an error makes it red, as a script that crashes on its own analysis is a genuine reproduction failure, and a script in one of the other three groups keeps it from being green. Calls that need a screen, which the run does not have (dev.print(), dev.copy2pdf(), dev.copy2eps(), savePlot(), windows(), win.graph(), x11(), quartz(), View()), are replaced before the run by calls that need none, which modifications records as screen_call_replaced. A script that fails with could not find function is run once more with the library() calls the project’s other scripts make added at its top (or the one package that exports the function, or magrittr for %>%), and a script that then runs is reported as reproducible only after that repair.

Dependencies are reported name-only, with the source (CRAN, GitHub, or a base package already shipped with R) — static analysis of the code cannot know which version was used, and running against current package versions is itself informative: a break argues the authors should have pinned versions. When the repository does record versions, a run with recorded_versions = TRUE installs the packages the scripts load at those versions, but it does not change the R version, which remains a limitation of the check.

Run order is derived from read-after-write data dependencies (a script writing a file another reads must run first), source() edges, and numeric filename prefixes as a weak tie-breaker. Ambiguous orderings, dependency cycles, and inputs a script reads but that no earlier script produces (and that are not in the repository) are surfaced as warnings, since these are the situations most likely to make an otherwise-correct reproduction fail.

Abstract

Does the way we picture our ideal life reveal what we value, who we are, and how we thrive? In a preregistered study (N = 273), we tested whether free-form descriptions (median 109 words) and seven-keyword lists of one's ideal life predict a broad battery of psychological constructs: the Big Five, the ten Schwartz values, social dominance, political orientation, meaning in life, and subjective well-being. Using regularized linear probes on embeddings from transformer large language models (LLMs), inspired by model-interpretability research, we find that ideal-life narratives predict most constructs above chance in both conditions (mean r = 0.24 for free-form, mean r = 0.12 for keywords). This free-form advantage was concentrated on constructs people rarely name outright, such as achievement, benevolence, conformity, and emotional stability, implying that part of the signal lies in the manner of the telling rather than in the referents alone. Nineteen of the 24 constructs were recovered from roughly 120 words of text, a far broader battery than earlier language-based work, which has relied on much longer samples and focused on personality and well-being. Our approach offers an open, privacypreserving alternative to zero-shot commercial LLMs, with comparable accuracy, no API cost, and freely released data and code.

Introduction

What is the link between what we consider an ideal life, personality and value?

What kind of ideal life should we strive for? It's an old question, and the ancient and Hellenistic schools of philosophy offer perhaps one of the broadest varieties of answers to it, reflecting the richness of human life.

Hedonistic accounts place pleasure at the center of the good life. Epicurus, for instance, taught a simple life among friends, seeking pleasure and the absence of pain by satisfying only some desires: the natural and necessary (e.g., friendship, hunger, and thirst), while limiting those that are natural but non necessary (luxury, sex), or outright vain (fame, wealth). Cyrenaics advocated a more radical hedonistic approach, claiming that what really matters is experiencing bodily pleasure (e.g., having sex, eating a good meal, or drinking wine).

Other traditions shifted the focus away from pleasure entirely. Aristotle taught that the ideal life is one of virtue, cultivated through habits that shape us into good people. The Stoics went further, holding that virtue and moral character in accordance with nature are the only true goods. They advocated focusing on what depends on us, our virtues, behaviors, and reactions to life events, rather than on what does not, such as our bodies, external events, wealth, or reputation.

The Cynics went further still, embracing an almost "punk" ascetism: they rejected material attachments and social convention alike, and were known for shocking others, walking barefoot, sleeping in public spaces, and haranguing the rich and powerful to abandon their possessions and vain desires.

These philosophical traditions do not merely teach ideals, they reflect genuine individual differences in the values underlying one's conception of the good life, and what the ideal life one should strive for is. Some individuals embrace pleasure while others reject it, some accept external goods as part of flourishing while others see them as obstacles, and some integrate social conformity and tradition while others call for their complete rejection. A useful empirical framework for capturing these differences is Schwartz's theory of basic human values (S. H. Schwartz, 1992; Nazirova & Borbala, 2024), which identifies ten motivationally distinct values organized along two bipolar dimensions (see Figure 1): (adapted from S. H. Schwartz, 2012)

Schwartz's framework offers a lens through which these individual differences can be studied systematically, and interindividual differences in the kind of ideal life people strive for might reflect differences in term of what individuals value. Some models, such as the threelayer framework developed by McAdams (McAdams, 1995; Sheppard et al., 2026), consider values as part of personality, specifically its second layer, which comprises motivational aspects (e.g., goals and purpose) and social-cognitive elements (e.g., values, beliefs, worldview). This layer reflects adaptations to our environment shaped by our experiences.

The first layer refers to personality traits, that is, relatively stable tendencies in how individuals think, feel, and behave across situations. Traits and values are distinct constructs: traits describe relatively stable patterns of thought, feeling, and behavior, whereas values reflect what individuals consider important and desirable and serve as guiding principles in their lives.

One of the most consensual approach to personality traits is known as the Big Five (Sheppard et al., 2026). This nickname comes from the fact that it comprises five main traits across which all individuals can be situated on a continuum: openness to experience (curiosity, a taste for novelty), conscientiousness (organization and discipline), extraversion (sociability and sensitivity to positive emotions), agreeableness (cooperativeness, empathy, and trust), and neuroticism (sensitivity to negative emotions and emotional instability).

Personality traits might be a key element that shapes the variety of ideal lives individuals strive for. We know that, depending on one's personality, one might be more inclined toward certain values than others (Sagiv & Schwartz, 2022). Meta-analysis found consistent correlation pattern between certain values and certain traits (Fischer & Boer, 2015; Parks-Leduc et al., 2015).

Our values might also explain our relationship to the public good and the way we think society should be structured, i.e., our political orientation, as well as whether we are inclined toward social dominance, that is, whether we favor a hierarchical society or a more equal and inclusive one. For example, in a large-scale German survey conducted in the aftermath of 09/11 IDEAL LIFE NARRATIVES PREDICT PERSONALITY, VALUES AND WELL-BEING (Cohrs et al., 2005), social dominance was found to correlate positively with conformity, and security, and negatively with benevolence. But what kind of ideal life we strive for might not only reflect our values and personality traits, but also our well-being.

Not every ideal life goal can lead to a happy and meaningful life

In their teachings, the Epicureans, Stoics, and Cynics alike promised, through both doctrine and example, a path to the "good" life. Translated into a modern scientific framework, the implicit idea is that certain value orientations might lead to greater or lesser well-being, or to a greater or lesser sense of meaning in life, and this idea finds support in contemporary psychological science. Well-being refers to what is intrinsically good for a person and encompasses various physical and psychological states, such as health, freedom, happiness, mental health, and meaning. Psychological well-being has been studied through diverse models and measures, with subjective well-being being one of the main approaches. It refers to how individuals feel and evaluate their lives and typically comprises three dimensions: life satisfaction, and the frequency of positive and negative emotions (E. Diener et al., 2018).

Self-determination theory (Deci & Ryan, 2012), and specifically its goal content minitheory, posits that not all goals lead to subjective well-being. Goals expressing intrinsic motives (e.g., self-growth, relationships, social contribution), lead to greater satisfaction and higher subjective well-being. In contrast, values or goals representing extrinsic motives (e.g., social approval, material gain) are associated with lower well-being, a claim supported by numerous empirical findings (Ryan et al., 2022).

However, the link between values and well-being varies across cultures. Across 32

European samples, cultural egalitarianism moderated these associations. In less egalitarian contexts, openness to change (hedonism, stimulation and self-direction) were more positively associated with subjective well-being, while conservation values (security, conformity, tradition) were more negatively associated with it (Sortheix & Schwartz, 2017).

Overall, these results provide indications that what we consider to be an ideal life through our value orientations may reflect our subjective well-being.

Yet what makes life good is not reducible to subjective well-being alone. Subjective well-being is self-centered in nature because it is about feeling well. But a more selftranscendent element of psychological well-being exists. Research over the past decades has established that a sense of meaning in life, which is distinct from the belief that life itself has meaning (Palmi et al., 2025; Fuhrer et al., 2026), is also a central component of psychological well-being, with a growing consensus that it constitutes a key dimension of positive mental health (Iasiello et al., 2026). This psychological state is traditionally defined as the experience of one's life as being directed by purpose, coherent, and significant (Martela & Steger, 2016).

More recently, it has been argued that a fourth dimension should be incorporated into this definition to better capture its self-transcendent nature (Fuhrer & Cova, 2026).

Values are likewise associated with meaning in life. For example, purpose, significance, and coherence each correlate positively with self-direction, security, and benevolence, among other values (Besika et al., 2022). Although these associations are likely to vary across contexts (e.g., culture, religion, GDP, or equality), this pattern suggests that the dimensions of meaning could, at least theoretically, be predicted from narratives of individuals' ideal lives.

Predicting important psychological aspects using data: the modern use of language-based AI

The idea that language and personality are related is an old one. It is the founding intuition of the lexical hypothesis, according to which the individual differences that matter most in people's lives become encoded in their language, such that the more socially important a difference, the more likely it is to be captured by a single word (see John et al., 1988 for a historical review). Working from this premise, Allport and Odbert (1936) extracted roughly 18,000 person-descriptive terms from an English dictionary, and the factor-analytic work that followed distilled this lexicon into the five broad dimensions that became the Big Five (Corr & Matthews, 2020).

A complementary claim is that the language a person actually produces also carries a measurable trace of who they are. Early computerized text analysis supported this: using wordcounting dictionaries such as Linguistic Inquiry and Word Count (LIWC), Pennebaker and King (1999) showed that stable individual differences in word use ("linguistic style") relate to personality, and later work mapped word categories onto emotion, social relationships, and thinking styles (Tausczik & Pennebaker, 2010). These effects were reliable but typically modest, and constrained by the predefined, closed vocabulary of the dictionaries.

The arrival of large digital corpora and machine learning turned this trace into a basis for prediction. Using an open-vocabulary approach that lets the data, rather than predefined word categories, drive the analysis, H. A. Schwartz et al. (2013) related roughly 700 million words from the Facebook posts of about 75,000 users to their personality, age, and gender, and Park et al. (2015) developed open-vocabulary models that predicted Big Five traits from socialmedia language with substantial convergent validity against self-reports. Collectively, this work established language-based assessment as a low-cost, scalable complement to self-report questionnaires. Kjell et al. (2019) showed that responses to open-ended questions, quantified with natural language processing, can measure psychological constructs at least as well as rating scales while additionally describing their content; using transformer language models, the same group predicted subjective well-being from brief text responses at levels approaching the theoretical reliability ceiling of the criterion scales (Kjell et al., 2022).

A very recent and rapidly developing alternative leverages commercial large language models (LLMs), prompted to read a text and return psychological judgments directly, in a zeroshot fashion. Such successfully detected emotions from short texts across many languages about as well as, or better than, traditional sentiment analysis supervised models ( Rathje et al., 2024 with self-report comparable to or exceeding established benchmarks, including bespoke machine-learning models. Because this generative approach appeared essentially in parallel with the present study, and because it advances the strong claim of rivaling trained models with no training data at all, it offers a timely benchmark for the supervised approach that is the focus of the current study.

Gap in the literature

What remains largely untested is whether a single, theoretically chosen prompt carries enough signal to predict such a broad battery of constructs, and several questions remains open: -How much data is needed to make accurate predictions?

Earlier language-based work typically relied on hundreds of social-media posts per person (Schwartz et al., 2013; Park et al., 2015), or on prompts directly targeting the construct of interest (Kjell et al., 2022). It remains unclear whether a few sentences of self-relevant narrative are sufficient.

-What part of the language is predictive? Is prediction driven by the content itself, such as the goods, relationships, and activities mentioned, or also by how this content is expressed, including syntax, structure, tone, and text volume?

-What can be predicted? Prior work has focused primarily on the Big Five and subjective well-being. It remains unclear whether a broader range of constructs can be predicted, or whether some are systematically easier to recover than others. As argued above, conceptions of the ideal life are shaped by value orientations, political dispositions, and potentially meaning in life, providing reason to expect such narratives to be predictive.

-Is what we depict being our ideal life really the mirror of who we are? Although intuitive, no previous work has tested whether individual characteristics can be predicted from narratives describing one's ideal life.

Preregistered analyses.

The confirmatory analyses follow our preregistration (https://doi.org/10.17605/OSF.IO/ZJDSH) and were run on the 273 participants retained after the preregistered exclusions (see Participants), separately for the free-form and keyword conditions. For each condition we predicted the same 24 self-report targets: the five TIPI dimensions, the ten Schwartz values, social dominance orientation, the four meaning dimensions (coherence, purpose, significance, and positive impact), life satisfaction, positive and negative affect, and political orientation (a 7-point scale treated as continuous, for consistency with the other instruments). All analyses were implemented in Python using scikitlearn (Pedregosa et al., 2011), Transformers (Wolf et al., 2020), NumPy (Harris et al., 2020), and SciPy (Virtanen et al., 2020).

Text encoding.

Each response was encoded into a fixed-length vector using pre-trained language models accessed through Hugging Face. We preregistered two model families: decoder-only causal transformers (Llama-3.2-1B and Llama-3.2-3B, in both base and instruction-tuned versions) and bidirectional encoders (RoBERTa-base, RoBERTa-large, ModernBERT-base, ModernBERT-large, and all-mpnet-base-v2).

For each model we extracted last-layer embeddings with all family-appropriate pooling strategies: last-token and mean pooling for the causal models, [CLS]-token and mean pooling for the encoders, and the native pooling layer for all-mpnet-base-v2. The (model × pooling) choice was treated as a single categorical hyperparameter selected within the inner cross-validation loop, so that model selection cannot inflate the false-discovery rate through silent multiple comparisons.

Dimensionality reduction.

Within each training fold, embeddings were standardized (zero mean, unit variance per feature) and reduced to 100 principal components; the scaler and the PCA were fit on the training data only and applied to the held-out fold, preventing leakage between folds. Fixing the projection at 100 components equalizes representational capacity across models (whose native dimensionalities range from 768 to 5120) and ensures that the free-form versus keyword comparison is not confounded by representation size.

Value centering. Because the ten Schwartz values are rated on a common scale and are known to be affected by individual differences in scale use, we ipsatized them before prediction, IDEAL LIFE NARRATIVES PREDICT PERSONALITY, VALUES AND WELL-BEING following Schwartz's scoring guidance: for each participant we subtracted their mean rating across the ten values from each value, turning absolute endorsement into relative priority and removing participant-level response style. This was applied only to the values; the Big Five, well-being, meaning, and social constructs come from separate instruments with no common within-person mean and were left unchanged.

Prediction model. For each target we fit a regularized linear model (elastic net; scikitlearn ElasticNet) predicting the continuous score from the 100-dimensional vector. The L1 mixing ratio (∈ {0, 0.25, 0.5, 0.75, 1}, spanning pure ridge to pure lasso) and the penalty strength λ (eleven values logarithmically spaced between 10⁻⁵ and 10⁵) were selected within the inner cross-validation loop.

Cross-validation.

Performance was estimated with nested cross-validation using 10 outer and 10 inner folds, stratified on quantile-binned targets (five bins) to balance score distributions across folds, with the random seed fixed at 42. The inner loop selected the (model, pooling, L1 ratio, λ) combination maximizing validation r; the outer loop produced held-out predictions for every participant. Out-of-fold predictions were then pooled across the ten outer folds and correlated with the observed scores, yielding a single Pearson r per condition × target.

Statistical Analyses

Statistical inference. We tested two confirmatory hypothesis families across the 24 targets. The primary test asks whether each condition predicts each target above chance (H₀: r = 0), evaluated separately in each condition with Fisher's z-transformation (two-sided). The secondary test asks whether free-form text outperforms keyword lists (H₀: r_text = r_keywords), evaluated with the Meng-Rosenthal-Rubin (1992) Z₂* test for two dependent correlations sharing a common criterion (the trait score). p-values were corrected for multiple comparisons with Benjamini-Hochberg FDR control at q = 0.05, applied within each family separately (text-vs-chance, keywords-vs-chance, and text-vs-keywords). As a robustness check we additionally report bootstrap 95% confidence intervals for r and Δr (1,000 resamples of participants).

The analyses below were added after the preregistration and are reported as exploratory. All steps after text encoding (PCA, elastic net, nested cross-validation, and inference) are identical to the preregistered pipeline.

Discussion

Comparison with previous studies

In this preregistered study, we asked whether descriptions of one's ideal life predict who people are across a broad range of psychological constructs. They do. Our first and central hypothesis, that both free-form and keyword descriptions would predict each target above chance, was supported for most constructs: free-form narratives predicted 19 of 24 targets above chance and keyword lists 12 of 24, spanning personality traits, most values, political orientation, subjective well-being, and dimensions of meaning in life. This breadth, spanning personality, values, meaning, and well-being from a single brief prompt, is, to our knowledge, unprecedented for open-ended text. Our second hypothesis, that free-form narratives would outperform keyword lists, was confirmed overall (free-form higher for 22 of 24 constructs, p < 0.001). Combining the two formats did not improve on free-form alone, contrary to our expectation. Together, these findings show that even a brief, indirect description of an ideal life carries substantial, recoverable information about personality, values, well-being, and meaning.

Our study is most directly comparable to Wright et al. (2026), who used zero-shot generative scoring of open-ended text and reported strong convergence with self-reported Big Five traits (mean r ≈ 0.44-0.48).

Our contribution is complementary and, in several respects, more demanding.

First, in scope: Wright et al. validated the method on the Big Five alone, whereas we show that ideal-life narratives predict a far broader battery, including the ten Schwartz values, the dimensions of meaning, subjective well-being, and political orientation, extending well beyond the personality and well-being constructs that most prior language-based work has targeted.

Second, in data regime: Their inputs were diaries and streams of thought of roughly 1,600 to 3,100 words, whereas our participants wrote about 120 words, more than an order of magnitude less. That we still obtain above-chance prediction for most constructs shows that the approach scales down to the brief, low-effort responses typical of applied settings; their higher absolute Big Five correlations are expected and partly reflect this large difference in input length rather than a difference in method.

Third, in method: When we hold the text constant and compare the two paradigms on the same participants, our supervised embedding-and-regression pipeline performed on par with the zero-shot generative procedure, while running locally at no cost on freely accessible models rather than requiring a proprietary, paid-API model. Because inference runs locally, participants' own words need never be sent to a third-party commercial service, which matters both for the sensitivity of ideal-life narratives and for institutional data-protection constraints. In short, we trade some absolute accuracy on the Big Five for substantially greater breadth, efficiency, and methodological transparency. The open-source code and trained regression models that accompany this paper will allow researchers to apply our methods to their own data, with minimal technical overhead.

Our approach also differs from the semantic and question-based methods of Kjell and colleagues (Kjell et al., 2019 (Kjell et al., , 2022)), who elicit open-ended descriptions aimed directly at the construct of interest (for example, asking respondents to describe their well-being in their own words) and reach very high accuracy for that target. We instead use a single, indirect prompt that names none of the measured constructs and recover a whole battery of traits, values, and states from it. This is at once more parsimonious, one elicitation rather than one per construct, and more stringent, because the narrative is not about the outcomes it is used to predict; the price, as expected, is lower accuracy than a construct-matched prompt would achieve for any single outcome.

The best encoder also depended on the modality, and revealingly so. The free-form condition was best served by a generative decoder (Llama-8B), whose autoregressive pretraining is geared to modelling connected, contextual prose, whereas the keyword condition was best served by a retrieval-tuned encoder (BGE-ICL-7B), optimized to map short, decontextualized text into a semantic space. A decoder may struggle to build a useful representation from a bare list of seven words with little syntax to condition on, while a retrieval encoder gains little from, and may even be diluted by, the surrounding discourse of a full narrative. The two input formats thus reward different inductive biases, so the best model is not the same across conditions; this is also why we selected the best model separately for each modality rather than forcing a single model onto both.

It is not only what people name, but how they say it

Free-form narratives outpredicted keyword lists for most constructs, but the size of the advantage varied sharply, and that variation is itself informative. A keyword list isolates the bare content of a person's ideal, the specific goods, relationships, and activities they name, whereas a free-form narrative adds the connected discourse in which that content is expressed; the free-form advantage therefore shows that predictive signal lies beyond the particular words a person lists.

Because the two formats also differ in length and syntax, we cannot credit expressive style alone, but the referents named are clearly not the whole story. The advantage was significant for achievement, benevolence, conformity, emotional stability, negative affect, and significance, that is, for constructs that are rarely named outright and must instead be inferred from how a person writes about their life. It was smallest where keyword lists already performed well (self-direction, life satisfaction, coherence, positive emotions, political orientation), all constructs that a short label captures directly, and absent where neither format succeeded (universalism, security, social dominance). When a construct can be conveyed by naming the right things, keywords suffice; when it lives in the manner of the telling, only the connected narrative reveals it.

What conceptions of the ideal life reveal about the self

A central empirical question of this study was whether the way people narrate their ideal life predicts the individual differences that characterize them. There are several reasons to doubt that it would. Such narratives might be too idiosyncratic to yield a systematic signal, too brief to carry much information, or too similar across people to capture meaningful psychological differences. Natural language processing allowed us to put these doubts to the test, and our findings speak against all three. Even short ideal-life narratives carried substantial information about psychological characteristics: we predicted, above chance, Big Five personality traits, most Schwartz values, political orientation, subjective well-being, and dimensions of meaning in life. But what, exactly, was predicted, and why?

The first striking finding is that value orientations were generally better predictors than Big Five personality traits. One plausible explanation is that Big Five traits capture broad, stable tendencies in how people function, rather than the specific content of what they pursue. For example, neuroticism captures differences in sensitivity to negative affect and emotional stability, which can shape well-being and the lifestyles people choose (Mroczek & Little, 2014).

Yet traits may reveal less about the specific values underlying ideal-life narratives, because values, rather than traits, define the goals people consider important and where they invest their time and energy. Two people with similar Big Five profiles may therefore pursue very different goals, with one oriented toward power or achievement and the other toward openness to change.

This interpretation is illustrated by the narratives of participants with different value profiles. Individuals high in self-enhancement, particularly achievement and power, might emphasize goal-directed and self-oriented elements. For example, one participant scoring high what matters. On the other hand, Participants high in conservation might describe more traditional ideal lives, emphasizing religion, family, or traditional gender role (tradition = 8/8, conformity = 8/8, security = 8/8): "My ideal life is having no stress or worry.

Political orientation was also relatively predictable. One possible explanation is that ideal-life narratives often implicitly reflect attitudes toward religion, tradition, and social structure, including family roles, stability, and moral norms. These cues overlap with conservation values and may allow language models to infer whether someone leans more conservative or liberal.

The remaining important findings concern subjective well-being and meaning in life.

We expected these constructs to be predictable because ideal-life narratives should reflect underlying value orientations. Given that not all ideal-life goals lead to greater well-being or meaning, as reviewed in the Introduction, certain goals may reflect value orientations that are themselves related to these outcomes. However, values and personality are unlikely to fully explain the predictive signal. The fact that free-form descriptions outperformed keyword lists suggests that some information lies in how people express their ideal life, beyond the specific values or goals they mention.

Taken together, our results show that how people imagine their ideal life provides an informative window into who they are. A description of barely 100 words, prompted by a single question that names none of the constructs being predicted, was sufficient to recover meaningful individual differences in personality, values, well-being, and meaning. Methodologically, a transparent supervised pipeline using freely available models can match or exceed scoring by large commercial models while requiring far less text than comparable work. More broadly, the ideal life a person envisions is not idle reverie: it reflects their personality, values, well-being, and sense of meaning.
