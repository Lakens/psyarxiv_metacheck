Reporting p values imprecisely (e.g., p < .05) reduces transparency, reproducibility, and re-use (e.g., in p value meta-analyses). Best practice is to report exact p-values with three decimal places (e.g., p = .032) unless p values are smaller than 0.001, in which case you can use p < .001.

What we found

We found 1 non-significant p value that should be checked for appropriate interpretation.

Show details

Meta-scientific research has shown nonsignificant p values are commonly misinterpreted. It is incorrect to infer that there is ‘no effect’, ‘no difference’, or that groups are ‘the same’ after p > 0.05.

It is possible that there is a true non-zero effect, but that the study did not detect it. Make sure your inference acknowledges that it is possible that there is a non-zero effect. It is correct to include the effect is ‘not significantly’ different, although this just restates that p > 0.05.

Metacheck does not yet analyze automatically whether sentences which include non-significant p-values are correct, but we recommend manually checking the sentences below for possible misinterpreted non-significant p values.

This module searches for statements of ethics approval, IRB approval, institutional review board approval, and related terms.

Patterns are designed to capture:

Declaration of Helsinki - Declaration of Helsinki / Helsinki Declaration

How Power Analysis Check works

This module uses regular expressions to identify sentences that contain a statistical power analysis. If specified by the user, it also uses a large language model (LLM) to extract information reported in power analyses, including the statistical test, sample size, alpha level, desired level of power, and magnitude and type of effect size.

The Power Analysis Check module uses regular expressions to identify sentences that contain a statistical power analysis. Without the use of an LLM, the module uses regular expressions to classify the power analysis as a-priori, sensitivity or post-hoc. How StatCheck works

Check consistency of p-values and test statistics

The Statcheck module runs Statcheck. Statcheck searches for regular expressions that match a predefined pattern, and identifies APA reported statistical tests. More information on the package can be found at https://github.com/cran/statcheck. The module only returns Statcheck results for t-tests and F-tests, as these are the only tests which have been validated, see https://osf.io/preprints/psyarxiv/tcxaj_v1/.

Statcheck was developed by Michèle Nuijten and Sascha Epskamp.

Statcheck considers p = 0.000 an error, as you should report p < 0.001. Furthermore, p < 0.03 is an error if the p-value was 0.031, and one should simply report exact p-values (p = 0.031). When the sentence of a test says it is one-sided (“one-tailed”, “one-sided” or “directional”), a p-value that fits a one-sided test counts as consistent (statcheck’s OneTailedTxt setting; #695). When the paper says anywhere that its tests are one-sided, a p-value that fits a one-sided test in either direction counts as consistent too: half the two-sided p, or 1 minus that half for an effect against the predicted direction. Equivalence tests (TOST) are left out, as their p-values do not test the difference. A statistic written with “<” or “>” is read as a bound, and in a sentence about equal variances an F-test’s two-sided p (twice the one-tailed p) counts as consistent. For more information, see StatCheck.

This module only checks statistical results reported in the running text of the manuscript. It cannot (yet) process statistics reported only in tables.

How Exact P-Values works

List any p-values reported with insufficient precision (e.g., p < .05 or p = n.s.), reported as exactly zero (e.g., p = .000), or impossible (below 0 or above 1, e.g., p = -.22).

This module uses regular expressions to identify p-values. It will flag any values reported as p > ? or p < numbers greater than .001. It will also flag p-values reported as exactly zero (e.g., p = .000, p = 0.00), which are mathematically impossible — p-values are never exactly zero and should instead be reported as p < .001.

A p-value that is not the result of a test is not flagged: a table note (“* p < .05, ** p < .01”), a figure legend (“Asterisks indicate significant differences (p < .05)”, “Values in bold are significant at p < .05”) or a stated threshold (“p < .05 was considered significant”, “thresholded at p < .001”). GROBID often puts such notes into the running text, so each p-value is judged by the words in its own clause (the text up to a “;” or a full stop), and never left out when a test statistic belongs to it (“F(1, 7) = 8.03, # p < .05”). The column not_a_test of the table says why a p-value was left out (“marker”, “threshold”, “legend” or “named”).

A p-value with the name of a correction or a test after the p (“pFWE < .05”, “padj < 0.05”, “p Wilcoxon = .02”) is flagged only when a test statistic comes before it in its clause (“t(37) = 7.17, p FWE < .05”). Without one it is mostly the rule that decided what was significant (“genes with padj < 0.05 were selected”); such a p-value is “named” in not_a_test. Notes in other forms, such as a marker after the p-value (“p < .05 (*)“), are still flagged.

A p-value below 0 or above 1 is impossible; it is listed apart and not also as imprecise. Often the statistic before it, or its minus sign, was copied into it (“t(134) = -2.32, p = -.13”, “Z = 3.091, P = 3.091”). A value above 1 is listed only after a test statistic in its clause: without one, a “P” above 1 was nearly always another quantity (a proportion, pH, a group’s mean, a model parameter). A number in scientific notation whose power of ten was lost when the PDF was read (“p = 2.4 x 10 -9” read as 2.4) is not listed. A “p” that is the subscript of another symbol (“r p = .64”, “²p = .02” for partial eta squared, “Δp = .33”), or a quantity with a unit, a logarithm or a ratio (“P = 2.9 µm”, “-log10 P = 7.5”, “Ca/P = 1.67”), is not read as a p-value at all (see extract_p_values()). Each p-value has its own row, also when the same one is written twice in a sentence.

This module sometimes flags false positives when sentences discuss how p-value thresholds were set. It can also miss an imprecise p-value that is reported against a threshold (“decreased at the p < .05 significance threshold”).

This module only checks p-values reported in the running text of the manuscript. It cannot (yet) process p-values reported only in tables (as opposed to a table’s footnote text, which the module does see and tries to exclude — see above).

This module was developed by Lisa DeBruine and Daniel Lakens

Read more in the metacheck manual.

How Codebook Check works

This module checks whether the data columns in a repository are documented in a codebook or README. It locates codebook/readme files, extracts the variable definitions they contain, matches those definitions against the data columns extracted by data_check, and reports documentation coverage: how many data columns are documented, and which documented variables are never used.

The Codebook Check module consumes the columns and file classification produced by data_check (and, transitively, repo_check). Files classified as codebook or readme are parsed with parse_codebook(), which reads structured tables (CSV/TSV/Excel with a variable-name column and a label column), embedded labels in haven files (SPSS/Stata/SAS), and plain text from rich-text formats (docx/pdf/rtf/odt). Embedded haven labels from data files are also harvested directly.

Each data column is then matched against the parsed variable definitions with match_column_labels(), using normalised-name matching with experiment-group scoping, haven-label priority, and rule-based label-equivalence merging.

Beyond the variable label, the module harvests the DDI-style per-variable properties a source supplies: the value labels / code list (the 1=“Strongly disagree”…5=“Strongly agree” mapping — from SPSS/Stata value labels and from a codebook “values”/“coding” column), the missing-value scheme (which codes denote missingness, from haven declared missings and labels that read as “refused”/“n/a”), and question text and columns when present. These are carried onto the matched data columns and exported into the Psych-DS variableMeasured (as a schema.org code list plus namespaced metacheck: fields).

The module defaults to rules-only when llm_use(FALSE). When llm_use(TRUE), three optional LLM tiers run: parsing unstructured codebook text that the rules could not handle, fuzzy-matching still-unlabelled columns to still-unmatched codebook variables, and merging conflicting label definitions into a single canonical label.

How Repository Check works

This module retrieves information from repositories.

The Repository Check module lists files on the OSF, GitHub, ResearchBox, DSpace (PsychArchives and other legacy- and DSpace 7-based installations), Zenodo, Dataverse, Figshare, Dryad, ReShare, 4TU.ResearchData, Mendeley Data, DataONE (Arctic Data Center, KNB, and other member nodes), and LDbase based on links in the manuscript.

A link to a file-sharing service (Google Drive, Dropbox, OneDrive, Box, WeTransfer, MEGA, iCloud Drive, Baidu Netdisk, SURFdrive; see [file_share_links()]) gets a warning and makes the light yellow: such services are not repositories, as files can be changed or deleted at any time, get no DOI, and the link stops working when the account is closed. The report advises a stable repository such as Zenodo instead. Their files are not read, and summary_table$file_share_n counts the links.

Deposits in archives for sequence and expression data (GEO, the INSDC archives BioProject, SRA, ENA and DDBJ, and ArrayExpress; see [seq_archive_links()]), mostly named by accession number, are read for whose deposit they are. The authors’ own are listed with what they hold ([seq_archive_size()]) and are not downloaded or checked as data and code; summary_table$archive_own_n counts them.

R packages on CRAN ([cran_links()], [cran_info()]) are the paper’s own when a paper author is a package author and the paper presents the package; the paper’s own are listed with their version and not checked (summary_table$cran_own_n). A Handle link (hdl.handle.net/...) that leads to a repository read here is checked as a link to that repository ([handle_links()]).

Listing a repository’s files never requires an API key, but some hosts answer faster or more completely with one: OSF allows 100 requests/hour unauthenticated versus 10,000/day with a token (see [osf_pat()]), and Dryad enforces a strict per-IP daily quota on repeated listing (see cache below). Dryad is a special case beyond rate limits: listing a Dryad dataset’s files works without a key, but actually downloading file CONTENTS from Dryad fails with HTTP 401 unless a key is set, even for a fully public dataset (see [dryad_pat()] or [dryad_auth()]). Since this module only lists files and never downloads their contents itself, that limitation applies to data_check and code_check (which do download content), not here – see their own documentation.

When a linked OSF page is a registration, its registered_from project (the one it was registered from, which the manuscript itself may never link directly) is also checked: if that project is public its files are listed under its own URL, and if it is closed or otherwise inaccessible the report flags it explicitly, since some registrations only describe their content rather than mirroring it.

Whose deposit is each link? The ownership table gives, for every repository linked in the text and (with references = TRUE) every deposit cited in the reference list, one of six labels: own_this (made by the authors for this paper), own_earlier_data or own_earlier_code (the authors’ own, from earlier work), others_data or others_code (made by other people, reused here), or not_data (a publication such as a preprint, not a deposit), with ownership_group (“own”, “others”, “not_data”) and the reason. It is decided without a language model, from the sentence or reference that cites the link, the paper’s authors (names, ORCID iDs, affiliations), and what the deposit’s own record and files say (who made it, what it names, when, whether it is a software package; for an OSF project cited only in the reference list, its record alone). On a round of labelled links the rules had not been written from, the three groups were right for 98% of links in the main text (93 of 95) and 90% in reference lists (74 of 82); the labels were made by Claude agents from each link’s evidence, and disputed ones checked against the deposits. How Code Check works

This module retrieves information from repositories checked by repo_check about code files (R, Python, SAS, SPSS, Stata, Mplus, MATLAB).

The Code Check module checks R (also R Markdown and Quarto), Python (also Jupyter notebooks), SAS, SPSS, Stata, Mplus, and MATLAB files, using regular expressions to check the code; JASP files are listed but not read. The language of a Quarto document or a notebook is read from the file itself (its engine or kernel), not from its extension. The regular expression search will detect the number of comments, the lines at which libraries/imports are loaded, attempts to detect absolute paths to files, setwd() and install.packages() calls, and lists files that are loaded, and checks if these files are in the repository; R code is also parsed. The module will return suggestions to improve the code if there are no comments, if libraries/imports are loaded in lines further than 4 lines apart, if files that are loaded are not in the repository, if absolute file paths, setwd() or install.packages() are found, and if R code cannot be parsed.

The regular expressions can miss information in code files, or falsely detect parts of the code as a fixed file path. Libraries/imports might be loaded in one block, even if there are more than 3 intermittent lines. The module was tried out internally on papers published in Psychological Science, but has not been formally validated. There might be valid reasons why some loaded files can’t be shared, but the module can’t evaluate these reasons, and always gives a warning.

The module also checks whether the repository pins the R/package versions the analysis actually depended on: an renv.lock file (parsed for the R version and every locked package + its version/source), a sessionInfo()/sessioninfo::session_info() text dump (matched by filename — sessionInfo.txt/session_info.txt and similar, or embedded in a README), or a groundhog::groundhog.library()/checkpoint::checkpoint() date-pin call in the code (a bare library(groundhog)/library(checkpoint) does not count — the pinning call itself must be present). When none of these is found, the report flags it as a reproducibility gap: package versions may drift between when the analysis was run and any later reproduction attempt.

How Data Check works

This module classifies the files in a repository into semantic types (data, codebook, code, software, output, supplemental, readme, asset, other) and, for tabular data files, extracts each column’s type and summary statistics.

The Data Check module consumes the file list produced by repo_check (or any files added via local_path). Each file is classified with rule-based heuristics layered over metacheck’s file_category() and file_types: file names matching README / codebook patterns win first, then an extension crosswalk, then format-locked extension overrides. For every file classified as tabular data that is available locally, the module reads the file head, describes each column with data_col_facets() and computes summary statistics for numeric columns. Every sheet of a spreadsheet that holds a table is read: a file with several such sheets has its columns under source_file = "file.xlsx [sheet]", and the sheet column names the sheet of any spreadsheet with several sheets; a sheet of notes or a codebook is treated as documentation when the file has another table. Following DDI, a column is described by orthogonal facets rather than a single type: representation (numeric/text/datetime/code — how it is stored), measurement_level (Stevens: nominal/ordinal/interval/ratio), concept (what it measures: reaction_time/age/gender/likert/id/…), role (identifier/measure/condition/timestamp), unit, and a quality state (ok/empty/constant). Qualtrics survey exports are recognised (data_check_is_qualtrics()): their extra header rows are stripped so columns type correctly, and the reserved response-metadata columns (StartDate, Duration, Finished, …) are tagged.

The module defaults to rules-only when llm_use(FALSE): columns the rules cannot resolve (ambiguous 3–20-unique integers, ambiguous character columns) fall back to continuous / text respectively. When llm_use(TRUE), ambiguous columns and unresolved file types (other) are sent to llm() for optional refinement, and every file is assigned a study group (ex1, pilot2, shared, …) so that multi-study repositories can be recognised (used by psychds_check). Without an LLM the study group is left NA (unknown).

For a paper whose repository is on Dryad, this means column extraction never happens unless a Dryad API key is set: Dryad requires one to download file bytes, even from a fully public dataset (dataset listing and metadata do not need one). Without a key, every Dryad file stays classified but un-downloaded, column_n is 0, and a warning naming Dryad and ?dryad_pat/?dryad_auth is included among the download failures. A one-time session message is also shown (see repo_check) the first time a Dryad dataset is encountered with no key set.

How Reproducibility Check works

This module assesses whether a paper’s R and Python code can be run on its data. It works in two phases. The static phase (always run) collects the package dependencies the code declares, rewrites the data-file paths that do not work in the repository as the authors organised it, works out the order the scripts must run in, and diagnoses why any referenced input file is unavailable — reporting what a reproduction attempt would involve and where it is likely to break. The execution phase (opt-in, execute = TRUE) then actually runs the code: it copies the repository into a throwaway directory, optionally installs the declared dependencies into a throwaway library, runs each script in order in an isolated subprocess with a per-script timeout, and captures the outcome and full output of each run.

By default (execute = FALSE) the module does not run any code — it performs only static analysis: reading dependencies with the same extractors as code_check, finding the files the code references in the repository, and building a run-order dependency graph. It reports what would be installed and run rather than doing it.

When execute = TRUE, the module additionally runs the downloaded code on your machine — a deliberate, opt-in action gated behind that argument (callr is required for R code). Each script runs in an isolated subprocess so a crash cannot take down the R session; note this isolates crashes, not the filesystem or network. Installs (when install_missing = TRUE) and the throwaway run library never touch your main R library. Each script’s outcome is one of ran_ok, errored, timed_out, dependency_unavailable, not_parsed, run_by_source (an R script another script runs with source(), which is run only inside that script, since on its own it lacks the packages and objects the sourcing script sets up first), run_by_import (a Python file other files import, a module rather than a script, unless it has an if __name__ == "__main__": block), jags_model (a JAGS or BUGS model saved with an R extension, which another script reads) or not_r_content (a file that is not R at all, such as a JSON or HTML dump); these last two are not run and are not failures. python2 marks Python 2 code that was not run. With sandbox = "docker" such code runs with Python 2.7 (option metacheck.docker_image_py2; FALSE turns this off), which modifications records; it is never converted, since that can change results. defines_functions is a file that only defines functions, which is used, not run (table$used_by names the scripts that use it), and not_analysis is a file of software rather than of the analysis: a package’s code, tests, documentation or setup.py, a copy of a tool, a web application, a script a program wrote (table$not_analysis_why says which); neither is run or counted as a script. docker_failed means the container never started, which says nothing about the script, so it keeps the light from being green but does not make it red. needs_a_person is a script that stopped because it asks a person to choose a file or answer a question, or that starts an app, and needs_internet one that stopped because the network is off in a Docker run, or, with internet = TRUE, could not reach what it asked for; download_too_large is a script stopped for downloading more than the limits allow (see internet), and out_of_memory one that, or a program it started (such as a compiler), ran out of the memory each script may use. All four are treated the same way. not_downloaded is a script that stopped on a file the repository lists but that was not downloaded, such as one over max_file_size: it could not be tried, so it is not counted as a script that did not reproduce (summary_table$repro_not_downloaded_n counts them apart). not_read is a file metacheck could not read, so it was not run; the light is then not green, as the file may read and run on another computer, and table$error_message says why, naming a package that is installed but cannot be loaded on the computer that ran the check. empty is a file with nothing in it, which is not run or counted as a script. For a script that did not run through, table$error_message is its error, short (at most 300 characters): the error line of its output, which names a package that is not there, with the address it asked for when it needed the internet, or the time limit it reached; table$reason sorts it into a kind. A timeout means “still running at the cutoff”, not a failure, so raise timeout for legitimately long-running (e.g. Bayesian) scripts. dependency_unavailable means the script’s own package could not be installed from live CRAN, the CRAN Archive, or a named GitHub/URL source — an infrastructure limitation, not a defect in the paper’s code. The full stdout/stderr of every run is kept in the result’s run_results (the report shows it in per-script dropdowns, capped for readability).

Provenance, kept so that a TRACE Research Object (TRO) declaration of the run can be written later from a stored result (metacheck #404; the helpers are in R/provenance.R). Only when code was run (execute = TRUE): * run_results$started_at, run_results$ended_at: when each run of a script started and ended (ISO 8601, UTC, milliseconds); NA for a script that was not started. A script run again in a later pass has the times of its last run. A TRO uses them for each trov:TransparentResearchPerformance. * run_results$exit_status: the exit status of the process that ran the script (0 = ended normally); NA when the process did not report one (a time limit, or Docker failing to start the container). * artifacts: one row per file, with stage (deposit: as downloaded from the repository, hashed from the downloaded file; before_run: the run folder just before the first script ran, after metacheck’s own changes, such as rewritten paths and unpacked archives; after_run: only the files the scripts made (status new), changed (changed) or removed (removed), as an unchanged file is the one listed before the run), path (relative to the run folder, as valid UTF-8, a byte of another encoding written as <xx>), size (bytes), sha256, mime_type (by extension, NA when unknown), source (the file’s address in the repository, for deposit). The package libraries metacheck installs in the run folder are left out, as are metacheck’s own files there (a script’s runner, and the statistical output it writes in statistical_output/). Files metacheck itself copied or made between passes (see modifications, output_copied, file_placed) show in after_run too. A TRO uses the rows as trov:ResearchArtifacts and each stage as a trov:ArtifactArrangement. * modifications$sha256_before, modifications$sha256_after: the hash of the changed script as downloaded and as it ran; NA when the script is not at the same path in both (a script made from an R Markdown file). * environment: the system that ran the code (trov:TransparentResearchSystem in a TRO): metacheck_version, started_at, ended_at, host (R version, platform, operating system), sandbox, network_isolated (TRUE only when every Docker run had --network none; the process sandbox does not stop the network), internet, timeout_per_script, total_timeout, python_local (the Python run outside Docker and its version), and docker: runs (for each kind of run, r_run, r_install, python_run, python_install, the image and the docker run arguments, such as --network none, --read-only, --cap-drop ALL, no-new-privileges, the process limit and the memory and processor limits) and images (for each image, its ID and digests from docker image inspect, its creation time and the R and Python versions its environment declares).

It is NA for files run inside another script, files that are not an analysis, files not read, and a Docker failure. summary_table counts each group (repro_ran_n, repro_code_error_n, repro_dependency_n, repro_time_n, repro_not_checkable_n), and the report’s first sentence gives them. The traffic light reflects the static readiness signals by default; a script in code_error that stopped with an error makes it red, as a script that crashes on its own analysis is a genuine reproduction failure, and a script in one of the other three groups keeps it from being green. Calls that need a screen, which the run does not have (dev.print(), dev.copy2pdf(), dev.copy2eps(), savePlot(), windows(), win.graph(), x11(), quartz(), View()), are replaced before the run by calls that need none, which modifications records as screen_call_replaced. A script that fails with could not find function is run once more with the library() calls the project’s other scripts make added at its top (or the one package that exports the function, or magrittr for %>%), and a script that then runs is reported as reproducible only after that repair.

Dependencies are reported name-only, with the source (CRAN, GitHub, or a base package already shipped with R) — static analysis of the code cannot know which version was used, and running against current package versions is itself informative: a break argues the authors should have pinned versions. When the repository does record versions, a run with recorded_versions = TRUE installs the packages the scripts load at those versions, but it does not change the R version, which remains a limitation of the check.

Run order is derived from read-after-write data dependencies (a script writing a file another reads must run first), source() edges, and numeric filename prefixes as a weak tie-breaker. Ambiguous orderings, dependency cycles, and inputs a script reads but that no earlier script produces (and that are not in the repository) are surfaced as warnings, since these are the situations most likely to make an otherwise-correct reproduction fail.

Each file is checked for syntax errors with Python’s own parser when a Python interpreter (python, or else python3) is available; dependencies are read from the import statements, with versions from a requirements.txt or pyproject.toml when there is one, and installed with pip; each script runs as its own python process (processx is required), so unlike R scripts, a name one script defines is not available to another. When no Python interpreter is available, the Python files are reported as not run and the R results are still returned. Abstract

Object identity depends on how constituent features are combined, such that the same features may form distinct objects when their configuration changes. The perirhinal and anterolateral entorhinal (ERC) cortices are implicated in conjunctive object processing; however, regional sensitivity alone cannot reveal how information is coordinated across regions, or whether this coordination extends beyond object-processing regions to spatial and relational regions. Using generalized psychophysiological interaction (gPPI) analysis of BOLD signals extracted from manually-segmented medial temporal lobe regions, we examined task-modulated functional connectivity while younger adults viewed repeated objects (familiar features in familiar configurations), recombined objects (familiar features in novel configurations), and novel objects (novel features in novel configurations). This design isolated connectivity changes associated with configural, featural, and global novelty/familiarity. Configural familiarity (repeated relative to recombined objects) was associated with widespread increases in connectivity across distributed hippocampal-cortical networks, encompassing anterior temporal regions implicated in object processing and posterior-medial and hippocampal regions implicated in relational processing, including connections with medial prefrontal and posterior-medial cortex. In contrast, configural novelty (recombined relative to repeated objects) elicited more focal connectivity increases between right posteromedial ERC and left superior parietal and right frontal regions.

Neither featural novelty/familiarity (recombined vs. novel objects) nor global novelty/familiarity (repeated vs. novel objects) was associated with significant connectivity differences. We interpret greater connectivity for configurally familiar repeated objects as reflecting reinstatement of established conjunctive representations, whereas connectivity changes for configurally novel recombined objects may reflect the demands of encoding novel conjunctions and/or resolving competition among partially matching representations.

Introduction

We identify objects by how their constituent features are arranged, such that conjunctions of the same features can form distinct perceived objects when their configuration changes. The neural processing underlying configural relationships is therefore central to how we construct and distinguish objects. Two medial temporal lobe (MTL) regions are implicated in configural object processing: the perirhinal cortex (PRC) and anterolateral entorhinal cortex (alERC). The PRC sits atop the ventral visual stream's representational hierarchyhttps://www.zotero.org/google-docs/?LFgyNX representing increasingly complex conjunctions of object features (Martin & Barense, 2023; Murray & Bussey, 1999; Saksida & Bussey, 2010) , as evidenced by impaired discrimination of objects with overlapping features following PRC damage in humans and nonhuman primates (Barense et al., 2012; Buckley et al., 2001; Bussey et al., 2003; Erez et al., 2013) and in aging (Gellersen et al., 2023; Jiang et al., 2024). Functional PRC activity is also sensitive to object feature conjunctions (Barense et al., 2012; Cacciamani et al., 2017; Ryan et al., 2012). This sensitivity extends to different forms of novelty: the PRC responds to featural novelty, in which individual features are new, and configural novelty, in which familiar features form novel arrangements (Ladyka-Wojcik et al., 2026). The adjacent alERC is similarly sensitive to configural changes (Ladyka-Wojcik et al., 2026) and alERC volume in older adults predicts object discrimination based on spatial feature arrangement (Yeung et al., 2017). Despite evidence that PRC and alERC respond to featural and configural changes, they have largely been studied independently, leaving open how they interact during configural object processing.

Detecting featural and configural changes may place different demands on the brain: the former involves tracking individual feature changes, whereas the latter requires sensitivity to changes in the spatial relationships among features. Regional sensitivity to these changes can identify where such information is processed but does not reveal how information is coordinated across regions to support these distinct computations that underlie detecting whether an object remains unchanged (familiarity) or changes (novelty). Examining functional connectivity therefore provides a means of characterizing how object-processing regions interact. Object processing preferentially engages the anterior-temporal (AT) network, including PRC and alERC, whereas the posterior-medial (PM) network, including posteromedial entorhinal cortex (pmERC) and parahippocampal cortex (PHC), is more strongly associated with spatial and relational information (Maass et al., 2015; Navarro Schröder et al., 2015; Ranganath & Ritchey, 2012).

Although this framework emphasizes the AT network in object processing, PM regions may also contribute, as objects are encountered within spatial and contextual environments (Ranganath & Ritchey, 2026). The hippocampushttps://www.zotero.org/google-docs/?wE53H8 in turnhttps://www.zotero.org/google-docs/?dATo1Z is positioned to integrate information across AT and PM networks (Ritchey et al., 2015) , consistent with its established role in binding disparate elements into coherent representations (Diana et al., 2007; Olsen et al., 2012) , including during online perceptual processing (Hodgetts et al., 2017). Thus, examining connectivity across AT and PM regions can reveal how configural object processing is supported within the object-related network, and whether it involves broader coordination across spatially-sensitive regions.

The present study examined how MTL connectivity varies with distinct types of novelty/familiarity during a complex object-viewing task in fMRI. We used a generalized psychophysiological interaction (gPPI) approach with BOLD signals extracted from participants' manually-segmented MTL regions as seeds, spanning AT and PM networks, including PRC, PHC, alERC, and pmERC, as well as hippocampal subfields (CA1, CA3/DG, and subiculum).

Participants viewed repeated objects, comprising familiar features in familiar configurations, recombined objects, comprising familiar features in novel configurations, and novel objects, comprising novel features in novel configurations. The critical repeated vs. recombined contrast isolated connectivity patterns associated with configural novelty/familiarity while holding feature novelty/familiarity constant. For completeness, we also examined connectivity patterns associated with featural (recombined vs. novel), while holding configural novelty/familiarity constant, and global novelty/familiarity (repeated vs. novel). Here, we show that configural novelty/familiarity is associated with altered connectivity across a distributed hippocampal-cortical network, extending beyond anterior-temporal regions traditionally implicated in conjunctive object processing.

Materials & Methods

An overview of the experimental paradigm is provided in Figure 1. The experiment was conducted entirely in the MRI scanner and comprised 14 blocks, with two blocks per fMRI run (maximum of seven runs). Each block consisted of an exposure phase followed by a critical manipulation phase. (B) During the exposure phase, three objects comprising distinct upper and lower feature parts, overlapping in the middle third of the object, were presented five times each in a randomized order. The three objects and their constituent features were unique to each block. (C) During the critical manipulation phase, three object types were presented: repeated objects, composed of familiar features in familiar configurations; recombined objects, composed of familiar features in novel configurations; and novel objects, composed of novel features in novel configurations. Each object type was presented twice per block. (D) Three contrasts isolate different forms of novelty and familiarity, depending on the directionality of the contrast: the critical repeated vs. recombined contrast isolates configural novelty/familiarity, recombined vs. novel isolates featural novelty/familiarity, and repeated vs. novel captures global novelty/familiarity. (E) Trial structure was identical across the exposure and critical manipulation phases. Each trial began with a jittered intertrial interval, followed by object presentation at one of seven evenly spaced positions along a 200-pixel-radius circle. Participants then rated the coherence of the object's features using a button box.

Participants

Participants were the young adult sample from Ladyka-Wojcik et al. (2026). The sample comprised 43 younger adults (19-35 years old; Mage = 21.44 years, SD = 2.52; 32 female) recruited from the greater Toronto area. Participants had normal/corrected-to-normal vision and were screened for color blindness, psychological and/or neurological disorders, brain damage (i.e., stroke, surgery, or concussions), and MRI contraindications. The study was approved by the Research Ethics Boards at the University of Toronto and the Rotman Research Institute at Baycrest Health Sciences, and all participants provided informed consent.

Stimuli and experimental conditions

Stimuli were presented across 14 experimental blocks, with two blocks per functional scanning run (participants completed five to seven runs in total; Figure 1A; paradigm adapted from Yeung et al., 2017). Object features were unique to each block. Stimuli were conjunctive objects composed of distinct upper and lower feature parts that overlapped in the middle third of the object (Figure 1B-C). Feature parts varied in shape, color, and/or texture. The objects were standardized to have the same vertical size of 300 pixels to facilitate their presentation in the scanner. As such, all objects had the same vertical height but ranged in horizontal width between 137 and 563 pixels. Stimuli were based on the object stimuli described in Yeung et al. (2017) https://www.zotero.org/google-docs/?U6rJUz adjusted in vertical and horizontal dimensions to accommodate the MRI setting.

Each block began with an exposure phase (Figure 1B), during which three objects (e.g., AB, CD, and EF) were each presented five times in a randomized order. The exposure phase was followed by a critical manipulation phase (Figure 1C), consisting of six object presentations: two repeated objects, composed of familiar features from the exposure phase in familiar configurations; two recombined objects, composed of familiar features from the exposure phase in novel configurations; and two novel objects, composed of novel features in novel configurations. Thus, each condition had two trials during the critical manipulation phase. These critical trials were used in the gPPI analyses, with repeated vs. recombined isolating configural changes, recombined vs. novel isolating featural changes, and repeated vs. novel capturing global changes (Figure 1D).

Procedure

Each trial consisted of a jittered fixation period (2-4 s), an object-viewing period (3 s), and a subsequent coherence-rating period (4 s; Figure 1E). During object viewing, participants were instructed to determine whether the two object parts coherently belonged together without responding. They then provided a subjective coherence rating on a three-point scale (1 = not well,2 = somewhat well,3 = very well) within 4 s. The coherence ratings were not relevant to analyses included here and are not discussed further.

MRI data acquisition

MRI data were acquired on a 3T Siemens Magnetom Prisma scanner at the Toronto Neuroimaging Facility (University of Toronto) using a 32-channel receiver head coil. Highresolution T1-weighted structural images were acquired using an MPRAGE sequence with 1 mm 3 isotropic resolution (160 slices; FOV, 256x244 mm; 0 mm interslice spacing; echo time [TE], 2.40 ms; repetition time [TR], 2,000 ms; flip angle, 9°, GRAPPA acceleration factor, 2). For the purpose of MTL segmentation, high-resolution T2-weighted structural images were acquired in an oblique-coronal plane perpendicular to the long axis of the hippocampus with 2 mm slice thickness (42 slices; FOV, 220 mm; 0.4 x 0.4 x 2mm voxel size; 0 mm interslice spacing; TE, 68.00 ms; TR, 4,220 ms; flip angle, 165°; GRAPPA acceleration factor, 2). Functional images were acquired using a T2*-weighted multiband echo-planar imaging (EPI) sequence with oblique orientation and partial coverage focused on the MTL, extending from early visual cortex to the anterior temporal lobe (51 slices; FOV, 220x220 mm; 2 mm 3 isotropic resolution; 0 mm interslice spacing; TE, 30.00 ms; TR, 1,500 ms; flip angle, 90°; simultaneous multi-slice acceleration factor, 3) and 280 volumes were acquired per functional run (except for two runs from separate participants, which comprised 100 and 279 volumes, respectively; both were retained in the analyses). Participants completed five to seven functional runs while performing the experimental task.

Region-of-interest (ROI) definitions

Medial temporal lobe (MTL) gray matter regions were manually segmented on T2-weighted structural images following the Olsen-Amaral-Palombo (OAP) protocol (Olsen et al.https://www.zotero.org/google-docs/?mQiguO 2013; Yushkevich et al., 2015) , supplemented by a modified protocol for subdivisions of the entorhinal cortex (Olsen et al., 2017; based on Maass et al., 2015). Although the ERC has traditionally been characterized as a single MTL structure in the human neuroimaging literature, this approach enabled us to examine connectivity patterns associated with its anterolateral and posterior-medial subdivisions, consistent with emerging evidence that these subregions are differentially associated with the AT and PM networks (Maass et al., 2015; Navarro Schröder et al., 2015).

Briefly, the ERC is divided into the alERC and pmERC as follows, in line with previous work (Olsen et al., 2017) https://www.zotero.org/google-docs/?xRr4jA in the most anterior aspect, only alERC is present, then pmERC appears approximately 2mm after the first appearance of the hippocampal head. The boundary between the two subregions is defined by the uncal notch (Ding & Van Hoesen, 2015) and progressively moves ventrally in more posterior slices of the ERC. Finally, in the posterior portion of the ERC, only pmERC is present.

Two independent raters manually segmented the perirhinal cortex (PRC), anterolateral entorhinal cortex (alERC), posteromedial entorhinal cortex (pmERC), parahippocampal cortex (PHC), and three hippocampal subfields: cornu ammonis (CA)1, dentate gyrus (DG)/CA3, and subiculum on coronal slices of T2-weighted structural scans using ITKSnap ver. 4.0.0 (www.itksnap.org; Yushkevich et al., 2006). Raw volumes of each ROI were adjusted for the head size using a regression-based method, accounting for differences in the brain size between participants. Specifically, raw ROI volumes were corrected for intracranial volume (ICV), estimated using the Computational Anatomy Toolbox (CAT12) pipeline (neuro-jena.github.io; Gaser et al., 2024) in SPM12 (Statistical Parametric Mapping, Wellcome Trust Centre for Neuroimaging, University College London), which serves as a proxy for the head size (Buckner et al., 2004). Subject-specific segmentations were binarized to create individual ROI masks, which were subsequently transformed into MNI space for use in the present analyses. Given the absence of strong a priori predictions regarding hemispheric differences, separate masks were retained for each hemisphere to allow for exploratory characterization of connectivity patterns within and across hemispheres.

fMRI data preprocessing and denoising

Preprocessing and denoising of fMRI data were performed using CONN (Nieto-Castanon & Whitfield-Gabrielihttps://www.zotero.org/google-docs/?8ilsBm 2025; Whitfield-Gabrieli & Nieto-Castanonhttps://www.zotero.org/google-docs/?Zvc7aP 2012) , release 25.b, and SPM (Penny et al., 2011) , release 12.7771.

Functional and anatomical data were preprocessed using a modular preprocessing pipeline (https://www.zotero.org/google-docs/?lpo08A including realignment with correction of susceptibility distortion interactions, slice timing correction, outlier detection, direct coregistration to structural, direct segmentation and MNI-space normalization, and smoothing. Functional data were realigned using the SPM realign & unwarp procedure (Andersson et al.https://www.zotero.org/google-docs/?WIr72N 2001) https://www.zotero.org/google-docs/?kcdZI6 where all scans were coregistered to a reference image (first scan of the first session) using a least squares approach and a 6-parameter (rigid body) transformation (Friston et al., 1995) , and resampled using b-spline interpolation to correct for motion and magnetic susceptibility interactions.

Temporal misalignment between different slices of the functional data (acquired in interleaved Siemens order) was corrected following the SPM slice-timing correction (STC) procedure (Henson et al.https://www.zotero.org/google-docs/?F8Yh8S 1999; Sladky et al., 2011) , using sinc temporal interpolation to resample each slice BOLD timeseries to a common mid-acquisition time. Potential outlier scans were identified using ART (Whitfield-Gabrieli et al.https://www.zotero.org/google-docs/?KKuD5I 2011) as acquisitions with framewise displacement above 0.9 mm or global BOLD signal changes above 5 standard deviations (Nieto-Castanon, 2025; Power et al., 2014) , and a reference BOLD image was computed for each subject by averaging all scans excluding outliers. Functional and anatomical data were coregistered using the SPM intermodality coregistration procedure (Ashburner & Friston, 1997) with a normalized mutual information objective function (Studholme et al., 1998). Functional and anatomical data were normalized into standard MNI space, segmented into grey matter, white matter, and CSF tissue classes, and resampled to 2 mm isotropic voxels following a direct normalization procedure (Calhoun et al., 2017; Nieto-Castanon, 2025) using the SPM unified segmentation and normalization algorithm (Ashburner, 2007; Ashburner & Friston, 2005) with the default IXI-549 tissue probability map template. Last, functional data were smoothed using spatial convolution with a Gaussian kernel of 4 mm full width at half maximum (FWHM; ≤ 2 × voxel size).

In addition, functional data were denoised using a confound regression pipeline incorporating established nuisance regressors (Nieto-Castanon, 2020b). This included the removal of potential confounding effects derived from white matterhttps://www.zotero.org/google-docs/?P4zuPH CSFhttps://www.zotero.org/google-docs/?EdUvYA motion parameters and their first-order derivatives (Friston et al., 1996) , outlier scans (Power et al., 2014) , session and task effects and their first-order derivatives, and linear trends within each functional run, followed by bandpass frequency filtering of the BOLD timeseries (Hallquist et al., 2013) between 0.008 Hz and 0.09 Hz. CompCor regressors (Behzadi et al., 2007; Chai et al., 2012) were estimated within each subject's eroded white matter and CSF masks by extracting the mean signal and the largest principal components orthogonal to the mean signal, motion parameters, and outlier scans. Global signal regression was not performed.

gPPI analyses

First level

To study how task-modulated connectivity differed between novel, repeated, and recombined conditions, both within the MTL and between the MTL and other cortical regions, we conducted generalized psychophysiological interaction (gPPI) analyses. The 14 manually segmented MTL ROIs (left and right alERC, pmERC, PRC, PHC, CA1, CA3/DG, and subiculum) were used as seed regions. Target regions were defined either as other ROIs or as individual voxels, depending on the analysis (see Group-level analyses below). For each participanthttps://www.zotero.org/google-docs/?irjtiH a separate gPPI model was estimated for each seed-target combination (Friston et al., 1997; McLaren et al., 2012) , with seed BOLD signals as physiological factors, boxcar signals characterizing each individual task condition (i.e., repeated, recombined, and novel) convolved with an SPM canonical hemodynamic response function as psychological factors, and the product of the two as psychophysiological interaction terms. Task-modulated connectivity for each condition was estimated by the multivariate regression coefficient of the psychophysiological interaction terms in each model, yielding an individual connectivity estimate for each participant, condition (i.e., repeated, recombined, and novel), and seed-target combination.

Group level

To examine how connectivity within the MTL, and between the MTL and other cortical regions, varied across different forms of object novelty/familiarity processing, we conducted both ROI-to-ROI and seed-to-voxel group-level analyses. Both analyses used a General Linear Model (https://www.zotero.org/google-docs/?eU483W with first-level gPPI connectivity estimates entered as dependent variables and subject-level identifiers and experimental contrasts as independent variables. Inferences were based on random-effects statistics across participants and were corrected for multiple comparisons at the cluster level.

ROI-to-ROI.

To characterize task-dependent functional connectivity within the MTL, we conducted ROI-to-ROI analyses examining connectivity between pairs of manually-segmented MTL ROIs (left and right alERC, pmERC, PRC, PHC, CA1, CA3/DG, and subiculum).

Hypotheses were evaluated at both the cluster and individual connection levels. Cluster-level inferences used parametric statistics (F-tests) to assess connectivity differences across connections within and between functional networks. These omnibus tests identified significant connectivity differences between conditions across network pairs, without specifying the direction of those differences. Networks were identified using complete-linkage hierarchical clustering procedure based on ROI anatomical proximity and functional similarity metrics (Jafri et al., 2008; Nieto-Castanon, 2020a). Cluster-level effects were FDR-corrected at p < .05 (Benjamini & Hochberg, 1995). Individual connections were evaluated using connection-level ttestshttps://www.zotero.org/google-docs/?dc3IZ5 thresholded at p < .05, with positive and negative effects indicating greater connectivity for the first and second conditions, respectively. The experimental contrasts included repeated vs. recombined, recombined vs. novel, and repeated vs. novel.

Seed-to-Voxel.

To characterize task-dependent functional connectivity between the MTL and other cortical regions, we conducted seed-to-voxel analyses using four entorhinal cortex (ERC) nodes as seeds: left and right alERC and pmERC. These regions were selected because they provide a potential interface between the anterior-temporal and posterior-medial MTL systems and the hippocampus, and their proposed differential engagement in processing object and spatial/relational information (Ladyka-Wojcik et al., 2026; Maass et al., 2015; Navarro Schröder et al., 2015; Shen et al., 2016). Seed-to-voxel analyses used the same group-level GLM framework, with cluster-level inference based on Gaussian Random Field theory (Nieto-Castanon, 2020a; Worsley et al., 1996). Results were thresholded at p < .001 at the voxel level and FDR-corrected p < .05 at the cluster level (Chumbley et al.https://www.zotero.org/google-docs/?M6yqQx 2010) , with an additional Bonferroni correction across the four seed regions applied to the cluster-level significance threshold (p < .0125). These analyses were conducted only for the repeated vs. recombined contrast, which showed significant ROI-to-ROI effects and isolated connectivity differences associated with configural novelty/familiarity. Positive and negative effects indicated greater task-modulated connectivity between the ERC seed and target voxels for repeated and recombined objects, respectively. This enabled the characterization of broader whole-brain connectivity patterns and identification of regions outside the predefined MTL ROIs contributing to these effects.

Critically, manual MTL segmentation allowed us to examine connectivity within and between hippocampal, AT, and PM regions with high anatomical precision, including separate anterolateral and posteromedial entorhinal cortex subdivisions that are differentially associated with these networks (Maass et al., 2015; Navarro Schröder et al., 2015).

Discussion

Here, we examined how task-modulated connectivity varies during distinct types of object novelty/familiarity processing using generalized psychophysiological interaction (gPPI) analysis of manually-segmented MTL regions spanning anterior- temporal (AT) and posterior-medial (PM) networks.

Participants viewed repeated objects, comprising familiar features in familiar configurations; recombined objects, comprising familiar features in novel configurations; and novel objects, comprising novel features in novel configurations. The critical repeated vs. recombined contrast isolated configural novelty/familiarity while holding feature novelty/familiarity constant. Configural familiarity (i.e., viewing repeated vs. recombined objects) was associated with greater task-modulated connectivity across bilateral AT, PM, and hippocampal regions, as well as between right alERC and mPFC and between right pmERC and posterior-medial cortex. Conversely, configural novelty (i.e., viewing recombined vs. repeated objects) was associated with task-modulated reductions in this widespread connectivity pattern, with more focal connectivity increases between right pmERC and superior parietal and frontal regions. Neither featural novelty/familiarity (novel vs. recombined) nor global novelty/familiarity (novel vs. repeated) were associated with significant connectivity differences. Together, these findings suggest that configural novelty/familiarity is associated with altered functional coupling across distributed MTL and cortical regions, reflecting broad reorganizations of interactions across AT, PM, and hippocampal systems, extending beyond canonical object-processing regions.

One possibility is that the increased connectivity for configurally familiar (repeated) versus configurally novel (recombined) objects-spanning AT and PM regions, the hippocampus, and mPFC-reflects the availability of established conjunctive representations of repeated objects to reinstate.

That ishttps://www.zotero.org/google-docs/?I1ZL2c because repeated objects matched previously encountered feature conjunctions, viewing them may reinstate stored representations (McClelland et al., 1995; Norman & O'Reilly, 2003) , including their associated spatial and relational context. This may trigger stronger interactions among MTL regions involved in representing and retrieving object features (AT) and the spatial and temporal context in which it was encountered (PM, hippocampus). The involvement of mPFC may reflect its contribution to strategically controlling this reinstatement process (Preston & Eichenbaum, 2013). In contrast, recombined objects lacked pre-existing conjunctive-level representations to reinstate, and their reduced connectivity may therefore reflect the relative absence of associated contextual representations rather than reduced engagement of MTL regions themselves. This account assumes retrieval of repeated objects, despite the absence of explicit retrieval instructions. Eye-movement data from this task (https://www.zotero.org/google-docs/?LSahSDWojcik et al., 2026) showed hallmark signatures reflecting object memory (e.g., longer fixations to repeated objects and more fixations to novel objects; Heisz & Ryan, 2011).

The idea that greater MTL connectivity reflects the reinstatement of established conjunctive representations is consistent with evidence linking large-scale MTL network integration to memory reinstatement. Connectivity among hippocampal, AT, and PM regions increases during retrieval versus encoding, with greater inter-network connectivity associated with higher fidelity of reinstated content (Cooper & Ritchey, 2019). Accordingly, increased connectivity for repeated objects may reflect reinstatement of established conjunctive representations, whereas reduced connectivity for recombined objects may reflect greater reliance on encoding processes to form new representations of feature conjunctions and their associated contexts. The present findings extend this literature by suggesting that MTL network connectivity can differ even without explicit retrieval demands, raising the possibility that availability of an established conjunction can influence network integration incidentally.

If greater connectivity for repeated objects reflects reinstatement of established conjunctive representations, one would predict that connectivity patterns for the recombined objects would come to resemble that for repeated objects as the recombined conjunctive representations become established and available for reinstatement. This possibility is consistent with evidence that experience shapes conjunctive representations across the brain. For example, overlearned versus novel objects elicit more widely distributed conjunctive representations across posterior ventral visual stream regions, including the fusiform face area and parahippocampal place area, alongside stronger conjunctive coding in PRC (Liang et al., 2020). This may reflect a handoff from MTL to broader cortical networks as object conjunctions become established.

Relatedly, PRC has been proposed to modulate responses in lower-level visual cortex according to the familiarity of object configurations (Peterson et al., 2012). Future research could examine whether repeated exposure to initially novel conjunctions produces changes in MTL and cortical connectivity as representations become learned, and whether these changes coincide with a broader distribution of conjunctive representations across the brain.

However, if increased connectivity for repeated versus recombined objects merely reflects availability of pre-existing representations, why were similar increases not observed when comparing repeated versus novel objects (since novel objects were also new and thus lacked established representations)? One possibility is that recombined objects differ from novel objects because their familiar features are associated with established, but competing, conjunctions, requiring MTL processing to arbitrate among multiple representations while updating stored representations to reflect the new conjunction. In contrast, novel objects, whose features had never been encountered before, would not incur this competition. Alternatively, the absence of a matching conjunction alone may be sufficient to reduce connectivity, predicting similar effects for novel and recombined objects. However, connectivity did not differ significantly between these conditions, leaving the present design unable to distinguish between these possibilities.

Notably, connectivity was not uniformly greater for repeated versus recombined objects: recombined objects elicited greater right pmERC connectivity with the left superior parietal lobule and right frontal pole, regions implicated in top-down attention and cognitive control (Uddin et al., 2019). One possibility is that this reflects the demands of processing familiar features in new relational configurations. In rodentshttps://www.zotero.org/google-docs/?o7yLAY medial ERC (pmERC analogue) integrates visual object information with spatial relational representations (Høydal et al., 2019) , suggesting a role for pmERC in representing relationships between objects and their surroundings. Although this does not map directly onto human pmERC connectivity, greater pmERC coupling with the attention/control regions may therefore reflect increased attentional and control demands when familiar features appear in new configurations, requiring established representations to be evaluated or updated.

More broadly, our findings illustrate how connectivity analyses extend evidence from regional responses and structure-function relationships implicating PRC and alERC in conjunctive object processing (Barense et al., 2012; Buckley et al., 2001; Bussey et al., 2003; Ladyka-Wojcik et al., 2026; Ryan et al., 2012; Yeung et al., 2017). The involvement of these regions is consistent with representational-hierarchical accounts, which propose that increasingly complex conjunctive representations are supported by progressively more anterior regions (Martin & Barense, 2023; Saksida & Bussey, 2010). Extending this, our findings suggest that configural object processing involves not only specialized regional responses but also altered coordination across AT, PM, and hippocampal systems involved in object and relational processing (Ranganath & Ritchey, 2012). The connectivity patterns we report likely reflect changes in how information is coordinated across regions rather than simply reduced MTL engagement. However, the direction of information flow and the specific content represented by PM and hippocampal regions cannot be determined here. Future studies using approaches such as dynamic causal modeling (Friston et al., 2003) could characterize the directionality of these MTL interactions.

The finding that connectivity effects for configural object familiarity/novelty extended beyond canonical AT object processing regions (e.g., alERC and PRC), to PM spatial/relational regions (e.g., pmERC and PHC), is consistent with evidence that functional dissociations between these systems are not absolute. In rodents, PRC, LEC (alERC analogue), and MEC (pmERC analogue) represent both object and spatial information, though PRC and LEC preferentially encode objects and MEC preferentially encodes space (Keene et al., 2016). Similarly, human studies suggest that PRC and PHC are not restricted to a single information type, with PRC implicated in spatial navigation and complex scene processing, and PHC showing object-related recognition-memory signals (Bai & Coutanche, 2026; Brown et al., 2016; Hartley et al., 2003; Martin et al., 2018). Consistent with this overlap, alERC volume predicts object-in-place memory, suggesting a role in integrating spatial information into object representations (Yeung et al., 2019). Together, these findings suggest that configural object processing may recruit both AT and PM regions because object representations incorporate not only feature conjunctions, but also the relational context in which objects are embedded.

In summary, this work extends evidence from regional sensitivity implicating the AT system in configural object processing by demonstrating that configural object processing is associated with altered task-modulated connectivity across distributed MTL and cortical regions.

Configurally familiar (repeated) relative to configurally novel (recombined) objects elicited widespread increases in connectivity across anterior-temporal, posterior-medial, and hippocampal regions, as well as between ERC seeds and mPFC and posterior-medial cortex. Conversely, configurally novel (recombined) relative to configurally familiar (repeated) objects elicited more focal increases in pmERC connectivity with the frontal pole and superior parietal cortex. Neither featural nor global novelty/familiarity showed reliable connectivity differences. One possibility is that greater connectivity for repeated objects reflects reinstatement of established conjunctive representations and their associated context, whereas the connectivity changes for recombined objects reflect the demands of encoding new conjunctions and/or resolving competition among partially matching representations. More broadly, this work suggests that configural object processing is not confined to canonical object-processing AT regions, but also involves changes in how information is coordinated across PM and hippocampal networks that support relational processing.

Each block consisted of an exposure phase followed by a critical manipulation phase. Each object type was presented twice per block.
