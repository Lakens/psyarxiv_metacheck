Reporting p values imprecisely (e.g., p < .05) reduces transparency, reproducibility, and re-use (e.g., in p value meta-analyses). Best practice is to report exact p-values with three decimal places (e.g., p = .032) unless p values are smaller than 0.001, in which case you can use p < .001.

This module sometimes flags false positives when sentences discuss how p-value thresholds were set. It can also miss an imprecise p-value that is reported against a threshold (e.g., “decreased at the p < .05 significance threshold”).

Meta-scientific research has shown nonsignificant p values are commonly misinterpreted. It is incorrect to infer that there is ‘no effect’, ‘no difference’, or that groups are ‘the same’ after p > 0.05.

It is possible that there is a true non-zero effect, but that the study did not detect it. Make sure your inference acknowledges that it is possible that there is a non-zero effect. It is correct to include the effect is ‘not significantly’ different, although this just restates that p > 0.05.

How Power Analysis Check works

This module uses regular expressions to identify sentences that contain a statistical power analysis. If specified by the user, it also uses a large language model (LLM) to extract information reported in power analyses, including the statistical test, sample size, alpha level, desired level of power, and magnitude and type of effect size.

The Power Analysis Check module uses regular expressions to identify sentences that contain a statistical power analysis. Without the use of an LLM, the module uses regular expressions to classify the power analysis as a-priori, sensitivity or post-hoc. With the use of an LLM, it checks if the power analysis is reported with all required information.

The regular expressions can miss power analyses, or fail to classify them correctly. The type of power analysis is often difficult to classify, which can easily be solved by explicitly specifying the type of power analysis as ‘a-priori’, ‘sensitivity’, or ‘post-hoc’. Note that ‘post-hoc’ or ‘observed’ power is rarely useful. The LLM can fail to identify information in the paper, and will not have access to information in paragraphs in the paper other than those that contain the word ‘power’. This package was validated by the Metacheck team on articles in Psychological Science.

How StatCheck works

Check consistency of p-values and test statistics

The Statcheck module runs Statcheck. Statcheck searches for regular expressions that match a predefined pattern, and identifies APA reported statistical tests. More information on the package can be found at https://github.com/cran/statcheck. The module only returns Statcheck results for t-tests and F-tests, as these are the only tests which have been validated, see https://osf.io/preprints/psyarxiv/tcxaj_v1/.

Statcheck was developed by Michèle Nuijten and Sascha Epskamp.

Statcheck considers p = 0.000 an error, as you should report p < 0.001. Furthermore, p < 0.03 is an error if the p-value was 0.031, and one should simply report exact p-values (p = 0.031). When the sentence of a test says it is one-sided (“one-tailed”, “one-sided” or “directional”), a p-value that fits a one-sided test counts as consistent (statcheck’s OneTailedTxt setting; #695). When the paper says anywhere that its tests are one-sided, a p-value that fits a one-sided test in either direction counts as consistent too: half the two-sided p, or 1 minus that half for an effect against the predicted direction. Equivalence tests (TOST) are left out, as their p-values do not test the difference. A statistic written with “<” or “>” is read as a bound, and in a sentence about equal variances an F-test’s two-sided p (twice the one-tailed p) counts as consistent. For more information, see StatCheck.

This module only checks statistical results reported in the running text of the manuscript. It cannot (yet) process statistics reported only in tables.

How Exact P-Values works

List any p-values reported with insufficient precision (e.g., p < .05 or p = n.s.), reported as exactly zero (e.g., p = .000), or impossible (below 0 or above 1, e.g., p = -.22).

This module uses regular expressions to identify p-values. It will flag any values reported as p > ? or p < numbers greater than .001. It will also flag p-values reported as exactly zero (e.g., p = .000, p = 0.00), which are mathematically impossible — p-values are never exactly zero and should instead be reported as p < .001.

A p-value that is not the result of a test is not flagged: a table note (“* p < .05, ** p < .01”), a figure legend (“Asterisks indicate significant differences (p < .05)”, “Values in bold are significant at p < .05”) or a stated threshold (“p < .05 was considered significant”, “thresholded at p < .001”). GROBID often puts such notes into the running text, so each p-value is judged by the words in its own clause (the text up to a “;” or a full stop), and never left out when a test statistic belongs to it (“F(1, 7) = 8.03, # p < .05”). The column not_a_test of the table says why a p-value was left out (“marker”, “threshold”, “legend” or “named”).

A p-value with the name of a correction or a test after the p (“pFWE < .05”, “padj < 0.05”, “p Wilcoxon = .02”) is flagged only when a test statistic comes before it in its clause (“t(37) = 7.17, p FWE < .05”). Without one it is mostly the rule that decided what was significant (“genes with padj < 0.05 were selected”); such a p-value is “named” in not_a_test. Notes in other forms, such as a marker after the p-value (“p < .05 (*)“), are still flagged.

A p-value below 0 or above 1 is impossible; it is listed apart and not also as imprecise. Often the statistic before it, or its minus sign, was copied into it (“t(134) = -2.32, p = -.13”, “Z = 3.091, P = 3.091”). A value above 1 is listed only after a test statistic in its clause: without one, a “P” above 1 was nearly always another quantity (a proportion, pH, a group’s mean, a model parameter). A number in scientific notation whose power of ten was lost when the PDF was read (“p = 2.4 x 10 -9” read as 2.4) is not listed. A “p” that is the subscript of another symbol (“r p = .64”, “²p = .02” for partial eta squared, “Δp = .33”), or a quantity with a unit, a logarithm or a ratio (“P = 2.9 µm”, “-log10 P = 7.5”, “Ca/P = 1.67”), is not read as a p-value at all (see extract_p_values()). Each p-value has its own row, also when the same one is written twice in a sentence.

This module sometimes flags false positives when sentences discuss how p-value thresholds were set. It can also miss an imprecise p-value that is reported against a threshold (“decreased at the p < .05 significance threshold”).

This module only checks p-values reported in the running text of the manuscript. It cannot (yet) process p-values reported only in tables (as opposed to a table’s footnote text, which the module does see and tries to exclude — see above).

This module was developed by Lisa DeBruine and Daniel Lakens

Read more in the metacheck manual.

Validation: Validated on 226 Psychological Science papers with 5,019 hand-coded p-values, 438 of them imprecise (scienceverse/validation, branch stat_p_exact). Version 0.4.4.3 reported 419 p-values as imprecise, 388 of them correctly (93%), and missed 50 (89% found). Of the misses, 13 are starred table notes (“*p < .05”) that the module leaves out on purpose and 11 are p-values it did not find; of the wrong reports, 20 are p-values the ground truth does not contain (such as “ps < .05”) and 6 use ≤ or ≥. How Repository Check works

This module retrieves information from repositories.

The Repository Check module lists files on the OSF, GitHub, ResearchBox, DSpace (PsychArchives and other legacy- and DSpace 7-based installations), Zenodo, Dataverse, Figshare, Dryad, ReShare, 4TU.ResearchData, Mendeley Data, DataONE (Arctic Data Center, KNB, and other member nodes), and LDbase based on links in the manuscript.

A link to a file-sharing service (Google Drive, Dropbox, OneDrive, Box, WeTransfer, MEGA, iCloud Drive, Baidu Netdisk, SURFdrive; see [file_share_links()]) gets a warning and makes the light yellow: such services are not repositories, as files can be changed or deleted at any time, get no DOI, and the link stops working when the account is closed. The report advises a stable repository such as Zenodo instead. Their files are not read, and summary_table$file_share_n counts the links.

Deposits in archives for sequence and expression data (GEO, the INSDC archives BioProject, SRA, ENA and DDBJ, and ArrayExpress; see [seq_archive_links()]), mostly named by accession number, are read for whose deposit they are. The authors’ own are listed with what they hold ([seq_archive_size()]) and are not downloaded or checked as data and code; summary_table$archive_own_n counts them.

R packages on CRAN ([cran_links()], [cran_info()]) are the paper’s own when a paper author is a package author and the paper presents the package; the paper’s own are listed with their version and not checked (summary_table$cran_own_n). A Handle link (hdl.handle.net/...) that leads to a repository read here is checked as a link to that repository ([handle_links()]).

Listing a repository’s files never requires an API key, but some hosts answer faster or more completely with one: OSF allows 100 requests/hour unauthenticated versus 10,000/day with a token (see [osf_pat()]), and Dryad enforces a strict per-IP daily quota on repeated listing (see cache below). Dryad is a special case beyond rate limits: listing a Dryad dataset’s files works without a key, but actually downloading file CONTENTS from Dryad fails with HTTP 401 unless a key is set, even for a fully public dataset (see [dryad_pat()] or [dryad_auth()]). Since this module only lists files and never downloads their contents itself, that limitation applies to data_check and code_check (which do download content), not here – see their own documentation.

When a linked OSF page is a registration, its registered_from project (the one it was registered from, which the manuscript itself may never link directly) is also checked: if that project is public its files are listed under its own URL, and if it is closed or otherwise inaccessible the report flags it explicitly, since some registrations only describe their content rather than mirroring it.

Whose deposit is each link? The ownership table gives, for every repository linked in the text and (with references = TRUE) every deposit cited in the reference list, one of six labels: own_this (made by the authors for this paper), own_earlier_data or own_earlier_code (the authors’ own, from earlier work), others_data or others_code (made by other people, reused here), or not_data (a publication such as a preprint, not a deposit), with ownership_group (“own”, “others”, “not_data”) and the reason. It is decided without a language model, from the sentence or reference that cites the link, the paper’s authors (names, ORCID iDs, affiliations), and what the deposit’s own record and files say (who made it, what it names, when, whether it is a software package; for an OSF project cited only in the reference list, its record alone). On a round of labelled links the rules had not been written from, the three groups were right for 98% of links in the main text (93 of 95) and 90% in reference lists (74 of 82); the labels were made by Claude agents from each link’s evidence, and disputed ones checked against the deposits. Telling this paper’s own deposit from the authors’ earlier one is less certain.

Only the deposits that are this paper’s own are checked. A deposit linked in the text that holds other people’s work (others_data, others_code) or the authors’ earlier work (own_earlier_data, own_earlier_code) is listed in the report, with the reason, but its files are left out of table and kept in table_not_checked: they count toward nothing here (files that do not belong in a repository, naming, READMEs, studies, the traffic light), and code_check, data_check and reproducibility_check, which read table, do not check them either. reproducibility_check still puts the files of theirs that the paper’s code names in the folder the code runs in, as a re-analysis needs the data it re-analyses. When every linked deposit is set aside, the traffic light is “na”. A deposit that is the paper’s own is counted as such when its README, title or description names the paper (its title or DOI).

How Code Check works

This module retrieves information from repositories checked by repo_check about code files (R, Python, SAS, SPSS, Stata, Mplus, MATLAB).

The Code Check module checks R (also R Markdown and Quarto), Python (also Jupyter notebooks), SAS, SPSS, Stata, Mplus, and MATLAB files, using regular expressions to check the code; JASP files are listed but not read. The language of a Quarto document or a notebook is read from the file itself (its engine or kernel), not from its extension. The regular expression search will detect the number of comments, the lines at which libraries/imports are loaded, attempts to detect absolute paths to files, setwd() and install.packages() calls, and lists files that are loaded, and checks if these files are in the repository; R code is also parsed. The module will return suggestions to improve the code if there are no comments, if libraries/imports are loaded in lines further than 4 lines apart, if files that are loaded are not in the repository, if absolute file paths, setwd() or install.packages() are found, and if R code cannot be parsed.

The regular expressions can miss information in code files, or falsely detect parts of the code as a fixed file path. Libraries/imports might be loaded in one block, even if there are more than 3 intermittent lines. The module was tried out internally on papers published in Psychological Science, but has not been formally validated. There might be valid reasons why some loaded files can’t be shared, but the module can’t evaluate these reasons, and always gives a warning.

The module also checks whether the repository pins the R/package versions the analysis actually depended on: an renv.lock file (parsed for the R version and every locked package + its version/source), a sessionInfo()/sessioninfo::session_info() text dump (matched by filename — sessionInfo.txt/session_info.txt and similar, or embedded in a README), or a groundhog::groundhog.library()/checkpoint::checkpoint() date-pin call in the code (a bare library(groundhog)/library(checkpoint) does not count — the pinning call itself must be present). When none of these is found, the report flags it as a reproducibility gap: package versions may drift between when the analysis was run and any later reproduction attempt.

If you want to extend the package to perform additional checks on code files, or make the checks work on other types of code files, reach out to the Metacheck development team.

Checking code requires downloading its file contents. For a paper whose repository is on Dryad, this never succeeds unless a Dryad API key is set: Dryad requires one to download file bytes, even from a fully public dataset (listing the repository’s files does not need one). Without a key, every Dryad-hosted code file is listed but unchecked, and a warning naming Dryad and ?dryad_pat/?dryad_auth is included among the download failures recorded in the manifest.

How Data Check works

This module classifies the files in a repository into semantic types (data, codebook, code, software, output, supplemental, readme, asset, other) and, for tabular data files, extracts each column’s type and summary statistics.

The Data Check module consumes the file list produced by repo_check (or any files added via local_path). Each file is classified with rule-based heuristics layered over metacheck’s file_category() and file_types: file names matching README / codebook patterns win first, then an extension crosswalk, then format-locked extension overrides. For every file classified as tabular data that is available locally, the module reads the file head, describes each column with data_col_facets() and computes summary statistics for numeric columns. Every sheet of a spreadsheet that holds a table is read: a file with several such sheets has its columns under source_file = "file.xlsx [sheet]", and the sheet column names the sheet of any spreadsheet with several sheets; a sheet of notes or a codebook is treated as documentation when the file has another table. Following DDI, a column is described by orthogonal facets rather than a single type: representation (numeric/text/datetime/code — how it is stored), measurement_level (Stevens: nominal/ordinal/interval/ratio), concept (what it measures: reaction_time/age/gender/likert/id/…), role (identifier/measure/condition/timestamp), unit, and a quality state (ok/empty/constant). Concepts are detected by name+value rules (the demographic concepts via data_check_demographic()); when llm_use(TRUE) the model fills concepts and measurement levels the rules left blank. Qualtrics survey exports are recognised (data_check_is_qualtrics()): their extra header rows are stripped so columns type correctly, and the reserved response-metadata columns (StartDate, Duration, Finished, …) are tagged.

The module defaults to rules-only when llm_use(FALSE): columns the rules cannot resolve (ambiguous 3–20-unique integers, ambiguous character columns) fall back to continuous / text respectively. When llm_use(TRUE), ambiguous columns and unresolved file types (other) are sent to llm() for optional refinement, and every file is assigned a study group (ex1, pilot2, shared, …) so that multi-study repositories can be recognised (used by psychds_check). Without an LLM the study group is left NA (unknown).

Column extraction requires files to be readable from disk. Files fetched by repo_check from OSF/GitHub/etc. without a local copy (file_location is NA) are classified but not column-extracted; pass local_path to point at a downloaded copy of the repository.

For a paper whose repository is on Dryad, this means column extraction never happens unless a Dryad API key is set: Dryad requires one to download file bytes, even from a fully public dataset (dataset listing and metadata do not need one). Without a key, every Dryad file stays classified but un-downloaded, column_n is 0, and a warning naming Dryad and ?dryad_pat/?dryad_auth is included among the download failures. A one-time session message is also shown (see repo_check) the first time a Dryad dataset is encountered with no key set.

Every downloaded text file the authors wrote (code, settings, survey definitions such as Qualtrics .qsf files, documentation, outputs) is searched for keys: API keys, access tokens and private keys, which let anyone who downloads the file use a paid service at the authors’ cost. Of a tabular data file only the column names and first 3 rows of the table as read are searched: its values come from participants, but a key the authors set for a whole survey (as embedded data in a Qualtrics survey flow) is exported in every response. The search uses the rules of the secret scanner betterleaks (https://github.com/betterleaks/betterleaks, MIT licence) of high and medium confidence. A key found turns the traffic light red; the report and the keys table give its file, line and type, and only its beginning. Other files over 25 MB and binary files are not searched. A key is never tested with its provider. Every module’s result has any whole key replaced by “keyremoved” (see module_run()).

How Reproducibility Check works

This module assesses whether a paper’s R and Python code can be run on its data. It works in two phases. The static phase (always run) collects the package dependencies the code declares, rewrites the data-file paths that do not work in the repository as the authors organised it, works out the order the scripts must run in, and diagnoses why any referenced input file is unavailable — reporting what a reproduction attempt would involve and where it is likely to break. The execution phase (opt-in, execute = TRUE) then actually runs the code: it copies the repository into a throwaway directory, optionally installs the declared dependencies into a throwaway library, runs each script in order in an isolated subprocess with a per-script timeout, and captures the outcome and full output of each run.

By default (execute = FALSE) the module does not run any code — it performs only static analysis: reading dependencies with the same extractors as code_check, finding the files the code references in the repository, and building a run-order dependency graph. It reports what would be installed and run rather than doing it.

When execute = TRUE, the module additionally runs the downloaded code on your machine — a deliberate, opt-in action gated behind that argument (callr is required for R code). Each script runs in an isolated subprocess so a crash cannot take down the R session; note this isolates crashes, not the filesystem or network. Installs (when install_missing = TRUE) and the throwaway run library never touch your main R library. Each script’s outcome is one of ran_ok, errored, timed_out, dependency_unavailable, not_parsed, run_by_source (an R script another script runs with source(), which is run only inside that script, since on its own it lacks the packages and objects the sourcing script sets up first), run_by_import (a Python file other files import, a module rather than a script, unless it has an if __name__ == "__main__": block), jags_model (a JAGS or BUGS model saved with an R extension, which another script reads) or not_r_content (a file that is not R at all, such as a JSON or HTML dump); these last two are not run and are not failures. python2 marks Python 2 code that was not run. With sandbox = "docker" such code runs with Python 2.7 (option metacheck.docker_image_py2; FALSE turns this off), which modifications records; it is never converted, since that can change results. defines_functions is a file that only defines functions, which is used, not run (table$used_by names the scripts that use it), and not_analysis is a file of software rather than of the analysis: a package’s code, tests, documentation or setup.py, a copy of a tool, a web application, a script a program wrote (table$not_analysis_why says which); neither is run or counted as a script. docker_failed means the container never started, which says nothing about the script, so it keeps the light from being green but does not make it red. needs_a_person is a script that stopped because it asks a person to choose a file or answer a question, or that starts an app, and needs_internet one that stopped because the network is off in a Docker run, or, with internet = TRUE, could not reach what it asked for; download_too_large is a script stopped for downloading more than the limits allow (see internet), and out_of_memory one that, or a program it started (such as a compiler), ran out of the memory each script may use. All four are treated the same way. not_downloaded is a script that stopped on a file the repository lists but that was not downloaded, such as one over max_file_size: it could not be tried, so it is not counted as a script that did not reproduce (summary_table$repro_not_downloaded_n counts them apart). not_read is a file metacheck could not read, so it was not run; the light is then not green, as the file may read and run on another computer, and table$error_message says why, naming a package that is installed but cannot be loaded on the computer that ran the check. empty is a file with nothing in it, which is not run or counted as a script. For a script that did not run through, table$error_message is its error, short (at most 300 characters): the error line of its output, which names a package that is not there, with the address it asked for when it needed the internet, or the time limit it reached; table$reason sorts it into a kind. A timeout means “still running at the cutoff”, not a failure, so raise timeout for legitimately long-running (e.g. Bayesian) scripts. dependency_unavailable means the script’s own package could not be installed from live CRAN, the CRAN Archive, or a named GitHub/URL source — an infrastructure limitation, not a defect in the paper’s code. The full stdout/stderr of every run is kept in the result’s run_results (the report shows it in per-script dropdowns, capped for readability).

Provenance, kept so that a TRACE Research Object (TRO) declaration of the run can be written later from a stored result (metacheck #404; the helpers are in R/provenance.R). Only when code was run (execute = TRUE): * run_results$started_at, run_results$ended_at: when each run of a script started and ended (ISO 8601, UTC, milliseconds); NA for a script that was not started. A script run again in a later pass has the times of its last run. A TRO uses them for each trov:TransparentResearchPerformance. * run_results$exit_status: the exit status of the process that ran the script (0 = ended normally); NA when the process did not report one (a time limit, or Docker failing to start the container). * artifacts: one row per file, with stage (deposit: as downloaded from the repository, hashed from the downloaded file; before_run: the run folder just before the first script ran, after metacheck’s own changes, such as rewritten paths and unpacked archives; after_run: only the files the scripts made (status new), changed (changed) or removed (removed), as an unchanged file is the one listed before the run), path (relative to the run folder, as valid UTF-8, a byte of another encoding written as <xx>), size (bytes), sha256, mime_type (by extension, NA when unknown), source (the file’s address in the repository, for deposit). The package libraries metacheck installs in the run folder are left out, as are metacheck’s own files there (a script’s runner, and the statistical output it writes in statistical_output/). Files metacheck itself copied or made between passes (see modifications, output_copied, file_placed) show in after_run too. A TRO uses the rows as trov:ResearchArtifacts and each stage as a trov:ArtifactArrangement. * modifications$sha256_before, modifications$sha256_after: the hash of the changed script as downloaded and as it ran; NA when the script is not at the same path in both (a script made from an R Markdown file). * environment: the system that ran the code (trov:TransparentResearchSystem in a TRO): metacheck_version, started_at, ended_at, host (R version, platform, operating system), sandbox, network_isolated (TRUE only when every Docker run had --network none; the process sandbox does not stop the network), internet, timeout_per_script, total_timeout, python_local (the Python run outside Docker and its version), and docker: runs (for each kind of run, r_run, r_install, python_run, python_install, the image and the docker run arguments, such as --network none, --read-only, --cap-drop ALL, no-new-privileges, the process limit and the memory and processor limits) and images (for each image, its ID and digests from docker image inspect, its creation time and the R and Python versions its environment declares).

run_results$checked says what the run of each script shows about the code, in five groups, so that a script that does not reproduce is kept apart from one the check could not test: ran (it ran to the end); code_error (it did not reproduce: it stopped with an error of the code or the deposit, could not be read, or needs a file the deposit does not hold); dependency (a package or program was not available: a package that could not be installed or was not loaded, a program outside R and Python, a system library, or R crashing in a package’s compiled code); time (it did not finish within the time limit for one script, or was not started because the time for all scripts had run out); and not_checkable (it could not be checked automatically: it needs a person, the internet, a key or another setting of the authors’ computer, one platform such as Google Colab, Windows or OpenSAFELY, more memory than the run allows, a file that was not downloaded, a screen, or a program that runs it, or it is a file of a package of the code that Python runs only as a module of that package). It is NA for files run inside another script, files that are not an analysis, files not read, and a Docker failure. summary_table counts each group (repro_ran_n, repro_code_error_n, repro_dependency_n, repro_time_n, repro_not_checkable_n), and the report’s first sentence gives them. The traffic light reflects the static readiness signals by default; a script in code_error that stopped with an error makes it red, as a script that crashes on its own analysis is a genuine reproduction failure, and a script in one of the other three groups keeps it from being green. Calls that need a screen, which the run does not have (dev.print(), dev.copy2pdf(), dev.copy2eps(), savePlot(), windows(), win.graph(), x11(), quartz(), View()), are replaced before the run by calls that need none, which modifications records as screen_call_replaced. A script that fails with could not find function is run once more with the library() calls the project’s other scripts make added at its top (or the one package that exports the function, or magrittr for %>%), and a script that then runs is reported as reproducible only after that repair.

Dependencies are reported name-only, with the source (CRAN, GitHub, or a base package already shipped with R) — static analysis of the code cannot know which version was used, and running against current package versions is itself informative: a break argues the authors should have pinned versions. When the repository does record versions, a run with recorded_versions = TRUE installs the packages the scripts load at those versions, but it does not change the R version, which remains a limitation of the check.

Run order is derived from read-after-write data dependencies (a script writing a file another reads must run first), source() edges, and numeric filename prefixes as a weak tie-breaker. Ambiguous orderings, dependency cycles, and inputs a script reads but that no earlier script produces (and that are not in the repository) are surfaced as warnings, since these are the situations most likely to make an otherwise-correct reproduction fail.

Python code (.py files, and notebooks and Quarto documents whose code is Python, from which the code is extracted first) goes through the same two phases, reported in its own “Python code” section. Each file is checked for syntax errors with Python’s own parser when a Python interpreter (python, or else python3) is available; dependencies are read from the import statements, with versions from a requirements.txt or pyproject.toml when there is one, and installed with pip; each script runs as its own python process (processx is required), so unlike R scripts, a name one script defines is not available to another. When no Python interpreter is available, the Python files are reported as not run and the R results are still returned. Statistics the Python scripts print are compared with the paper together with the R output and any self-reproducible output (JASP/jamovi, SPSS-Viewer, notebook outputs).

Abstract

Our goal-directed attentional control abilities enable us to flexibly maximize how efficiently we search the visual environment. However, a growing body of research reveals that we often fail to use these abilities. Here, we question how motivational incentives might be used to improve attentional control strategies. Using the Adaptive Choice Visual Search (Irons & Leber, 2018), a task designed to measure attentional strategy use, we manipulated motivation in two ways. In Experiment 1, we limited the exposure of the visual search items, and in Experiment 2, we provided a greater monetary reward for faster search performance. In both experiments, we reasoned that participants would choose the search strategies that enabled faster target identification times; faster search would reduce errors in Experiment 1 and increase earnings in Experiment 2. Results showed that the time-pressure manipulation failed to induce more optimal strategy choices, while the performance-contingent reward manipulation did induce a modest improvement in strategy. Overall, we find some evidence of a link between motivation and strategy optimization, although methods to elicit a more robust boost in optimization remain elusive. Further work is needed in this understudied but vital domain of research.

Investigating the Factors Motivating the Adoption of Optimal Attentional Strategies

Life on this planet reached a critical juncture when animals began to exhibit flexibility in how they respond to environmental stimuli, and humans today are particularly distinguished by the extent that they bear this evolutionary adaptation. For example, when our goal is to find a friend wearing a red shirt, we can selectively attend to red things while ignoring salient moving things, like a bouncing ball; further, in the same exact scenario, when our goal is to find that ball, we can instead attend to moving things while ignoring salient red things. Beginning nearly 35 years ago, Charles Folk and Roger Remington, along with their colleagues, dramatically pushed the envelope in demonstrating the degree to which humans can exert goal-driven control over attention (Folk et al., 1992 (Folk et al., , 1993 (Folk et al., , 1994;; Folk & Remington, 1998; Remington et al., 2001). Their work offered striking demonstrations that the involuntary processing of various classes of distracting stimuli --previously thought to automatically capture attention -were contingent upon our behavioral goals.

The evidence provided by Folk, Remington, and colleagues for their contingent involuntary orienting hypothesis represented a watershed moment in how we understand the scope of human abilities to flexibly wield attention, but it also ushered in many new questions.

One such question is that, if people have the ability to configure their attentional control settings to match their current goals, then why do they not always use this ability? That is, why do people so often allow distraction by salient stimuli, such as abrupt onsets (Yantis & Jonides, 1984), salient colors (Theeuwes, 1992), or moving stimuli (Franconeri & Simons, 2003)?

Folk and colleagues mused on this question when addressing why abrupt onsets seemed to possess a special status in capturing attention (see Jonides & Yantis, 1988): "when there is little motivation to configure the system for any other property, abrupt luminance change (or dynamic discontinuities in general) may be instantiated as the 'default setting'" (Folk et al., 1992 (Folk et al., , p. 1042)). This sentence established two important ideas. First, implementing an attentional control setting is an act that requires some degree of motivation. Second, in the absence of a particular control setting, individuals operate with a default setting. These ideas are provocative, but they have not stimulated the same magnitude of research as the more spirited topics of debate surrounding attention capture in the past 30+ years. Bacon and Egeth (1994) weighed in, very much following the logic of Folk et al. (1992), when they speculated that individuals default to a salience driven search -i.e., "singleton detection mode"when they lack sufficient motivation to adopt a more precise "feature search mode." Kawahara (2010) used a novel operant conditioning method to identify what individuals' default attentional settings were, finding that participants were generally "singleton detectionists." Alternative interpretations do exist, however, as one recent paper has argued that feature search mode may demand less effort than singleton detection mode (Lee et al., 2024). Clearly, more work is needed to understand how motivation relates to goal-directed attentional control, In this paper, we directly tackle the subject of how motivation drives attentional control settings. When considering this subject, we must first invoke the construct of the optimal strategy, which we define as that which maximizes behavioral success, yielding the fastest response times without sacrificing accuracy (see, e.g., Zhang & Leber, 2024). When Folk et al. (1992) and Bacon & Egeth (1994) speculated that participants were not sufficiently motivated to avoid irrelevant distraction, they implied it would have been desirable by some behavioral yardstick to have done so. For example, in the task of Theeuwes (1992), attentional capture carries a response time cost, which confers a behavioral disadvantage. Egeth, Leonard, and Leber (2010) explicitly entertained this idea, calculating the cumulative response time cost of distraction in the Theeuwes study to be a few seconds across the entire session and concluding that perhaps the time saved by adopting a feature search mode was not desirable enough to justify the required effort investment (see also Leber, 2021). These costs of suboptimality are perhaps somewhat paltry, and in exploring how motivation might impact attentional control, we arguably should focus on scenarios in which it would be more decisively advantageous to choose an optimal strategy. At the same time, we must also consider conditions in which a motivational roadblock prevents the use of the optimal strategy. With these considerations in mind, a growing body of work has exposed a variety of ways in which individuals use suboptimal strategies during attentional tasks in ways that provide substantial behavioral costs (Araujo et al., 2001; Boot et al., 2009; Clarke et al., 2022; Irons & Leber, 2016 , 2018; Nowakowska et al., 2017; Pauszek & Gibson, 2016; Rajsic et al., 2015). Experiment 2), a search display shows red, blue, and green squares, each containing a digit from 2 to 9 (see Figure 1). Two targets appear on each trial, with one in the red squares and the other in the blue squares. These targets always have digits 2, 3, 4, or 5, but the two targets are never the same digit. Participants are explicitly told they can choose to search for either target, and they only need to report one. Importantly, on each trial, one color subset (red or blue) contains fewer items than the other, with approximately a 1:2 ratio of items. Therefore, the quickest way to perform the task is to selectively search through the less numerous color subset. The color of the small subset changes unpredictably, so in order to realize the performance advantage of searching the small subset, participants must take on the added cognitive operations of comparing the color subsets on each trial (Hansen et al., 2019). The main measure of strategy use in the ACVS is the percentage of trials in which participants report the target from the less numerous color subset (i.e., the "optimal" target; we refer to this dependent measure as optimality). We have observed significant individual differences in this measure, which show good reliability and stability across tests, as well as good internal consistency (see Irons & Leber, 2020). Perhaps the most striking finding is that participants are largely far from optimal, typically with mean optimality not exceeding 70% (Clement & Anderson, 2023; Irons & Leber, 2016; Lee et al., 2022; Zhang & Leber, 2025). These relatively low levels of optimality seem especially surprising given that searching with chance-level optimality (i.e., 50%) is approximately 1000 ms slower per trial than searching with 100% optimality, based on analysis of our data from Zhang et al. (2024). That is, the average suboptimal participant is about 45% slower than the average optimal participant, which translates to a cumulative cost of about 8 minutes across our typical experimental sessions. Note that this is due to strategy and not slower search speed for suboptimal individuals, as ACVS optimality does not tend to relate to RT in control single-target search tasks (Irons & Leber, 2018).

Due to the robust psychometric properties of the ACVS, we have been able to systematically investigate why people would perform suboptimally. For example, we have tested whether some participants are simply unaware of the optimal strategy and whether some simply need more time to implement and configure the optimal attentional control settings (Hansen et al., 2019; Zhang et al., 2024). Indeed, when observers are explicitly told which strategy is optimal and given time to prepare, their search optimality does enjoy modest improvements, but optimality nevertheless does not approach ceiling. More recently, we have begun to investigate the motivational account, in which strategy choice is impacted by avoiding the cognitive effort required to achieve the optimal strategy. Two key pieces of evidence have supported this account. First, Irons and Leber (2018, Exp 2) designed an "enforced optimal" version of the task in which participants had to report only the small-subset target on each trial. We then asked participants to rate how effortful this version of the task was, and these ratings negatively correlated with optimality scores in a separate block of Standard ACVS trials. That is, those who found it more effortful to perform the task optimally were less likely to do so when they were given the option to search optimally or suboptimally. Second, Zhang and Leber (2024) implemented a demand selection procedure (Kool et al., 2010), in which participants could choose between two modified versions of the task. The subset cue version was similar to the enforced optimal task of Irons and Leber (2018), in which participants had to find a single target within a cued subset on each trial. The color cue version was matched in every way, except participants only had to find the target within a cued color. The former version of the task carried the additional cognitive load of comparing the numerosity values of the two subsets to determine which subset to search. The demand selection procedure revealed an overwhelming preference for the color cue, demonstrating avoidance of the cognitive effort required to perform the ACVS optimally.

To summarize, our recent work has revealed a key motivational conflict. On the one hand, participants should be incentivized to choose the optimal strategy in order to complete the task much faster than if they choose a suboptimal strategy (i.e., about 8 minutes per experimental session). On the other hand, the drive to avoid the cognitive operations required to achieve the optimal strategy may lower participants' willingness to adopt it. When combining these two conflicting sources of motivation, one's degree of optimality can depend upon the relative weighting of the two.

In this study, we explore how we can tip the balance between these conflicting sources of motivation to favor greater strategy optimization. Discovering factors that increase motivation to optimize attentional control have potential real-world consequences, as efficiency is highly prized in today's fast-paced world. Moreover, finding such factors will improve our basic understanding of how goal-driven attention is controlled. That is, we know so far that motivation plays an important role, but we still lack the knowledge about what factors increase motivation to behave more optimally.

Recent work by Nowakowska et al. (2021) provides important clues. They were interested in understanding whether and how people use saccadic eye movements to maximize information gain during a visual search task, using the split-half line segment task (Nowakowska et al., 2017). In this task, participants search for an oriented bar, which either pops out among homogeneous distractors on one side of the display or is much less conspicuous among heterogeneous distractors on the other side of the display. Since the target can be detected covertly on the homogeneous side, eye movements to this side are unnecessary and significantly slow response times, yet many participants frequently make these saccades anyway. Nowakowska et al. (2021) attempted to motivate participants to make saccades more optimally in two different experiments. In the first experiment, they limited the display exposure to 2000 ms, which decreased accuracy. The authors reasoned that participants would be incentivized to use saccades more optimally, in order to increase their odds of finding the target before the display was removed and thus reduce errors. However, the researchers found no reduction in irrelevant saccades to the homogeneous side during the reduced display exposure. In the second experiment, they gave participants a financial bonus for faster response times (RTs), reasoning that more optimal saccade placement would help to facilitate target detection times and thus confer greater rewards. Nevertheless, the authors once again failed to find a benefit of the manipulation.

There are notable differences between the split-half line segment (SHLS) and the ACVS tasks. The former is concerned with how individuals control the oculomotor system to maximize information gain, while the latter is concerned with how individuals implement feature-based attentional control settings. We have previously observed that rates of strategy optimization in the SHLS and the ACVS show negligible cross-task correlations, despite each task having good test-retest reliability (Clarke et al., 2022), revealing that the factors driving strategy choice in these tasks are independent. Moreover, participants in the ACVS typically have good metacognitive knowledge about their strategies (e.g., Irons & Leber, 2016; Irons & Leber, 2018), but it is unknown whether those in the SHLS do. Recent work with other eye movement tasks has suggested that individuals have poor metacognition about their fixation locations (Clarke et al., 2017; Marti et al., 2015). It is thus possible that, given greater conscious access to their strategy use, participants in the ACVS task will be more receptive to motivational manipulations.

The present experiments are conceptually similar to the time-pressure and reward experiments conducted by Nowakowska et al. (2021), and our goal is to determine whether these manipulations succeed in boosting strategy optimization in the ACVS.

In Experiment 1, we use a time pressure manipulation. Time pressure has classically been used in cognitive tasks to elicit criterion changes along the speed/accuracy tradeoff function, in which individuals prioritize speed at the cost of increased errors (Pachella et al., 1968). However, multiple strategies are often not available in typical time-pressure manipulations. As reviewed by Nowakowska et al. (2021), time pressure manipulations in behavioral decision making studies has shown participants to alter their decision rules (Svenson & Edland, 1987). In the ACVS task, an individual who knows the optimal strategy but avoids the effort associated with it might begin using the optimal strategy to enable faster search without sacrificing accuracy. Here, we manipulated the duration of the digit search display in ACVS and evaluated participants' search optimality. In some blocks, in half of the trials, the digits were masked after a short period, although participants were allowed to respond afterward. We created three conditions for the digit exposure duration: 1 s, 3 s, and not masked (10 s). Given that searching the smaller subset speeds search in the ACVS, we predicted that participants would adopt a more optimal search strategy when facing strong time pressure (e.g., 1 s digit exposure).

For Experiment 2, we used a performance-contingent reward manipulation, in which we provided a greater monetary bonus for faster response times. The rationale for this manipulation is similar to the time-pressure experiment, in which our goal is to incentivize faster search.

Similar to the time-pressure manipulation, studies that reward faster performance have also classically shown a shift in the speed/accuracy tradeoff function (Fitts, 1966; Snodgrass et al., 1967). Once again, our rationale is that, in the ACVS task, participants with the option to adopt the optimal strategy will choose to do so, in order to speed performance without sacrificing accuracy. For Experiment 2, we introduced a rewarded phase of the ACVS, where monetary rewards were assigned on each trial. For the experimental (Performance Contingent) group, the reward values were based on response speed, while for the control (Random Rewards) group, the reward values were chosen at random. Importantly, we did not directly reward specific choices, but the consequences of their choice (i.e., response speed). Once again, similar to the time-pressure-based motivation we predicted that shifting the effort-reward trade-off in the ACVS would result in a shift towards more optimal strategies.

Experiment 1

As our first attempt to motivate greater optimality, we limit search exposure durations in this experiment by masking the display digits. Our approach is for the participants to have different expectations about their search accuracy in the different block types. For example, when the digits are masked after only 1 s, participants should expect to make many errors. In contrast, when participants know they will have 10 s to search the display, they should generally expect ceiling-level accuracy. We parametrically manipulated exposure across three different block types: 1-s, 3-s, and 10-s (the 10-s condition is used as a baseline, as this matches the response deadline used in the standard version of our task). There are some limitations in interpreting ACVS performance when accuracy is low (something we discuss further in the results section), so for each block, we only present the exposure-limited trials 50% of the time and mix them with non-limited trials (i.e., 10 s). Given the random mixing of trials within blocks, participants cannot anticipate when a limited or non-limited trial will appear. Therefore, their expectations should still differ across the blocks, and we should be able to measure variations in performance stemming from differences in their expectations on the non-limited trials.

We anticipated that the short-exposure blocks would bring increased motivation to search optimally. Since searching the small subset enables participants to find the target more rapidly, optimal search will increase the likelihood of identifying the target before the mask appears on short-exposure trials. Therefore, whereas optimality typically speeds RT, it should also increase accuracy for the short-exposure trials. We hypothesize that the added incentive to increase accuracy will drive participants to be more optimal on the short-exposure trials, while this added incentive is not present on the long-exposure trials. Stimuli and Procedures

We conducted this experiment online. Participants used their own computers, so screen sizes and viewing distances varied across individuals. Therefore, we cannot report stimuli in visual angle degrees. Instead, we report stimulus sizes in fixed visual angle units. This unit was created such that, on a typical 24-inch display with a viewing distance of 68 cm, 1 unit equals 1º of visual angle.

Adaptive Choice Visual Search

The stimulus contained 54 colored squares sized 1*1 unit. Among them, there were 13 red squares, 13 blue squares, 14 green squares, and 14 variably colored squares. The color of the variable squares alternated between all red and all blue for runs of one to six successive trials. All colored squares were randomly arranged in three concentric rings around a fixation cross at the center of the screen. The radii of the inner, middle, and outer rings were 5.6, 8.5, and 11.3 units, respectively. The number of colored squares in the inner, middle, and outer rings were 12, 18, and 24, respectively, each spaced equidistantly within their respective rings. Each colored square contained a white digit (0.65 units, font: Arial) placed at the center of the square. Two digits randomly picked from the set [2,3,4,5] without replacement served as targets on each search trial, with one in the red set and one in the blue set. For all other red and blue squares, digits from the set [6,7,8,9] were randomly assigned. Green squares contained digits randomly chosen from 2 to 9; the inclusion of all digits served to dissuade participants from ignoring color and adopting a deliberate search for the target digits (see Figure 1). Procedure

We instructed all participants that they would view search displays containing two targets (red and blue) on every trial and that they only needed to find one. They were always free to search for either target on each trial. We also informed participants of the optimal strategy; specifically, we displayed a message on the screen stating that the fastest way to do the task is to look for whichever color has the fewest squares.

On each search trial, a fixation cross was first displayed at the center of the screen for 500 ms, followed by a 1000 ms preview which contained the colored squares only, without any digits. We have used these preview displays to allow participants to start preparing to search through the optimal color subset before the search onset, if they choose to do so (Hansen et al., 2019; Zhang et al., 2024). With this preview the time required to determine and implement an attentional template for the optimal target color need not constitute time that could be spent searching at the onset of the digits. After the preview, the digits were superimposed on the squares, at which point search for the target digits could commence. Upon finding a target, participants identified its digit by button press on a standard keyboard (V, B, N or M, corresponding to 2, 3, 4 or 5 respectively). Upon response or after 10 s, all stimuli were removed from the screen. An error message was displayed for 1000 ms when participants failed to respond or reported an incorrect target.

Across blocks we manipulated the digit exposure duration, which could be 1 s, 3 s, or 10 s, the last of which was the baseline condition. In each of these blocks, the exposure duration was imposed on 50% of trials, while the remaining trials were standard ACVS trials, in which the digits were available for up to 10 s. This manipulation was designed to create variable expectations of the time allowed to search across blocks. For example, in a 1-s block, participants would enter each trial anticipating that the digits might only be visible for a short period of time; we reasoned that this should incentivize the participants to search as quickly as possible before the digits became masked. The exposure duration was enforced by replacing all digits with the "#" symbol in the 1-s and 3-s blocks. Since all trials were terminated at 10 s, these masks were not used in the 10-s blocks. Participants were able to respond after the masks appeared, although they would of course no longer be able to search for targets. Participants were informed what exposure duration they would receive at the beginning of each block. They were encouraged to respond as quickly and as accurately as possible.

Six total blocks of 84 trials were presented (42 exposure-limited and 42 unlimited trials per block). The exposure condition was fixed for each block, and participants performed each of three exposure conditions blocks twice, once in the first three blocks and a second time in the latter three blocks. The order of the first three blocks was fully counterbalanced across subjects, and the second set of three blocks repeated the ordering of the first three blocks. For the 1-s and 3-s blocks, we randomized the presentation order of masked and unmasked trials, with the constraint that no more than two trials with digit masks occurred consecutively. Between each block, participants could take self-paced breaks.

At the end of the experiment, participants received a "strategy awareness check," designed to test whether they were explicitly aware of the optimal search strategy. For 10 trials, participants were shown an array of colored squares without digits, which was the same as a preview stimulus during the search trials. They were told to imagine that they were still performing the search task and were asked to report whether they thought it would be faster to find the target by searching through the red or the blue color subset. Responses were made by clicking one of three choices marked "Red," "Blue," or "None of the above," displayed on the right side of the screen.

Optimality

For the exposure-manipulated trials, we present the optimality data for completeness, but we recommend caution in interpreting the results. Recall that accuracy was well off of ceiling, particularly for the 1-s condition. While we only compute optimality on trials with correct responses, the results inherently include trials in which the participant was guessing.

Mathematically, the measured accuracy rate can be inferred as a mixture of a 50%-correct rate on guess trials and a 100%-correct rate on no-guess trials. For example, a participant who knows the answer on 50% of trials and guesses on 50% of trials would yield a 75% accuracy rate, and half of the guess trials would be correct (i.e., 25%). Guess trials are expected to be 50% optimal, so even if a participant with 75% accuracy is searching the small subset on every trial, their calculated optimality rate would be 87.5%. In contrast, when the same participant is 95% correct (e.g., in the 10-s trials), their optimality rate would be calculated as 97.5%. Thus, the optimality rate that we measure on these masked trials is misleading. With this in mind, we observed significant differences in optimality across three conditions (F(2,102) = 50.635, p < .001, 𝜂 𝑝2 = .498; see Figure 3C). Overall, participants showed high awareness of the optimal strategy (M = .883, t(52) = 11.6, p < .001, d = 1.61), similar to rates of awareness in previous experiments in which we explicitly informed people of the optimal strategy at the beginning of the experiment (Zhang et al., 2024).

Discussion

The main finding is that short-exposure blocks failed to motivate greater optimality than the baseline 10-s blocks. In fact, participants were less optimal -and less accurate -on the 1-s blocks, even for the 10-s exposure trials. Based on the awareness check data, the participants did understand that searching the smaller subset would have led to faster search performance, which suggests that metacognition is not a sufficient condition to achieve boosts in optimality in a timepressured environment.

There are several potential reasons why this manipulation failed to boost optimality.

First, it is possible that the participants were insensitive to their accuracy rates. As discussed in the introduction, our previous work has shown that a boost of roughly 1000-ms in RT for optimal vs. suboptimal search has not been sufficient for many participants to search optimally.

Likewise, in this study, a boost in accuracy for optimal search might not be a sufficiently strong incentive to shift the balance between desire for behavioral gains and effort avoidance.

Second, while time pressure generally speeds performance, it can sometimes elicit a less strategic state, akin to "choking under pressure" (Baumeister, 1984; Beilock & Carr, 2001).

Time pressure has also been shown to reduce exploratory behavior (Wu et al., 2022), which could translate to participants being less likely to test different strategies -and thus try the optimal strategy -during the experiment.

Experiment 2

Methods Preregistration

We previously conducted unpublished experiments to investigate the impact of performance-contingent reward on ACVS optimality, which each yielded relatively small effect sizes (e.g., see an earlier conference presentation, Irons & Leber, 2017). The present experiment was designed with a greater sample size to gain a stable estimate of the effect size and greater statistical power to find significant results. We pre-registered the methods, hypothesis, and analysis plan for this experiment prior to data collection, and we also summarized the experiments conducted prior to this one. The pre-registration is posted on the Open Science Framework (OSF) website (https://osf.io/876d4/overview).

Participants

We preregistered an "ethical" flexible stopping rule for data collection, based on guidance by Sagarin, Ambler, and Lee (2014). If, after 100 usable participants (not including exclusions), the mixed ANOVA of group assignment (performance-contingent reward vs. random reward) x phase (pre-reward vs. post-reward) was p < .05, we planned to stop collecting data and reject the null hypothesis. If p > .20, we would stop collecting data and conclude that either no effect exists or it is smaller than what we consider meaningful. If we observed .05 < p < .20, we would increase the sample size with an additional 50 participants and adjust the critical p-value to .035.

This procedure led us to stop at 100 participants (59 men, 38 women, 1 non-binary, 1 prefer not to say, 1 unreported) aged 22 -64 years (M = 33.90, SD = 7.37). An additional 28 participants were tested but were excluded from further analysis due to poor accuracy (lower than 85% or more than three SD below the group mean in the baseline or feedback phase of ACVS). All participants were recruited through the MTurk platform and were prescreened by their approval rates (>= 98%) and number of completion (>= 750). Participants were compensated for their time at a base rate of $6/hr, plus $1-8 extra based on their reward (mean bonus was $5.04). All participants were provided with the online informed consent form approved by The Ohio State University institutional review board.

Stimuli

Experiment 2 was conducted online. Therefore, we use the fixed visual angle units described in Experiment 1 to report the report stimulus sizes.

The ACVS task was similar to the one in Experiment 1, with one exception. The radii of the inner, middle, and outer rings were slightly smaller than Experiment 1 (5.1, 7.7, and 10.2 units, respectively).

Procedure

Participants completed five blocks of 42 trials each. The first block was the pre-reward baseline block, which was identical to Experiment 1, except that the feedback was provided for both correct and incorrect trials for 2000 ms. No rewards were provided during this block.

Next, participants advanced to the four reward blocks. Participants were randomly assigned to one of two reward groups: performance-contingent reward and random reward (control). Participants were informed that they would now receive points for each correct trial, and every point would earn them an additional 1 cent at the end of the experiment. In the performance-contingent reward group, participants were instructed that the points were based on their speed, with 1 point assigned to very slow responses, 2 points to moderately-slow responses, 3 points to moderate responses, 4 points to moderately-fast responses, and 5 points to very fast responses. No points were given on error trials. Unbeknownst to participants, points were determined by comparing each RT against the participant's own RT distribution calculated from the immediately preceding block. An RT that fell in the slowest (5 th ) quintile was given one point, an RT falling within the next slowest (4 th ) quintile received two points, and so on. In this way, participants essentially competed against themselves, enabling us to roughly standardize reward across participants, and prevent any effects of floor or ceiling reward.

RT RT data are plotted in Figure 4B. A 2 by 2 mixed ANOVA revealed only a main effect of condition phase on RT (F(1,98) = 44.967, p < .001, 𝜂 𝑝2 = .315), in that RT was significantly reduced in the feedback phase for both the random reward group (baseline: M = 3219 ms, SD = 1889; reward: M = 2740 ms, SD = 1044; t(49) = 3.192, pHB = .004, d = 0.45) and the performance-contingent group (baseline: M = 3301 ms, SD = 1332; reward: M = 2502 ms, SD = 1077; t(49) = 6.796, pHB < .001, d = 0.96). The main effect of reward group was not significant (F(1,98) = 0.091, p = .764, 𝜂 𝑝2 = .001), and neither was the interaction between phase and group (F(1,98) = 2.829, p = .096, 𝜂 𝑝2 = .028).

Optimality

Optimality was our main variable of interest, as we wanted to test if the boost in optimality from pre-reward baseline to the reward blocks was greater in the performancecontingent than random group. As declared in our preregistration, we focused on the interaction between phase and reward group assignment, as this contrast would better handle betweensubject variance across the groups. Optimality data are plotted in Figure 4C. A 2 by 2 mixed ANOVA revealed a main effect of phase on optimality (F(1,98) = 13.467, p < .001, 𝜂 𝑝2 = .121).

Critically, we did find a significant interaction between phase and reward group (F(1,98) = 11.078, p < .001, 𝜂 𝑝2 = .102). To characterize this, we found that optimality increased significantly in the performance-contingent group (baseline: M = .650, SD = .213; reward: M = .749, SD = .207; t(49) = 4.432, pHB < .001, d = 0.63), while it remained relatively stable in the random reward group (baseline: M = .695, SD = .204; reward: M = .700, SD = .227; t(49) = 0.278, pHB = 1, d = 0.04). However, the across-group comparison did not show significant results in either the baseline phase (performance-contingent: M = .650, SD = .213; random: M = .695, SD = .204; t(98) = 1.080, pHB = .566, d = 0.22) or the reward phase (performance-contingent: M = .749, SD = .207; random: M = .700, SD = .227; t(98) = 1.128, pHB = .524, d = 0.23).

Switch rates

Switch rates were calculated as the percentage of correct trials where individuals chose a different target color than on the previous trial (Irons & Leber, 2018), and data are shown in Figure 4D. A 2 by 2 mixed ANOVA on switch rates revealed no significant main effects (group: F(1,98) = 0.077, p = .782, 𝜂 𝑝2 = .001; phase: F(1,98) = 0.828, p = .365, 𝜂 𝑝2 = .008) or interactions (F(1,98) = 0.406, p = .526, 𝜂 𝑝2 = .004). In the reward manipulation of Experiment 2, we found some success in motivating more optimal strategies, as optimality improved from baseline more in the performance-contingent group than the random group. However, a comparison between groups during the reward phase showed no significant difference in optimality across the two reward groups, tempering the strength of our conclusions. Statistics aside, it is safe to conclude that neither of the manipulations drove massive improvements in strategy optimization. Taken together, the results of both experiments are somewhat consistent with the findings of Nowakowska et al. (2021), in the split-half line segment task.

The results might prompt us to question whether it is at all possible to motivate ceilinglevel optimality in the ACVS task. To address this question, consider the "enforced optimal" task, which we described in the introduction. The task is the same as the ACVS in every way, except that participants must report the target in the smaller subset, which is identical to using the optimal strategy in the standard ACVS. Participants perform this task with ceiling-level accuracy (see Irons & Leber, 2018; Zhang & Leber, 2024), demonstrating that they are readily capable of searching optimally at ceiling levels. What is different between this task and the current incentives we provided participants? In the enforced optimal task, the consequences of not complying are much steeper, as accuracy would drop to chance level. Future investigations should map out the space of motivation between what we have done in the present study and what the enforced-optimal task achieves. McKinney et al. (2025, November) recently introduced one promising method to greater incentivize ACVS optimality. They assigned different reward outcomes for reporting the smallsubset vs. large-subset target. While the reward differences were not extreme, their results suggest modest improvements in optimality when the small-subset target receives a greater reward than the large-subset target. Future work could parametrically vary the reward differential between small-and large-subset targets. Awarding zero points for the largest subset target would be conceptually similar to the enforced-optimal version of the task, and then we would predict that intermediate reward values would yield lower rates of optimality.

In summary, this study represents the start of a potentially long line of research to better understand how and why individuals abandon their default strategies in favor of greater performance outcomes. Folk and Remington, along with their colleagues, had an important insight over 30 years ago: humans are capable of flexibly using a wide array of goal-directed attentional strategies, but they do not always do so. We have made some initial progress in fully exploring the implications of this insight, and it is vital to continue; studying the many sources of motivation contributing to strategy selection promises a more comprehensive understanding of how we use our attentional system.

Results

Mean accuracy across all blocks was 96.7%. When analyzing response time (RT), we excluded trials with RTs less than 300 or more than three standard deviations of the mean (1.55% of the total trials).

Accuracy

Accuracy data are shown in Figure 4A. We carried out a 2 (Phase: pre-reward baseline vs reward) by 2 (Reward group: random reward vs performance-contingent) mixed ANOVA on accuracy. We observed a main effect of reward group (F(1,98) = 17.157, p < .001, 𝜂 𝑝2 = .149), and a significant interaction between phase and reward group, F(1,98) = 9.826, p = .002, 𝜂 𝑝2 = .091. Discussion

The results of Experiment 2 provide some evidence that increasing the motivation to perform quickly leads to an increase in optimal performance. The performance-contingent group showed a significant increase in optimality from the baseline block to the reward blocks (9.9%), while the random reward group showed a smaller, non-significant improvement (0.5%).

However, this result is a bit qualified by the lack of a significant group difference during the reward phase. This seems due to a numerically lower (albeit non-significant) baseline optimality rate in the performance-contingent group than the random group. Nevertheless, given a reasonably large sample size of N=50 per group, we should have expected a significant group difference in the reward phase if the nature of the reward robustly motivates changes in optimality.

All things considered, we might conclude that performance-contingent reward seems to motivate more optimal strategy use, but the effect is not particularly large -and certainly does not drive the participants to approach ceiling-level optimality.

General discussion

We began by shining a light on two important ideas introduced by Folk et al. (1992), relating to default modes of attention and motivation. According to these authors and others (Bacon & Egeth, 1994), we default to salience based strategies unless sufficiently motivated to configure more selective attentional control settings. This study represents an effort to systematically explore this idea. Using the ACVS, a task specifically designed to investigate the strategic use of attentional control, we manipulated two factors to alter participants' motivation levels: time pressure and performance-contingent reward.

In the time-pressure manipulation of Experiment 1, results showed that, although the deadline manipulation led to faster responses, accuracy and optimality did not improve. In fact, it decreased significantly in the shortest exposure condition. This indicates that, under time pressure, participants appeared to have somewhat of a breakdown in strategy, possibly related to choking under pressure (Baumeister, 1984; Beilock & Carr, 2001) or becoming less willing to flexibly explore different strategies (Wu et al., 2022).

As part of this recent literature, our lab has designed a task to systematically investigate why and how individuals use various, often suboptimal, strategies. This task, the Adaptive Choice Visual Search (ACVS), assesses the optimality of individuals' visual search strategies on a trial-by-trial basis.
