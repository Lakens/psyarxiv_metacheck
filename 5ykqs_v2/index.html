We left out 30 files that software creates by itself, not the authors: operating system (30). They hold nothing a reader can use, but they clutter the repository, and software can mistake them for real files (for example a ._ copy of a .csv for data).

Remove these: Operating system files: macOS adds a __MACOSX folder and a ._ copy of every file it puts in a zip, and .DS_Store files to folders; Windows adds Thumbs.db and desktop.ini. On a Mac, create zips from the command line with zip -r -X, or remove them afterwards with zip -d archive.zip "__MACOSX/*" "*.DS_Store". RStudio session files (.Rproj.user/) hold open tabs and unsaved edits; R history (.Rhistory) lists the commands typed in a session and can hold file paths and passwords; Jupyter checkpoints (.ipynb_checkpoints/) are automatic copies of notebooks; compiled Python files (__pycache__/, .pyc) are recreated when the code runs; open-document lock files (~$...docx, .~lock...#) are left while a document is open; editor backups (file~, .bak, .swp) and temporary files (.tmp, .temp) are copies a program made by itself.

Keep only on purpose: version control folders (.git, .svn, .hg) hold the project’s history, which can include earlier versions of files and data that was later removed; editor settings (.idea, .vscode) can hold paths on your own computer. A .gitignore based on GitHub’s templates (https://github.com/github/gitignore) keeps them out of a repository.

How Power Analysis Check works

This module uses regular expressions to identify sentences that contain a statistical power analysis. If specified by the user, it also uses a large language model (LLM) to extract information reported in power analyses, including the statistical test, sample size, alpha level, desired level of power, and magnitude and type of effect size.

The Power Analysis Check module uses regular expressions to identify sentences that contain a statistical power analysis. Without the use of an LLM, the module uses regular expressions to classify the power analysis as a-priori, sensitivity or post-hoc. With the use of an LLM, it checks if the power analysis is reported with all required information.

The regular expressions can miss power analyses, or fail to classify them correctly. The type of power analysis is often difficult to classify, which can easily be solved by explicitly specifying the type of power analysis as ‘a-priori’, ‘sensitivity’, or ‘post-hoc’. Note that ‘post-hoc’ or ‘observed’ power is rarely useful. The LLM can fail to identify information in the paper, and will not have access to information in paragraphs in the paper other than those that contain the word ‘power’. This package was validated by the Metacheck team on articles in Psychological Science.

How Preregistration Check works

Retrieve information from preregistrations in a standardised way, and make them easier to check.

The Preregistration Check module identifies preregistrations on the OSF and AsPredicted based on links in the manuscript, retrieves the preregistration text, and organizes the information into a template. The module retrieves text from the OSF with its API, and from AsPredicted with ResearchBox’s API when a ResearchBox key is set (see rbox_token()), or else from the preregistration’s web page. The information in the preregistration is returned. An AsPredicted link that could not be read is named in the report, with the reason.

The module can’t extract information from non-structured preregistration templates (i.e., where the preregistration is uploaded in a single text field) and it can’t retrieve information in preregistrations that are stored as text documents on the OSF.

The marginal module searches for regular expressions that match a predefined pattern. The list of terms is a subset of those listed in a blog post by Matthew Hankins. The module returns all sentences that match terms describing ‘marginally significant’ results.

Some of the terms identified might not be problematic in some contexts, and there are ways to describe ‘marginal significance’ that are not detected by the module.

How StatCheck works

Check consistency of p-values and test statistics

The Statcheck module runs Statcheck. Statcheck searches for regular expressions that match a predefined pattern, and identifies APA reported statistical tests. More information on the package can be found at https://github.com/cran/statcheck. The module only returns Statcheck results for t-tests and F-tests, as these are the only tests which have been validated, see https://osf.io/preprints/psyarxiv/tcxaj_v1/.

Statcheck was developed by Michèle Nuijten and Sascha Epskamp.

Statcheck considers p = 0.000 an error, as you should report p < 0.001. Furthermore, p < 0.03 is an error if the p-value was 0.031, and one should simply report exact p-values (p = 0.031). Statcheck might miss one-sided tests, and falsely assume the p-value is incorrect. For more information, see StatCheck.

This module only checks statistical results reported in the running text of the manuscript. It cannot (yet) process statistics reported only in tables.

How Exact P-Values works

List any p-values reported with insufficient precision (e.g., p < .05 or p = n.s.), reported as exactly zero (e.g., p = .000), or impossible (below 0 or above 1, e.g., p = -.22).

This module uses regular expressions to identify p-values. It will flag any values reported as p > ? or p < numbers greater than .001. It will also flag p-values reported as exactly zero (e.g., p = .000, p = 0.00), which are mathematically impossible — p-values are never exactly zero and should instead be reported as p < .001.

A p-value that is not the result of a test is not flagged: a table note (“* p < .05, ** p < .01”), a figure legend (“Asterisks indicate significant differences (p < .05)”, “Values in bold are significant at p < .05”) or a stated threshold (“p < .05 was considered significant”, “thresholded at p < .001”). GROBID often puts such notes into the running text, so each p-value is judged by the words in its own clause (the text up to a “;” or a full stop), and never left out when a test statistic belongs to it (“F(1, 7) = 8.03, # p < .05”). The column not_a_test of the table says why a p-value was left out (“marker”, “threshold”, “legend” or “named”).

A p-value with the name of a correction or a test after the p (“pFWE < .05”, “padj < 0.05”, “p Wilcoxon = .02”) is flagged only when a test statistic comes before it in its clause (“t(37) = 7.17, p FWE < .05”). Without one it is mostly the rule that decided what was significant (“genes with padj < 0.05 were selected”); such a p-value is “named” in not_a_test. Notes in other forms, such as a marker after the p-value (“p < .05 (*)“), are still flagged.

A p-value below 0 or above 1 is impossible; it is listed apart and not also as imprecise. Often the statistic before it, or its minus sign, was copied into it (“t(134) = -2.32, p = -.13”, “Z = 3.091, P = 3.091”). A value above 1 is listed only after a test statistic in its clause: without one, a “P” above 1 was nearly always another quantity (a proportion, pH, a group’s mean, a model parameter). A number in scientific notation whose power of ten was lost when the PDF was read (“p = 2.4 x 10 -9” read as 2.4) is not listed. A “p” that is the subscript of another symbol (“r p = .64”, “²p = .02” for partial eta squared, “Δp = .33”), or a quantity with a unit, a logarithm or a ratio (“P = 2.9 µm”, “-log10 P = 7.5”, “Ca/P = 1.67”), is not read as a p-value at all (see extract_p_values()). Each p-value has its own row, also when the same one is written twice in a sentence.

This module sometimes flags false positives when sentences discuss how p-value thresholds were set. It can also miss an imprecise p-value that is reported against a threshold (“decreased at the p < .05 significance threshold”).

This module only checks p-values reported in the running text of the manuscript. It cannot (yet) process p-values reported only in tables (as opposed to a table’s footnote text, which the module does see and tries to exclude — see above).

This module was developed by Lisa DeBruine and Daniel Lakens

Read more in the metacheck manual.

Version 0.4.4.3 reported 419 p-values as imprecise, 388 of them correctly (93%), and missed 50 (89% found). Of the misses, 13 are starred table notes (“*p < .05”) that the module leaves out on purpose and 11 are p-values it did not find; of the wrong reports, 20 are p-values the ground truth does not contain (such as “ps < .05”) and 6 use ≤ or ≥. How Non-Significant P Value Check works

This module checks for imprecisely reported p values. If p > .05 is detected, it warns for misinterpretations.

The nonsignificant p-value check searches for regular expressions that match a predefined pattern. The module identifies all p-values in a manuscript and selects those that are not reported to be smaller than or equal to 0.05. It returns all sentences containing non-significant p-values.

In the future, the Metacheck team aims to incorporate a machine learning classifier to only return sentences likely to contain misinterpretations. If you want to help to improve the module, reach out to the Metacheck development team.

A p-value in a table note (“† p < .10, * p < .05”) or a figure legend (“dashed lines indicate non-significant paths (p > .05)”) is left out, as in stat_p_exact; the column not_a_test says why. A p-value next to words that state a threshold is kept, because such sentences often report a result against that level (“not significant at the conventional threshold (p = .054)”).

This module only checks p-values reported in the running text of the manuscript. It cannot (yet) process p-values reported only in tables.

How Codebook Check works

This module checks whether the data columns in a repository are documented in a codebook or README. It locates codebook/readme files, extracts the variable definitions they contain, matches those definitions against the data columns extracted by data_check, and reports documentation coverage: how many data columns are documented, and which documented variables are never used.

The Codebook Check module consumes the columns and file classification produced by data_check (and, transitively, repo_check). Files classified as codebook or readme are parsed with parse_codebook(), which reads structured tables (CSV/TSV/Excel with a variable-name column and a label column), embedded labels in haven files (SPSS/Stata/SAS), and plain text from rich-text formats (docx/pdf/rtf/odt). Embedded haven labels from data files are also harvested directly.

Each data column is then matched against the parsed variable definitions with match_column_labels(), using normalised-name matching with experiment-group scoping, haven-label priority, and rule-based label-equivalence merging.

Beyond the variable label, the module harvests the DDI-style per-variable properties a source supplies: the value labels / code list (the 1=“Strongly disagree”…5=“Strongly agree” mapping — from SPSS/Stata value labels and from a codebook “values”/“coding” column), the missing-value scheme (which codes denote missingness, from haven declared missings and labels that read as “refused”/“n/a”), and question text and columns when present. These are carried onto the matched data columns and exported into the Psych-DS variableMeasured (as a schema.org code list plus namespaced metacheck: fields).

The module defaults to rules-only when llm_use(FALSE). When llm_use(TRUE), three optional LLM tiers run: parsing unstructured codebook text that the rules could not handle, fuzzy-matching still-unlabelled columns to still-unmatched codebook variables, and merging conflicting label definitions into a single canonical label.

How Repository Check works

This module retrieves information from repositories.

The Repository Check module lists files on the OSF, GitHub, ResearchBox, DSpace (PsychArchives and other legacy- and DSpace 7-based installations), Zenodo, Dataverse, Figshare, Dryad, ReShare, 4TU.ResearchData, Mendeley Data, DataONE (Arctic Data Center, KNB, and other member nodes), and LDbase based on links in the manuscript.

Listing a repository’s files never requires an API key, but some hosts answer faster or more completely with one: OSF allows 100 requests/hour unauthenticated versus 10,000/day with a token (see [osf_pat()]), and Dryad enforces a strict per-IP daily quota on repeated listing (see cache below). Dryad is a special case beyond rate limits: listing a Dryad dataset’s files works without a key, but actually downloading file CONTENTS from Dryad fails with HTTP 401 unless a key is set, even for a fully public dataset (see [dryad_pat()] or [dryad_auth()]). Since this module only lists files and never downloads their contents itself, that limitation applies to data_check and code_check (which do download content), not here – see their own documentation.

When a linked OSF page is a registration, its registered_from project (the one it was registered from, which the manuscript itself may never link directly) is also checked: if that project is public its files are listed under its own URL, and if it is closed or otherwise inaccessible the report flags it explicitly, since some registrations only describe their content rather than mirroring it.

Whose deposit is each link? The ownership table gives, for every repository linked in the text and (with references = TRUE) every deposit cited in the reference list, one of six labels: own_this (made by the authors for this paper), own_earlier_data or own_earlier_code (the authors’ own, from earlier work), others_data or others_code (made by other people, reused here), or not_data (a publication such as a preprint, not a deposit), with ownership_group (“own”, “others”, “not_data”) and the reason. It is decided without a language model, from the sentence or reference that cites the link, the paper’s authors (names, ORCID iDs, affiliations), and what the deposit’s own record and files say (who made it, what it names, when, whether it is a software package; for an OSF project cited only in the reference list, its record alone). On a round of labelled links the rules had not been written from, the three groups were right for 98% of links in the main text (93 of 95) and 90% in reference lists (74 of 82); the labels were made by Claude agents from each link’s evidence, and disputed ones checked against the deposits. Telling this paper’s own deposit from the authors’ earlier one is less certain.

Only the deposits that are this paper’s own are checked. A deposit linked in the text that holds other people’s work (others_data, others_code) or the authors’ earlier work (own_earlier_data, own_earlier_code) is listed in the report, with the reason, but its files are left out of table and kept in table_not_checked: they count toward nothing here (files that do not belong in a repository, naming, READMEs, studies, the traffic light), and code_check, data_check and reproducibility_check, which read table, do not check them either. reproducibility_check still puts the files of theirs that the paper’s code names in the folder the code runs in, as a re-analysis needs the data it re-analyses. When every linked deposit is set aside, the traffic light is “na”. A deposit that is the paper’s own is counted as such when its README, title or description names the paper (its title or DOI).

How Code Check works

This module retrieves information from repositories checked by repo_check about code files (R, Python, SAS, SPSS, Stata, Mplus, MATLAB).

The Code Check module checks R (also R Markdown and Quarto), Python (also Jupyter notebooks), SAS, SPSS, Stata, Mplus, and MATLAB files, using regular expressions to check the code; JASP files are listed but not read. The language of a Quarto document or a notebook is read from the file itself (its engine or kernel), not from its extension. The regular expression search will detect the number of comments, the lines at which libraries/imports are loaded, attempts to detect absolute paths to files, setwd() and install.packages() calls, and lists files that are loaded, and checks if these files are in the repository; R code is also parsed. The module will return suggestions to improve the code if there are no comments, if libraries/imports are loaded in lines further than 4 lines apart, if files that are loaded are not in the repository, if absolute file paths, setwd() or install.packages() are found, and if R code cannot be parsed.

The regular expressions can miss information in code files, or falsely detect parts of the code as a fixed file path. Libraries/imports might be loaded in one block, even if there are more than 3 intermittent lines. The module was tried out internally on papers published in Psychological Science, but has not been formally validated. There might be valid reasons why some loaded files can’t be shared, but the module can’t evaluate these reasons, and always gives a warning.

The module also checks whether the repository pins the R/package versions the analysis actually depended on: an renv.lock file (parsed for the R version and every locked package + its version/source), a sessionInfo()/sessioninfo::session_info() text dump (matched by filename — sessionInfo.txt/session_info.txt and similar, or embedded in a README), or a groundhog::groundhog.library()/checkpoint::checkpoint() date-pin call in the code (a bare library(groundhog)/library(checkpoint) does not count — the pinning call itself must be present). When none of these is found, the report flags it as a reproducibility gap: package versions may drift between when the analysis was run and any later reproduction attempt.

If you want to extend the package to perform additional checks on code files, or make the checks work on other types of code files, reach out to the Metacheck development team.

Checking code requires downloading its file contents. For a paper whose repository is on Dryad, this never succeeds unless a Dryad API key is set: Dryad requires one to download file bytes, even from a fully public dataset (listing the repository’s files does not need one). Without a key, every Dryad-hosted code file is listed but unchecked, and a warning naming Dryad and ?dryad_pat/?dryad_auth is included among the download failures recorded in the manifest.

How Data Check works

This module classifies the files in a repository into semantic types (data, codebook, code, software, output, supplemental, readme, asset, other) and, for tabular data files, extracts each column’s type and summary statistics.

The Data Check module consumes the file list produced by repo_check (or any files added via local_path). Each file is classified with rule-based heuristics layered over metacheck’s file_category() and file_types: file names matching README / codebook patterns win first, then an extension crosswalk, then format-locked extension overrides. For every file classified as tabular data that is available locally, the module reads the file head, describes each column with data_col_facets() and computes summary statistics for numeric columns. Every sheet of a spreadsheet that holds a table is read: a file with several such sheets has its columns under source_file = "file.xlsx [sheet]", and the sheet column names the sheet of any spreadsheet with several sheets; a sheet of notes or a codebook is treated as documentation when the file has another table. Following DDI, a column is described by orthogonal facets rather than a single type: representation (numeric/text/datetime/code — how it is stored), measurement_level (Stevens: nominal/ordinal/interval/ratio), concept (what it measures: reaction_time/age/gender/likert/id/…), role (identifier/measure/condition/timestamp), unit, and a quality state (ok/empty/constant). Concepts are detected by name+value rules (the demographic concepts via data_check_demographic()); when llm_use(TRUE) the model fills concepts and measurement levels the rules left blank. Qualtrics survey exports are recognised (data_check_is_qualtrics()): their extra header rows are stripped so columns type correctly, and the reserved response-metadata columns (StartDate, Duration, Finished, …) are tagged.

The module defaults to rules-only when llm_use(FALSE): columns the rules cannot resolve (ambiguous 3–20-unique integers, ambiguous character columns) fall back to continuous / text respectively. When llm_use(TRUE), ambiguous columns and unresolved file types (other) are sent to llm() for optional refinement, and every file is assigned a study group (ex1, pilot2, shared, …) so that multi-study repositories can be recognised (used by psychds_check). Without an LLM the study group is left NA (unknown).

Column extraction requires files to be readable from disk. Files fetched by repo_check from OSF/GitHub/etc. without a local copy (file_location is NA) are classified but not column-extracted; pass local_path to point at a downloaded copy of the repository.

For a paper whose repository is on Dryad, this means column extraction never happens unless a Dryad API key is set: Dryad requires one to download file bytes, even from a fully public dataset (dataset listing and metadata do not need one). Without a key, every Dryad file stays classified but un-downloaded, column_n is 0, and a warning naming Dryad and ?dryad_pat/?dryad_auth is included among the download failures. A one-time session message is also shown (see repo_check) the first time a Dryad dataset is encountered with no key set.

Every downloaded text file the authors wrote (code, settings, survey definitions such as Qualtrics .qsf files, documentation, outputs) is searched for keys: API keys, access tokens and private keys, which let anyone who downloads the file use a paid service at the authors’ cost. Of a tabular data file only the column names and first 3 rows of the table as read are searched: its values come from participants, but a key the authors set for a whole survey (as embedded data in a Qualtrics survey flow) is exported in every response. The search uses the rules of the secret scanner betterleaks (https://github.com/betterleaks/betterleaks, MIT licence) of high and medium confidence. A key found turns the traffic light red; the report and the keys table give its file, line and type, and only its beginning. Other files over 25 MB and binary files are not searched. A key is never tested with its provider. Every module’s result has any whole key replaced by “keyremoved” (see module_run()).

How Reproducibility Check works

This module assesses whether a paper’s R and Python code can be run on its data. It works in two phases. The static phase (always run) collects the package dependencies the code declares, rewrites the data-file paths that do not work in the repository as the authors organised it, works out the order the scripts must run in, and diagnoses why any referenced input file is unavailable — reporting what a reproduction attempt would involve and where it is likely to break. The execution phase (opt-in, execute = TRUE) then actually runs the code: it copies the repository into a throwaway directory, optionally installs the declared dependencies into a throwaway library, runs each script in order in an isolated subprocess with a per-script timeout, and captures the outcome and full output of each run.

By default (execute = FALSE) the module does not run any code — it performs only static analysis: reading dependencies with the same extractors as code_check, finding the files the code references in the repository, and building a run-order dependency graph. It reports what would be installed and run rather than doing it.

When execute = TRUE, the module additionally runs the downloaded code on your machine — a deliberate, opt-in action gated behind that argument (callr is required for R code). Each script runs in an isolated subprocess so a crash cannot take down the R session; note this isolates crashes, not the filesystem or network. Installs (when install_missing = TRUE) and the throwaway run library never touch your main R library. Each script’s outcome is one of ran_ok, errored, timed_out, dependency_unavailable, not_parsed, run_by_source (an R script another script runs with source(), which is run only inside that script, since on its own it lacks the packages and objects the sourcing script sets up first), run_by_import (a Python file other files import, a module rather than a script, unless it has an if __name__ == "__main__": block), jags_model (a JAGS or BUGS model saved with an R extension, which another script reads) or not_r_content (a file that is not R at all, such as a JSON or HTML dump); these last two are not run and are not failures. python2 marks Python 2 code that was not run. With sandbox = "docker" such code runs with Python 2.7 (option metacheck.docker_image_py2; FALSE turns this off), which modifications records; it is never converted, since that can change results. defines_functions is a file that only defines functions, which is used, not run (table$used_by names the scripts that use it), and not_analysis is a file of software rather than of the analysis: a package’s code, tests, documentation or setup.py, a copy of a tool, a web application, a script a program wrote (table$not_analysis_why says which); neither is run or counted as a script. docker_failed means the container never started, which says nothing about the script, so it keeps the light from being green but does not make it red. needs_a_person is a script that stopped because it asks a person to choose a file or answer a question, or that starts an app, and needs_internet one that stopped because the network is off in a Docker run, or, with internet = TRUE, could not reach what it asked for; download_too_large is a script stopped for downloading more than the limits allow (see internet), and out_of_memory one that, or a program it started (such as a compiler), ran out of the memory each script may use. All four are treated the same way. not_downloaded is a script that stopped on a file the repository lists but that was not downloaded, such as one over max_file_size: it could not be tried, so it is not counted as a script that did not reproduce (summary_table$repro_not_downloaded_n counts them apart). not_read is a file metacheck could not read, so it was not run; the light is then not green, as the file may read and run on another computer, and table$error_message says why, naming a package that is installed but cannot be loaded on the computer that ran the check. empty is a file with nothing in it, which is not run or counted as a script. For a script that did not run through, table$error_message is its error, short (at most 300 characters): the error line of its output, which names a package that is not there, with the address it asked for when it needed the internet, or the time limit it reached; table$reason sorts it into a kind. A timeout means “still running at the cutoff”, not a failure, so raise timeout for legitimately long-running (e.g. Bayesian) scripts. dependency_unavailable means the script’s own package could not be installed from live CRAN, the CRAN Archive, or a named GitHub/URL source — an infrastructure limitation, not a defect in the paper’s code, so unlike errored/timed_out it does not force the traffic light red. The full stdout/stderr of every run is kept in the result’s run_results (the report shows it in per-script dropdowns, capped for readability). The traffic light reflects the STATIC readiness signals by default, but an execution error (errored/timed_out) does recolour it to red — a script that crashes on its own analysis is a genuine reproduction failure. A script that fails with could not find function is run once more with the library() calls the project’s other scripts make added at its top (or the one package that exports the function, or magrittr for %>%), and a script that then runs is reported as reproducible only after that repair.

Dependencies are reported name-only, with the source (CRAN, GitHub, or a base package already shipped with R) — static analysis of the code cannot know which version was used, and running against current package versions is itself informative: a break argues the authors should have pinned versions. When the repository does record versions, a run with recorded_versions = TRUE installs the packages the scripts load at those versions, but it does not change the R version, which remains a limitation of the check.

Run order is derived from read-after-write data dependencies (a script writing a file another reads must run first), source() edges, and numeric filename prefixes as a weak tie-breaker. Ambiguous orderings, dependency cycles, and inputs a script reads but that no earlier script produces (and that are not in the repository) are surfaced as warnings, since these are the situations most likely to make an otherwise-correct reproduction fail.

Python code (.py files, and notebooks and Quarto documents whose code is Python, from which the code is extracted first) goes through the same two phases, reported in its own “Python code” section. Each file is checked for syntax errors with Python’s own parser when a Python interpreter (python, or else python3) is available; dependencies are read from the import statements, with versions from a requirements.txt or pyproject.toml when there is one, and installed with pip; each script runs as its own python process (processx is required), so unlike R scripts, a name one script defines is not available to another. When no Python interpreter is available, the Python files are reported as not run and the R results are still returned. Statistics the Python scripts print are compared with the paper together with the R output and any self-reproducible output (JASP/jamovi, SPSS-Viewer, notebook outputs).

Abstract

1 Universality of intrinsic vowel F0 in 75 languages We examine intrinsic vowel F0 (VF0)-higher fundamental frequency (F0) in high than low vowels-in read speech from 75 languages and 18 language families in the VoxCommunis Corpus. We compare /i/, /u/, and /a/ across languages and speakers, test associations with vowel inventory size and word prosodic system, and assess within-vowel F1-F0 covariation. High vowels had higher F0 than /a/ in 95% of languages for /i/-/a/ and 89% for /u/-/a/; the majority of individual speakers showed the same trend. By contrast, F0 did not systematically differ between /i/ and /u/. VF0 magnitude varied across languages but was not reliably associated with inventory size or word prosodic system. Within-vowel F1-F0 correlations were mostly weak but skewed positive, especially for high vowels: tokens with higher F1 tended to have higher F0, opposite to the negative association predicted by continuous biomechanical account. The categorical consistency is compatible with a biomechanical origin, potentially under uniform phonetic targets, but target uniformity alone does not fully explain the within-vowel pattern. VF0's direction is therefore broadly consistent across languages, while its fine-grained realization may involve additional speaker control.

I. INTRODUCTION

The acoustic consequences of vowel height extend beyond its primary correlate, the first formant frequency (F1). High vowels such as /i/ and /u/ tend to exhibit not only lower F1, but also higher fundamental frequency (F0) and shorter duration than low vowels such as /a/ (Maddieson, 1996). These secondary patterns, known as intrinsic vowel F0 (VF0) and intrinsic vowel duration (IVD), raise a question about the relationships between abstract phonetic representations, physical articulation, and acoustic realization: to what extent do these differences emerge as consequences of producing vowels of different heights, and to what extent can speakers independently control them? Both effects have traditionally been considered mechanistic phonetic universals, arising at least in part as biomechanical consequences of vowel articulation (Keating, 1985; Maddieson, 1996). Yet their automaticity has long been debated. Speakers could instead control F0 and duration as secondary correlates to the high-low contrast (Connell, 2002; Hoole and Honda, 2011; Kingston, 2007). Indeed, both F0 and duration can serve as secondary perceptual cues to vowel height (e.g., Gussenhoven, 2007; Hombert, 1977; Stone, 2015; Ting and Clayards, 2024), and it has been found that the magnitude of intrinsic vowel effects also varies across languages, speakers, and phonetic contexts (e.g., Hoole and Honda, 2011; Shadle, 1985; Ting et al., 2025). Nevertheless, such variation does not necessarily imply perceptually motivated enhancement. Understanding the relative contributions of biomechanical factors and speaker control is therefore central to explaining these patterns.

VF0 is especially useful for examining this question because its typical direction is well documented, even though F0 is extensively controlled for other linguistic purposes. The phenomenon has been noted for over a century (Meyer, 1896 (Meyer, , 1910)), with high vowels generally exhibiting higher F0 than low vowels across languages (Ting et al., 2025; Whalen and Levitt, 1995). VF0 has been linked to effects of tongue and jaw configuration on laryngeal tension and vocal fold vibration (Chen et al., 2021; Ladefoged, 1968; Ohala and Eukel, 1976). At the same time, F0 also conveys lexical tone and other prosodic distinctions. The consistent relationship between F0 and vowel height, despite the capacity for independent control of pitch, makes VF0 a particularly interesting case for examining the interaction between biomechanical and language-specific influences on phonetic realization.

Existing studies provide substantial evidence for the crosslinguistic prevalence of VF0, but leave several opportunities for further investigation. Whalen and Levitt (1995) A useful parallel comes from IVD, which associates vowel height with a different secondary acoustic dimension through distinct physiological mechanisms. In a corpus analysis of more than 60 languages, Chodroff and Zhang (2026) found that high vowels were shorter than low vowels in approximately 90% of comparisons. Within /a/, lower vowel realizations (higher F1) also tended to be longer on a token-by-token basis for most speakers, consistent with a continuous biomechanical contribution to duration. These findings suggest that intrinsic vowel effects can exhibit regularities both between and within vowel categories, motivating the question of whether comparable patterns occur for VF0. The IVD study also proposed that biomechanical explanations of such regularities depend on the relative uniformity of certain underlying phonetic targets across vowels.

The present study examines VF0 across 75 languages and 18 language families using Common Voice recordings (Ardila et al., 2019) and word-and phone-level alignments from VoxCommunis (Ahn and Chodroff, 2022). We investigate how consistently high-low F0 differences occur across languages and individual speakers; whether their magnitude covaries with vowel inventory size and lexical tone system; and whether F1 and F0 covary within individual vowel categories. By extending the empirical approach applied to IVD, we examine whether two well-documented intrinsic vowel effects exhibit comparable patterns at both categorical and continuous levels, and what their similarities and differences may reveal about the mechanisms underlying crosslinguistic phonetic regularities.

II. BACKGROUND A. Biomechanical sources of intrinsic vowel F0

Biomechanical explanations of VF0 attribute the F0 differences between high and low vowels to the articulatory configurations and movements involved in vowel production, rather than to independently specified pitch targets (Chen et al., 2021; Ladefoged, 1968; Ohala, 1973). Several studies have argued that the VF0 effect arises as a biomechanical consequence of the different tongue heights required for different vowel targets (Di Cristo et al., 1979; Fischer-Jørgensen, 1990; Sapir, 1989; Shadle, 1985; Whalen and Levitt, 1995). The most widely cited explanation for this is the tongue-pull hypothesis, originally proposed by Ladefoged (1964 Ladefoged ( , 1968)). According to this hypothesis, raising the tongue for high vowels increases tension on the vocal folds through connections involving the tongue, hyoid bone, and laryngeal structures, resulting in higher F0.

However, the original tongue-pull hypothesis was not fully corroborated by subsequent experimental studies on the position of the larynx-hyoid complex, with several studies finding a lowered larynx for /u/ than for /A/ (Ewan and Krones, 1974; Sundberg, 1969). Ohala (1973); Ohala and Eukel (1976) proposed a revised version of the tongue-pull hypothesis, suggesting that the tissues connecting the tongue dorsum with the ary-epiglottic folds may exert an indirect pull on the vocal folds or influence their vibration through changes in the laryngeal ventricle. They further showed that F0 differs for vowels of different heights even when the magnitude of jaw opening is held constant. Electromyographic evidence has also implicated the hyoid bone: Honda (1983) argued that high vowel production requires the hyoid bone and tongue root to be pulled forward, achieved through contraction of the geniohyoid and genioglossus muscles, which rotates the thyroid cartilage forward and increases the longitudinal tension of the vocal folds. More recent articulatory research has highlighted the role of jaw movement alongside tongue movement, such that jaw lowering can also reduce F0 in low vowels (Chen et al., 2021).

B. Evidence for speaker control and contrast enhancement

An alternative perspective is that VF0 is shaped, at least in part, by speaker control aimed at enhancing the perceptual distinctiveness of vowel-height contrasts (Connell, 2002; Hoole and Honda, 2011; Kingston, 2007). One reason for considering this possibility is that biomechanical constraints alone may not satisfactorily account for all phonetic phenomena related to vowel height. Diehl and Kluender (1989) noted that the mapping between articulation and acoustics is many-to-one, so the F0 differences observed in vowels may not arise entirely from tongue position. Similarly, Vilkman et al. (1991) concluded that articulatory activity, such as contraction of the cricothyroid muscles, may contribute to the intrinsic pitch of vowels without fully explaining its observed magnitude.

Electromyographic studies have provided mixed evidence for the enhancement view. Both Honda (1991); Vilkman et al. (1991) found that the cricothyroid (CT) muscles contract during the production of high vowels. Because the CT muscles are involved in the active control of F0 levels (Löfqvist et al., 1989), this activity could reflect additional control aimed at enhancing the auditory distinction between high and low vowels. However, Whalen et al. (1999) found only limited articulatory evidence for the enhancement view after controlling for active pitch control: only one of four subjects showed additional CT contraction for high vowels. These findings suggest that active laryngeal adjustments may contribute to VF0, but do not establish that such adjustments necessarily serve contrast enhancement.

Perceptual studies have also shown that listeners can rely on F0 as a secondary cue to distinguish vowels of different heights. Hombert (1977) showed that when the formant structure of a synthesized vowel corresponds to a high vowel, its perceived pitch is also higher even when F0 is held constant. Ting and Clayards (2024) reported that listeners tend to judge preceding consonants as voiceless when the nucleus consists of a low vowel, since low vowels are perceived to have a higher pitch than high vowels even when fundamental frequencies are held constant, and higher pitch is typically associated with voiceless consonants (for consonant intrinsic F0, see Hombert, 1978; Kirby and Ladd, 2016). Relatedly, several studies have found that listeners rely on the distance between F1 and F0, rather than on F1 alone, when perceiving vowels of different heights (Hirahara and Kato, 1992; Hoemeke and Diehl, 1994; Syrdal and Gopal, 1986; Traunmüller, 1981). Barreda and Nearey (2012) further showed that F0 plays a direct role in vowel identification, with listeners shifting their vowel judgments in response to F0 differences even when formant information was available. On this basis, Diehl and Kluender (1989) argued that the covariation of F0 and tongue height may serve to auditorily enhance the phonological contrast between high and low vowels. Importantly, however, the perceptual relevance of F0 does not by itself establish that speakers actively enhance this cue during production.

Crosslinguistic comparisons provide another approach to evaluating the role of speaker control. If VF0 serves as a secondary acoustic correlate of vowel height, its magnitude might be greater in languages with larger vowel inventories, where additional acoustic differentiation could facilitate the maintenance of vowel contrasts. Whalen and Levitt (1995) and Ting et al. (2025) both observed a positive numerical, though statistically non-significant, correlation between vowel inventory size and VF0 magnitude; whereas Whalen and Levitt (1995) took the lack of significance as further evidence for an automatic effect, Ting et al.

(2025) left open the possibility that the numerical trend reflects enhancement. A smallerscale study found a larger VF0 effect in Dutch, a language with twelve vowel segments in its inventory, than in Arabic, a language with three (Van Hoof and Verhoeven, 2011).

The magnitude of VF0 has also been reported to vary across languages as a function of lexical tone, with smaller effect sizes in tone languages, where pitch carries a larger functional load in distinguishing lexical meanings (Ting et al., 2025; Whalen and Levitt, 1995). Within tone languages, the effect may be reduced or absent when vowels occur with low tones (Hombert, 1977; Lalhminghlui et al., 2019; Zee, 1980). VF0 has also been reported to be smaller in nonprominent syllables (Ladd and Silverman, 1984; Shadle, 1985; Steele, 1986) and in lower pitch ranges (Ladd and Silverman, 1984; Whalen and Levitt, 1995). The magnitude of VF0 can therefore vary considerably depending on the phonetic and prosodic context. Although such variation is compatible with speaker control, it does not necessarily imply perceptually motivated enhancement, as changes in articulatory and laryngeal settings may also influence the magnitude of biomechanical effects.

C. Target uniformity and predictions for F0

Traditionally, biomechanical and enhancement accounts have often been treated as competing explanations for intrinsic vowel effects. More recent work, however, has adopted a hybrid view in which biomechanical consequences of articulation and speaker-controlled phonetic adjustments can contribute simultaneously (Hoole and Honda, 2011; Keating, 1990; Maddieson, 1996; Ting et al., 2025). The challenge is to explain how these sources of variation interact, particularly given that speakers can actively control F0 in ways that could potentially attenuate or override the biomechanical consequences of vowel articulation.

The target uniformity proposal developed for IVD (Chodroff and Zhang, 2026) distinguishes abstract phonetic target specification from physical implementation and its acoustic outcomes (see also Chodroff and Wilson, 2017, 2022). For IVD, shared targets governing movement timing or velocity can be instantiated alongside distinct vowel height configurations, yielding durational differences as a mechanical consequence. The relevant targets are not themselves observed directly in acoustic duration. Similarly, for VF0 the measured F0 difference should not be equated with an underlying target, which might be specified in articulatory, auditory, or other phonetic terms.

Extending this proposal to VF0 requires identifying which underlying targets might remain relatively uniform across vowels while vowel-height gestures influence laryngeal tension and vocal fold vibration. For example, relatively similar baseline laryngeal control across vowel categories could permit height-related mechanical effects on F0, even if speakers also make compensatory or enhancing adjustments. The proposal does not require VF0 magni-tude to be invariant across languages, speakers, or prosodic contexts. Articulatory configurations, baseline laryngeal settings, and other aspects of implementation may differ, while enhancement or competing linguistic uses of F0 may additionally modulate the acoustic outcome. Consequently, inventory-size and tone effects cannot straightforwardly adjudicate between automaticity and enhancement. More informative is the combined evidence from the direction of VF0, its prevalence across speakers, and any within-category relationship to F1, interpreted with appropriate caution.

The present study investigates these issues through four empirical questions: 1.

How stable is the VF0 effect between high and low vowels across languages and individual speakers? If biomechanical factors contribute systematically to VF0, we expect high vowels to exhibit higher F0 than low vowels across a substantial majority of languages and speakers. We also compare /i/ and /u/, which share the same phonological height specification, as a baseline for evaluating whether the high-low differences are particularly systematic. Although these vowels differ in other articulatory properties, there is no corresponding height-based prediction for a consistent difference in F0 between them.

2. Does the magnitude of VF0 vary with vowel inventory size? If F0 is recruited to enhance vowel-height contrasts, larger inventories may be associated with greater F0 differentiation. However, inventory size may also be associated with differences in vowel spacing or other aspects of articulation, so any observed relationship would not uniquely establish contrast enhancement.

3. Does VF0 vary across languages as a function of the lexical tone system? We test whether VF0 differs across non-tonal, simple tone, and complex tone languages. Because F0 carries lexical contrasts in tone languages, these systems may differ in the extent to which the intrinsic effect is expressed. However, systematic modulation by tone is not necessarily inconsistent with a biomechanical source, since the relevant articulatory and laryngeal settings may also vary across prosodic systems. 4. Do F1 and F0 covary continuously within individual vowel categories? If VF0 is partly a mechanical byproduct of vocal fold tension induced by tongue position, this relationship should not be restricted to categorical differences between high and low vowels. A negative relationship between F1 and F0 within a vowel category would be consistent with such coupling: realizations with higher F1, corresponding approximately to lower tongue positions, would also exhibit lower F0. The strength of this association may differ across vowels. We draw a methodological parallel to studies of intrinsic vowel duration (Chodroff and Zhang, 2026; Coretta, 2023; Toivonen et al., 2015), which have examined whether continuous within-category variation in vowel height predicts duration. Evidence for an analogous relationship in VF0 would be consistent with biomechanical coupling operating at the level of individual vowel tokens.

III. METHODS

A. Corpus and dataset

The data analyzed in this study are from the VoxCommunis Corpus, a large-scale multilingual phonetic corpus with time-aligned phonetic transcripts for read speech audio recordings from 75 languages (Ahn and Chodroff, 2022) in the crowdsourced Mozilla Common Voice Corpus (Ardila et al., 2019). Because the Common Voice dataset relies on ambiguous 'client ID' labels rather than explicit speaker metadata, recordings with a similarity score below 0.4 were excluded to better approximate distinct yet still anonymous speaker identities following the protocol described in Zhang et al. (2025).

For each main vowel-pair (/i/-/a/, /u/-/a/, and /i/-/u/) comparison, a speaker needed at least ten usable tokens in each of the two relevant vowel categories, and a language required at least five qualifying speakers. Speaker and language eligibility was determined separately for each comparison. To examine how F0 differ between high and low vowels, and between high front and high back vowels, the broad vowel categories /i/, /u/, and /a/ include all vowels transcribed as [i, I, y, Y, ô " , ] (the last four are transcriptions used for Mandarin apical vowels as found in words such as /sô " Ď£/ 'four' or /ùó " Ď£/ 'to be'), [u, U, W], and [a, 6, A, Q, æ], respectively.

The Abkhaz [@] is also coded as /i/ because there are only two phonemic vowels in Abkhaz: /@, a/. Only short vowels were included, except that in Central Kurdish and Kurmanji Kurdish, long [i:] and long low vowels [a:, A:, 6:, Q:, æ:] were also eligible for the corresponding broad categories. This exception accounts for the long-vowel transcriptions used in the two Kurdish datasets due to lack of short /i/ or /a/ in the broad vowel categories; other long vowels remain excluded. Only Catalan tokens marked with primary or secondary stress were retained, since /a/ rarely occurs in Catalan unstressed syllables.

For the within-speaker F1-F0 correlation analysis, we selected one most frequent eligible vowel symbol per language and peripheral vowel region (high front, high back, and low) in our data. The same Kurdish long-vowel exception applied. The Abkhaz /@/ is again treated as a special case of /i/. The correlation analysis treated the selected vowels from each of the three peripheral vowel regions as high front, high back, and low vowels. For any selected vowel from a language to be included in the correlation analysis, the speakers needed at least 10 usable tokens of the selected vowel, and a language-vowel needed at least five such qualifying speakers. Speakers and languages were not required to contribute all three vowels.

The languages were classified into three groups in terms of whether they have lexical tones: non-tonal, simple tone, and complex tone languages, according to the criterion in Hyman (2006), as indicated by colors on language names in Figure 2.

The /i/-/a/, /u/-/a/, and /i/-/u/ datasets contained data, respectively, from 52,498 (median per language: 159), 34,126 (median: 138.5), and 33,561 (median: 123.5) speakers. The numbers of vowel tokens were 42,249,060 for /i/-/a/, 35,940,379 for /u/-/a/, and 22,836,875 for /i/-/u/. V. DISCUSSION

The present study investigated the crosslinguistic distribution of vowel intrinsic F0 (VF0) in a large-scale corpus analysis. A central goal was to evaluate the origins of the effect: that is, whether it reflects a biomechanical consequence of uniform phonetic targets or speakercontrolled enhancement of the contrast. Across 75 languages from 18 language families, high vowels were on average produced with a higher F0 than low vowels, both across languages and across individual speakers, while with no apparent bias in the F0 difference between high front and high back vowels. We begin our discussion by restating the four research questions posed in §II C and summarizing what the results showed for each.

1. How stable is the VF0 effect between high and low vowels across languages and individual speakers? The effect was in the expected direction in the large majority of languages (95% for /i/-/a/ and 89% for /u/-/a/), and the majority of individual speakers also produced a higher F0 for high vowels than for low vowels. In contrast, estimates were centered near zero.

434 2. Does the magnitude of VF0 vary with vowel inventory size? Vowel inventory size correlated weakly positively with VF0 magnitude in all three comparisons, but none of the correlations reached significance.

3. Does VF0 vary across languages as a function of word prosodic system? Neither simple nor complex tone languages differed significantly from non-tonal languages in any of the three comparisons.

4. Do F1 and F0 covary continuously within individual vowel categories? Most withinspeaker correlations were weak, but positive correlations were more common in all three selected vowel regions and most common in the high vowels. Pooled mixedeffects models estimated positive F1 coefficients, with a smaller estimated value for the low vowel.

A. Biomechanical origins and speaker control

Several aspects of the present results are consistent with a biomechanical origin for VF0.

The direction of the effect was highly consistent across languages (95% for /i/-/a/ and 89% for /u/-/a/) and among individual speakers. Even in some languages whose overall estimate was negative (/i/-/a/ in Yakut, /u/-/a/ in Central Kurdish), the majority of speakers still conformed to the expected direction. The comparison between the two high vowels, /i/ and /u/, provides a useful contrast: although these vowels differ in backness and other articulatory properties, no systematic F0 asymmetry emerged across languages or speakers. Moreover, VF0 was generally small in magnitude, remaining below approximately two semitones across nearly all languages, consistent with previous crosslinguistic findings (Ting et al., 2025; Whalen and Levitt, 1995). These patterns are compatible with a biomechanical influence of vowel-height articulation on vocal fold vibration.

However, the token-by-token F1-F0 analysis presents a substantial challenge to a purely automatic biomechanical account of VF0. If differences in tongue height mechanically induce corresponding changes in vocal fold tension, then variation in vowel height within individual vowel categories should also be accompanied by systematic F0 differences. Specifically, a higher F1, corresponding approximately to a lower tongue position, should be associated with lower F0. Contrary to this prediction, within-category correlations were generally weak and skewed positive, particularly for the high vowels, and the hierarchical analysis revealed a positive F1 coefficient for all three vowels. Notably, the relationship was not simply absent: its direction tended to be opposite to the biomechanical prediction. Within high vowels, tokens with higher F1 also tended to exhibit higher F0, a pattern that could serve to maintain the perceptual distinction associated with vowel height even when its primary acoustic correlate is less extreme. These findings are difficult to reconcile with a purely passive biomechanical coupling between tongue position and F0.

The observed crosslinguistic and speaker-level variability provides additional, though less direct, evidence for phonetic control. Dutch and Upper Sorbian exhibited particularly large VF0 effects, especially for /u/-/a/ (see also Van Hoof and Verhoeven (2011) for Dutch), and the degree of speaker-level consistency varied across languages. However, the weak, nonsignificant inventory-size correlations and the absence of significant tonal-category differences provide no clear evidence of systematic modulation by these two language-level factors.

Taken together, these results suggest an important distinction between the possible origins of VF0 and its realization in contemporary speech production. The consistency of the categorical effect may reflect a biomechanical bias associated with vowel-height articulation, but the opposite direction of the within-category F1-F0 relationship suggests that F0 is not simply determined by the immediate mechanical consequences of tongue position. Rather, its realization seems consistent with additional speaker-controlled or learned phonetic coordination that can counteract the predicted biomechanical relationship. One possibility is that speakers adjust F0 to reinforce vowel-height distinctions, although the acoustic correlations alone cannot establish intentional enhancement or online compensation. Nevertheless, the results provide substantial reason to question a purely automatic account of VF0: its crosslinguistic directionality may be physiologically motivated, while its token-level implementation appears to be subject to phonetic control.

B. The relationship between intrinsic vowel effects and target uniformity

The distinction between categorical and token-level behavior becomes particularly striking when VF0 is compared with intrinsic vowel duration (IVD), another widespread acoustic correlate of vowel height examined using a parallel corpus-based approach (Chodroff and Zhang, 2026). At the categorical level, the two effects exhibit similar crosslinguistic regularities: high vowels tend to have both higher F0 and shorter durations than low vowels. At the token level, however, they diverge. In the IVD study, F1 and duration were positively correlated within /a/ for the large majority of speakers: lower vowel realizations, reflected in higher F1, tended to be longer. This relationship is consistent with the predicted continuous biomechanical coupling between vowel articulation and duration. In contrast, the present VF0 analysis found little evidence for the predicted negative relationship between F1 and F0, instead revealing correlations that tended in the opposite direction. Thus, similar categorical regularities do not necessarily imply comparable relationships between vowel height and its secondary acoustic correlates at the level of individual vowel tokens.

The target uniformity account proposed by Chodroff and Zhang (2026) offers one possible explanation for the shared categorical regularities. The account makes explicit an assumption underlying biomechanical explanations of intrinsic vowel effects: certain phonetic targets must remain relatively uniform across vowel categories for differences in articulatory configuration to yield systematic acoustic consequences. Applied to VF0, relatively uniform underlying laryngeal settings could allow differences in tongue and jaw configuration to produce F0 differences without requiring independently specified pitch targets for high and low vowels. This interpretation is compatible with the widespread directionality of VF0 and allows for variation in its magnitude through additional language-or speaker-specific phonetic control.

However, target uniformity does not currently account for the discrepancy between the token-level findings for IVD and VF0. A principle of relatively uniform target specification might explain why systematic differences emerge between vowel categories without necessarily requiring that the same relationship be observed across individual realizations.

Nevertheless, if the relevant biomechanical coupling operates continuously, variation in vowel height would still be expected to produce corresponding changes in F0, unless other factors intervene. While an absence of within-category correlations might be attributable to such factors, the tendency toward positive correlations is more difficult to explain. Target uniformity alone provides no mechanism for generating a relationship opposite to the predicted biomechanical effect. It may therefore help explain the categorical pattern of VF0, but is insufficient to account for its fine-grained phonetic realization.

One possible explanation for the divergence between IVD and VF0 is that speakers exert more flexible control over F0 than over duration. F0 is centrally involved in lexical tone and intonation, and speakers can rapidly adjust vocal pitch in response to experimentally induced perturbations (Burnett et al., 1998; Löfqvist et al., 1989). Vowel duration, however, can equally be used for length and consonant contrasts (House, 1961; Ryan, 2026), but it may be more directly constrained by the kinematics of the articulatory gestures involved in vowel production (Coretta, 2023; Lindblom, 1967; Toivonen et al., 2015). This difference could allow speakers to maintain or modify F0 independently of the immediate consequences of vowel-height articulation, even while preserving a categorical VF0 pattern whose direction is grounded in biomechanical tendencies. However, the present acoustic data cannot determine whether the observed relationships reflect active compensation, learned coordination, or other factors influencing F1 and F0.

Accounting for the contrasting token-level results for duration and F0 will require a more detailed understanding of how target specification interacts with the biomechanical and speaker-controlled processes involved in individual phonetic realizations. The two intrinsic vowel effects may therefore share a common basis for their categorical regularities while differing substantially in the mechanisms governing their continuous variation.

C. Limitations and Future Directions

While the current findings demonstrate remarkable consistency across a broad sample of languages, several limitations remain. Given the wide range of linguistic diversity, it was prohibitively difficult to account for a wide range of prosodic variations including internal phrase structure that might be present within the utterance, along with pitch accent, boundary tone, lexical stress, and lexical tone variation. A limited set of corrections were applied to mitigate this, such as utterance percentage as a rough approximation to the well-known F0 declination that occurs across most prosodic phrases and utterances (Collier, 1975; Ladd, 1984; Pierrehumbert, 1979). In addition, the random intercept for word within each language-specific model could provide a rough estimate for lexical effects on F0, such as frequency and, less directly, neighboring segmental effects. For several, but critically not all, tone languages (Cantonese, Mandarin, Taiwan Minnan, Thai, Vietnamese), we were also able to include statistical control for phonological tone on F0 prediction. However, these corrections provide a merely superficial control over prosodic variation that is inherently present throughout the data. Furthermore, the range of vowel inventory sizes in the current sample was relatively restricted: only two languages had more than 12 vowels. In addition, future work should address potential non-independence arising from geographic clustering and genealogical relatedness among languages (Graff et al., 2025).

Expanding the dataset to include more languages, particularly from underrepresented regions such as the Americas, will be crucial for assessing the robustness of the observed patterns. Additionally, a closer examination of the few non-conforming languages and speakers may reveal important exceptions or constraints that refine our understanding of VF0 universality. Follow-up studies focusing on individual languages could provide more precise control over linguistic and prosodic factors that influence F0 variation, shedding light on languagespecific mechanisms. Finally, future research should explore the perceptual consequences of these patterns to identify the extent to which the observed crosslinguistic differences in VF0 production are perceptually salient, and whether the magnitude of production correlates with their perceptual relevance.

VI. CONCLUSION

Across 75 languages and 18 language families, high vowels consistently exhibited higher F0 than low vowels, while no comparable asymmetry emerged between high front and high back vowels, providing further evidence for VF0 as a widespread phonetic universal. These categorical patterns are consistent with a biomechanical contribution to VF0, potentially mediated by relatively uniform underlying phonetic targets across vowel categories. Although VF0 magnitude varied across languages and speakers, evidence for systematic contrast enhancement was limited. Importantly, however, the within-category F1-F0 relationships did not follow the predicted biomechanical pattern, instead tending toward positive correlations, particularly for high vowels. This contrasts with intrinsic vowel duration, for which withincategory variation was more consistent with biomechanical predictions (Chodroff and Zhang, 2026). The discrepancy suggests that similar categorical regularities may arise alongside different patterns of fine-grained phonetic variation, which the target uniformity framework does not yet fully explain.

For the five languages with tone annotations (Cantonese, Mandarin, Taiwan Minnan, Thai, and Vietnamese), phonological tone and its interactions with vowel height and utterance position were also included as fixed effects, with phonological tone sum-coded. The Vietnamese /i/-/a/ model and the Taiwan Minnan /i/-/u/ model instead included tone as an additive fixed effect without interactions. Tone could not be included for the remaining tone languages owing to the lack of tone annotations. In languages where the maximal model failed to converge, the interaction term and the by-speaker random slope of vowel height were dropped. If the linear mixed effect model always resulted in a singular fit, simple linear regression was used.
