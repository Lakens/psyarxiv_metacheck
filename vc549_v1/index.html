Meta-scientific research has shown nonsignificant p values are commonly misinterpreted. It is incorrect to infer that there is ‘no effect’, ‘no difference’, or that groups are ‘the same’ after p > 0.05.

It is possible that there is a true non-zero effect, but that the study did not detect it. Make sure your inference acknowledges that it is possible that there is a non-zero effect. It is correct to include the effect is ‘not significantly’ different, although this just restates that p > 0.05.

This module searches for statements of ethics approval, IRB approval, institutional review board approval, and related terms.

Patterns are designed to capture:

How Power Analysis Check works

This module uses regular expressions to identify sentences that contain a statistical power analysis. If specified by the user, it also uses a large language model (LLM) to extract information reported in power analyses, including the statistical test, sample size, alpha level, desired level of power, and magnitude and type of effect size.

The Power Analysis Check module uses regular expressions to identify sentences that contain a statistical power analysis. Without the use of an LLM, the module uses regular expressions to classify the power analysis as a-priori, sensitivity or post-hoc. With the use of an LLM, it checks if the power analysis is reported with all required information.

The regular expressions can miss power analyses, or fail to classify them correctly. The type of power analysis is often difficult to classify, which can easily be solved by explicitly specifying the type of power analysis as ‘a-priori’, ‘sensitivity’, or ‘post-hoc’. Note that ‘post-hoc’ or ‘observed’ power is rarely useful. The LLM can fail to identify information in the paper, and will not have access to information in paragraphs in the paper other than those that contain the word ‘power’. This package was validated by the Metacheck team on articles in Psychological Science.

This module was developed by Lisa DeBruine, Daniel Lakens and Cristian Mesquida

Overall, among all instances flagged as power statements, 90.6% were correct (positive predictive value).

How Preregistration Check works

Retrieve information from preregistrations in a standardised way, and make them easier to check.

The Preregistration Check module identifies preregistrations on the OSF and AsPredicted based on links in the manuscript, retrieves the preregistration text, and organizes the information into a template. The module retrieves text from the OSF with its API, and from AsPredicted with ResearchBox’s API when a ResearchBox key is set (see rbox_token()), or else from the preregistration’s web page. The information in the preregistration is returned. An AsPredicted link that could not be read is named in the report, with the reason.

The module can’t extract information from non-structured preregistration templates (i.e., where the preregistration is uploaded in a single text field) and it can’t retrieve information in preregistrations that are stored as text documents on the OSF.

If you want to extend the package to be able to download information from other preregistration sites, reach out to the Metacheck development team.

How StatCheck works

Check consistency of p-values and test statistics

The Statcheck module runs Statcheck. Statcheck searches for regular expressions that match a predefined pattern, and identifies APA reported statistical tests. More information on the package can be found at https://github.com/cran/statcheck. The module only returns Statcheck results for t-tests and F-tests, as these are the only tests which have been validated, see https://osf.io/preprints/psyarxiv/tcxaj_v1/.

Statcheck was developed by Michèle Nuijten and Sascha Epskamp.

Statcheck considers p = 0.000 an error, as you should report p < 0.001. Furthermore, p < 0.03 is an error if the p-value was 0.031, and one should simply report exact p-values (p = 0.031). When the sentence of a test says it is one-sided (“one-tailed”, “one-sided” or “directional”), a p-value that fits a one-sided test counts as consistent (statcheck’s OneTailedTxt setting; #695). When the paper says anywhere that its tests are one-sided, a p-value that fits a one-sided test in either direction counts as consistent too: half the two-sided p, or 1 minus that half for an effect against the predicted direction. Equivalence tests (TOST) are left out, as their p-values do not test the difference. A statistic written with “<” or “>” is read as a bound, and in a sentence about equal variances an F-test’s two-sided p (twice the one-tailed p) counts as consistent. For more information, see StatCheck.

This module only checks statistical results reported in the running text of the manuscript. It cannot (yet) process statistics reported only in tables.

This module was developed by Daniel Lakens and Lisa DeBruine

Read more in the metacheck manual.

Therefore 0% of true instances were missed, and 43% of detections were false positives. See https://osf.io/preprints/psyarxiv/tcxaj_v1/ for more details of the validation.

How Exact P-Values works

List any p-values reported with insufficient precision (e.g., p < .05 or p = n.s.), reported as exactly zero (e.g., p = .000), or impossible (below 0 or above 1, e.g., p = -.22).

This module uses regular expressions to identify p-values. It will flag any values reported as p > ? or p < numbers greater than .001. It will also flag p-values reported as exactly zero (e.g., p = .000, p = 0.00), which are mathematically impossible — p-values are never exactly zero and should instead be reported as p < .001.

A p-value that is not the result of a test is not flagged: a table note (“* p < .05, ** p < .01”), a figure legend (“Asterisks indicate significant differences (p < .05)”, “Values in bold are significant at p < .05”) or a stated threshold (“p < .05 was considered significant”, “thresholded at p < .001”). GROBID often puts such notes into the running text, so each p-value is judged by the words in its own clause (the text up to a “;” or a full stop), and never left out when a test statistic belongs to it (“F(1, 7) = 8.03, # p < .05”). The column not_a_test of the table says why a p-value was left out (“marker”, “threshold”, “legend” or “named”).

A p-value with the name of a correction or a test after the p (“pFWE < .05”, “padj < 0.05”, “p Wilcoxon = .02”) is flagged only when a test statistic comes before it in its clause (“t(37) = 7.17, p FWE < .05”). Without one it is mostly the rule that decided what was significant (“genes with padj < 0.05 were selected”); such a p-value is “named” in not_a_test. Notes in other forms, such as a marker after the p-value (“p < .05 (*)“), are still flagged.

A p-value below 0 or above 1 is impossible; it is listed apart and not also as imprecise. Often the statistic before it, or its minus sign, was copied into it (“t(134) = -2.32, p = -.13”, “Z = 3.091, P = 3.091”). A value above 1 is listed only after a test statistic in its clause: without one, a “P” above 1 was nearly always another quantity (a proportion, pH, a group’s mean, a model parameter). A number in scientific notation whose power of ten was lost when the PDF was read (“p = 2.4 x 10 -9” read as 2.4) is not listed. A “p” that is the subscript of another symbol (“r p = .64”, “²p = .02” for partial eta squared, “Δp = .33”), or a quantity with a unit, a logarithm or a ratio (“P = 2.9 µm”, “-log10 P = 7.5”, “Ca/P = 1.67”), is not read as a p-value at all (see extract_p_values()). Each p-value has its own row, also when the same one is written twice in a sentence.

This module sometimes flags false positives when sentences discuss how p-value thresholds were set. It can also miss an imprecise p-value that is reported against a threshold (“decreased at the p < .05 significance threshold”).

This module only checks p-values reported in the running text of the manuscript. It cannot (yet) process p-values reported only in tables (as opposed to a table’s footnote text, which the module does see and tries to exclude — see above).

How Repository Check works

This module retrieves information from repositories.

The Repository Check module lists files on the OSF, GitHub, ResearchBox, DSpace (PsychArchives and other legacy- and DSpace 7-based installations), Zenodo, Dataverse, Figshare, Dryad, ReShare, 4TU.ResearchData, Mendeley Data, DataONE (Arctic Data Center, KNB, and other member nodes), and LDbase based on links in the manuscript.

A link to a file-sharing service (Google Drive, Dropbox, OneDrive, Box, WeTransfer, MEGA, iCloud Drive, Baidu Netdisk, SURFdrive; see [file_share_links()]) gets a warning and makes the light yellow: such services are not repositories, as files can be changed or deleted at any time, get no DOI, and the link stops working when the account is closed. The report advises a stable repository such as Zenodo instead. Their files are not read, and summary_table$file_share_n counts the links.

Deposits in archives for sequence and expression data (GEO, the INSDC archives BioProject, SRA, ENA and DDBJ, and ArrayExpress; see [seq_archive_links()]), mostly named by accession number, are read for whose deposit they are. The authors’ own are listed with what they hold ([seq_archive_size()]) and are not downloaded or checked as data and code; summary_table$archive_own_n counts them.

R packages on CRAN ([cran_links()], [cran_info()]) are the paper’s own when a paper author is a package author and the paper presents the package; the paper’s own are listed with their version and not checked (summary_table$cran_own_n). A Handle link (hdl.handle.net/...) that leads to a repository read here is checked as a link to that repository ([handle_links()]).

Listing a repository’s files never requires an API key, but some hosts answer faster or more completely with one: OSF allows 100 requests/hour unauthenticated versus 10,000/day with a token (see [osf_pat()]), and Dryad enforces a strict per-IP daily quota on repeated listing (see cache below). Dryad is a special case beyond rate limits: listing a Dryad dataset’s files works without a key, but actually downloading file CONTENTS from Dryad fails with HTTP 401 unless a key is set, even for a fully public dataset (see [dryad_pat()] or [dryad_auth()]). Since this module only lists files and never downloads their contents itself, that limitation applies to data_check and code_check (which do download content), not here – see their own documentation.

When a linked OSF page is a registration, its registered_from project (the one it was registered from, which the manuscript itself may never link directly) is also checked: if that project is public its files are listed under its own URL, and if it is closed or otherwise inaccessible the report flags it explicitly, since some registrations only describe their content rather than mirroring it.

Whose deposit is each link? The ownership table gives, for every repository linked in the text and (with references = TRUE) every deposit cited in the reference list, one of six labels: own_this (made by the authors for this paper), own_earlier_data or own_earlier_code (the authors’ own, from earlier work), others_data or others_code (made by other people, reused here), or not_data (a publication such as a preprint, not a deposit), with ownership_group (“own”, “others”, “not_data”) and the reason. It is decided without a language model, from the sentence or reference that cites the link, the paper’s authors (names, ORCID iDs, affiliations), and what the deposit’s own record and files say (who made it, what it names, when, whether it is a software package; for an OSF project cited only in the reference list, its record alone). On a round of labelled links the rules had not been written from, the three groups were right for 98% of links in the main text (93 of 95) and 90% in reference lists (74 of 82); the labels were made by Claude agents from each link’s evidence, and disputed ones checked against the deposits. Telling this paper’s own deposit from the authors’ earlier one is less certain.

Only the deposits that are this paper’s own are checked. A deposit linked in the text that holds other people’s work (others_data, others_code) or the authors’ earlier work (own_earlier_data, own_earlier_code) is listed in the report, with the reason, but its files are left out of table and kept in table_not_checked: they count toward nothing here (files that do not belong in a repository, naming, READMEs, studies, the traffic light), and code_check, data_check and reproducibility_check, which read table, do not check them either. reproducibility_check still puts the files of theirs that the paper’s code names in the folder the code runs in, as a re-analysis needs the data it re-analyses. When every linked deposit is set aside, the traffic light is “na”. A deposit that is the paper’s own is counted as such when its README, title or description names the paper (its title or DOI).

How Code Check works

This module retrieves information from repositories checked by repo_check about code files (R, Python, SAS, SPSS, Stata, Mplus, MATLAB).

The Code Check module checks R (also R Markdown and Quarto), Python (also Jupyter notebooks), SAS, SPSS, Stata, Mplus, and MATLAB files, using regular expressions to check the code; JASP files are listed but not read. The language of a Quarto document or a notebook is read from the file itself (its engine or kernel), not from its extension. The regular expression search will detect the number of comments, the lines at which libraries/imports are loaded, attempts to detect absolute paths to files, setwd() and install.packages() calls, and lists files that are loaded, and checks if these files are in the repository; R code is also parsed. The module will return suggestions to improve the code if there are no comments, if libraries/imports are loaded in lines further than 4 lines apart, if files that are loaded are not in the repository, if absolute file paths, setwd() or install.packages() are found, and if R code cannot be parsed.

The regular expressions can miss information in code files, or falsely detect parts of the code as a fixed file path. Libraries/imports might be loaded in one block, even if there are more than 3 intermittent lines. The module was tried out internally on papers published in Psychological Science, but has not been formally validated. There might be valid reasons why some loaded files can’t be shared, but the module can’t evaluate these reasons, and always gives a warning.

The module also checks whether the repository pins the R/package versions the analysis actually depended on: an renv.lock file (parsed for the R version and every locked package + its version/source), a sessionInfo()/sessioninfo::session_info() text dump (matched by filename — sessionInfo.txt/session_info.txt and similar, or embedded in a README), or a groundhog::groundhog.library()/checkpoint::checkpoint() date-pin call in the code (a bare library(groundhog)/library(checkpoint) does not count — the pinning call itself must be present). When none of these is found, the report flags it as a reproducibility gap: package versions may drift between when the analysis was run and any later reproduction attempt.

If you want to extend the package to perform additional checks on code files, or make the checks work on other types of code files, reach out to the Metacheck development team.

Checking code requires downloading its file contents. For a paper whose repository is on Dryad, this never succeeds unless a Dryad API key is set: Dryad requires one to download file bytes, even from a fully public dataset (listing the repository’s files does not need one). Without a key, every Dryad-hosted code file is listed but unchecked, and a warning naming Dryad and ?dryad_pat/?dryad_auth is included among the download failures recorded in the manifest.

How Data Check works

This module classifies the files in a repository into semantic types (data, codebook, code, software, output, supplemental, readme, asset, other) and, for tabular data files, extracts each column’s type and summary statistics.

The Data Check module consumes the file list produced by repo_check (or any files added via local_path). Each file is classified with rule-based heuristics layered over metacheck’s file_category() and file_types: file names matching README / codebook patterns win first, then an extension crosswalk, then format-locked extension overrides. For every file classified as tabular data that is available locally, the module reads the file head, describes each column with data_col_facets() and computes summary statistics for numeric columns. Every sheet of a spreadsheet that holds a table is read: a file with several such sheets has its columns under source_file = "file.xlsx [sheet]", and the sheet column names the sheet of any spreadsheet with several sheets; a sheet of notes or a codebook is treated as documentation when the file has another table. Following DDI, a column is described by orthogonal facets rather than a single type: representation (numeric/text/datetime/code — how it is stored), measurement_level (Stevens: nominal/ordinal/interval/ratio), concept (what it measures: reaction_time/age/gender/likert/id/…), role (identifier/measure/condition/timestamp), unit, and a quality state (ok/empty/constant). Concepts are detected by name+value rules (the demographic concepts via data_check_demographic()); when llm_use(TRUE) the model fills concepts and measurement levels the rules left blank. Qualtrics survey exports are recognised (data_check_is_qualtrics()): their extra header rows are stripped so columns type correctly, and the reserved response-metadata columns (StartDate, Duration, Finished, …) are tagged.

The module defaults to rules-only when llm_use(FALSE): columns the rules cannot resolve (ambiguous 3–20-unique integers, ambiguous character columns) fall back to continuous / text respectively. When llm_use(TRUE), ambiguous columns and unresolved file types (other) are sent to llm() for optional refinement, and every file is assigned a study group (ex1, pilot2, shared, …) so that multi-study repositories can be recognised (used by psychds_check). Without an LLM the study group is left NA (unknown).

Column extraction requires files to be readable from disk. Files fetched by repo_check from OSF/GitHub/etc. without a local copy (file_location is NA) are classified but not column-extracted; pass local_path to point at a downloaded copy of the repository.

For a paper whose repository is on Dryad, this means column extraction never happens unless a Dryad API key is set: Dryad requires one to download file bytes, even from a fully public dataset (dataset listing and metadata do not need one). Without a key, every Dryad file stays classified but un-downloaded, column_n is 0, and a warning naming Dryad and ?dryad_pat/?dryad_auth is included among the download failures. A one-time session message is also shown (see repo_check) the first time a Dryad dataset is encountered with no key set.

Every downloaded text file the authors wrote (code, settings, survey definitions such as Qualtrics .qsf files, documentation, outputs) is searched for keys: API keys, access tokens and private keys, which let anyone who downloads the file use a paid service at the authors’ cost. Of a tabular data file only the column names and first 3 rows of the table as read are searched: its values come from participants, but a key the authors set for a whole survey (as embedded data in a Qualtrics survey flow) is exported in every response. The search uses the rules of the secret scanner betterleaks (https://github.com/betterleaks/betterleaks, MIT licence) of high and medium confidence. A key found turns the traffic light red; the report and the keys table give its file, line and type, and only its beginning. Other files over 25 MB and binary files are not searched. A key is never tested with its provider. Every module’s result has any whole key replaced by “keyremoved” (see module_run()).

How Reproducibility Check works

This module assesses whether a paper’s R and Python code can be run on its data. It works in two phases. The static phase (always run) collects the package dependencies the code declares, rewrites the data-file paths that do not work in the repository as the authors organised it, works out the order the scripts must run in, and diagnoses why any referenced input file is unavailable — reporting what a reproduction attempt would involve and where it is likely to break. The execution phase (opt-in, execute = TRUE) then actually runs the code: it copies the repository into a throwaway directory, optionally installs the declared dependencies into a throwaway library, runs each script in order in an isolated subprocess with a per-script timeout, and captures the outcome and full output of each run.

By default (execute = FALSE) the module does not run any code — it performs only static analysis: reading dependencies with the same extractors as code_check, finding the files the code references in the repository, and building a run-order dependency graph. It reports what would be installed and run rather than doing it.

When execute = TRUE, the module additionally runs the downloaded code on your machine — a deliberate, opt-in action gated behind that argument (callr is required for R code). Each script runs in an isolated subprocess so a crash cannot take down the R session; note this isolates crashes, not the filesystem or network. Installs (when install_missing = TRUE) and the throwaway run library never touch your main R library. Each script’s outcome is one of ran_ok, errored, timed_out, dependency_unavailable, not_parsed, run_by_source (an R script another script runs with source(), which is run only inside that script, since on its own it lacks the packages and objects the sourcing script sets up first), run_by_import (a Python file other files import, a module rather than a script, unless it has an if __name__ == "__main__": block), jags_model (a JAGS or BUGS model saved with an R extension, which another script reads) or not_r_content (a file that is not R at all, such as a JSON or HTML dump); these last two are not run and are not failures. python2 marks Python 2 code that was not run. With sandbox = "docker" such code runs with Python 2.7 (option metacheck.docker_image_py2; FALSE turns this off), which modifications records; it is never converted, since that can change results. defines_functions is a file that only defines functions, which is used, not run (table$used_by names the scripts that use it), and not_analysis is a file of software rather than of the analysis: a package’s code, tests, documentation or setup.py, a copy of a tool, a web application, a script a program wrote (table$not_analysis_why says which); neither is run or counted as a script. docker_failed means the container never started, which says nothing about the script, so it keeps the light from being green but does not make it red. needs_a_person is a script that stopped because it asks a person to choose a file or answer a question, or that starts an app, and needs_internet one that stopped because the network is off in a Docker run, or, with internet = TRUE, could not reach what it asked for; download_too_large is a script stopped for downloading more than the limits allow (see internet), and out_of_memory one that, or a program it started (such as a compiler), ran out of the memory each script may use. All four are treated the same way. not_downloaded is a script that stopped on a file the repository lists but that was not downloaded, such as one over max_file_size: it could not be tried, so it is not counted as a script that did not reproduce (summary_table$repro_not_downloaded_n counts them apart). not_read is a file metacheck could not read, so it was not run; the light is then not green, as the file may read and run on another computer, and table$error_message says why, naming a package that is installed but cannot be loaded on the computer that ran the check. empty is a file with nothing in it, which is not run or counted as a script. For a script that did not run through, table$error_message is its error, short (at most 300 characters): the error line of its output, which names a package that is not there, with the address it asked for when it needed the internet, or the time limit it reached; table$reason sorts it into a kind. A timeout means “still running at the cutoff”, not a failure, so raise timeout for legitimately long-running (e.g. Bayesian) scripts. dependency_unavailable means the script’s own package could not be installed from live CRAN, the CRAN Archive, or a named GitHub/URL source — an infrastructure limitation, not a defect in the paper’s code. The full stdout/stderr of every run is kept in the result’s run_results (the report shows it in per-script dropdowns, capped for readability).

Provenance, kept so that a TRACE Research Object (TRO) declaration of the run can be written later from a stored result (metacheck #404; the helpers are in R/provenance.R). Only when code was run (execute = TRUE): * run_results$started_at, run_results$ended_at: when each run of a script started and ended (ISO 8601, UTC, milliseconds); NA for a script that was not started. A script run again in a later pass has the times of its last run. A TRO uses them for each trov:TransparentResearchPerformance. * run_results$exit_status: the exit status of the process that ran the script (0 = ended normally); NA when the process did not report one (a time limit, or Docker failing to start the container). * artifacts: one row per file, with stage (deposit: as downloaded from the repository, hashed from the downloaded file; before_run: the run folder just before the first script ran, after metacheck’s own changes, such as rewritten paths and unpacked archives; after_run: only the files the scripts made (status new), changed (changed) or removed (removed), as an unchanged file is the one listed before the run), path (relative to the run folder, as valid UTF-8, a byte of another encoding written as <xx>), size (bytes), sha256, mime_type (by extension, NA when unknown), source (the file’s address in the repository, for deposit). The package libraries metacheck installs in the run folder are left out, as are metacheck’s own files there (a script’s runner, and the statistical output it writes in statistical_output/). Files metacheck itself copied or made between passes (see modifications, output_copied, file_placed) show in after_run too. A TRO uses the rows as trov:ResearchArtifacts and each stage as a trov:ArtifactArrangement. * modifications$sha256_before, modifications$sha256_after: the hash of the changed script as downloaded and as it ran; NA when the script is not at the same path in both (a script made from an R Markdown file). * environment: the system that ran the code (trov:TransparentResearchSystem in a TRO): metacheck_version, started_at, ended_at, host (R version, platform, operating system), sandbox, network_isolated (TRUE only when every Docker run had --network none; the process sandbox does not stop the network), internet, timeout_per_script, total_timeout, python_local (the Python run outside Docker and its version), and docker: runs (for each kind of run, r_run, r_install, python_run, python_install, the image and the docker run arguments, such as --network none, --read-only, --cap-drop ALL, no-new-privileges, the process limit and the memory and processor limits) and images (for each image, its ID and digests from docker image inspect, its creation time and the R and Python versions its environment declares).

run_results$checked says what the run of each script shows about the code, in five groups, so that a script that does not reproduce is kept apart from one the check could not test: ran (it ran to the end); code_error (it did not reproduce: it stopped with an error of the code or the deposit, could not be read, or needs a file the deposit does not hold); dependency (a package or program was not available: a package that could not be installed or was not loaded, a program outside R and Python, a system library, or R crashing in a package’s compiled code); time (it did not finish within the time limit for one script, or was not started because the time for all scripts had run out); and not_checkable (it could not be checked automatically: it needs a person, the internet, a key or another setting of the authors’ computer, one platform such as Google Colab, Windows or OpenSAFELY, more memory than the run allows, a file that was not downloaded, a screen, or a program that runs it, or it is a file of a package of the code that Python runs only as a module of that package). It is NA for files run inside another script, files that are not an analysis, files not read, and a Docker failure. summary_table counts each group (repro_ran_n, repro_code_error_n, repro_dependency_n, repro_time_n, repro_not_checkable_n), and the report’s first sentence gives them. The traffic light reflects the static readiness signals by default; a script in code_error that stopped with an error makes it red, as a script that crashes on its own analysis is a genuine reproduction failure, and a script in one of the other three groups keeps it from being green. Calls that need a screen, which the run does not have (dev.print(), dev.copy2pdf(), dev.copy2eps(), savePlot(), windows(), win.graph(), x11(), quartz(), View()), are replaced before the run by calls that need none, which modifications records as screen_call_replaced. A script that fails with could not find function is run once more with the library() calls the project’s other scripts make added at its top (or the one package that exports the function, or magrittr for %>%), and a script that then runs is reported as reproducible only after that repair.

Dependencies are reported name-only, with the source (CRAN, GitHub, or a base package already shipped with R) — static analysis of the code cannot know which version was used, and running against current package versions is itself informative: a break argues the authors should have pinned versions. When the repository does record versions, a run with recorded_versions = TRUE installs the packages the scripts load at those versions, but it does not change the R version, which remains a limitation of the check.

Run order is derived from read-after-write data dependencies (a script writing a file another reads must run first), source() edges, and numeric filename prefixes as a weak tie-breaker. Ambiguous orderings, dependency cycles, and inputs a script reads but that no earlier script produces (and that are not in the repository) are surfaced as warnings, since these are the situations most likely to make an otherwise-correct reproduction fail.

Abstract

Response-conflict tasks, such as the Simon and flanker tasks, are widely used to study how individuals exert cognitive control to override prepotent automatic responses (habits) in favor of goal-directed actions (goals). As task demands vary-from local, trial-by-trial interference to global changes in conflict frequency-control parameters may need to be adjusted to maintain task performance. Such cognitive control adaptations can be examined through congruency sequence effects (CSE, the congruency effect is reduced following an incongruent trial compared to a congruent trial) and list-wide proportional congruency effects (LWPCE, the congruency effect is reduced in mostly incongruent compared to mostly congruent blocks). Although both effects involve adjustments in control, it remains unclear whether these adjustments reflect similar or different mechanisms. Here, we used a "forced-response" paradigm combined with a computational model to understand the temporal dynamics of cognitive control that contribute to CSE and LWPCE. This approach allowed us to decompose cognitive control into the latencies of habitual and goal-directed processing and the probabilities with which these processes are expressed as overt behavior. We found that both recent conflict (driving the CSE) and frequent conflict within a block (driving the LWPCE) accelerated goal-directed processing and-in the Simon task onlyincreased the likelihood of inhibiting the habitual output; the LWPCE persisted after accounting for previous-trial congruency and thus could not be fully reduced to an accumulation of the CSE. These findings indicate that cognitive control adaptations share a common computational signature when regulating conflicts at both short and long timescales.

Introduction

When driving in North America (right-hand-traffic rules), British drivers, who are used to lefthand-traffic rules, must adopt new driving behaviors, such as driving on the right side of the road, making right turns on a red light (but not left turns on a red light). To avoid serious accidents, they need to keep their new driving goals in mind to combat their habitual tendencies learned from years of experience driving in Britain. This example showcases one of many instances when habitual and goaldirected behaviors collide.

Many behaviors are driven by fast, automatic, and unconscious "habitual" processes. In contrast, goal-directed behaviors require the involvement of an executive system that is more flexible at the cost of slower processing. These two dissociable processes can jointly mediate one instrumental behavior, as outlined by 'dual-process' theories (Dickinson, 2016; Dolan & Dayan, 2013; Norman & Shallice, 1986).

Hereafter, we use the terms "habit" and "goal" as shorthand for habitual and goal-directed responses, respectively. When a habit is aligned with a goal, achieving the goal is easy and efficient. However, when the habit conflicts with the goal, a set of mechanisms by which the brain regulates behavior in line with the goal is needed to override the prepotent habitual response and resolve the conflict. Over decades, researchers have sought to elucidate how adjustments in cognitive control affect our behaviors during conflict resolution.

Some experimental tasks have been widely used to investigate conflict resolution, such as the Eriksen flanker task, the Simon task, and the Stroop task (Eriksen & Eriksen, 1974; Simon, 1969; Stroop, 1935). For instance, in one version of the flanker task, participants are asked to indicate the direction of a centrally presented arrow while ignoring the flanking arrows that could either signal a congruent response (">>>>>" or "<<<<<") or an incongruent response (">><>>" or "<<><<") (Eriksen & Eriksen, 1974; Stoffels & van der Molen, 1988). As another example, in an arrow version of the Simon task, participants are asked to press a key on the left or right side of a keyboard to indicate the direction of an arrow ( or →) presented on the left or right side of a screen. The direction of the presented arrow can be congruent (e.g.,  on the left side) or incongruent (e.g.,  on the right side) with the spatial position of the arrow (left or right side) (Horga et al., 2011; Simon, 1969). In both tasks, the habitual response aligns with the goal on congruent trials, but conflicts with the goal on incongruent trials, invoking a competing response that needs to be inhibited.

Both response time (RT) and accuracy rate for different trial types are typical dependent variables to assess performance. The difference in mean-RTs comparing incongruent trials to congruent trials is commonly used to measure the "congruency effect" (Kornblum et al., 1990; Kornblum & Lee, 1995; Zhang et al., 1999). That is, longer RTs on incongruent trials reflect the additional time needed for conflict resolution during which goal-directed processing overrides habitual processing. The magnitude of the RT difference serves as a key indicator of cognitive control efficiency, with smaller values signifying more efficient conflict resolution. Likewise, the difference in accuracy rate between congruent and incongruent trials is also used as a dependent measure, with accuracy on congruent trials typically being higher than on incongruent trials.

Adjustments of Cognitive Control

Cognitive control is flexible and can adjust dynamically based on environmental context to better enable goal-directed behavior (e.g., Gratton et al., 1992; Botvinick et al., 2001). Two basic observations provide evidence for adaptive control in conflict resolution: the congruency sequence effect (CSE) and the proportional congruency effect (PCE; we focused on the list-wide PCE in this paper and will always use "PCE" in the following text). The CSE refers to the fact that a stronger congruency effect occurs on trials following a congruent trial than on the trials following an incongruent trial (Egner, 2007; Gratton et al., 1992). The PCE refers to the fact that congruency effects are weaker in blocks with mostly incongruent trials compared to blocks with mostly congruent trials (Lehle & Hübner, 2008; Lindsay & Jacoby, 1994; Logan, 1980; Logan & Zbrodoff, 1979; Toth et al., 1995). The CSE implies that there can be short-timescale sequential or transient modulation of cognitive control, whereas the PCE implies that global or long-timescale modulation of cognitive control also occurs. Alternative accounts of these two patterns of cognitive control adjustments have been discussed for many years. Here, we summarize two major accounts to explain the CSE and PCE: the attentional shift account (Botvinick et al., 2001) and the response modulation account (Logan & Zbrodoff, 1979; Ridderinkhof, 2002), as contrasted by Weissman and his colleagues (Weissman et al., 2024; Weissman & Saba, 2024).

The key hypothesis of the attentional shift account is that cognitive control processes reallocate attention between target and distractors depending on previous trial congruency. This account posits that cognitive control adjustments occur during the information processing stage derived from the stimulus or response conflict on the previous trial (Botvinick et al., 2001; Duthoo et al., 2013 Duthoo et al., , 2014;; Egner et al., 2010; Gratton et al., 1992; van den Wildenberg et al., 2012). In this view, target information processing is enhanced while distractor processing is suppressed following an incongruent trial. In contrast, the response modulation account claims that control processes operate at the response level, inhibiting the distractor-associated response from the preceding trial before the current target response comes online. It encompasses two sub-variants: Ridderinkhof's activation-suppression hypothesis, in which the distractor-activated response is suppressed following incongruent trials and the suppression carries over to the subsequent trial (Ridderinkhof, 2002), while Logan's response expectation hypothesis suggests that subjects expect the same trial type after an incongruent trial and pre-activate the opposite response of the current distractor signal (Logan, 1985; Logan & Zbrodoff, 1979). Framed in terms of the dual-process system, the attentional shift account amounts to shifting inputs that feed into goal-directed and habitual processes depending on the previous trial congruency, whereas the response modulation account centers on how the output of the habitual process is regulated by cognitive control.

Both accounts can be applied to explain the list-wide PCE. According to an attentional shift account, experiencing conflict frequently in a mostly incongruent block proactively shifts attention away from the distractors toward the target. In contrast, the response modulation account suggests that the memory of conflict probability in a block biases the response expectation of the most probable trial type (Logan, 1985; Logan & Zbrodoff, 1979; Weissman et al., 2024; Weissman & Saba, 2024). The outcome of the automatic process would be activated if congruent trials were more frequent and it would be suppressed if incongruent trials were more frequent. Note, however, that the typical PCE design is confounded by a different proportion of congruency of previous trials. That is, PCE could reflect the cumulative effect of these trial-to-trial adjustments rather than an independent adaptation to the overall proportion of congruency. Therefore, some researchers have proposed that the PCE could be driven by an accumulation of many CSEs (Aben et al., 2017; Braem et al., 2019; Braver, 2012; Braver et al., 2007; Bugg & Crump, 2012; Weissman et al., 2024; Wühr et al., 2015). Based on this perspective, the reduction of the congruency effect with conflict on short or long timescales may derive from similar mechanisms of cognitive control adjustment.

Yet there are also alternative views and evidence supporting the idea that the PCE taps into a separate mechanism from the CSE. Studies using a Spatial Stroop-Simon hybrid paradigm showed that PCE can be transferred across different conflict types whereas CSE is conflict-type specific, and PCE can also be observed even when the CSE is absent (Funes et al., 2010; Torres-Quesada et al., 2013 , 2014). Furthermore, neuroimaging studies by De Pisapia and Braver showed that the detection of shorttimescale and long-timescale conflict is implemented in different units in the anterior cingulate cortex (ACC), as well as activating different modules in the prefrontal cortex (PFC) (De Pisapia & Braver, 2006).

Similarly, aMCC (anterior midcingulate cortex) was found to be more sensitive to a block-wide frequency manipulation of congruent vs. incongruent trials whereas preSMA (pre-supplementary motor area), which lies adjacent to the aMCC, was more sensitive to CSE (Beldzik & Ullsperger, 2024). These neural findings collectively suggest that CSE and PCE have qualitatively distinct control mechanisms.

How is the interplay between goal-directed and habitual processes reconfigured when control demands shift, and do these reconfigurations express in a unified form across short-and longtimescales? Addressing these questions aimed at understanding the nature of the cognitive control processes underlying the CSE and the PCE requires an investigation of how short-timescale and longtimescale conflicts modulate goal-directed and habitual processing. This is a difficult issue to address with the standard dependent measures (accuracy rate and mean-RT) that are used in conflict tasks, as free-response mean-RT (free-RT) approaches only reveal the result of the conflict resolution processes.

What is needed instead is a method that can decompose the response preparation process and so reveal whether CSE-and PCE-related control adjustments differentially act on habitual and goal-directed processing.

Problems with Traditional Measurements of Conflict Resolution

A number of issues have been noted in using free-RT and response accuracy as dependent measures. These issues have become obstacles for studying the full temporal window of cognitive control processes associated with conflict. First, free-RT may not be an accurate reflection of the duration of the cognitive processing required to make a response as prior work has shown that people are biased to delay response initiation even if the response has already been prepared (Haith et al., 2016; Miller & Ulrich, 2013; Wong et al., 2017). Second, people may sacrifice their speed to enhance their accuracy rate or vice versa (the speed-accuracy tradeoff: SAT : Fitts, 1966; Heitz, 2014). Therefore, free RT can be deceptive in some cases: For instance, a fast but error-prone individual may appear to perform better than a slower individual who makes fewer mistakes. Third, RT-difference scores, commonly used to index the congruency effect, are confounded with individual differences in general processing speed and are task-dependent (Draheim et al., 2019 (Draheim et al., , 2021;; Hedge et al., 2018; Miller & Ulrich, 2013). In Stroop tasks, RT-differences are positively correlated with mean-RTs, while in flanker and Simon tasks, there is little variation in RT difference scores between faster and slower individuals (Rey-Mermet & Gade, 2018). These basic problems, detailed in Lee et al. (2024), suggest that a different experimental approach may be necessary to make progress on the nature of adaptive control in conflict tasks.

Most importantly, free-RTs serve as a behavioral endpoint that conflates multiple processing stages into one snapshot of performance, which obscures the distinct processing stages between stimulus perception and response. To determine whether CSE and PCE share similar outcomes because habitual and goal-directed processing interact in the same way throughout response preparation, it is necessary to characterize the full time-course of processing from stimulus onset to response execution.

Some have made inroads to solve this problem by partitioning RT distributions into time bins of relatively fast and relatively slow RTs (Gratton et al., 1992; Miller & Schwarz, 2021; Stins et al., 2008). This is a promising approach, but it has the problem that the partitioning of RTs into bins is idiosyncratic to each participant and not under the control of the experimenter. To uncover the temporal dynamics of cognitive processing masked in free-RTs, we need to sample a broad range of processing times more precisely, particularly when the time available for response preparation is far shorter than that required to fully prepare a goal-directed response. Therefore, stricter and more systematic control of the SAT is needed. There have been improved experiment paradigms that can be used to study the time-course of conflict resolution, such as the "response signal" method proposed by Reed in 1973 (Reed, 1973 , 1976).

A response signal (e.g., a probe consonant) was given shortly after the stimulus presentation, notifying the participants to initiate a response. The time lag between the onsets of the stimuli and the signal is varied trial-by-trial. Another simple way used in previous studies to obtain trials with short RT was to warn the participants whenever their response exceeded a deadline (Gratton et al., 1988; Yu et al., 2009). The main drawback of both methods is that participants cannot predict when the response signal will appear, and so they may adjust their strategy to deal with the uncertainty.

The Forced-Response Approach

To address the issues with free-RTs mentioned above and to dissociate habitual and goaldirected processes, we applied a "forced-response" approach to traditional conflict tasks. First proposed by Schouten and Bekker (1967), the idea of this approach involves fixing response initiation and systematically varying the time available for response preparation (Haith et al., 2016; Hardwick et al., 2019; Lee et al., 2024; Schouten & Bekker, 1967). Here, the onset of the stimulus varies randomly trialby-trial while the onset of the response signal ("GO") is fixed, requiring participants to respond precisely at the response signal. This approach controls "processing time (PT)", defined as the interval from the onset of the stimulus to the actual response (see schematic diagram in Figure 1A). This approach allows experimenters to explicitly examine the SAT function if the distribution of times between stimulus and required response covers the entire range of PT. If responses are always initiated exactly on time, PTs should be uniformly distributed from 0 to 1000 ms, covering a broader range than the typical distribution of free RTs. Average response accuracy at each PT is the dependent variable; thus, the accuracy rate can be plotted as a function of PT (Figure 1B). With a free-response paradigm, conflict resolution has usually been completed by the time a response is initiated. However, the forced-response paradigm allows one to trace out the entire time course of conflict resolution processing, including the time period when goal-directed processing is gradually overriding habitual processing. A "dip" in accuracy for incongruent trials can usually be observed at shorter PTs (200 -500 ms, shown in Figure 1B), reflecting a period during which habitual processing is dominant and overt habitual errors are expressed. In recent years, similar timing-controlled paradigms have been used in conflict tasks in conjunction with eye-movement tracking (Poth, 2021; Salinas et al., 2019; Salinas & Stanford, 2021; Zhang et al., 2025).

We applied a computational model to interpret the potential mechanisms involving the cognitive control processes underlying this time-dependent congruency effect -"Response Preparation Model (RPM)". The model allowed us to quantify variations in the component processes of cognitive control driven by adjustments of control that affect the latency distribution of goal-directed response preparation, the latency distribution of habitual response preparation, and the probability that each of these responses will be expressed given that they are prepared. The Present Study

In the present study, we used a forced-response paradigm to characterize the temporal dynamics of cognitive control underlying the CSE and PCE, and to test whether control adaptations over short and long timescales share a common computational basis. Therefore, across two experiments, separate groups performed forced-response flanker or arrow Simon tasks in which we examined trial-to-trial control adjustments (Experiment 1, with balanced congruency proportions) and block-wise adjustments (Experiment 2, with manipulated congruency proportions). Fitting the RPM to these data allowed us to attribute the CSE and LWPCE to changes in the preparation time and expression probability of habitual versus goal-directed responses. We hypothesized that both effects reflect the same adjustment in the computational model -goal-directed responses prepared faster and more likely to be expressed, habitual responses prepared more slowly and more likely to be inhibited, whether triggered by a preceding incongruent trial or a mostly incongruent block.

Hierarchical Response Preparation Model

Extending the prior work by Hardwick et al. (2019), we adapted the hierarchical Response Preparation Model to explain performance in traditional conflict tasks with binary response options. The model separately quantifies processes related to habits and goals with a few basic assumptions. First, we assume that two response representations are prepared independently and simultaneously which we refer to as h (for Habit) and g (for Goal). Second, response representation latencies are normally distributed. Each of the two responses is prepared with an estimated mean latency, μ, and an estimated standard deviation, σ (Example distribution of response preparation is shown in Figure 3). Third, response preparation is imperfect, and action slips can occur. Lastly, once the goal-directed response is prepared, it will override the habitual response (Adkins & Lee, 2023; Hardwick et al., 2019).

Empirically, habits are always prepared a bit earlier than goals (μ h < μ g in Figure 3A), consistent with the intuition that the automatic association of a stimulus with a response happens earlier than the more deliberate goal-directed processing. To describe the effect of experimental manipulations (e.g., previous trial congruency or proportion congruency), we used posterior distributions of the group-level parameters. For performance prediction, we used the individual-level parameters which can better capture individual differences.

Estimating the Effects of Covariates with the Model.

When another covariate needs to be input into the model, such as the congruency of the previous trial or the proportion of congruency, we assume that the effect of this covariate on each model parameter follows a linear form (Adkins & Lee, 2023). For instance, to quantify the effects of the congruency of the previous trial on response preparation latencies, μ parameters vary linearly with previous trial type covariate, x: μ = Δ 0 + Δ 1 * x. Here, x is contrast-encoded with a value of 0.5 for a trial following a congruent trial, and -0.5 for a trial following an incongruent trial. The intercept Δ 0 represents the average preparation time across both conditions, and the slope Δ 1 represents the difference in μ between two conditions. Δ 1 s were given weakly informative normal priors, with a mean of 0 and standard deviation of 0.5. To better understand the transformation of alternative hypotheses for the Δ parameters -Δμ h , Δμ g , Δβ h , Δβ g into the predicted performance, please see the diagrams and explanations in Figure 3B. These diagrams show that smaller μ g , larger μ h , or reduced β h can be the potential reasons for a smaller magnitude of congruency effects.

We finally transformed the Δ 1 s to the time (ms) or probability (%) scale for result interpretation.

Data Preprocessing

Data exclusion criteria were pre-registered on OSF (https://osf.io/nm2z5/files/osfstorage/64638d2d1a5dd505491f0bb9). Broadly, the criteria served two purposes: first, participants or trials with poor timing accuracy needed to be excluded to ensure that the retained trials for each participant had enough usable data, and second, participants or trials with low response accuracy also needed to be excluded to ensure that participants were not merely guessing across the range of PTs. If a block of trials had either more than 25% of all the trials or more than 10 consecutive trials with no response, that block was excluded for a participant. If a participant received "Respond faster!" or "Respond slower!" for all the trials in a block, that block was excluded for the participant. After excluding data at the block level, we performed data exclusion at the participant level based on the remaining trials. If a participant did not respond to more than 20% of all the trials, the participant was excluded. A participant was also removed if they had fewer than four available blocks.

Otherwise, if a participant had a sufficient number of blocks but the total "on-time" accuracy was lower than 30%, that participant was also removed. Lastly, any participant who had an accuracy rate lower than 70% for all the trials with a PT over 800 ms was removed from the analysis. Only the "on-time" trials were included in analyses and modeling. Ten trials at the beginning of each block were considered warm-up trials and were also excluded. A tiny number of trials with PT over 1000 ms were also excluded.

After applying the exclusion criteria for data preprocessing, the Arrow Simon task in Experiment 1 retained 119 of the 126 participants who completed the task, yielding a total of 42,053 trials, of which 28,745 (68.35%) had on-time responses. Among these on-time trials, 14,244 were congruent and 14,501 were incongruent. The arrow flanker task experiment retained 116 participants from 132 completed submissions, producing 40,898 trials, with 27,392 on-time responses (66.98%). Specifically, 13,837 trials were congruent and 13,855 trials were incongruent. Data Analyses

Code for data pre-processing, visualization, modeling, and statistical analyses was written in Python. For visualizing the accuracy rate over PT for congruent versus incongruent trials, a smoothing window that had a width of 50 ms and a moving step size of 1 ms was applied for each participant. The window moved from 0 ms to 1000 ms, and at each step, we calculated the mean accuracy rate of all trials within each window. We took the average of all participants' accuracy at each step to generate the final curves. To investigate CSE and PCE in the two experiments, we evaluated whether the interaction between the current trial congruency and conditions (previous trial congruency or the congruency proportion) had significant influence on performance. To assess model fit, we computed R² between the predicted and observed accuracy at each PT window, with higher R² values indicating better fit. We segmented the PT into three bins based on empirical data in the Simon and flanker tasks: 0-200 ms, 200-500 ms, 500-1000 ms (Lee et al., 2024). These coarse temporal boundaries were set based on data from previous studies (i.e., Stins et al., 2008), for instance, human beings can accomplish a simple motor response within 200 ms (Johnson et al., 1985; Woods et al., 2015), and the mean RTs for a free-response Simon task or flanker task were usually distributed around 500 ms. A two-way repeated-measure ANOVA was conducted to demonstrate CSE and PCE within specific PT ranges.

For Bayesian modeling, Python packages "Arviz" and "PyMC" were used (Abril-Pla et al., 2023).

For the model sampler, we set 4 MCMC chains with 2000 tuning iterations and 4000 draws (numbers of posterior samples to keep) per chain. The target acceptance rate was set to 0.95 to ensure the efficiency of sampling. The posterior distributions of parameters at the group level and at the subject level were obtained from the model. We randomly selected 2000 sets of parameters from 16000 sample draws to generate posterior predictions (θ) within 0-1000 ms. We used the median of all the samples for (μ h , σ h ) and (μ g , σ g ) to generate the normal distributions of habitual or goal-directed response preparation latencies.

We also report 95% credible intervals (CI) to indicate the range of the posterior distributions of the Δ parameters. If the 95% CI did not contain 0, that would indicate the probability for that Δ to be 0 was low. We also reported the probability of direction (pd), a Bayesian measure of an effect's direction, which quantifies the proportion of the posterior distribution of each Δ parameter falling on the same side of 0 as the median. If pd is over 97.5%, there is very strong evidence that the effect is in a particular direction, either positive or negative (Makowski, Ben-Shachar, Chen, et al., 2019; Makowski, Ben-Shachar, & Lüdecke, 2019). A pd value below 95% suggests insufficient evidence to support the existence of the effect, and a pd value between 95% and 97.5% suggests moderate evidence for the effect.

The PCE after Excluding CSE as a Confounding Variable

The list-wide PCE in two-choice flanker and Simon tasks is confounded by the CSE and thus can be substantially influenced by the accumulation of CSE (Braem et al., 2019; Braver, 2012; Braver et al., 2007; Bugg & Crump, 2012). As the probability of an incongruent trial is increased, for example, the number of trials preceded by an incongruent trial will increase. To determine whether the PCE persists once the CSE is accounted for -that is, whether congruency proportion modulates the congruency effect independently of previous-trial congruency -we isolated the CSE in both the Simon and flanker tasks by treating "previous trial congruency" as the main effect and "congruency proportion" as the nested effect in the model (see Supplementary Figure S1). This allowed us to examine the pure effect of congruency proportion separately within each level of previous-trial congruency.

Discussion

Previous research has unambiguously shown that in conflict tasks, the congruency effect following an incongruent trial is smaller than that following a congruent trial. Similarly, the congruency effect in a mostly incongruent block is smaller than that in a mostly congruent block (Gratton et al., 1992; Lindsay & Jacoby, 1994; Logan, 1980; Logan & Zbrodoff, 1979) These findings suggest that both short-timescale and long-timescale conflict trigger cognitive control adjustments that modulate cognitive processing in a similar way: by accelerating goal-directed processing and inhibiting the habitual response expression.

Both Short-and Long-Timescale Conflict Can Modulate Cognitive Control Processes

Across both experiments, our results show that neither short-nor long-timescale conflict exposure affects habitual processing speed. However, both forms of conflict can inhibit habitual response expression in the Simon task only. This finding implies that automatic processing of the taskirrelevant stimuli (i.e., spatial location) operates with a fixed temporal profile that cannot be easily modulated by adaptive control (Schneider & Chein, 2003; Schneider & Shiffrin, 1977). However, in specific scenarios (i.e., the Simon task), when the goal has not yet been prepared, cognitive control still mediates the balance between habitual and goal-directed processing by withholding the prepotent habitual response tendency.

Our results suggest that short-lived prior conflict and long-timescale conflict experience modulate our controlled and automatic cognitive processes following similar mechanisms. Revisiting the two cognitive control accounts for CSE and PCE mentioned in the introduction-the attention shift and response modulation accounts-our model provided statistical evidence to support aspects of both hypotheses. On the one hand, the accelerated preparation process for the goal with preceding incongruent trials or within mostly incongruent blocks is aligned with shifting attention to enhance target-information processing in the attentional shift account (Botvinick et al., 2001; van den Wildenberg et al., 2012; Weissman et al., 2015). These results indeed reflect the enhancement of cognitive control triggered by preceding or frequent conflicts, as proposed by the conflict monitoring hypothesis.

However, on the other hand, the response modulation account highlights that the distractor-related response is inhibited by a controlled process before the target is identified (Logan, 1985; Logan & Zbrodoff, 1979; Ridderinkhof, 2002), which aligns more closely with the interpretation of β h in our model.

Interestingly, the response modulation account links larger PCE to a temporal advantage of distractor processing (Weissman et al., 2024). In our model, the Simon task showed a larger PCE (accuracy difference across the whole-time window) than the flanker task, alongside a larger temporal gap between habitual and goal-directed response preparation (see supplementary materials). Consistently, we found that the inhibition of expressing the habitual response-modulated by conflict frequency-was observed only in the Simon task, providing support for a response modulation account for PCE.

Unpacking the Confounding Factors in PCE and CSE

The arrow Simon task and the arrow flanker task for CSE and PCE in this study employed traditional two-alternative forced-choice (2-AFC) designs, with four possible stimulus configurations and two response options. In such designs, manipulating congruency proportion necessarily adjusts the frequencies of different trial sequences within a block (Braem et al., 2019; Braver, 2012; Braver et al., 2007; Bugg & Crump, 2012). Therefore, the additional question we examined in depth was whether the model-parameter differences we found between mostly congruent (MC) blocks and mostly incongruent (MI) blocks could only be attributed to the accumulated impact of the CSE. Although our experimental design did not allow us to fully disentangle list-wise PCE from sequential influences, conditional analyses revealed PCE with the strength of evidence differing across previous-trial congruency conditions. We found that goal-directed preparation latency was shorter in MI blocks than in MC blocks on trials following a congruent trial in both tasks, whereas evidence for this difference following an incongruent trial was moderate and limited to the Simon task. Moreover, we found no statistically reliable difference in the probability of expressing a habitual response (β h ) between MC and MI blocks after stratifying trials by previous-trial congruency, suggesting that the long-term high-conflict context exerted little additional influence on the inhibition of habitual response initiation beyond that of short-term conflict experience.

Together, we can conclude from these findings that long-term contextual adaptation cannot be fully reduced to an accumulation of the trial-by-trial adjustments underlying the CSE, but is conditional on the short-term conflict experience. Our conclusion converges with prior evidence that block-level PCE was dissociable from the mechanism underlying CSE: in a confounded color-word Stroop setup, Rothermund Another known limitation of the 2-AFC design is that both CSE and PCE can be partially explained by feature integration rather than adaptive control. With a small stimulus set, congruency-repeating trial pairs (CC, II) can involve full stimulus-response repetitions, whereas congruency-switching pairs (CI, IC) involve only partial repetitions, incurring a binding cost that mimics a CSE (Mayr et al., 2003; Schmidt & Weissman, 2014; Weissman et al., 2014). Similarly, the PCE may partly reflect greater practice with the stimulus-response combinations in the high-proportion condition rather than genuine list-wide control adaptation. The extent to which feature integration contributes to the present findings therefore remains an open question, and future work employing designs that dissociate feature integration from adaptive control will be needed to clarify this (Braem et al., 2019).

Comparison between the Arrow Simon Task and the Arrow Flanker Task

While comparing the modeling results between the arrow Simon task and the arrow flanker task, the main difference is the variation of β h , the probability of expressing the habitual response. Preceding conflict and high-frequency conflict can lead to habitual response suppression in the Simon task, but not in the flanker task.

Why is there a difference in the CSE and PCE between the two tasks? One obvious explanation for the difference between the two tasks is the potential variation in processing speed for different sources of conflict. In the flanker task, targets and distractors constitute distinct visual stimuli that share visual similarity, leading to nearly parallel processing speeds. This structural equivalence necessitates robust selective attention mechanisms to effectively filter distractors. By contrast, the Simon task generates interference through spatial location -a feature subject to privileged neural processing due to inherent left-right hemispheric specialization in the human brain, resulting in faster response times compared to other visual attributes (Vallesi et al., 2005). As a result, the temporal gap between taskirrelevant and task-relevant information is larger in the Simon task (Hübner & Töbel, 2019; Pratte et al., 2010). Mansfield et al. used EEG to validate the hypothesis that interference on response speed in the Simon task is attributable to direct and fast stimulus-response priming, whereas it is incurred via an indirect process later in the flanker task (Mansfield et al., 2013). In our study, we also provided statistical evidence to support that both habitual response preparation and goal-directed response preparation are faster, and the temporal gap between the two latencies is larger in the Simon task (Supplementary Figure S2). Based on one of our model assumptions that once the goal is prepared, the habitual response is suppressed, a shorter temporal distance between the latencies indicates a shorter time for the habitual processing to be dominant. It can be hypothesized that with larger similarity between the target and task-irrelevant information, as well as a smaller temporal gap between goal-directed response preparation and habitual response preparation, cognitive control can do less to adjust the response preparation processes following a short-timescale conflict or coping with frequent conflict. As discussed earlier, the response modulation account also posits a similar idea that the larger CSE or PCE observed in Simon tasks may be attributed to the greater amount of time available for cognitive control to modulate the habitual response (Weissman et al., 2024).

It is worth commenting on the comparison of the results from the forced-response method with those methods relying on delta plots, which visualize interference effects as RT difference varies across different quantiles of the free-RT distribution. An increasing trend of interference effect over RT indicates stronger suppression of interference for an early automatic process relative to the later controlled process. The slope of the delta plot is usually positive for the flanker task but negative for the Simon task (Miller & Schwarz, 2021; Ridderinkhof et al., 2004; Ulrich et al., 2015). Therefore, in the Simon task, the interference between the goal-directed process and the habitual process is highest at the beginning but decreases as RT increases. In the flanker task, interference increases with RT as the slower habitual process engages with task-irrelevant stimuli. These patterns are in line with our findings of longer latencies for both habitual and goal-directed response preparation in the flanker task relative to the Simon task.

Comparison of the HRP Model to Previous Frameworks

Earlier models have provided valuable computational insights into the dynamic nature of cognitive control. Most of these frameworks, including the early dual-process model (De Jong et al., 1994; Hommel, 1998; Ridderinkhof, 1997), the dual-stage two-phase (DSTP) model (Hübner et al., 2010; Hübner & Töbel, 2019), the shrinking spotlight model (White et al., 2011), the diffusion model for conflict tasks (DMC) (Koob et al., 2023; Luo & Proctor, 2022; Ulrich et al., 2015), and the dual-route evidence accumulation (DREAM) model (López & Pomi, 2024) are variants of the diffusion decision model and share the RPM model's core assumption that two competing processes drive the response preparation process, with the controlled process becoming dominant later than the automatic process.

Yet only a few have been extended to model and simulate the CSE or PCE. Below we compare how these models and the response preparation model account for these effects.

Recently, two separate groups extended the DMC to fit the free-RT distributions of the CSE (Koob et al., 2023; Luo & Proctor, 2022), with the drift rate -the efficiency of evidence accumulation -as the key parameter (Ulrich et al., 2015). The assumption was that the total drift rate is the sum of the drift rates for the controlled and automatic processes for congruent trials, but their difference for incongruent trials. Luo and Proctor's model assumed that the controlled process was influenced by feature integration, and the automatic process was influenced by conflict adaptation (Hommel et al., 2004; Luo & Proctor, 2022). However, conflict in the previous trial was only hypothesized to reduce the drift rate of automatic processes (Luo & Proctor, 2022). Later, Koob et al. showed, using DMC, that the automatic process, rather than the controlled process, drives CSE in both Simon and Flanker tasks (Koob et al., 2023). Our model, however, had very different hypotheses for automatic processing, and reached the opposite conclusion for the controlled process. This divergence likely arises because earlier diffusion models inferred habitual processing from free-response RT distributions, which rarely sample the very short PTs at which habitual errors occur, whereas the forced-response paradigm used here observes this time window directly.

Alterations in the automatic process due to high conflict conditions have also been demonstrated by some previous models. With Hübner's DSTP model, during an 80% conflict condition, there was stronger stimulus selection and stronger response selection after identification of the target, but the probability of selecting a response in phase 1 (RS1, dominated by automatic process) was highly reduced in the letter flanker task (Hübner et al., 2010). This conclusion was reiterated and validated later using the shrinking spotlight model, which illustrated a reducing attention distribution width as the proportion of conflict increased (White et al., 2011). However, here we did not find clear evidence that demonstrates that the cognitive process toward the flankers was reduced under a high conflict situation.

Hübner and Töbel also compared DMC and DSTP models on the Simon task with congruency proportion manipulations (Hübner & Töbel, 2019). The DSTP model suggested that the rate of stimulus processing for spatial location had less influence on early response selection if incongruent trials were in a larger proportion, while the DMC modeled that the rate for automatic activation decays faster in high conflict conditions compared to low conflict conditions. At a broad level, our finding with RPM regarding the habitual process in the arrow Simon task in Experiment 2 aligns with the general conclusions of DSTP and DMC models. However, given the differences in architectural assumptions between RPM and these diffusion-based models, a direct parameter-level comparison is not meaningful -for instance, RPM does not have a direct counterpart to the late suppression of automatic activation that DSTP posits.

A key advantage of our RPM over previous diffusion-based models is that it explicitly accounts for the speed-accuracy tradeoff function. While diffusion-based models for conflict tasks are often evaluated through delta plots, delta plots are sensitive to extreme RT values and outliers, which can distort interpretations of the underlying cognitive processes (Ulrich et al., 2015). By using the forcedresponse paradigm to distribute PT evenly across the full range of preparation times, the RPM characterizes how accuracy evolves as a continuous function of preparation time. The model captures the entire speed-accuracy tradeoff rather than only the tail of the tradeoff that relies on only a handful of RT quantiles, and this is the time window during which habitual errors can be revealed. The main cost of this approach is that it requires a relatively large number of trials per participant and stricter data inclusion criteria, since only on-time trials enter the analysis.

Conclusions

In this study, we demonstrated that applying a novel forced-response method to conflict tasks can produce behavioral patterns -namely the congruency sequence effects and the proportion congruent effects -similar to those observed in traditional free-response paradigms. We used a hierarchical response preparation model to dissect the temporal dynamics of cognitive control processes as they adapt to conflict at both short and long timescales. Our findings indicate that cognitive adaptation to short-and long-term conflict experience involves a shared process-level mechanism: goaldirected processing is accelerated both following recent conflict and in contexts characterized by frequent conflict, while habitual responses are less likely to be expressed under certain task conditions.
