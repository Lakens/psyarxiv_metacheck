Meta-scientific research has shown nonsignificant p values are commonly misinterpreted. It is incorrect to infer that there is ‘no effect’, ‘no difference’, or that groups are ‘the same’ after p > 0.05.

It is possible that there is a true non-zero effect, but that the study did not detect it. Make sure your inference acknowledges that it is possible that there is a non-zero effect. It is correct to include the effect is ‘not significantly’ different, although this just restates that p > 0.05.

This module uses regular expressions to identify sentences that contain a statistical power analysis. The Power Analysis Check module uses regular expressions to identify sentences that contain a statistical power analysis. How StatCheck works

Check consistency of p-values and test statistics

The Statcheck module runs Statcheck. Statcheck searches for regular expressions that match a predefined pattern, and identifies APA reported statistical tests. More information on the package can be found at https://github.com/cran/statcheck. The module only returns Statcheck results for t-tests and F-tests, as these are the only tests which have been validated, see https://osf.io/preprints/psyarxiv/tcxaj_v1/.

Statcheck was developed by Michèle Nuijten and Sascha Epskamp.

Statcheck considers p = 0.000 an error, as you should report p < 0.001. Furthermore, p < 0.03 is an error if the p-value was 0.031, and one should simply report exact p-values (p = 0.031). When the sentence of a test says it is one-sided (“one-tailed”, “one-sided” or “directional”), a p-value that fits a one-sided test counts as consistent (statcheck’s OneTailedTxt setting; #695). When the paper says anywhere that its tests are one-sided, a p-value that fits a one-sided test in either direction counts as consistent too: half the two-sided p, or 1 minus that half for an effect against the predicted direction. Equivalence tests (TOST) are left out, as their p-values do not test the difference. A statistic written with “<” or “>” is read as a bound, and in a sentence about equal variances an F-test’s two-sided p (twice the one-tailed p) counts as consistent. How Exact P-Values works

List any p-values reported with insufficient precision (e.g., p < .05 or p = n.s.), reported as exactly zero (e.g., p = .000), or impossible (below 0 or above 1, e.g., p = -.22).

This module uses regular expressions to identify p-values. It will flag any values reported as p > ? or p < numbers greater than .001. It will also flag p-values reported as exactly zero (e.g., p = .000, p = 0.00), which are mathematically impossible — p-values are never exactly zero and should instead be reported as p < .001.

A p-value that is not the result of a test is not flagged: a table note (“* p < .05, ** p < .01”), a figure legend (“Asterisks indicate significant differences (p < .05)”, “Values in bold are significant at p < .05”) or a stated threshold (“p < .05 was considered significant”, “thresholded at p < .001”). GROBID often puts such notes into the running text, so each p-value is judged by the words in its own clause (the text up to a “;” or a full stop), and never left out when a test statistic belongs to it (“F(1, 7) = 8.03, # p < .05”). The column not_a_test of the table says why a p-value was left out (“marker”, “threshold”, “legend” or “named”).

A p-value with the name of a correction or a test after the p (“pFWE < .05”, “padj < 0.05”, “p Wilcoxon = .02”) is flagged only when a test statistic comes before it in its clause (“t(37) = 7.17, p FWE < .05”). Without one it is mostly the rule that decided what was significant (“genes with padj < 0.05 were selected”); such a p-value is “named” in not_a_test. Notes in other forms, such as a marker after the p-value (“p < .05 (*)“), are still flagged.

A p-value below 0 or above 1 is impossible; it is listed apart and not also as imprecise. Often the statistic before it, or its minus sign, was copied into it (“t(134) = -2.32, p = -.13”, “Z = 3.091, P = 3.091”). A value above 1 is listed only after a test statistic in its clause: without one, a “P” above 1 was nearly always another quantity (a proportion, pH, a group’s mean, a model parameter). A number in scientific notation whose power of ten was lost when the PDF was read (“p = 2.4 x 10 -9” read as 2.4) is not listed. A “p” that is the subscript of another symbol (“r p = .64”, “²p = .02” for partial eta squared, “Δp = .33”), or a quantity with a unit, a logarithm or a ratio (“P = 2.9 µm”, “-log10 P = 7.5”, “Ca/P = 1.67”), is not read as a p-value at all (see extract_p_values()). Each p-value has its own row, also when the same one is written twice in a sentence.

This module sometimes flags false positives when sentences discuss how p-value thresholds were set. It can also miss an imprecise p-value that is reported against a threshold (“decreased at the p < .05 significance threshold”).

This module only checks p-values reported in the running text of the manuscript. It cannot (yet) process p-values reported only in tables (as opposed to a table’s footnote text, which the module does see and tries to exclude — see above).

How Code Check works

This module retrieves information from repositories checked by repo_check about code files (R, Python, SAS, SPSS, Stata, Mplus, MATLAB).

The Code Check module checks R (also R Markdown and Quarto), Python (also Jupyter notebooks), SAS, SPSS, Stata, Mplus, and MATLAB files, using regular expressions to check the code; JASP files are listed but not read. The language of a Quarto document or a notebook is read from the file itself (its engine or kernel), not from its extension. The regular expression search will detect the number of comments, the lines at which libraries/imports are loaded, attempts to detect absolute paths to files, setwd() and install.packages() calls, and lists files that are loaded, and checks if these files are in the repository; R code is also parsed. The regular expressions can miss information in code files, or falsely detect parts of the code as a fixed file path. Libraries/imports might be loaded in one block, even if there are more than 3 intermittent lines. The module was tried out internally on papers published in Psychological Science, but has not been formally validated. There might be valid reasons why some loaded files can’t be shared, but the module can’t evaluate these reasons, and always gives a warning.

How Data Check works

This module classifies the files in a repository into semantic types (data, codebook, code, software, output, supplemental, readme, asset, other) and, for tabular data files, extracts each column’s type and summary statistics.

The Data Check module consumes the file list produced by repo_check (or any files added via local_path). Each file is classified with rule-based heuristics layered over metacheck’s file_category() and file_types: file names matching README / codebook patterns win first, then an extension crosswalk, then format-locked extension overrides. For every file classified as tabular data that is available locally, the module reads the file head, describes each column with data_col_facets() and computes summary statistics for numeric columns. Every sheet of a spreadsheet that holds a table is read: a file with several such sheets has its columns under source_file = "file.xlsx [sheet]", and the sheet column names the sheet of any spreadsheet with several sheets; a sheet of notes or a codebook is treated as documentation when the file has another table. Following DDI, a column is described by orthogonal facets rather than a single type: representation (numeric/text/datetime/code — how it is stored), measurement_level (Stevens: nominal/ordinal/interval/ratio), concept (what it measures: reaction_time/age/gender/likert/id/…), role (identifier/measure/condition/timestamp), unit, and a quality state (ok/empty/constant). Concepts are detected by name+value rules (the demographic concepts via data_check_demographic()); when llm_use(TRUE) the model fills concepts and measurement levels the rules left blank. Qualtrics survey exports are recognised (data_check_is_qualtrics()): their extra header rows are stripped so columns type correctly, and the reserved response-metadata columns (StartDate, Duration, Finished, …) are tagged.

The module defaults to rules-only when llm_use(FALSE): columns the rules cannot resolve (ambiguous 3–20-unique integers, ambiguous character columns) fall back to continuous / text respectively. When llm_use(TRUE), ambiguous columns and unresolved file types (other) are sent to llm() for optional refinement, and every file is assigned a study group (ex1, pilot2, shared, …) so that multi-study repositories can be recognised (used by psychds_check). Without an LLM the study group is left NA (unknown).

Column extraction requires files to be readable from disk. Files fetched by repo_check from OSF/GitHub/etc. without a local copy (file_location is NA) are classified but not column-extracted; pass local_path to point at a downloaded copy of the repository.

For a paper whose repository is on Dryad, this means column extraction never happens unless a Dryad API key is set: Dryad requires one to download file bytes, even from a fully public dataset (dataset listing and metadata do not need one). Without a key, every Dryad file stays classified but un-downloaded, column_n is 0, and a warning naming Dryad and ?dryad_pat/?dryad_auth is included among the download failures. A one-time session message is also shown (see repo_check) the first time a Dryad dataset is encountered with no key set.

Every downloaded text file the authors wrote (code, settings, survey definitions such as Qualtrics .qsf files, documentation, outputs) is searched for keys: API keys, access tokens and private keys, which let anyone who downloads the file use a paid service at the authors’ cost. Of a tabular data file only the column names and first 3 rows of the table as read are searched: its values come from participants, but a key the authors set for a whole survey (as embedded data in a Qualtrics survey flow) is exported in every response. A key found turns the traffic light red; the report and the keys table give its file, line and type, and only its beginning. Other files over 25 MB and binary files are not searched. A key is never tested with its provider. Every module’s result has any whole key replaced by “keyremoved” (see module_run()).

How Reproducibility Check works

This module assesses whether a paper’s R and Python code can be run on its data. It works in two phases. The static phase (always run) collects the package dependencies the code declares, rewrites the data-file paths that do not work in the repository as the authors organised it, works out the order the scripts must run in, and diagnoses why any referenced input file is unavailable — reporting what a reproduction attempt would involve and where it is likely to break. The execution phase (opt-in, execute = TRUE) then actually runs the code: it copies the repository into a throwaway directory, optionally installs the declared dependencies into a throwaway library, runs each script in order in an isolated subprocess with a per-script timeout, and captures the outcome and full output of each run.

By default (execute = FALSE) the module does not run any code — it performs only static analysis: reading dependencies with the same extractors as code_check, finding the files the code references in the repository, and building a run-order dependency graph. It reports what would be installed and run rather than doing it.

When execute = TRUE, the module additionally runs the downloaded code on your machine — a deliberate, opt-in action gated behind that argument (callr is required for R code). Each script runs in an isolated subprocess so a crash cannot take down the R session; note this isolates crashes, not the filesystem or network. Installs (when install_missing = TRUE) and the throwaway run library never touch your main R library. Each script’s outcome is one of ran_ok, errored, timed_out, dependency_unavailable, not_parsed, run_by_source (an R script another script runs with source(), which is run only inside that script, since on its own it lacks the packages and objects the sourcing script sets up first), run_by_import (a Python file other files import, a module rather than a script, unless it has an if __name__ == "__main__": block), jags_model (a JAGS or BUGS model saved with an R extension, which another script reads) or not_r_content (a file that is not R at all, such as a JSON or HTML dump); these last two are not run and are not failures. python2 marks Python 2 code that was not run. With sandbox = "docker" such code runs with Python 2.7 (option metacheck.docker_image_py2; FALSE turns this off), which modifications records; it is never converted, since that can change results. defines_functions is a file that only defines functions, which is used, not run (table$used_by names the scripts that use it), and not_analysis is a file of software rather than of the analysis: a package’s code, tests, documentation or setup.py, a copy of a tool, a web application, a script a program wrote (table$not_analysis_why says which); neither is run or counted as a script. docker_failed means the container never started, which says nothing about the script, so it keeps the light from being green but does not make it red. needs_a_person is a script that stopped because it asks a person to choose a file or answer a question, or that starts an app, and needs_internet one that stopped because the network is off in a Docker run, or, with internet = TRUE, could not reach what it asked for; download_too_large is a script stopped for downloading more than the limits allow (see internet), and out_of_memory one that, or a program it started (such as a compiler), ran out of the memory each script may use. All four are treated the same way. not_downloaded is a script that stopped on a file the repository lists but that was not downloaded, such as one over max_file_size: it could not be tried, so it is not counted as a script that did not reproduce (summary_table$repro_not_downloaded_n counts them apart). not_read is a file metacheck could not read, so it was not run; the light is then not green, as the file may read and run on another computer, and table$error_message says why, naming a package that is installed but cannot be loaded on the computer that ran the check. empty is a file with nothing in it, which is not run or counted as a script. For a script that did not run through, table$error_message is its error, short (at most 300 characters): the error line of its output, which names a package that is not there, with the address it asked for when it needed the internet, or the time limit it reached; table$reason sorts it into a kind. A timeout means “still running at the cutoff”, not a failure, so raise timeout for legitimately long-running (e.g. Bayesian) scripts. dependency_unavailable means the script’s own package could not be installed from live CRAN, the CRAN Archive, or a named GitHub/URL source — an infrastructure limitation, not a defect in the paper’s code. The full stdout/stderr of every run is kept in the result’s run_results (the report shows it in per-script dropdowns, capped for readability).

Provenance, kept so that a TRACE Research Object (TRO) declaration of the run can be written later from a stored result (metacheck #404; the helpers are in R/provenance.R). Only when code was run (execute = TRUE): * run_results$started_at, run_results$ended_at: when each run of a script started and ended (ISO 8601, UTC, milliseconds); NA for a script that was not started. A script run again in a later pass has the times of its last run. A TRO uses them for each trov:TransparentResearchPerformance. * run_results$exit_status: the exit status of the process that ran the script (0 = ended normally); NA when the process did not report one (a time limit, or Docker failing to start the container). * artifacts: one row per file, with stage (deposit: as downloaded from the repository, hashed from the downloaded file; before_run: the run folder just before the first script ran, after metacheck’s own changes, such as rewritten paths and unpacked archives; after_run: only the files the scripts made (status new), changed (changed) or removed (removed), as an unchanged file is the one listed before the run), path (relative to the run folder, as valid UTF-8, a byte of another encoding written as <xx>), size (bytes), sha256, mime_type (by extension, NA when unknown), source (the file’s address in the repository, for deposit). The package libraries metacheck installs in the run folder are left out, as are metacheck’s own files there (a script’s runner, and the statistical output it writes in statistical_output/). Files metacheck itself copied or made between passes (see modifications, output_copied, file_placed) show in after_run too. A TRO uses the rows as trov:ResearchArtifacts and each stage as a trov:ArtifactArrangement. * modifications$sha256_before, modifications$sha256_after: the hash of the changed script as downloaded and as it ran; NA when the script is not at the same path in both (a script made from an R Markdown file). * environment: the system that ran the code (trov:TransparentResearchSystem in a TRO): metacheck_version, started_at, ended_at, host (R version, platform, operating system), sandbox, network_isolated (TRUE only when every Docker run had --network none; the process sandbox does not stop the network), internet, timeout_per_script, total_timeout, python_local (the Python run outside Docker and its version), and docker: runs (for each kind of run, r_run, r_install, python_run, python_install, the image and the docker run arguments, such as --network none, --read-only, --cap-drop ALL, no-new-privileges, the process limit and the memory and processor limits) and images (for each image, its ID and digests from docker image inspect, its creation time and the R and Python versions its environment declares).

run_results$checked says what the run of each script shows about the code, in five groups, so that a script that does not reproduce is kept apart from one the check could not test: ran (it ran to the end); code_error (it did not reproduce: it stopped with an error of the code or the deposit, could not be read, or needs a file the deposit does not hold); dependency (a package or program was not available: a package that could not be installed or was not loaded, a program outside R and Python, a system library, or R crashing in a package’s compiled code); time (it did not finish within the time limit for one script, or was not started because the time for all scripts had run out); and not_checkable (it could not be checked automatically: it needs a person, the internet, a key or another setting of the authors’ computer, one platform such as Google Colab, Windows or OpenSAFELY, more memory than the run allows, a file that was not downloaded, a screen, or a program that runs it, or it is a file of a package of the code that Python runs only as a module of that package). It is NA for files run inside another script, files that are not an analysis, files not read, and a Docker failure. summary_table counts each group (repro_ran_n, repro_code_error_n, repro_dependency_n, repro_time_n, repro_not_checkable_n), and the report’s first sentence gives them. Dependencies are reported name-only, with the source (CRAN, GitHub, or a base package already shipped with R) — static analysis of the code cannot know which version was used, and running against current package versions is itself informative: a break argues the authors should have pinned versions. Abstract

Cue combination and competition in navigation have been observed among various spatial cues, yet it remains unclear whether the decision to combine cues is driven by the uncertainties of individual cues or by strategy-level competition. To address this, we examined whether compound or single cue learning experience can influence the selection of cue combination or competition. Participants learned target locations in a virtual environment with two landmarks and were assigned to either the compound learning group (who encoded the target with both landmarks) or the single learning group (who learned from one landmark at a time). In the testing phase, participants recalled the target location under single-cue, compound, and landmark-shift (conflict) conditions. In compound tests, both groups showed lower variances than in single-cue tests, indicating optimal cue combination based on single-cue uncertainties. In shift tests, however, despite optimal cue weights, no variance reduction was observed, and the variances were inconsistent with both cue combination and competition models. Using a maximum likelihood estimation approach, we estimated the probability of using the combination strategy and found that learning experience systematically modulated this probability: The majority of the compound learning group showed high probabilities of combination, whereas the single learning group showed large individual differences. AIC model comparisons indicate that our strategy selection model, which incorporates the estimated probability of combination, provided a better fit to the observed data than pure combination or competition models, especially in shift tests.

These results support the strategy-mediated account, suggesting a potential decision-making process in cue combination.

1. Introduction

Navigating one's environment is an essential ability for survival. Successful navigation involves accurate encoding and retrieval of information from multiple sources. For example, a navigator in a forest may use multiple spatial cues (a creek, a tall oak tree, an oddly shaped rock, etc.) to find their way back to the cave they previously used as shelter on a cold night. By combining these cues, the uncertainty related to any single cue can be reduced, and the precision of the navigator's estimate about the target location can be improved (Newman et al., 2023).

Research studies have demonstrated that navigators will make use of multiple spatial cues (for reviews, see Cheng et al., 2007; Newman et al., 2023) including multiple landmarks (Du et al., 2017; Newman & McNamara, 2022), boundaries and landmarks (Doeller & Burgess, 2008), and path integration and landmarks (Chen & McNamara, 2017; Nardini et al., 2008; Sjolund et al., 2018; L. Zhang et al., 2020; Zhao & Warren, 2015). However, whether these cues are combined to create a unitary spatial representation of a target's location or maintained as independent relationships between the target and each of the available spatial cues remains unclear. Furthermore, if independent cue-target representations are maintained, the question of whether a navigator makes behavioral decisions based on a single cue or combines across cues during retrieval is also poorly understood.

Whether spatial relationships are encoded within a unitary representation or combined during retrieval, cue combination could be expected to reduce uncertainty, as the use of multiple cues could lead to a more precise representation of the target location than that provided by even the best individual cue (Cheng et al., 2007; Newman et al., 2023). A common paradigm for examining cue combination is to test participants' memories regarding a target location with both individual cues and compound cue conditions. Evidence of cue combination in such paradigms is the response variability (often the variance) in the compound cue condition is reduced comparing to the individual cue conditions. A combined estimate of the target's location would be considered optimal when cues are combined according to their relative reliabilities (e.g., more reliable cues should show lower uncertainties and be given greater weighting), such that variance is reduced to a minimum (Cheng et al., 2007; Newman et al., 2023). Indeed, cue weightings have been shown to be related to the relative uncertainty of competing sensory inputs (Cheng et al., 2007; Newman et al., 2023). If the relationships between individual spatial cues and target locations are encoded with reasonable accuracy, and information from cues is weighted according to reliability, cue combination could be expected to result in improved navigation.

However, assuming multiple independent cue-target representations are maintained, it is also possible that a navigator might use a single cue-target representation during navigation. In that case, one cue might be selected as the reference for a given trial, and the target location would be identified based on its spatial relationship to that cue. Additionally, over the course of many trials, there may be competition among cues, with the outcome of a specific trial reflecting the precision of one of several possible cue-target representations. Cue competition would thus be expected to result in more uncertainty and less precision in target estimation than one might expect based on the best individual cue (Du et al., 2017; Nardini et al., 2008). Previous research often employs cue conflict tests to examine cue competition (Newman et al., 2023). In these tests, researchers present compound cues to participants and make some form of modifications to these cues such that they are different from when they are encoded and inconsistent with each other (e.g., intentionally increasing the distance between landmarks). Under such conditions, response bias towards the most reliable cue is likely to be observed (although responses towards other cues may also occur) and response variability will be increased comparing to the individual cue conditions.

Although the ideas of cue combination and competition have been extensively discussed (e.g., Newman et al., 2023), it remains unclear whether an individual navigator can employ both strategies, and under what circumstances one might be selected over the other. As described above, compared to using individual cue-target representations, combining across spatial cues should reduce uncertainty and improve target localization; however, in some circumstances cue combination may not be feasible. For example, young children appear more likely to use a strategy based on cue competition than combination, showing greater response variability when multiple cues are available than when provided with only a single cue (Nardini et al., 2008). This suggests that effective cue combination may require a good deal of experience or rely on cognitive abilities with a protracted developmental timeline. Moreover, when too many spatial cues are present, adult navigators fail to show evidence of effective cue combination (Scherer et al., 2024), perhaps because computing a unitary representation of the target location becomes too cognitively demanding. Finally, when the individual cue-target relationships are discordant (i.e., when the target location estimates based on individual spatial cues are non-overlapping), it may be impossible to combine across cues. Indeed, when facing large conflicts between cues, the effects of cue combination appear weakened or faded (Du et al., 2017; Harootonian et al., 2022; Sjolund et al., 2018; Zhao & Warren, 2015).

Whether a combination or competition strategy is used for navigation is at least partially determined by the amount of information available to the navigator. For example, when sensory inputs become too complex (e.g., too many landmarks in the environment), adults are less likely to combine across cues than in simpler environments (Scherer et al., 2024). In addition, both the generation of a combined, weighted representation based on cue reliability and the selection of the most reliable representation among individual competing cues suggest that prior belief and experience may also play a significant role in strategy selection. A navigator's experience with similar tasks or belief that one spatial cue may be more useful than another is likely to contribute to the baseline weightings of cue reliability that may be used to optimize combination, or affect the likelihood of selecting an individual cue in the case of competition. Indeed, computational modeling work shows that prior experience is involved in cue combination and influences the cue weighting (McNamara & Chen, 2022; Vishwanath et al., 2026). Thus, strategy selection may depend on the nature of the cues (e.g., cue complexity, cue types, the degree of cue conflict, etc.; bottom-up) and a navigator's experience with those types of cues (top-down).

Depending on the nature of a navigational task, the reliability of the spatial cues involved, and an individual's experience and beliefs, combination and competition strategies may produce different estimates of a target's location. Thus, the strategy adopted by a navigator can have a significant impact on their performance. Strategy selection does not appear to be a conscious decision on the part of the navigator; computational work has reinforced that cue combination emerges from dynamic interactions between cues rather than from an explicit strategy selection process (Kessler et al., 2024). However, it remains unclear whether a single strategy is adopted for a given task, or whether the target representations produced by both strategies are both available to the navigator on any given trial and are, thus, also in competition. The current study proposes the latter, suggesting that navigators choose between combination-and competitionbased strategies based on their experience (both long-term and recent) and the similarity between the current trial and the way they have been trained to perform a specific navigational task.

Based on previous work (Du et al., 2017; Newman et al., 2022), the current study focused on navigating to a target based on its proximity to multiple visual landmarks. Specifically, we presented participants with a desktop virtual reality navigation-and-localization task with two visual landmarks. Participants first learned a target object's location via virtual navigation in the presence of one or both of these landmarks and were later asked to recall the target's location (Figure 1). To examine the potential effect of recent experience on subsequent recall, participants either experienced compound cues (i.e., the presence of two landmarks presented at the same time) or isolated cues (i.e., the same landmarks presented one at a time) during learning trials. If strategy selection is determined solely by exposure to the cues in the environment, the two groups would be expected to show similar probabilities of selecting a cue combination/competition strategy, since the visual information provided in training was equivalent across learning conditions. However, if recent experience of encoding compound or isolated cues also affects strategy selection, the compound learning group would be expected to show an increased probability of selecting the combination strategy compared to the group who learned the cue-target representations independently (e.g., Newman et al., 2023). Performance was measured on test trials in which the spatial cues were presented in isolation, and in which the cues were presented simultaneously in the positions they occupied during learning ("compound condition") and shifted away from those positions ("shift condition"). Response variability in the compound and the shift condition trials was compared to single cue trials to determine when navigators showed evidence of cue combination/competition. Finally, performance on trials showing evidence of cue combination was compared to optimal predicted responses to assess how appropriately navigators were able to weight the available spatial cues when responding (Chen et al., 2017; Du et al., 2017; Sjolund et al., 2018; Newman et al., 2022). These specific learning and test conditions will allow us to determine if there is strategy-level competition in navigational decision making and how recent learning experience may influence this competition.

2.3. Materials and design

Participants performed a virtual navigation task to learn and then retrieve from memory a target object's position in a virtual environment (Figure 1). In the learning phase of the task, participants learned an object's position relative to two landmarks by navigating towards it. On test trials, the target was removed from the virtual environment, and the participants were asked to recall and navigate to the location where the target had been previously located using one or both landmarks as reference cue(s) (depending on the type of test trial). The task consisted of 24 blocks, where each block included a learning phase with one or two trials and four test trials. The key difference between the two groups was the learning phase: the CLM group always learned the target's position in a single trial with both landmarks presented simultaneously (i.e., compound cue learning), while the SLM group learned the target's position over two trials with each landmark presented in isolation on each trial (i.e., single cue learning). For the SLM group, which landmark was learned first was counterbalanced across blocks.

The environment was grassland without any boundaries. A tower and a windmill were used as landmarks and were set 40 virtual meters (vm) apart at the beginning of each block (Figure 1).

Their sizes and perceptual salience were comparable in the virtual environment. In the learning phase, an orange traffic cone (the target) was presented between the landmarks, on an imaginary line connecting them. Therefore, the target's position relative to the landmarks was based on a single spatial dimension (which we refer to as the "x axis"). During each learning trial, the target was placed between 2 and 15 vm away from the midpoint of the x-axis in either direction, with a minimum distance of 0.4 vm between target locations across experimental blocks. Which landmark the target was closer to (i.e., which side of the x-axis midpoint the target was on) was counterbalanced across blocks.

In the testing phase, the target was not shown. The first three test trials of each block consisted of two trials in which each landmark was presented in isolation ("nearLM test", "farLM test") and a third trial in which both landmarks were presented ("compound cue test"), presented in random order. The fourth test trial presented both landmarks, but each was shifted away from the midline of the x-axis by 10 vm such that they were a total of 60 vm apart ("shift test"). In total, there were 96 test trials in total (24 blocks × 4 test types) that were identical across groups.

2.4. Procedure

Participants were tested individually 2 . After signing the consent form, participants performed two practice blocks to familiarize themselves with the virtual navigation task. These two blocks were identical to the experimental blocks described above. A demonstration of the task can be found at https://osf.io/nzf2m/files/eymz9.

Each block started by informing the participant that they would learn a new target position.

After pressing a button on the controller, the environment, landmark(s), and target were shown on the screen. Participants were instructed to remember the target position and were informed that they could take as much time as they needed. After the instructions disappeared, they used the controller to freely move towards the target until they ran into it. When the target was hit, the screen was frozen (i.e., no further movement was allowed) and a message was displayed that read "Found the target! Wait for the next trial being loaded." The message and the environment disappeared after two seconds. For the SLM group, a second learning trial that presented the other landmark and the same absolute target position was completed. After completing the learning trial(s), the testing phase began. Participants were informed that the test trials could present one or both landmarks, but they were not informed that the landmarks could be shifted.

On each test trial, with one or both landmarks shown, participants were first asked to imagine where the target was for 2 seconds during which navigation was not allowed. Then, participants were instructed to go to the original target's position and press a button on the controller to record their response. There was no time limit for their navigation and response. Participants were instructed to be as accurate as possible, and they were allowed to make only one response in each trial. No feedback was given for their response accuracy.

At the beginning of each trial, participants were repositioned such that they were facing the midpoint of the x-axis between the two landmark positions. On learning trials, they were positioned 25-35 vm away from the the x axis, while on test trials they were 35-45 vm away. The initial distance from the x-axis (i.e., the starting z-axis position) was randomly chosen for each trial and ensured that both landmarks could be seen from the initial view. Participants were instructed not to use the starting distance as a cue to remember the target's position, as it would not be reliable.

To quantify the fitness of the models, we compared the Akaike Information Criterion (AIC; Equation ( 12)) computed for each of the three candidate models. To determine the best-fitting model, we calculated the difference between each model's AIC and the minimum AIC obtained for each participant (ΔAIC). Models with ΔAIC ≤ 2 were considered as plausible as the model with the minimum AIC, whereas models with ΔAIC > 2 were considered lower supported than the model with the minimum AIC (Burnham & Anderson, 2002). Participants were grouped into one of the seven categories based on the outcome of this comparison: combination model clearly best, competition model clearly best, strategy selection model clearly best, combination and competition models both plausible (strategy selection model ruled out), combination and strategy selection models both plausible (competition model ruled out), competition and strategy selection models both plausible (combination model ruled out), and not clear (all three models plausible; ΔAIC ≤ 2 for all).

The total number of participants for whom each model provided the best fit, and the Akaike weights for those models (Equation ( 15)) are shown in Figure 5A-H (also see Figure S5).

For the compound learning group, performance in the compound test was rarely best fit by a single model; 24 participants (66.67%) showed plausible fits to both the combination and strategy selection models. The Akaike weights indicate that the combination model showed the highest relative support (median Akaike weight = 0.65). In the shift test, the strategy selection model was the best fitting model for 18 participants (50%), and showed the highest relative support (median Akaike weight = 0.72). For the single learning group, there was no good model fit for compound test data for most participants, with the proportion of participants best fit by a given model and the Akaike weights showing similar performance across models. In the shift test, the strategy selection model was the best fitting model for 30 participants (78.95%) and showed the highest relative support (median Akaike weight = 0.99). The performance of the strategy selection model relative to the combination and competition models is shown in Figure 5I-L, where positive values indicate a better fit to strategy selection. For both groups, the strategy selection model provided a better fit the performance in the shift test across a majority of participants. For the compound learning group, the combination model and the strategy selection models provided the optimal fits across individuals in the compound test. For the single learning group, no particular model outperformed the others.

5. Discussion

Spatial navigation is an essential cognitive task that requires the accurate encoding of multiple sources of information from the environment and their interactions, which may involve different strategies across individuals and environments. The current study asks whether there is competition between these different strategies when a navigator is presented with multiple spatial cues, each of which has a unique relationship to the target location. Using a virtual navigation and localization task, we observed responses consistent with cue combination when two landmark cues were simultaneously presented at the same positions they occupied on target location learning trials, regardless of whether cue-target representations were learned simultaneously or sequentially. However, when the landmarks were shifted away from their previously learned positions, a conflict was created between cue-target representations and cue combination was no longer observed. Additionally, we found that prior learning experience (with compound cues and single cues) affected the likelihood that a given navigator would employ a cue combination strategy. Among the different strategies (cue combination, cue competition, or strategy selection) that were compared to determine which provided the best fit to the behavioural response data, strategy-selection was the best performing model, especially in the shift test (Table 2).

Both compound and single landmark learning groups showed reduced variance in the compound test relative to the single-landmark tests, which was consistent with the optimal values predicted by the combination model (Figure 3). This deviated from the findings of Du et al. (2017), where navigators who learned cue-target representations individually did not show evidence of cue combination in subsequent compound test trials. These inconsistent results may be due to differences in task and study design. First, while Du et al. (2017) used a small-scale, non-navigable space on a computer screen, the current task was implemented in a 3D virtual, navigable environment, much more analogous to real world navigation. Second, participants in the current study learned the target's position only once for each landmark and no feedback was provided during test trials, whereas in Du et al. (2017), participants completed dozens of training trials for the same cue-target representations and received feedback during some single cue test trials. Therefore, individual cue-target representations in Du et al. (2017) were enhanced through extensive encoding and resulted in small variances in single cue tests compared to compound test trials which were presented only a handful of times. These differences in familiarly across trial types were better controlled in the current study.

Although the empirical weighting ascribed to the near landmark in the shift test was consistent with the optimal weight predicted by the combination model (Figure 4), the observed variability in localization responses was not consistent with what was predicted by the combination model or the competition model for either group of learners (Figure 3). This is consistent with previous findings that when faced with conflict, humans are less likely to combine cues (Du et al., 2017; Harootonian et al., 2022; Sjolund et al., 2018; Zhao & Warren, 2015). Instead, the variability observed in the shift test was best described by the strategyselection model. Large conflicts between cues may cause competition between multiple candidate representations (Harootonian et al., 2022). According to the recently proposed Bayesian casual inference model (Chen, Chen, et al., 2025), awareness of large cue conflicts indicates uncommon sources of cues and thus the lower cue weighting assigned to the more unstable, noisier cue and increased sensory noises on that cue. It should be noted that we did not directly test whether participants were aware of cue conflicts in the shift test. Even if they were aware of the cue conflicts, it seems they did not reconcile the conflicts and follow the cue combination strategy. It is worth noting that no individual participant's pattern of results was best fit by a pure cue combination or cue competition model, even when the spatial cues were identical across learning and testing trials (i.e., compound test trials for compound learners;

Figure 5A-D and Figure S5).

It is worth noting that, while the way in which cue-target representations were learned in the current study (i.e., compound vs. single cue learning) had an effect on subsequent test trial performance, participants also have a great deal of experience with real life spatial navigation, where combining representations from multiple landmarks would be expected to improve performance relative to alternating between single landmarks. This longer-term learning might be expected to result in a natural preference for cue combination over competition that may have also affected their patterns of behavior in the current study. For example, if the current task is considered novel relative to their typical navigation experiences, individuals may default to a familiar strategy (cue combination). Thus, the effect of cue learning in the current experiment was likely either congruent (compound learning group) or incongruent (single learning group) with an individual's longer-term experience; this may have produced group level differences in the extent to which cue combination vs competition-based strategies were employed during test trials.

These group level differences would be expected to be most apparent during shift test trials, where conflicting cue-target representations may have required participants to re-evaluate their strategy rather than simply relying upon the one they used on compound trials. Indeed, the degree to which navigators appeared to use cue combination in the compound vs. shift tests was not correlated across participants, as the best model fit across tests was not consistent for all participants (Figure S5). These results are in line with the idea that conflicts judged to arise from different causes (e.g., the judgment that a particular cue-target representation is unstable due to the shifting of a landmark) evoke a top-down approach to weighting the reliability of competing representations (Chen, Chen, et al., 2025). It is possible that the selection between combination and competition-based strategies was reset on each trial, suggesting cognitive flexibility in navigation.

We observed broad individual differences in the likelihood of adopting a cue combination strategy. While most participants in the compound learning group overwhelmingly favored cue combination, a few participants showed surprisingly low probabilities of employing this strategy.

Similar evidence of individual differences in rotation and straight-line translation navigation tasks has been observed previously (Harootonian et al., 2022; Vishwanath et al., 2026). This suggests that in addition to the effects of learning, strategy choice may also depend upon an individual's cognitive style, uncertainty tolerance, or preference for fixed vs. heuristic strategies.

Future research is needed to further examine how these aspects might influence strategy choice.

Our strategy selection model proposes that when faced with a navigational task, there is competition between multiple strategies. The plausibility of this model is supported by the observation that humans can process multiple spatial representations in parallel (Chen, Wei, et al., 2025; Harootonian et al., 2022; Ishikawa & Montello, 2006; H. Zhang et al., 2014). However, our results suggest that despite parallel processing, not all representations may be equally accessible or active at any given moment; rather, the extent to which a given representation is accessed appears to vary as a function of experience (both long-term and task-specific) and the accordance between cue-target representations. Maintaining multiple representations at the same time allows different cues to be evaluated and used, making it adaptive in an environment with changing conditions.
