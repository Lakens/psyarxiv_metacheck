What we found

Show details

Meta-scientific research has shown nonsignificant p values are commonly misinterpreted. It is incorrect to infer that there is ‘no effect’, ‘no difference’, or that groups are ‘the same’ after p > 0.05.

It is possible that there is a true non-zero effect, but that the study did not detect it. Make sure your inference acknowledges that it is possible that there is a non-zero effect. It is correct to include the effect is ‘not significantly’ different, although this just restates that p > 0.05.

We left out 1 file that software creates by itself, not the authors: editor settings (1). They hold nothing a reader can use, but they clutter the repository, and software can mistake them for real files (for example a ._ copy of a .csv for data).

Remove these: Operating system files: macOS adds a __MACOSX folder and a ._ copy of every file it puts in a zip, and .DS_Store files to folders; Windows adds Thumbs.db and desktop.ini. On a Mac, create zips from the command line with zip -r -X, or remove them afterwards with zip -d archive.zip "__MACOSX/*" "*.DS_Store". RStudio session files (.Rproj.user/) hold open tabs and unsaved edits; R history (.Rhistory) lists the commands typed in a session and can hold file paths and passwords; Jupyter checkpoints (.ipynb_checkpoints/) are automatic copies of notebooks; compiled Python files (__pycache__/, .pyc) are recreated when the code runs; open-document lock files (~$...docx, .~lock...#) are left while a document is open; editor backups (file~, .bak, .swp) and temporary files (.tmp, .temp) are copies a program made by itself.

Keep only on purpose: version control folders (.git, .svn, .hg) hold the project’s history, which can include earlier versions of files and data that was later removed; editor settings (.idea, .vscode) can hold paths on your own computer. A .gitignore based on GitHub’s templates (https://github.com/github/gitignore) keeps them out of a repository.

Declaration of Helsinki - Declaration of Helsinki / Helsinki Declaration

How Exact P-Values works

List any p-values reported with insufficient precision (e.g., p < .05 or p = n.s.) or reported as exactly zero (e.g., p = .000).

This module uses regular expressions to identify p-values. It will flag any values reported as p > ? or p < numbers greater than .001. It will also flag p-values reported as exactly zero (e.g., p = .000, p = 0.00), which are mathematically impossible — p-values are never exactly zero and should instead be reported as p < .001.

A p-value that is not the result of a test is not flagged: a table note (“* p < .05, ** p < .01”), a figure legend (“Asterisks indicate significant differences (p < .05)”, “Values in bold are significant at p < .05”) or a stated threshold (“p < .05 was considered significant”, “thresholded at p < .001”). GROBID often puts such notes into the running text, so each p-value is judged by the words in its own clause (the text up to a “;” or a full stop), and never left out when a test statistic belongs to it (“F(1, 7) = 8.03, # p < .05”). The column not_a_test of the table says why a p-value was left out (“marker”, “threshold”, “legend” or “named”).

A p-value with the name of a correction or a test after the p (“pFWE < .05”, “padj < 0.05”, “p Wilcoxon = .02”) is flagged only when a test statistic comes before it in its clause (“t(37) = 7.17, p FWE < .05”). Without one it is mostly the rule that decided what was significant (“genes with padj < 0.05 were selected”); such a p-value is “named” in not_a_test. Notes in other forms, such as a marker after the p-value (“p < .05 (*)“), are still flagged.

This module sometimes flags false positives when sentences discuss how p-value thresholds were set. It can also miss an imprecise p-value that is reported against a threshold (“decreased at the p < .05 significance threshold”).

This module only checks p-values reported in the running text of the manuscript. It cannot (yet) process p-values reported only in tables (as opposed to a table’s footnote text, which the module does see and tries to exclude — see above).

How Repository Check works

This module retrieves information from repositories.

The Repository Check module lists files on the OSF, GitHub, ResearchBox, DSpace (PsychArchives and other legacy- and DSpace 7-based installations), Zenodo, Dataverse, Figshare, Dryad, ReShare, 4TU.ResearchData, Mendeley Data, DataONE (Arctic Data Center, KNB, and other member nodes), and LDbase based on links in the manuscript.

Whose deposit is each link? Telling this paper’s own deposit from the authors’ earlier one is less certain.

How Code Check works

This module retrieves information from repositories checked by repo_check about code files (R, Python, SAS, SPSS, Stata, Mplus, MATLAB).

The Code Check module checks R (also R Markdown and Quarto), Python (also Jupyter notebooks), SAS, SPSS, Stata, Mplus, and MATLAB files, using regular expressions to check the code; JASP files are listed but not read. The language of a Quarto document or a notebook is read from the file itself (its engine or kernel), not from its extension. The regular expression search will detect the number of comments, the lines at which libraries/imports are loaded, attempts to detect absolute paths to files, setwd() and install.packages() calls, and lists files that are loaded, and checks if these files are in the repository; R code is also parsed. The module will return suggestions to improve the code if there are no comments, if libraries/imports are loaded in lines further than 4 lines apart, if files that are loaded are not in the repository, if absolute file paths, setwd() or install.packages() are found, and if R code cannot be parsed.

The regular expressions can miss information in code files, or falsely detect parts of the code as a fixed file path. Libraries/imports might be loaded in one block, even if there are more than 3 intermittent lines. The module was tried out internally on papers published in Psychological Science, but has not been formally validated. There might be valid reasons why some loaded files can’t be shared, but the module can’t evaluate these reasons, and always gives a warning.

The module also checks whether the repository pins the R/package versions the analysis actually depended on: an renv.lock file (parsed for the R version and every locked package + its version/source), a sessionInfo()/sessioninfo::session_info() text dump (matched by filename — sessionInfo.txt/session_info.txt and similar, or embedded in a README), or a groundhog::groundhog.library()/checkpoint::checkpoint() date-pin call in the code (a bare library(groundhog)/library(checkpoint) does not count — the pinning call itself must be present). When none of these is found, the report flags it as a reproducibility gap: package versions may drift between when the analysis was run and any later reproduction attempt.

If you want to extend the package to perform additional checks on code files, or make the checks work on other types of code files, reach out to the Metacheck development team.

Checking code requires downloading its file contents. For a paper whose repository is on Dryad, this never succeeds unless a Dryad API key is set: Dryad requires one to download file bytes, even from a fully public dataset (listing the repository’s files does not need one). Without a key, every Dryad-hosted code file is listed but unchecked, and a warning naming Dryad and ?dryad_pat/?dryad_auth is included among the download failures recorded in the manifest.

The Data Check module consumes the file list produced by repo_check (or any files added via local_path). How Reproducibility Check works

This module assesses whether a paper’s R and Python code can be run on its data. It works in two phases. The static phase (always run) collects the package dependencies the code declares, rewrites the data-file paths that do not work in the repository as the authors organised it, works out the order the scripts must run in, and diagnoses why any referenced input file is unavailable — reporting what a reproduction attempt would involve and where it is likely to break. The execution phase (opt-in, execute = TRUE) then actually runs the code: it copies the repository into a throwaway directory, optionally installs the declared dependencies into a throwaway library, runs each script in order in an isolated subprocess with a per-script timeout, and captures the outcome and full output of each run.

By default (execute = FALSE) the module does not run any code — it performs only static analysis: reading dependencies with the same extractors as code_check, finding the files the code references in the repository, and building a run-order dependency graph. It reports what would be installed and run rather than doing it.

When execute = TRUE, the module additionally runs the downloaded code on your machine — a deliberate, opt-in action gated behind that argument (callr is required for R code). Each script runs in an isolated subprocess so a crash cannot take down the R session; note this isolates crashes, not the filesystem or network. Installs (when install_missing = TRUE) and the throwaway run library never touch your main R library. Each script’s outcome is one of ran_ok, errored, timed_out, dependency_unavailable, not_parsed, run_by_source (an R script another script runs with source(), which is run only inside that script, since on its own it lacks the packages and objects the sourcing script sets up first), run_by_import (a Python file other files import, a module rather than a script, unless it has an if __name__ == "__main__": block), jags_model (a JAGS or BUGS model saved with an R extension, which another script reads) or not_r_content (a file that is not R at all, such as a JSON or HTML dump); these last two are not run and are not failures. python2 marks Python 2 code that was not run. With sandbox = "docker" such code runs with Python 2.7 (option metacheck.docker_image_py2; FALSE turns this off), which modifications records; it is never converted, since that can change results. defines_functions is a file that only defines functions, which is used, not run (table$used_by names the scripts that use it), and not_analysis is a file of software rather than of the analysis: a package’s code, tests, documentation or setup.py, a copy of a tool, a web application, a script a program wrote (table$not_analysis_why says which); neither is run or counted as a script. docker_failed means the container never started, which says nothing about the script, so it keeps the light from being green but does not make it red. needs_a_person is a script that stopped because it asks a person to choose a file or answer a question, or that starts an app, and needs_internet one that stopped because the network is off in a Docker run, or, with internet = TRUE, could not reach what it asked for; download_too_large is a script stopped for downloading more than the limits allow (see internet), and out_of_memory one that, or a program it started (such as a compiler), ran out of the memory each script may use. All four are treated the same way. not_downloaded is a script that stopped on a file the repository lists but that was not downloaded, such as one over max_file_size: it could not be tried, so it is not counted as a script that did not reproduce (summary_table$repro_not_downloaded_n counts them apart). not_read is a file metacheck could not read, so it was not run; the light is then not green, as the file may read and run on another computer, and table$error_message says why, naming a package that is installed but cannot be loaded on the computer that ran the check. empty is a file with nothing in it, which is not run or counted as a script. For a script that did not run through, table$error_message is its error, short (at most 300 characters): the error line of its output, which names a package that is not there, with the address it asked for when it needed the internet, or the time limit it reached; table$reason sorts it into a kind. A timeout means “still running at the cutoff”, not a failure, so raise timeout for legitimately long-running (e.g. Bayesian) scripts. dependency_unavailable means the script’s own package could not be installed from live CRAN, the CRAN Archive, or a named GitHub/URL source — an infrastructure limitation, not a defect in the paper’s code, so unlike errored/timed_out it does not force the traffic light red. The full stdout/stderr of every run is kept in the result’s run_results (the report shows it in per-script dropdowns, capped for readability). The traffic light reflects the STATIC readiness signals by default, but an execution error (errored/timed_out) does recolour it to red — a script that crashes on its own analysis is a genuine reproduction failure. A script that fails with could not find function is run once more with the library() calls the project’s other scripts make added at its top (or the one package that exports the function, or magrittr for %>%), and a script that then runs is reported as reproducible only after that repair.

Dependencies are reported name-only, with the source (CRAN, GitHub, or a base package already shipped with R) — static analysis of the code cannot know which version was used, and running against current package versions is itself informative: a break argues the authors should have pinned versions. When the repository does record versions, a run with recorded_versions = TRUE installs the packages the scripts load at those versions, but it does not change the R version, which remains a limitation of the check.

Run order is derived from read-after-write data dependencies (a script writing a file another reads must run first), source() edges, and numeric filename prefixes as a weak tie-breaker. Ambiguous orderings, dependency cycles, and inputs a script reads but that no earlier script produces (and that are not in the repository) are surfaced as warnings, since these are the situations most likely to make an otherwise-correct reproduction fail.

Python code (.py files, and notebooks and Quarto documents whose code is Python, from which the code is extracted first) goes through the same two phases, reported in its own “Python code” section. Each file is checked for syntax errors with Python’s own parser when a Python interpreter (python, or else python3) is available; dependencies are read from the import statements, with versions from a requirements.txt or pyproject.toml when there is one, and installed with pip; each script runs as its own python process (processx is required), so unlike R scripts, a name one script defines is not available to another. When no Python interpreter is available, the Python files are reported as not run and the R results are still returned. Statistics the Python scripts print are compared with the paper together with the R output and any self-reproducible output (JASP/jamovi, SPSS-Viewer, notebook outputs).

Full text

Abstract

Psychology and social neuroscience study the biological basis of real-world interactive behaviors, such as dancing or playing music in groups. Autonomic nervous system reactivity, assessed through cardiac and respiratory signals, plays an important role in these behaviors.

However, affordable, scientifically validated, research-grade devices for synchronous, real-time physiological monitoring of multiple individuals in natural settings remain scarce. We propose a wearable open-source physiological monitoring device, the BRAMS-Bio-Box (B3), that can record cardiac and respiratory signals simultaneously from multiple individuals. B3 can be built cost-effectively using open-source blueprints and software we provide to yield a transparent, flexible option for research-grade physiological data collection. We empirically validated B3 against a widely used reference device in nine participants performing various motor and guidedrespiration tasks. Heart rate (HR) and heart rate variability (HRV) were derived from electrocardiographic (ECG) signals, while respiratory sensors were evaluated for respiration rate and the accuracy and consistency of exhalation event detection. B3 derived HR and HRV closely matched reference measures across tasks, with high quality ECG recordings and minimal data loss, except during vigorous arm swinging. Respiratory rate and pattern metrics, including exhalation peak timing, also showed strong agreement. The B3 thermistor accurately tracked respiration rate even at higher breathing frequencies, although minor timing offsets occurred during some guided respiration segments. Overall, B3 performed comparably to the reference system for cardiac and respiratory measures, offering an affordable, open-source solution for physiological monitoring in real-world interactive settings.

Introduction

Imagine a few dozen people dancing to music in a park, while researchers wirelessly and reliably measure their heartbeats, respiration and electrodermal response. Imagine a concert hall where fifty or so spectators' emotional states are tracked in parallel for offline analysis. Physiological signals, including heart rate (HR), heart rate variability (HRV), and respiration, offer researchers a powerful lens through which to study human behavior and health. Cardiac and respiratory measures have long been used to monitor stress (Faust, Hagiwara, Hong, Lih, & Acharya, 2018; Kim, Cheon, Bai, Lee, & Koo, 2018; Pourmohammadi & Maleki, 2020), cognitive load (Ayres, Lee, Paas, & Van Merrienboer, 2021; Hidalgo-Muñoz et al., 2019), emotional states (Harmat et al., 2015; Jerritta, Murugappan, Nagarajan, & Wan, 2011; Zhang, Chen, Zhan, Yang, & Xia, 2017), and physical exertion (Nicolò, Massaroni, Schena, & Sacchetti, 2020) giving researchers the ability to objectively assess various psychophysiological states. For instance, acute mental stress is typically associated with increased HR and respiration rate, together with reduced HRV.

The latter phenomenon is generally interpreted as reflecting reduced vagal/parasympathetic influence (Widjaja, Orini, Vlemincx, & Van Huffel, 2013). Beyond applications focused on individual physiological states, there is growing interest in studying physiological processes at the group level, particularly in research on interpersonal dynamics and music cognition (Delius & Müller, 2023; Gugnowska et al., 2022; Lange et al., 2022). Notably, physiological variables such as HR and HRV become in some cases synchronized in individuals during joint action, providing insight into emotional and collaborative dynamics (Danyluck & Page-Gould, 2019; Gordon et al., 2020; Palumbo et al., 2017; Thorson, West, & Mendes, 2018). To enable such applications, an essential first step is to ensure that individual cardiac and respiratory signals can be recorded accurately under conditions approximating real interactive settings.

Accurately capturing cardiac (HR, HRV) and respiratory signals is critical in both laboratory and field studies. Traditionally, researchers have relied on off-the-shelf wired and wireless physiological recording systems from vendors such as ADInstruments (Dunedin, New Zealand), BIOPAC Systems, Inc. (Goleta, CA, USA), and BioSemi B.V. (Amsterdam, the Netherlands). In highly mobile or interactive paradigms, wired configurations can restrict participants' freedom of movement because of cables and bulky hardware, thereby reducing ecological validity. Wireless systems alleviate some of these constraints; however, many still depend on a central acquisition module connected to a personal computer (PC), which limits portability and complicates their use in naturalistic settings outside the laboratory.

In recent years, a variety of portable and wearable physiology monitors have emerged, providing greater flexibility while maintaining research-grade data quality. A comparison of available platforms is provided in the accompanying https://doi.org/10.17605/OSF.IO/GX6W3 (Bahadori, Voix, Dalla Bella, & van Vugt, 2024). For example, a validation study of the Shimmer wearable sensor platform (Shimmer Research Ltd., Dublin, Ireland) showed that its electrocardiographic (ECG), electromyographic (EMG), and galvanic skin response (GSR) signals closely matched those recorded using standard laboratory equipment (Burns et al., 2010). Similarly, the Polar H10 heart rate sensor (Polar Electro Oy, Kempele, Finland) has been shown to produce HRV metrics that agree with those derived from standard ECG recordings (Schaffarczyk, Rogers, Reer, & Gronwald, 2022). The Empatica wristband (Empatica Inc., Cambridge, MA, USA) has also demonstrated the ability to capture heart rate and HRV accurately under controlled, low-motion conditions, offering an unobtrusive alternative to wired systems (Schuurmans et al., 2020).

Collectively, these systems illustrate the range of tools now available for physiological data acquisition, from traditional wired setups to modern wireless wearables.

Despite these advances in wearable technology, many current solutions remain proprietary. High equipment costs can restrict the number of units that can be purchased for simultaneous recording, thereby limiting achievable group sizes and the statistical power of group-based studies. Proprietary hardware and software may also constrain researchers' ability to modify the system, integrate additional sensors or data streams, and develop experimental paradigms beyond those anticipated by the manufacturer. This limitation is particularly relevant to studies of interpersonal dynamics and music cognition, where synchronized audio recordings of speech or musical performance may be essential alongside physiological signals. (see the OSF repository for available platforms (Bahadori et al., 2024)). Finally, many available systems, including commercial ones, have not been subjected to stress tests under conditions which do not require that the participant sit absolutely still. As a result, their reliability in more naturalistic settings, where participants can move, talk, and interact, remains insufficiently documented. To evaluate the utility of B3 for rigorous scientific research, the device was benchmarked against BioNomadix from BIOPAC, a widely used commercial research-grade physiological recording system (Babusiak, Hajducik, Medvecky, Lukac, & Klarak, 2021; Flagler, Tong, Allison, & Wilcox, 2020). ECG and respiratory signals were recorded simultaneously with both systems on the same set of participants while they performed tasks varying in motor involvement, including rest, voice production, walking, arm-swing movements, and guided respiration at different rates.

The analyses compared (1) the proportion of usable data collected during each task, (2) HR and HRV, with HRV indexed by the root mean square of successive differences (RMSSD), and (3) respiratory signal usability, respiration rate, and the accuracy and consistency of detected respiratory events. In the guided-respiration task, the pacing cue provided a ground-truth reference for expected respiration rate and timing, allowing calculation of the absolute measurement error.

Methods

Participants

Nine participants were recruited for this study (7 females; age range, 23-46 years; mean ± std, 30.6 ± 6.3 years). The experimental protocol adhered to the principles of the World Medical Association's Declaration of Helsinki and received approval from the Ethics Committee for Research in Education and Psychology at the University of Montreal (CEREP-22-007-D). All participants provided written informed consent prior to participation.

Materials

The B3 system is an ambulatory hardware-software platform that enables the simultaneous recording and streaming of cardiac, respiratory, movement, and audio data using a compact wireless device. Cardiac activity is recorded through electrocardiography (ECG) and photoplethysmography (PPG), which captures changes in peripheral blood volume. Respiratory activity is recorded using a respiration belt and a thermistor; movement is captured through a three-dimensional (3D) accelerometer; and ambient sound is recorded using a mono omnidirectional electret microphone. Physiological and movement signals are sampled at 500 Hz, whereas audio is sampled at 48 kHz. All data streams are synchronized (Figure 1A). The computational core consists of a Teensy 4.1 development board (PJRC, Sherwood, OR, USA), operating at 600 MHz, which interfaces with the onboard sensors through serial peripheral interface (SPI), inter-integrated circuit (I²C), inter-IC sound (I²S), universal asynchronous receiver-transmitter (UART), Secure Digital input/output (SDIO), and digital and analog connections. Acquired data is passed to an ESP32-S3 system-on-chip used as a coprocessor (Espressif Systems The B3 supports two concurrent acquisition modes: a real-time streaming mode via Lab Streaming Layer and local recording mode, saving data to an SD card. Streaming is available for all data channels except audio and enables real-time inspection of signal quality, whereas all channels are continuously stored on the SD card for subsequent offline analysis. Streaming can be enabled or disabled without interrupting SD-card recording. (Figure 1C).

For validation, ECG and respiratory data were collected simultaneously from B3 and an MP160 data-acquisition system equipped with a BioNomadix wireless respiration/ECG amplifier (BN-RSPEC; BIOPAC Systems, Inc., Goleta, CA, USA). Hereafter, the respiratory signals recorded using the BIOPAC respiration belt, B3 respiration belt, and B3 thermistor are referred to as BIOPAC-belt, B3-belt, and B3-thermistor, respectively. Procedure

Before the experimental tasks, participants were fitted with both the B3 and BIOPAC systems.

The B3 PPG sensor was clipped to the left earlobe, the thermistor was positioned beneath the nostrils to measure respiratory airflow, and the B3 unit containing the embedded 3D accelerometer was secured to the participant as illustrated in Figure 1B.

For both systems, ECG electrodes were positioned according to a single-channel Lead II configuration: the negative electrode was placed below the right clavicle, the positive electrode over the lower left rib, and the ground electrode over the manubrium (similar to Harmat et al., 2015). Corresponding B3 and BIOPAC electrodes were positioned side by side, with at least 3 cm between each pair. The BIOPAC respiration belt and wireless amplifier were then attached, and both systems remained in place throughout the experiment. Before recording, the B3 signals were inspected through Lab Streaming Layer streaming (using B3 streaming mode), and sensor placement was adjusted until satisfactory signal quality was obtained. Then B3 was switched to local recording mode (streaming was disabled) so that its data was written to an SD card for offline analysis.

Each participant completed one continuous 15-minute run (i.e., a single recording session) consisting of the task blocks listed in Table 1. Before starting the tasks, participants were briefed on the procedure and given instructions for each task. They were also informed that they would be notified about the type, onset, and end of each task during the data collection session. After providing these explanations, recordings were initiated on both devices (B3 and BIOPAC). The same BIOPAC unit was used for all nine participants, whereas three separate B3 units with identical designs, architectures, and settings were each tested in three participants to assess interunit consistency.

The experiment began with a 30-second stationary rest block, during which participants stood still and remained silent. This block established a stationary reference before the first active task.

Equivalent 30-second rest blocks were inserted between the active tasks (hereafter referred to as "rest") to separate consecutive task periods and to provide local reference segments for detecting task-related audio and acceleration activity. Following the initial rest, participants were instructed to perform the first experimental task (Table 1). In this task, they were asked to either speak freely about a random subject or, if they felt comfortable, to speak and sing the "Happy Birthday" song. Hereafter, this task is referred to as "voice" and each participant performed it twice, with rest in between.

The walking task (here after referred as "walk") required participants to walk continuously around the available space in the experimental room while synchronizing their steps to a metronome set at 90 beats per minute.

The third task (here after referred as "swing") was designed as a movement stress test, using large, repetitive upper-body movements to challenge signal acquisition and evaluate the robustness of the B3 recordings under motion-related perturbations. Participants started with their arms alongside the body and first performed the movement in a posterior-to-anterior direction: the arms moved backward behind the body, then upward through an overhead position, then forward in front of the body before returning to the starting position alongside the body. The movement was paced by a metronome set at 45 beats per minute. After 30 seconds, participants were asked to reverse the direction of the movement and continue.

The fourth task involved a guided respiration (hereafter referred to as "resp") exercise. In this task, participants viewed a video in which a blue circle on a grey background periodically expanded (accompanied by a high-pitched click) to signal inhalation onset and contracted (accompanied by a low-pitched click) to signal exhalation onset. Participants were instructed to inhale during circle expansion and exhale during contraction, synchronizing their respiration with the visual cue. Each exhalation lasted three times longer than each inhalation. Five respiration rates (4, 5, 6, 10, and 14 breaths per minute [bpm]) were presented in randomized order, each in a separate 90-second block. The https://doi.org/10.17605/OSF.IO/GX6W3 are made available on OSF (guided respiration videos (Bahadori et al., 2024)]. All five blocks were performed consecutively without rest. After completing the guided respiration task, participants completed a 60 second final rest block under the same standing-still and silent instructions, marking the end of the experiment. Data processing B3 data were acquired at the sampling rates specified above, whereas the BIOPAC system recorded at a sampling rate of 2 kHz. To synchronize the data from the B3 and BIOPAC offline, their time series were aligned using naturally occurring heart rate variability; specifically, one signal was temporally shifted until the R-R intervals, defined as the time intervals between successive R peaks in the ECG, matched between the two recordings (see Fig. 1 in https://doi.org/10.17605/OSF.IO/GX6W3).

After this between-system alignment, each recording was segmented into individual experimental blocks corresponding to each task. For voice-1 and voice-2, the block boundaries where speech onset and offset in the audio waveform, and for the walk and swing blocks, boundaries were determined using the magnitude of the three-axis acceleration vector, calculated as sqrt(x² + y² + z²), where x, y, and z denote acceleration along the accelerometer's device-fixed axes) (see Fig. 2 in https://doi.org/10.17605/OSF.IO/GX6W3).

Then we used the onsets and offsets of audio and acceleration signals to determine when each task started, so that the stream could be segmented by task. The onsets and offsets of the audio and acceleration signals were detected using a threshold-based method. For each block, the threshold was defined as the mean absolute signal amplitude during the 3-second rest period immediately preceding the block plus two standard deviations. An onset was marked when the absolute amplitude of the raw signal exceeded this threshold, whereas an offset was marked when the absolute amplitude fell below the same threshold and remained below it for at least 3 s during the subsequent rest period.

The respiration block was further segmented into the five consecutive 90-second guided respiration blocks corresponding to the different respiration rate cues. The first inhalation cue marked the onset of the block (time zero). A 450-second window (5 × 90 s) beginning at this cue encompassed all respiration rates. This window was then divided into five contiguous 90-second epochs, each labeled with its corresponding target respiration rate (4, 5, 6, 10, and 14 bpm).

ECG preprocessing and cardiac metric extractions R peaks in the ECG and inhalation and exhalation onsets in the respiratory signals were detected using the BioTop Python toolbox (van Vugt, 2026) as follows. The direct-current (DC) offset was first removed from each ECG signal (Van Gent, Farah, Van Nes, & Van Arem, 2019) and after the Neurokit detector algorithm was used to process and autodetect R peaks (Makowski et al., 2021). The missing or wrongly detected peaks were corrected manually after the autodetection using a graphical interface. This procedure was followed for the ECG data from the B3 and BIOPAC separately.

Artefactual segments of each recording, defined as periods with excessive noise (e.g., motion artefact or muscle contraction) that prevented reliable R peak detection, were identified manually and excluded from further analysis (see Supplementary Materials; Fig. 3). These artefactual portions of the signal were marked manually using the BioTop Python interface. After R peak detection, intervals between successive R peaks outside artefactual periods were calculated to derive HR (by converting the average R-R peak time difference to beats per minute, BPM) and HRV (quantified as the root mean square of successive R-R interval differences, RMSSD). Both metrics were calculated only for signal segments in which neither B3 or BIOPAC ECG signals were marked as artefactual.

To compare device performance, HR and RMSSD were derived for five experimental conditions: rest (all rest periods combined), voice (two talk/sing blocks), walk, swing, and respiration (all guided respiration blocks combined). For conditions recorded more than once (rest, voice, respiration), HR and RMSSD values were averaged across blocks; For the respiration condition, these metrics were additionally computed separately for each of the five 90-second guided-respiration blocks.

Respiration preprocessing and respiratory metric extraction

Respiration signals were bandpass-filtered using a second order Butterworth filter (0.05-1 Hz) to isolate the respiratory waveform (Harmat et al., 2015; Hidalgo-Muñoz et al., 2019). Inhalation and exhalation onsets were automatically detected in BioTop (van Vugt, 2026) via NeuroKit2's respiration peak detection using the Khodadad et al. ( 2018) method and inspected manually and corrected as needed (Khodadad et al., 2018; Makowski et al., 2021); detected timestamps were then exported to MATLAB R2018a for further analysis.

Respiration measurements were compared between the BIOPAC respiration belt, the B3 respiration belt, and the B3 thermistor. Usable signal segments were identified by visual inspection, excluding any portions lacking clear respiratory cycles (e.g., flat signals). Respiration rate (breaths per minute; bpm) was calculated by dividing 60 by the mean interval, in seconds, between consecutive exhalation onsets, while discarding intervals that overlapped with unusable segments identified in the previous steps. Blocks with fewer than two detected exhalation peaks were excluded from rate analysis.

Temporal alignment of exhalation onsets during guided respiration blocks was assessed by converting each detected exhalation onset into a phase within the paced respiration cycle and summarizing timing bias (circular mean phase) and timing consistency (resultant vector length); the phase calculation is defined below and illustrated in Figure 2. Indeed, because the pacing cue was strictly periodic and participants were instructed to synchronize their breathing with it, detected exhalation onsets were expressed as phase within each paced respiration cycle. The circular mean phase quantified timing bias (accuracy) relative to the cue, whereas the resultant vector length quantified the consistency of exhalation timing. For each block, the guided respiration cycle duration (T = 60/bpm) was used, the rate at which participants ought to be breathing if they perfectly followed the guide. This paced cycle duration was used to convert each exhalation timestamp (t) into an angular phase θ = 2π × (t mod T)/T thereby collapsing all events into a single representative cycle. Phases were then shifted by -π/2 so that the expected exhalation onset corresponded to 0 radians. The Circular Statistics Toolbox for MATLAB R2018a was used to compute the mean phase, reflecting synchronization accuracy relative to the expected exhale onset, and the resultant vector length (range: 0-1), indicating temporal consistency of exhalation timing (1 = perfect alignment) across participants for each guided respiration block.

Statistical analysis

Statistical comparisons were conducted using nonparametric tests given the small sample size.

To assess systematic differences in HR and RMSSD calculated from the B3 and BIOPAC ECG signals, a Wilcoxon signed-rank test was used (Wilcoxon, 1945). For the respiration data, Friedman tests were used to compare measures derived from the BIOPAC belt, B3 belt, and B3 thermistor, including phase consistency quantified by resultant vector length (range 0-1) (Friedman, 1937).

Discussion

In this study, the open-source B3 device demonstrated measurement performance comparable to the widely used BIOPAC BioNomadix system for both ECG and respiratory signals. B3 could accurately measure HR and HRV across a range of activities ranging from resting and speaking to moderate exercise including walking and arm swings. No statistically significant differences in mean HR or HRV were found between the two systems in almost any task conditions, indicating that B3 can reliably capture cardiac dynamics even during mild physical activity. This strong agreement in HR metrics mirrors prior observations that modern wearable or low-cost devices can accurately track heart rate, with minimal error relative to ECG references (Stone et al., 2021). Notably, both devices produced very little artefactual ECG data: even during movement tasks, signal quality was largely maintained, and only the vigorous swing task introduced a slight increase in noise for the B3 recordings. Indeed, both devices were quite similar in finding the HR and HRV in the portions that were considered in the calculations. This outcome is encouraging, especially as HRV (and RMSSD) is a sensitive measure of autonomic function; the B3's ability to capture RMSSD suggests it successfully detects beat-to-beat intervals with high fidelity. Such parity in HRV measurement is likely due to B3's direct ECG sensing, unlike some wearables that rely on PPG and show degraded HRV accuracy (Langevin et al., 2021), an ECG-based open device like B3 can achieve research-grade precision in inter-beat interval detection.

Respiratory measurements from the B3 closely followed those from the reference BIOPAC system. The B3 is equipped with a flexible respiration belt sensor (recording chest expansion) and a nasal thermistor (recording airflow temperature changes), providing two modalities to capture respiration. Both of these B3 sensors showed close agreement with BIOPAC respiration signals in terms of respiratory rate and timing. Across all tasks, respiration rates measured by B3 were similar to those obtained with BIOPAC, and the pattern of inhalations and exhalations aligned closely across devices. The agreement also extended to the timing of exhalation events.

During natural respiration and most guided respiration segments, peaks corresponding to exhalations in B3's recordings occurred close to those observed in the BIOPAC data. This indicates that B3 can accurately track the dynamics of respiration cycles, which is essential for applications like stress monitoring or cardiorespiratory research. In particular, the B3 thermistor sensor performed very well at higher respiration frequencies. The sensor continued to detect each breath without dropouts or missed peaks, while maintaining accurate counts of breaths per minute. This is remarkable because some respiratory monitoring modalities, such as inductive belts or PPG-based respiration estimates, can be less reliable at fast respiration rates. By contrast, thermistors can capture rapid airflow changes reliably when properly calibrated (Ermer, Brewer, Orr, Egan, & Johnson, 2019). Notably, the B3 thermistor (B3T) generally outperformed the belt sensors in both devices in terms of data usability, particularly during tasks involving movement.

Taken together, the respiration results demonstrate that B3's open hardware approach does not compromise on signal quality: it can measure respiration as effectively as a laboratory-grade system, providing both rate information and close timing of respiratory phases.

Sensor performance

While B3 displayed very similar performance to the reference system (BIOPAC), a few minor discrepancies merit discussion. First, during the swing task, the B3's ECG channel showed a slightly higher level of high-frequency noise and sporadic signal artifact compared to the BIOPAC. This difference is likely due to motion artifacts -the physical jostling of electrodes and movement-induced muscle electrical activity that contaminate the ECG trace (Kher, Pawar, & Thakar, 2013). Arm swinging involves repetitive shoulder and torso movement, which can tug on leads or generate electromyographic noise. The BIOPAC BioNomadix, may employ advanced shielded cables, high-quality amplifiers, and sophisticated filtering to mitigate motion artifacts, whereas the B3 -a prototype and lower-cost open-source device -might have more basic shielding or filtering. Despite these factors, B3 retained a high portion of analyzable ECG data during arm swings, and the derived HR and HRV remained comparable to those obtained with BIOPAC. This resilience suggests that the B3's design is sufficiently robust for moderate activity, though future improvements, including improved motion artifact filtering algorithms or accelerometer-based noise cancellation could further enhance signal quality in high-motion scenarios. This outcome shows that, for most practical purposes, the B3's ECG is functionally very close to the reference system (BIOPAC) ECG even when the person being measured is in motion, as they may often be during real-world physiological monitoring.

A slight temporal offset was observed in the B3 thermistor signal during some guided-respiration blocks. Specifically, during some segments of slower guided respiration, the peaks corresponding to exhalations in the B3 thermistor trace appeared earlier than those observed in the BIOPAC and B3 belt signals. Several factors could explain this lag. One possibility is the difference in sensor modality and placement: the BIOPAC likely used a respiratory inductance plethysmography belt, which measures chest expansion directly. In contrast, the B3 thermistor detected temperature changes of air flow at the nostrils; This suggests that the thermistor's placement and mechanism allow it to capture the onset of airflow at the source, whereas the BIOPAC system's respiratory belt measures a downstream mechanical response. In particular, the B3T's nasal thermistor directly senses the temperature change of exhaled air at the nostrils (Sabil et al., 2019), providing an immediate proxy for airflow, while the BIOPAC respiratory inductance plethysmography belt monitors chest wall expansion and contraction (i.e., changes in thoracic volume) (Sabil et al., 2019). In essence, the belt output is an integrated representation of airflow, which inherently introduces a small phase lag: the peak volume (i.e., the chest deflation) occurs moments after peak airflow (Hoskuldsson, Hallgrimsson, & Sigurdarson, 2020).

However, the observed offset was small and consistent. It did not affect breath counting nor the estimated respiration rate, but only the temporal alignment of the exhalation peaks. Such a discrepancy is likely inconsequential for most research applications. Yet, it should be taken into account when the precise timing of respiratory phases relative to another time reference matters, particularly when comparing airflow-based measurements with measures of chest-volume change. Altogether, aside from this timing difference, the B3 thermistor's performance was robust, even under the challenging condition of guided respiration where participants rapidly inhale and exhale on a cue. The accuracy of B3 in capturing respiration rate and timing pattern, despite using different sensor types (belt vs. thermistor), underscores the reliability of its design.

This also demonstrates how multiple sensors on an open-source device can be combined to cross-validate and enrich respiratory monitoring, for example by integrating both chestmovement and airflow signals to detect apnea or irregular respiration.

Implications for open-source physiological monitoring

The present validation of the B3 device has significant implications for physiological research and health monitoring. B3's performance, comparable to that of an widely used commercial system, points to the possibility of obtaining high-quality biosignal data without relying exclusively on expensive, proprietary platforms. These findings support a growing body of evidence that low-cost, open-source biosensing platforms can achieve research-grade accuracy, effectively lowering barriers to entry for laboratory and field researchers (Wagner, Plácido da Silva, & Gramann, 2021). This democratization of technology is crucial. Traditional research equipment like BIOPAC, while highly reliable, comes with high costs and often operates within closed ecosystems requiring proprietary software (Montgomery, Nair, Chen, & Dikker, 2024; Wagner et al., 2021). In contrast, an open-source device like B3 offers affordability, flexibility, and transparency, allowing researchers to access raw data in real time without relying on opaque algorithms (Montgomery et al., 2024). This transparency supports open science practices and reproducibility by enabling researchers to inspect, validate, modify, and share signal-processing methods, including custom HRV analysis pipelines and artifact-removal techniques. Moreover, the low cost of B3 means that laboratories with limited budgets, as well as large-scale requiring many sensors, to deploy multiple units without prohibitive expense. The ability to integrate B3 with other open-source tools and software, since it is not locked into a single vendor's ecosystem, further enhances its utility for multi-modal experiments. In our case, we further encourage integration in existing lab settings via the LSL platform with which B3 is fully compatible. Notably, the present study demonstrates that these open source advantages need not come at the cost of data quality. By showing comparable data quality across HR, HRV, and respiratory measures, these results support the use of B3 for scientific data collection in psychophysiology, exercise science, human-computer interaction, and related fields. Moreover, the present results help establish confidence in the use of open-source devices in contexts that have historically relied upon commercial equipment. Just as the EmotiBit project and others have aimed to "bridge the gap" between user-friendly wearables and high-fidelity research tools (Montgomery et al., 2024), the B3 adds to this movement by proving that an open hardware approach can meet the standards of physiological signal monitoring demanded by research applications.

Future Directions

The present findings provide a validation of B3 as an open-source platform for ECG and respiration recording.Several directions remain for future development and testing. From an engineering perspective, future versions of B3 could further improve motion-artifact resistance, for example by using accelerometer or gyroscope data to reduce movement-related noise in the ECG signal during dynamic tasks. The dual respiration setup (belt and thermistor) could also be further exploited by combining belt-and thermistor-based signals in a sensor-fusion approach, potentially improving the precision of respiration timing estimates. In addition, although the present study focused on ECG and respiration, B3's open-source architecture could be extended to other physiological signals, such as electroencephalography (EEG) or EMG, provided that each new module is separately validated. Future studies should also formally assess userexperience factors, including comfort, ease of setup, battery life, and suitability for longer recordings.

The present study validated individual B3 units rather than the multi device group configuration that ultimately motivates the platform. Establishing the measurement performance of individual units was a necessary first step; however, future studies should assess the reliability, synchronization, and practical deployment of multiple B3 devices during interactive and ecologically valid experiments. The ability to record sound synchronously with cardiac and respiratory signals, together with the possibility of using multiple devices simultaneously, makes B3 particularly suitable for studies of interpersonal dynamics, joint action, and music cognition.

For example, B3 could be used to examine physiological synchrony in dyads, small groups, ensemble musicians, dancers, choirs, or concert audiences.

Limitations

The modest sample cannot fully represent variability across body types, age groups, or clinical populations. Future validations should include a larger and more diverse sample, both to confirm B3's accuracy across different body types, ages, or clinical conditions, and to ensure that the device performs well for individuals with varied signal characteristics. Another limitation is that the tasks, while covering a range of activities, were relatively short in duration. Moreover, future studies could examine the durability of signal quality over time and under conditions like perspiration or prolonged motion, which can affect sensor adhesion and noise.

Conclusion

The comparative analysis indicates that the B3 open-source device is capable of delivering ECG and respiratory measurements with accuracy close to a widely used commercial system under variety of typical testing conditions. Minor differences observed (a slight increase in motion artifacts during rapid arm movement, and a timing offsets in one respiratory sensor) did not undermine the overall data integrity. The successful validation of B3 holds promise for the broader adoption of open-source physiology monitors. By providing an affordable, transparent, and flexible alternative to proprietary systems, devices like B3 can empower a wider range of researchers and clinicians to collect high-quality physiological data. This democratization of technology can accelerate scientific discovery and educational projects, as more groups are able to engage in biosignal research without the hurdle of prohibitive equipment costs. Ultimately, these findings contribute to a growing confidence in open-source biosensing: as seen with other platforms validated against laboratory systems (Montgomery et al., 2024; Wagner et al., 2021),

B3 exemplifies how open hardware innovations can meet stringent research standards. Future work building on this foundation will help to refine these tools and expand their capabilities, moving the field toward an era where accessible, research-grade physiological monitoring is available to all.
