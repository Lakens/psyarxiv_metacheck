Reporting p values imprecisely (e.g., p < .05) reduces transparency, reproducibility, and re-use (e.g., in p value meta-analyses). Best practice is to report exact p-values with three decimal places (e.g., p = .032) unless p values are smaller than 0.001, in which case you can use p < .001.

This module sometimes flags false positives when sentences discuss how p-value thresholds were set. It can also miss an imprecise p-value that is reported against a threshold (e.g., “decreased at the p < .05 significance threshold”).

What we found

We found 22 non-significant p values that should be checked for appropriate interpretation.

Show details

Meta-scientific research has shown nonsignificant p values are commonly misinterpreted. It is incorrect to infer that there is ‘no effect’, ‘no difference’, or that groups are ‘the same’ after p > 0.05.

It is possible that there is a true non-zero effect, but that the study did not detect it. Make sure your inference acknowledges that it is possible that there is a non-zero effect. It is correct to include the effect is ‘not significantly’ different, although this just restates that p > 0.05.

Patterns are designed to capture:

When a statement is expected

The module sorts each paper by where its data came from (the internal .data_source(); the signs and how the rule was tested are described in R/data-source.R): - own: the authors collected data from people or animals, for this paper, in an earlier study of their own, or (a protocol) will collect them; - existing_records: records about individual people that the authors obtained for this study, such as hospital records or a cohort; - existing_unclear: existing data about people from a source the module could not identify; - open_resource: an open resource any researcher can use, such as UK Biobank or NHANES; - none: no data about people or animals (a review, simulation, commentary, theory, tutorial, coding of published papers, or figures about groups); - uncertain: the signs were missing or pointed both ways; - no_text: the paper has no text.

How Power Analysis Check works

This module uses regular expressions to identify sentences that contain a statistical power analysis. If specified by the user, it also uses a large language model (LLM) to extract information reported in power analyses, including the statistical test, sample size, alpha level, desired level of power, and magnitude and type of effect size.

The Power Analysis Check module uses regular expressions to identify sentences that contain a statistical power analysis. Without the use of an LLM, the module uses regular expressions to classify the power analysis as a-priori, sensitivity or post-hoc. With the use of an LLM, it checks if the power analysis is reported with all required information.

The regular expressions can miss power analyses, or fail to classify them correctly. The type of power analysis is often difficult to classify, which can easily be solved by explicitly specifying the type of power analysis as ‘a-priori’, ‘sensitivity’, or ‘post-hoc’. Note that ‘post-hoc’ or ‘observed’ power is rarely useful. The LLM can fail to identify information in the paper, and will not have access to information in paragraphs in the paper other than those that contain the word ‘power’. This package was validated by the Metacheck team on articles in Psychological Science.

This module was developed by Lisa DeBruine, Daniel Lakens and Cristian Mesquida

Overall, among all instances flagged as power statements, 90.6% were correct (positive predictive value).

How Preregistration Check works

Retrieve information from preregistrations in a standardised way, and make them easier to check.

The Preregistration Check module identifies preregistrations on the OSF and AsPredicted based on links in the manuscript, retrieves the preregistration text, and organizes the information into a template. The module retrieves text from the OSF with its API, and from AsPredicted with ResearchBox’s API when a ResearchBox key is set (see rbox_token()), or else from the preregistration’s web page. The information in the preregistration is returned. An AsPredicted link that could not be read is named in the report, with the reason.

The module can’t extract information from non-structured preregistration templates (i.e., where the preregistration is uploaded in a single text field) and it can’t retrieve information in preregistrations that are stored as text documents on the OSF.

If you want to extend the package to be able to download information from other preregistration sites, reach out to the Metacheck development team.

How StatCheck works

Check consistency of p-values and test statistics

The Statcheck module runs Statcheck. Statcheck searches for regular expressions that match a predefined pattern, and identifies APA reported statistical tests. More information on the package can be found at https://github.com/cran/statcheck. The module only returns Statcheck results for t-tests and F-tests, as these are the only tests which have been validated, see https://osf.io/preprints/psyarxiv/tcxaj_v1/.

Statcheck was developed by Michèle Nuijten and Sascha Epskamp.

Statcheck considers p = 0.000 an error, as you should report p < 0.001. Furthermore, p < 0.03 is an error if the p-value was 0.031, and one should simply report exact p-values (p = 0.031). When the sentence of a test says it is one-sided (“one-tailed”, “one-sided” or “directional”), a p-value that fits a one-sided test counts as consistent (statcheck’s OneTailedTxt setting; #695). When the paper says anywhere that its tests are one-sided, a p-value that fits a one-sided test in either direction counts as consistent too: half the two-sided p, or 1 minus that half for an effect against the predicted direction. Equivalence tests (TOST) are left out, as their p-values do not test the difference. A statistic written with “<” or “>” is read as a bound, and in a sentence about equal variances an F-test’s two-sided p (twice the one-tailed p) counts as consistent. For more information, see StatCheck.

This module only checks statistical results reported in the running text of the manuscript. It cannot (yet) process statistics reported only in tables.

This module was developed by Daniel Lakens and Lisa DeBruine

Read more in the metacheck manual.

Therefore 0% of true instances were missed, and 43% of detections were false positives. See https://osf.io/preprints/psyarxiv/tcxaj_v1/ for more details of the validation.

How Exact P-Values works

List any p-values reported with insufficient precision (e.g., p < .05 or p = n.s.), reported as exactly zero (e.g., p = .000), or impossible (below 0 or above 1, e.g., p = -.22).

This module uses regular expressions to identify p-values. It will flag any values reported as p > ? or p < numbers greater than .001. It will also flag p-values reported as exactly zero (e.g., p = .000, p = 0.00), which are mathematically impossible — p-values are never exactly zero and should instead be reported as p < .001.

A p-value that is not the result of a test is not flagged: a table note (“* p < .05, ** p < .01”), a figure legend (“Asterisks indicate significant differences (p < .05)”, “Values in bold are significant at p < .05”) or a stated threshold (“p < .05 was considered significant”, “thresholded at p < .001”). GROBID often puts such notes into the running text, so each p-value is judged by the words in its own clause (the text up to a “;” or a full stop), and never left out when a test statistic belongs to it (“F(1, 7) = 8.03, # p < .05”). The column not_a_test of the table says why a p-value was left out (“marker”, “threshold”, “legend” or “named”).

A p-value with the name of a correction or a test after the p (“pFWE < .05”, “padj < 0.05”, “p Wilcoxon = .02”) is flagged only when a test statistic comes before it in its clause (“t(37) = 7.17, p FWE < .05”). Without one it is mostly the rule that decided what was significant (“genes with padj < 0.05 were selected”); such a p-value is “named” in not_a_test. Notes in other forms, such as a marker after the p-value (“p < .05 (*)“), are still flagged.

A p-value below 0 or above 1 is impossible; it is listed apart and not also as imprecise. Often the statistic before it, or its minus sign, was copied into it (“t(134) = -2.32, p = -.13”, “Z = 3.091, P = 3.091”). A value above 1 is listed only after a test statistic in its clause: without one, a “P” above 1 was nearly always another quantity (a proportion, pH, a group’s mean, a model parameter). A number in scientific notation whose power of ten was lost when the PDF was read (“p = 2.4 x 10 -9” read as 2.4) is not listed. A “p” that is the subscript of another symbol (“r p = .64”, “²p = .02” for partial eta squared, “Δp = .33”), or a quantity with a unit, a logarithm or a ratio (“P = 2.9 µm”, “-log10 P = 7.5”, “Ca/P = 1.67”), is not read as a p-value at all (see extract_p_values()). Each p-value has its own row, also when the same one is written twice in a sentence.

This module sometimes flags false positives when sentences discuss how p-value thresholds were set. It can also miss an imprecise p-value that is reported against a threshold (“decreased at the p < .05 significance threshold”).

How Repository Check works

This module retrieves information from repositories.

The Repository Check module lists files on the OSF, GitHub, ResearchBox, DSpace (PsychArchives and other legacy- and DSpace 7-based installations), Zenodo, Dataverse, Figshare, Dryad, ReShare, 4TU.ResearchData, Mendeley Data, DataONE (Arctic Data Center, KNB, and other member nodes), and LDbase based on links in the manuscript.

A link to a file-sharing service (Google Drive, Dropbox, OneDrive, Box, WeTransfer, MEGA, iCloud Drive, Baidu Netdisk, SURFdrive; see [file_share_links()]) gets a warning and makes the light yellow: such services are not repositories, as files can be changed or deleted at any time, get no DOI, and the link stops working when the account is closed. The report advises a stable repository such as Zenodo instead. Their files are not read, and summary_table$file_share_n counts the links.

Deposits in archives for sequence and expression data (GEO, the INSDC archives BioProject, SRA, ENA and DDBJ, and ArrayExpress; see [seq_archive_links()]), mostly named by accession number, are read for whose deposit they are. The authors’ own are listed with what they hold ([seq_archive_size()]) and are not downloaded or checked as data and code; summary_table$archive_own_n counts them.

R packages on CRAN ([cran_links()], [cran_info()]) are the paper’s own when a paper author is a package author and the paper presents the package; the paper’s own are listed with their version and not checked (summary_table$cran_own_n). A Handle link (hdl.handle.net/...) that leads to a repository read here is checked as a link to that repository ([handle_links()]).

Listing a repository’s files never requires an API key, but some hosts answer faster or more completely with one: OSF allows 100 requests/hour unauthenticated versus 10,000/day with a token (see [osf_pat()]), and Dryad enforces a strict per-IP daily quota on repeated listing (see cache below). Dryad is a special case beyond rate limits: listing a Dryad dataset’s files works without a key, but actually downloading file CONTENTS from Dryad fails with HTTP 401 unless a key is set, even for a fully public dataset (see [dryad_pat()] or [dryad_auth()]). Since this module only lists files and never downloads their contents itself, that limitation applies to data_check and code_check (which do download content), not here – see their own documentation.

When a linked OSF page is a registration, its registered_from project (the one it was registered from, which the manuscript itself may never link directly) is also checked: if that project is public its files are listed under its own URL, and if it is closed or otherwise inaccessible the report flags it explicitly, since some registrations only describe their content rather than mirroring it.

Whose deposit is each link? The ownership table gives, for every repository linked in the text and (with references = TRUE) every deposit cited in the reference list, one of six labels: own_this (made by the authors for this paper), own_earlier_data or own_earlier_code (the authors’ own, from earlier work), others_data or others_code (made by other people, reused here), or not_data (a publication such as a preprint, not a deposit), with ownership_group (“own”, “others”, “not_data”) and the reason. It is decided without a language model, from the sentence or reference that cites the link, the paper’s authors (names, ORCID iDs, affiliations), and what the deposit’s own record and files say (who made it, what it names, when, whether it is a software package; for an OSF project cited only in the reference list, its record alone). On a round of labelled links the rules had not been written from, the three groups were right for 98% of links in the main text (93 of 95) and 90% in reference lists (74 of 82); the labels were made by Claude agents from each link’s evidence, and disputed ones checked against the deposits. Telling this paper’s own deposit from the authors’ earlier one is less certain.

Only the deposits that are this paper’s own are checked. A deposit linked in the text that holds other people’s work (others_data, others_code) or the authors’ earlier work (own_earlier_data, own_earlier_code) is listed in the report, with the reason, but its files are left out of table and kept in table_not_checked: they count toward nothing here (files that do not belong in a repository, naming, READMEs, studies, the traffic light), and code_check, data_check and reproducibility_check, which read table, do not check them either. reproducibility_check still puts the files of theirs that the paper’s code names in the folder the code runs in, as a re-analysis needs the data it re-analyses. When every linked deposit is set aside, the traffic light is “na”. A deposit that is the paper’s own is counted as such when its README, title or description names the paper (its title or DOI).

How Code Check works

This module retrieves information from repositories checked by repo_check about code files (R, Python, SAS, SPSS, Stata, Mplus, MATLAB).

The Code Check module checks R (also R Markdown and Quarto), Python (also Jupyter notebooks), SAS, SPSS, Stata, Mplus, and MATLAB files, using regular expressions to check the code; JASP files are listed but not read. The language of a Quarto document or a notebook is read from the file itself (its engine or kernel), not from its extension. The regular expression search will detect the number of comments, the lines at which libraries/imports are loaded, attempts to detect absolute paths to files, setwd() and install.packages() calls, and lists files that are loaded, and checks if these files are in the repository; R code is also parsed. The module will return suggestions to improve the code if there are no comments, if libraries/imports are loaded in lines further than 4 lines apart, if files that are loaded are not in the repository, if absolute file paths, setwd() or install.packages() are found, and if R code cannot be parsed.

The regular expressions can miss information in code files, or falsely detect parts of the code as a fixed file path. Libraries/imports might be loaded in one block, even if there are more than 3 intermittent lines. The module was tried out internally on papers published in Psychological Science, but has not been formally validated. There might be valid reasons why some loaded files can’t be shared, but the module can’t evaluate these reasons, and always gives a warning.

The module also checks whether the repository pins the R/package versions the analysis actually depended on: an renv.lock file (parsed for the R version and every locked package + its version/source), a sessionInfo()/sessioninfo::session_info() text dump (matched by filename — sessionInfo.txt/session_info.txt and similar, or embedded in a README), or a groundhog::groundhog.library()/checkpoint::checkpoint() date-pin call in the code (a bare library(groundhog)/library(checkpoint) does not count — the pinning call itself must be present). When none of these is found, the report flags it as a reproducibility gap: package versions may drift between when the analysis was run and any later reproduction attempt.

If you want to extend the package to perform additional checks on code files, or make the checks work on other types of code files, reach out to the Metacheck development team.

Checking code requires downloading its file contents. For a paper whose repository is on Dryad, this never succeeds unless a Dryad API key is set: Dryad requires one to download file bytes, even from a fully public dataset (listing the repository’s files does not need one). Without a key, every Dryad-hosted code file is listed but unchecked, and a warning naming Dryad and ?dryad_pat/?dryad_auth is included among the download failures recorded in the manifest.

How Data Check works

This module classifies the files in a repository into semantic types (data, codebook, code, software, output, supplemental, readme, asset, other) and, for tabular data files, extracts each column’s type and summary statistics.

The Data Check module consumes the file list produced by repo_check (or any files added via local_path). Each file is classified with rule-based heuristics layered over metacheck’s file_category() and file_types: file names matching README / codebook patterns win first, then an extension crosswalk, then format-locked extension overrides. For every file classified as tabular data that is available locally, the module reads the file head, describes each column with data_col_facets() and computes summary statistics for numeric columns. Every sheet of a spreadsheet that holds a table is read: a file with several such sheets has its columns under source_file = "file.xlsx [sheet]", and the sheet column names the sheet of any spreadsheet with several sheets; a sheet of notes or a codebook is treated as documentation when the file has another table. Following DDI, a column is described by orthogonal facets rather than a single type: representation (numeric/text/datetime/code — how it is stored), measurement_level (Stevens: nominal/ordinal/interval/ratio), concept (what it measures: reaction_time/age/gender/likert/id/…), role (identifier/measure/condition/timestamp), unit, and a quality state (ok/empty/constant). Concepts are detected by name+value rules (the demographic concepts via data_check_demographic()); when llm_use(TRUE) the model fills concepts and measurement levels the rules left blank. Qualtrics survey exports are recognised (data_check_is_qualtrics()): their extra header rows are stripped so columns type correctly, and the reserved response-metadata columns (StartDate, Duration, Finished, …) are tagged.

The module defaults to rules-only when llm_use(FALSE): columns the rules cannot resolve (ambiguous 3–20-unique integers, ambiguous character columns) fall back to continuous / text respectively. When llm_use(TRUE), ambiguous columns and unresolved file types (other) are sent to llm() for optional refinement, and every file is assigned a study group (ex1, pilot2, shared, …) so that multi-study repositories can be recognised (used by psychds_check). Without an LLM the study group is left NA (unknown).

Column extraction requires files to be readable from disk. Files fetched by repo_check from OSF/GitHub/etc. without a local copy (file_location is NA) are classified but not column-extracted; pass local_path to point at a downloaded copy of the repository.

For a paper whose repository is on Dryad, this means column extraction never happens unless a Dryad API key is set: Dryad requires one to download file bytes, even from a fully public dataset (dataset listing and metadata do not need one). Without a key, every Dryad file stays classified but un-downloaded, column_n is 0, and a warning naming Dryad and ?dryad_pat/?dryad_auth is included among the download failures. A one-time session message is also shown (see repo_check) the first time a Dryad dataset is encountered with no key set.

Every downloaded text file the authors wrote (code, settings, survey definitions such as Qualtrics .qsf files, documentation, outputs) is searched for keys: API keys, access tokens and private keys, which let anyone who downloads the file use a paid service at the authors’ cost. Of a tabular data file only the column names and first 3 rows of the table as read are searched: its values come from participants, but a key the authors set for a whole survey (as embedded data in a Qualtrics survey flow) is exported in every response. The search uses the rules of the secret scanner betterleaks (https://github.com/betterleaks/betterleaks, MIT licence) of high and medium confidence. A key found turns the traffic light red; the report and the keys table give its file, line and type, and only its beginning. Other files over 25 MB and binary files are not searched. A key is never tested with its provider. Every module’s result has any whole key replaced by “keyremoved” (see module_run()).

How Reproducibility Check works

This module assesses whether a paper’s R and Python code can be run on its data. It works in two phases. The static phase (always run) collects the package dependencies the code declares, rewrites the data-file paths that do not work in the repository as the authors organised it, works out the order the scripts must run in, and diagnoses why any referenced input file is unavailable — reporting what a reproduction attempt would involve and where it is likely to break. The execution phase (opt-in, execute = TRUE) then actually runs the code: it copies the repository into a throwaway directory, optionally installs the declared dependencies into a throwaway library, runs each script in order in an isolated subprocess with a per-script timeout, and captures the outcome and full output of each run.

By default (execute = FALSE) the module does not run any code — it performs only static analysis: reading dependencies with the same extractors as code_check, finding the files the code references in the repository, and building a run-order dependency graph. It reports what would be installed and run rather than doing it.

When execute = TRUE, the module additionally runs the downloaded code on your machine — a deliberate, opt-in action gated behind that argument (callr is required for R code). Each script runs in an isolated subprocess so a crash cannot take down the R session; note this isolates crashes, not the filesystem or network. Installs (when install_missing = TRUE) and the throwaway run library never touch your main R library. Each script’s outcome is one of ran_ok, errored, timed_out, dependency_unavailable, not_parsed, run_by_source (an R script another script runs with source(), which is run only inside that script, since on its own it lacks the packages and objects the sourcing script sets up first), run_by_import (a Python file other files import, a module rather than a script, unless it has an if __name__ == "__main__": block), jags_model (a JAGS or BUGS model saved with an R extension, which another script reads) or not_r_content (a file that is not R at all, such as a JSON or HTML dump); these last two are not run and are not failures. python2 marks Python 2 code that was not run. With sandbox = "docker" such code runs with Python 2.7 (option metacheck.docker_image_py2; FALSE turns this off), which modifications records; it is never converted, since that can change results. defines_functions is a file that only defines functions, which is used, not run (table$used_by names the scripts that use it), and not_analysis is a file of software rather than of the analysis: a package’s code, tests, documentation or setup.py, a copy of a tool, a web application, a script a program wrote (table$not_analysis_why says which); neither is run or counted as a script. docker_failed means the container never started, which says nothing about the script, so it keeps the light from being green but does not make it red. needs_a_person is a script that stopped because it asks a person to choose a file or answer a question, or that starts an app, and needs_internet one that stopped because the network is off in a Docker run, or, with internet = TRUE, could not reach what it asked for; download_too_large is a script stopped for downloading more than the limits allow (see internet), and out_of_memory one that, or a program it started (such as a compiler), ran out of the memory each script may use. All four are treated the same way. not_downloaded is a script that stopped on a file the repository lists but that was not downloaded, such as one over max_file_size: it could not be tried, so it is not counted as a script that did not reproduce (summary_table$repro_not_downloaded_n counts them apart). not_read is a file metacheck could not read, so it was not run; the light is then not green, as the file may read and run on another computer, and table$error_message says why, naming a package that is installed but cannot be loaded on the computer that ran the check. empty is a file with nothing in it, which is not run or counted as a script. For a script that did not run through, table$error_message is its error, short (at most 300 characters): the error line of its output, which names a package that is not there, with the address it asked for when it needed the internet, or the time limit it reached; table$reason sorts it into a kind. A timeout means “still running at the cutoff”, not a failure, so raise timeout for legitimately long-running (e.g. Bayesian) scripts. dependency_unavailable means the script’s own package could not be installed from live CRAN, the CRAN Archive, or a named GitHub/URL source — an infrastructure limitation, not a defect in the paper’s code. The full stdout/stderr of every run is kept in the result’s run_results (the report shows it in per-script dropdowns, capped for readability).

Provenance, kept so that a TRACE Research Object (TRO) declaration of the run can be written later from a stored result (metacheck #404; the helpers are in R/provenance.R). Only when code was run (execute = TRUE): * run_results$started_at, run_results$ended_at: when each run of a script started and ended (ISO 8601, UTC, milliseconds); NA for a script that was not started. A script run again in a later pass has the times of its last run. A TRO uses them for each trov:TransparentResearchPerformance. * run_results$exit_status: the exit status of the process that ran the script (0 = ended normally); NA when the process did not report one (a time limit, or Docker failing to start the container). * artifacts: one row per file, with stage (deposit: as downloaded from the repository, hashed from the downloaded file; before_run: the run folder just before the first script ran, after metacheck’s own changes, such as rewritten paths and unpacked archives; after_run: only the files the scripts made (status new), changed (changed) or removed (removed), as an unchanged file is the one listed before the run), path (relative to the run folder, as valid UTF-8, a byte of another encoding written as <xx>), size (bytes), sha256, mime_type (by extension, NA when unknown), source (the file’s address in the repository, for deposit). The package libraries metacheck installs in the run folder are left out, as are metacheck’s own files there (a script’s runner, and the statistical output it writes in statistical_output/). Files metacheck itself copied or made between passes (see modifications, output_copied, file_placed) show in after_run too. A TRO uses the rows as trov:ResearchArtifacts and each stage as a trov:ArtifactArrangement. * modifications$sha256_before, modifications$sha256_after: the hash of the changed script as downloaded and as it ran; NA when the script is not at the same path in both (a script made from an R Markdown file). * environment: the system that ran the code (trov:TransparentResearchSystem in a TRO): metacheck_version, started_at, ended_at, host (R version, platform, operating system), sandbox, network_isolated (TRUE only when every Docker run had --network none; the process sandbox does not stop the network), internet, timeout_per_script, total_timeout, python_local (the Python run outside Docker and its version), and docker: runs (for each kind of run, r_run, r_install, python_run, python_install, the image and the docker run arguments, such as --network none, --read-only, --cap-drop ALL, no-new-privileges, the process limit and the memory and processor limits) and images (for each image, its ID and digests from docker image inspect, its creation time and the R and Python versions its environment declares).

run_results$checked says what the run of each script shows about the code, in five groups, so that a script that does not reproduce is kept apart from one the check could not test: ran (it ran to the end); code_error (it did not reproduce: it stopped with an error of the code or the deposit, could not be read, or needs a file the deposit does not hold); dependency (a package or program was not available: a package that could not be installed or was not loaded, a program outside R and Python, a system library, or R crashing in a package’s compiled code); time (it did not finish within the time limit for one script, or was not started because the time for all scripts had run out); and not_checkable (it could not be checked automatically: it needs a person, the internet, a key or another setting of the authors’ computer, one platform such as Google Colab, Windows or OpenSAFELY, more memory than the run allows, a file that was not downloaded, a screen, or a program that runs it, or it is a file of a package of the code that Python runs only as a module of that package). It is NA for files run inside another script, files that are not an analysis, files not read, and a Docker failure. summary_table counts each group (repro_ran_n, repro_code_error_n, repro_dependency_n, repro_time_n, repro_not_checkable_n), and the report’s first sentence gives them. The traffic light reflects the static readiness signals by default; a script in code_error that stopped with an error makes it red, as a script that crashes on its own analysis is a genuine reproduction failure, and a script in one of the other three groups keeps it from being green. Calls that need a screen, which the run does not have (dev.print(), dev.copy2pdf(), dev.copy2eps(), savePlot(), windows(), win.graph(), x11(), quartz(), View()), are replaced before the run by calls that need none, which modifications records as screen_call_replaced. A script that fails with could not find function is run once more with the library() calls the project’s other scripts make added at its top (or the one package that exports the function, or magrittr for %>%), and a script that then runs is reported as reproducible only after that repair.

Dependencies are reported name-only, with the source (CRAN, GitHub, or a base package already shipped with R) — static analysis of the code cannot know which version was used, and running against current package versions is itself informative: a break argues the authors should have pinned versions. When the repository does record versions, a run with recorded_versions = TRUE installs the packages the scripts load at those versions, but it does not change the R version, which remains a limitation of the check.

Run order is derived from read-after-write data dependencies (a script writing a file another reads must run first), source() edges, and numeric filename prefixes as a weak tie-breaker. Ambiguous orderings, dependency cycles, and inputs a script reads but that no earlier script produces (and that are not in the repository) are surfaced as warnings, since these are the situations most likely to make an otherwise-correct reproduction fail.

Python code (.py files, and notebooks and Quarto documents whose code is Python, from which the code is extracted first) goes through the same two phases, reported in its own “Python code” section. Each file is checked for syntax errors with Python’s own parser when a Python interpreter (python, or else python3) is available; dependencies are read from the import statements, with versions from a requirements.txt or pyproject.toml when there is one, and installed with pip; each script runs as its own python process (processx is required), so unlike R scripts, a name one script defines is not available to another. When no Python interpreter is available, the Python files are reported as not run and the R results are still returned. Statistics the Python scripts print are compared with the paper together with the R output and any self-reproducible output (JASP/jamovi, SPSS-Viewer, notebook outputs).

Abstract

Here we examined how physical-effort induced arousal may have a differential impact on perception and metacognition in older adults. While arousal has been shown to enhance some aspects of perceptual performance in young adults, it can also disrupt metacognitive performance. However, both perceptual and metacognitive functions decline with age, alongside deterioration of neural systems that regulate arousal (e.g., Locus Coeruleus-Norepinephrine; LC-NE). Thus, it is unclear how physical-effort induced arousal influences perceptual performance and metacognitive efficiency in older adults. To test this, we had participants complete two perceptual discrimination tasks (auditory and visual), which involved judging whether two sequential stimuli were the same or different, and subsequently rating their confidence in their same/different response. At the start of each trial, arousal was manipulated by instructing participants to maintain either a low or high hand grip force on a dynamometer. We fit psychometric functions to characterize perceptual performance between grip levels and used the Relative Psychometric Function (RPF) analysis framework to characterize metacognitive ability while controlling for perceptual performance. Across tasks, high grip increased psychometric thresholds, but not psychometric slopes. On the other hand, metacognitive efficiency increased under high grip and was numerically larger in the auditory task, which appeared to be driven by increased error awareness during the easiest stimulus level. Together, these findings suggest that acute arousal can disrupt perceptual performance but enhance metacognitive efficiency in older adults.

Introduction

Aging is associated with declines in how sensory information is processed (Schneider & Pichora-Fuller, 2000). Older adults typically require stronger sensory signals to achieve the same level of accuracy as younger adults, reflecting elevated detection and discrimination thresholds across visual and auditory tasks (Owsley, 2011; Humes et al., 2013). Central auditory dysfunction in particular has been linked to later cognitive decline and Alzheimer's disease (Gates et al., 2011; Mohammed et al., 2022), and untreated hearing and vision impairments are now listed as modifiable risk factors for Alzheimer's disease and related dementias (Livingston et al., 2024).

Age-related perceptual declines are also accompanied by deficits in perceptual metacognitionthe ability to monitor and evaluate one's own perceptual decisions-usually quantified with retrospective confidence judgments (Fleming & Lau, 2014; Palmer et al., 2014; Klever et al., 2022). Perceptual metacognition allows individuals to recognize when their perceptual judgments are unreliable and deploy compensatory strategies, which helps maintain safety and autonomy in older adulthood. The extent of age-related declines in metacognitive performance may vary across processing domains (Palmer et al., 2014; Klever et al., 2022). Specifically, Palmer et al. (2014) found significant decreases in metacognition for a visual decision-making task, but only a nonsignificant decrease on an analogous recognition memory task for words. However, no studies have directly compared perceptual metacognition of older adults across modalities (e.g. auditory vs. visual stimuli), nor how this is impacted by effects of arousal.

Both perceptual performance and metacognition are impacted by arousal, and systems that help regulate arousal---such as the locus coeruleus-norepinephrine (LC-NE) system---also degrade with age (Flood & Coleman, 1988; Mather & Harley, 2016). The LC is the brain's primary source of norepinephrine, a neuromodulator critical for regulating arousal, attention, and cognitive control (Sara, 2009; Mather & Harley, 2016). Structural and histopathological studies show that the LC is vulnerable to age-related degeneration (Flood & Coleman, 1988) and is among the first sites affected by Alzheimer's disease-related tau pathology (Jacobs et al., 2021). Aging-related changes in the LC-NE system complicate predictions about how arousal will affect perception and metacognition in late life. On the perceptual side, there is evidence that brief, phasic arousal manipulations using auditory warning cues can improve visual processing speed in older adults (Haupt et al., 2018). Similarly, a short bout of arousal-inducing exercise using isometric hand grip before performing an easy auditory oddball detection task tended to speed detection in older women (Mather et al., 2020). However, arousal induced by a concurrent physical effort task using isometric hand grip has also been shown to impair cognitive control in older adults; specifically, high exertion selectively reduced visual workingmemory accuracy when distractors were present (Azer et al., 2023). Thus, arousal induced shortly before a task has mainly been shown to speed processing in older adults, without altering visual perceptual thresholds (Haupt et al., 2018), whereas arousal from concurrent physical effort has been shown to reduce accuracy under higher attentional demands.

On the metacognitive side, studies in younger adults which have experimentally manipulated arousal or its physiological components suggest that elevated arousal can alter how confidence tracks perceptual performance (Allen et al., 2016; Hauser et al., 2017). For example, Allen et al. (2016) showed that arousal induced by unconscious disgust cues disrupted the normal relationship between sensory noise and subjective uncertainty (where greater noise should induce greater uncertainty), without affecting metacognitive sensitivity. Hauser et al. (2017) showed that attenuating noradrenergic signaling by blocking β-adrenergic receptors using propranolol improved metacognitive sensitivity without changing perceptual accuracy. Similarly, raising cortisol, a slower component of the stress response, reduced metacognitive efficiency at matched perceptual performance (Reyes et al., 2020). One account Hauser and colleagues considered to explain their findings was that LC-NE activity raises neural gain, amplifying strong inputs and attenuating weak ones, which could flatten the subtle signal differences required for metacognitive judgments. However, this gain mechanism may operate differently in aging: in younger adults, arousal induced by classical fear conditioning selectively enhanced neural responses to salient visual stimuli, whereas in older adults it enhanced responses to both salient and non-salient stimuli (Lee et al., 2018). Thus, if the metacognitive cost of arousal depends on selective gain increases, older adults may not experience these costs.

In the current study, we use a trial-by-trial hand grip manipulation (low vs. high force, similar to Azer et al., 2023) to modulate arousal while older adults perform auditory and visual perceptual discrimination tasks that involved both same-different judgments and confidence ratings of those judgements. We model perceptual performance by fitting psychometric curves across five standard-probe stimulus levels to quantify psychometric slope and threshold, where higher slopes indicate greater discrimination precision, and lower thresholds indicate greater sensitivity to the stimulus (Kingdom & Prins, 2016). We quantify metacognitive efficiency using the Relative Psychometric Function (RPF) to examine type-2 performance at matched type-1 performance (Maniscalco & Lau, 2012 , 2014; Maniscalco et al., 2026).

Given the lack of prior work on arousal effects on metacognition in older adults, and perceptual findings that depend on when arousal is induced, we addressed the following research questions: (1) Does trial-by-trial arousal modulation via hand grip affect perceptual performance in older adults? (2) Does arousal affect metacognitive efficiency? (3) Do these effects differ between auditory and visual modalities? If concurrent physical effort primarily impairs processing (as in Azer et al., 2023), we should observe shallower slopes and elevated thresholds. Alternatively, if arousal speeds perceptual processing (Haupt et al., 2018; Mather et al., 2020), we might observe faster response times without change in slopes or thresholds. For metacognition, if the cost of noradrenergic activity observed in younger adults extends to aging (Hauser et al., 2017), elevated arousal should reduce metacognitive efficiency. Alternatively, if aging reduces the selectivity of arousal-related gain (Lee et al., 2018), the metacognitive costs of arousal seen in younger adults may be reduced or absent in older adults. Because prior arousal effects have been reported separately for auditory (Mather et al., 2020) and visual (Haupt et al., 2018; Azer et al., 2023) tasks, we treated modality differences as exploratory.

Methods

Participants

Seventy participants were recruited from areas surrounding the University of California, Riverside, via mail, flyers, social media, and word-of-mouth. An a priori power analysis (G*Power 3.1; Faul et al., 2007) indicated that a sample of 34 participants would provide 80% power (α = 0.05) to detect a medium within-subject effect (f = 0.25) in a repeated-measures ANOVA with two levels (low vs. high grip) and an assumed correlation among repeated measures of 0.5. Eligibility criteria included being between the ages of 60-90, having normal hearing and normal or corrected-to-normal vision, and being able to understand English well enough to follow experimenter instructions. Additionally, participants were required to be righthanded and free of the following: contraindications to undergo MRI scans, use of psychotropic medications, significant neurological conditions, and major health conditions such as diabetes. One participant was removed after self-reporting a possible diagnosis of MCI, and another for possible diagnosis of essential tremor. Additional data cleaning (described in the data cleaning section) left a final sample of 68 participants who completed at least one task (auditory: n = 66; visual: n = 66; both: n = 64; M=69.50 years, SD=6.43 years, 50% Female). All participants provided written informed consent and were compensated for their participation. All procedures were approved by the University of California, Riverside Institutional Review Board. The study was not pre-registered.

Procedure

Participants underwent 4 testing sessions, where sessions 1, 2, and 3 were always on separate days. Session 1 consisted of task practice and structural MRI. Participants first watched short instructional videos for the auditory and visual tasks without hand grip or confidence ratings and practiced at least 60 trials on each task. Then, participants' maximum voluntary contraction (MVC) was measured using 3 trials where participants squeezed the dynamometer as hard as they could for 5 seconds, with about 30 seconds of rest between each trial. The average of the grip force across these 3 trials was taken as the MVC for subsequent normalization of the 5% (low) and 40% (high) target grip force in the subsequent practice tasks. Finally, participants watched additional instructional videos of the auditory and visual tasks that included hand grip and confidence ratings and completed short practice blocks for each. During each practice block, hand grip performance was also monitored to ensure participants were holding at the designated low or high grip level for the instructed duration-visual indicators were present during the hand grip gauge display, with a green fill indicating an acceptable grip range, yellow indicating slight deviation for the acceptable range, and red fills indicating major deviations for the ranges. After each practice block, accuracy and response time were monitored to ensure participants understood the auditory and visual tasks. Participants were instructed to repeat practice blocks at the discretion of the experimenter. Following this, participants underwent a series of structural MRI scans (MRI data not reported here).

During Sessions 2 and 3, participants performed either the auditory or visual task inside the MRI scanner while functional MRI scans were acquired (MRI data not reported here), with session order counterbalanced across participants. The MVC was acquired again during Session 2 inside the scanner, which was used to normalize the target grip force during the tasks for both Sessions 2 and 3. Before Sessions 2 and 3, participants also received a short practice block outside of the MRI scanner before performing the 5 blocks of the auditory task or visual task, punctuated by short periods of rest between each block. Session 4 was administered remotely over a touchscreen tablet, where participants completed neuropsychological tests adapted for digital implementation. Results of these tests are not included in the present study.

Stimuli & Task Design

Participants engaged in separate auditory and visual same/different discrimination tasks. In both tasks, a standard and probe stimulus were presented in succession, and participants judged whether the stimuli were the same or different using button presses; subsequently, they provided a confidence judgment. The trial structure is shown in Figure 1. For both tasks, trials began with a 1.5-4.5 s jittered period where only a blank screen with a gray background was displayed. Next, participants were shown a 3 s rectangular grip gauge with a marker at 5% or 40% from the bottom of the gauge, indicating to the participant to hold the dynamometer (left hand) at 5% or 40% of their maximum voluntary contraction (MVC), followed by a 0.25 s blank screen and 0.5 s fixation dot. Subsequently, the auditory or visual stimuli were presented, depending on the task. For the auditory task (Figure 1, left), the initial (standard) stimulus was a 0.1 s sinusoidal tone played at 1000 Hz and 0.5 s later the second (probe) stimulus was a 0.1 s tone that was either identical to the standard tone or positively offset at 8, 16, 32, or 64 Hz. For the visual task (Figure 1, top right), the initial (standard) stimulus was a centrally-presented sinusoidal grating (Gabor patch) at a Michelson contrast of 0.2 and spatial frequency of 1.5 cycles/degree, subtending 4 visual degrees, and 0.5 s later the second (probe) stimulus was grating that was identical to the standard grating or positively offset by a contrast increase of 0.06, 0.12, 0.24, or 0.48. Participants then relaxed their hand grip and had a 3 s fixed time window to indicate whether the two stimuli were the same or different using their right index finger ("different") or middle finger ("same"), followed by a second 3 s response window where participants indicated their level of confidence in their same/different response on a 4-point scale (1 = low,4 = high). For each task, each of the 5 probe stimulus levels was pseudorandomly shown in equal proportions, with a total of 150 trials split evenly over 5 blocks. Hand grip performance was monitored for each block, and participants were given corrective feedback if they were consistently failing to hold the dynamometer at the designated level (around the grip gauge marking) and/or for the correct duration (until the offset of the second stimulus). All stimuli were generated and presented using Psychophysics Toolbox Version 3.0.18 (Brainard, 1997; Kleiner et al., 2007) and MATLAB R2022b (The MathWorks, Inc., Natick, USA).

Quantifying Adherence to Hand Grip Manipulation

To quantify participant adherence to the hand grip manipulation, we computed a metric that captures the separability between distributions of high and low grip force trials. This metric is analogous to Cohen's d and provides a standardized, unitless measure of effect size. The grip adherence metric was calculated as the difference between the mean grip force observed during high-grip trials and that which was observed during low-grip trials, divided by the pooled standard deviation from both grip levels. The time window used to calculate mean grip force excluded the first 2 seconds to allow time for participants to reach their target grip force. Higher values of grip adherence indicate a greater separation between the grip force distributions (Figure 2). This measure not only facilitates direct comparisons of hand grip manipulation adherence across subjects and sessions but can also serve as a covariate for analyses involving performance differences between high and low grip levels.

Data Cleaning

We excluded trials where a participant's run had greater than 90% of single-button same/different responses (i.e. 90% "same" or 90% "different" response). An overwhelmingly single-button response would indicate a technical issue or failure of the participant to understand or perform the task. This exclusion removed 3.62% of trials. Trials in which the participant missed the same/different response were also removed, which consisted of an additional 1.69% of trials. To exclude implausibly fast responses, we set a lower bound of 200 ms after the same/different response prompt (450 ms after offset of the second stimulus), which removed an additional 1.37% of total trials. Trials were also excluded if participants failed to maintain their target grip force for at least two-thirds of the 2 to 3 s period following trial onset, defined as 30-55% MVC for high grip and 1-15% MVC for low grip. This removed an additional 4.00% of trials. A total of 90.01% of trials remained after data cleaning.

Statistical Analysis Same/Different Psychometric Function Analysis

To characterize behavioral performance on the perceptual tasks (auditory and visual), we fit psychometric functions to each individual participant's behavioral data using the Psignifit 4 toolbox in MATLAB (Schütt et al., 2016). This method allows for robust estimation of psychometric thresholds and slopes while accounting for potential overdispersion in the datamore variance in performance at a given stimulus level than would be expected by the standard binomial model. Psignifit 4 fits 5 parameters: threshold, width, lapse rate, guess rate, and a dispersion metric, eta. While width is estimated in place of slope, a psychometric slope can be calculated after fitting.

We quantified how grip levels influence sensitivity by comparing estimated thresholds and slopes of the psychometric function between grip levels. For each participant and grip level (high vs. low), we fit a Weibull function to the proportion of "different" responses across stimulus levels (e.g., frequency or contrast offsets). Because the Weibull function is undefined at a stimulus level of 0, we replaced the 0-offset (i.e., physically identical stimuli) with half of the smallest non-zero stimulus level, which acts to preserve the full range of difficulty levels while ensuring compatibility with the Weibull function. Because this substitution is arbitrary, we repeated the fits with the 0-offset set to 1/4, 1/8, and 1/16 of the smallest non-zero level. Thresholds were stable across substitutions (rank correlations .96-.99), but slopes were less so (.79-.97, lowest in the auditory task); effects that depended on the substitution are noted in the Results and Table 3. Lapse and guess rates were allowed to vary for each fit, and slopes and thresholds were calculated at the point halfway between the guess rate and 1 minus the lapse rate, corresponding to the function's effective midpoint (~0.5 probability of "different" response).

Participants were excluded from statistical analyses of psychometric function parameters if the estimated threshold exceeded that of the stimulus range (i.e. >64Hz for Auditory task, >0.48 contrast for the Visual task), as threshold estimates beyond this range do not reflect a valid characterization of the participant's psychometric function within the tested stimulus space. This excluded 3 participants for the auditory task, and 0 participants for the visual task.

Goodness of fit of the same/different psychometric functions were assessed using the deviance statistic D, as computed by the Psignifit toolbox (Schütt et al., 2016). For well-characterized data, deviance converges to 1.0 per stimulus level, yielding expected total deviance of 5.0 across the five stimulus levels used. Mean deviance values were well below this expected value across all four conditions (Table 2), indicating that the Weibull model provided an adequate characterization of participant data.

Relative Psychometric Function Analysis

Metacognitive research distinguishes between two layers of performance. Type-1 performance refers to the accuracy of a decision about external stimuli. Type-2 performance refers to how well an observer monitors their type-1 decisions. This is indexed by measures like confidence ratings which ideally track type-1 performance; confidence is typically high when the type-1 decision is correct and is low when the type-1 decision is incorrect. However, confidence naturally drops when the task itself gets harder (here, lower frequency/contrast offsets) even as one's inherent monitoring ability is unchanged. Therefore, analyses which seek to quantify type-2 performance must account for the difficulty of the type-1 task. The Relative Psychometric Function analysis framework achieves this by treating both type-1 and type-2 performance as functions of a common independent variable. Exact details of the analysis framework are detailed in Maniscalco et al. (2026), though a brief description is given below.

To examine whether hand grip level modulates the relationship between type-1 (same/different task) and type-2 (confidence response) performance, for participant, task, and grip level, we first constructed a type-1 psychometric function by interpolating the probability of a "different" response on different trials across stimulus levels-equivalent to type-1 accuracy for those trials (Figure 6a, Figure 7a). Over those 4 stimulus levels, we then derived a type-2 psychometric function, which related type-2 AUC by stimulus level, a non-parametric measure of metacognitive efficiency (Figure 6b, Figure 7b). Type-2 AUC was defined as the area under the type-2 receiver operating characteristic (ROC) curve, which plots the type-2 hit rate (probability of reporting high confidence on correct trials) against the type-2 false-alarm rate (probability of reporting high confidence on incorrect trials) as the confidence criterion varies (Fleming and Lau, 2014). With k = 4 discrete confidence ratings, the empirical ROC comprised k -1 = 3 points corresponding to each rating-threshold criteria, and this curve was closed by appending the endpoints (0, 0) and (1, 1). Area under the curve was computed by the trapezoidal rule. Finally, we generated relative psychometric functions (RPFs) by plotting type-2 AUC against the corresponding interpolated type-1 probability-"different" for each grip level (Figure 6c, Figure 7c). For each participant and task, we identified the range of probability-"different" covered by both the low-and high-grip RPFs. Then for that shared range, we computed 𝑃 ̅ 2,𝑡𝑦𝑝𝑒-2 𝐴𝑈𝐶 for each grip level as the mean type-2 AUC. Note that the shared range was identical for the two grip levels within a participant and task, but was not identical across tasks. 𝑃 ̅ 2,𝑡𝑦𝑝𝑒-2 𝐴𝑈𝐶 measures metacognitive sensitivity with type-1 performance held constant (i.e., metacognitive efficiency). For comparison, we also analyzed raw confidence ratings outside the RPF framework.

Statistical Modeling Framework

We used linear mixed models to analyze the effects of task modality, grip level, and grip adherence on the following outcome measures: threshold, slope, correct-trial response time, 𝑃 ̅ 2,𝑡𝑦𝑝𝑒-2 𝐴𝑈𝐶 , and mean confidence. For each outcome measure, two classes of linear mixed models were estimated:

Combined Models: For analyses including both auditory and visual tasks, we fit models with task modality, grip level, and grip adherence as fixed effects, including task modality × grip level and grip level × grip adherence interactions. Subjects were modeled with both random intercepts, with random slopes by task, allowing for individual differences in how grip effects varied across modalities (68 participants, observations per outcome are listed in Table 3). Psychometric threshold and slope were z-scored within each task as these measures have incomparable units (Hz for auditory: contrast for visual). Reaction time, 𝑃 ̅ 2,𝑡𝑦𝑝𝑒-2 𝐴𝑈𝐶 ,, and mean confidence were entered in raw units, as these measures shared a common scale across tasks. As a result of within-task z-scoring, the main effect of task modality for threshold and slope is uninterpretable in the combined model, and the task modality × grip level interaction should be interpreted with caution. Task-specific models (described below), are therefore used for inference for grip effects within each modality for threshold and slope.

Task-Specific Models: Planned task-specific analyses were run to explore modality-specific effects. Specifically, we fit separate models for the auditory and visual tasks, each including grip level and grip adherence as fixed effects with grip level × grip adherence interaction and subjects as random intercepts. The auditory task included 66 participants (132 observations), and the visual task included 66 participants (132 observations).

High grip associated with increases in threshold but not slope

We first asked whether high grip affects how large a stimulus offset participants need to detect a difference (threshold), as well as how steeply their "different" choice probability rises with stimulus offset (slope). In the combined mixed model, grip level was associated with higher thresholds (β = 0.174, p = .001), and similarly in the task-specific models; in the auditory task (p < .001), and in the visual task (p = .035), although the visual threshold effect was not robust to the value substituted for the zero-offset stimulus (p from .033 to .064). The grip level × task interaction was not significant for threshold, as well as other fixed effects, for these threshold models (Table 3).

On the other hand, grip level was not associated with changes in slope in either combined or task-specific models. The grip level × task interaction was also not significant. Grip adherence (how well participants distinguished low and high grip levels) was associated with steeper slope in the combined model (p = .012) and in the visual task (p = .009), though both adherence effects were significant only at smaller zero-offset substitutions. Taken together, high grip shifted the psychometric function to the right with no detectable change in slope, perhaps indicating a more conservative criterion for a "different" response. There was also a significant main effect of task modality (p = .041). However, because the type-1 range over which 𝑃 ̅ 2,𝑡𝑦𝑝𝑒-2 𝐴𝑈𝐶 was averaged was matched across grip levels but not across tasks, this effect may partly reflect differences in type-1 performance between tasks, and we do not interpret it as a modality difference in metacognitive efficiency. The grip level × task modality interaction was not significant. In the auditory task only, higher grip adherence was also associated with higher 𝑃 ̅ 2,𝑡𝑦𝑝𝑒-2 𝐴𝑈𝐶 (p = .024). The grip level × grip adherence interaction was not significant for either task (auditory p = .721; visual p = .557) or in the combined model (p = .492).

To better understand what was driving the grip effect on metacognitive efficiency, visual inspection of the confidence rating by stimulus level plots (figure 6D, 7D) suggested that in the auditory task, participants appropriately gave lower confidence ratings to incorrect trials during high grip compared to low grip conditions specifically during the easiest stimulus level, while confidence ratings for correct trials remained relatively similar across grip levels. Association between grip level and raw confidence was small

We asked whether the increase in metacognitive efficiency under high grip could be due to a general rise in confidence, as metacognitive efficiency is known to have a small to medium positive relationship with overall confidence (Xue et al., 2021). Mean confidence, outside the RPF analysis, was fit in the same mixed model framework (Table 3). Figure 8 shows mean confidence by grip level for each task, which lie close together. In the combined model, high grip was associated with higher confidence (β = 0.031, p = .034). However, the grip-level effect was not significant in the auditory task (p = .058), nor in the visual task (p = .943), and the grip level × task modality interaction was not significant . In the visual task, higher grip adherence was associated with lower confidence (p = .033). Remaining terms are in Table 3. Grip effects on threshold and metacognitive efficiency were unrelated across participants

Given the significant effect of grip level on both psychometric threshold and metacognitive efficiency, we wanted to ask whether participants who showed a larger threshold change also show a larger metacognitive efficiency change. For each participant and task modality (auditory, visual), we defined the grip effect as the difference between high-and low-grip conditions on the measures of interest: psychometric threshold and 𝑃 ̅ 2,𝑡𝑦𝑝𝑒-2 𝐴𝑈𝐶 . To place auditory and visual effects on a common scale before aggregating, each modality-specific difference was z-scored across participants. We then averaged the modality-specific z-scores, yielding one cross-modality composite for each measure. The correlation between the threshold composite and 𝑃 ̅ 2,𝑡𝑦𝑝𝑒-2 𝐴𝑈𝐶 composite was not significant (Pearson r = .05, two-tailed p = .673, 95% CI [-.20, .30]), visualized in Figure 9. In other words, participants who showed a larger grip effect on threshold were not the participants who showed a larger effect on metacognitive efficiency.

Discussion

The present study examined how grip-induced arousal affects perceptual and metacognitive performance in older adults across auditory and visual modalities. We found that high grip was associated with both higher perceptual thresholds (but not slope) and metacognitive efficiency, but that these effects did not covary.

These findings address our three research questions. First, regarding whether trial-by-trial arousal modulation affects perceptual performance in older adults, we found that psychometric thresholds increased significantly, but not slopes, nor reaction times. This pattern is consistent with a shift in response criterion; in this case, setting a more conservative criterion to responding "different" to the comparison stimuli. Therefore, this result was not consistent with the previous finding of a hand grip manipulation imposing dual-task costs in older adults (Azer et al., 2023), nor with the finding that brief arousal speeds perceptual processing (Haupt et al., 2018 , Mather et al., 2020). Broadly, the criterion shift found in the current study is consistent with Allen et al.'s (2016) finding that arousal can shift response bias independently of perceptual sensitivity, though the specific mechanism driving the conservative criterion in the present study remains unclear.

Second, for the effect of grip level on metacognitive efficiency, we observed an unexpected pattern: high grip enhanced rather than impaired metacognitive efficiency. This contradicts the prediction derived from younger adult studies (Allen et al., 2016; Hauser et al., 2017) and suggests that age-related differences in the LC-NE system may alter how arousal affects metacognitive monitoring. Visual inspection of confidence ratings across stimulus levels in the auditory task revealed that this enhanced metacognitive efficiency during high grip trials appeared to be primarily driven by increased error awareness rather than increased confidence in correct responses (Figure 6d). Specifically, participants gave consistently lower confidence ratings to incorrect trials during high grip compared to low grip conditions during the easiest stimulus level, while confidence ratings for correct trials remained relatively similar across grip levels. However, this pattern only appeared to be present in the auditory but not the visual task. Despite the opposing effects found in perceptual threshold and metacognitive efficiency, the per-participant high-low grip differences for threshold and 𝑃 ̅ 2,𝑡𝑦𝑝𝑒-2 𝐴𝑈𝐶 were not significantly correlated, indicating opposing average effects without evidence of a trade-off across individuals. A key next step to test this interpretation would be to relate the behavioral effects reported here (high-low grip differences in thresholds, slopes, and 𝑃 ̅ 2,𝑡𝑦𝑝𝑒-2 𝐴𝑈𝐶 ) to independent measures of arousal and LC function that we collected, including changes in pupil size, measures of LC integrity, and measures of fMRI BOLD activity, including functional connectivity of auditory and visual regions with the LC.

Lastly, both perceptual and metacognitive grip effects were numerically larger in the auditory domain, with the auditory threshold effect being individually more robust than the visual effect. However, the grip × task modality interaction did not reach significance for either threshold or metacognitive efficiency, so a firm conclusion about modality-specific differences is not warranted by these data.

A key limitation lies in the number of trials required to accurately estimate a psychometric slope. Slope can often require orders of magnitude more trials compared to threshold to estimate accurately. For the method of constant stimuli design, 400 trials have been suggested as a target for accurate estimation (Kingdom & Prins, 2016). The present study's trial counts per grip level (75) fall substantially below this benchmark, and therefore, the lack of significant effects related to slope estimates should be interpreted with caution, as the present design may have been insufficiently powered to detect true slope differences.

Conclusion

High hand grip during auditory and visual same/different tasks raised perceptual thresholds and improved metacognitive efficiency, while having no effect on response time. To the extent that high hand grip is inducing arousal, this suggests that for older adults, arousal may hinder fine perceptual discrimination but improve metacognitive efficiency. These effects did not covary across individuals.
