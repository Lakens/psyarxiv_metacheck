How Power Analysis Check works

This module uses regular expressions to identify sentences that contain a statistical power analysis. If specified by the user, it also uses a large language model (LLM) to extract information reported in power analyses, including the statistical test, sample size, alpha level, desired level of power, and magnitude and type of effect size.

The Power Analysis Check module uses regular expressions to identify sentences that contain a statistical power analysis. Without the use of an LLM, the module uses regular expressions to classify the power analysis as a-priori, sensitivity or post-hoc. With the use of an LLM, it checks if the power analysis is reported with all required information.

The regular expressions can miss power analyses, or fail to classify them correctly. The type of power analysis is often difficult to classify, which can easily be solved by explicitly specifying the type of power analysis as ‘a-priori’, ‘sensitivity’, or ‘post-hoc’. Note that ‘post-hoc’ or ‘observed’ power is rarely useful. The LLM can fail to identify information in the paper, and will not have access to information in paragraphs in the paper other than those that contain the word ‘power’. This package was validated by the Metacheck team on articles in Psychological Science.

How StatCheck works

Check consistency of p-values and test statistics

The Statcheck module runs Statcheck. Statcheck searches for regular expressions that match a predefined pattern, and identifies APA reported statistical tests. More information on the package can be found at https://github.com/cran/statcheck. The module only returns Statcheck results for t-tests and F-tests, as these are the only tests which have been validated, see https://osf.io/preprints/psyarxiv/tcxaj_v1/.

Statcheck was developed by Michèle Nuijten and Sascha Epskamp.

Statcheck considers p = 0.000 an error, as you should report p < 0.001. Furthermore, p < 0.03 is an error if the p-value was 0.031, and one should simply report exact p-values (p = 0.031). When the sentence of a test says it is one-sided (“one-tailed”, “one-sided” or “directional”), a p-value that fits a one-sided test counts as consistent (statcheck’s OneTailedTxt setting; #695). When the paper says anywhere that its tests are one-sided, a p-value that fits a one-sided test in either direction counts as consistent too: half the two-sided p, or 1 minus that half for an effect against the predicted direction. Equivalence tests (TOST) are left out, as their p-values do not test the difference. A statistic written with “<” or “>” is read as a bound, and in a sentence about equal variances an F-test’s two-sided p (twice the one-tailed p) counts as consistent. For more information, see StatCheck.

This module only checks statistical results reported in the running text of the manuscript. It cannot (yet) process statistics reported only in tables.

This module was developed by Daniel Lakens and Lisa DeBruine

How Exact P-Values works

List any p-values reported with insufficient precision (e.g., p < .05 or p = n.s.), reported as exactly zero (e.g., p = .000), or impossible (below 0 or above 1, e.g., p = -.22).

This module uses regular expressions to identify p-values. It will flag any values reported as p > ? or p < numbers greater than .001. It will also flag p-values reported as exactly zero (e.g., p = .000, p = 0.00), which are mathematically impossible — p-values are never exactly zero and should instead be reported as p < .001.

A p-value that is not the result of a test is not flagged: a table note (“* p < .05, ** p < .01”), a figure legend (“Asterisks indicate significant differences (p < .05)”, “Values in bold are significant at p < .05”) or a stated threshold (“p < .05 was considered significant”, “thresholded at p < .001”). GROBID often puts such notes into the running text, so each p-value is judged by the words in its own clause (the text up to a “;” or a full stop), and never left out when a test statistic belongs to it (“F(1, 7) = 8.03, # p < .05”). The column not_a_test of the table says why a p-value was left out (“marker”, “threshold”, “legend” or “named”).

A p-value with the name of a correction or a test after the p (“pFWE < .05”, “padj < 0.05”, “p Wilcoxon = .02”) is flagged only when a test statistic comes before it in its clause (“t(37) = 7.17, p FWE < .05”). Without one it is mostly the rule that decided what was significant (“genes with padj < 0.05 were selected”); such a p-value is “named” in not_a_test. Notes in other forms, such as a marker after the p-value (“p < .05 (*)“), are still flagged.

A p-value below 0 or above 1 is impossible; it is listed apart and not also as imprecise. Often the statistic before it, or its minus sign, was copied into it (“t(134) = -2.32, p = -.13”, “Z = 3.091, P = 3.091”). A value above 1 is listed only after a test statistic in its clause: without one, a “P” above 1 was nearly always another quantity (a proportion, pH, a group’s mean, a model parameter). A number in scientific notation whose power of ten was lost when the PDF was read (“p = 2.4 x 10 -9” read as 2.4) is not listed. A “p” that is the subscript of another symbol (“r p = .64”, “²p = .02” for partial eta squared, “Δp = .33”), or a quantity with a unit, a logarithm or a ratio (“P = 2.9 µm”, “-log10 P = 7.5”, “Ca/P = 1.67”), is not read as a p-value at all (see extract_p_values()). Each p-value has its own row, also when the same one is written twice in a sentence.

This module sometimes flags false positives when sentences discuss how p-value thresholds were set. It can also miss an imprecise p-value that is reported against a threshold (“decreased at the p < .05 significance threshold”).

This module only checks p-values reported in the running text of the manuscript. It cannot (yet) process p-values reported only in tables (as opposed to a table’s footnote text, which the module does see and tries to exclude — see above).

How Repository Check works

This module retrieves information from repositories.

The Repository Check module lists files on the OSF, GitHub, ResearchBox, DSpace (PsychArchives and other legacy- and DSpace 7-based installations), Zenodo, Dataverse, Figshare, Dryad, ReShare, 4TU.ResearchData, Mendeley Data, DataONE (Arctic Data Center, KNB, and other member nodes), and LDbase based on links in the manuscript.

A link to a file-sharing service (Google Drive, Dropbox, OneDrive, Box, WeTransfer, MEGA, iCloud Drive, Baidu Netdisk, SURFdrive; see [file_share_links()]) gets a warning and makes the light yellow: such services are not repositories, as files can be changed or deleted at any time, get no DOI, and the link stops working when the account is closed. The report advises a stable repository such as Zenodo instead. Their files are not read, and summary_table$file_share_n counts the links.

Deposits in archives for sequence and expression data (GEO, the INSDC archives BioProject, SRA, ENA and DDBJ, and ArrayExpress; see [seq_archive_links()]), mostly named by accession number, are read for whose deposit they are. The authors’ own are listed with what they hold ([seq_archive_size()]) and are not downloaded or checked as data and code; summary_table$archive_own_n counts them.

R packages on CRAN ([cran_links()], [cran_info()]) are the paper’s own when a paper author is a package author and the paper presents the package; the paper’s own are listed with their version and not checked (summary_table$cran_own_n). A Handle link (hdl.handle.net/...) that leads to a repository read here is checked as a link to that repository ([handle_links()]).

Listing a repository’s files never requires an API key, but some hosts answer faster or more completely with one: OSF allows 100 requests/hour unauthenticated versus 10,000/day with a token (see [osf_pat()]), and Dryad enforces a strict per-IP daily quota on repeated listing (see cache below). Dryad is a special case beyond rate limits: listing a Dryad dataset’s files works without a key, but actually downloading file CONTENTS from Dryad fails with HTTP 401 unless a key is set, even for a fully public dataset (see [dryad_pat()] or [dryad_auth()]). Since this module only lists files and never downloads their contents itself, that limitation applies to data_check and code_check (which do download content), not here – see their own documentation.

When a linked OSF page is a registration, its registered_from project (the one it was registered from, which the manuscript itself may never link directly) is also checked: if that project is public its files are listed under its own URL, and if it is closed or otherwise inaccessible the report flags it explicitly, since some registrations only describe their content rather than mirroring it.

Whose deposit is each link? The ownership table gives, for every repository linked in the text and (with references = TRUE) every deposit cited in the reference list, one of six labels: own_this (made by the authors for this paper), own_earlier_data or own_earlier_code (the authors’ own, from earlier work), others_data or others_code (made by other people, reused here), or not_data (a publication such as a preprint, not a deposit), with ownership_group (“own”, “others”, “not_data”) and the reason. It is decided without a language model, from the sentence or reference that cites the link, the paper’s authors (names, ORCID iDs, affiliations), and what the deposit’s own record and files say (who made it, what it names, when, whether it is a software package; for an OSF project cited only in the reference list, its record alone). On a round of labelled links the rules had not been written from, the three groups were right for 98% of links in the main text (93 of 95) and 90% in reference lists (74 of 82); the labels were made by Claude agents from each link’s evidence, and disputed ones checked against the deposits. Telling this paper’s own deposit from the authors’ earlier one is less certain.

Only the deposits that are this paper’s own are checked. A deposit linked in the text that holds other people’s work (others_data, others_code) or the authors’ earlier work (own_earlier_data, own_earlier_code) is listed in the report, with the reason, but its files are left out of table and kept in table_not_checked: they count toward nothing here (files that do not belong in a repository, naming, READMEs, studies, the traffic light), and code_check, data_check and reproducibility_check, which read table, do not check them either. reproducibility_check still puts the files of theirs that the paper’s code names in the folder the code runs in, as a re-analysis needs the data it re-analyses. When every linked deposit is set aside, the traffic light is “na”. A deposit that is the paper’s own is counted as such when its README, title or description names the paper (its title or DOI).

How Code Check works

This module retrieves information from repositories checked by repo_check about code files (R, Python, SAS, SPSS, Stata, Mplus, MATLAB).

The Code Check module checks R (also R Markdown and Quarto), Python (also Jupyter notebooks), SAS, SPSS, Stata, Mplus, and MATLAB files, using regular expressions to check the code; JASP files are listed but not read. The language of a Quarto document or a notebook is read from the file itself (its engine or kernel), not from its extension. The regular expression search will detect the number of comments, the lines at which libraries/imports are loaded, attempts to detect absolute paths to files, setwd() and install.packages() calls, and lists files that are loaded, and checks if these files are in the repository; R code is also parsed. The module will return suggestions to improve the code if there are no comments, if libraries/imports are loaded in lines further than 4 lines apart, if files that are loaded are not in the repository, if absolute file paths, setwd() or install.packages() are found, and if R code cannot be parsed.

The regular expressions can miss information in code files, or falsely detect parts of the code as a fixed file path. Libraries/imports might be loaded in one block, even if there are more than 3 intermittent lines. The module was tried out internally on papers published in Psychological Science, but has not been formally validated. There might be valid reasons why some loaded files can’t be shared, but the module can’t evaluate these reasons, and always gives a warning.

The module also checks whether the repository pins the R/package versions the analysis actually depended on: an renv.lock file (parsed for the R version and every locked package + its version/source), a sessionInfo()/sessioninfo::session_info() text dump (matched by filename — sessionInfo.txt/session_info.txt and similar, or embedded in a README), or a groundhog::groundhog.library()/checkpoint::checkpoint() date-pin call in the code (a bare library(groundhog)/library(checkpoint) does not count — the pinning call itself must be present). When none of these is found, the report flags it as a reproducibility gap: package versions may drift between when the analysis was run and any later reproduction attempt.

If you want to extend the package to perform additional checks on code files, or make the checks work on other types of code files, reach out to the Metacheck development team.

Checking code requires downloading its file contents. For a paper whose repository is on Dryad, this never succeeds unless a Dryad API key is set: Dryad requires one to download file bytes, even from a fully public dataset (listing the repository’s files does not need one). Without a key, every Dryad-hosted code file is listed but unchecked, and a warning naming Dryad and ?dryad_pat/?dryad_auth is included among the download failures recorded in the manifest.

How Data Check works

This module classifies the files in a repository into semantic types (data, codebook, code, software, output, supplemental, readme, asset, other) and, for tabular data files, extracts each column’s type and summary statistics.

The Data Check module consumes the file list produced by repo_check (or any files added via local_path). Each file is classified with rule-based heuristics layered over metacheck’s file_category() and file_types: file names matching README / codebook patterns win first, then an extension crosswalk, then format-locked extension overrides. For every file classified as tabular data that is available locally, the module reads the file head, describes each column with data_col_facets() and computes summary statistics for numeric columns. Every sheet of a spreadsheet that holds a table is read: a file with several such sheets has its columns under source_file = "file.xlsx [sheet]", and the sheet column names the sheet of any spreadsheet with several sheets; a sheet of notes or a codebook is treated as documentation when the file has another table. Following DDI, a column is described by orthogonal facets rather than a single type: representation (numeric/text/datetime/code — how it is stored), measurement_level (Stevens: nominal/ordinal/interval/ratio), concept (what it measures: reaction_time/age/gender/likert/id/…), role (identifier/measure/condition/timestamp), unit, and a quality state (ok/empty/constant). Concepts are detected by name+value rules (the demographic concepts via data_check_demographic()); when llm_use(TRUE) the model fills concepts and measurement levels the rules left blank. Qualtrics survey exports are recognised (data_check_is_qualtrics()): their extra header rows are stripped so columns type correctly, and the reserved response-metadata columns (StartDate, Duration, Finished, …) are tagged.

The module defaults to rules-only when llm_use(FALSE): columns the rules cannot resolve (ambiguous 3–20-unique integers, ambiguous character columns) fall back to continuous / text respectively. When llm_use(TRUE), ambiguous columns and unresolved file types (other) are sent to llm() for optional refinement, and every file is assigned a study group (ex1, pilot2, shared, …) so that multi-study repositories can be recognised (used by psychds_check). Without an LLM the study group is left NA (unknown).

Column extraction requires files to be readable from disk. Files fetched by repo_check from OSF/GitHub/etc. without a local copy (file_location is NA) are classified but not column-extracted; pass local_path to point at a downloaded copy of the repository.

For a paper whose repository is on Dryad, this means column extraction never happens unless a Dryad API key is set: Dryad requires one to download file bytes, even from a fully public dataset (dataset listing and metadata do not need one). Without a key, every Dryad file stays classified but un-downloaded, column_n is 0, and a warning naming Dryad and ?dryad_pat/?dryad_auth is included among the download failures. A one-time session message is also shown (see repo_check) the first time a Dryad dataset is encountered with no key set.

Every downloaded text file the authors wrote (code, settings, survey definitions such as Qualtrics .qsf files, documentation, outputs) is searched for keys: API keys, access tokens and private keys, which let anyone who downloads the file use a paid service at the authors’ cost. Of a tabular data file only the column names and first 3 rows of the table as read are searched: its values come from participants, but a key the authors set for a whole survey (as embedded data in a Qualtrics survey flow) is exported in every response. The search uses the rules of the secret scanner betterleaks (https://github.com/betterleaks/betterleaks, MIT licence) of high and medium confidence. A key found turns the traffic light red; the report and the keys table give its file, line and type, and only its beginning. Other files over 25 MB and binary files are not searched. A key is never tested with its provider. Every module’s result has any whole key replaced by “keyremoved” (see module_run()).

How Reproducibility Check works

This module assesses whether a paper’s R and Python code can be run on its data. It works in two phases. The static phase (always run) collects the package dependencies the code declares, rewrites the data-file paths that do not work in the repository as the authors organised it, works out the order the scripts must run in, and diagnoses why any referenced input file is unavailable — reporting what a reproduction attempt would involve and where it is likely to break. The execution phase (opt-in, execute = TRUE) then actually runs the code: it copies the repository into a throwaway directory, optionally installs the declared dependencies into a throwaway library, runs each script in order in an isolated subprocess with a per-script timeout, and captures the outcome and full output of each run.

By default (execute = FALSE) the module does not run any code — it performs only static analysis: reading dependencies with the same extractors as code_check, finding the files the code references in the repository, and building a run-order dependency graph. It reports what would be installed and run rather than doing it.

When execute = TRUE, the module additionally runs the downloaded code on your machine — a deliberate, opt-in action gated behind that argument (callr is required for R code). Each script runs in an isolated subprocess so a crash cannot take down the R session; note this isolates crashes, not the filesystem or network. Installs (when install_missing = TRUE) and the throwaway run library never touch your main R library. Each script’s outcome is one of ran_ok, errored, timed_out, dependency_unavailable, not_parsed, run_by_source (an R script another script runs with source(), which is run only inside that script, since on its own it lacks the packages and objects the sourcing script sets up first), run_by_import (a Python file other files import, a module rather than a script, unless it has an if __name__ == "__main__": block), jags_model (a JAGS or BUGS model saved with an R extension, which another script reads) or not_r_content (a file that is not R at all, such as a JSON or HTML dump); these last two are not run and are not failures. python2 marks Python 2 code that was not run. With sandbox = "docker" such code runs with Python 2.7 (option metacheck.docker_image_py2; FALSE turns this off), which modifications records; it is never converted, since that can change results. defines_functions is a file that only defines functions, which is used, not run (table$used_by names the scripts that use it), and not_analysis is a file of software rather than of the analysis: a package’s code, tests, documentation or setup.py, a copy of a tool, a web application, a script a program wrote (table$not_analysis_why says which); neither is run or counted as a script. docker_failed means the container never started, which says nothing about the script, so it keeps the light from being green but does not make it red. needs_a_person is a script that stopped because it asks a person to choose a file or answer a question, or that starts an app, and needs_internet one that stopped because the network is off in a Docker run, or, with internet = TRUE, could not reach what it asked for; download_too_large is a script stopped for downloading more than the limits allow (see internet), and out_of_memory one that, or a program it started (such as a compiler), ran out of the memory each script may use. All four are treated the same way. not_downloaded is a script that stopped on a file the repository lists but that was not downloaded, such as one over max_file_size: it could not be tried, so it is not counted as a script that did not reproduce (summary_table$repro_not_downloaded_n counts them apart). not_read is a file metacheck could not read, so it was not run; the light is then not green, as the file may read and run on another computer, and table$error_message says why, naming a package that is installed but cannot be loaded on the computer that ran the check. empty is a file with nothing in it, which is not run or counted as a script. For a script that did not run through, table$error_message is its error, short (at most 300 characters): the error line of its output, which names a package that is not there, with the address it asked for when it needed the internet, or the time limit it reached; table$reason sorts it into a kind. A timeout means “still running at the cutoff”, not a failure, so raise timeout for legitimately long-running (e.g. Bayesian) scripts. dependency_unavailable means the script’s own package could not be installed from live CRAN, the CRAN Archive, or a named GitHub/URL source — an infrastructure limitation, not a defect in the paper’s code. The full stdout/stderr of every run is kept in the result’s run_results (the report shows it in per-script dropdowns, capped for readability).

Provenance, kept so that a TRACE Research Object (TRO) declaration of the run can be written later from a stored result (metacheck #404; the helpers are in R/provenance.R). Only when code was run (execute = TRUE): * run_results$started_at, run_results$ended_at: when each run of a script started and ended (ISO 8601, UTC, milliseconds); NA for a script that was not started. A script run again in a later pass has the times of its last run. A TRO uses them for each trov:TransparentResearchPerformance. * run_results$exit_status: the exit status of the process that ran the script (0 = ended normally); NA when the process did not report one (a time limit, or Docker failing to start the container). * artifacts: one row per file, with stage (deposit: as downloaded from the repository, hashed from the downloaded file; before_run: the run folder just before the first script ran, after metacheck’s own changes, such as rewritten paths and unpacked archives; after_run: only the files the scripts made (status new), changed (changed) or removed (removed), as an unchanged file is the one listed before the run), path (relative to the run folder, as valid UTF-8, a byte of another encoding written as <xx>), size (bytes), sha256, mime_type (by extension, NA when unknown), source (the file’s address in the repository, for deposit). The package libraries metacheck installs in the run folder are left out, as are metacheck’s own files there (a script’s runner, and the statistical output it writes in statistical_output/). Files metacheck itself copied or made between passes (see modifications, output_copied, file_placed) show in after_run too. A TRO uses the rows as trov:ResearchArtifacts and each stage as a trov:ArtifactArrangement. * modifications$sha256_before, modifications$sha256_after: the hash of the changed script as downloaded and as it ran; NA when the script is not at the same path in both (a script made from an R Markdown file). * environment: the system that ran the code (trov:TransparentResearchSystem in a TRO): metacheck_version, started_at, ended_at, host (R version, platform, operating system), sandbox, network_isolated (TRUE only when every Docker run had --network none; the process sandbox does not stop the network), internet, timeout_per_script, total_timeout, python_local (the Python run outside Docker and its version), and docker: runs (for each kind of run, r_run, r_install, python_run, python_install, the image and the docker run arguments, such as --network none, --read-only, --cap-drop ALL, no-new-privileges, the process limit and the memory and processor limits) and images (for each image, its ID and digests from docker image inspect, its creation time and the R and Python versions its environment declares).

run_results$checked says what the run of each script shows about the code, in five groups, so that a script that does not reproduce is kept apart from one the check could not test: ran (it ran to the end); code_error (it did not reproduce: it stopped with an error of the code or the deposit, could not be read, or needs a file the deposit does not hold); dependency (a package or program was not available: a package that could not be installed or was not loaded, a program outside R and Python, a system library, or R crashing in a package’s compiled code); time (it did not finish within the time limit for one script, or was not started because the time for all scripts had run out); and not_checkable (it could not be checked automatically: it needs a person, the internet, a key or another setting of the authors’ computer, one platform such as Google Colab, Windows or OpenSAFELY, more memory than the run allows, a file that was not downloaded, a screen, or a program that runs it, or it is a file of a package of the code that Python runs only as a module of that package). It is NA for files run inside another script, files that are not an analysis, files not read, and a Docker failure. summary_table counts each group (repro_ran_n, repro_code_error_n, repro_dependency_n, repro_time_n, repro_not_checkable_n), and the report’s first sentence gives them. The traffic light reflects the static readiness signals by default; a script in code_error that stopped with an error makes it red, as a script that crashes on its own analysis is a genuine reproduction failure, and a script in one of the other three groups keeps it from being green. Calls that need a screen, which the run does not have (dev.print(), dev.copy2pdf(), dev.copy2eps(), savePlot(), windows(), win.graph(), x11(), quartz(), View()), are replaced before the run by calls that need none, which modifications records as screen_call_replaced. A script that fails with could not find function is run once more with the library() calls the project’s other scripts make added at its top (or the one package that exports the function, or magrittr for %>%), and a script that then runs is reported as reproducible only after that repair.

Dependencies are reported name-only, with the source (CRAN, GitHub, or a base package already shipped with R) — static analysis of the code cannot know which version was used, and running against current package versions is itself informative: a break argues the authors should have pinned versions. When the repository does record versions, a run with recorded_versions = TRUE installs the packages the scripts load at those versions, but it does not change the R version, which remains a limitation of the check.

Run order is derived from read-after-write data dependencies (a script writing a file another reads must run first), source() edges, and numeric filename prefixes as a weak tie-breaker. Ambiguous orderings, dependency cycles, and inputs a script reads but that no earlier script produces (and that are not in the repository) are surfaced as warnings, since these are the situations most likely to make an otherwise-correct reproduction fail.

Python code (.py files, and notebooks and Quarto documents whose code is Python, from which the code is extracted first) goes through the same two phases, reported in its own “Python code” section. Each file is checked for syntax errors with Python’s own parser when a Python interpreter (python, or else python3) is available; dependencies are read from the import statements, with versions from a requirements.txt or pyproject.toml when there is one, and installed with pip; each script runs as its own python process (processx is required), so unlike R scripts, a name one script defines is not available to another. When no Python interpreter is available, the Python files are reported as not run and the R results are still returned. Statistics the Python scripts print are compared with the paper together with the R output and any self-reproducible output (JASP/jamovi, SPSS-Viewer, notebook outputs).

Abstract

Does the target of speech shape public support for hate speech laws? Regulating hate speech is controversial, partly because partisans are assumed to disagree over which groups such laws should protect. This article conducts a comprehensive test of how support for hate speech laws varies across partisan lines when speech targets ethnic, religious, gender, or political groups.

Based on conjoint experiments in Denmark and the United States, the results show that support for regulation increases by up to 32 percentage points when severity increases from "incivility" to "incitement to violence." Target characteristics increase support for regulation by up to 6.3 percentage points and exert the strongest effects when speech targets ethnic and religious groups rather than gender or political groups. These effects persist when severity is held constant and are broadly stable across severity levels. They are also heterogeneous across partisan groups, mostly ranging from 3 to 7.2 percentage points, with one exception reaching 11.9 percentage points. In neither country are partisans more willing to regulate hate speech targeting their political opponents than hate speech targeting their political allies. Overall, severity has the strongest effect on support for hate speech regulation, while target characteristics have smaller, heterogeneous effects that are largest when speech targets ethnic or religious groups.

Introduction

Does the target of speech shape public support for hate speech laws? Countries around the world are introducing laws that restrict hate speech (Parekh, 2012, p. 37) directed at groups based on target characteristics such as ethnicity, religion, and gender (Sellars, 2016, p. 25). Public opinion polls often indicate that partisans are polarized on restricting hate speech (Ekins, 2017, p. 14; Knight Foundation, 2024, p. 24; Poushter, 2015; Skaaning & Krishnarajan, 2025, p. 31).

Nevertheless, existing evidence often relies on questions that do not make it possible to distinguish whether support for hate speech restrictions depends on whom the speech targets or on how severe it is.

To make valid inferences about public opinion on restrictions of civil liberties, scholars have recommended using a concrete context instead of abstract questions (Gibson & Gouws, 2001 , pp. 1067 -71, 1074; Petersen et al., 2011, pp. 581-85). This may be particularly important in the context of hate speech, as people can have different perceptions of what it is. As noted by Gagliardone et al. (2016, p. 7), "hate speech continues largely to be used in everyday discourse as a generic term, mixing concrete threats to individuals' and groups' security with cases in which people may be simply venting their anger against authority." Thus, a central challenge in measuring support for hate speech laws is to separate the target of the speech from its severity.

Yet while hate speech laws have sparked considerable controversy (Howard, 2019, p. 94), empirical evidence on the extent to which ethnic, religious, gender, or political target characteristics shape people's support for such laws is limited.

The article addresses this shortcoming using two large conjoint experiments fielded in Denmark and the U.S., which make it possible to separate the effects of speech severity and target characteristics on support for regulating hate speech. The design also permits an assessment of whether and to what extent specific target identities influence support for hate speech laws across partisan divides. Moreover, it extends existing work by systematically testing the most salient target characteristics. In short, this article conducts a comprehensive, crossnational test of how targeting people based on ethnicity, religion, gender, and political affiliation affects support for hate speech regulation.

The results show that severity and target characteristics have independent effects on support for hate speech regulation. Support for regulation increases by up to 32 percentage points in Denmark and 31 percentage points in the U.S. when severity changes from incivility to incitement to violence. The target of hate speech also affects support for regulation, although to a lesser degree. On average, support for hate speech regulation increases by up to 6.3 percentage points in Denmark and the U.S. The effects of target characteristics are strongest when hate speech targets ethnic or religious groups rather than gender or political groups, and the effects are broadly stable across levels of severity. Support for hate speech regulation also varies across partisan groups, as target characteristics have larger effects for some partisans when hate speech targets religious or ethnic minority groups. Among partisans, target characteristics affect support for hate speech laws by 3 to 7.2 percentage points, with one exception: among left-wing respondents in Denmark, support for regulation increases by 11.9 percentage points when statements target Muslims. Although the effects of target characteristics vary across partisans, the results also suggest substantial overlap in the extent to which target characteristics influence partisans' support for hate speech laws in the U.S. and Denmark.

The article also speaks to concerns about the adverse consequences of polarization in the U.S. Previous research shows that partisans can engage in selective censorship (Ashokkumar et al., 2020; Dias et al., 2025; Kubin et al., 2025; Lelkes & Westwood, 2016). This article finds little evidence that these preferences extend to hate speech restrictions, as partisans were neither more nor less willing to regulate hate speech targeting political opponents, allies, or people supporting particular political viewpoints.

Measuring Support for Hate Speech Restrictions

Hate speech laws are increasingly being introduced (Parekh, 2012, p. 37). According to Howard (2019, pp. 95-96), hate speech refers to "particular expressions of hatred against particular (groups of) people in particular contexts" on the basis of characteristics such as race, ethnicity, or religion (Sellars, 2016, p. 25). Yet hate speech is a broad and contested term that "continues largely to be used in everyday discourse as a generic term, mixing concrete threats to individuals' and groups' security with cases in which people may be simply venting their anger against authority" (Gagliardone et al., 2016, p. 7).

Scholars have highlighted the importance of assessing support for speech restrictions based on concrete judgments rather than abstract questions (Gibson & Gouws, 2001 , pp. 1069 -71, 1074). However, much existing evidence relies on measures that do not specify the level of severity and conflate multiple minority groups. For example, prior studies ask about speech that is "harmful or offensive to" (Doré et al., 2022), speech that "attacks people based on [characteristics]" (Knight Foundation, 2024), or speech that "offend[s] certain minorities or religious groups" (Chong et al., 2024, pp. 141-43; McClosky & Brill, 1983). Such measures therefore do not make it possible to isolate the effect of whom hate speech targets from the effect of its severity. As an illustrative example, a public opinion survey by YouGov and the Cato Institute compared support for hate speech laws across multiple ethnic and religious groups among partisans in the U.S. (Ekins, 2017, p. 14). Respondents in an American sample were asked, "Would you favor or oppose a law that would make it illegal to say offensive or insulting things in public about [African Americans/Christians/Muslims/White people]?" The results show partisan differences between Democrats and Republicans depending on the target of the offensive or insulting statements. Likewise, Chong et al. (2024, p. 143), using a measure from McClosky and Brill (1983), found that conservatives are more tolerant than liberals of offensive speech targeting minorities and women but less tolerant of "unpopular or controversial left-wing opinions and ideas on nonracial topics" (Chong et al., 2024, pp. 141-43). Overall, existing research suggests that partisans differ in their support for speech restrictions, but the extent to which this support depends on the target of the speech or on how severe it is remains unclear.

The importance of separating severity from target characteristics is highlighted by previous public opinion research in other domains. Research on affective polarization (Druckman et al., 2022; Klar et al., 2018) and support for political violence (Westwood et al., 2022) has shown that reliance on abstract questions can lead to misleading inferences about public opinion. For example, Westwood et al. (2022) demonstrate that when researchers "ask about general support for violence without offering context, [the researchers] leave the respondent to infer what 'violence' means," which results in misleading inferences. Similarly, general questions about banning "offensive" language without specifying context or level of severity may complicate inferences about whether people support hate speech regulation because of its severity or its target. These challenges underscore the value of research designs that separate the effects of severity and target characteristics to yield credible inferences about public support for hate speech regulation. This article does not provide an empirical test of whether respondents presented with generic survey questions infer different levels of severity depending on the target group; this potential mechanism is beyond its scope. The aim is instead to separate the effects of speech severity and target characteristics on support for hate speech regulation.

Public Opinion and Hate Speech Regulation

Drawing on the literature, I outline three predictions about public demand for regulating hate speech. First, the severity of the speech matters; when severity increases, people are more supportive of regulating it. Second, the group being targeted matters; people may be willing to restrict hate speech directed at vulnerable or historically marginalized groups (e.g., racial or religious minorities). Third, popular support for hate speech regulation may be shaped through a partisan lens, such that partisans are more supportive of regulating hate speech directed at groups they sympathize with or believe deserve protection. I address these three accounts in turn.

Severity is a key feature in definitions of hate speech. Although there is no single definition of online hate speech (Article 19, 2015; Siegel, 2020, pp. 56-57), it generally portrays a group negatively and may range from offensive speech to threats and incitement to violence (Alkiviadou et al., 2020; Rossini, 2019; Siegel, 2020). The International Covenant on Civil and Political Rights (ICCPR), adopted by the United Nations General Assembly in 1966, stipulates that "any advocacy of national, racial or religious hatred that constitutes incitement to discrimination, hostility or violence shall be prohibited by law" (ICCPR, 1966). Some types of hate speech may be lawful but still raise concerns about intolerance and discrimination, while other types of speech, such as dehumanization and degradation, can be unlawful (Article 19, 2015; Mchangama et al., 2021).

Empirical evidence also documents the effect of severity on public support for content moderation (Ashokkumar et al., 2020; Kozyreva et al., 2023; Pradel et al., 2024; Solomon et al., 2024), crowd moderation (Wilhelm et al., 2020), and regulation (Munzert et al., 2025). Perceived threat is a crucial factor when people judge whether statements are acceptable (Davis & Silver, 2004; Gibson, 2011; Marcus et al., 1995; Petersen et al., 2011). Most people perceive threatening statements and harassment as unacceptable in political discussions (Stryker et al., 2016), and Skytte (2022 Skytte ( , p. 1746) ) finds that while copartisans tolerate milder forms of incivility, "a limit exists beyond which the rhetoric becomes too extreme for even the base." Hypothesis 1: Severity increases support for hate speech regulation.

Hate speech laws are often introduced to protect social or demographic groups from harm (but see Mchangama, 2014), although which groups are legally protected from hate speech varies considerably across countries (for an overview, see Alkiviadou et al., 2020). Hate speech laws and content moderation policies on social media often protect groups based on race, ethnicity, or religion because they represent salient group markers within societies (Sellars, 2016, p. 25). As noted by Mchangama (2021, p. 20): "Given the long and bloody history of religious, ethnic and racial intolerance in Europe and the US, equality and non-discrimination are vital goods constituting cornerstones of liberal democratic societies. These fundamental principles are undermined when minority groups are subject to hatred and bigotry."

Evidence indicates that when people consider whether speech should be allowed, they often place considerable emphasis on the groups targeted. Recent evidence shows that people are more supportive of social media platforms removing hate speech targeting certain minorities and historically marginalized groups (Munzert et al., 2025; Solomon et al., 2024). Public opinion tends to emphasize racial, ethnic, and religious group markers in the regulation of hate speech. Chong et al. (2024) argue that there has been a "dramatic realignment in public tolerance of offensive expression about race, gender, and religious groups," suggesting that the public increasingly supports regulating hate speech targeting minority groups. Moreover, Eady and Rasmussen (2025, p. 1446) find that politicians and citizens "regard messages targeting women politicians as more toxic than otherwise equivalent messages targeting men." This suggests that target characteristics may play an important role in shaping public opinion on hate speech regulation.

People on the political left and right identify with different social groups (Finkel et al., 2020; Mason, 2018) and have different views of which groups are vulnerable to harm (Crawford, 2017; Gray & Kubin, 2024; Womick et al., 2024). For example, Democrats in the U.S. are more supportive of protecting minority groups (Chong et al., 2024, p. 143; Moore, 2015; Poushter, 2015; Skaaning & Krishnarajan, 2025, p. 31; Solomon et al., 2024, p. 4). In contrast, right-leaning partisans show greater opposition to hate speech prohibitions. Research Design

To study the factors shaping support for restricting hate speech, two conjoint experiments were fielded in the U.S. and Denmark. Conjoint experiments make it possible to disentangle the relative influence of multiple attributes (e.g., severity and target characteristics) of social media 3s on support for regulating hate speech (Bansak et al., 2021; Hainmueller et al., 2014). The causal quantity of interest in conjoint experiments is the average marginal component effect (AMCE).

The AMCE for each attribute is the marginal effect of seeing a particular attribute level in a statement, relative to the baseline, on the preference for restricting a statement, averaged across all other possible combinations of statement attributes (Hainmueller et al., 2014). For example, it allows researchers to estimate the average causal effect on support for hate speech regulation when the speech is directed at Muslims compared with Christians.

The conjoint experiments were fielded in two national samples in Denmark and the U.S.

The survey agency YouGov conducted 1,518 interviews in the U.S. and 1,535 interviews in Denmark between February 2 and 9, 2021. YouGov sampled from its internet panels and employed quota sampling to match population characteristics on age, gender, region, and education. All analyses use survey weights (see Section B in the appendix). Respondents were excluded if they did not answer the main outcome question in any task of the conjoint experiment (147 in Denmark and 110 in the U.S.). The final sample was 1,388 respondents in Denmark and 1,408 in the U.S. Preregistration, questionnaire, and other materials are available on the Open Science Framework: https://osf.io/7xvq6/overview.

Publics in Denmark and the U.S. generally support freedom of expression (Skaaning & Krishnarajan, 2025), but the two countries differ in two respects that are relevant to support for hate speech regulation. First, they differ in their legal frameworks for restricting freedom of expression, including hate speech (Bleich, 2014). Both countries restrict freedom of expression when expressions incite violence or imminent lawless action. However, below this threshold, Danish law is more restrictive of hate speech targeting certain characteristics (see Table S4 in the appendix for an overview). While U.S. law relies solely on the severity of the speech, Danish law is more closely aligned with the legal framework of the European Union. For example, at the time of data collection, section 266b of the Danish Criminal Code restricted speech by which "a group of people are threatened, insulted or degraded on account of their race, skin colour, national or ethnic origin, religious belief, or because of their sexual orientation" (Justitsministeriet, 2021).

However, in neither country were there restrictions on speech targeting groups based on political beliefs, disabilities, age, or social status. 3 Some theories argue that criminal laws primarily originate from a common set of intuitions of justice (Sznycer & Patrick, 2020), but an alternative perspective suggests that national variation in laws may reflect political culture and norms (Bleich, 2014, pp. 297-298). If the latter is the case, we should expect larger target effects in Denmark. Thus, using Denmark and the U.S. as cases provides an opportunity to study the alignment between public opinion and existing laws in different legal contexts.

Second, the U.S. is considered a polarized context (Iyengar et al., 2019). This study advances the extensive literature on the origins and consequences of polarization, including the relationship between polarization and partisan hostility (Amira et al., 2021; Iyengar & Westwood, 2015; Lelkes & Westwood, 2016; Westwood et al., 2022), by examining preferences for regulating hate speech against political, religious, gendered, or ethnic groups in countries with varying levels of polarization. For instance, if polarization matters for regulating hate speech, partisans should be less (more) restrictive when hate speech targets out-group (in-group) members. In sum, Americans likely live in a more politically polarized society with fewer restrictions on freedom of expression than Danes. Consequently, Denmark and the U.S. provide an opportunity to assess support for hate speech regulation across distinct legal frameworks and levels of polarization.

Stimuli

Table 1 shows a simplified version of the experimental setup (see Table S3 in Section A of the appendix for a detailed description of all attributes). Seven attributes were manipulated in the vignettes, and all were randomly assigned. The first four attributes in Table 1 were manipulated as text, whereas the latter three were incorporated into contextual elements such as the profile picture, the individual's name, and the nature of the conversation (public/private). All attribute levels had equal probability (uniform distribution) except for the ethnicity of the sender (majority/minority), as this attribute by definition entails an unequal real-world distribution. To better reflect the actual demographic proportions in the U.S. and Denmark, an 80/20 split was used (De la Cuesta et al., 2022).

The analysis focuses on two key attributes relevant to evaluating the hypotheses: (1) the severity of the speech and (2) the target of the statement. The severity of statements was manipulated by presenting participants with four types of hate speech through eight statements: (1) incivility, (2) degradation and dehumanization without a direct threat, (3) degradation and dehumanization with a threat, and (4) incitement to violence. 4 This conceptualization builds on past work on incivility (Druckman et al., 2019; Skytte, 2022), toxic speech (Eady & Rasmussen, 2025; Petersen et al., 2024), and content moderation (Munzert et al., 2025; Pradel et al., 2024; Solomon et al., 2024).

The hierarchical progression in severity also reflects definitions of hate speech in international and national legal frameworks (Article 19, 2015, pp. 18-22; United Nations, 2012, p. 13). Crucially, it makes it possible to separate the effects of severity and target characteristics across varying degrees of severity. Moreover, it enables testing whether variations in severity condition the effects of target characteristics (Druckman et al., 2019, p. 295).

Next, the target of the statement was manipulated. Specifically, groups were included along political lines (left-wing/right-wing), religion (Christian/Muslim), ethnicity (Black/White in the U.S., Danes/immigrants in Denmark), and gender (male/female), as these are central to legal and public understandings of hate speech (Alkiviadou et al., 2020, pp. 3-12; Howard, 2019, p. 95; Siegel, 2020, pp. 56-59).

Five additional attributes were included to mimic political posts on social media and to capture potential effects based on context, message, and sender. First, the target type was manipulated so that the statement targeted either politicians or voters. Previous research has examined perceptions of toxic behaviors such as incivility, intolerance, and hate speech directed at politicians (Eady & Rasmussen, 2025). Partisans have more negative feelings toward politicians of the opposing party than toward its voters (Druckman & Levendusky, 2019; Kingzette, 2021).

Varying the target type (politicians/voters) makes it possible to test whether citizens are more restrictive of hate speech toward voters than toward politicians.

Second, the valence of the targeted issue position (e.g., support for or opposition to affirmative action) was manipulated to make it possible to assess whether people selectively supported regulating ideas they disagreed with. Research shows that "supporters of a political cause (e.g., abortion or gun rights) preferentially censored comments that opposed their cause" (Ashokkumar et al., 2020, p. 1). Similarly, Crawford and Pilanski (2014, p. 849) found that "both liberals and conservatives were intolerant of those with whom they disagreed." If this is true, we should expect a person who supports affirmative action programs to be more restrictive when hate speech targets people who support such policies. Third, the gender and ethnicity of the sender were varied, as prior research suggests that these attributes can shape public evaluations of speech. For example, Eady and Rasmussen (2025, p. 1456) show how "toxic messages sent to a woman politician are deemed more toxic if it is sent by a user [who] is a man rather than a woman." Lindner and Nosek (2009, p. 86) find mixed evidence regarding Americans' willingness to restrict speech based on the speaker's ethnicity. To capture potential effects of sender characteristics, the study varied them using profile images and names that signaled the sender's gender and whether they belonged to an ethnic majority or minority. For the Danish experiment, profile images were drawn from the Oslo Face Database (Chelnokova et al., 2014), while the American experiment used images from the Chicago Face Database (Ma et al., 2015).

Fourth, the publicness of the statement was manipulated. Previous research indicates that public hate speech is perceived as more offensive and that speakers are held more accountable for public speech (Cowan & Hodge, 1996, p. 366). The present study therefore manipulated whether the statement was disseminated in a public social media post or a private message.

The number of attributes introduces complexity and potential threats to causal interpretation. For instance, estimated effects may be conditional on sender characteristics or the presence of issue positions. A series of robustness checks in the supplementary material demonstrates that the results hold across alternative specifications. These include re-estimating the main model while conditioning on sender ethnicity (Figures S3-S4), severity levels across partisanship (Figure S2), and profile position (Figures S6-S7), as well as excluding profiles with issue positions (Figure S5).

The study used a paired vignette design in which participants saw two social media posts at a time (Bansak et al., 2021; Hainmueller et al., 2015). The vignettes resemble typical content on social media platforms (Munzert et al., 2025). A limitation of the design is that it does not simulate a complete social media feed, which may affect its ecological validity (Mutz, 2011).

Measures

The main outcome of interest, support for hate speech regulation, was assessed using a rating outcome, which is among "the two most common measures of stated preference in political science applications of conjoint designs" (Bansak et al., 2021, p. 27). The main advantage is that a rating outcome enables estimation of the absolute level of support for restriction, unlike forced-choice designs, which only capture relative preferences. Participants were asked to respond to the following question: "Do you think that it should be legal or illegal to write the statement in [the U.S./Denmark]?" (see Figure 1). Response options included "Should be legal," "Should be illegal," and "Don't know." "Don't know" responses were excluded from the analysis.

Figure S18 in the appendix replicates the main results with "Don't know" coded as the midpoint on the scale (0.5). Bansak et al. (2021, p. 28) recommend eliciting preferences through multiple measures. Accordingly, three additional outcomes were preregistered: (1) a choice-based measure of perceived offensiveness ("Which of the two statements do you find most offensive?"), (2) a rating-based measure of perceived offensiveness ("On a scale from 1 to 7, where 1 indicates that the statement is not at all offensive and 7 indicates that the statement is extremely offensive, how would you rate [Statement A/Statement B]?"), and (3) a measure of perceived legality ("Do you think that it is legal or illegal to write the statement in [the U.S./Denmark]?"). All preregistered analyses related to these outcomes are reported in Figures S19-S20 in the appendix.

To measure partisanship, standard measures from the American (ANES) and Danish (DNES) National Election Studies were used. Based on answers to the question of whether participants saw themselves as supporters of a specific party, they were categorized as either Republican, Independent, or Democrat in the U.S. and either left-wing or right-wing in Denmark.

Respondents who did not report supporting or leaning toward a specific party were not included in the analyses of heterogeneous effects across partisan groups.

Results

The Effects of Target Characteristics I begin the analysis by separating the effects of target characteristics and severity on support for hate speech laws. To this end, I estimate the average marginal component effect (AMCE) of each target group and severity level. 5 Positive values indicate that a specific attribute level increases support for regulation (see Figure 2). On average, support for hate speech restrictions in Denmark and the U.S. increases by 3 to 6.3 percentage points when hate speech targets religious groups (Christians and Muslims) and ethnic minorities (Black people in the U.S. and immigrants in Denmark) relative to statements that do not mention an identity group. The largest effects of target characteristics in Denmark are observed for statements targeting Muslims, which increase support for regulation by 6.3 percentage points. In the U.S., hate speech targeting Black people increases support by 5.4 percentage points. In both countries, the second-largest target effects are for statements targeting Christians, which increase support for regulation by 3.5 (U.S.) and 3.4 percentage points (Denmark). These results suggest that the public is, on average, more supportive of hate speech laws when speech targets Muslims, Christians, and ethnic minorities.

Figure 2 also displays the effects of severity. It shows that, compared with incivility, threatening dehumanization or degradation and incitement to violence increase support for hate speech regulation by 25.3 and 32 percentage points, respectively, in Denmark and by 17.4 and 31 percentage points in the U.S. The overall pattern is that people primarily support regulating hate speech when it amounts to threats and incitement to violence, whereas they do not seem to differentiate between incivility and degradation or dehumanization that falls short of direct threats or incitement to violence. While statistically significant effects of target characteristics are in the range of 3 to 6.3 percentage points, we might expect target characteristics to have heterogeneous effects across partisan groups and levels of severity. In the following, I examine four plausible empirical patterns.

Are partisans more supportive of regulating hate speech targeting their political in-group or less supportive when it targets their political opponents? The results indicate that they are not. In Figure 2, the rows with "Democratic (Left-wing)" and "Republican (Right-wing)" provide evidence on this question. They show null effects for partisans in Denmark and the U.S. This suggests that partisans were neither more nor less likely to support hate speech regulation when it targeted their political allies or opponents than when no identity group was mentioned. These findings contrast with research suggesting that partisans selectively accept or oppose hostility conditional on its political motivation (Kalmoe & Mason, 2022; Lelkes & Westwood, 2016; Westwood et al., 2022). Thus, the findings provide no evidence that partisans distinguish between hate speech targeting their fellow partisans and the opposing party.

Are partisans more supportive of regulating hate speech targeting ethnic, gender, or religious groups they sympathize with? In Denmark, the effects of target characteristics are also heterogeneous: they are more pronounced among left-wing partisans, who are more supportive of hate speech restrictions when speech targets people based on religious, ethnic, and gender characteristics. Specifically, their support increases by 11.9 percentage points when hate speech targets Muslims, 7.2 percentage points when it targets immigrants, 5.4 percentage points when it targets women, and 5.2 percentage points when it targets Christians. In contrast, there are no statistically significant effects of target characteristics among right-wing partisans in Denmark. Overall, target characteristics have heterogeneous effects across partisan groups in both Denmark and the U.S.

Does the effect of target characteristics depend on the level of severity? The results suggest that it does not. Figure 3 shows the conditional effects of target characteristics. The left panel shows the AMCEs at low severity, while the center panel shows the AMCEs at high severity.

The right panel makes it possible to assess directly whether the AMCEs for target characteristics vary across levels of severity. The results show no statistically significant differences in AMCEs between low and high severity. This suggests that the effects of target characteristics on support for hate speech regulation are broadly stable and do not vary systematically between low-and high-severity conditions. In other words, the effects of target characteristics persist when severity is held constant, and the evidence does not suggest that they depend on the level of severity.

This was tested with a threeway interaction between severity, target group, and partisanship. The results do not support this proposition, as none of the interaction terms were statistically significant (see Figure S2).

Overall, the results suggest that severity and target characteristics have independent effects on support for hate speech regulation. Although the effect of severity is substantially larger, the effect of target characteristics persists when severity is held constant and is largest when speech targets religious and ethnic groups. The persistence of target effects when severity is held constant suggests that they are not wholly attributable to severity. Moreover, partisans are neither more nor less supportive of hate speech regulation when it targets their political ingroup or out-group. Finally, the effects of target characteristics on support for hate speech regulation are broadly similar at low and high levels of severity.

Discussion

While hate speech laws are being introduced around the globe (Parekh, 2012, p. 37), evidence on the extent to which public support for such laws depends on the target of hate speech or on its severity remains limited. This article contributes by estimating the independent effects of severity and target characteristics on support for hate speech laws through conjoint experiments fielded in Denmark and the U.S. The results show that when severity increases from incivility to incitement to violence, support for hate speech regulation increases by up to 32 percentage points. Target characteristics have smaller but non-zero effects that are heterogeneous across target groups and partisan groups. These effects are broadly stable across low and high levels of severity. In other words, the effect of target characteristics persists when the level of severity is held constant. On average, support for hate speech regulation changes by up to 6.3 percentage points depending on the target in Denmark and the U.S. The effects are largest when hate speech targets religious groups (Christians and Muslims) and ethnic minorities (Black people in the U.S., immigrants in Denmark). This suggests that people in Denmark and the U.S. are more supportive of regulating hate speech targeting certain groups. There is variation across partisan groups, as the effects of target characteristics are more pronounced for some partisans when hate speech targets certain religious or ethnic minority groups. With one exception, statistically significant effect sizes among partisans range from 3 to 7.2 percentage points. The exception is among leftwing respondents in Denmark, whose support for regulation increases by 11.9 percentage points when statements target Muslims. Finally, I find no evidence that partisans are more supportive of regulating hate speech targeting their political opponents than of hate speech targeting their political allies.

The findings speak to concerns about the adverse consequences of polarization among partisans (Lelkes & Westwood, 2016; Westwood et al., 2022). In short, partisans in both countries are no more willing to regulate hate speech targeting their political opponents than to regulate hate speech targeting their political allies. This contribution is important, as previous research suggests that partisans harbor negative feelings about their political opponents (Iyengar et al., 2012 (Iyengar et al., , 2019) ) and are more willing to tolerate and support preferential treatment of in-partisans (Lelkes & Westwood, 2016, p. 498), particularly when their partisan identity is threatened (Amira et al., 2021, pp. 473-74). This article provides no evidence that partisans apply different standards when regulating hate speech targeting political opponents versus political allies.

The main focus of the article, severity and target characteristics, is central to public debates about regulating hate speech (Kaye, 2021). The experiments also tested whether people were more likely to support regulation when hate speech targeted individuals (voters or politicians) holding certain opinions (e.g., opposing affirmative action), whether the speech was public or private, and whether the sender's gender and ethnicity influenced responses. Overall, the results showed limited or null effects of these attributes (see Figure S20 in the appendix; see Figures S8-S15 for an extensive test of heterogeneity by issue position). These findings align with previous research showing minimal effects of source cues on support for content moderation (Feezell et al., 2023; Kozyreva et al., 2023; Munzert et al., 2025; Solomon et al., 2024) and censorship (Carlos et al., 2023; Dias et al., 2025) but contradict studies suggesting that partisans censor political out-groups (Ashokkumar et al., 2020). An important difference is that many of these studies examine content moderation, whereas this article focuses on support for hate speech regulation. Future studies should compare differences in support for platform moderation, national legislation, and other types of moderation such as crowd moderation. The results also show that publicness had no effect on support for hate speech regulation, despite broad dissemination typically being considered an aggravating factor (Alkiviadou et al., 2020).

While this result is consistent with findings that the number of followers does not influence support for moderating misinformation (Kozyreva et al., 2023), future research is warranted to further test this proposition.

The study adds to a burgeoning literature on public opinion about regulation and content moderation (Ashokkumar et al., 2020; Dias et al., 2025; Kozyreva et al., 2023; Munzert et al., 2025; Pradel et al., 2024; Solomon et al., 2024; Wilhelm et al., 2020) but naturally has limitations that merit investigation. One limitation concerns the question of why some individuals are more supportive of regulating hate speech directed at certain groups. For example, why are Democrats more supportive of regulating hate speech targeting Black people? A prominent explanation is that liberals tend to place greater emphasis on fairness and the prevention of harm (Graham et al., 2009; Gray & Kubin, 2024). Recent research supports the view that people are more likely to support censorship when they perceive content as harmful (Boch, 2020; Crawford, 2017; Kubin et al., 2025; Womick et al., 2024). Relatedly, a large literature in political science has shown that the major political parties in the U.S. have "sorted in terms of ideological identity and demography" (Finkel et al., 2020, p. 534). This attachment to and alignment with specific groups may shape support for speech restrictions. Another perspective suggests that support for regulating hate speech arises from concerns about its role in perpetuating social inequalities affecting historically marginalized groups (Sidanius & Pratto, 2001). Indeed, research has shown that a preference for group-based dominance is associated with racism, sexism, and prejudice (Kunst et al., 2017), dehumanization of refugees and immigrants (Costello & Hodson, 2011; Esses et al., 2008; Kteily et al., 2015), and even acceptance of hate speech (Bilewicz et al., 2017).

Conversely, some argue that opposition to hate speech regulation stems from principled conservatism and a general resistance to government intervention (Grossmann & Hopkins, 2015; Sniderman et al., 1996).

This study contributes by disentangling the effect of target characteristics from the severity of the content and estimating their independent causal impact on support for hate speech regulation. The design manipulates different levels of severity (e.g., incivility and incitement to violence) through concrete statements (e.g., "I'm so sick of [group]! They're a bunch of idiots who are tearing our country apart!"), which makes it possible to show that target characteristics have independent effects that are not wholly attributable to severity. However, the design does not test whether respondents presented with generic survey questions (e.g., "offensive to [group]") infer different levels of severity depending on the target group. Future research should test this potential mechanism by comparing generic questions with conditions in which severity is explicitly fixed.

The conjoint experiments were designed to capture a wide range of typical hate speech targets at varying levels of severity in two countries with distinct socio-political contexts, thereby enhancing the generalizability of the findings. However, three issues warrant further investigation. First, the experiments were designed so that each severity statement (incivility; degradation/dehumanization without threat; degradation/dehumanization with threat; incitement to violence) could apply to each target to allow for valid inferences. This design facilitates the estimation of average marginal component effects (AMCEs) for both severity and Overall, this study demonstrates that severity is the main driver of support for hate speech regulation. Target characteristics also have smaller but non-zero effects, particularly when hate speech targets ethnic or religious groups. These effects of target characteristics persist when severity is held constant and broadly similar across levels of severity. In both the U.S. and Denmark, partisans differ in their overall support for hate speech regulation and, to some extent, in which target groups they are most inclined to protect.
