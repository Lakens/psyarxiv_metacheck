Files that do not belong in the repository

We left out 2 files that software creates by itself, not the authors: R history (2). They hold nothing a reader can use, but they clutter the repository, and software can mistake them for real files (for example a ._ copy of a .csv for data).

Remove these: Operating system files: macOS adds a __MACOSX folder and a ._ copy of every file it puts in a zip, and .DS_Store files to folders; Windows adds Thumbs.db and desktop.ini. On a Mac, create zips from the command line with zip -r -X, or remove them afterwards with zip -d archive.zip "__MACOSX/*" "*.DS_Store". RStudio session files (.Rproj.user/) hold open tabs and unsaved edits; R history (.Rhistory, .Rapp.history) lists the commands typed in a session and can hold file paths and passwords; Jupyter checkpoints (.ipynb_checkpoints/) are automatic copies of notebooks; compiled Python files (__pycache__/, .pyc) are recreated when the code runs; open-document lock files (~$...docx, .~lock...#) are left while a document is open; editor backups (file~, .bak, .swp) and temporary files (.tmp, .temp, an interrupted save of R’s workspace, .RDataTmp) are copies a program made by itself.

Keep only on purpose: version control folders (.git, .svn, .hg) hold the project’s history, which can include earlier versions of files and data that was later removed; editor settings (.idea, .vscode) can hold paths on your own computer. A .gitignore based on GitHub’s templates (https://github.com/github/gitignore) keeps them out of a repository.

This module searches for statements of ethics approval, IRB approval, institutional review board approval, and related terms.

How StatCheck works

Check consistency of p-values and test statistics

The Statcheck module runs Statcheck. Statcheck searches for regular expressions that match a predefined pattern, and identifies APA reported statistical tests. More information on the package can be found at https://github.com/cran/statcheck. The module only returns Statcheck results for t-tests and F-tests, as these are the only tests which have been validated, see https://osf.io/preprints/psyarxiv/tcxaj_v1/.

Statcheck was developed by Michèle Nuijten and Sascha Epskamp.

Statcheck considers p = 0.000 an error, as you should report p < 0.001. Furthermore, p < 0.03 is an error if the p-value was 0.031, and one should simply report exact p-values (p = 0.031). When the sentence of a test says it is one-sided (“one-tailed”, “one-sided” or “directional”), a p-value that fits a one-sided test counts as consistent (statcheck’s OneTailedTxt setting; #695). When the paper says anywhere that its tests are one-sided, a p-value that fits a one-sided test in either direction counts as consistent too: half the two-sided p, or 1 minus that half for an effect against the predicted direction. Equivalence tests (TOST) are left out, as their p-values do not test the difference. A statistic written with “<” or “>” is read as a bound, and in a sentence about equal variances an F-test’s two-sided p (twice the one-tailed p) counts as consistent. For more information, see StatCheck.

This module only checks statistical results reported in the running text of the manuscript. It cannot (yet) process statistics reported only in tables.

How Exact P-Values works

List any p-values reported with insufficient precision (e.g., p < .05 or p = n.s.), reported as exactly zero (e.g., p = .000), or impossible (below 0 or above 1, e.g., p = -.22).

This module uses regular expressions to identify p-values. It will flag any values reported as p > ? or p < numbers greater than .001. It will also flag p-values reported as exactly zero (e.g., p = .000, p = 0.00), which are mathematically impossible — p-values are never exactly zero and should instead be reported as p < .001.

A p-value that is not the result of a test is not flagged: a table note (“* p < .05, ** p < .01”), a figure legend (“Asterisks indicate significant differences (p < .05)”, “Values in bold are significant at p < .05”) or a stated threshold (“p < .05 was considered significant”, “thresholded at p < .001”). GROBID often puts such notes into the running text, so each p-value is judged by the words in its own clause (the text up to a “;” or a full stop), and never left out when a test statistic belongs to it (“F(1, 7) = 8.03, # p < .05”). The column not_a_test of the table says why a p-value was left out (“marker”, “threshold”, “legend” or “named”).

A p-value with the name of a correction or a test after the p (“pFWE < .05”, “padj < 0.05”, “p Wilcoxon = .02”) is flagged only when a test statistic comes before it in its clause (“t(37) = 7.17, p FWE < .05”). Without one it is mostly the rule that decided what was significant (“genes with padj < 0.05 were selected”); such a p-value is “named” in not_a_test. Notes in other forms, such as a marker after the p-value (“p < .05 (*)“), are still flagged.

A p-value below 0 or above 1 is impossible; it is listed apart and not also as imprecise. Often the statistic before it, or its minus sign, was copied into it (“t(134) = -2.32, p = -.13”, “Z = 3.091, P = 3.091”). A value above 1 is listed only after a test statistic in its clause: without one, a “P” above 1 was nearly always another quantity (a proportion, pH, a group’s mean, a model parameter). A number in scientific notation whose power of ten was lost when the PDF was read (“p = 2.4 x 10 -9” read as 2.4) is not listed. A “p” that is the subscript of another symbol (“r p = .64”, “²p = .02” for partial eta squared, “Δp = .33”), or a quantity with a unit, a logarithm or a ratio (“P = 2.9 µm”, “-log10 P = 7.5”, “Ca/P = 1.67”), is not read as a p-value at all (see extract_p_values()). Each p-value has its own row, also when the same one is written twice in a sentence.

This module sometimes flags false positives when sentences discuss how p-value thresholds were set. It can also miss an imprecise p-value that is reported against a threshold (“decreased at the p < .05 significance threshold”).

This module only checks p-values reported in the running text of the manuscript. It cannot (yet) process p-values reported only in tables (as opposed to a table’s footnote text, which the module does see and tries to exclude — see above).

How Repository Check works

This module retrieves information from repositories.

The Repository Check module lists files on the OSF, GitHub, ResearchBox, DSpace (PsychArchives and other legacy- and DSpace 7-based installations), Zenodo, Dataverse, Figshare, Dryad, ReShare, 4TU.ResearchData, Mendeley Data, DataONE (Arctic Data Center, KNB, and other member nodes), and LDbase based on links in the manuscript.

The report advises a stable repository such as Zenodo instead. Their files are not read, and summary_table$file_share_n counts the links.

A Handle link (hdl.handle.net/...) that leads to a repository read here is checked as a link to that repository ([handle_links()]).

Listing a repository’s files never requires an API key, but some hosts answer faster or more completely with one: OSF allows 100 requests/hour unauthenticated versus 10,000/day with a token (see [osf_pat()]), and Dryad enforces a strict per-IP daily quota on repeated listing (see cache below). Dryad is a special case beyond rate limits: listing a Dryad dataset’s files works without a key, but actually downloading file CONTENTS from Dryad fails with HTTP 401 unless a key is set, even for a fully public dataset (see [dryad_pat()] or [dryad_auth()]). Since this module only lists files and never downloads their contents itself, that limitation applies to data_check and code_check (which do download content), not here – see their own documentation.

When a linked OSF page is a registration, its registered_from project (the one it was registered from, which the manuscript itself may never link directly) is also checked: if that project is public its files are listed under its own URL, and if it is closed or otherwise inaccessible the report flags it explicitly, since some registrations only describe their content rather than mirroring it.

Whose deposit is each link? The ownership table gives, for every repository linked in the text and (with references = TRUE) every deposit cited in the reference list, one of six labels: own_this (made by the authors for this paper), own_earlier_data or own_earlier_code (the authors’ own, from earlier work), others_data or others_code (made by other people, reused here), or not_data (a publication such as a preprint, not a deposit), with ownership_group (“own”, “others”, “not_data”) and the reason. It is decided without a language model, from the sentence or reference that cites the link, the paper’s authors (names, ORCID iDs, affiliations), and what the deposit’s own record and files say (who made it, what it names, when, whether it is a software package; for an OSF project cited only in the reference list, its record alone). On a round of labelled links the rules had not been written from, the three groups were right for 98% of links in the main text (93 of 95) and 90% in reference lists (74 of 82); the labels were made by Claude agents from each link’s evidence, and disputed ones checked against the deposits. Telling this paper’s own deposit from the authors’ earlier one is less certain.

Only the deposits that are this paper’s own are checked. A deposit linked in the text that holds other people’s work (others_data, others_code) or the authors’ earlier work (own_earlier_data, own_earlier_code) is listed in the report, with the reason, but its files are left out of table and kept in table_not_checked: they count toward nothing here (files that do not belong in a repository, naming, READMEs, studies, the traffic light), and code_check, data_check and reproducibility_check, which read table, do not check them either. reproducibility_check still puts the files of theirs that the paper’s code names in the folder the code runs in, as a re-analysis needs the data it re-analyses. When every linked deposit is set aside, the traffic light is “na”. A deposit that is the paper’s own is counted as such when its README, title or description names the paper (its title or DOI).

How Code Check works

This module retrieves information from repositories checked by repo_check about code files (R, Python, SAS, SPSS, Stata, Mplus, MATLAB).

The Code Check module checks R (also R Markdown and Quarto), Python (also Jupyter notebooks), SAS, SPSS, Stata, Mplus, and MATLAB files, using regular expressions to check the code; JASP files are listed but not read. The language of a Quarto document or a notebook is read from the file itself (its engine or kernel), not from its extension. The regular expression search will detect the number of comments, the lines at which libraries/imports are loaded, attempts to detect absolute paths to files, setwd() and install.packages() calls, and lists files that are loaded, and checks if these files are in the repository; R code is also parsed. The module will return suggestions to improve the code if there are no comments, if libraries/imports are loaded in lines further than 4 lines apart, if files that are loaded are not in the repository, if absolute file paths, setwd() or install.packages() are found, and if R code cannot be parsed.

The regular expressions can miss information in code files, or falsely detect parts of the code as a fixed file path. Libraries/imports might be loaded in one block, even if there are more than 3 intermittent lines. The module was tried out internally on papers published in Psychological Science, but has not been formally validated. There might be valid reasons why some loaded files can’t be shared, but the module can’t evaluate these reasons, and always gives a warning.

The module also checks whether the repository pins the R/package versions the analysis actually depended on: an renv.lock file (parsed for the R version and every locked package + its version/source), a sessionInfo()/sessioninfo::session_info() text dump (matched by filename — sessionInfo.txt/session_info.txt and similar, or embedded in a README), or a groundhog::groundhog.library()/checkpoint::checkpoint() date-pin call in the code (a bare library(groundhog)/library(checkpoint) does not count — the pinning call itself must be present). When none of these is found, the report flags it as a reproducibility gap: package versions may drift between when the analysis was run and any later reproduction attempt.

If you want to extend the package to perform additional checks on code files, or make the checks work on other types of code files, reach out to the Metacheck development team.

Checking code requires downloading its file contents. For a paper whose repository is on Dryad, this never succeeds unless a Dryad API key is set: Dryad requires one to download file bytes, even from a fully public dataset (listing the repository’s files does not need one). Without a key, every Dryad-hosted code file is listed but unchecked, and a warning naming Dryad and ?dryad_pat/?dryad_auth is included among the download failures recorded in the manifest.

How Data Check works

This module classifies the files in a repository into semantic types (data, codebook, code, software, output, supplemental, readme, asset, other) and, for tabular data files, extracts each column’s type and summary statistics.

The Data Check module consumes the file list produced by repo_check (or any files added via local_path). Each file is classified with rule-based heuristics layered over metacheck’s file_category() and file_types: file names matching README / codebook patterns win first, then an extension crosswalk, then format-locked extension overrides. For every file classified as tabular data that is available locally, the module reads the file head, describes each column with data_col_facets() and computes summary statistics for numeric columns. Every sheet of a spreadsheet that holds a table is read: a file with several such sheets has its columns under source_file = "file.xlsx [sheet]", and the sheet column names the sheet of any spreadsheet with several sheets; a sheet of notes or a codebook is treated as documentation when the file has another table. Following DDI, a column is described by orthogonal facets rather than a single type: representation (numeric/text/datetime/code — how it is stored), measurement_level (Stevens: nominal/ordinal/interval/ratio), concept (what it measures: reaction_time/age/gender/likert/id/…), role (identifier/measure/condition/timestamp), unit, and a quality state (ok/empty/constant). Concepts are detected by name+value rules (the demographic concepts via data_check_demographic()); when llm_use(TRUE) the model fills concepts and measurement levels the rules left blank. Qualtrics survey exports are recognised (data_check_is_qualtrics()): their extra header rows are stripped so columns type correctly, and the reserved response-metadata columns (StartDate, Duration, Finished, …) are tagged.

The module defaults to rules-only when llm_use(FALSE): columns the rules cannot resolve (ambiguous 3–20-unique integers, ambiguous character columns) fall back to continuous / text respectively. When llm_use(TRUE), ambiguous columns and unresolved file types (other) are sent to llm() for optional refinement, and every file is assigned a study group (ex1, pilot2, shared, …) so that multi-study repositories can be recognised (used by psychds_check). Without an LLM the study group is left NA (unknown).

Column extraction requires files to be readable from disk. Files fetched by repo_check from OSF/GitHub/etc. without a local copy (file_location is NA) are classified but not column-extracted; pass local_path to point at a downloaded copy of the repository.

For a paper whose repository is on Dryad, this means column extraction never happens unless a Dryad API key is set: Dryad requires one to download file bytes, even from a fully public dataset (dataset listing and metadata do not need one). Without a key, every Dryad file stays classified but un-downloaded, column_n is 0, and a warning naming Dryad and ?dryad_pat/?dryad_auth is included among the download failures. A one-time session message is also shown (see repo_check) the first time a Dryad dataset is encountered with no key set.

Every downloaded text file the authors wrote (code, settings, survey definitions such as Qualtrics .qsf files, documentation, outputs) is searched for keys: API keys, access tokens and private keys, which let anyone who downloads the file use a paid service at the authors’ cost. Of a tabular data file only the column names and first 3 rows of the table as read are searched: its values come from participants, but a key the authors set for a whole survey (as embedded data in a Qualtrics survey flow) is exported in every response. The search uses the rules of the secret scanner betterleaks (https://github.com/betterleaks/betterleaks, MIT licence) of high and medium confidence. A key found turns the traffic light red; the report and the keys table give its file, line and type, and only its beginning. Other files over 25 MB and binary files are not searched. A key is never tested with its provider. Every module’s result has any whole key replaced by “keyremoved” (see module_run()).

How Reproducibility Check works

This module assesses whether a paper’s R and Python code can be run on its data. It works in two phases. The static phase (always run) collects the package dependencies the code declares, rewrites the data-file paths that do not work in the repository as the authors organised it, works out the order the scripts must run in, and diagnoses why any referenced input file is unavailable — reporting what a reproduction attempt would involve and where it is likely to break. The execution phase (opt-in, execute = TRUE) then actually runs the code: it copies the repository into a throwaway directory, optionally installs the declared dependencies into a throwaway library, runs each script in order in an isolated subprocess with a per-script timeout, and captures the outcome and full output of each run.

By default (execute = FALSE) the module does not run any code — it performs only static analysis: reading dependencies with the same extractors as code_check, finding the files the code references in the repository, and building a run-order dependency graph. It reports what would be installed and run rather than doing it.

When execute = TRUE, the module additionally runs the downloaded code on your machine — a deliberate, opt-in action gated behind that argument (callr is required for R code). Abstract

Unlike other screen-based technologies such as computer monitors, virtual reality (VR) systems allow the user to feel a sense of presence -the sense that they are actually situated within the surrounding virtual environment. Although the foundational experience of existing within a physical environment goes far beyond aspects of vision, our study is the first, to our knowledge, to operationalise and measure different facets of the multidimensional concept of the SOOP, ranging from indirect, trial-by-trial measures of reaction times and accuracy to higher-order aspects of presence judgements such as their trial-by-trial metacognitive efficiency, and to modality-specific and modality-general global (i.e. across many trials), retrospective self-report measures. We primarily hypothesised that whilst multisensory stimulation is the most important factor in the creation of presence, unisensory touch will be a greater causative factor in the creation of presence than unisensory vision. 44 participants completed an implicit reaction-time task (reacting to target stimuli) and an explicit metacognitive task (rating confidence in object presence). We manipulated sense type (unisensory vs multisensory), sensory modality (vision vs touch) and temporal order (e.g., touch-first vs. vision-first). Results indicated that multisensory integration significantly enhanced metacognitive efficacy, accuracy and reaction speeds compared to unisensory conditions. However, a key dissociation emerged between unisensory modalities. While participants reacted faster to visual stimuli, they achieved higher perceptual accuracy with tactile stimuli, with participants retrospectively rating touch as feeling significantly more "real" than vision. These findings support the notion that realtime "felt" presence and retrospective "judged" presence may be caused by distinct factors.

1. Introduction

In both cognitive science and VR research, the sense of presence (SOP) is defined as the feeling of existing within one's surrounding environment (Metzinger, 2003; Sanchez-Vives & Slater, 2005; Singleton & Fotopoulou, 2026). While the technological and cognitive determinants of SOP, such as field-of-view, latency, and agency are well-documented (e.g., Hendrix & Barfield, 1996; Nakano et al., 2021; Slater, 2009), less is known about how we perceive the presence of inanimate objects, hereafter referred to as the 'Sense of Object Presence' (SOOP). Specifically, the role of proximal senses, such as touch, remains underexplored compared to visual dominance.

For the purposes of the current study, we specifically relate our hypotheses, analyses and discussion to the SOOP rather than the SOP. This is not because we see the SOOP as a distinct concept from the SOP (SOOP would be a subset of SOP (Seth, 2014)) -instead the reasons for this are entirely driven by experimental pragmatics. Usually in presence research, the dependent variables (normally measures of how present one feels in the virtual environment) relate to the entire virtual environment as a whole rather than any specific subset of that environment (Suzuki et al., 2023). Even when studies manipulate one specific aspect of the environment (such as gravity, embodiment, etc. (Drori et al., 2025)), the dependent variables collected relate to a participant's entire experience rather than the specific manipulation. However, in the current study our dependent variables relate to the specific manipulation of how participants interact with objects, in that we attempt to determine whether participants feel as if the objects presented to them are also present in the virtual space with them. Augmented reality (AR) paradigms may also be suited to answer this type of question, though there may be a potential mismatch in that an AR paradigm would be asking participants whether they felt as if a virtual object was present in the physical world, whereas our VR paradigm asks whether this virtual object feels present within the virtual world. Therefore, due to this specific difference between the current study and previous studies, and for the sake of precision and transparency, we will instead conduct and discuss our experiment with reference to object presence (SOOP) than general presence, despite the fact that the SOOP is merely a more specific instance of the SOP (Suzuki et al., 2019).

Most previous research on the SOP and SOOP has focused on the role of distant sensory modalities such as vision, or audition, with only limited research examining proximal sensations such as touch. Touch is considered a proximal modality in the sense that to touch an object or be touched by it, that object needs to be near to the body. The current emphasis on distant modalities may have been due to the ease by which one can present or manipulate visual and auditory stimuli in related experimental paradigms and VR settings. However, such differences in research volume could introduce an unintentional bias in the understanding of the SOOP, potentially underestimating the specific role of proximal sensory modalities, such as touch. This specificity may, for example, stem from the fact that typically, we will first see or hear an approaching object, and we will only be able to touch it when we are near it. In other terms, touch of an object is habitually added to its multisensory perception later than distant modalities such as vision. Moreover, perceiving an object near the body (in its so-called peripersonal space) is known to recruit different neural and perceptual processes than perceiving an object far from the body, both because proximity allows for action towards the world and because the body needs to be defended from potential threats in the environment (Serino, 2019 (Serino, , 2022)). To our knowledge, the effects of this proximity and habitual temporal order by which we perceive objects to the sense of presence have not been examined.

According to some philosophers, touch can be a 'reality verificator' (Massin, 2009; Merleau-Ponty, 2002). However, it is unclear as to whether this is because touch is typically the last modality used to verify the perceptual content of other modalities, or whether there is something intrinsically different about the information touch adds to the SOOP. Indeed, touch does display some other unique properties. For example, we cannot touch an object without being touched back; a reciprocal relationship between body and objects that has led some philosophers to claim that touch has a unique role in a related concept, the sense of reality (SOR) -one's subjective sense of reality of the world and the self positioned within it (Metzinger, 2003; (Merleau-Ponty, 2002) (Massin, 2009).

Only four studies have directly compared touch to other unisensory or multisensory stimuli in creating the sense of presence in VR. Two of these studies found that the addition of touch feedback to vision increased self-reported presence (Brasen et al., 2019; Kreimeier et al., 2019). However, both studies utilised a relatively small sample size (N =14 in both), indicating a low power for the intended effect size. A third study found that the addition of touch feedback directly to the hands during a game of Simon Says did not increase presence (Viciana-Abad et al., 2010). Rather, presence was only increased when participants utilised a stylus to press the virtual buttons, receiving touch feedback via the stylus (Viciana-Abad et al., 2010). A final study not only found that the addition of touch feedback to visual events in VR enhanced presence, but that touch feedback alone seemed to contribute more to presence than visual feedback alone (Gibbs et al., 2022). To our knowledge, this was the first study to conduct such direct, unisensory comparisons between touch and vision. Collectively, these four studies suggest that the addition of touch, or at least certain types of touch, to multisensory VR experiences can enhance self-reported SOP. However, strong conclusions cannot be made from these such varied and small sample studies that relied only on self-report. The current, well-powered study aimed to compare directly between touch and vision in both unisensory and multisensory conditions, as well as to utilise indirect (reaction times) and trial-by-trial (visual analogue scale (VAS) ratings) behavioural and metacognitive measures of the SOOP to provide greater reliability and specificity to our understanding of the role of touch in SOOP.

Moreover, we are also interested in how the order of stimulus presentation within a multisensory context impacts the SOOP, given the aforementioned 'proximal' properties of touch, i.e. we are typically able to touch an object when it is near the body and after we have seen it. To our knowledge, the effects of this proximity and habitual temporal order by which we perceive objects to the SOP have not been examined.

In addition, our study aimed to go beyond using questionnaires to measure the SOP. Indeed, the validity of SOP questionnaires has been questioned from a theoretical standpoint, as post-task questionnaires rely on global, retrospective judgements while presence is seen as a property of immediate sensory experience (Sanchez-Vives & Slater, 2005; Slater, 2018). A recent review found that in addition to this limitation, different presence questionnaires used different SOP definitions (Grassini & Laumann, 2020), which reduces the generalisability of findings across studies.

To reduce some of the limitations associated with global, retrospective questionnaire measures of presence, our study used individual trial-by-trial ratings of whether the target stimulus was present within their environments. These trial-by-trial VAS ratings allowed us also to assess individuals' confidence on their presence judgement and hence investigate differences between these conditions not only at the perceptual, but also the metacognitive level. Specifically, metacognitive processes are defined as the monitoring, controlling and awareness of one's own cognitive processes without direct feedback from the environment (Flavell, 1979). The extent to which the SOOP or the SOP are impacted by metacognitive processes is unknown and, as far as we are aware, untested in previous studies, despite the more general debates on the role of low-level perceptual processes, as opposed to topdown, cognitive influences (Fleming, 2024; Skarbez et al., 2017). It may be the case that because a greater sense of presence induces stronger perceptual representation of objects, that this will therefore lead to an improvement in metacognitive efficiency. However, stronger perceptual signals do not necessarily lead to an increase in metacognitive efficiency, and vice versa (Fleming, 2024). Instead, our hypothesis that increased presence will correlate with an improved metacognitive performance is based on the nature of metacognition as a second-order computation about one's own performance, based on prior beliefs about the reliability and noise of one's own first order processing (Fleming & Daw, 2017). Because a virtual environment that generates a robust sense of presence is likely to be close to the ecological normality of the physical environment, we can therefore engage more ecologically normal metacognitive models instead of having to update existing models based on a new type of virtual environment. This would mean that an increase in presence would also improve metacognitive efficiency.

Finally, our study will also collect reaction times to stimuli as a dependent variable to determine whether participants react faster in unisensory conditions involving touch versus vision, and corresponding multisensory manipulations. Previous studies that have used reaction times as alternative, indirect measures of the SOP (Chandio et al., 2024; Hecht et al., 2006; Klimmt et al., 2005) have found negative correlations between reaction times and presence scores (e.g. Chandio et al., 2024), implying that people react faster to objects they experience as real. Thus, our study uses three different measures to capture the SOP, namely trial-by-trial ratings and reaction times, and a global, validated SOP questionnaire. We also controlled for key confounding parameter such as risk taking, ability to sustain attention over long periods of time, visual discrimination ability and touch discrimination ability.

Our study had three main hypotheses which were pre-registered on OSF prior to data collection (Registration ID: 10.17605/OSF.IO/SWUX2, accessible at https://osf.io/swux2/). We hypothesise (1) that touch induces a greater sense of object presence than vision. To test the possibility that touch's typical role as the last experienced sense impacts its relationship to the SOOP, we will vary the order by which participants experience objects in a multisensory capacity and compare reaction times to these conditions. We therefore predict that (1a) touch-first multisensory trials will induce quicker reaction times than visionfirst multisensory trials. We will also test the possibility that there is something specific about the nature of touch which induces a quicker understanding of object presence than vision by comparing reaction times between unisensory touch trials and unisensory vision trials. We predict that (1b) touch unisensory trials will induce quicker reaction times than vision unisensory trials. Secondly, we hypothesise that (2) although touch is the sense which produces the greatest increase in object presence, multisensory stimuli will always provide a greater sense of object presence than unisensory stimuli. We will therefore compare confidence values between unisensory and multisensory conditions. We predict that (2a) participants will exhibit greater metacognitive efficacy in multisensory trials compared to unisensory trials, and (2b) this will be accompanied with a higher overall accuracy in multisensory trials compared to unisensory trials. Finally, we hypothesise that (3) a unisensory touch stimulus will provide a greater sense that an object is present than a unisensory visual stimulus. We will therefore compare confidence values at identifying the presence of target stimuli between unisensory touch and unisensory vision conditions. We predict that (3a) participants will exhibit greater metacognitive efficacy in touch unisensory trials compared to visual unisensory trials, and (3b) be more accurate in touch unisensory trials compared to visual unisensory trials.

2. 1 Participants

Participants were automatically excluded from participating further in the study if they answered TRUE when asked if they had experienced a history of motion sickness in the demographics questionnaire. No participants were excluded. 44 participants (19-61 years, 27 female 17 male) were therefore recruited through the UCL SONA system. The mean age of participants was 31.8 years (SD = 11.5). An age distribution of 19 to 61 years significantly enhances the external validity and generalisability of our study, allowing us to investigate presence across adulthood rather than uniquely constrained to digital-native young adults. Participants were aged 18 or above and provided informed consent before taking part in the study. Each participant was remunerated a minimum of £13.50 with a chance to earn an extra £6 depending on task performance in the task (see below).

2.2 Experimental Design

Our experiment employed a within-subjects design, in which we first manipulated the type of sensory modality participants experienced objects in VR within 2 levels, touch versus vision. We also separately, manipulated the number of modalities presented to participants in 2 levels (Unisensory vs Multisensory). Finally, in a third set of comparisons we tested the effects of temporal order in multisensory integration in two levels, we presented visuotactile stimuli to participants, but we presented either the touch or the vision stimuli half a second earlier (figure 1).

The experiment is broken up into two blocks based on the dependent variable: a Reaction Time block and a Confidence block, counterbalanced between participants. Reaction Time blocks measured perceptual accuracy and participant reaction time as the main dependent variables, whereas Confidence blocks collected perceptual accuracy and participant confidence as the main dependent variables. We also collected four control measures to control for more basic, domain-general cognitive processes such as attention, and modality-specific discrimination abilities and RT, and also took into account participant age and VR familiarity into our analyses. Specifically, Balloon Analogue Risk-Taking task (BART) score (Lejuez et al., 2002), Sustained Attention to Response task (SART) score (Stoet, 2010 (Stoet, , 2017)), a visual discrimination task (VDT) score and a touch discrimination task (HDT) score. Self-reported age and VR and VR touch familiarity scores as the final two control variables. The HDT and VDT were included to ensure that results were not confounded by a participant's individual difference in being able to discriminate a touch stimulus against other touch stimuli and being able to discriminate a visual stimulus from other visual stimuli. The SART was included to minimise the impact of a participant's ability to sustain attention over a long period of time, since the main experiments involved long stretches of time completing the task in VR. The BART score was included as a control since participant's general risk taking behaviour may influence the threshold at which they were sure enough that the target stimulus was present within their environments. Age was included as people's reaction times tend to increase with age, and VR and VR haptics familiarity scores (how familiar participants were with VR and VR haptic technology on a scale of 0-5) were included as controls as participants with more experience in VR would feasibly do 'better' in both tasks than participants who were not as familiar with VR and had to learn the technology as they completed the task.

2.3 Power Consideration

Sample size estimation was based on a power analysis performed on hypothesis 1 using G*Power3.1 (Faul et al., 2007). For our study, with Multisensory Order and Unisensory Modality (not their interaction) as our two main independent variables of interest regarding hypothesis 1, a moderate effect size of .4 (Barutchu & Spence, 2021), a power of .8, and alpha of .05, the recommended total sample size is 40 participants. The moderate effect size utilised in this power calculation was based on a behavioural sensory-switching study undertaken by Barutchu & Spence (2021), since the core dependent variable (reaction time) and independent variables remain consistent with our study. In total, we recruited and tested 44 participants (19-61 years, 27 female 17 male).

2.4 Materials

Our study utilised the Meta Quest 3 and its controllers to immerse participants within a VR environment. Touch sensation was generated using https://www.ultraleap.com/ (previously UltraHaptics) HDK-REC192 touch device (Carter et al., 2013). This device utilises mid-air haptics to provide tactile feedback to users without the need for physical contact with an intermediary interface. The haptic feedback is generated through the use of focused ultrasound. The VR environment was created in-house using Unity 2023.2.15f1, with the Modular Caves asset bought from ProAssets in the Unity store.

Most VR studies which induce some kind of haptic feedback to the user do so either via controller vibration, vibrotactile stimulation via electrodes or mechanical stimulation via a glove-like device (Shi & Shen, 2024). However, each of these techniques includes the utilisation of some type of mediator to induce the feeling of touch (controller, electrode or glove). The HDK_REC192 touch device allows for the simulation of touch without the need for a mediator to be attached to the skin, providing a more naturalistic experience of what it is like to reach out and touch an object in VR. The device achieves this via a series of ultrasound generators, which work in synchronisation to project the sensation of touch onto the palm of the hand and can be programmed to induce the feeling of different shapes as well as movement.

The VR environment created was that of a cave system. In the VR environment, participants are sat in the centre of a steel minecart travelling slowly along tracks within this cave system. Participants are also embodied within this stimulation -which is to say that when they looked down, they could see their own body sat in the same position as their body in the real world (figure 2). 2.5 Procedure

2.5.1 Reaction Time Block

In this block, participants were told that the target stimuli they had been trained on was a species of Bat which was dangerous to humans. Participants were tasked to remove the Bat from the cave by activating an inbuilt laser system by pressing the left index trigger on the left controller. However, they were also told that this laser system could only be activated up to 20 times per day. Participants were updated on how many laser activations they had remaining through a number shown to them in the VR headset. Participants were also given a health bar which acted as an incentive for them to perform as well as possible during the task. For every unit left on a participant's health bar at the end of the task, they would receive an extra 50 pence in compensation. This gave participants a theoretical maximum of 19.5 pounds for their time (6 pounds for 12 health bar units left at the end of the task, plus the base pay of 13.5 pounds).

Before starting the task, participants were allowed to familiarise themselves with the target stimuli for 30 seconds uninterrupted. Participants were then allowed to re-familiarise themselves with the target stimuli for 5 seconds before undertaking the practice block, and then for another 5 seconds before undertaking the experimental block. Participants wore ear defenders whilst completing the tasks to reduce any perception of noise created by the midair haptics device.

After completing the practice block, participants then moved on to the experimental block. Once a stimulus from a random condition has been shown to the participant, the following scenario occurs:

The minecart stops moving, followed by a delay of 3 seconds. If the participant thinks that the stimulus presented to them was the target stimulus, they choose to activate the laser and their screen flashes red. If not, the participant does nothing. If the participant correctly activates the laser, they lose no units of health, but their number of remaining laser activations reduces by 1. If the participant incorrectly activates the laser (activates the laser when the stimulus presented was a noise stimulus), then they lose no health, but their remaining number of laser activations reduces by 1. If a participant incorrectly does not activate the laser (does not activate the laser when a target stimulus was presented), their health bar reduces by 1 unit. If the participant correctly does not activate the laser (does not activate the laser when a noise stimulus was presented), then neither their health bar nor their activations remaining is reduced.

Once 3 seconds has elapsed, the minecart begins moving again and the timer is reset, meaning that another stimulus will appear to the participant within a random interval of 5-15 seconds. This cycle continues until each stimulus has appeared in each condition exactly twice, for a total of 48 trials. If, at any point during the experimental block, a participant activated the laser so many times that they ended up with 0 laser shots remaining, they were told to disregard the fact they had 0 activations remaining and to carry on the task as normal.

A participant would have been told the same if their health bar also reached 0 at any point during the task.

2.5.2 Confidence Block

In this block, participants were told that they would be giving explicit ratings as to whether the stimuli they experienced in VR were the same or different as compared to the learned target stimuli (see figure 5 for a summary of key differences). Participants gave their answers on a confidence scale from 0-100, with 0 indicating a strong confidence that the stimulus just presented to them was the target stimulus, and 100 indicating that the stimulus just presented to them was not the target stimulus. A participant's score on this scale allowed us to collect both their answer (whether the presented stimulus was the target stimulus or not) and their confidence in their answer (how far from 50 the participant rated the stimulus) at the same time. Note. The difference between our confidence block procedure (a) and reaction time block procedure (b).

In the confidence block, participants were asked to rate each stimulus following stimulus presentation, whereas in the reaction time block participants were asked to react by pressing a button if they thought they experienced the target stimulus.

Before starting the task, participants were allowed to familiarise themselves with the target stimuli for 30 seconds uninterrupted. Participants were then allowed to re-familiarise themselves with the target stimuli for 5 seconds before undertaking the practice block, and then for another 5 seconds before undertaking the experimental block. Participants wore ear defenders whilst completing the tasks to reduce any perception of noise created by the midair haptics device.

After completing the practice block, participants then moved on to the experimental block. Once a stimulus from a random condition has been shown to the participant, the following scenario occurs:

The minecart stops moving, followed by a delay of 3 seconds. Once 3 seconds has elapsed, a slider appears in front of the participant in VR, with Same on one end of the slider and Different on the other end. The participant then rates their confidence regarding whether they think that the stimulus just shown to them was the same or different from the target stimulus. This is done using the thumb stick on the left controller. Once a participant is happy with their rating, they press the X button on the left controller to confirm their answer. Once the X button has been pressed their data is recorded, and the slider is reset to a random value between 0-100 and the timer starts again -meaning the participant will now wait for another 5-15 seconds before being presented with the next stimulus. These random values were not recorded or controlled for in the final analyses, since the random nature of the reset slider should provide adequate control for anchoring effects here.

2.7 Statistical Analyses Plan

2.7.1 Preliminary Analysis

To first determine whether reaction times in the reaction time task negatively correlated with presence scores measured by the presence questionnaire, we will conduct an exploratory linear mixed-effects model with mean reaction time per conditions as our dependent variable, using average presence score per participant as our other dependent variable of interest. We will include random effects here for ID and Condition.

We will also do the same to determine whether confidence in the confidence task positively correlates with presence scores measured by the presence questionnaire. We will conduct another linear mixed-effects model, using metacognitive efficacy as our dependent variable and presence scores as our independent variable of interest with random effects for ID and Condition.

If either of these correlations is non-significant, we will conduct a Bayes equivalence test to determine whether these results are truly negative (Stanton, 2021), thus providing us with useful information regarding the utilisation of either reaction time or confidence as behavioural measures of presence.

2.7.2 Hypothesis 1a

We will determine whether touch-first multisensory trials induced quicker reaction times than vision-first multisensory trials using a linear mixed-effects model using the lme4 package in R. This model included Integration (our multisensory independent variables of interest with 2 levels -Touch then Visual and Visual then Touch), BART score (continuous control), SART score (continuous control), Visual discrimination score (continuous control), Touch discrimination score (continuous control), Age, VR Familiarity and VR Touch Familiarity as our fixed effects, with the log of Mean Reaction Time as our dependent variable of interest. The model also included random intercepts for ID. We also pre-registered including differences in signal conduction velocity between the visual and touch sensory systems as a control in our analyses. We were unable to find any reliable literature on this; therefore we are excluding this control variable from all our analyses. We will also not be controlling for scores in the Wisconsin Card Sorting task (WCST), since we decided that behavioural measures in this task would not capture any significant mental processes which would confound the results in our experiment.

2.7.3 Hypothesis 1b

Analysis 1b -We will determine whether touch unisensory trials induced quicker reaction times than vision unisensory trials using a linear mixed-effects model using the lme4 package in R. This model included Modality (our unisensory independent variables of interest with 2 levels -Touch or Visual), BART score (continuous control), SART score (continuous control), Visual discrimination score (continuous control), Touch discrimination score (continuous control), Age, VR Familiarity and VR Touch Familiarity as our fixed effects variables with the log of Mean Reaction Time as our dependent variable of interest. The model also included random intercepts for ID and Stimulus Duration.

2.7.4 Hypothesis 2a

We will determine whether participants exhibited greater metacognitive efficacy in multisensory trials compared to unisensory trials using a linear mixed-effects model. Our pre-registered analyses included calculating m-ratio from confidence and accuracy values generated in the Confidence block. However, we were unable to generate these figures using the most optimal method since we did not have enough signal trials per condition per participant. Therefore, we created a replacement measure for metacognition in which we correlated accuracy on the confidence task with reported confidence, giving us a score for each participant per object per condition. We used our replacement measure for metacognition as our dependent variable, with Sense (unisensory or multisensory) as our independent variable of interest and ID as a random effects variable.

2.7.5 Hypothesis 2b

Analysis 2b -We will determine whether participants exhibited a higher overall accuracy in multisensory trials compared to unisensory trials using a linear mixed-effects model using the lme4 package in R. We used Accuracy as our dependent variable (d' values calculated using the psycho package in R, a deviation from our pre-registered analyses), with Sense (our independent variable of interest with 2 levels: Multisensory or Unisensory), BART score (continuous control), SART score (continuous control), Visual discrimination score (continuous control), Touch discrimination score (continuous control), Age, VR Familiarity and VR Touch Familiarity as our fixed effects variables. We also included ID and Duration as random effects variables.

2.7.6 Hypothesis 3a

We will determine whether unisensory touch scenarios induced a significantly greater metacognitive efficacy than unisensory visual trials by using a linear mixed-effects model using the lme4 package in R. We used metacognition as our dependent variable, with Modality (our independent variable of interest with 2 levels: Touch or Vision) as our independent variable of interest and ID as a random effects variable.

2.7.7 Hypothesis 3b

Analysis 3b -We will determine whether participants were more accurate in touch unisensory trials compared to visual unisensory trials by using a linear mixed-effects model using the lme4 package in R. We used accuracy as our dependent variable (d' values calculated using the psycho package in R, a deviation from our pre-registered analyses), with Modality (our independent variable of interest with 2 levels: Touch or Vision), BART score (continuous control), SART score (continuous control), Visual discrimination score (continuous control), Touch discrimination score (continuous control), Age, VR Familiarity and VR Touch Familiarity as our fixed effects variables and ID as a random effects variable.

2.7.8 Correcting for Multiple Comparisons

For our core experimental analyses (Hypotheses 1, 2, and 3), statistical thresholds will be kept at p=0.05 without broad multi-test corrections, as each model evaluates independent, a priori pre-registered hypotheses addressing distinct psychological mechanisms. While Hypotheses 2b and 3b share the same underlying accuracy metrics (d'), they evaluate orthogonal statistical effects (the macro-effect of multisensory integration vs the effect of sensory modality within unisensory contexts, respectively). Applying broad adjustments across conceptually independent primary models would over-penalize the architecture and artificially inflate Type II error rates. However, for post-hoc exploratory comparisons involving repeated lookups on the same data array (e.g., the questionnaire items in Exploratory Analysis 4), an explicit Bonferroni correction is applied to control family-wise error rates.

4. Discussion

The broad aim of this study was to investigate the impact of touch on the SOOP in VR. We had three main hypotheses: (1) touch induces a greater SOOP than vision, (2) multisensory stimuli will always provide a greater SOOP than unisensory stimuli and (3) a unisensory touch stimulus will provide a greater SOOP than a unisensory visual stimulus. Hypotheses 1 and 3 remain unsupported, since touch did not induce a significantly greater SOOP than vision in either multisensory or unisensory contexts, but hypothesis 2 is supported since multisensory stimuli did provide a greater SOOP than unisensory stimuli. However, we also found significant findings with regards to differences between behavioural results between touch and vision stimuli and questionnaire results. Our study is the first to our knowledge to operationalise and measure different facets of the multidimensional concept of the SOOP, ranging from indirect, trial-by-trial measures of reaction times and accuracy to higher-order aspects of presence judgements such as their trial-by-trial metacognitive efficiency, and to modality-specific and modality-general global (i.e. across many trials), retrospective selfreport measures. By examining our central hypotheses on all our measures, we were able to account for the role of touch on the SOOP as a multidimensional construct.

To investigate our hypotheses, we wanted to utilise comparisons between behavioural measures of presence: reaction time and metacognitive efficacy. Therefore, we investigated whether presence scores, as measured by the IPQ questionnaire, correlated with reaction time and metacognitive efficacy. The current study found that presence scores increased significantly as reaction time decreased -meaning that we can use reaction times from our reaction time block as behavioural predictors of presence. However, we found no relationship between presence scores and metacognition as calculated in the analysis described in section 3.2. We further investigated this relationship by utilising a Bayesian equivalence test, which confirmed the results as truly null.

It is important to re-iterate here that some of our analyses deviated significantly from our preregistered protocols -specifically any analysis using either d' or m-ratio as a dependent variable. Originally, we planned to use a Bayesian estimation method to generate both d' and m-ratio values via the metadpy Python toolbox (Embodied Cognition Group, 2023). However, the parameter estimates generated by this modelling framework over our low trialto-condition ratio introduced severe mathematical artifacts. To calculate m-ratio in this way, responses must be binned into a minimum number of categories. Since we had a low number of observations per participant per condition, many of these bins ended up empty, causing artefacts when meta-d' was calculated and, therefore, resulting in the generation of multiple impossible final m-ratio numbers (negative values and values well above 1 (e.g. one participant in particular scored an m-ratio of 11.23 -1123% metacognitive efficiency). Had we used this data for our analyses, we would've had to exclude 13 out of our 44 participants. Therefore, to preserve statistical validity, we implemented alternative computational approaches. For our exploratory analysis of perceptual sensitivity, d' variables were generated using the psycho package in R, which calculates sensitivity directly from unbinned raw trial counts (Hits, Misses, False Alarms, and Correct Rejections). This was paired with a beta-distribution GLMM framework (glmmTMB) to account for the heavy positive skew and bounded nature of our accuracy data. Furthermore, because individual m-ratio modelling collapsed entirely under zero-cell counts, it was replaced in our exploratory analyses with a non-parametric index of metacognitive monitoring generated via trial-by-trial, within-subject correlations between confidence and objective accuracy. While we acknowledge this replacement measure is inherently noisier and susceptible to data loss when performance is invariant, it provides a robust window into metacognitive monitoring without forcing rigid parametric assumptions onto sparse data. Consequently, this discussion focuses primarily on the results generated from these distribution-corrected variables, while the original, pre-registered modelling outputs can be found in the supplementary materials.

Regarding our replacement measure of metacognitive efficiency, we cannot draw any further conclusions regarding the relationship between our independent variables and the sense of presence in VR. This is because we found no significant correlation between metacognitive efficiency and global presence scores. This may be for a number of reasons. Firstly, there was a limitation within our experiment regarding the gamification of blocks. Although the reaction time block was gamified, in that participants won more money for performing better, the metacognition block was not. This may have introduced a confound that meant participants cared less and therefore performed worse in the confidence block, causing our measure of metacognition to no longer correlate with presence. However, there is ample evidence in psychology to suggest that although gamification is one method to ensure participants maintain attention and concentration on the set task, it is not the only method, and other general rewards as well as the satisfaction of successfully completing a task to the best of one's ability are also sufficient (Hanks & Summerfield, 2017; Harvey et al., 2024; James et al., 2019). Secondly, previous research regarding the relationship between metacognitive processes and the sense of reality has similar results. One recent study (Dijkstra et al., 2024) attempted to define the relationship between metacognition and the sense of reality through the lens of perceptual reality monitoring -the ability to distinguish between internally generated content and external perceptual phenomena (Lau, 2019). In this study, the authors attempted to determine whether participants demonstrated insight into whether their judgments regarding the origins of perceptual stimulation (either internally or externally generated) were correct. This study found that, although participants had some limited global, task-level insight into their performance, this was uncorrelated with the triallevel insight measured during the task. Therefore, trial-by-trial confidence ratings do not distinguish between imagination and reality during perceptual tasks. It is therefore clear that, in this case, the accuracy of metacognitive judgements does not fully depend on the same signal parameters or cognitive processes as those that determine perceptual performance (Fleming, 2024). Although our two studies are underlined with different theoretical frameworks (the current study was not designed and draws no conclusion regarding perceptual reality monitoring), our finding that trial-level measures of metacognitive efficiency were not correlated with a participant's sense of presence seems parallel to findings both in the field of perceptual reality monitoring and more broad theoretical conceptions of metacognition as being dissociable from task performance. Measures of metacognition are therefore not likely to perform as good measures of presence.

We found no difference in either reaction times or metacognitive efficacy when comparing our multisensory conditions VisionxTouch and TouchxVision. This was an unexpected finding. We hypothesised that participants would react faster in touch-first multisensory conditions compared to vision-first multisensory conditions, and that this would be accompanied by an increase in metacognitive efficacy. This hypothesis was based on previous studies which suggested that touch alone contributed more to the sense of presence than vision alone (Gibbs et al., 2022), and also empirical and theoretical investigations of touch and its role in perception and action (Massin, 2009; Serino, 2019 Serino, , 2022)). Considering this research, we expected a multisensory, visuo-haptic condition in which we presented touch slightly before vision to induce a greater sense of presence faster than a visuo-haptic condition in which we presented vision before touch. However, our results suggest that this is not the case, and that there is no difference between these two conditions. This may simply be because the presentation of vision and touch together, regardless as to which was presented first, is more than enough of a sensory signal to determine that an object is present within one's environment.

In support of hypothesis 2, we found that participants demonstrated significantly faster reaction times, greater accuracy and increased metacognitive ability in multisensory trials compared to unisensory trials, meaning participants felt that multisensory objects were present within their environments faster than unisensory objects. This result is a replication of previous findings in the field of human-computer interaction, which consistently find that multisensory experiences induce greater presence for individuals in VR than unisensory experiences. Multiple previous studies and meta analyses have found significant differences in how present participants feel in VR environments when the environment is purely visual vs multisensory, with participants always feeling more present in multisensory environments (Gallace et al., 2012; Melo et al., 2022; Schwind et al., 2017). Although our result here is just a replication of previous findings, this provides some validity to our paradigm. This is particularly important, since our experimental paradigm involves the usage of a novel haptic medium -mid-air haptics. Typically, haptic stimulation is deployed to participants in VR via some kind of intermediary mechanism. Such mechanisms typically include haptic gloves (Perret & Vander Poorten, 2018), controller vibrations (Våpenstad et al., 2013) or other types of vibrotactile stimulators (Hwang et al., 2024). However, experiencing vibrotactile feedback via an intermediary controller is not necessarily naturalistic since the feeling of the intermediary controller on the skin impacts the overall haptic experience. In theory, novel mid-air haptics presents a more naturalistic way for participants in VR to experience tactile feedback from objects since there is no intermediary contact with the participant's skin. Our finding that participants were faster in multisensory scenarios compared to unisensory scenarios suggests that, despite the novelty of mid-air haptics, multisensory mechanisms were still recruited when participants were presented with a visual stimulus accompanied by a haptic stimulus produced via novel mid-air haptics.

Our results also show that participants were faster at responding to the presence of target objects in unisensory vision trials compared to unisensory touch trials. This finding is in opposition to hypothesis 1. This is in spite of the fact that mean haptic reaction times tend to be slightly faster than mean visual reaction times (155ms vs 180-200ms) (Fieandt, 1956; Wang et al., 2022; Welford & Brebner, 1980). It may be that we feel as if touch confirms an object's presence in our environments due to the fact that the addition of touch to vision merely recruits multisensory mechanisms, which then go on to improve our sense that the object is present (Cooper et al., 2018; Gallace et al., 2012; Marucci et al., 2021), and that there is no special role of touch. However, there is a significant confound within our methodology that caveats this conclusion. Although our experiment attempted to attenuate the role of visual dominance in perception (Fan et al., 2020; Mayeli, 2019; Stokes & Biggs, 2014) by presenting target touch and target visual stimuli to participants in a random order, meaning they must attend equally to both tactile and visual information, it is likely that the addition of visual-only task-relevant information (the counter for the number of shots the participant had remaining, and the red health bar which indicated how many target stimuli the participant had missed) may have shifted attention, and therefore perceptual dominance in the task, towards vision. This would bias reaction times in favour of the visual stimuli. This is a clear limitation which reduces confidence in our rejection of hypothesis 1 and warrants a replication where this limitation is removed.

However, this caveated conclusion would be in opposition to the results of items on our modified presence questionnaire. When asked specifically which condition felt most real to them during the experiment (touch, vision or multisensory), participants rated touch as feeling significantly more real than both multisensory and vision conditions and rated multisensory conditions as more real than visual conditions. We first hypothesise that participants rated touch as feeling significantly more real than multisensory scenarios due to the fact that all of the multisensory conditions were temporally incongruent (vision presented either 500ms before touch, or touch 500ms before vision). We also hypothesise that this difference between touch and vision means that there is a difference between the online sense of presence and a post-hoc judgment of the same sense. It is important, especially when investigating concepts such as the SOP and SOOP, to distinguish between the moment of the original, real experience (the perception of a stimulus in VR) and the judgments based around it (presence questionnaires administered outside of VR) (Blankenburg, 1971; Jaspers, 1913). Put more simply, although presence questionnaires may give us accurate measures of post-hoc judgments of presence, they do not give us insight into a participants' immediate perceptual awareness of presence. Since the definition of presence is rooted in its impact on immediate phenomenology (Burdea & Coiffet, 2024), this raises further questions about how to incorporate other measures besides questionnaires into experiments attempting to measure presence (Usoh et al., 2000).

Additionally, it may be that differences between behavioural and questionnaire measures of presence are due to the nature of the virtual stimuli and the environment. Recent thinking in the field of cognitive neuroscience has placed emphasis on the way in which we present stimuli to participants. In a vast majority of cases, the stimuli used in these experiments are proxies of realism (Snow & Culham, 2021) -by which we mean 2D or 3D images meant to represent real-world stimuli (for an example of this, see Magritte's famous work "Ceci n'est pas une pipe" (Magritte & Torczyner, 1994)). In our case, and the case of other experiments using both VR headsets alongside haptic stimulation, the stimuli presented to participants in VR are not mere proxies for reality, but as close to real objects as one could feasibly get whilst controlling for various confounding variables within an experimental context (Singleton & Fotopoulou, 2026). It may be the case that 3D virtual renderings of objects in an embodied space produce faster reaction time measures in visual conditions because the brain utilizes isolated visual input as a highly efficient, feedforward spatial radar to initiate rapid motor choices (Gomez et al., 2018). Conversely, haptic feedback provides greater perceptual accuracy and retrospective judgements of 'realness' because interacting with an actionable, tangible asset recruits distinct mechanisms that satisfy the brain's evolutionary requirements for physical interaction and object solidity (Snow & Culham, 2021). This may explain why participants had a greater accuracy at identifying virtual objects via haptics alone and also reported these objects as feeling more real, though they were slower at reacting to them since the 'realness' of the object compared to the 3D visual-only render recruited a wider assortment of brain mechanisms (Gomez et al., 2018; Snow & Culham, 2021). This raises significant questions about how best to experimentally measure concepts such as presence as well as implement multimodal virtual environments, since presence relies on the subject feeling as if they are in a real environment and interacting with real objects.

Although we found no difference in metacognitive ability between unisensory touch and unisensory visual trials in our confidence block, exploratory analysis 3b did find that participants were significantly more accurate in unisensory touch trials compared to unisensory visual trials. This lends some very limited support to hypothesis 3, though the lack of a significant difference regarding metacognitive ability means that we should also reject this hypothesis. However, we also found that participants were more accurate in multisensory conditions where touch was presented before vision than conditions in which vision was presented before touch. Importantly, these findings cannot be explained by any subjective or objective difference in difficulty in discriminating between noise and target visual and touch trials, since these factors were controlled for in two control tasks (VDT and HDT) administered prior to the experiment. These findings to be consistent with previous literature, in that touch has been found to induce greater confidence about the identity of objects than vision in cases where the object is perceptually ambiguous (Fairhurst et al., 2018; Wijntjes et al., 2009). Since both our visual and haptic stimuli were designed to be perceptually ambiguous, it seems plausible that participants would therefore be more accurate at identifying ambiguous stimuli via touch than via vision. These findings also suggest that although we utilised novel technology to deliver the feeling of touch to participants in VR, that this novelty did not negatively impact participants ability to discern between target and non-target stimuli through touch. This provides some level of validation for the materials used in the experiment.

Our finding that participants exhibited significantly lower metacognitive efficacy and less accuracy in unisensory conditions compared to multisensory conditions is consistent with previous literature from the field, lending some validity to our paradigm. Multiple previous studies testing participant response in a variety of experimental paradigms, including reaction times, discriminatory ability and perceptual accuracy (Cooper et al., 2018; Marucci et al., 2021; Uemae et al., 2015) have found that, broadly, participants perform better in tasks in which they are given multisensory cues compared to unisensory cues. However, fewer studies have investigated the role of metacognition in incoming multisensory vs unisensory perceptual information (Kimmet et al., 2023; Meijer & Noppeney, 2023). Our finding that participants experienced greater metacognitive efficacy regarding perceptual discrimination in visuo-touch conditions compared to vision-only or touch-only conditions may be a significant contribution to the field of multisensory integration. Additionally, although we did find that multisensory conditions increased presence, reaction time and accuracy over unisensory conditions, these results may understate the true impact of congruent multisensory stimuli on presence since our multisensory stimuli were always temporally incongruent.

Future studies could address these limitations in a number of ways. First, future studies intending to investigate similar questions regarding the relative importance of touch vs vision on the sense of presence should be careful to match visual and touch dominance. Importantly, avoiding any task-relevant information which is only presented in one sensory domain. Secondly, it may be of interest to the field as a whole for future studies to attempt to decipher the role of task engagement in the creation of the sense of presence. If undertaking different types of task within the same virtual environment causes shifts in how present a participant feels within the VR simulation, this may have crucial implications when it comes to translating psychological research undertaken in VR into real-world applications.

5. Summary

This study investigated the relative contributions of touch and vision to the Sense of Object Presence (SOOP) in VR, utilizing novel mid-air haptic technology (ultrasound) to simulate tactile feedback without physical intermediaries. Across a sample of 44 participants, we employed a rigorous dual-paradigm approach, contrasting implicit behavioural measures (reaction times verified against attention and risk-taking controls) with explicit metacognitive judgments.

Our results confirmed that multisensory integration significantly enhances metacognitive efficacy, accuracy, and reaction speeds compared to unisensory conditions, independent of temporal order. However, a key dissociation emerged between unisensory modalities: while participants reacted significantly faster to visual stimuli, they achieved higher perceptual accuracy with touch. Furthermore, although reaction times correlated with general presence scores, participants retrospectively rated touch as feeling significantly more "real" than vision. These findings suggest a disconnect between the immediate, action-oriented "felt" presence dominated by vision and a reflective "judged" presence where touch is dominant. By validating these effects using contact-free haptics, this research offers a new insight into how measures of presence are collected in virtual reality studies.
