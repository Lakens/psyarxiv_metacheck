Meta-scientific research has shown nonsignificant p values are commonly misinterpreted. It is incorrect to infer that there is ‘no effect’, ‘no difference’, or that groups are ‘the same’ after p > 0.05.

How Exact P-Values works

List any p-values reported with insufficient precision (e.g., p < .05 or p = n.s.), reported as exactly zero (e.g., p = .000), or impossible (below 0 or above 1, e.g., p = -.22).

This module uses regular expressions to identify p-values. It will flag any values reported as p > ? or p < numbers greater than .001. It will also flag p-values reported as exactly zero (e.g., p = .000, p = 0.00), which are mathematically impossible — p-values are never exactly zero and should instead be reported as p < .001.

A p-value that is not the result of a test is not flagged: a table note (“* p < .05, ** p < .01”), a figure legend (“Asterisks indicate significant differences (p < .05)”, “Values in bold are significant at p < .05”) or a stated threshold (“p < .05 was considered significant”, “thresholded at p < .001”). GROBID often puts such notes into the running text, so each p-value is judged by the words in its own clause (the text up to a “;” or a full stop), and never left out when a test statistic belongs to it (“F(1, 7) = 8.03, # p < .05”). The column not_a_test of the table says why a p-value was left out (“marker”, “threshold”, “legend” or “named”).

A p-value with the name of a correction or a test after the p (“pFWE < .05”, “padj < 0.05”, “p Wilcoxon = .02”) is flagged only when a test statistic comes before it in its clause (“t(37) = 7.17, p FWE < .05”). Without one it is mostly the rule that decided what was significant (“genes with padj < 0.05 were selected”); such a p-value is “named” in not_a_test. Notes in other forms, such as a marker after the p-value (“p < .05 (*)“), are still flagged.

A p-value below 0 or above 1 is impossible; it is listed apart and not also as imprecise. Often the statistic before it, or its minus sign, was copied into it (“t(134) = -2.32, p = -.13”, “Z = 3.091, P = 3.091”). A value above 1 is listed only after a test statistic in its clause: without one, a “P” above 1 was nearly always another quantity (a proportion, pH, a group’s mean, a model parameter). A number in scientific notation whose power of ten was lost when the PDF was read (“p = 2.4 x 10 -9” read as 2.4) is not listed. A “p” that is the subscript of another symbol (“r p = .64”, “²p = .02” for partial eta squared, “Δp = .33”), or a quantity with a unit, a logarithm or a ratio (“P = 2.9 µm”, “-log10 P = 7.5”, “Ca/P = 1.67”), is not read as a p-value at all (see extract_p_values()). Each p-value has its own row, also when the same one is written twice in a sentence.

This module sometimes flags false positives when sentences discuss how p-value thresholds were set. It can also miss an imprecise p-value that is reported against a threshold (“decreased at the p < .05 significance threshold”).

This module only checks p-values reported in the running text of the manuscript. It cannot (yet) process p-values reported only in tables (as opposed to a table’s footnote text, which the module does see and tries to exclude — see above).

How Code Check works

This module retrieves information from repositories checked by repo_check about code files (R, Python, SAS, SPSS, Stata, Mplus, MATLAB).

The Code Check module checks R (also R Markdown and Quarto), Python (also Jupyter notebooks), SAS, SPSS, Stata, Mplus, and MATLAB files, using regular expressions to check the code; JASP files are listed but not read. The language of a Quarto document or a notebook is read from the file itself (its engine or kernel), not from its extension. The regular expression search will detect the number of comments, the lines at which libraries/imports are loaded, attempts to detect absolute paths to files, setwd() and install.packages() calls, and lists files that are loaded, and checks if these files are in the repository; R code is also parsed. The module will return suggestions to improve the code if there are no comments, if libraries/imports are loaded in lines further than 4 lines apart, if files that are loaded are not in the repository, if absolute file paths, setwd() or install.packages() are found, and if R code cannot be parsed.

The regular expressions can miss information in code files, or falsely detect parts of the code as a fixed file path. Libraries/imports might be loaded in one block, even if there are more than 3 intermittent lines. The module was tried out internally on papers published in Psychological Science, but has not been formally validated. There might be valid reasons why some loaded files can’t be shared, but the module can’t evaluate these reasons, and always gives a warning.

The module also checks whether the repository pins the R/package versions the analysis actually depended on: an renv.lock file (parsed for the R version and every locked package + its version/source), a sessionInfo()/sessioninfo::session_info() text dump (matched by filename — sessionInfo.txt/session_info.txt and similar, or embedded in a README), or a groundhog::groundhog.library()/checkpoint::checkpoint() date-pin call in the code (a bare library(groundhog)/library(checkpoint) does not count — the pinning call itself must be present). When none of these is found, the report flags it as a reproducibility gap: package versions may drift between when the analysis was run and any later reproduction attempt.

If you want to extend the package to perform additional checks on code files, or make the checks work on other types of code files, reach out to the Metacheck development team.

Without a key, every Dryad-hosted code file is listed but unchecked, and a warning naming Dryad and ?dryad_pat/?dryad_auth is included among the download failures recorded in the manifest.

How Data Check works

This module classifies the files in a repository into semantic types (data, codebook, code, software, output, supplemental, readme, asset, other) and, for tabular data files, extracts each column’s type and summary statistics.

The Data Check module consumes the file list produced by repo_check (or any files added via local_path). Each file is classified with rule-based heuristics layered over metacheck’s file_category() and file_types: file names matching README / codebook patterns win first, then an extension crosswalk, then format-locked extension overrides. For every file classified as tabular data that is available locally, the module reads the file head, describes each column with data_col_facets() and computes summary statistics for numeric columns. Every sheet of a spreadsheet that holds a table is read: a file with several such sheets has its columns under source_file = "file.xlsx [sheet]", and the sheet column names the sheet of any spreadsheet with several sheets; a sheet of notes or a codebook is treated as documentation when the file has another table. Following DDI, a column is described by orthogonal facets rather than a single type: representation (numeric/text/datetime/code — how it is stored), measurement_level (Stevens: nominal/ordinal/interval/ratio), concept (what it measures: reaction_time/age/gender/likert/id/…), role (identifier/measure/condition/timestamp), unit, and a quality state (ok/empty/constant). Concepts are detected by name+value rules (the demographic concepts via data_check_demographic()); when llm_use(TRUE) the model fills concepts and measurement levels the rules left blank. Qualtrics survey exports are recognised (data_check_is_qualtrics()): their extra header rows are stripped so columns type correctly, and the reserved response-metadata columns (StartDate, Duration, Finished, …) are tagged.

The module defaults to rules-only when llm_use(FALSE): columns the rules cannot resolve (ambiguous 3–20-unique integers, ambiguous character columns) fall back to continuous / text respectively. When llm_use(TRUE), ambiguous columns and unresolved file types (other) are sent to llm() for optional refinement, and every file is assigned a study group (ex1, pilot2, shared, …) so that multi-study repositories can be recognised (used by psychds_check). Without an LLM the study group is left NA (unknown).

Column extraction requires files to be readable from disk. Files fetched by repo_check from OSF/GitHub/etc. without a local copy (file_location is NA) are classified but not column-extracted; pass local_path to point at a downloaded copy of the repository.

For a paper whose repository is on Dryad, this means column extraction never happens unless a Dryad API key is set: Dryad requires one to download file bytes, even from a fully public dataset (dataset listing and metadata do not need one). Without a key, every Dryad file stays classified but un-downloaded, column_n is 0, and a warning naming Dryad and ?dryad_pat/?dryad_auth is included among the download failures. A one-time session message is also shown (see repo_check) the first time a Dryad dataset is encountered with no key set.

How Reproducibility Check works

This module assesses whether a paper’s R and Python code can be run on its data. It works in two phases. The static phase (always run) collects the package dependencies the code declares, rewrites the data-file paths that do not work in the repository as the authors organised it, works out the order the scripts must run in, and diagnoses why any referenced input file is unavailable — reporting what a reproduction attempt would involve and where it is likely to break. The execution phase (opt-in, execute = TRUE) then actually runs the code: it copies the repository into a throwaway directory, optionally installs the declared dependencies into a throwaway library, runs each script in order in an isolated subprocess with a per-script timeout, and captures the outcome and full output of each run.

By default (execute = FALSE) the module does not run any code — it performs only static analysis: reading dependencies with the same extractors as code_check, finding the files the code references in the repository, and building a run-order dependency graph. It reports what would be installed and run rather than doing it.

When execute = TRUE, the module additionally runs the downloaded code on your machine — a deliberate, opt-in action gated behind that argument (callr is required for R code). Each script runs in an isolated subprocess so a crash cannot take down the R session; note this isolates crashes, not the filesystem or network. Installs (when install_missing = TRUE) and the throwaway run library never touch your main R library. Each script’s outcome is one of ran_ok, errored, timed_out, dependency_unavailable, not_parsed, run_by_source (an R script another script runs with source(), which is run only inside that script, since on its own it lacks the packages and objects the sourcing script sets up first), run_by_import (a Python file other files import, a module rather than a script, unless it has an if __name__ == "__main__": block), jags_model (a JAGS or BUGS model saved with an R extension, which another script reads) or not_r_content (a file that is not R at all, such as a JSON or HTML dump); these last two are not run and are not failures. python2 marks Python 2 code that was not run. With sandbox = "docker" such code runs with Python 2.7 (option metacheck.docker_image_py2; FALSE turns this off), which modifications records; it is never converted, since that can change results. defines_functions is a file that only defines functions, which is used, not run (table$used_by names the scripts that use it), and not_analysis is a file of software rather than of the analysis: a package’s code, tests, documentation or setup.py, a copy of a tool, a web application, a script a program wrote (table$not_analysis_why says which); neither is run or counted as a script. docker_failed means the container never started, which says nothing about the script, so it keeps the light from being green but does not make it red. needs_a_person is a script that stopped because it asks a person to choose a file or answer a question, or that starts an app, and needs_internet one that stopped because the network is off in a Docker run, or, with internet = TRUE, could not reach what it asked for; download_too_large is a script stopped for downloading more than the limits allow (see internet), and out_of_memory one that, or a program it started (such as a compiler), ran out of the memory each script may use. All four are treated the same way. not_downloaded is a script that stopped on a file the repository lists but that was not downloaded, such as one over max_file_size: it could not be tried, so it is not counted as a script that did not reproduce (summary_table$repro_not_downloaded_n counts them apart). not_read is a file metacheck could not read, so it was not run; the light is then not green, as the file may read and run on another computer, and table$error_message says why, naming a package that is installed but cannot be loaded on the computer that ran the check. empty is a file with nothing in it, which is not run or counted as a script. For a script that did not run through, table$error_message is its error, short (at most 300 characters): the error line of its output, which names a package that is not there, with the address it asked for when it needed the internet, or the time limit it reached; table$reason sorts it into a kind. A timeout means “still running at the cutoff”, not a failure, so raise timeout for legitimately long-running (e.g. Bayesian) scripts. dependency_unavailable means the script’s own package could not be installed from live CRAN, the CRAN Archive, or a named GitHub/URL source — an infrastructure limitation, not a defect in the paper’s code. The full stdout/stderr of every run is kept in the result’s run_results (the report shows it in per-script dropdowns, capped for readability).

Provenance, kept so that a TRACE Research Object (TRO) declaration of the run can be written later from a stored result (metacheck #404; the helpers are in R/provenance.R). Only when code was run (execute = TRUE): * run_results$started_at, run_results$ended_at: when each run of a script started and ended (ISO 8601, UTC, milliseconds); NA for a script that was not started. A script run again in a later pass has the times of its last run. A TRO uses them for each trov:TransparentResearchPerformance. * run_results$exit_status: the exit status of the process that ran the script (0 = ended normally); NA when the process did not report one (a time limit, or Docker failing to start the container). * artifacts: one row per file, with stage (deposit: as downloaded from the repository, hashed from the downloaded file; before_run: the run folder just before the first script ran, after metacheck’s own changes, such as rewritten paths and unpacked archives; after_run: only the files the scripts made (status new), changed (changed) or removed (removed), as an unchanged file is the one listed before the run), path (relative to the run folder, as valid UTF-8, a byte of another encoding written as <xx>), size (bytes), sha256, mime_type (by extension, NA when unknown), source (the file’s address in the repository, for deposit). The package libraries metacheck installs in the run folder are left out, as are metacheck’s own files there (a script’s runner, and the statistical output it writes in statistical_output/). Files metacheck itself copied or made between passes (see modifications, output_copied, file_placed) show in after_run too. A TRO uses the rows as trov:ResearchArtifacts and each stage as a trov:ArtifactArrangement. * modifications$sha256_before, modifications$sha256_after: the hash of the changed script as downloaded and as it ran; NA when the script is not at the same path in both (a script made from an R Markdown file). * environment: the system that ran the code (trov:TransparentResearchSystem in a TRO): metacheck_version, started_at, ended_at, host (R version, platform, operating system), sandbox, network_isolated (TRUE only when every Docker run had --network none; the process sandbox does not stop the network), internet, timeout_per_script, total_timeout, python_local (the Python run outside Docker and its version), and docker: runs (for each kind of run, r_run, r_install, python_run, python_install, the image and the docker run arguments, such as --network none, --read-only, --cap-drop ALL, no-new-privileges, the process limit and the memory and processor limits) and images (for each image, its ID and digests from docker image inspect, its creation time and the R and Python versions its environment declares).

It is NA for files run inside another script, files that are not an analysis, files not read, and a Docker failure. summary_table counts each group (repro_ran_n, repro_code_error_n, repro_dependency_n, repro_time_n, repro_not_checkable_n), and the report’s first sentence gives them. The traffic light reflects the static readiness signals by default; a script in code_error that stopped with an error makes it red, as a script that crashes on its own analysis is a genuine reproduction failure, and a script in one of the other three groups keeps it from being green. Calls that need a screen, which the run does not have (dev.print(), dev.copy2pdf(), dev.copy2eps(), savePlot(), windows(), win.graph(), x11(), quartz(), View()), are replaced before the run by calls that need none, which modifications records as screen_call_replaced. A script that fails with could not find function is run once more with the library() calls the project’s other scripts make added at its top (or the one package that exports the function, or magrittr for %>%), and a script that then runs is reported as reproducible only after that repair.

Dependencies are reported name-only, with the source (CRAN, GitHub, or a base package already shipped with R) — static analysis of the code cannot know which version was used, and running against current package versions is itself informative: a break argues the authors should have pinned versions. When the repository does record versions, a run with recorded_versions = TRUE installs the packages the scripts load at those versions, but it does not change the R version, which remains a limitation of the check.

Run order is derived from read-after-write data dependencies (a script writing a file another reads must run first), source() edges, and numeric filename prefixes as a weak tie-breaker. Ambiguous orderings, dependency cycles, and inputs a script reads but that no earlier script produces (and that are not in the repository) are surfaced as warnings, since these are the situations most likely to make an otherwise-correct reproduction fail.

Python code (.py files, and notebooks and Quarto documents whose code is Python, from which the code is extracted first) goes through the same two phases, reported in its own “Python code” section. Each file is checked for syntax errors with Python’s own parser when a Python interpreter (python, or else python3) is available; dependencies are read from the import statements, with versions from a requirements.txt or pyproject.toml when there is one, and installed with pip; each script runs as its own python process (processx is required), so unlike R scripts, a name one script defines is not available to another. When no Python interpreter is available, the Python files are reported as not run and the R results are still returned. Statistics the Python scripts print are compared with the paper together with the R output and any self-reproducible output (JASP/jamovi, SPSS-Viewer, notebook outputs).

Abstract

Voluntary task switching (VTS) provides a useful paradigm for examining how recent reward outcomes are associated with the balance between cognitive stability and flexibility. We investigated whether reward-history effects on task choice varied as a function of cueoutcome contingency. Participants (N = 616) completed a VTS task with performance-contingent rewards. Reward contingency was manipulated between-subjects at probabilities of100%, 80%, 70%, and 60%. Switch probability was modeled using logistic mixedeffects regression. The relationship between prior reward outcomes and the current reward prospect in predicting switch behavior differed across probability conditions. Reward transition effects were larger at 100% and 80% than at 70% and 60%. Secondary analyses further indicated that outcomes that were unexpected given the cuereward mapping were associated with subsequent switching in some comparisons, although evidence that these associations systematically varied with probability was mixed. Because task choices did not influence reward outcomes, the observed effects are more consistent with carry-over associations between reward history and task selection than with reward-guided exploration or reward maximization. Exploratory individual-differences analyses suggested that reward transition effects were more pronounced in males than in females; additionally, traitlevel reward sensitivity moderated the magnitude of reward transition effects on switch behavior. Overall, the findings are consistent with the hypothesis that cue-outcome contingency modulates the extent to which recent rewards are followed by particular task-choice patterns, although further research is required to clarify the mechanisms through which reward uncertainty may contribute to these effects.

Dysregulation of this balance has been implicated in a range of psychiatric and neurological conditions (Goschke, 2014; Grant & Chamberlain, 2023; F. Lange et al., 2017; Uddin, 2021). Therefore, a central question concerns the mechanisms that govern how individuals dynamically adjust stability and flexibility in response to environmental and internal signals.

A common approach to studying this balance is the task-switching paradigm, in which participants alternate between different tasks. In this context, the switch cost, the performance decrement (e.g., slower responses or reduced accuracy) when switching tasks compared to repeating the same task, serves as an index of the efficiency of cognitive flexibility (Koch et al., 2018; Meiran, 2000; Monsell, 2003). The voluntary task switching (VTS) paradigm extends this approach by allowing participants to freely choose which task to perform on each trial (Arrington & Logan, 2004 , 2005; Mayr & Bell, 2006). This agency provides an additional measure of control allocation: the voluntary switch rate, or the proportion of trials on which participants choose to switch tasks.

A well-established result in the VTS literature is the repeat bias, whereby participants exhibit a systematic tendency to repeat tasks more frequently than they switch between tasks. This tendency is informative about how individuals allocate cognitive control, and variability in repeat bias has been linked to differences in control engagement and neural activity (Orr & Banich, 2014; Orr & Weissman, 2011). Several accounts have been proposed to explain this bias, including limitations in working memory, habitual response tendencies, and the perceived cost of engaging cognitive control (Arrington & Logan, 2005; Braun & Arrington, 2018; Brosowsky & Egner, 2021; Demanet et al., 2010; Mayr & Bell, 2006; Vermeylen et al., 2022). In particular, the engagement of control required for task switching may be experienced as effortful or aversive, leading individuals to favor repetition over switching (Kool et al., 2010; Westbrook et al., 2013).

Importantly, these accounts align in suggesting that repeat bias stems not only from capacity constraints, but also from differences in the willingness to recruit cognitive control. A large body of research demonstrates that effort expenditure is sensitive to motivational factors, particularly rewardSummerside et al., 2018; Treadway et al., 2009. In particular, performance contingent rewards have been shown to promote proactive control and improve maintenance of task-sets, thus promoting cognitive stability Fröber and Dreisbach, 2014; LOCKE and BRAVER, 2008 (Chiew & Braver, 2013; Hefer & Dreisbach, 2017). In contrast, rewards not tied to performance can have qualitatively different effects, sometimes reducing proactive control engagement (Fröber & Dreisbach, 2016a). Moreover, Manohar and colleagues (2017) demonstrated that although contingent and non-contingent rewards can influence performance, they do so via dissociable mechanisms, with only performancecontingent rewards producing the largest improvements in response speed. Together, these findings highlight that reward modulates cognitive control in complex ways, influencing not only how efficiently control is implemented, but also the extent to which it is engaged.

In addition, trial-to-trial transitions in reward magnitude can moderate the balance of stability and flexibility in voluntary task switching (Balcazar & Orr, 2025; Fröber & Dreisbach, 2021; Fröber et al., 2018 Fröber et al., , 2019)). Because task choices do not alter reward probability or magnitude, these effects are typically interpreted as carryover influences of recent reward history on subsequent voluntary behavior, rather than goal-directed reward optimization. Within the stabilityflexibility framework, such reward transition effects have been interpreted as reflecting adjustments in meta-control parameters that regulate the balance between maintaining and updating task representations (Eppinger et al., 2021). As such, these adjustments may reflect adaptive tuning of control states in response to environmental signals (Fröber & Dreisbach, 2021). This is one possible account of the observed behavioral carry-over; reward-transition effects alone do not establish that participants adaptively tune control states or identify the process that produces the effects.

An open question concerns how the reliability of reward cues modulates reward transition effects. Previous studies have largely used deterministic reward schedules, in which reward outcomes are fully predictable given successful performance (Fröber et al., 2018 (Fröber et al., , 2019 (Fröber et al., , 2020)). Such deterministic mappings may produce strong, reliable meta-control signals. However, real-world environments sometimes involve uncertainty about the delivery of rewards. Stochastic reward schedules, where rewards occur with some probability, make reward expectations less dependable and can thus diminish the impact of reward-related signals on how control is allocated. (Platt & Huettel, 2008). If reward transitions act as meta-control signals, then their influence should depend on the degree to which reward outcomes are expected and interpretable.

The present study investigates whether graded reductions in cue-outcome contingency through probabilistic reward delivery attenuate reward transition effects. Using a between-subjects design, we manipulated the reward contingency with four levels of reward probabilities (100%, 80%, 70% and 60%) while keeping performance requirements constant. Participants were presented with cues normally worth a low (1 cent) or high (10 cents) amount of reward, but depending on the reward probability, on a portion of trials they would receive the alternate reward amount (i.e., 10 cents instead of 1 cent). Crucially, reward transitions were defined based on experienced outcomes rather than cued expectations, allowing us to examine the association between recent reward history and subsequent behavior, including outcomes that were unexpected relative to the cue's programmed reward schedule. These outcome contrasts are not direct estimates of computational reward prediction errors: participants' trial-by-trial expectations and learning processes were not measured or modeled.

Because task choices do not influence reward outcomes, any effects of reward contingency are interpreted as incidental influences of the reward history on subsequent task selection, rather than strategic attempts to maximize reward through task choice. Regarding outcomes that were unexpected relative to the cue schedule, we predicted that participants would likely switch tasks following worse than expected outcomes and repeat tasks after better than expected outcomes. This directional prediction is motivated by reward-learning accounts (Schultz et al., 1997), but the present design does not distinguish prediction-error learning from other processes that could produce outcome-related carry-over. Finally, we explored individual differences by testing gender and reward sensitivity (BIS/BAS-Reward Responsiveness), predicting more preserved transition effects under higher uncertainty with higher BAS-Reward Responsiveness and greater sensitivity to unexpectedly low rewards with higher BIS (Joue et al., 2022; Smillie et al., 2006).

Method Participants

A total of 715 undergraduate students at Texas A&M University enrolled in this study for course credit. The sample size was not determined a priori; we had the goal of collecting a large sample in order to have sufficient power to look at individual differences in a complex design. Data were collected between Fall 2021 and Fall 2022 during the COVID-19 pandemic. Although we were able to collect data in person at this time, a large number of restrictions were in place that limited throughput, so data were collected online concurrently. The administration platform (in person or online) was included as a covariate to examine the effects of the platform and control for differences. For online data collection, participants were required to have a computer equipped with a keyboard and running Windows, MacOS, or Linux; this was enforced through JavaScript code. We also asked participants to report information about their surroundings, e.g., noise level and possible distractions. We reviewed this information for possible exclusion and did not identify any notable responses. Participants completed one of four experimental conditions manipulating cue-outcome contingency: specifically, conditions with 100%, 80%, 70%, and 60% probabilities for the reward cue. The final sample consisted of 171, 144, 170, and 131 participants in each of these respective groups. As shown in Table 1, data collection was not concurrent across all reward-probability conditions. Thus, the reward probability condition was partly aligned with data collection semester and cohort. The proportion of participants tested online also varied across conditions. We therefore cannot rule out the possibility that differences between conditions reflect cohort, semester, or related changes in data collection, in addition to differences in cue-outcome contingencies. Participants received course credit for participating, and the money the participants earned in the experiment was paid as a bonus through an Amazon.com gift card. All participants gave their informed consent and study procedures were determined by the Texas A&M University Institutional Review Board to involve only benign behavioral interventions according to the Revised Common Rule, and qualified as exempt research.

Stimuli and procedure

Before the task, participants responded to several questionnaires to collect demographic data, history of substance use, as well as the BIS-BAS (Behavioral Inhibition Scale -Behavioral Approach Scale) (Carver & White, 1994) to determine reward responsiveness and behavioral inhibition. While the full BIS-BAS scale was administered, we only included the BIS and BAS-Reward Responsiveness subscale.

The experiment was programmed in PsychoPy (Peirce et al., 2019). For online administration, the task was converted to JavaScript in PsychoPy and then uploaded and hosted on Pavlovia. Online studies through PsychoPy have been shown to have excellent timing and precision (Bridges et al., 2020). Before starting the experimental task, the participants completed a training session designed to familiarize them with the value most associated with each reward cue. These cues, which consisted of a simple polygon (circle, hexagon, diamond, or star), were predominantly associated with low or high monetary reward ($.01 or $.10), with two cues associated with each reward level. One of the cues was displayed on the left side of the screen, while a different cue was displayed on the right side; each cue was positioned at a distance equal to 10% of the height of the screenfoot_0 . The pair of shapes were presented for a maximum duration of 3000 ms or until the participant selected a shape using a left or right button press ('a' or 'l'); notably, the buttons used were distinct from those used for task responses. Upon making a response (or after 3 seconds elapsed), the participants were informed of the monetary amount they received ($.01 or $.10), unless no response was made, in which case they received no reward ($0.00) and were instructed to respond more quickly ("Respond Faster!"). Feedback was displayed for 1500 ms. The reward probability during the training phase was consistent with that of the main task, although there were no response performance requirements for reward in the training phase. The next trial began following a 1000 ms inter-trial interval (ITI). The participants completed 3 blocks of 32 trials, with three repetitions of each pairing of cues.

During the primary task phase of the experiment, a reward cue was followed by a target stimulus and finally by feedback indicating any reward received, as shown in Figure1. A single shape (from the same set used during the training phase) was displayed centrally on the screen for a duration of 1500 milliseconds. The target stimuli were randomly selected from a set of digits (125, 132, 139, 146, 160, 167, 174, 181) and letters (B, D, F, H, S, U, W, Y), with one of each selected. One stimulus was presented above fixation and the other was presented below fixation, with each appearing at a distance equal to 10% of the height of the screen. These stimuli were presented in Arial font at a size of 5% of the height of the screen. For the numerical task, the digit was categorized based on the numerical value being less than or greater than 153. For the letter task, the letter was categorized according to its proximity to the beginning or end of the alphabet. Participants engaged with the task on top using their left hand, specifically the "D" and "F" keys on a QWERTY keyboard, and with the task located at the bottom using their right hand, using the "J" and "K" keys. We counterbalanced which stimulus appeared on the top or bottom among the participants. The target stimuli remained visible on the screen until the participant provided a response or a maximum duration of 3000 ms was reached. Upon response, feedback was presented for 1500 ms. The feedback for the rewarded phase was the same as in the training phase.

In order to set reaction time thresholds for fast responses during the reward phase, participants first completed 64 trials without rewards. Although the cues were presented, participants were instructed to ignore them. The feedback contained only information on the accuracy of the participant. From the performance in this block, an initial threshold of the 33rd percentile was set for the rewarded blocks. Separate thresholds were established based on the task and whether the trial was a task repeat or switch. The thresholds were updated after each block, based on cumulative correct trials for each condition. On error trials, the feedback said "Error," and on trials in which a response was not made within 3000 ms, it said "Please respond!!". For low-reward trials, there was no speed requirement, only an accuracy requirement. For high-reward trials, a reward was only given if the response was correct and faster than the speed threshold. If the response was correct, but not fast enough, the participant received 0 cents and feedback that said "Respond Faster!" The next trial began after a 1500 ms inter-trial interval.

Following the training period, but before starting the primary task, participants individually practiced the two tasks. They were given eight trials and had to achieve an accuracy rate of 80%; otherwise, the practice was repeated up to 3 times. If participants did not achieve the required accuracy after 3 blocks, the study was terminated. After successful practice of each task, participants practiced switching between the two tasks. The instructions were to "aim to perform each task equally but in a random sequence, akin to a coin flip deciding your task. Refrain from predictable strategies, such as alternating tasks with each trial or counting them." Participants completed 16 trials and would repeat the practice if they did not achieve at least 80% accuracy and/ or switched tasks between 20% and 80% of the time. Participants could repeat this practice up to three times, and the study ended if the required performance was not achieved. Subsequently, participants performed 64 non-rewarded trials to set the initial thresholds for performance-contingent reward in the rewarded phase. The instructions on random task selection were reiterated, but there was no feedback on the probability of switching in the block. The participants then proceeded with the reward phase, which consisted of 8 blocks of 32 trials. Participants received the following instruction: "The shapes are worth the same amount as they were in the [training phase]. At the end of each trial, you will be told how much you received on that trial. Your cumulative total will be displayed at the end of each block." No other instructions pertaining to task choice were given.

Analysis

Previous research has often defined reward transitions based on the relationship between consecutive reward prospects (i.e., the identity of the cue). However, this approach may obscure the role of experienced outcomes, particularly in cases where the cued reward is not delivered due to performance failures. Notably, failures to obtain a high reward due to slow response may be experienced as especially salient events. Prior work suggests that higheffort, high-reward contexts can be experienced as aversive when effort requirements are not met or rewards are not obtained (Kool et al., 2010; Westbrook et al., 2013). Additionally, asymmetries in reward contingencies, such as stricter response thresholds for obtaining high relative to low rewards, may amplify the behavioral impact of such outcomes (Fröber & Dreisbach, 2016b; Fröber et al., 2018 Fröber et al., , 2020)) (Shen & Chun, 2011, Expt. 1). In the present framework, these factors are expected to influence the magnitude of outcome-driven biases on subsequent behavior, rather than reflecting deliberate avoidance strategies.

To isolate these outcome-driven influences, we defined reward transitions based on experienced reward outcomes on the preceding trial. Specifically, we examined the extent to which different classes of prior outcomes biased subsequent voluntary task selection using two orthogonal contrasts. The first contrast compared trials following high-reward outcomes (10 cents) to trials following no-reward outcomes resulting from slow responses (High Fast vs. High Slow), capturing the influence of successful versus unsuccessful performance under high-reward conditions. The second contrast compared trials following low-reward outcomes (1 cent) to those following high-reward outcomes (High vs. Low), indexing the effect of reward magnitude on subsequent behavior. Notably, we reserved trials with better-or worsethan-expected outcomes for separate analyses for expectation violations. As a comparison to existing studies with transitions of reward prospects, we conducted a confirmatory analysis when we examined the influence of reward contingencies on reward prospect transitions. This analysis is presented in the Supplementary Results C.

Unexpected outcomes offered an opportunity to test whether outcomes that deviated from the cue schedule were linked to subsequent task choice. In secondary analyses, we therefore examined how better-and worse-than-cued reward outcomes on the preceding trial were associated with current-trial behavior. These analyses were conducted separately for high-reward and low-reward cue trials. For high-reward cue trials, we compared trials preceded by the expected outcome (10 cents) with those preceded by an unexpectedly lower outcome (1 cent). For low-reward cue trials, we compared trials preceded by the expected outcome (1 cent) with those preceded by an unexpectedly higher outcome (10 cents). Importantly, because task choices did not affect reward probability or magnitude, these analyses assess associations between recent reward history and voluntary task selection, not whether participants adaptively selected tasks to maximize reward. Because subjective expectations were not measured and learning was not modeled, the outcome contrasts should not be interpreted as quantitative reward prediction errors. Together, these contrasts allow us to test whether different features of recent reward experience-outcome success, reward magnitude, and outcomes unexpected relative to the cue schedule-are associated with subsequent voluntary task selection, and whether these associations differ across rewardprobability conditions.

Most previous voluntary task switching studies calculate a voluntary switch rate (i.e., the proportion of switch trials) for each condition of interest, which is then examined with a repeated measures ANOVA. This procedure averages over trials without weighing the averages by the total number of trials within a condition. This procedure also requires dropping participants with a low number of repeat or switch trials in any given condition. To avoid these shortcomings, we used a (generalized) linear mixed-effects modeling framework, which leverages trial-level data and can improve efficiency and handling of unbalanced designs relative to ANOVA approaches (Gelman, 2006). For the primary analyses, sum contrasts were defined for the following fixed factors: task transition or alternation, currenttrial reward prospect, and administration platform. Custom contrasts were used for the previous reward outcome to contrast 1) high-reward trials with fast responses (referred to as 'hi') and high-reward trials with slow responses without reward (referred to as 'hiSlow'), and 2) high-reward trials with fast responses with low-reward trials with low reward outcomes (referred to as 'lo'). Orthogonal polynomial coding was used for reward probability with linear, quadratic, and cubic contrasts for the four levels (100%, 80%, 70%, 60%). For the secondary analyses examining reward expectancy violations, we used the same modeling framework but replaced the previous reward outcome contrasts with contrasts comparing expected versus unexpected reward outcomes, analyzed separately for high-reward and lowreward cue trials. That is, one contrast was defined to compare high reward cue trials when the expected high reward outcome was received ('hi') compared to when the unexpected low reward outcome was received (referred to as 'hi-'), and another contrast was defined to compare low reward trials where the expected low reward outcome was received ('lo') compared to when the unexpected high reward outcome was received (referred to as 'lo+').

We analyzed descriptive statistics for reaction time, accuracy, task choice (number or letter), and probability of switching tasks, excluding participants with values marked as extreme outliers through the boxplot methodfoot_1 . Data from 43 participants were not usable due to incomplete data, and data from 56 participants were removed due to extreme outliers. We also removed trials with reaction times less than 200 ms, trials following errors, and trials with errors (except in the analysis of accuracy) prior to analysis.

For each dependent measure (switch probability, reaction time, and accuracy), the optimal model was determined by comparing model fit. The initial model we considered included all interactive effects between task transition (except for the analysis of task switch probability), previous reward outcome, current reward prospect, reward probability, and administration platform, with trial number included as an additional covariate to account for drift. We compared this model to a model with platform as an additive covariate, i.e., not involved in any interactions. The models for accuracy data would not fit when interactive terms were included. We removed all interactive terms for the final accuracy model. The analysis of accuracy is reported in the Supplemental Analysis C.

For each of the models, the most parsimonious random effects structure (Bates et al., 2018) was determined by starting with the maximal random effects structure of the form (1 + Alternation * P rev.Rew. * Curr.Rew. | P articipant) and then simplifying the structure in cases of singular fits or convergence issues.

Model fits were compared using the ANOVA approach. The models were fit using lme4 (Bates et al., 2015). To examine accuracy and choice behavior, we used a generalized linear mixed model with accuracy (incorrect: 0, correct: 1) or task transition (repeat: 0, switch: 1) as binary dependent measures, and a binomial distribution family with a logit link function was used for the models. Reaction times were log 10 -transformed to correct for skewed residuals, and back-transformed for plots and post-hoc comparisons. Post-hoc contrasts were computed as differences in model-estimated marginal means on the response scale (i.e., differences in switch probability for choice models, represented as ∆p; differences in milliseconds for reaction time models), averaged over the observed covariate distribution using the marginaleffects package (Arel-Bundock et al., 2024). The p-values were adjusted using the Holm-Bonferroni method.

Although prior work has illustrated the effect of reward transition as a bar graph with four levels, where the typical finding is lower switch rates for consistent reward (i.e., remain high or remain low) and higher switch rates for changing reward (i.e., increase or decrease), we chose to plot the reward transition effect on switch probability as a twoway line graph, where the typical effect is observed as a crossover interaction. Plotting the reward transition in this way makes it easier to qualitatively compare the effect as a function of other factors, as well as between individual differences.

To examine individual differences, we performed additional exploratory models that included variables of gender identity, BIS score, and BAS-Reward Responsiveness score. We only included those who self-reported their gender as male and female, excluding those identified as non-binary, transgender, or unspecified due to low response numbers (a total of 10 participants across all data, or 1.4% of the initial sample). Gender was coded as a sum contrast, while the BIS/BAS scores were treated as continuous variables and centered and scaled. For ease of interpretation, we plot results involving BIS and BAS at ± 1 SD, referred to in the figures as low and high.

Training

To confirm that participants learned the cue-reward associations during the training blocks, we first looked at the proportion of trials in which the high reward cue was chosen. We excluded the first of the three training blocks to remove the influence of early learning and exploration, especially at higher levels of reward uncertainty. The proportion of high value cue choices mirrored the reward probabilities: 100%: M = 0.94, SD = 0.118; 80%: M = 0.74, SD = 0.172; 70%: M = 0.71, SD = 0.151; 60%: M = 0.58, SD = 0.154. Next, we ran a generalized (binomial) linear mixed model on high vs. low value cue choices to see if reward probability influenced training choices, followed by equivalence testing to test if choices were equivalent to chance (i.e. 50% high vs. low choices). We compared models that 1) examined training choices across reward probabilities alone, 2) included additive factors of probability and administration platform, and 3) had reward probability interacting with platform. Model (3) with the reward probability and platform interaction was the best fitting. The model showed a large effect for a linear contrast of reward probability (log -Odds = -2.59, 95% CI = [-2.88, -2.31]) and a smaller effect for the interaction (log -Odds = 0.93, 95% CI = [0.57, 1.28]). The proportion of high value choices differed between in-lab and online data at 100% and 70% probability (100%: ∆p = 0.06, 95% CI = [0.04, 0.08]; 70%: ∆p = 0.07, 95% CI = [0.004, 0.14]) but not at 80% and 60% probability (80%: ∆p = 0.04, 95% CI = [-0.03, 0.11]; 60%: ∆p = 0.02, 95% CI = [-.07, 0.11]). Discussion

The present study examined whether recent reward history is associated with subsequent voluntary task selection, and whether this association differs across cue-outcome contingency conditions. Replicating previous work, changes in reward magnitude were associated with increased voluntary task switching, whereas stable rewards were associated with more task repetition. The estimated reward-transition effect was smaller in the lowerprobability conditions; it was statistically detectable at 100% and 80% probability, but not at 70% or 60%. These results are consistent with the possibility that cue-outcome contingency modulates the association between recent reward history and subsequent choice, although nonsignificant effects do not establish that the effect is absent. The secondary analyses also found associations between outcomes unexpected relative to the cue schedule and subsequent choice, but the evidence for their modulation by probability was mixed. Importantly, task choices did not affect future reward outcomes. The observed carry-over therefore does not demonstrate that participants switched to explore for greater reward or that they were optimizing reward through their task choices. The behavioral effects were clearest in voluntary choice; this pattern alone does not identify the cognitive representation or mechanism responsible.

The secondary analyses found that, following a low-reward cue, an unexpectedly high outcome was associated with a lower switch probability than an expected low outcome. Following a high-reward cue, an unexpectedly low outcome was associated with a higher switch probability than an expected high outcome in some comparisons. These directions are compatible with reward-learning accounts in which outcomes better or worse than expected influence subsequent behavior (Cohen et al., 2007; Daw et al., 2006). However, these contrasts classify outcomes by the programmed cue schedule; they are not estimates of trial-wise prediction errors. We did not measure participants' subjective expectations, fit a learning model, or test whether task choice was guided by updated values. Consequently, the results cannot establish that prediction-error learning caused the choice effects, or that switching reflects exploration. Other outcome-related processes, including changes in affect, arousal, attention, or persistence, could also contribute. Moreover, the omnibus interaction among prior outcome, current reward prospect, and reward probability was not statistically significant. The significant lower-order contrasts should therefore be interpreted cautiously rather than as conclusive evidence that uncertainty changes the processing of prediction errors. The lack of a main effect of probability on switching, alongside interactions involving prior outcomes and current prospects, is consistent with probability condition being associated with how recent outcomes relate to subsequent task selection rather than with a uniform change in switching. It does not, by itself, identify a mechanism such as adaptive meta-control or reinforcement learning. The mixed-effects approach allowed trial-level estimation while accounting for participant-level variability, which is expected in voluntary task-switching paradigms, where baseline switching preferences differ between participants (Arrington & Logan, 2005; Mayr & Bell, 2006; Orr & Banich, 2014).

The exploratory individual-differences analyses suggested that BIS and BAS-Reward Responsiveness may moderate reward-history effects under some probability contrasts. Surprisingly, low rather than high scores on BAS-Reward Responsiveness were associated with more pronounced effects of reward transition, particularly in male participants. BAS-Reward Responsiveness is thought to positively relate to reward sensitivity in general (Beaver et al., 2006), sensitivity to reward mismatches (S. Lange et al., 2012), and enhanced working memory and context updating in high reward environments (Heritage et al., 2018). On the other hand, high BAS-Reward Responsiveness has been associated with risky gambling choices (Balconi et al., 2015) and haVoigt et al., 2009s been related to symptomatology in bipolar disorder (L. B. Alloy et al., 2008; L. Alloy et al., 2012; Meyer et al., 2001). This raises the possibility that the lack of reward transition effect at high BAS-Reward Responsiveness was due to maladaptive decision-making. However, the present study does not show that a larger or smaller reward-transition effect is adaptive or maladaptive. Follow-up work should test these individual-difference patterns with preregistered, theory-driven analyses and models that directly assess candidate learning and choice processes.

Several methodological characteristics boost confidence in the findings. We used a principled model selection approach, began from maximal random-effects structures when feasible, and evaluated models via likelihood ratio tests, with population-level conditional effects estimated using established R tools. We included a large, representative sample, albeit from an American undergraduate population (Roberts et al., 2020). At the same time, there are important limitations. The design was not preregistered and a sizable number of participants were excluded due to incomplete data or extreme outliers; although motivated by data quality, such exclusions can reduce generalizability and introduce bias (Bakker & Wicherts, 2014; Miller, 1991). We also combined online and in-laboratory data collection; while online responses were generally slower and reward transition effects for switch probability were smaller compared to in-lab data, the pattern of the effects was overall similar. This is in line with previous work that demonstrated comparable results with online and laboratory data collection (Germine et al., 2012; Weydmann et al., 2023); due to the smaller effects found with online compared to in person data, larger sample sizes are likely warranted for online data collection. Finally, we restricted gender analyses to self-reported male and female due to small cell sizes for other identities, limiting the inclusiveness and generalizability of these exploratory individual-difference results (Nielsen et al., 2018).

Future work could test reinforcement-learning accounts against alternative explanations by combining voluntary task-switching with measures of participants' trial-by-trial expectations and computational models that estimate learning and choice processes. Such models could evaluate whether reward-learning parameters explain behavior beyond simpler outcome-history or choice-persistence accounts; exploration-exploitation interpretations would require evidence that switching changes access to, or selection among, actions with different expected rewards. Advanced modeling, such as drift diffusion models of reinforcement learning, could help characterize how decision and feedback processes interact (Fengler et al., 2022; Pedersen et al., 2017). Furthermore, direct manipulation of subjective uncertainty (e.g., through volatility or feedback noise) along with objective validity could clarify whether uncertainty affects learning, decision noise, or both (Lurie & Swaminathan, 2009; Massi et al., 2018; Zylberberg et al., 2016). Replication with preregistered analyses, oversampling of underrepresented gender identities, and cross-platform validation will also be valuable. Combining behavior with physiological or neural measures could help evaluate whether neural or physiological responses to unexpected outcomes are related to subsequent task-selection policies.

A key limitation is that reward-probability conditions were not collected concurrently. The 100%, 80%, and 60% conditions were associated with different collection periods, while the 70% condition spanned two periods. Consequently, reward probability is partly confounded with semester and cohort. Modeling administration platform does not address this issue, and the available design may not permit the independent effects of probability and collection period to be identified. We therefore cannot attribute the between-condition pattern uniquely to cue-outcome contingencies; cohort or other time-related differences could also contribute. Replication with concurrent, randomized assignment to all probability conditions is needed to test whether the pattern is caused by the contingency manipulation.

Conclusions

Our results show that recent reward outcomes and current reward prospects are associated with voluntary task selection, and that the estimated reward-history effects differed across reward-probability conditions. Outcomes that were unexpected relative to the cue schedule were also associated with subsequent switching in some comparisons. These findings are compatible with reward-learning accounts, but do not demonstrate that predictionerror learning or reward-guided exploration caused the observed effects: subjective expectations and learning processes were not measured, and task choices did not change future reward. Replication with concurrent condition assignment and direct tests of learning-based and non-learning explanations are needed to determine the mechanisms underlying these associations.

As we examined transitions to current trial reward prospects from previous trial outcomes rather than previous trial prospects like many previous studies of rewarded voluntary task switching (Fröber & Dreisbach, 2016b; Fröber et al., 2018 Fröber et al., , 2020)), we carried out a confirmatory analysis to examine the effect of trial-to-trial transitions of reward prospects (i.e., cue value) on switch probability. This analysis included all possible outcomes following a low or high value cue, including trials too slow to receive a reward and unexpected reward outcomes. The full model parameter estimates are reported in Table C1, and the model-estimated marginal means for switch probability as a function of previous trial reward prospect, current trial reward prospect, and reward probability are reported in Figure C1. There was a significant three-way interaction between previous reward prospect, current reward prospect, and reward probability. At the 100% probability condition, which most closely matches these previous studies, the reward prospect transition effect was significant and the pattern resembled the reward outcome transition effect we report in the main analysis. In line with our main analysis, the reward prospect transition effect declined with decreasing reward probability (100%: ∆p = 0.149, 95% CI = [0.126, 0.172]; 80%: ∆p = 0.078, 95% CI = [0.053, 0.103]; 70%: ∆p = 0.032, 95% CI = [0.005, 0.059]; 60%: ∆p = -0.014, 95% CI = [-0.042, 0.014]). Pairwise comparisons also followed a similar pattern as the main analysis, with the reward prospect transition effect differing between subsequent levels of reward probability, with the exception of 70% versus 60%. The similarities between our main analysis and this confirmatory analysis suggest that our analytic choices do not substantially deviate from the existing literature on rewarded voluntary task switching.
